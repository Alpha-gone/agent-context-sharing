## 로컬 계약

- 서비스 동작·구조·구성값·상한은 SRS와 해당 분야 SDD에만 정의한다. DOX에서 별도 기본값이나 미정 상태를 복제하지 않는다.
- 구현 배치와 분야 간 경계는 [아키텍처](sdd/architecture.md), 연결·인증 표면은 [MCP](sdd/mcp.md)·[인증](sdd/authentication.md), 실행·환경 경계는 [운영](sdd/operations.md)을 따른다. 나머지 분야는 SDD 진입점에서 소유 문서를 찾는다.
- 채택된 목표·현재 구현·검증 대기를 구분한다. 표준 MCP 직접 연결과 호스트 지원은 설계 채택만으로 완료 처리하지 않고 [상호운용 시험](sdd/testing.md)의 증거로 판정한다.
- 신규 개발 계획은 기존 구현을 완료 근거로 승계하지 않는다. 계획의 작업 상태로 요구사항·설계 채택 상태를 바꾸지 않는다.
- 계약 변경은 소유 정본에서 수행하고 영향을 받는 추적표·계획·[서비스 색인](../README.md)을 정합화한다. 과거 기록의 시점과 검증 범위는 보존한다.

## 작업 지침

- 대상 분야의 SRS·SDD·용어집을 확인한 뒤 문서를 편집한다. 교차 분야 변경은 소유권과 참조를 함께 확인한다.
- 신규 분야나 책임 이동은 SDD·개발 계획 진입점과 추적표에 반영한다.
- 요청과 결과는 기존 요청 기록에 남기고, 구현 검토의 발견 사항은 근거·상태와 함께 관리한다.

## 검증

- 요구사항→주 책임 설계→개발·인수 작업의 연결과 문서 간 상태가 일치하는지 확인한다.
- 데이터·권한·오류·트랜잭션·자원·시간 계약은 각 소유 문서와 교차 참조에서 대조한다.
- 미정 사항은 현재 SRS·설계 추적표를 기준으로 확인하고 해소된 항목을 DOX에서 미정으로 되살리지 않는다.
