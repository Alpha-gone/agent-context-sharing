## 구현 결과

`model.ValidateRegistrationKey`는 16~128자의 ASCII 영문·숫자·밑줄·하이픈을 확인한다. 기존 MCP 공개 스키마의 같은 입력 계약을 유지하며 오류에는 키 원문을 넣지 않는다.

`store.RegisterAgent`는 계정 존재를 확인하고 계정 행 잠금 아래 client·등록 키를 재조회한다. 같은 활성 등록은 ID·생성 시각을 유지하며 128개 상한에서도 재조회할 수 있다. 새 등록의 활성 개수는 모든 client를 합쳐 센다. Read Committed의 별도 조회 명령으로 잠금 대기 중 커밋된 상태를 읽고 동시 삽입을 직렬화한다. 새 ID는 UUIDv7이며 정식 스키마의 영구 유일 키와 upsert가 중복을 막는다. 폐기한 키는 새 ID로 복구하지 않는다.

`ValidateAgent`는 매번 현재 계정·client·활성 상태를 대조한다. 없는 ID·다른 계정/client·폐기·잘못된 ID는 같은 agent_id 입력 오류로 반환한다. `RevokeAgent`는 웹 세션에서 확인한 소유 계정과 등록 ID만 받는 관리 API다. 다른 계정·없는 ID는 같은 오류이고 반복 폐기는 최초 시각을 유지한다. 등록·폐기는 같은 계정 잠금 순서를 사용하여 상한의 빈자리를 일관되게 회복한다. 등록 행·기존 created_by_agent·과거 관리 감사는 삭제하거나 재작성하지 않는다.

`mcp.Principal`은 HTTP 인증 경계가 검증한 계정·OAuth client만 담는다. 도구 인자·호스트 clientInfo·계열을 등록 신원으로 저장하지 않는다. `mcp.RegisterAgent`와 `BindActor`는 이 결합을 저장 인터페이스에 전달하며 후자는 검증된 계정·agent만 반환한다. 감사 판단 입력과 실제 여섯 쓰기 매핑은 MCP-06이 채운다. 등록은 그래프 등급이나 개별 대화/프로세스의 신원 증명이 아니다. 공유 저장 장애는 입력 거부와 구분하고 원문 없는 내부 실패로 전달하며 원인은 보존한다. 저장 값 해석 실패의 cause가 FieldError여도 사용자 입력 오류로 바꾸지 않는다.

서버 경계 시험은 실제 코드 교환→Bearer 검증→Principal→등록으로 연결했다. 같은 계정의 다른 OAuth client는 같은 등록 키에도 다른 ID를 받고 서로의 등록을 쓸 수 없다. OAuth 계열 폐기 후 새 계열로 인가해도 등록 ID는 유지하며, 등록 폐기는 웹 세션·다른 client의 등록을 폐기하지 않는다. 이 시험은 내부 API 연결의 증거이며 실제 MCP·브라우저 UI 인수의 증거가 아니다.

## 모듈 시험과 검증

Go 1.27.1에서 `-timeout=120s -race -json -count=1`을 적용했다. DB 범위에는 TEST_DATABASE_REQUIRED=1과 전용 TEST_DATABASE_URL을 지정했다.

- MCP **203건**: `go test -race -json -count=1 ./internal/mcp`의 200건과, 감싼 저장 해석 장애의 분류를 확인한 `TestAgentWrappedStorageFailure` 3건. 기존 SDK·14종 스키마와 새 등록/행위자 입력·한도·장애·취소·원인 보존/비노출을 포함한다.
- 모델 **13건**: `go test -race -json -count=1 -run '^TestRegistrationKey$' ./internal/model`. 최소·최대·ASCII와 공백·NUL·개행·한글·잘못된 UTF-8 등을 확인했다.
- 저장 **22건**: `go test -race -json -count=1 -run '^TestAgent.*' ./internal/store`. 시험별 임시 DB와 풀 상한 4개인 두 저장소에서 동일 키 16건 동시 등록·127개 직전 16건 경합의 단일 추가·상한 재조회·계정/client 격리·폐기/자리 회복·다른 계정 진행·잠금 대기 취소·대기 중 폐기 재검사·저장/COMMIT 장애 롤백·과거 기여/감사 보존·닫힌 DB 장애를 검증했다.
- 서버 **1건**: `go test -race -json -count=1 -run '^TestAgentBearerIdentityIntegration$' ./cmd/server`. 실제 OAuth/Bearer 계정·client와 등록/폐기의 결합을 확인했다.
- **중복 제외 총 239건 통과·건너뜀 0건·race 통과**. 전체 저장소·MCP 분야 전체 통합·실제 전송/UI/호스트 인수와 구분한다.

첫 정적 검사에서 저장 시험의 변수 범위 오류를 발견해 수정했다. 모델 시험은 유지하고 영향받은 MCP·저장·서버를 재실행했다. 저장 해석 장애의 분류를 보강한 회귀는 해당 시험만 추가 실행했다. 실패 실행은 위 완료 건수에 포함하지 않았다.

각 실행은 이번 실행이 만든 무작위 mcp04_suite DB에 TEST_DATABASE_URL을 고정했다. 실제 DB 시험은 다시 시험별 자식 DB를 만들고 현재 DB명·정식 마이그레이션으로 격리를 확인했다. 연결을 반환한 뒤 자신이 만든 DB만 정리했으며 두 실행 모두 suite DB 삭제·부재를 확인했다. 기존 개발·운영 DB의 계정·등록·키를 시험 준비에 사용하지 않았다.
