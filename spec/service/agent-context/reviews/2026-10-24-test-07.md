## 새 인수 시나리오

`internal/authz/testing_server_acceptance_test.go`는 하나의 실제 TLS 서버·서명 키·인증 처리기·SDK에 24개 요청을 순서대로 보낸다. 업무 결과와 공유 인증 저장 장애만 주입한다. 이전 발견·성공·실패가 다음 요청의 현재 인증과 오류 계층을 바꾸지 않는지 확인한다. 업무 주체는 서명한 account/client와 대조한다.

- 발견 전 독립 호출 → 발견 → 14종 목록은 모두 표준 완료 결과이며, 발견/목록에는 `ttlMs=0`·`cacheScope=private`가 있다.
- 발견 뒤 Bearer 부재·잘못된 자격·현재 폐기는 401, 다른 scope는 403이다. 인증 저장 장애는 500 `server_error`이며 재인가 헤더가 없고 이후 정상 요청은 성공한다.
- 잘못된 JSON은 400/-32700, 표준 메서드 헤더 부재는 400/-32020, 미지원 revision은 400/-32022, 미지원 RPC는 404/-32601이다. GET/DELETE는 빈 405·`Allow: POST`로 거부된다.
- 도메인 코드 `invalid_argument`·`permission_denied`·`not_found`·`version_conflict`·`limit_exceeded`·`not_supported`·`internal`은 HTTP 200의 표준 완료 결과·`isError=true`를 유지한다. 필요한 필드·등급·현재 판·한도·웹 대체 채널과 2^53을 넘는 판 번호의 원시 숫자를 대조한다.
- 여덟 번째 코드인 `result_truncated`는 정상 부분 상태다. 절단·홉 경계와 임베딩 채널 실패를 가진 결과는 `isError=false`이며 도메인 실패로 바뀌지 않는다. text와 structuredContent는 같은 값이다.
- 모든 요청의 `no-store`, 세션 ID·쿠키·리디렉션 부재, 자격/내부 원문 비노출, 거부 요청의 업무 미진입과 정상 업무의 단일 호출, 모든 실패 뒤 성공을 확인한다.

`cmd/server/testing_replay_acceptance_test.go`는 정식 마이그레이션의 새 DB에 실제 쓰기 어댑터를 연결한다. 첫 저장소 인스턴스의 그래프 갱신이 커밋한 뒤 SDK가 첫 응답 본문을 쓰는 지점에서 ResponseController.Hijack으로 실제 TLS 연결을 닫는다. 클라이언트는 전송 실패를 관찰하지만 그래프의 이름과 판은 한 번 갱신돼 있다. 두 번째 저장소/TLS 인스턴스에서 같은 키와 이전 기대 판으로 두 번 재시도해 최초 성공 결과를 받는다. 최초 커밋 뒤 지문과 매 재생 뒤 지문을 비교해 정점·간선·판·감사·큐·저장량·쓰기 빈도·멱등성 기록의 중복 변경이 없음을 확인한다. 이 시험의 인증 주체는 검증된 결합을 대역으로 주입하며 실제 Bearer/OAuth 인수는 위 행렬과 아래 별도 시험이 담당한다.

## 계약별 새 실행 증거

- **SDK·도구 계약**: `internal/mcp` 전체를 새로 실행해 고정 SDK v1.8.0·revision 2026-07-28의 독립 호출·발견·14종 입력 스키마·설명/annotations·스냅샷·표준 외피·캐시·필수 메타데이터/헤더·미지원 revision/RPC·GET/DELETE·본문 상한을 확인했다. 실제 조립 서버 전체의 도구 스냅샷 인수는 MCP-09 범위다.
- **OAuth 발견·인가·수명**: `internal/authz` 전체와 서버의 OAuth 표본을 실행했다. 고정 issuer/resource·Host 위조 거부, PKCE S256과 callback/resource/client 결합, 코드 60초 만료와 행 잠금 뒤 재검사·단일 소비, 접근 토큰의 1시간 직전/정각, 갱신 유휴 7일·절대 30일 경계를 주입 시계로 확인했다.
- **회전·폐기·보존**: 두 인스턴스/재시작의 회전·재사용 계열 폐기·8개 동시 교환·실패 롤백·만료 후 소비 기록의 재사용 탐지와 `retain_until` 비축소를 확인했다. `TestOPS04OAuthCleanupIntegration`에서 소비 자식 보존·절대 수명+1시간 보호·잠금 뒤 재검사·실패 원자성·128건 넘는 정리·실행권을 대조했다. `TestAUTH10ConnectionsTLSIntegration`에서 현재 Bearer와 독립 등록/웹 세션의 폐기 경계도 확인했다.
- **쓰기 안전**: 서버의 실제 여덟 쓰기·권한/등록 재검사·잠금 대기 후 취소·실패/커밋 롤백과 저장소의 MCP05 재생·24시간 수명·다른 도구/인자 충돌·커밋 전후 취소·현재 검사·수명 종료를 새로 실행했다. `TestTEST03ConcurrentWriteCommitBoundaryIntegration`의 커밋 전 외부 비가시성·단일 적용도 확인했다. 실제 응답 유실은 이번 새 TLS 시나리오로 별도 확인했다.
- **오류·취소**: 실제 Bearer의 키/공유 저장 장애, SDK RPC 오류와 도메인 부가 정보, 정상 부분 결과, HTTP 취소·요청 예산의 제공자 취소를 실행했다. 인증 내부 장애가 로그인 반복 신호로 바뀌지 않았다.
