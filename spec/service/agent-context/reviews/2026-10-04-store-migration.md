# 저장소·마이그레이션 계층 회귀 검증

## 대상과 확인 근거

[GitHub #59](https://github.com/Alpha-gone/agent-context-sharing/issues/59)의 네 항목을 `dev`의 `2ed3782`에서 만든 `fix/store-migration_#59` 브랜치에서 처리했다. 시작 시 upstream과 원격이 일치했고 기존 변경은 없었다. 적용 DOX 체인과 용어를 확인했다. 코딩 표준·Modern Go 지침은 최소 구현과 회귀 시험에, service-design은 SDD 정합화에, work-history는 계획·요청·검증 기록에 적용했다.

코드 확인 결과 컨텍스트 상태 오류 네 경로에는 `ErrInvalidState`가 없었고, 충돌 재조회는 쓰기 연결을 보유한 채 예약하지 않은 풀 읽기를 수행했다. 화면은 owner 부여 행 수를 세지만 실제 회수는 부여를 삭제한 뒤 소유자 등급을 쓸 계정의 존재를 확인했다. 이 때문에 빈 팀·삭제된 팀의 부여가 있으면 마지막 직접 소유자 회수를 허용하는 안내가 나올 수 있었다. 반대로 동일 계정의 직접·팀 중복이나 유일한 팀의 여러 구성원을 단순 계정 수로 대체해도 부여 전체의 회수 결과와 일치하지 않는다.

마이그레이션 항목은 현재 기준에서 이미 해결되어 있었다. `cmd/migrate`는 `Prepare`·`LoadRecorded`를 거쳐 적용 당시 `render_config`로 과거 SQL을 대조하고, `migrations/AGENTS.md`에는 `ColdTablespaceClause`가 등록되어 있다. 따라서 SHA-256 형식을 원본 파일 해시로 교체하거나 기존 이력을 다시 쓰지 않았다. 이 항목은 모든 치환 값의 회귀와 실제 DB 이력 보존 시험을 추가해 확인했다.

## 해결 및 유지한 계약

- 상태 오류: 사전 확인과 조건부 갱신 뒤 재조회 모두 `ErrInvalidState`를 감싼다. AGE 동시 갱신 오류도 폐기·복구의 현재 상태를 확인해 이미 완료된 전이는 상태 오류, 본문·판 충돌은 `VersionConflictError`로 구분한다. 기존 MCP 사상이 이를 `invalid_argument`로 변환한다.
- 연결 예약: 컨텍스트 생성·대체·갱신·폐기·복구는 시작 전에 트랜잭션과 충돌 읽기의 최대 점유 2개를 예약한다. 생성·대체의 근거 무효 전파도 같은 경계 안이다. 멱등성 저장점은 이미 확보한 바깥 예약을 공유하며, 롤백·커밋과 예약 반납의 순서를 유지한다. 예약 상한·풀 최소값·배포 구성은 바꾸지 않았다.
- 권한 화면: 공통 `usableOwnersSQL`이 직접 계정과 활성 팀 구성원의 owner 부여를 나열한다. 실제 회수는 그 계정의 존재를, 화면은 대상 부여를 제외한 계정의 존재를 확인한다. 조회 하나에서 안내를 산출해 별도 집계 시점의 불일치도 없앴다. 상속 행은 회수할 수 없으며 표시는 조회 시점의 안내이고 실제 회수는 그래프 잠금 뒤 다시 판정한다.
- 마이그레이션: 현재 구성 변경은 미적용 파일에만 반영하며 과거 파일의 내용·주석 변경은 계속 거부한다. 체크섬·구성·적용 시각을 보존한다. 구성 변경만으로 기존 스키마가 자동 변경된다고 해석하지 않는다. SQL 파일과 실행기 구현은 수정하지 않았다.

## 검증

Go 1.27.1 `darwin/arm64`를 사용했다. 기존 개발 DB와 분리한 `issue59_regression`·`issue59_suite`에 정식 001·007·008을 적용했다. DB 시험에는 `TEST_DATABASE_URL`, `TEST_DATABASE_REQUIRED=1`을 설정했고 마이그레이션 자체 시험은 추가 임시 DB를 생성·정리하는 기존 격리 도우미를 사용했다. 외부 임베딩 호출은 수행하지 않았다.

- 같은 원천의 동시 폐기와 복구: 적용은 한 번이고 나머지는 상태 오류이며 저장량을 한 번만 변경한다.
- 풀 상한 4·요청 8의 실제 AGE 갱신·폐기·복구 충돌: 잠금 대기를 관측하고, 동시 첫 연결은 2개 이하이며 모든 결과가 제한 시간 안에 올바른 오류로 끝나고 예약이 남지 않는다.
- 생성·갱신·폐기·복구의 예약 대기 취소: 연결을 먼저 획득하지 않으며, 취소 뒤 새 생성이 가능하다. 바깥 예약 공유와 반납도 단위 시험으로 확인했다.
- 회수 안내 여덟 조합: 빈 팀·삭제된 팀·중복 직접/상속 계정·여러 구성원의 유일한 팀·다른 직접 소유자·소유자 없는 그래프를 실제 회수 결과와 대조했다. 상속 행의 회수 수단은 없었다.
- 치환 값 다섯 종: `GraphName`, `VectorType`, `VectorDim`, `ColdTablespaceClause`, `IndexTargetLayers` 변경에서 과거 체크섬은 유지하고 새 파일은 현재 구성으로 준비한다. 원본 주석 변조는 거부한다. 실제 001 적용 DB에서 구성 변경 뒤 체크섬·구성·시각 보존과 미적용 007 준비를 확인했다.
- 새 회귀와 기존 동시 갱신·근거 무효 전파·예약·소유자·임베딩 차원 전환 회귀를 `go test -race -p 1 ... -count=10`으로 실행해 통과했다.
- 새 DB의 서버 전체 `go test -race -p 1 -count=1 -json ./...`: 테스트 항목 764개 통과, 실패·테스트 건너뛰기 없음. 테스트 파일이 없는 패키지의 JSON `skip` 이벤트는 개별 테스트와 구분했다.
- 클라이언트 전체 `go test -race ./...`, 서버와 클라이언트 각각 `go build ./...`, `go vet ./...`, 루트 `gofmt -l .`과 `git diff --check`: 통과했다.

첫 회귀 작성 중 import 누락, 시험 그래프에 직접 부여를 준비하지 않은 경우와 잠금 대기의 직접 PID만 센 관측 오류가 있었다. 시험 준비를 수정한 뒤 관련 1회·10회 및 전체 검사에서 모두 통과했다. 이를 제품 코드의 수정 전 재현 실패로 해석하지 않는다.

## DOX pass와 제한

- SDD의 연결 예약·상태 오류·권한 화면·테스트 전략과 `migrations/AGENTS.md`의 체크섬 기준을 정합화했다. 개발 계획과 요청 기록을 갱신했고 한국어 표현·맞춤법·Markdown 구조·상대 링크를 검토했다.
- 루트·spec 부모·서비스 AGENTS와 Child DOX Index는 경계·소유권·지속 구조가 달라지지 않아 유지했다. SRS·용어집·공개 도구 계약·클라이언트·SQL 마이그레이션은 요구사항·용어·API·스키마 변경이 없어 유지했다. 새 배포 구성이나 의존성은 없다.
- 시험용 DB만 정리했으며 기존 개발 DB·볼륨·`.env`·비밀·Ollama 모델·운영 환경은 변경하지 않았다. 접속 정보와 비밀값은 출력하거나 기록하지 않았다.
- 브라우저 수동 시험·`client_live` 실제 종단 간 시험·외부 API·운영 배포·커밋·푸시·PR·이슈 종료는 수행하지 않았다. #59 범위의 미해결 결함은 없다.
