# MCP 개발 계획

[전체 계획](../DEVELOPMENT_PLAN.md) · [기준 SDD](../sdd/mcp.md) · [작업 추적](traceability.md)

## 목표와 구현 범위

공식 SDK의 표준 무상태 Streamable HTTP와 도구 14종, 계정·행위자 결합, 선택 쓰기 키·24시간 재생을 새로 구현한다. 전용 프로젝트 클라이언트를 만들지 않는다.

- 설계 입력: [표준 경계](../sdd/mcp.md#표준-mcp-경계), [행위자와 쓰기](../sdd/mcp.md#공통-행위자도구쓰기-안전성), [연산](../sdd/mcp.md#연산-계약), [입력](../sdd/mcp.md#입력-검증), [SDK](../sdd/mcp.md#sdk와-수명주기), [도구](../sdd/mcp.md#도구-입력과-반환-계약), [멱등성](../sdd/mcp.md#멱등성-저장과-경합).
- 예정 구현 영역: `internal/mcp`, 등록·멱등성 저장 API, 서버의 MCP 어댑터·계약 스냅샷.
- 다른 분야와의 경계: 토큰·OAuth는 인증 계획, 도메인 쓰기·검색은 각 소유 계획, 실제 Codex 지원은 테스트 계획이 소유한다.

## 개발 작업

### MCP-01

- [x] **고정 SDK와 목표 revision의 실제 적합성을 확인한다.**
- 선행: [ARCH-01](architecture.md#arch-01).

1. 공식 Go SDK v1.8.0의 사용 API·release notes를 확인하고 지원 revision을 2026-07-28 하나로 제한한 최소 서버를 빌드한다.
2. 발견 생략 호출·server/discover·요청별 메타데이터·완료 외피·캐시·무상태 handler를 루프백에서 대조한다.
3. SDK가 설계 계약을 충족하지 못하면 정확한 차이를 기록하고 소유 SDD·TBD-064에서 해결한다. 이전 initialize/세션 방식으로 자동 하향하지 않는다.

- 산출물: 버전 고정·최소 적합성 시험·공식 API 근거와 미충족 항목.
- 완료 기준: 실제 빌드·메시지 교환이 목표 계약과 맞는다. SDK 적합성을 호스트 지원 완료로 확대하지 않는다.

- 완료 근거: 2026-10-18 [최소 SDK 적합성 검토와 보완 후 인수](../reviews/2026-10-18-mcp-01.md#서비스-진입-경계-보완과-최종-인수). SDK 단독의 네 차이는 관찰 시험으로 보존하고 비공개 newSDKTransport에서 필수 외피·revision·허용 RPC·중복 헤더 검사와 Base64 Mcp-Name 해독을 보완했다. 두 루프백 서버의 발견 생략·요청별 메타데이터·완료 외피·private/0 캐시와 이전 수명주기 거부·JSON-RPC 오류·한글/sentinel 이름 호출을 확인했다. mcp 모듈 87건·race와 전체 build·vet·형식 검사가 통과했다. 실제 서버·Origin·Bearer/OAuth·14종 업무 도구·호스트 지원은 후속 범위이며 MCP-02의 AUTH-08 선행 조건은 유지한다. 다음 착수 가능한 MCP 작업은 MCP-03이다.

### MCP-02

- [x] **표준 HTTP 외피·발견·요청 검증을 구현한다.**
- 선행: [MCP-01](#mcp-01), [ARCH-03](architecture.md#arch-03), [AUTH-08](authentication.md#auth-08).

1. POST /mcp의 단일 JSON 요청·응답, Content-Type·Accept·Origin과 GET/DELETE 405를 구현한다. SSE·MCP-Session-Id를 광고하지 않는다.
2. 요청별 protocolVersion·clientCapabilities와 MCP-Protocol-Version·Mcp-Method·호출의 Mcp-Name을 본문과 대조한다. 표준 Base64 sentinel도 같은 규칙으로 비교한다.
3. server/discover의 supportedVersions·tools·serverInfo·instructions, 발견/list의 ttlMs=0·private를 제공한다. 발견 이력 없이 독립 요청을 처리한다.
4. 본문 상한·JSON-RPC 요청 검증·미지원 revision/RPC·필수 외피 누락을 전송 오류 표대로 반환한다.

- 산출물: 무상태 전송 처리기·발견 응답과 외피 오류 시험.
- 완료 기준: 400/-32602·400/-32020·400/-32022·404/-32601·403·405가 정확히 구분되고 서비스 전용 필수 헤더·이전 초기화 교환이 추가되지 않는다.
- 완료 근거: [MCP-02 검토](../reviews/2026-10-20-mcp-02.md). 14종 처리기·인증 경계를 필수 주입하는 보호 HTTP 생성자와 서버 라우터 결합을 구현했다. Origin·메서드·미디어 타입·표준 헤더·4 MiB 본문·JSON-RPC·revision을 검증하고 독립 발견/목록·private/0·HTTP no-store를 유지한다. 실제 TLS 두 인스턴스에서 OAuth/Bearer·계정/client 격리·공유 폐기와 등록을 연결하고 선언/미상/축소 길이·실제 chunked·최대 이스케이프 입력·실행 중 취소를 검증했다. MCP 283건·서버 161건·인증 92건, 총 536건·race와 전체 build·vet·형식 검사를 통과했다. 기동 경로의 업무 13종 연결·전체 서버 계약·실제 호스트 인수는 MCP-06·07·09와 TEST-08의 후속 범위다.

### MCP-03

- [x] **14종 도구 스키마·설명·annotations를 구현한다.**

- 완료 근거: 2026-10-18 [14종 도구 정의·입력 경계 검토](../reviews/2026-10-18-mcp-03.md). 공통 instructions와 14종의 설명·annotations·닫힌 입력 스키마를 구현했다. 같은 스키마를 서버 검증에 사용하며 적용 판에서 검사하지 않는 format은 UUIDv7·UTC·URI·불투명 커서 인코딩 검증으로 보완했다. 계층 조건·keep·불변 필드·8000자·100/1000개 참조·필터 3/7/4개·등록/쓰기 키·기대 판 정밀도와 실제 SDK 목록·14종 형식상 정상 호출/잘못된 입력의 처리기 호출 차단을 확인했다. mcp 모듈 175건·race와 전체 build·vet·형식 검사가 통과했다. 실제 권한·행위자 등록·업무 저장·HTTP 인증·전체 스냅샷·호스트 인수는 후속 작업이며 MCP-02·MCP-04는 AUTH-08 선행 조건을 유지한다.

### MCP-04

- [x] **에이전트 등록·결합·폐기를 구현한다.**
- 선행: [MCP-03](#mcp-03), [AUTH-08](authentication.md#auth-08), [DATA-03](data.md#data-03).

1. 인증 계정·검증 client·16~128자 등록 키의 유일 결합으로 UUIDv7 agent_id를 발급·조회한다.
2. 계정당 활성 128개 상한과 동시 동일 등록을 직렬화/유일 제약으로 처리하고 폐기한 키를 암묵 복구하지 않는다.
3. 네 노드·두 관계 쓰기의 agent_id에 활성·같은 계정/client 결합을 확인한다. 임의·다른 계정/client·폐기 ID는 같은 invalid_argument로 거부한다.
4. 본인 등록 폐기는 웹 연결 관리에 제공하고 과거 컨텍스트·감사 UUID를 재작성하지 않는다.

- 산출물: 등록 API·쓰기 행위자 검증·관리 폐기 경계.
- 완료 기준: 동시 등록은 같은 활성 ID를 반환하고 다른 계정/client가 등록 ID를 공유해 쓸 수 없다. agent에 독립 등급·대화 신원 증명을 부여하지 않는다.
- 완료 근거: [MCP-04 검토](../reviews/2026-10-20-mcp-04.md). 계정/client/등록 키의 안정적인 UUIDv7과 계정 행 잠금 아래 활성 128개 한도·폐기 자리 회복·폐기 키 복구 거부를 구현했다. 인증 경계의 Principal만 받는 등록·공통 BindActor와 소유 계정의 RevokeAgent를 제공한다. 실제 DB에서 동일 키 16건 경합·상한 직전 16건 경합·다른 계정/client 격리·즉시 폐기·잠금 취소/재검사·저장/커밋 롤백·과거 기여/감사 보존과 Bearer→등록 결합을 확인했다. MCP 203건·모델 13건·저장 22건·서버 1건, 총 239건·race와 전체 build·vet·형식 검사를 통과했다. 실제 /mcp 전송·여섯 쓰기 어댑터·/connections 화면 연결은 MCP-02·06·AUTH-10에서 인수한다.

### MCP-05

- [ ] **8종 쓰기의 선택 키·24시간 결과 재생을 구현한다.**
- 선행: [MCP-04](#mcp-04), [ARCH-04](architecture.md#arch-04), [PERM-06](authorization.md#perm-06), [DATA-03](data.md#data-03).

1. 인증 계정·16~128자 request_id 범위의 자문 잠금·예약 행과 결정적 정규화 인자의 SHA-256 지문을 구현한다. 지문에는 도구·agent·기대 판·판단 입력을 포함하고 request_id·표준 외피·자격은 제외한다.
2. 현재 인증·등급·행위자 검증 후 최초 완료 결과를 재생한다. 같은 키의 다른 도구·인자는 invalid_argument다.
3. 도메인 쓰기·적용 감사·큐와 최초 성공/결정적 거부 결과를 같은 바깥 트랜잭션·저장점에서 커밋한다. 결과 없는 예약을 커밋하지 않는다.
4. 내부 일시 장애·취소·연결 실패는 예약까지 롤백하고 재생은 24시간 수명·기대 판·카운터·감사를 다시 적용하지 않는다.

- 산출물: 키·지문·예약·저장점·재생 실행 경계.
- 완료 기준: 병행 동일 요청의 업무·기록·카운터는 한 번만 적용되고 커밋 후 단절에도 최초 결과가 남는다. 키 없는 쓰기는 재조회로 불확정 결과를 확인한다.
