# RINF-06 정식 평가용 신규 합성 표본

상태: 작성 완료, 작성자 외 의미 정답 검토 대기. 이 자료만으로 자동 확정 합격이나 독립 표본 확보를 선언하지 않는다. [SRS의 관계 추론 모델 비교](../../SRS.md#관계-추론-모델-비교)와 [사전 계획](../2026-11-14-rinf-06-preregistration.md)에 따라 작성한 판정 전용 holdout 초안이다. 모델 응답을 정답이나 생성 자료로 사용하지 않았으며 유료 API 호출·임베딩·DB 검색·실제 과업 측정을 수행하지 않았다.

## 구성과 소유권

- [generate_samples.py](generate_samples.py): 네 집합의 명시적 의미 쌍, 사건 구조 부여, 정답 생성과 재현 검증을 소유한다. Python 표준 라이브러리만 사용하며 네트워크나 외부 프로세스를 호출하지 않는다.
- [samples.json](samples.json): 정답을 제외한 대상·후보·무관 후보 사건을 소유한다. 정답·생성 집합 이름을 모델 입력에 넣지 않는다.
- [gold.json](gold.json): 사건 쌍의 유형별 의미 정답·방향·근거·채널별 검색 정답과 검토 상태를 소유한다. 모델 입력으로 전달하지 않는다.
- 이 문서: 자료 범위·검토 경계·재현 방법과 한계를 기록한다. 서비스 동작이나 합격선을 변경하지 않는다.

총 400개 의미 쌍이며 모든 `id`와 `scenario_id`가 고유하다. `relates_to` 양성 100개·음성 100개, `part_of` 양성 100개·음성 100개다. `part_of` 양성의 대상→후보·후보→대상은 각각 50개다. 음성도 각 방향의 기계적 자격을 50개씩 갖춘다. `relates_to` 양성은 방향이 없다.

표본은 사건 이름만 바꾼 동일 문장 전개를 독립 사례로 세지 않도록 서로 다른 작업·대상·판단 근거를 갖춘 400개 명시적 쌍으로 작성했다. 분야는 자연과학·생태·의료·제조·교통·토목·에너지·금융·법률·교육·정보기술·예술·기록·스포츠·농식품 등이다. 기존 N01~N08·탐색 판정 입력을 재사용하거나 그 응답에 맞추어 고치지 않았다. 모든 사건은 허구이며 실제 인물·기관·원천 자료를 나타내지 않는다. 비용과 작성 길이를 제한하고 표기를 일관되게 유지하기 위해 사건 본문은 영어로 작성했다.

## 의미와 기계적 조건

`relates_to` 양성은 같은 구체적 주제나 대상을 서로 다른 관점에서 다룬다. 예를 들어 같은 표본의 성분과 연대, 같은 문서의 본문과 봉인을 함께 다룰 수 있다. 같은 과업이거나 직접 인과가 있어야 한다는 좁은 조건을 정답에 추가하지 않았다. 음성은 구체적 대상과 분야가 다른 쌍이며, 같은 시설의 서로 다른 업무를 무조건 음성으로 두는 과거 초안의 문제를 피했다.

`part_of` 양성은 전체 활동과 그 활동에서 실제 수행한 구성 작업을 명시한다. 부분 사건의 구성원 1개는 전체 사건의 구성원 3개에 대한 진부분집합이며, 시작·종료 시각은 전체 시간 범위 안에 엄격히 포함된다. `part_of` 음성도 동일한 시간·진부분집합 자격을 충족하지만 본문에 다른 독립 활동임을 명시한다. 공유 구성원은 별개 활동에서 참고한 원천 레코드이며 사건 동일성의 증거가 아니다. 따라서 집합·시간 규칙만으로 양성을 맞힐 수 없다. ISO 8601 UTC의 닫힌 시작·종료 시각과 사례별 고유 구성원 문자열을 제공한다.

각 표본에는 본문과 식별자가 고유한 무관 사건 한 개를 넣었다. 해당 사건은 구성원을 공유하지 않으며 대상 사건보다 90일 뒤에 둔다. 무관 사건의 의미 작업 틀은 20개이고 별도 레코드 번호를 부여한다. 이 반복을 새로운 독립 의미 사례 400개로 주장하지 않는다. 독립 평가 단위의 후보는 대상–주 후보 쌍 400개이며 무관 사건·구성원·반복 호출을 독립 표본 수에 더하지 않는다.

음성 유형마다 10개에 유도 지시를, 별도 10개에 명시 인과 근거 부재를, 별도 10개에 시간 일치만으로 관계를 만들 수 없다는 사실을 포함했다. 따라서 유도 지시 20개·인과 보류 진단 20개·시간 우연 진단 20개다. 유도 문구는 인용한 신뢰할 수 없는 본문이며 의미 정답을 바꾸지 않는다. `relates_to` 시간 우연 10개는 실제 시각이 같다. 모든 `part_of` 쌍은 포함된 시각을 갖춘다. 이 자료에는 `causes` 양성이 없고 원인 관계는 보류가 정답이다. 독립적인 인과 성능 인수 자료로 사용하지 않는다.

## 형식과 채널별 정답

입력 형식은 `{version, samples: [...]}`다. 각 표본은 `id`, `scenario_id`, `category`, `relation_type` 및 `target`·`candidate`·`distractor`를 갖는다. 사건에는 `body`, `start`, `end`, `members`, `conversation_id`가 있다. `category`는 `topic_pair` 또는 `activity_pair`이며 양성/음성 라벨이 아니다. 식별자는 의미 쌍의 SHA-256 일부로 생성하고 그 순서로 정렬하여 양성/음성을 집합 순서로 노출하지 않는다. 날짜와 무관 레코드 번호도 정답 집합 번호로 만들지 않는다.

정답 형식은 `{version, gold: {id: {...}}}`다. `expected`는 해당 표본의 `relation_type`에 대한 양성 여부이고 `decision`은 `confirm` 또는 `abstain`이다. 양성 `direction`은 `undirected`, `target_to_candidate`, `candidate_to_target` 중 하나이며 음성은 `null`이다. 음성의 `eligible_direction`은 의미 정답이 아니라 규칙이 허용한 방향이다. `rationale`은 각 쌍의 의미 근거이며 `provenance.semantic_pair`는 생성기의 해당 행을 가리킨다.

`candidate_channel_gold`는 실제 검색 출력과 다음처럼 구분한다.

- `semantic`·`keyword`의 `relevant`: 해당 유형의 관계 정답 후보다. 양성에서는 `candidate`, 음성에서는 빈 집합이다. `observe_actual: true`는 실제 검색에서 반환·순위·누락을 관찰해야 한다는 뜻이다. 임베딩이나 DB 키워드 순위를 미리 계산했다고 주장하지 않는다. 음성 후보가 검색되는 것은 판정용 유효한 음성 입력이며 검색 실패와 같지 않다.
- `member`의 `eligible`: 구성원 공유가 있는 `part_of` 200개는 `candidate`, 나머지는 빈 집합이다.
- `rule`의 `eligible`: 진부분집합·시간 포함으로 `part_of` 200개는 `candidate`, 나머지는 빈 집합이다. 관련성 표본의 비중첩 쌍 간격은 2~5일로, **인접 창이 24시간 이하인 프로필**을 전제로 한다. 그보다 큰 창에서는 실제 규칙 채널 정답을 재산출해야 한다.
- `conversation`의 `eligible`: 각 생성 집합의 매 다섯 번째 사례에서만 `candidate`다. 총 80개이며 이 쌍은 같은 대화 식별자를 갖는다. 다른 사례는 빈 식별자다.

각 채널의 `excluded: [distractor]`는 구성원·규칙·대화 자격이 없음을 뜻한다. 의미·키워드 채널에서는 무관 후보가 반환될 수도 있으므로 하드 제외를 단정하지 않는다. 표본별 격리 그래프, 활성 사건, 신규 관계 없음, 후보 상한 2개 이상, 일치하는 색인 모델과 완료된 색인이 전제다. 가져오기 단계는 `members`의 상징 문자열을 그래프 내부 실제 원천/파생 식별자로 일관되게 치환해야 한다. 한 사례의 구성원이나 대화 식별자를 다른 그래프와 공유하지 않는다.

`part_of` 정답은 그 유형만 판정한다. 실제 서버가 추가로 허용한 `relates_to`를 `part_of` 음성이라는 이유만으로 오답 처리하지 않는다. `causes`와 무관 후보의 보류 정답은 별도 필드에 기록했다. 실측 실행기는 실제 후보 생성 경로의 채널·허용 유형과 `BuildInput` 입력을 보존하고 의미 정답과 비교해야 한다.

## 재현과 작성자 검증

저장소 루트에서 실행한다.

```sh
python3 spec/service/agent-context/reviews/rinf-06-acceptance/generate_samples.py --check
```

`--check`는 파일을 변경하지 않고 생성 결과와 바이트 단위로 비교한다. 재생성은 옵션 없이 실행한다. 생성기는 유형별 양음 100개, 총 400개, 사건 본문·사례 식별자 고유성, 모든 `part_of` 쌍의 실제 진부분집합·시간 포함을 확인한다. 작성자는 재생성과 `--check`의 일치를 확인했다. 이는 독립적인 의미 정답 검토나 모델 성능 검증을 대신하지 않는다.

현재 SHA-256은 다음과 같다. 본문·정답을 수정하면 재생성 및 검토와 함께 이 값을 갱신하고 호출 전 manifest에 다시 고정한다.

```text
samples.json        4011859de090ed8d4e0c893134a897ce0d766df879af4b18d3cb2f077ce6b8f7
gold.json           65239750e7d2fc78b77ddda3474bc9e926268fd2b7f5784ae08d3564612c7d59
generate_samples.py a5df0675d7a8846ae631d55b2324a236d6cbfc95eb642281f7368f9cda9aabec
```

## 검토·사용 제한

400개 사건 소재가 다르다는 사실만으로 통계적 독립성이 입증되지는 않는다. 네 개 본문 생성 틀과 유형별 시간·구성원 구조가 공유된다. `provenance.template_family`와 `structural_cluster`는 이 상관을 숨기지 않기 위한 정답 전용 메타데이터다. 독립 검토자는 본문 의미·라벨·방향뿐 아니라 같은 생성 틀의 상관이 SRS의 독립 단위 요건을 충족하는지도 검토해야 한다. 같은 의미의 재서술로 판정한 행은 별개 독립 단위로 세지 않는다. 유형별 인정 양성/음성이 100개보다 적으면 자료를 보강하기 전까지 자동 확정은 보류한다.

포함 관계를 명확히 표현한 양성·음성은 문구 단서가 강하여 실서비스의 모호한 기술보다 쉬울 수 있다. 이 자료로 현실 분포의 일반 성능이나 100개 생성 틀의 독립성을 주장하지 않는다. 유도 지시는 한 가지 문구 틀이고 무관 후보도 20가지 틀이므로 공격·잡음 다양성에 한계가 있다. 실제 판정 입력의 발췌 길이가 의미를 잘라 버리는지 확인해야 한다.

이 자료는 조정용이 아니다. 평가 전 독립 검토는 작성자가 아닌 검토자가 전체 400개를 대상으로 수행한다. 모델 응답을 본 뒤 라벨이나 본문을 조정하여 같은 holdout으로 재판정하지 않는다. 프로필·정답·본문·순서·생성 코드 지문을 실제 호출 전에 고정하고, 사례별 10회 반복을 독립 표본으로 더하지 않는다. 독립 검토·후보 검색·실제 두 조건 과업·전체 비용과 SRS 기준 판정은 별도 인수 단계이며 이 작성 작업의 완료로 대체되지 않는다.

## 독립 검토 상태

작성자와 별도 검토자가 400개 의미 쌍과 시간·구성원 조건을 모두 대조했다. `review-approval.json`에 승인 ID·입력/정답 SHA-256과 템플릿 상관 한계를 기록했다. gold의 `independent_review: pending`은 작성 당시 동결한 메타데이터이며 현재 승인은 별도 기록을 따른다. 이 메타데이터를 사후 변경해 고정 checksum을 바꾸지 않는다.
