# ARCH-05 구성 해석·기동 전 검증 모듈 시험

2026-10-15에 [ARCH-05](../development-plan/architecture.md#arch-05)를 구현하고 모듈 시험을 완료했다. 시작 커밋은 `646475f`, 브랜치는 `feat/new-implementation-architecture`다. 선행 ARCH-03·PERM-01은 완료 상태다. upstream이 없어 원격 대비 상태는 확인할 수 없다.

기준은 [배포 구성](../sdd/operations.md#배포-구성)·[목표 추가 구성](../sdd/operations.md#목표-추가-구성), [임베딩 제공자](../sdd/indexing.md#임베딩-제공자-전환), [인증](../sdd/authentication.md#oauth-discovery와-최초-인가)과 [진단 경로](../sdd/observability.md#경로권한다중-인스턴스)다. 기존 구성 코드의 존재·과거 시험을 새 완료 근거로 승계하지 않았다.

## 구현과 계약 대응

- [구성 패키지](../../../../internal/config/config.go)는 운영 SDD의 허용 키 38개를 한 번씩 읽은 뒤 값·조합을 검증한다. Compose·시험 전용 키와 토큰 수명·회전 상한 같은 고정 정책을 서버 구성으로 열지 않는다. `AllowedKeys` 반환 목록과 로드 결과는 다른 호출의 상태를 바꾸지 않는다. 업무 패키지 의존은 `plan` 하나다.
- Gemini 명시·HTTPS·모델·차원·HNSW 저장 타입·API 키·선택 tablespace 식별자, 검색 실행/후보/범위/기본값·적응형 조합, 플랜 JSON·정규화 중복, TLS direct/proxy·인증서 경로 조합·정규화 후 프록시 중복을 검증한다. 검색·관계 임계값의 NaN·Inf를 거부한다.
- 고정 HTTPS issuer와 독립된 `/mcp` resource, 원문 Origin 목록을 검증한다. OAuth 등록은 공개 client ID별 callback·resource 배열과 loopback 포트 정책을 형식화한다. 빈 목록·null·중복 이름/원소·미정의 필드·비루프백 HTTP·사용자 정보·fragment·다른 resource를 거부한다. 일반 loopback `same_ip`와 첫 Codex 시험의 `exact`는 등록 데이터로 전달한다. 실제 요청 callback 대조는 AUTH 후속 항목의 책임이다.
- 진단 루트의 절대·정규 경로와 공개/임시 경로 제외, 1~64자 ASCII 슬롯, INFO 기본·DEBUG/WARN/ERROR를 검증한다. 경로 검사로 실제 심볼릭 링크·소유권·권한·영속성·파일 잠금이 확인되는 것은 아니다. 실제 준비는 OBS-02와 OPS-02에서 수행한다.
- [서버 진입점](../../../../cmd/server/main.go)은 `configureAndRun`에서 전체 검증을 마친 구성만 자원 조립 함수에 전달한다. 잘못된 구성은 부분 값을 반환하지 않고 DB·제공자·수신 조립에 들어가지 않는다. 오류에는 고정 키·사유만 표시하고 URL·자격 증명·등록 원문·계정 표기를 복사하지 않는다. URL/JSON 해석 원인은 Unwrap으로 판별한다.
- 운영 SDD에 등록 JSON 필드·포트 정책·진단 경로 검사·38개 키 목록을 먼저 명시하고 [.env.example](../../../../.env.example)·[.env.prod.example](../../../../.env.prod.example)·[README](../../../../README.md)·[운영 안내](../../../../OPERATIONS.md)를 맞췄다. 예시 client ID는 합성 값이며 실제 호스트에서 확인한 ID로 교체해야 한다.
