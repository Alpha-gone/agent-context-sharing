# RINF-06 실제 측정과 채택 보류

## 판정

자동 확정 채택은 보류한다. 실제 제공자·시험 DB·모델의 도구 선택·서버 반영 경로를 측정했으나, 사전 계획의 독립 표본 수와 검증된 정답 조건을 충족하지 못했다. RINF-06 전체 완료의 근거로 삼지 않는다. 운영 구성과 기본 활성화는 변경하지 않았다.

## 자료와 독립 검토

[결과 묶음](rinf-06-final/summary.json)과 [측정 전 manifest](rinf-06-final/manifest.json)를 보존했다. 신규 사례 8건의 작성 정답을 숨기고 별도 모델 호출로 검토했으며, `n04`와 `n08`의 불일치는 측정 전에 제외했다. 이후 별도 코드 검토자가 측정 출력을 읽지 않고 정답·SRS를 대조했다. `n02`·`n07`의 강제 음성은 SRS의 ‘같은 주제나 대상’ 정의보다 좁고, `n03` 본문의 오전 9시와 후보 시작 시각 08:00도 불일치한다는 지적을 확인했다. 따라서 기존 6건의 일치 수를 의미 정확도로 인정하지 않으며, 결과를 본 뒤 정답을 바꿔 소급 채점하지 않는다. 모델 검토는 사람의 독립 검토와 동등하지 않다.

고정 입력은 한 후보·한 유형의 판정 검사 자료다. 실제 후보 스냅숏 전체를 `BuildInput`으로 생성한 자료와 같다고 주장하지 않는다. 확정 판정용 후속 자료에서는 이 출처 대응까지 고정해야 한다.

## 실제 측정

- 프롬프트 판 2, 신규 6건, 각 10회: 60호출 중 출력 검증 59회 통과. 초안 정답 일치는 45회지만 위 정답 충돌 때문에 품질 지표로 사용하지 않는다. 지연 중앙값 2,533.5ms, 최근접 순위 p95 3,510ms다. [호출 기록](rinf-06-final/measure-p2-10.jsonl)에 본문·근거·원시 응답은 없다.
- Gemini 문서 임베딩 13호출, 768차원, 입력 336토큰. 합성 본문에서 생성한 [벡터](rinf-06-final/vectors.json)를 보존해 후보 검색을 재현한다.
- [다섯 채널 검색](rinf-06-final/candidates-semantic.json)은 격리 DB의 여섯 사건 쌍과 공통 무관 후보를 사용했다. 의미상 양성이 확인된 `n01`·`n03`·`n05`의 기대 유형 자격은 의미·키워드·구성원 각각 3/3, 규칙 1/3, 대화 0/3이다. 이는 세 작은 합성 사례이며 채널의 일반 포함률이나 단독 기여가 아니다. 의미·구성원 채널은 무관 후보도 반환한다.
- [실제 과업 trace](rinf-06-final/flow.json)는 한 개의 예약 결함 합성 과업을 조건별 10회 실행했다. 기준선 모델은 `list_events`와 `confirm` 행동을 선택하고 실제 저장소 조회·확정을 수행했다. 서버 조건은 실제 후보 생성·모델 판정·검증·`apply`를 수행했다. 각 조건은 새 그래프에 같은 본문·구성원 구조를 만들며 DB 전체는 시험 종료 후 정리된다. 후속 실제 1홉 조회는 양쪽 모두 10/10에서 기대 사건을 반환했고 무관 사건은 반환하지 않았다. 반복 10회를 독립 과업 10개로 세지 않는다.

기준선은 직접 저장소를 호출하는 JSON 행동 실행기이며 일반 MCP 호스트의 인수는 아니다. 서버는 구성원 채널의 두 후보에 대해 여러 허용 유형을 검사하지만 기준선 과업은 `relates_to`만 요구한다. 지연은 사건 생성·큐 등록 이후부터 후속 조회까지이며 준비·색인 시간은 제외한다. 서버의 `RunOnce` 반환만으로 성공을 판정하지 않고 후속 조회 결과를 별도로 확인했다. `apply`의 승인 프로필은 이 격리 시험에만 주입했다.

## 실제 생성 입력의 추가 판정

정답 의미가 별도 검토에서 확인된 `n01`·`n03`·`n05`·`n06`은 실제 격리 DB의 다섯 채널 후보 스냅숏을 `BuildInput`에 넣어 각 10회 추가 호출했다. `n03`의 후보 시작 시각은 본문의 09:00에 맞췄고 상위 사건에 별도 원천 구성원을 추가해 진부분집합 조건을 충족했다. 실제 여러 후보·허용 유형을 그대로 전송했다. [생성 입력](rinf-06-final/generated-inputs.json)의 정확한 JSON 문자열과 [결과](rinf-06-final/generated-quality.json)의 입력 SHA-256이 일치함을 확인했다. 결과에는 본문·원시 응답을 넣지 않고 입력 지문만 기록했다.

기대 사건 쌍의 지정 유형·방향은 40/40에서 출력 검증과 정답 대조를 통과했다. 입력 20,033·출력 17,317토큰을 사용했다. 전체 출력의 모든 후보를 의미 채점한 결과가 아니며, 기존 탐색 사례를 재사용했으므로 새 독립 판정용 표본으로 간주하지 않는다. 원래 한 후보 고정 입력의 일치 수와 합산하지 않는다.

## 사용량과 비용

과업 기준선 입력·출력은 2,590·924토큰, 서버는 5,383·4,222토큰이다. 이 조건에서는 서버 추론 쪽 모델 사용량이 더 많았으며 비용 절감 근거가 없다. 임베딩은 별도 후보 검색에서 호출했고 구성원 채널만 쓰는 과업 비교에서는 호출하지 않았다.

11월 14일 확인한 공식 표준 요금의 OpenAI 입력·출력·30분 캐시 쓰기 상한 100만 토큰당 $0.10·$0.50·$0.125와 Gemini 텍스트 $0.20을 적용했다. 캐시 상세를 수집하지 않은 OpenAI 호출은 모든 입력에 $0.125를 적용한 보수적 환산이다. 모델 검토 1회, 판정 60회, 기준선 20회, 서버 10개 작업 회차(제공자 호출 수는 미계수), 임베딩 13회의 합산 환산은 **$0.011943075** (추가 생성 입력 판정 전)다. 이는 실제 청구액 확인이 아니며 요금제별 차이가 있을 수 있다. 최대 호출 수와 모델 최대 출력으로 예약한 보수적 예산은 승인된 $10 이내다. 인프라·준비·캐시 상세가 빠져 있으므로 전체 흐름 총비용과 총비용 절감은 미측정으로 유지한다.

추가 실제 생성 입력 40호출의 보수 환산 $0.011162625를 더하면 전체는 **$0.0231057**다. 실제 청구액·전체 흐름 총비용의 미확인 상태는 동일하다.

가격 근거: [OpenAI](https://developers.openai.com/api/docs/pricing), [Gemini](https://ai.google.dev/gemini-api/docs/pricing/).

## 재현과 검증

`internal/store/relation_evaluation_integration_test.go`는 `RINF_EVALUATION_FILE`, `RINF_CANDIDATE_REPORT`, 선택적인 `RINF_VECTOR_FILE`을 사용한다. `TEST_DATABASE_URL`과 `TEST_DATABASE_REQUIRED=1`을 설정하고 `go test ./internal/store -run '^TestRelationEvaluationCandidates$' -count=1 -v`로 실행한다. 결과 경로는 새 경로여야 한다. 실제 벡터를 쓰면 30행을, 의미 채널을 생략하면 24행을 요구한다. 파일을 쓰지 못하면 실패하며 빈 표본을 통과시키지 않는다.

실제 과업은 `RINF_FLOW_REPORT`와 `RELATION_INFERENCE_API_KEY`를 추가하고 `go test ./internal/store -run '^TestRelationEvaluationFlow$' -count=1 -v`로 재실행한다. 최대 기준선 40회(각 출력 1,024토큰 제한)와 서버는 출력 오류 재시도를 포함해 최대 20회 호출한다. API 호출에는 비용이 발생하며 이전 결과를 덮어쓰지 않는다. 새 보고서 경로를 사용한다. 기존 측정 결과는 모델의 비결정성 때문에 같은 숫자를 보장하지 않는다.

추가 판정은 `RINF_JUDGE_EVALUATE=1`과 새 결과 입력 경로 `RINF_GENERATED_INPUTS`를 명시한다. 이 경로는 네 개의 지정 사례에만 적용하고 40개 결과를 요구한다. 제공자 키와 별도 API 예산도 필요하다.

입력 검사는 `go run ./cmd/eval -check-relation-samples <inputs.json> -relation-gold <ground-truth.json>`이며 반복 측정은 기존 `-measure-relation` 경로를 사용한다. manifest의 60호출 제한과 별도 사전 예산 검사를 유지한다.

Go 1.27.3에서 두 평가 통합 경로가 필수 DB 설정으로 통과했다. 평가·추론·임베딩 패키지 회귀도 통과했으며 이 패키지 회귀에는 외부 API/DB 환경을 주입하지 않아 DB 미설정에 따른 건너뜀을 DB 인수로 세지 않는다. build·vet·gofmt를 확인했다. 초기 빈 후보 보고서는 JSON v2 필드 대소문자 오류로 무효이며 별도 파일에 보존했다. 포함 관계 구성원·원천 시각 fixture 오류도 수정 후 재실행했다. 최종 유효 후보 보고서는 `candidates-semantic.json`이다.

## 남은 완료 조건

SRS의 합격선은 후속 정식 평가용으로 확정했다. 검증된 새로운 독립 판정용 정답·입력과 충분한 독립 표본, 동등한 유형 범위의 다양한 실제 과업, 준비·임베딩·재시도·인프라를 포함한 전체 비용과 정식 결과 묶음이 남는다. 현재 결과는 실제 경로 측정의 증거이며 이러한 미측정 항목을 통과로 승격하지 않는다.
