## 구현과 발견 사항

- store의 비공개 풀·트랜잭션·질의 실행기를 유지했다. 핵심 그래프 저장 API는 graph_id 또는 생성할 그래프 모델의 식별자를 받고, 계정·서명 키는 각 식별 범위로 조회한다.
- 단건·묶음·쓰기 응답의 참조 조립을 attachReferences로 통일했다. 참조와 구성원은 간선에서 조립하며 반환한 속성·slice가 입력과 공유되지 않게 복제한다. source_ref의 외부 객체와 두 AGE property는 같은 변환기를 사용한다.
- 정점의 Context label과 관계의 상태·확정 주체·선택 시각·정규 방향을 모델로 검증한다. 속성 해석과 참조가 조립된 전체 모델 검증의 경계를 분리했다.
- StorageError는 고정된 작업명만 메시지로 제공하고 SQL·저장 본문·DB 상세를 노출하지 않는다. 원래 오류는 Unwrap으로 보존하여 PostgreSQL SQLSTATE·유일성 위반·취소 원인을 판별한다. 도메인 부재·상태·판 충돌·필드 오류의 식별은 유지한다. 상위 전송 계층의 오류 매핑 완성은 후속 MCP/웹 작업이다.
- 핵심 그래프·컨텍스트·관계 쓰기는 실제 트랜잭션과 중첩 저장점을 독립 예산으로 정리하고 실패를 반환한다. 단건·묶음·관계 읽기는 전달된 스냅숏과 읽기 자리를 재사용하며 접근 기록·종료 오류를 반영한다.
- 실제 폐기 시험에서 근거 무효 표시가 참조 없는 정점 속성만으로 전체 상태 전이를 검증하던 문제를 확인했다. 대상 식별자를 읽은 뒤 같은 트랜잭션의 공통 묶음 조립으로 참조를 완성해 검증하도록 수정했다.

## 실행 환경과 결과

- Go 1.27.1, macOS/arm64, pgx/pgxpool v5.10.0. Modern Go Guidelines의 Go 1.27 전체 목록과 공급자 공식 API·고정 판 모듈 소스를 확인했다.
- 전용 프로젝트 `data03-db-vduo5ioy`, 신규 합성 DB·볼륨·loopback 동적 포트만 사용했다. 실제 환경 파일은 읽지 않았다. 고정 Dockerfile의 캐시 허용 빌드와 새 DB의 001·009·010 적용을 수행했다.
- 실제 DB는 PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6, Linux/aarch64다.

첫 스냅숏 시험은 같은 최소 풀의 예약을 유지한 채 별도 쓰기 예약을 요청해 대기했다. 해당 시험 프로세스를 종료하고 후속 커밋을 독립된 저장소 연결에서 만들도록 수정했으며 90초 전체 제한을 적용했다. 이후 폐기 시험에서 발견한 참조 조립 문제도 수정하고 최종 범위 전체를 다시 통과했다.

## 완료와 제한

DATA-03을 완료한다. 다음은 [DATA-04](../development-plan/data.md#data-04)의 모든 질의 격리·저장 상태 검증이다. 전체 불변식/감사·인덱스/성능·온라인 계층·권한 정책·목표 OAuth/MCP 저장·외부 API·실제 호스트·운영 DB·amd64 runtime 인수는 수행하지 않았다.

DOX pass에서 소유권·구조·색인·요구사항·용어가 바뀌지 않아 DOX·SRS·SDD와 기존 SQL을 유지했다. 사용자 운영 Compose·IDE 변경은 보존했다. 커밋·푸시는 수행하지 않았다.
