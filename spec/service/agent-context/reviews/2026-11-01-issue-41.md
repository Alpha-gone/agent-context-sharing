# #41 Gemini Embedding 2 전환 채택 정리

## 결정

2026-11-01 사용자는 임베딩이 이미 Gemini로 전환되었으므로 이슈의 비교 평가(이전 로컬 모델 기준선, `gemini-embedding-2` 768·1536차원 후보의 검색 품질·지연·비용·호스트 자원 비교)를 수행하지 않기로 결정했다. 운영·개발 기본 구성은 `EMBEDDING_PROVIDER=gemini`, `gemini-embedding-2`, 768차원 `vector`로 채택한다. 비교를 실행하지 않았으므로 이전 구성 대비 품질·지연·비용 우위는 주장하지 않는다.

## 완료 조건 대조

| 이슈 완료 조건 | 처리 |
|------|------|
| 기준선·후보 구성, 데이터셋, 반복 조건과 채택 기준 기록 | 사용자 결정으로 비교를 수행하지 않음. 채택 구성과 결정 일자를 [임베딩 제공자 전환](../sdd/indexing.md#임베딩-제공자-전환)에 기록했다 |
| 품질·지연·비용·자원 비교와 검색/관계 제안 임계값 영향 | 비교는 수행하지 않음. 차원·압축·임계값 변경이 필요하면 `FR-AGENT_CONTEXT-162`의 [임베딩 순위와 임계값 비교](../sdd/evaluation.md#임베딩-순위와-임계값-비교) 실행기로 평가한다 |
| 외부 전송 정책, 제공자 인증, 호출 한도와 장애 처리 | 본문·질의 전송은 SRS가 확정한 유일한 경계 밖 경로다(`FR-AGENT_CONTEXT-141`·`TBD-AGENT_CONTEXT-054`). 인증·비밀·전송·장애 계약은 [임베딩 제공자 전환](../sdd/indexing.md#임베딩-제공자-전환)과 [제공자 장애 중 작업 확보 차단](../sdd/indexing.md#제공자-장애-중-작업-확보-차단)에 구현되어 있다. 이용 계층·과금·호출 한도는 운영자가 키·제공자 프로젝트에서 관리한다고 명시했다 |
| 재색인·DB 마이그레이션·전환 중 검색 영향·복귀 절차와 검증 항목 | [전환·복귀 경계](../sdd/indexing.md#전환복귀-경계)·`012_embedding_configuration.sql`·`test-transition.sh`가 담당한다 |
| 채택 또는 보류 결론과 근거, 후속 범위 | 채택. 구현·전환은 [2026-10-04 Gemini 전환](2026-10-04-gemini-embedding.md)·[2026-10-12 제공자 범위 축소](2026-10-12-embedding-provider-removal.md)에서 이미 완료되어 추가 구현 후속은 없다 |

## 변경

- [색인 설계](../sdd/indexing.md)의 「임베딩 제공자 전환」 절을 갱신했다.
  - "승인된 구현 계약이며 운영 적용 승인을 뜻하지 않는다"는 보류 문구를 채택 결정과 비교 미실행 사실로 바꿨다.
  - 768차원 `vector`를 개발·운영 기본값으로 명시하고, 변경이 필요할 때의 평가 경로를 연결했다.
  - "외부 전송 정책·이용 계층·비용 한도는 실제 API 검증 전에 확인한다"를 다음으로 정리했다. 외부 전송은 SRS 확정 경로이고, 이용 계층·과금·한도는 운영자 관리이며, 서버는 판정·속도 제한을 하지 않고, 429·장애는 기존 장애 계약으로 처리한다.
- SRS는 모델명을 배포 구성으로 두고 초기 제공자를 Gemini로 이미 확정했으므로 바꾸지 않았다. 코드·구성 예시(`.env.example`·`.env.prod.example`의 `gemini-embedding-2`·768·`vector`)는 이미 채택 구성과 같아 바꾸지 않았다.
- 과거 검토 기록(2026-10-04·2026-10-12)의 미검증 표기는 당시 시점의 증거로 보존한다. 추적표·DOX의 소유권과 구성은 바뀌지 않아 유지했다.

## 검증

- 문서 변경만 수행했다. 변경 Markdown의 링크·앵커(`OPERATIONS.md`, 평가·색인 절)와 공백을 확인했다.
- 인용한 구성 예시·마이그레이션·전환 시험 파일이 저장소에 있는지, 색인 패키지에 제공자 호출 속도 제한이 없는지를 확인했다.
- 실제 Gemini의 검색 품질·지연·비용은 측정하지 않았다(사용자 결정).
