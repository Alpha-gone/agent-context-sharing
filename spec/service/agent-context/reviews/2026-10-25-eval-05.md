## 비교 축과 입력

기본 실행은 `baseline,references,relations,global,evidence`의 인접 누적 단계만 허용한다. 단일 단계 측정도 가능하다. 모든 질의는 `scope=auto`를 요구하고, 비그래프 기준선은 진입 세 채널을 유지하면서 그래프 확장·전역 fallback·근거 선택을 끈다. 전역 단계와 마지막 근거 선택 단계는 그래프 범위가 같고 선택 기능만 다르다. 회차 안에서 조건 순서를 순환하며 조건·회차별 새 그래프에서 같은 입력·모델·예산을 측정한다.

`-compare-index-targets -stages=references`와 같이 고정 단계 하나를 명시하면 `all_layers`와 `without_source`를 별도로 비교한다. `-index-targets` 및 다른 평가 모드와의 동시 지정은 거부한다. 대상별 저장소·작업자를 만들고 매 회차 전체 입력을 새로 적재·색인하므로 이전 색인 벡터가 비교에 섞이지 않는다. 양쪽에 원천·참조·사건 관계·근거 입력을 그대로 보존한다.

`-prepared-input <디렉터리>`는 EVAL-02의 준비 메타데이터와 실제 기억·평가 파일 checksum을 대조한 뒤 기억 그룹별 그래프와 질의·독립 단위를 연결한다. 같은 대화 문항은 같은 독립 단위로 보존한다. 질의 없는 준비 그룹은 실행 그룹 수와 구분한다. 정답 문자열·원본 매핑은 검색 입력으로 사용하지 않는다. 원본 유형과 `annotated`·`unmeasured`·`not_applicable` 상태는 비식별 표본에 남긴다. 주석 없는 문항과 답변 유보 문항의 재현율·순위·정답당 문자는 `-1`이며 문자·지연·채널은 실측한다. 그룹 결과 합산에서도 미주석 문항의 문자를 정답당 문자 분모·분자에 넣지 않는다.

생략한 조회 시각은 실행 시작 시각으로 고정한다. 준비 정책은 새 그래프의 전체 색인 후 별도 warmup 없이 측정하는 방식이며 DB/OS 공유 캐시를 비우지는 않는다. 실제 준비 시간·문서 임베딩 HTTP 시도 수·현재 모델 벡터 행 수·`pg_column_size(embedding)`의 바이트 합계를 조건·회차별로 기록한다. 준비 시간과 검색 시간은 분리한다. 벡터 열 바이트에 테이블·색인·WAL·금액은 포함되지 않는다.

사용 사례별 독립 단위 대응 지표와 p95 500ms·채널 실패를 확인한다. 유의한 개선이 없거나 품질/효율 회귀·지연 초과·실패가 있으면 기본 활성화 후보를 거부한다. 개선 관찰도 비용 비례성과 공개 효과 검증 전에는 보류하며 결과의 `default_activation`은 false다. 색인 비교는 재현율의 유의한 손실·관찰되지 않은 손실·표본 부족을 구분한다. 운영 기본값은 바꾸지 않았다.

## 실행 결과와 실패 이력

최종 고유 시험 **352건**(최상위 **108건**, 하위 사례 포함)이 실패·건너뜀 없이 통과했다. 모듈 **344건**과 실제 CLI **8건**이며 중간·중복 실행은 더하지 않았다.

- 모듈: Go 1.27.1, `go test -race -count=1 -json -timeout=240s -skip Integration ./cmd/eval`. 축 혼합·단계 생략·옵션 충돌의 입력 전 거부, 조회 시각 고정, 조건 순환, 실패·취소 중단, 준비 checksum·독립 단위·주석 매핑, 미측정 분모와 기본값 승격 거부를 검증했다.
- 실제 CLI: `TEST_DATABASE_URL`·`TEST_DATABASE_REQUIRED=1`을 설정하고 `TestControlledComparisonsIntegration`의 graph/index/prepared/정리 실패와 `TestEvaluationCommandSignalCleansGraphIntegration/index`를 race 조건으로 실행했다. 그래프 비교 50개·색인 비교 20개·준비 그룹 비교 40개의 전용 그래프가 정상 측정 후 소프트 삭제됐다. 기준선 그래프/전역 채널 비활성, 원천 저장 보존, 문서 요청 수와 벡터 행/바이트, 미주석 문항·독립 단위 수를 확인했다. 두 정리 실패에서 정상 보고서 생성을 거부했고 색인 비교의 종료 신호에서도 그래프를 정리했다.
- 정적 검사: `GO_BINARY=/Users/alphagone/sdk/go1.27.1/bin/go sh check-go.sh`의 의존성 검증·전체 build·vet·gofmt가 통과했다. `git diff --check`도 통과했다.
- 실제 준비 파일: LongMemEval_S 500문항/471과업, LoCoMo 1,251문항/10대화, 자체 보완 6문항/6과업의 checksum·집계·유형·주석·독립 단위 연결을 CLI에서 확인했다. DB 설정을 비운 상태에서 입력 검증을 마치고 DB 연결 전에 의도적으로 중단했다. 검색·효과 측정 건수에는 포함하지 않았다.

첫 모듈 실행은 샌드박스의 로컬 포트 개설 제한으로 중단되어 대역 서버 실행 권한으로 재검증했다. 초기 CLI 시험의 검증용 원천 집계 SQL에서 AGE 연산자 스키마와 `context_graph.graph_id`를 누락하여 수정했다. 실제 공개 파일 검사에서는 답변 유보의 `not_applicable`과 자체 보완 데이터셋의 `own-supplement-v1` 식별자를 확인하여 어댑터·회귀 시험을 보완했다. 이후 최종 모듈·CLI·정적 검사를 통과했다.

전용 컨테이너 `acs-eval05-db`에 정식 마이그레이션 6개를 적용했다. 개발 이미지의 PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6과 vector 768 구성을 사용하고 Gemini는 로컬 HTTPS 대역만 호출했다. 유료 모델 호출이나 새 공개 데이터 다운로드는 수행하지 않았다. 시험 후 연결 종료를 확인하고 자신이 생성한 컨테이너·볼륨을 정리했다.

## 남은 조건과 작업 경계

공개 준비 기억은 원천 중심 입력이므로 에이전트가 고정한 파생·사건·전역 요약과 실제 모델 호출에 의한 효과 실증은 별도 실행이 필요하다. 자체 보완의 상태 변경·격리·공격·복구 시나리오 실행은 EVAL-07/08이 소유한다. 이번 인수는 비교 실행 기능의 동작을 검증했으며 합성 표본으로 공개 품질 개선을 주장하지 않는다.

`-check-manifest`는 사전 검사 모드로 유지한다. manifest 자동 실행 적용·입력/구성 대조, 총비용과 최종 채택·실패 공개는 EVAL-12/13에서 완료한다. 다음 권장 작업은 EVAL-06의 라우팅·일관 읽기·홉 구현 비교다.

DOX pass에서 새 소유 경계나 패키지·환경 변수·마이그레이션 변경이 없음을 확인하여 기존 DOX를 유지했다. 평가 SDD·개발 계획·진입 상태·서비스 색인·요청/공식 근거 기록을 갱신했다. 변경 Markdown 8개·로컬 링크/앵커 432개·계획 ID 124개와 108개 완료 상태를 확인했다. 현재 브랜치 `feat/evaluation`에는 upstream이 없고 변경은 미커밋 상태다. 개인 `.idea` 두 파일은 제외한다.
