# Diagram Creator

## 개요

문서의 근거를 바탕으로 관계 파악에 필요한 Mermaid 다이어그램을 작성하고 검증한다. 다이어그램은 본문을 보충해야 하며, 입력에 없는 구성 요소, 상태, 관계 또는 기술 결정을 임의로 추가하지 않는다.

## 필수 입력

- 다이어그램을 삽입하거나 수정할 대상 Markdown 문서를 읽는다.
- 대상 문서가 참조하는 요구사항, 설계 문서, 용어집과 적용되는 `AGENTS.md`를 확인한다.
- 기존 다이어그램을 수정할 때 본문에서 사용하는 명칭과 유효한 관계를 보존한다.

입력끼리 충돌하거나 관계 방향, 상태 전이 조건, 데이터 소유권이 불명확해 결과가 달라질 수 있으면 임의로 선택하지 말고 선택지와 영향을 사용자에게 보고한다.

## 작업 절차

1. 시각화할 질문과 독자를 한 문장으로 정의한다.
2. 입력에서 노드, 관계, 방향, 조건, 경계와 근거 식별자를 추출한다.
3. 문장이나 표보다 다이어그램이 관계 이해를 실질적으로 개선하는지 판단한다.
4. 아래 선택 기준으로 가장 작은 Mermaid 유형을 선택한다.
5. 본문 용어를 그대로 사용하고 안정적인 영문 식별자로 다이어그램을 작성한다.
6. 다이어그램 앞에 목적과 범위를, 뒤에 핵심 흐름, 예외, 경계와 설계 판단을 설명한다.
7. 문서의 요구사항 ID 또는 다른 근거 식별자를 앞뒤 문단이나 표에 연결한다.
8. Mermaid 구문, 본문과의 의미 일치, 중복, 누락과 가독성을 검증한다.
9. 적용되는 프로젝트 규칙에 따라 맞춤법, 작업 기록과 DOX pass를 수행한다.

## 다이어그램 선택

| 표현 대상 | Mermaid 유형 | 선택 기준 |
| :- | :- | :- |
| 서비스·사용자·외부 시스템 경계 | `flowchart` | 시스템 컨텍스트와 의존 방향을 보여준다. |
| 구성 요소·데이터·책임 관계 | `flowchart` | 세 개 이상의 요소 관계나 분기 경로를 보여준다. |
| 요청·응답·비동기 상호작용 | `sequenceDiagram` | 시간 순서, 참여자, 정상 흐름과 중요한 실패 흐름을 보여준다. |
| 생명주기와 전이 조건 | `stateDiagram-v2` | 시작·종료 상태, 허용 전이와 조건을 보여준다. |
| 영속 데이터 관계 | `erDiagram` | 엔터티, 주요 속성, 선택성·다중성과 관계를 보여준다. |
| 배포 단위·인프라·네트워크 경계 | `flowchart` | 런타임과 저장소의 배치·연결을 보여준다. |

한 단계 관계, 두 항목의 단순 비교, 순서가 중요하지 않은 짧은 목록은 문장이나 표를 사용한다. 같은 사실을 설명하는 다이어그램을 반복하지 않는다. 한 다이어그램이 여러 질문을 섞어 복잡해지면 책임이나 시나리오별로 분리한다.

## 작성 계약

- 코드 블록 언어는 `mermaid`로 지정한다.
- 노드 식별자는 영문·숫자로 안정적으로 작성하고, 표시 문구는 본문의 용어와 일치시킨다.
- 방향 화살표는 실제 호출, 데이터 이동, 소유 또는 상태 전이 방향과 일치시킨다.
- `sequenceDiagram`은 참여자별 책임과 호출 순서를 보존하고, 중요한 성공·실패 분기는 `alt`, 반복은 `loop`, 선택적 흐름은 `opt`로 표현한다.
- `stateDiagram-v2`는 모든 전이를 `현재 상태 --> 다음 상태: 조건 또는 사건`으로 읽을 수 있게 작성하고, 정의되지 않은 우회 전이를 만들지 않는다.
- `erDiagram`은 문서에 근거가 있는 엔터티와 핵심 속성만 포함하고, 관계의 선택성과 다중성을 임의로 확정하지 않는다.
- 기술 스택, 배포 단위, 저장소 제품이 미확정이면 논리 요소로 표현하고 특정 제품명을 추가하지 않는다.
- 색상, 테마, 아이콘 같은 장식은 의미 구분에 필수적이지 않으면 사용하지 않는다.

## 본문 연결

각 다이어그램은 다음 순서를 따른다.

1. 앞 문단: 다이어그램이 답하는 질문, 범위와 제외 대상을 설명한다.
2. Mermaid 코드 블록: 본문에서 정의한 요소와 관계만 표현한다.
3. 뒤 문단: 핵심 흐름, 예외, 트랜잭션 또는 책임 경계, 미정 사항을 설명한다.
4. 근거 연결: 관련 요구사항 ID, 제안 ID 또는 문서 절을 문단이나 표에 연결한다.

다이어그램만으로 요구사항이나 설계 판단을 대신하지 않는다. 다이어그램에 표시하기 어려운 제약이나 오류는 뒤 문단에 명시한다.

## 검증

### 구문 검증

- 모든 ` ```mermaid ` 코드 블록이 닫혔는지 확인한다.
- 선언한 Mermaid 유형의 문법만 사용했는지 확인한다.
- 식별자 중복, 잘못된 화살표, 닫히지 않은 분기와 지원되지 않는 문자를 확인한다.
- 저장소에 Mermaid 렌더러나 린터가 있으면 실행하고, 없으면 정적 구조 검증 결과와 한계를 보고한다.

### 의미 검증

- 모든 노드, 참여자, 상태와 엔터티가 본문 또는 입력 근거에 존재하는지 확인한다.
- 모든 관계와 전이 방향이 본문의 설명과 일치하는지 확인한다.
- 본문에 중요한 예외나 분기가 다이어그램에서 누락되지 않았는지 확인한다.
- 다이어그램에만 존재하는 결정, 상태, 데이터 속성 또는 기술 선택이 없는지 확인한다.
- 용어, 대소문자, 서비스명과 상태명이 문서 전체에서 일관적인지 확인한다.

## 산출물

- 대상 Markdown 문서 안의 Mermaid 다이어그램
- 다이어그램 앞뒤의 설명 문단과 근거 연결
- 검증 결과와 근거가 없어 남긴 미정 사항

다이어그램만 별도로 요청받아 대상 문서가 없으면 Mermaid 코드 블록과 이를 이해하는 데 필요한 최소 설명을 함께 제공한다.

## 품질 기준

- 다이어그램이 명확한 질문 하나에 답해야 한다.
- 본문과 다이어그램이 같은 구조, 흐름과 상태를 설명해야 한다.
- 모든 요소와 관계를 입력 근거로 추적할 수 있어야 한다.
- 단순한 관계를 불필요하게 시각화하거나 같은 정보를 반복하지 않아야 한다.
- 렌더링하지 못한 경우 이를 성공으로 단정하지 않고 수행한 정적 검증과 남은 한계를 구분해야 한다.
