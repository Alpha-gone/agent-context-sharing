## 구현과 조립 계약

- [공유 검색 타입](../../../../internal/model/flow.go)은 후보·홉 결과·검색 입력·흐름·자원 집계를 저장 방식과 무관한 값으로 정의한다. 검색·저장소의 기존 이름은 가능한 범위에서 alias로 유지했다. 라우팅 판정은 `search`에 남으며 평가 실행기의 신호 수집도 명시적 변환으로 맞췄다.
- [검색 인터페이스](../../../../internal/search/search.go)는 `model`만 import한다. 저장 질의·질의 임베딩·스냅숏 읽기를 주입받고 DB 핸들을 받지 않는다. [저장소 경계](../../../../internal/store/search_boundary.go)는 기존 격리·홉 처리를 재사용하면서 내부 계측을 제외한 결과를 전달하고 스냅숏 종료를 `defer`로 소유한다. 실제 연결·취소·반환의 DB 인수는 ARCH-04 이후에 수행한다.
- [MCP 주입 계약](../../../../internal/mcp/dependencies.go)은 등급·플랜·그래프/노드/홉/관계 읽기·흐름 검색·등록/결합·기능별 쓰기·멱등성 실행·진단을 나눈다. 인증 계정과 검증된 client의 등록 결합, 업무 감사 전용 판단 입력과 저장 트랜잭션의 쓰기 원자성을 계약에 명시했다. `Dependencies.Validate`는 의존 구현을 호출하지 않고 조립 누락을 거부한다.
- [진단 이벤트](../../../../internal/diagnostic/event.go)는 여섯 종류와 수준을 독립적으로 유지하고 UTC·고정 코드만 수락한다. `Reporter`는 종류를 조립 시 고정하고 업무 패키지가 선언한 `RecordDiagnostic` 인터페이스를 구현한다. 임의 객체·error·URL·헤더·본문·자격을 전달하는 필드는 없다. 코드 모양 검사는 입력 문자열을 로그에 넣어도 된다는 허가가 아니며 생성자는 고정 코드를 사용해야 한다.
- 검색 흐름·웹 세션 검증·저장소 상태 확인에 선택적 진단 인터페이스를 연결했다. 수신기 거부는 기존 성공/오류 결과를 바꾸지 않으며 인증 자격 실패와 인증 저장소 장애를 다른 코드로 전달한다. `SetDiagnostics`는 요청·작업자 시작 전 조립 때만 호출한다.
- [조립 타입 대조](../../../../cmd/server/dependency_contract_test.go)는 저장소·색인 작업자·검색기·플랜·기록기와 소비자의 14개 인터페이스 결합을 컴파일로 확인한다. 등록·쓰기·멱등성 어댑터와 실제 서버 주입은 AUTH·MCP·ARCH-06의 후속 구현 범위다.

이번 기록의 실제 업무 패키지 import는 다음과 같다. [경계 시험](../../../../cmd/server/boundary_test.go)은 이 표를 별도 허용 정본으로 사용하지 않고 SDD의 두 표를 직접 읽는다.

| 패키지 | 실제 프로젝트 내부 import |
|---|---|
| model | 없음 |
| plan | model |
| store | model, plan |
| perm | model |
| index | model, store |
| authz | model, store |
| search | model |
| web | model, perm, plan, store |
| config | plan |
| mcp | model, perm, plan |
| diagnostic | 없음 |

DB 풀·트랜잭션·질의 실행기는 비공개다. 마이그레이션은 업무 패키지 밖의 도구로만 예외 처리하며, 관리 연산·웹 감사의 저장·보존 정리는 계속 `store` 트랜잭션에 남는다. 진단 이벤트 수신기에 업무 감사 저장을 옮기지 않았다.

## 새 실행 증거

Go 1.27.1 SDK `/Users/alphagone/sdk/go1.27.1/bin/go`를 사용했다. 구현이 준비된 ARCH-03 모듈 시험 시점에 관련 시험을 작성·보강·실행했다.

```sh
# 초기 묶음: search 빌드 실패, MCP·진단은 패키지별 통과
go test -count=1 -race -json ./internal/search ./internal/mcp ./internal/diagnostic
# 호출부·대역 타입 정합화 후 검색 재실행
go test -count=1 -race -json ./internal/search
go test -count=1 -race -json ./cmd/server -run 'TestPackageDependenciesMatchDesign|TestDatabaseHandleStaysInStore|TestBoundaryRulesRejectViolations|TestStoreExportsNoDatabaseHandle|TestHandleDetectorRejectsExports'
go test -count=1 -race -json ./internal/authz ./internal/store -run 'TestVerifyDiagnosticDropPreservesCredentialError|TestPingDiagnosticDropPreservesUninitializedError'
GO_BINARY=/Users/alphagone/sdk/go1.27.1/bin/go sh ./check-go.sh
```

- 최종 유효 결과의 시험·하위 시험 103건 통과: 검색 69건, MCP·진단 23건, 경계 9건, 인증·저장소 진단 주입 2건. 최종 패키지별 결과의 실패·건너뜀은 0건이며 race 검사 통과. 초기 묶음 명령은 search 빌드 실패로 종료 코드 1이고, 이후 검색 재실행·경계·진단 주입·공통 검사 명령은 각각 종료 코드 0이다.
- 초기 전체 빌드에서 평가 신호의 타입 변환 누락, 첫 모듈 시험에서 검색 대역의 기존 HopResult·RouteSignals 타입을 발견했다. 호출부·대역을 정합화한 뒤 검색 범위를 다시 실행해 69건 통과했다. 첫 명령의 search 빌드 실패를 전체 통과로 사용하지 않았으며 MCP·진단의 통과 결과만 포함했다.
- SDD 표와 실제 import의 양방향 일치, 실제 열한 패키지·무순환, 누락/추가 패키지·의존의 위반 표본과 DB 드라이버 직접 의존·export된 핸들 타입을 검사했다. 진단 종류/수준·UTC·비정형 문자열 거부·수신기 누락, MCP 조립 누락/무부작용과 검색 스냅숏 callback의 결과·오류·집계 보존을 확인했다.
- 공통 검사 스크립트의 모듈 체크섬·최소 의존성 실행 파일·전체 `go build -mod=readonly ./...`·`go vet -mod=readonly ./...`·SDK `gofmt -l .` 통과. 실제 DB·외부 제공자·원격 CI·전체 저장소 시험은 실행하지 않았다.

SDK 전송·14종 도구·OAuth·등록 저장·쓰기 어댑터·여섯 파일의 대기열/인스턴스·기동 외피/회전·보존은 이번 항목의 구현 완료 대상이 아니다. 파일 저장 완료나 실제 호스트 지원을 주장하지 않으며 해당 분야 계획에서 계속 검증 대기로 유지한다.
