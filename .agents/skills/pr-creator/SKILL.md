# PR Creator

## 개요

현재 브랜치의 기존 커밋, 검증 결과와 연결 이슈를 근거로 커밋을 원격에 게시하고 Pull Request를 준비·생성·갱신한다. 새 브랜치를 만들거나 다른 브랜치로 전환하지 않으며, 로컬 파일 변경과 커밋은 해당
작업 소유 스킬에 맡긴다.

PR 제목과 본문을 작성하기 전에 [PR 작성 기준](references/pr-structure.md)을 읽고 적용한다.

## 필수 입력

| 입력                             | 사용 방법                                      |
|:---------------------------------|:-----------------------------------------------|
| 현재 Git 저장소, 원격과 브랜치   | 변경의 사실 기준으로 사용한다.                 |
| GitHub 기본 브랜치               | 비교 기준과 PR base로 사용한다.                |
| `base...HEAD` 커밋과 diff        | 이미 커밋된 브랜치 변경을 확인한다.            |
| staged, unstaged, untracked 변경 | 게시 전 작업 트리가 깨끗한지 확인한다.         |
| 연결 GitHub 이슈                 | 범위, 인수 조건과 완료 처리 키워드를 결정한다. |
| 실행한 검증 결과                 | PR에 성공·실패·미실행 상태를 정확히 기록한다.  |

현재 브랜치가 기본 브랜치이거나 저장소·원격이 불명확하면 푸시와 PR 생성을 진행하지 않고 상태를 보고한다.

## 작업 절차

### 1. 저장소와 원격 상태 확인

1. Git 루트, 현재 브랜치, 원격 URL과 작업 트리 상태를 확인한다.
2. GitHub 연결 도구로 저장소와 기본 브랜치를 확인한다.
3. 현재 브랜치의 upstream을 확인한다. 추적 브랜치가 있으면 ahead/behind를 계산하고, 뒤처져 `pull` 가능한 경우 사용자에게 경고한 뒤 실행 여부를 확인한다.
4. upstream이 없으면 그 사실을 보고하고 기본 브랜치 및 예정된 push ref와 비교한다. upstream이 없는 상태를 최신 상태로 단정하지 않는다.
5. 원격 조회가 가능하면 승인 없는 `pull` 없이 fetch로 비교 기준을 갱신한다.

### 2. 커밋과 작업 트리 확인

다음 범위를 섞지 말고 각각 확인한다.

```text
기본 브랜치...HEAD의 커밋과 diff
index에 staged된 diff
작업 트리의 unstaged diff
untracked 파일 목록과 내용
```

- PR 대상은 기본 브랜치와 현재 브랜치 사이의 기존 커밋과 diff로 한정한다.
- uncommitted 변경이 있으면 자동으로 스테이징하거나 커밋하지 않고 해당 작업 소유 스킬의 미완료 변경인지 확인한다.
- 관련 없는 사용자 변경을 보존하고 push 또는 PR 범위에 포함됐다고 설명하지 않는다.
- 비밀번호, 토큰, 개인 식별 정보, 원본 데이터, 대용량 결과물과 생성 산출물의 포함 가능성을 점검한다.
- 바이너리나 내용을 안전하게 검토할 수 없는 파일은 자동 포함하지 않는다.

### 3. 이슈와 기존 PR 확인

1. 같은 head 브랜치의 열린 PR과 닫힌 PR을 조회해 중복 생성을 방지한다.
2. 연결 이슈를 재조회하고 실제 변경이 범위와 인수 조건을 충족하는지 비교한다.
3. 병합으로 이슈 전체가 해결되면 `Closes #<번호>`, 일부 또는 간접 관련이면 `Refs #<번호>`를 선택한다.
4. 검증되지 않았거나 미구현인 체크리스트는 완료로 표시하지 않는다.
5. 후속 작업은 기존 이슈를 먼저 검색하고, 담당 이슈가 없을 때만 `spec-issue-creator` 형식의 초안을 제시한다.

### 4. 검증과 PR 초안 작성

1. 변경 영역의 기존 검증 계약을 찾아 승인된 범위에서 실행한다.
2. 성공, 실패와 미실행 검증을 구분하고 명령과 결과를 기록한다.
3. `references/pr-structure.md`에 따라 제목과 본문을 작성한다.
4. diff에 없는 변경이나 실행하지 않은 검증을 PR 본문에 포함하지 않는다.
5. 커밋 SHA와 포함 파일은 게시 범위 검증에 사용하되 PR 본문에 커밋별 설명이나 별도 커밋 목록을 작성하지 않는다.

### 5. 실행 승인

다음 내용을 한눈에 검토할 수 있게 제시하고 명시적인 승인을 받는다.

| 항목           | 제시할 내용                                   |
|:---------------|:----------------------------------------------|
| 포함 커밋      | push 및 PR에 포함할 커밋 SHA와 파일 목록      |
| 작업 트리      | staged, unstaged, untracked 변경과 처리 판단  |
| 푸시           | 원격과 현재 branch ref                        |
| PR             | base, head, 제목, 본문, 라벨, 연결 이슈       |
| 이슈 수정 후보 | 실제로 충족된 체크리스트와 수정할 정확한 문구 |

승인은 제시한 파일, 커밋, 푸시와 GitHub 변경에만 적용한다. 범위가 달라지면 다시 승인을 받는다.

### 6. 승인된 변경 게시

1. 작업 트리에 uncommitted 변경이 있으면 push와 PR 갱신에 미치는 영향을 확인하고, Issue 작업의 미완료 변경이면 게시를 중단한다.
2. 승인된 기존 커밋과 현재 브랜치를 일반 push한다. 별도 요청과 승인 없이 force push하지 않는다.
3. push된 head를 확인한 뒤 GitHub 연결 도구를 우선 사용해 PR을 생성하거나 기존 PR을 갱신한다.
4. PR의 URL, 상태, base, head, 제목, 본문, 라벨, 커밋, 파일과 연결 이슈를 재조회한다.
5. 이슈 본문이나 체크리스트 수정은 승인된 정확한 항목만 반영하고 재조회한다.
6. PR 생성만으로 이슈를 직접 닫지 않는다. `Closes`가 포함된 PR이 기본 브랜치에 병합될 때 자동 종료되게 한다.

## 기존 PR 처리

- 같은 head와 base의 열린 PR이 있으면 새 PR을 만들지 말고 기존 PR의 상태와 URL을 보고한다.
- 기존 PR 갱신이 요청 범위에 포함되면 변경할 제목, 본문, 라벨을 제시하고 승인 후 수정한다.
- 닫힌 PR만 있으면 재사용 가능 여부를 단정하지 말고 현재 변경과 종료 사유를 비교한다.

## 실패 처리

| 상황                                   | 처리                                                                                |
|:---------------------------------------|:------------------------------------------------------------------------------------|
| dirty worktree에 관련 없는 변경이 있음 | 파일별로 분리하고 관련 없는 변경을 보존한 채 게시 판단에서 제외한다.                |
| Issue 작업의 미커밋 변경이 있음        | 해당 작업 소유 스킬에서 검증·커밋하도록 게시를 중단하고 남은 파일을 보고한다.       |
| 원격 또는 GitHub 조회 실패             | 최신 상태, 중복 PR 없음 또는 push 성공을 단정하지 않는다.                           |
| 검증 실패                              | 실패 내용을 PR 초안에 기록하고 성공으로 표시하지 않는다. 게시 여부를 다시 확인한다. |
| push 실패                              | PR을 만들지 않고 오류와 로컬 커밋 상태를 보고한다.                                  |
| PR 생성 후 재조회 실패                 | 반환된 URL과 미검증 필드를 구분해 보고한다.                                         |
| 비밀 정보 가능성이 있음                | push와 PR 생성·갱신을 중단하고 커밋, 파일과 근거를 보고한다.                        |

## 제외 범위

- 새 브랜치 생성 또는 다른 브랜치로 전환
- 파일 스테이징, 로컬 커밋 생성 또는 기존 커밋 재작성
- 사용자 승인 없는 푸시, PR·이슈 생성 또는 수정
- 검증하지 않은 항목의 성공 표기
- force push, 이슈 직접 종료 또는 관련 없는 변경 정리

## 검증

- 작업 트리 상태와 기본 브랜치 대비 커밋·파일 목록을 확인한다.
- 각 커밋의 검증 근거와 Issue 작업 단계가 일치하는지 확인한다.
- push 후 원격 head SHA가 로컬 HEAD와 일치하는지 확인한다.
- PR 생성 후 GitHub에서 base, head, 제목, 본문, 라벨, 커밋, 파일과 연결 이슈를 재조회한다.
- Markdown 링크, 체크리스트, 맞춤법과 자연스러운 한국어 표현을 확인한다.
