## 현재 구현과 잠금 판단

현재 공개 파생 갱신·근거 폐기·대체는 `da8fd0b` 이후 같은 그래프 행을 AGE 쓰기와 대상 읽기 전에 잠근다. 무효 전파는 그 잠금을 유지한 채 대상 집합·본문·판을 읽는다. 파생 일반 갱신이 참조 전이 자문 잠금을 쓰지 않아도 그래프 행에서 직렬화되므로, 보고된 대상 조회 후 갱신의 끼어들기는 공개 API로 발생하지 않는다.

이슈가 제안한 대상별 정렬 정점 잠금 대신 현재의 그래프 선행 직렬화를 유지한다. 같은 그래프의 모든 관련 쓰기를 이미 직렬화하고 있어 추가 정점 잠금은 중복된다. 그래프를 정점 뒤에서 얻는 역순 경로나 자동 재시도는 추가하지 않았다. 독립 구조·코드 검토에서도 같은 판단을 확인했다.

공개 API를 우회하는 직접 AGE 변경은 별개다. 기존 세 방어 시험은 그 변경을 끼워 넣어 조건부 SET 실패가 폐기·대체 전체를 롤백하고, 재시도가 최신 본문을 보존하는지 검증한다. 이 검사를 제거하지 않았다. 전파가 먼저 커밋되면 이전 판을 지정한 파생 갱신의 충돌은 정상 낙관적 동시성 계약이다.

## 경합 회귀 보강

[기존 공개 직렬화 시험](../../../../internal/store/evidence_invalidation_integration_test.go)의 `TestEvidenceInvalidationWriteSerializationIntegration`을 원천 폐기·파생 폐기·대체의 세 사례로 확장했다. 각 사례는 정식 마이그레이션을 적용한 독립 DB를 사용한다.

- 직접 파생 2개와 그중 하나를 근거로 한 간접 파생 1개를 준비한다.
- 바깥 트랜잭션에서 직접 파생의 본문과 판을 갱신한 뒤 커밋을 보류한다.
- 다른 연결에서 폐기·대체를 시작하고 실제 연결 간 대기를 `pg_blocking_pids`로 확인한다.
- 갱신 커밋 뒤 폐기·대체도 커밋되는지, 최신 본문 보존과 정확한 판 증가·직접 무효 표시·간접 파생 불변을 대조한다. 연결·예약 반환도 확인한다.

대조를 위해 `changeContextDeletion`과 `createContext`의 그래프 선행 잠금만 제거한 임시 Go overlay를 사용했다. 저장소 제품 파일은 바꾸지 않았다. 이 대조에서는 세 사례 모두 현재 판 2의 충돌로 실패하여, 시험이 보고된 잘못된 거부를 검출함을 확인했다. 원래 구현에서는 세 사례가 2.772초에 모두 통과했다.

## 검증

Go 1.27.1, 고정 PostgreSQL/AGE/pgvector 이미지의 전용 컨테이너와 `TEST_DATABASE_REQUIRED=1`·`TEST_DATABASE_URL`을 사용한다.

```sh
go test -race -count=1 -run '^TestEvidenceInvalidationWriteSerializationIntegration$' ./internal/store
# 그래프 선행 잠금 제거 대조: 세 사례 실패가 기대 결과다.
go test -overlay=/private/tmp/issue149-overlay.json -race -count=1 -run '^TestEvidenceInvalidationWriteSerializationIntegration$' ./internal/store
go test -race -count=1 -json -timeout=15m ./internal/store
go build ./...
go vet ./...
gofmt -l .
```

필터 없는 전체 `store` 패키지는 **1,679건(최상위 374건)**이 430.040초에 실패·건너뜀 없이 통과했다. 기존 파생 수명주기·방어적 전파 롤백·색인·격리·검색 회귀를 포함한다. build·vet·gofmt·문서 링크/앵커·diff 검사와 독립 읽기 전용 검토도 통과했다.

시험별 DB 잔류 없음과 생성 ID를 확인한 뒤 이번 작업의 컨테이너·익명 볼륨만 정리하고 기존 세 컨테이너·개인 IDE 파일은 보존했다. 제품 코드·스키마·오류 계약은 유지하며 수명주기 SDD의 직렬화 설명과 testing SDD의 인수 표본만 정합화했다. DOX의 구조·소유권·색인은 바뀌지 않았다.
