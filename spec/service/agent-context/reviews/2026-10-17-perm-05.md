- 시작 상태: `feat/permission-improve`, `2a0120b`. upstream이 설정되지 않은 로컬 브랜치다. 선행 PERM-01·DATA-03은 완료 상태이며 기존 Compose·IDE 변경을 보존했다.
- 범위: 요청 한도 해석 API·웹 조회 연결, 원자적 누적 판정, 활성 문자 수와 상태 경계, 웹 복구 플랜 전달·안전한 한도 안내. 실제 MCP 입력 연결·토큰·브라우저·운영 배포는 후속 범위다.

## 발견 사항과 구현

| ID | 영향도 | 발견 사항 | 처리·검증 |
|---|---|---|---|
| PERM05-R1 | 중간 | 요청 한도에 공통 수치 비교만 있고 홉·노드·페이지·예산을 계정 플랜으로 해석하는 입력 경계가 없었다. | `CheckHop`, `PageSize.Resolve`, `ResolveBudget`을 추가했다. 생략과 명시한 값을 구분하며 호출자의 0으로 유한한 한도를 해제하지 않는다. 웹 목록·시각화도 같은 API를 사용한다. 실제 MCP 처리기의 연결은 MCP-04 이후다. |
| PERM05-R2 | 중간 | 저장 API에 음수 한도가 직접 전달되면 그래프 수 판정을 생략하거나 저장량 거부를 다른 오류로 처리할 수 있었다. | 공통 `WriteLimits` 검사로 트랜잭션·연결 예약 전 음수 한도를 거부한다. DB 핸들이 없는 저장소에서 생성·갱신·복구·그래프 생성 경계의 선검사를 확인했다. |
| PERM05-R3 | 중간 | 생성 입력에 삭제 상태를 넣거나 일반 갱신으로 삭제 상태·삭제 본문을 바꾸면 활성 문자 수 합과 누계가 어긋날 수 있었다. | 생성은 활성 상태만 허용하고 일반 갱신은 활성 컨텍스트만 처리한다. 갱신 SQL도 활성 상태를 조건으로 유지하며 삭제·복구는 전용 경로를 사용한다. 거부 뒤 정점·누계·큐·감사가 보존됐다. |
| PERM05-R4 | 낮음 | 웹 복구가 저장량 한도 초과를 일반 상태 오류로만 표시했다. | 알려진 저장량 오류만 현재·허용 문자 수로 안내한다. 내부 오류와 알 수 없는 항목명은 원문을 노출하지 않는다. |

- 그래프 수는 한도가 있을 때 계정 행을 먼저 잠그고 별도 명령으로 활성 소유 그래프 수를 집계하는 기존 구현을 유지했다. 서로 다른 멱등성 키도 저장점 해제 후 바깥 커밋까지 계정 잠금이 유지됨을 실제 잠금 대기에서 재검증했다.
- 저장량은 본문 변경과 같은 트랜잭션의 조건부 그래프 행 갱신에서 판정한다. 이미 한도를 넘었어도 축소·동일 크기 수정은 허용하며, 각 호출에 전달한 현재 플랜으로 증가를 판정한다. 환경 구성의 실시간 재적재 기능을 추가하거나 검증한 것은 아니다.
- 14개 플랜 항목·기본값·SRS는 유지했다. 입력 생략·0·상태 경계를 소유 SDD에 정합화했다. 패키지·문서 소유권과 DOX 색인 경계가 바뀌지 않아 DOX는 유지했다.
