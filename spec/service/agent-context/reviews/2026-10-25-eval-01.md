# EVAL-01 실행 명세·모드·입력 계약 모듈 인수

- 기준: 2026-10-25, `feat/evaluation`의 `1973eb6` 기반 변경.
- 대상: [EVAL-01](../development-plan/evaluation.md#eval-01), [실행 manifest 입력 계약](../sdd/evaluation.md#실행-manifest-입력-계약), [SRS 반복 정책](../SRS.md#초기-공개-평가와-반복-정책).
- 판정: 실행 명세의 사전 검증과 CLI 입력 경계 완료. 실제 공개 평가·효과·채택 판정은 미수행.

## 구현

[manifest 입력 타입·검사](../../../../cmd/eval/manifest.go)에서 판 1 JSON과 4 MiB 입력 상한을 정의했다. `cmd/eval -check-manifest <파일>`은 명세 파일만 읽으며 데이터 파일·DB·제공자에 접근하거나 결과 파일을 만들지 않는다. 입력 경로·원문·질의·URI·자격 필드를 받지 않고 성공 로그에는 비식별 시험 코드와 모드만 남긴다. 알 수 없는 JSON 필드·중복 키·필수 값 누락/null·후행 JSON은 거부한다.

- 입력별 dataset·판·commit·SHA-256 형식, 변환/정답/근거 매핑 판과 평가 전용 주석 정책을 고정한다. 변환은 원본, 업무는 업무 입력, 나머지는 컨텍스트·질의, 적대적 모드는 공격 표본의 checksum 선언도 요구한다. 실제 파일과의 checksum 대조는 EVAL-02 이후 데이터 준비가 담당한다.
- 질의 코드는 dataset 안에서 유일하며 같은 대화/과업은 같은 독립 단위에 묶인다. 서로 다른 대화/과업을 같은 독립 단위로 합치거나 한 대화의 질의를 서로 다른 단위로 나누면 거부한다. 전체 질의 수는 포함+제외 수와 같아야 하고 제외 코드의 중복·포함 표본과의 겹침을 거부한다.
- 모델·프롬프트 판·차원·벡터 표현, 단계·색인 대상·임계값·예산, 10회·회차 내 순환 순서·지원 seed·유한 요청/색인/시간 상한과 준비/캐시 정책을 검증한다. 지원 seed의 실제 0과 seed 미지원을 구분한다.
- 단가 판·산정일·통화·배분 판과 에이전트/임베딩/요약/검색/저장 항목의 상태를 받는다. 측정한 0은 보존하고 미측정·비해당 항목에는 값을 허용하지 않는다. 선언을 실제 비용 산정 결과로 승격하지 않는다.

기존 CLI의 조건별 반복 기본값·허용값을 현재 SRS의 10회로 맞췄다. 기존 업무 집계의 최소 세 대응 표본은 별개로 유지했다. 모드 충돌과 전용 옵션 불일치, 변환 형식/필터, 문자·홉·노드 예산/색인 대상, 일관성 후보 상한·요청/부하·쓰기 간격을 데이터 입력 읽기·DB·파일 생성 전에 확인한다. 적응형 임계값의 NaN도 거부하고 정규화된 컨텍스트·질의·공격 입력의 알 수 없는 JSON 필드를 거부한다.

## 모듈 시험과 실제 CLI 회귀

Go 1.27.1 darwin/arm64, PostgreSQL 18.6 linux/aarch64·AGE 1.8.0·pgvector 0.8.6, 기존 고정 이미지 `2b6d51048c03`을 사용했다. 실제 CLI 시험은 새 tmpfs 컨테이너 `acs-eval01`의 합성 DB와 루프백 TLS 제공자 대역만 사용했다. 정식 `cmd/migrate up`의 001·009~013 여섯 판을 적용했으며 운영 DB·개발 DB·외부 유료 제공자·공개 데이터 다운로드는 사용하지 않았다.

```sh
go test -race -count=1 -json -timeout=180s -skip Integration ./cmd/eval

# TEST_DATABASE_URL은 이 작업만을 위한 새 합성 DB에 지정한다.
TEST_DATABASE_REQUIRED=1 go test -race -count=1 -json -timeout=300s \
  -run '^(TestEvalCommandProcess|TestEvaluationCommandCleanupFailsExitIntegration|TestEvaluationCommandRejectsUnreadyIndexIntegration)$' \
  ./cmd/eval
```

첫 명령은 DB 통합 시험을 선택 범위에서 제외한 평가 모듈 시험 **229건**(최상위 73건), 두 번째는 실제 CLI 회귀 **18건**(최상위 3건)이 통과했다. 두 명령의 공통 `TestEvalCommandProcess` 보조 항목 한 건을 중복 제외하면 **고유 246건**(최상위 **75건**)이다. 실패·건너뜀은 없었고 최종 명령 시간은 각각 3.434초·99.995초였다. 전체 저장소 시험은 TEST-09에서 수행하므로 이번에 실행하지 않았다.

새 시험은 일곱 모드의 유효 명세, 독립 단위의 분리/병합 오류, checksum 선언 누락, 측정 0/미측정·seed 0/미지원, 제외 분모, 잘못된 JSON과 크기 상한을 확인한다. 없는 데이터 경로와 도달할 수 없는 DB를 지정한 잘못된 CLI 실행은 사전 검증 오류로 끝났고 파일이 생기지 않았다. 실제 자식 프로세스의 manifest 검사도 DB 구성 없이 성공하고 출력 파일을 만들지 않았다.

기존 실제 CLI 회귀는 기본·적응형·지속·일관성 실행의 정상 종료·정리 오류 실패 종료, 후보 상한 24의 사전 거부/25의 정상 실행, 다섯 모드의 색인 준비 실패와 정상 결과 파일 부재를 확인했다. 합성 제공자의 성공은 실제 임베딩 품질 검증을 뜻하지 않는다.

## 검증과 남은 범위

전체 `go build ./...`·`go vet ./...`·`gofmt -l .`이 통과했다. 변경 Markdown 8개·로컬 링크/앵커 411개와 개발 작업 124개 중 완료 104개·미완료 20개를 확인했고, 미완료는 TEST-06 진행 1개와 미착수 19개로 구분했다. DOX의 소유 경계·Child Index는 바뀌지 않았으며 명세는 평가 SDD, 완료 상태는 평가/전체 개발 계획, 실행 증거는 이 검토에 유지한다. 시험 종료 후 DB의 다른 연결 0개를 확인하고 자체 컨테이너만 제거했다. 기존 개발 DB·WAL 컨테이너와 개인 `.idea` 파일 두 개는 유지했다.

manifest는 현재 읽기 전용 사전 검증 명령이며 기존 직접 실행 CLI에 선언값을 자동 적용하지 않는다. 데이터 변환·실물 checksum 대조(EVAL-02), 독립 그래프와 준비 실행(EVAL-03), 새 통계·지표(EVAL-04), 통제 비교(EVAL-05~12), manifest와 결과의 일치·원자적 공개·최종 판정(EVAL-13)은 후속이다. 이번 완료를 공개 벤치마크·업무 효과·운영 채택 완료로 사용하지 않는다. 다음 권장은 EVAL-02다.
