# OAuth DCR 전용 전환 검토

- 요청: 여러 참여자가 자동으로 client ID를 발급받아 연결하도록 DCR을 추가하고 사전 등록은 제거한다.
- 범위: FR-AGENT_CONTEXT-147·166의 등록과 인증 조회, 설정·마이그레이션·안내. 실제 운영 적용은 수행하지 않았다.
- 상태: 서버 구현·모듈/DB 시험과 실제 Codex 0.165.0의 초기 DCR handshake 확인. 브라우저 로그인 이후의 실제 CLI 전체 인수는 대기다.

## 변경

- `POST /oauth/register`와 discovery의 registration_endpoint를 추가했다. JSON·callback·공개 client 메타데이터를 검증하고 난수 ID를 발급한다. client secret·외부 URI 조회·등록 관리 API는 제공하지 않는다.
- `016_oauth_client.sql`과 공유 client registry를 추가했다. 인가·최초 교환·갱신·Bearer가 같은 저장소를 요청 컨텍스트로 조회하며, DB 장애를 미등록 자격으로 숨기지 않는다.
- 사전 등록 환경 변수와 production의 등록 map 경로를 제거했다. 시험 전용 map은 기존 토큰·권한 시험의 저장소 대역으로만 남는다. 기존 계정·그래프·계열을 삭제하거나 고정 ID를 자동 이관하지 않는다.
- 등록 본문·callback·이름·출처 예산과 공유 DB 총량에 [인증 설계](../sdd/authentication.md#oauth-discovery와-최초-인가)의 상한을 적용했다.
- 환경 예시·README·운영 안내·SRS·인증/데이터/운영·추적 문서를 정합화했다. DOX 소유 경계는 기존 authz/store/config/server/web/migrations 영역과 동일하므로 새 DOX는 만들지 않았다.

## 확인한 검증

- Go 1.27.3으로 전체 패키지 컴파일·go build ./...·go vet ./...를 통과했고 gofmt -l . 출력이 없음을 확인했다. 변경 문서의 로컬 링크·코드 블록과 git diff --check도 통과했다.
- DCR·authorize 저장 장애 보강 시험의 race 검사를 통과했다.
- 인증·구성·웹·서버 모듈 시험을 실행했다. 실제 DB가 필요한 분야 시험은 TEST_DATABASE_URL과 TEST_DATABASE_REQUIRED=1로 시험 전용 DB를 생성·정리했다.
- `TestDCRClientPersistenceIntegration`·`TestDCRClientCapacityConcurrentIntegration`: 저장 공유·중복 ID 보존·동시 등록 10000개 상한.
- `TestDCRAccountAndRestartIntegration`: TLS 등록·코드 교환·두 계정의 토큰 분리·새 서비스의 Bearer 검증·갱신.
- 인증·구성·웹·서버·진단의 필수 DB 분야 시험이 통과했다. 마이그레이션의 적용 수·테이블 수 기대값은 016까지의 형상에 맞추고 마이그레이션 분야 전체 시험을 통과했다.
- `TestDCRCodexCLIRegistrationIntegration`: macOS의 실제 codex-cli 0.165.0이 401→discovery→POST 등록 201→발급 ID·S256·resource를 사용한 인가 URL 생성까지 통과했다. 시험 전용 CODEX_HOME·CA·DB·TLS 서버를 사용하고 기존 사용자 설정·자격과 운영 서버는 변경하지 않았다.
- headless Chrome이 없어 기존 실제 브라우저 기반 TEST-08 전체 인수는 실행하지 않았다. 현재 DCR 경로의 한 시간 자연 만료·TUI·앱/IDE·다른 클라이언트와 운영 HTTPS/Tunnel 지원 판정으로 확대하지 않는다.

## 독립 검토

읽기 전용 독립 검토에서 Critical/Important 결함은 발견되지 않았다. 권고한 URI·이름·callback 경계, IPv6 /64 공유, 갱신/Bearer registry 장애·조회 중 취소와 authorize 장애 시험을 보강했다. 과거 exact 사전 등록 문장은 현행 계약에서 제거했다. 웹 저장 장애는 기존 sessionUnavailable의 500 계약을 유지한다.

## 전환

새 스키마를 적용하고 서버를 갱신한 뒤 클라이언트의 고정 oauth.client_id를 제거하여 DCR 재등록·재인가한다. OAUTH_CLIENT_REGISTRATIONS는 더 이상 읽지 않으며 환경 예시에서도 제거했다. 기존 데이터 삭제·실제 운영 migration·배포·사용자 전역 Codex 설정 변경은 수행하지 않았다.
