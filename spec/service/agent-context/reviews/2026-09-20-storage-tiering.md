# 임베딩 저장 계층화 구현 검증

## 목적과 범위

- 검증일: 2026-09-20
- 대상 요구사항: `FR-AGENT_CONTEXT-123`
- 목적: 접근이 차단됐거나 플랜 기준보다 오래 쓰이지 않은 임베딩을 삭제하지 않고 콜드 계층으로 옮기며, 활성 컨텍스트를 조회하면 즉시 핫 계층으로 되읽는지 확인한다.
- 범위: 관계형 `context_embedding`만 계층화한다. AGE `Context` 정점의 파티셔닝 가능 여부는 기존 미정 사항을 유지한다.

## 구현 결정

`context_embedding`을 `storage_tier`의 `hot`·`cold` 값으로 목록 파티셔닝했다. 새 색인은 `hot`에서 시작하고 `last_accessed_at`으로 마지막 실제 사용 시점을 기록한다. 콜드 파티션은 선택 구성 `EMBEDDING_COLD_TABLESPACE`가 가리키는 기존 PostgreSQL tablespace를 사용할 수 있으며, 값을 비우면 기본 tablespace에서 논리 파티션만 나눈다.

일곱 번째 주기 작업 `embedding_tier_move`는 하루마다 다음 대상을 옮긴다.

- 소프트 삭제된 그래프의 모든 임베딩
- 폐기된 컨텍스트의 임베딩
- 생성 계정 플랜의 `TierMoveAfterDays`보다 오래 사용하지 않은 활성 임베딩

플랜 값 0은 활성 임베딩을 옮기지 않는다. 검색 후보 조립에 사용되거나 단일 조회와 홉 조회에서 반환된 활성 컨텍스트는 접근 시각을 갱신하며 `cold` 행을 `hot`으로 되읽는다. 삭제된 컨텍스트는 조회해도 콜드에 유지한다.

## 검증 결과

별도 임시 데이터베이스 `agent_context_tier_test_20260920`을 만들어 새 `001_init.sql`만 적용했다. AGE와 pgvector를 포함한 개발 이미지에서 파티션 테이블과 부모 HNSW 인덱스가 정상 생성됐고, 같은 마이그레이션을 다시 실행했을 때 적용할 항목이 없다고 판정됐다.

통합 테스트는 다음을 확인했다.

- 플랜 기간을 넘긴 활성 임베딩과 폐기 임베딩이 `cold`로 이동한다.
- 플랜 기본값 0에서는 오래 사용하지 않은 활성 임베딩이 `hot`에 남는다.
- 소프트 삭제된 그래프는 플랜 값과 무관하게 `cold`로 이동한다.
- 콜드의 활성 컨텍스트를 직접 조회하면 행이 물리적으로 `context_embedding_hot`으로 이동한다.
- 삭제된 컨텍스트는 활성 컨텍스트 조회의 부수 효과로 승격되지 않는다.

`TEST_DATABASE_REQUIRED=1 go test ./...`를 임시 데이터베이스에 연결해 실행했고 모든 패키지가 통과했다. `go build ./...`, `go vet ./...`, `gofmt -l .`도 별도로 확인했다.

## 남은 운영 조건

현재 개발 데이터베이스는 평가 데이터 보존을 위해 재생성하지 않았다. 이 저장소는 개발 단계에서 초기 스키마를 `001_init.sql`에 직접 합치는 방식을 사용하므로, 기존 개발 데이터베이스에 새 구조를 적용하려면 데이터를 보존하는 별도 전환을 만들거나 `docker compose down -v` 후 처음부터 다시 만들어야 한다.

별도 tablespace를 지정하는 배포는 PostgreSQL에 해당 tablespace를 먼저 만들고 그 이름을 `EMBEDDING_COLD_TABLESPACE`에 넣어야 한다. 빈 값은 기능을 끄는 값이 아니라 동일 저장 장치 안에서 논리 파티션만 적용하는 값이다.
