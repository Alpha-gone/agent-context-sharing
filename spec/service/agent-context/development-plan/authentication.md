# 인증 개발 계획

[전체 계획](../DEVELOPMENT_PLAN.md) · [기준 SDD](../sdd/authentication.md) · [작업 추적](traceability.md)

## 목표와 구현 범위

계정·비밀번호·웹 세션부터 OAuth 최초 인가, Bearer 검증, 갱신 회전·폐기까지 새로 구현한다. 호스트 자격 저장·재사용은 서버 시험과 실제 호스트 인수를 분리한다.

- 설계 입력: [공개 자원 보호](../sdd/authentication.md#공개-로그인가입-자원-보호), [발견과 최초 인가](../sdd/authentication.md#oauth-discovery와-최초-인가), [갱신과 공유 저장](../sdd/authentication.md#갱신폐기와-공유-저장), [수명](../sdd/authentication.md#갱신-자격의-수명과-정리), [원자적 전이](../sdd/authentication.md#oauth-저장-모델과-원자적-전이).
- 예정 구현 영역: `internal/authz`, 인증 저장 API, `cmd/server`의 인증 어댑터·OAuth 경로.
- 다른 분야와의 경계: 웹 양식·쿠키 전송은 웹 계획, 그래프 등급은 권한 계획, 호스트 안전 저장·복원은 테스트 계획이 소유한다.

## 개발 작업

### AUTH-01

- [x] **계정 입력·비밀번호 저장·검증을 구현한다.**
- 선행: [ARCH-02](architecture.md#arch-02), [ARCH-03](architecture.md#arch-03).

1. 로그인 아이디의 3~32자 소문자·숫자·밑줄, 비밀번호 8~128자와 UUIDv7 계정 모델을 검증한다.
2. UTF-8 비밀번호의 SHA-256을 padding 없는 표준 base64로 인코딩한 뒤 bcrypt를 적용하고 `bcrypt-sha256-b64-v2:` 형식으로 저장한다.
3. SDD가 정한 이전 해시 형식의 검증·성공 후 재해시도 새 코드와 합성 fixture로 구현한다. 평문·해시·더미 값을 로그에 넣지 않는다.

- 산출물: 비밀번호 처리기·계정 검증·이전 형식 fixture.
- 완료 기준: 유니코드·72바이트 초과·잘못된 형식·잘못된 비밀번호가 올바르게 처리되고 성공 재해시가 같은 작업 자리에서 수행된다.
- 완료 근거: [AUTH-01 검토](../reviews/2026-10-18-auth-01.md). 잘못된 UTF-8 가입 차단을 보완하고 계정·현재 저장 형식·이전 두 형식의 성공/실패·동일 자리 재해시를 새 합성 표본으로 검증했다. 인증 패키지 73건·race와 전체 build·vet·형식 검사를 통과했다.

### AUTH-02

- [x] **공유 서명 키·JWKS·검증 캐시를 구현한다.**
- 선행: [AUTH-01](#auth-01), [DATA-03](data.md#data-03), [ARCH-04](architecture.md#arch-04).

1. go-jose/v4로 ES256 키·서명·검증을 구현하고 활성 키 유일성·생성 경합·회전을 공유 DB에서 처리한다.
2. JWKS는 공개 키만 반환하고 기존 유효 토큰 검증에 필요한 과거 키를 보존한다. 허용 알고리즘은 ES256으로 고정한다.
3. 새 kid 재조회·병행 캐시 조회·폐기 상태 조회·저장소 장애를 구분하고 장애를 자격 불일치로 바꾸지 않는다.

- 산출물: 키 저장·회전·JWKS·캐시와 임시 DB 기반 통합 시험.
- 완료 기준: 두 인스턴스가 같은 활성 키를 사용하고 회전 전 유효 토큰을 검증한다. 개인 키가 JWKS·응답·진단에 나오지 않으며 시험이 공유 DB의 키를 바꾸지 않는다.
- 완료 근거: [AUTH-02 검토](../reviews/2026-10-18-auth-02.md). JWKS·캐시의 ES256 공개 키 검증과 발급 키 쌍 검증을 보완했다. 시험별 임시 DB에서 두 인스턴스의 초기화 경합·교차 검증·회전·서비스 재생성·취소를 인수하고 인증 98건·저장 경합 2건·race와 전체 build·vet·형식 검사를 통과했다.

### AUTH-03

- [x] **계정 등록과 자격 대조를 구현한다.**
- 선행: [AUTH-01](#auth-01), [AUTH-02](#auth-02), [DATA-05](data.md#data-05).

1. 계정 등록과 로그인 대조를 인가 서비스에 구현하고 아이디 유일 제약의 동시 가입 오류를 판별한다.
2. 없는 계정은 더미 bcrypt를 실행하고 중복 가입도 같은 해시 비용을 거친다. 일반 불일치와 허용된 중복 가입 안내를 구분한다.
3. 취소 전·후를 검사하여 해시 작업 뒤 취소되면 계정 생성·해시 갱신·세션 발급을 중단한다.

- 산출물: 등록·대조 서비스와 중복·더미·취소 표본.
- 완료 기준: 정상·없는 계정·중복·동시 등록·저장소 장애를 검증하고 자격이나 내부 오류 원문을 노출하지 않는다.
- 완료 근거: [AUTH-03 검토](../reviews/2026-10-18-auth-03.md). 실제 아이디 유일 제약만 중복으로 판별하고 불일치·손상/저장 장애·취소를 구분했다. 시험별 DB의 동시 가입·조건부 재해시와 더미·같은 해시 비용·오류 원문 비노출·웹 400/401/500·후속 세션 차단을 검증했다. 인증 122건·웹 345건·어댑터 7건, 총 474건·race와 전체 build·vet·형식 검사를 통과했다.

### AUTH-04

- [x] **공개 로그인·가입의 자원 보호를 구현한다.**
- 선행: [AUTH-03](#auth-03), [OPS-03](operations.md#ops-03).

1. 출처 검사 뒤 양식·DB 조회 전에 로그인·가입 합계 60초 고정 창을 적용한다. 출처 10회, 인스턴스 60회, 최대 4096개 출처 상태와 만료 정리를 구현한다.
2. IPv4·IPv6 /64·mapped 주소를 정규화하고 검증된 프록시 경로의 단일 CF-Connecting-IP만 사용한다. 잘못된 헤더·해석 실패는 공통 또는 실제 상대 예산으로 합산한다.
3. 양식 8 KiB와 인가 서비스 최대 4개 비밀번호 작업·대기열 없음, 취소와 해제 경계를 구현한다. 시작한 bcrypt는 반환까지 자리를 유지한다.
4. 413·400·429, no-store, Retry-After와 고정 한국어 안내를 검증한다. 거부로 창을 연장하거나 성공으로 카운터를 초기화하지 않는다.

- 산출물: 공유 시도 예산·작업 자리·출처 해석과 보호 회귀.
- 완료 기준: 제한·취소 요청이 DB·bcrypt 전에 차단되고 모든 경로에서 작업 자리를 회복한다. 계정 잠금·비밀번호 보관·무제한 출처 키가 생기지 않는다.
- 완료 근거: [AUTH-04 검토](../reviews/2026-10-19-auth-04.md). 본문 읽기 전 413·형식 400·공유 예산 429와 no-store, 취소·4096개 상태의 남은 창·만료 회복을 보완했다. 120개 동시 HTTP 처리의 60회 상한·취소된 비밀번호 작업의 반환 전 자리 유지와 회복, 시험별 DB의 실제 프록시/IPv6 예산을 검증했다. 인증 123건·웹 382건·서버 181건, 총 686건·race와 전체 build·vet·형식 검사를 통과했다.

### AUTH-05

- [x] **웹 세션 발급·검증·로그아웃을 구현한다.**
- 선행: [AUTH-02](#auth-02), [AUTH-03](#auth-03).

1. 웹 audience의 서명된 JWT를 12시간·갱신 없음으로 발급하고 issuer·sub·iat·exp·jti와 폐기를 검증한다.
2. 로그아웃은 해당 jti를 만료까지 폐기하고 쿠키 삭제를 웹 어댑터에 전달한다. 저장소 장애는 로그인 실패와 구분한다.
3. Bearer 전달·대상과 웹 쿠키를 분리하고 상대 채널의 자격을 거부한다.

- 산출물: 웹 세션 서비스와 발급·만료·폐기·교차 채널 시험.
- 완료 기준: 12시간 경계·로그아웃·키 회전·다중 인스턴스 폐기가 재현되고 서버에 웹 세션 본문을 저장하지 않는다.
- 완료 근거: [AUTH-05 검토](../reviews/2026-10-19-auth-05.md). 웹 전용 발급·단일 audience·필수 클레임·12시간 반열린 수명과 JWT/쿠키 만료를 정합화하고 검증·폐기 장애의 500 및 취소 뒤 성공 차단을 보완했다. 두 서비스의 공유 폐기·10초 캐시 경계·재시작·키 회전과 실제 TLS 쿠키/채널 분리·로그아웃 재사용 거부를 검증했다. 인증 153건·웹 410건·서버 201건, 총 764건·race와 전체 build·vet·형식 검사를 통과했다.

### AUTH-06

- [x] **OAuth 발견과 공개 클라이언트 등록을 구현한다.**
- 선행: [ARCH-05](architecture.md#arch-05), [AUTH-02](#auth-02).

1. 고정 공개 resource·issuer·scope를 보호 리소스와 인가 서버 메타데이터에 제공한다. PKCE S256·none·두 grant·iss 지원을 명시한다.
2. 사전 등록 client의 callback·허용 resource를 대조한다. 첫 Codex callback은 127.0.0.1:49152/callback 완전 일치로 검사하고 일반 등록의 가변 loopback 포트 예외와 나눈다.
3. resource·issuer·Origin·callback 각각의 HTTPS·URI 형식·허용 예외와 중복·빈 등록을 소유 SDD의 정책으로 검증한다. CIMD나 외부 URL 조회를 자동으로 추가하지 않는다.

- 산출물: 메타데이터·등록 해석·결합 검증과 issuer/resource/callback 위반 표본.
- 완료 기준: 임의 Host로 메타데이터를 만들지 않고 등록하지 않은 URI로 오류 리디렉션하지 않는다.
- 완료 근거: [AUTH-06 검토](../reviews/2026-10-19-auth-06.md). 고정 resource·issuer·scope·PKCE·grant·iss 메타데이터 두 경로를 조립하고 사전 등록의 복사·client/callback/resource 대조와 exact/same_ip 포트 경계를 구현했다. URI 오류의 자원 시작 전 차단, Host·전달 헤더·query 비의존, 닫힌 DB에서의 실제 TLS GET/HEAD·405를 검증했다. 인증 201건·구성 303건·서버 251건, 총 755건·race와 전체 build·vet·형식 검사를 통과했다. 인가 HTTP와 오류 리디렉션 연결은 AUTH-07에서 이 대조 경계를 사용한다.

### AUTH-07

- [x] **최초 인가·코드 발급·토큰 교환을 구현한다.**
- 선행: [AUTH-04](#auth-04), [AUTH-05](#auth-05), [AUTH-06](#auth-06), [DATA-02](data.md#data-02).

1. 로그인·명시적 동의·등록 검증 뒤 60초 단일 사용 코드의 해시와 계정·client·callback·resource·scope·S256 challenge를 저장한다.
2. 코드 교환은 검증 후 1시간 접근 토큰과 새 갱신 계열을 원자적으로 발급하고 성공·오류 응답의 iss를 정확히 반환한다.
3. 코드 재사용은 처음 연결한 계열을 폐기하고 이를 커밋한 뒤 표준 오류를 반환한다. 서명·저장 실패는 최초 교환을 롤백한다.
4. token 양식 64 KiB, OAuth JSON·Bearer·no-store·no-cache를 적용하고 비밀을 도구 결과·진단에 넣지 않는다.

- 산출물: authorize·token 처리기와 코드 저장·소비·재사용 시험.
- 완료 기준: 잘못된 verifier·client·callback·resource·만료·동시 교환을 거부하고 최초 성공이 한 번만 적용된다.
- 완료 근거: [AUTH-07 검토](../reviews/2026-10-20-auth-07.md). 로그인 복원·명시적 동의·검증한 callback의 state/iss·60초 코드 해시·최초 ES256 접근/갱신 발급을 연결했다. 실제 DB에서 잠금 대기 후 만료·8건 동시 교환의 단일 성공·만료 후 재사용 계열 폐기·서명/저장/취소 롤백과 TLS 흐름·자격 비노출을 검증했다. 인증 248건·웹 436건·선별 서버 239건, 중복 제외 총 923건·race와 전체 build·vet·형식 검사를 통과했다. Bearer·갱신 회전·본인 연결 관리·실제 브라우저/호스트 인수는 후속 범위다.

### AUTH-08

- [ ] **Bearer 검증과 보호 리소스 인증을 구현한다.**
- 선행: [AUTH-02](#auth-02), [AUTH-07](#auth-07).

1. iss·sub·aud·exp·iat·jti·scope·client_id·grant_id와 ES256을 검증하고 인증된 계정·client·계열만 다음 경계에 전달한다.
2. 개별·계열 폐기와 만료를 공유 DB에서 매 요청 확인하고 그래프 등급은 권한 서비스가 현재 상태로 판정하게 한다.
3. 자격 부재·만료·서명·폐기는 401과 인증 도전, scope 부족은 403, 내부 저장·키 장애는 500으로 나눈다.

- 산출물: 보호 요청 검증기·인증 주체·HTTP 오류 매핑.
- 완료 기준: 웹 세션의 MCP 사용, 다른 resource·scope·client 결합을 차단하고 내부 장애가 재인증 반복을 유발하는 401로 변하지 않는다.

### AUTH-09

- [ ] **갱신 회전·수명·재사용 계열 폐기를 구현한다.**
- 선행: [AUTH-07](#auth-07), [AUTH-08](#auth-08).

1. 32바이트 난수의 불투명 갱신 값과 SHA-256 해시 저장, 30일 절대·7일 비활동 만료 및 retain_until 계산을 구현한다.
2. 계열→토큰 행 순서로 잠그고 결합·현재 상태를 재검사한 뒤 소비·후속 해시·접근 서명·최근 회전·비활동 만료를 한 트랜잭션으로 처리한다.
3. 소비 토큰 재사용은 계열 폐기를 커밋한 뒤 invalid_grant를 반환한다. 응답 유실·동시 갱신·서명/저장 실패·취소를 별도 표본으로 검증한다.
4. 도구 호출·웹 로그인·실패한 갱신은 비활동 수명을 연장하지 않는다. 상태 정리 조건은 [OPS-04](operations.md#ops-04)가 같은 계약으로 사용한다.

- 산출물: 회전 저장 API·해시 자격·수명 판정과 경합 시험.
- 완료 기준: 이전 토큰은 한 번만 소비되고 재사용 계열 폐기가 다른 인스턴스에도 즉시 적용된다. 원문·해시·verifier가 진단에 없고 정리 지연이 유효성을 늘리지 않는다.
