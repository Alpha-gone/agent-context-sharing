# 프로젝트 스킬 영역

## 목적

- `.agents/skills/`는 이 저장소의 명세 작성, 시각화, 이력 관리와 GitHub 협업 절차를 제공하는 프로젝트 로컬 스킬을 보관한다.

## 소유권

- 루트 `AGENTS.md`가 저장소 공통 계약과 이 영역의 경계를 소유한다.
- 이 문서는 `.agents/skills/` 하위 스킬의 공통 작성·실행·검증 계약을 소유한다.
- 각 스킬 폴더의 `SKILL.md`가 해당 스킬의 구체적인 입력, 절차, 승인 경계와 산출물을 정의한다.

## 로컬 계약

- 스킬을 실행하기 전에 루트부터 작업 대상까지 적용되는 `AGENTS.md` 체인과 `spec/DICTIONARY.md`를 읽는다.
- 파일 생성·수정·이동·삭제는 체크박스 계획을 제시하고 사용자 승인을 받은 뒤 수행한다.
- 서비스 명세는 `spec/service/`, 프로젝트 이력은 `spec/history/`, 비공개 작업 로그는 `.personal/logs/` 아래에서 관리한다.
- 서비스 또는 이력 산출물은 실제 입력과 작업 범위가 생겼을 때만 생성하며 빈 예시 폴더를 미리 만들지 않는다.
- 명세 변경은 기존 추적 ID와 사용자 작성 내용을 보존하고, 확인되지 않은 사실이나 제안을 확정 내용으로 승격하지 않는다.
- 커밋은 사용자가 명시적으로 요청한 경우에만 수행한다.
- GitHub 이슈, Pull Request, 라벨, 마일스톤, 원격 브랜치 같은 외부 상태 변경은 정확한 대상을 제시하고 별도 승인을 받은 뒤 수행한다.
- 원격 저장소나 GitHub 연결을 확인할 수 없으면 외부 쓰기 작업을 중단하고 확인하지 못한 상태를 보고한다.
- 다른 프로젝트의 서비스명, 사용자명, 날짜, 저장소 경로나 조직별 관례를 예시 또는 기본값으로 남기지 않는다.
- `SKILL.md`의 YAML frontmatter에는 `name`과 `description`만 둔다.
- `agents/openai.yaml`의 사용자 표시 문구는 한국어로 작성하고 `default_prompt`에 `$스킬명`을 명시한다.

## 작업 지침

- `SKILL.md`에는 핵심 절차와 판단 기준을 두고, 긴 형식·매핑·문서 템플릿은 `references/`에 둔다.
- 프로젝트에 이미 있는 소유 스킬을 재사용하고 같은 계약을 여러 스킬에 중복 정의하지 않는다.
- 기술 식별자와 파일명은 원문을 유지하고 설명은 자연스러운 한국어로 작성한다.
- 작업 결과와 변경 파일은 적용되는 프로젝트 규칙에 따라 `.personal/logs/YYYY-MM-DD 작업 내용.md`에 기록한다.

## 검증

- `SKILL.md`와 `agents/openai.yaml`의 이름, 설명과 기본 프롬프트가 일치하는지 확인한다.
- Markdown 제목, 표, 상대 링크, 경로, 맞춤법과 한국어 표현을 확인한다.
- 완료 전 DOX pass로 이 문서와 루트 Child DOX Index의 일관성을 확인한다.

## Child DOX Index

- 현재 하위 `AGENTS.md` 문서는 없다.
