# #154 팀 상속 등급의 구성원 표시 범위

- 대상: [이슈 #154](https://github.com/Alpha-gone/agent-context-sharing/issues/154).
- 기준: `dev`의 `742b285`, 작업 브랜치 `fix/154-team-inheritance-visibility`.

## 결정과 구현

기존 팀 관리 영역의 관리자 범위를 등급 표의 구성원별 상속 행에도 적용했다. 그래프 소유자는 모든 직접 계정·팀 부여를 계속 확인하되, 구성원별 로그인 아이디·계정 UUID는 자신이 관리하는 활성 팀에 한해 조회한다. 다른 팀의 상속 효과는 기존 팀 직접 부여 행의 이름·식별자·등급과 공통 안내로 표시한다. 모든 팀을 일괄 요약하는 방식보다 관리 팀의 기존 상세 기능을 유지하는 선택이다.

[SRS](../SRS.md#권한과-팀-관리-화면)에 표시 범위를, [웹 SDD](../sdd/web.md#웹-화면-계약)에 세션 계정 전달·저장소 질의 제한과 표시·인수 경계를 명시했다. ListGraphGrants는 요청 계정 식별자를 필수로 받아 상속 UNION의 팀 관리자 조건에 바인딩한다. 화면에서 받은 전체 구성원을 숨기는 방식으로 처리하지 않는다. 실제 웹 요청의 계정은 세션에서 얻으며 기존 그래프 소유자 확인은 유지한다.

직접 계정 부여와 실제 유효 등급·접근 목록·마지막 소유자 회수 판단·팀 부여에 상대 동의를 요구하지 않는 정책은 유지한다. 삭제된 팀은 상속 행을 만들지 않지만 그 팀 관리자는 관리 영역에서 보존된 구성원 목록을 계속 볼 수 있다. 내부 GraphStore 인터페이스와 모든 구현·호출부·대역을 함께 갱신했다. 스키마·공개 구성·DOX 소유권·색인은 바뀌지 않았다.

## 재현과 검증

- 관리자 조건을 제거하되 새 요청 계정 인자만 호환시킨 Go overlay로 기존 질의를 대조했다. 실제 TLS 웹 요청에서 다른 관리자 팀의 구성원 정보가 노출되어 새 회귀가 실패했다.
- 새 웹/DB 회귀는 같은 그래프의 소유자 두 명이 서로 다른 팀을 관리하는 구성을 사용한다. 관리자별 상속 조회·응답 본문의 숨겨진 로그인 아이디/UUID·팀 단위 표시·삭제/복구·직접 계정 부여의 표시·실제 상속 등급 유지가 통과했다.
- 예비 시험에서 이미 활성인 팀에 복구를 요청한 상태 충돌을 바로잡았다. 삭제 팀의 관리자 영역에는 구성원이 보존되므로, 해당 관리자의 상속 무효 판정은 등급 표만 대조하도록 시험 범위를 정합화했다.
- Store의 팀 부여·감사·회수·마지막 소유자·삭제 영향 관련 필수 DB/race 회귀 13건이 통과했다.
- 서버 전체 필수 DB/race 회귀 688건이 116.729초에 통과했다. 별도 Codex CLI·물리 복구·이전 인수 21건은 환경 미설정으로 건너뛰었으며 통과 수에 포함하지 않았다.
- 웹 전체 필수 DB/race 회귀 812건이 19.821초에 실패·건너뜀 없이 통과했다. 실제 TLS/세션/서버 렌더링 인수이며 별도 Chrome 수동 인수로 확대하지 않는다.

Go 1.27.1과 기존 고정 로컬 arm64 PostgreSQL/AGE/pgvector 이미지의 새 전용 컨테이너를 사용했다. 정식 CLI로 생성한 기준 DB에만 마이그레이션을 적용하고 웹 시험은 자신의 별도 DB를 생성·정리했다. 기존 개발 DB·컨테이너·개인 IDE 파일은 변경하지 않았다.

Modern Web Guidance의 privacy 가이드에서 “Collect only the bare minimum required for the immediate task.” 원칙을 적용해 구성원을 템플릿에서 숨기는 대신 조회 단계에서 최소화했다. 새로운 브라우저 API·CSS·클라이언트 스크립트는 추가하지 않았다. 적용 pgx v5.10.0의 기존 Query 인자 바인딩 방식은 유지했고 새 SQL 조건은 실제 PostgreSQL에서 실행해 검증했다.
