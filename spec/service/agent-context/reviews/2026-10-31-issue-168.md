# #168 임베딩 비교의 비용 개선 판정

- 대상: [이슈 #168](https://github.com/Alpha-gone/agent-context-sharing/issues/168).
- 기준: `dev`의 `9dcf218`, 브랜치 `fix/168-embedding-cost-improvement`.

## 항목별 처리

| 항목 | 처리 | 내용 |
|---|---|---|
| 저장량·호출 수 감소의 후보 판정 | 처리 | 품질·임계값·검색 비악화와 실제 출처 조건은 그대로 두고, 문서·측정 임베딩 HTTP 시도 수, 벡터 열 바이트 또는 실측 금액 중 하나가 독립 단위 2개 이상에서 유의하게 감소하면 비용 개선으로 판정한다. 지연 개선만 인정하던 판정을 보완했다. |
| 지연·비용 사유 구분 | 처리 | 후보 사유를 `quality_preserved_latency_improved_…`, `quality_preserved_cost_improved_…`, `quality_preserved_latency_and_cost_improved_…`로 구분한다. 개선이 없으면 기존 `no_significant_measured_latency_or_cost_improvement`로 보류한다. |
| 미계측 금액 | 처리 | 미계측 금액 -1은 기존 유효 지표 검사로 대응 표본에서 빠져 독립 단위 수 조건을 넘지 못한다. 0을 미계측으로 쓰는 실행은 기존 무결성 검사가 거부한다. |

비용 증가를 새 거부 사유로 추가하지 않았다. 정본은 품질 악화만 거부·보류 조건으로 두므로 그 범위를 넓히지 않는다. 벡터 행 수·준비/측정 소요 시간은 비용 근거에 포함하지 않는다. [평가 정본](../sdd/evaluation.md#임베딩-비교-실행-계약)에 비용·지연 개선의 정의와 사유 구분을, [시험 설계](../sdd/testing.md#테스트-계층)에 판정 회귀를 추가했다. 결과 JSON의 필드·상태 값은 바뀌지 않고 후보 사유 문자열만 추가된다. DOX pass에서 소유권·경로 변경이 없어 기존 DOX를 유지했다.

## 재현과 검증

- 이슈의 재현 표본을 단위 시험으로 구성했다. axis=compression(vector→halfvec), 독립 평가 단위 5개, 지연 차이 없음, 벡터 열 바이트 차이 -2000·-3000·-2500·-1800·-2200이다. 기준 코드에서 `vector_column_bytes`는 평균 차이 -2300·유의·개선으로 집계되지만 최종 판정이 `deferred`/`no_significant_measured_latency_or_cost_improvement`인 것을 재현했다. 판정 표에서도 저장량·문서/측정 호출·실측 금액만 개선된 경우가 보류되고, 지연과 비용이 모두 개선되면 지연 사유만 남는 것을 확인했다.
- 수정 후 같은 표본은 실제 출처에서 `candidate`/`quality_preserved_cost_improved_final_acceptance_pending`, 합성 출처에서 `deferred`/`synthetic_provider`다. 미계측 금액·증가·비유의·단일 독립 단위·비용 외 지표는 보류된다.
- Go 1.27.1과 고정 이미지 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`(PostgreSQL 18.6)의 전용 합성 컨테이너에 기본 vector 768·비교 vector 128·halfvec 768 DB를 만들고 각각 정식 7개 마이그레이션을 적용했다. 기존 개발·다른 시험 DB는 사용하지 않았다.
- `TEST_DATABASE_URL`, `TEST_EMBEDDING_SMALL_URL`, `TEST_EMBEDDING_HALF_URL`, `TEST_DATABASE_REQUIRED=1`을 지정한 `go test -race -p 1 -json ./cmd/eval -count=1 -timeout=40m`에서 899건이 실패·건너뜀 없이 통과했다. [#196 검토](2026-10-31-issue-196.md)의 884건과의 차이는 새 시험·하위 시험 15건이다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check`와 변경 문서의 로컬 링크·앵커를 확인했다.
- 시험 종료 후 시험 DB 외 임시 DB와 idle transaction 잔류가 없음을 확인하고 소유 컨테이너만 정리했다. 기존 개발·다른 시험 자원과 개인 IDE 파일은 유지했다.
