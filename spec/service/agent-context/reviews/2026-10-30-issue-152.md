# #152 키워드 제외 조건의 전체 결합

- 기준: 2026-10-30 KST, `dev`의 `48c8eb0`에서 분기한 `fix/152-keyword-exclusion`.
- 대상: [이슈 #152](https://github.com/Alpha-gone/agent-context-sharing/issues/152), [검색 채널](../sdd/search.md#채널-구현), [시험 계층](../sdd/testing.md#테스트-계층).

## 재현과 수정

기존 `websearchOrQuery`는 제외 토큰까지 `OR`로 연결했다. 격리 PostgreSQL 18에서 `foo OR -bar`가 `foo | !bar`가 되고, `querytree`가 긍정 검색 조건을 찾지 못해 `T`가 되는 것을 확인했다. `foo -bar`는 foo가 없거나 bar가 있는 문단까지 후보로 포함했고 `git push -f`도 git·push와 겹치지 않는 본문을 반환했다.

[신규 DB 회귀](../../../../internal/store/keyword_exclusion_integration_test.go)는 10개 본문을 분리된 시험 DB에 저장하고 14개 질의를 대조한다. 수정 전 11개 사례가 제외 실패나 무관한 후보 유입으로 실패했다. 일반 어휘 OR·인용구 OR·빈 질의의 세 기존 동작은 통과했다.

따옴표 밖 공백 분할을 유지하며 긍정 어휘·인용구는 OR로, 제외 토큰은 기본 AND로 각각 조립한다. 두 묶음을 값 파라미터로 PostgreSQL에 전달해 `websearch_to_tsquery('simple', ...)`로 해석한 뒤 타입 연산자 `&&`로 결합한다. `(foo OR baz) AND NOT bar`를 문자열 괄호에 의존하지 않고 보장하며 후보 필터와 `ts_rank_cd`가 같은 질의를 사용한다. 빈 묶음은 나머지만 사용해 기존 단독 제외·빈 질의 동작을 유지한다.

전문 검색의 왼쪽 `to_tsvector('simple', body)` 표현과 그래프·활성 상태·유효 기간·후순위 정렬·상한은 유지한다. 두 묶음은 읽기 한 번 안에서 계산하므로 별도 DB 왕복을 추가하지 않는다. `querytree`의 긍정 조건 보존을 실제 실행 계획이나 지연 개선 측정으로 확대하지 않는다. 외부 구문·연산자 근거는 [reference.md](../reference.md#2026-10-30-152-키워드-제외-조건)에 기록했다.

## 검증

Go 1.27.1, 고정 PostgreSQL/AGE/pgvector 전용 컨테이너, 정식 마이그레이션과 `TEST_DATABASE_REQUIRED=1`·`TEST_DATABASE_URL`을 사용했다.

```sh
go test -race -count=1 -run '^TestKeywordExclusionIntegration$' ./internal/store
go test -race -count=1 -json -run '^Test(KeywordExclusionIntegration|EntryChannelCandidatesIntegration)$' ./internal/store
go test -race -count=1 -json -timeout=15m ./internal/store ./internal/search
go build ./...
go vet ./...
gofmt -l .
```

수정 후 신규 14사례와 기존 vector·halfvec 진입 채널 계약을 포함한 30건이 3.140초에 실패·건너뜀 없이 통과했다. 제외 위치·복수 대안·복수 제외·단일 CLI 플래그·겹침 없는 입력·명시적 OR·긍정/제외 인용구·단독 제외·유니코드 공백·빈 입력을 대조했다. 기존 시험은 그래프·활성·유효 기간·순위·후보 상한·병렬/순차 동등성도 검증한다.

필터 없는 race 인수에서 `internal/store` 1,697건(최상위 376건, 421.095초)과 `internal/search` 342건(최상위 69건, 7.084초)이 실패·건너뜀 없이 통과했다. 건수에는 하위 사례를 포함한다.

build·vet·gofmt·문서 링크/앵커·diff 검사와 독립 읽기 전용 검토를 통과했다. 반복 `-`의 PostgreSQL 해석을 정규화하거나 CLI 플래그 자체를 문자 그대로 검색하는 기능은 추가하지 않았다. 스키마·구성·요구사항·DOX 소유권과 구조는 변경하지 않으며, 키워드 결합의 상세 계약은 검색 SDD, 시험 경계는 테스트 SDD에 유지한다.

시험별 DB 잔류 없음과 idle transaction 0개·생성 컨테이너 ID를 확인한 뒤 이번 시험의 컨테이너·익명 볼륨만 정리했다. 기존 세 컨테이너와 개인 IDE 파일은 보존했다.
