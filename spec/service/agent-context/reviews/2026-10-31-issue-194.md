# #194 복구 요청 중복과 대기 목록 상한 검토

- 대상: [이슈 #194](https://github.com/Alpha-gone/agent-context-sharing/issues/194).
- 기준: `dev`의 `8952f1f`, 브랜치 `fix/194-restore-request-bounds`.

## 변경과 결정

같은 계정·그래프의 미처리 요청은 멱등 처리한다. 기존 그래프 잠금을 얻은 뒤 자동 삭제 상태·과거 소유자 자격을 확인하고, 별도 조회로 같은 계정의 미처리 요청 유무를 확인한다. 이미 있으면 감사 행이나 최초 시각을 바꾸지 않고 커밋하여 웹의 기존 성공 이동을 유지한다. 운영자 처리도 같은 그래프 잠금을 사용하므로 Read Committed의 다음 명령에서 앞선 커밋을 읽는다.

서로 다른 과거 소유자의 요청은 구분한다. 운영자 복구 뒤 다시 자동 삭제된 주기에는 이전 처리 기록보다 새로운 요청을 남길 수 있다. 활성 그래프·사용자 직접 삭제·부적격 계정의 기존 거부를 유지한다. 대기 상태는 계속 감사 기록으로 계산하며 새 테이블·인덱스·마이그레이션을 만들지 않는다.

대기 목록은 기존 요청 시각·감사 식별자 오름차순을 유지하고 SQL에서 최대 100건만 반환한다. 페이지 커서를 추가하는 대신 오래된 요청을 먼저 처리하는 유한 목록을 선택했다. 화면은 상한과 처리 후 후속 요청이 나타남을 안내한다. 같은 목록으로 확인 화면을 구성하므로 표시 범위 밖 graph_id는 404이며 처리 후 범위에 들어오면 확인할 수 있다. 요청을 처리하기 전에는 임의의 뒤쪽 요청을 탐색하는 페이지를 제공하지 않는다.

수정 전 이미 존재하는 중복 감사 행은 삭제하거나 다시 쓰지 않는다. 해당 그래프가 복구되면 기존 규칙대로 모든 앞선 요청이 대기 목록에서 제외된다. SQL LIMIT는 반환·렌더링 건수를 제한하며, 감사 행 검사·정렬 등 DB 내부 비용이 항상 100행에 한정된다는 보장은 아니다. 운영자 자격·컨텍스트 본문 비조회·최초 요청자 복원·감사 보존 계약은 유지한다.

[웹 화면 계약](../sdd/web.md#화면-배치)과 [잠금 판정](../sdd/context-lifecycle.md#판정의-직렬화)을 구현 전에 갱신하고 [시험 설계](../sdd/testing.md#테스트-계층)·[공식 근거](../reference.md#2026-10-31-194-복구-요청-중복과-목록-상한)를 정합화했다. 기존 SRS 복구 자격·감사·최초 미처리 요청 우선 계약의 상세 선택이므로 SRS와 추적 요구사항 ID는 유지했다. DOX pass에서 새 소유 경계나 경로 이동이 없어 DOX를 유지했다.

## 재현과 검증

Go 1.27.1과 고정 PostgreSQL/AGE 이미지 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`의 전용 합성 컨테이너를 사용했다. 공유 개발·다른 시험 DB를 변경하지 않고 정식 7개 마이그레이션을 적용했다. 새 저장소 시험은 별도 8차원 DB를, 웹 시험은 별도 128차원 DB·서명 세션·실제 HTTP 처리기를 사용한다.

- 수정 전 생성자·과거 소유자의 최초 요청과 3회 반복은 각각 감사 행 4개를 남겼다. 동시 최초 요청 8개는 8행을 남겼고 목록은 101건을 모두 반환했다. `/tmp/acs194-red.json`에 재현 결과를 보관한다.
- 저장소 회귀는 반복 요청의 감사 행 1개·최초 시각 보존, 부적격·활성 거부, 다른 과거 소유자 구분, 처리 후 다음 자동 삭제 주기의 새 요청과 동시 최초 요청 8개를 대조한다. 다음 주기는 소유 합성 DB의 삭제·유예 상태를 옮긴 표본이며 유예 스케줄러의 전체 인수를 대신하지 않는다.
- 저장소와 웹은 각각 99/100/101건에서 순서·상한과 처리 후 다음 1건의 노출을 확인한다. 웹은 같은 요청의 반복 POST 성공 이동, 상한 안내, 범위 밖 확인 404·처리 후 확인 진입도 대조한다. 기존 웹 시험의 본문 비조회·출처·세션·오류 사상·최초 요청자 처리 계약은 함께 유지한다.
- `TEST_DATABASE_REQUIRED=1 go test -race -p 1 -json ./internal/store ./internal/web -count=1 -timeout=15m`에서 전체 저장소 1,798건·웹 813건이 실패·건너뜀 없이 통과했다. 결과는 `/tmp/acs194-modules.json`에 보관한다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check`와 문서 로컬 링크·앵커 검사를 마쳤다.
- 시험 종료 후 전용 기본 DB와 postgres 외 임시 DB가 없고 idle transaction이 0임을 확인했다. 소유 컨테이너와 연결 익명 볼륨만 정리한 뒤 잔류가 없음을 확인했으며 기존 개발·다른 시험 자원은 유지했다.

독립 읽기 전용 검토에서 잠금 뒤 명령별 스냅숏, 요청자·복구 주기 구분, 100건 상한·404·처리 후 후속 노출과 회귀 범위를 확인했으며 수정이 필요한 결함은 발견되지 않았다. 검토자는 DB 시험을 따로 실행하지 않았다. 기존 전체 회귀의 headless Chrome 156.0.8078.74 인수도 통과했다. 이번에 추가한 101건 대기 흐름은 HTTP 인수로 확인했으며 해당 흐름의 별도 브라우저 조작과 Safari·실제 스크린리더 음성은 미실행이다.
