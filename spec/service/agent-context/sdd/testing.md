# 테스트와 직접 연결 인수

단위·DB 통합·격리·대역, 호스트 인수·이행·복귀의 실행 계층을 소유한다. 시험 계획은 실제 합격 결과가 아니다.

## 테스트 계층

공개 인증 가용성은 /56 안의 여섯 /64가 각각 10회 시도한 뒤 다른 출처의 로그인·가입·MCP 동의 허용/거절이 정상 처리되는지 웹 시험으로 확인한다. 소진된 출처는 유효 세션으로도 한도를 우회하지 않아야 한다. 여러 출처의 합산 시도를 전역 분당 한도로 막지 않으면서 동시 요청은 각 출처의 상한을 지키는지, 만료·상태 용량·재시도 안내와 기존 비밀번호 작업 자리 4개·취소 반환·실제 서버 주소 검증을 유지하는지 대조한다.

인증 캐시 회귀는 공개 키·웹 폐기 목록 각각의 적재 중 요청 취소·마감과 정상 대기 요청을 실제 단일 적재 대기 진입 장벽으로 겹쳐 확인한다. 취소된 적재자만 중단하고 정상 요청은 자기 예산 안에서 재조회하여 서명 검증을 완료해야 한다. 시간 경계는 Go testing/synctest의 격리된 가상 시간으로 검증한다. 취소된 두 적재를 4초간 기다린 조회는 새 적재에 남은 1초만 사용하고 총 5초에서 종료해야 한다. 완료와 호출자 취소가 모두 준비된 경우, 저장소 오류 확정 뒤 취소되는 경우, 마감 통지 전 시각만 지난 경우도 대조한다. 부모가 정상인 저장소 오류는 계속 `ErrUnavailable`로 공유하며 각 조회의 예산 소진 뒤 다음 호출이 회복되는지 확인한다. 대기자 자신의 취소, 키 회전·로컬 폐기의 세대 검사와 기존 캐시 상한 회귀도 유지한다.

마이그레이션·감사 회귀는 [#162 검토](../reviews/2026-10-31-issue-162.md)의 항목별로 확인한다. 실제 카탈로그의 모든 키워드에 대해 예약어·타입 함수 이름 키워드만 그래프·tablespace 이름에서 거부하는지, 열 이름 키워드 그래프로 전체 마이그레이션이 적용되는지 확인한다. `status`용 조회는 빈 DB에 이력 테이블을 만들지 않고, 구형 이력의 구성 열을 만들지 않으며, 다른 연결이 적용 잠금을 쥐어도 읽기 전용 트랜잭션에서 기다리지 않아야 한다. 전체 감사는 미등록 `graph_id`의 정점·간선·임베딩을 `graph_registration`으로 보고하고 그래프를 지정한 감사는 보고하지 않아야 한다.

평가 실행기 회귀는 [#177 검토](../reviews/2026-10-31-issue-177.md)의 항목별로 확인한다. 시험 기한 전의 감싼 마감 오류와 기한 경과를 구분하고, 다른 실행의 예약이 있으면 기존 결과보다 예약 충돌을 먼저 보고하는지 확인한다. 입력 스냅숏 뒤 취소는 측정 없이 실패 묶음만 남기고 예약·임시 입력을 정리해야 한다. 변환은 같은 출력 경로·중복 질의 id를 기존 파일을 바꾸지 않고 거부해야 한다. 직접 준비한 평가 그래프의 측정 실패는 `measurement` 단계와 완료된 정리로 보고하고, 확장 과업 판정은 재색인 시간 생략만으로 보류하지 않는다. 적응형 반복 평균은 일부 회차의 미정의 품질 값을 섞지 않는다.

색인·검색·진단 회귀는 [#164 검토](../reviews/2026-10-31-issue-164.md)의 항목별로 확인한다. 소비 루프는 작업을 처리한 회차 뒤 대기 없이 다음 회차를 실행하고 이어지는 빈 회차가 1초부터 늘어나는지 가상 시계로 확인한다. 제공자 호출 분류는 작업 context 취소·마감을 제공자 장애와 구분하고, 2xx가 아닌 HTTP/1.1 응답 세 번이 연결 하나를 재사용하는지 확인한다. 접기는 같은 묶음의 여러 대표 중 비슷한 대표에 접히는지 대조한다. 진단 기동은 저장소 잠금과 다른 슬롯의 기록자 잠금을 함께 쥔 정리 상태에서 기다렸다가 성공해야 하며, 실행 중인 같은 instance는 계속 거부해야 한다.

서버 조립·종료 회귀는 [#161 검토](../reviews/2026-10-31-issue-161.md)의 항목별로 확인한다. 연결을 받고 응답하지 않는 합성 DB로 조립을 붙잡은 뒤 실제 종료 신호를 보내 기동이 기한 안에 취소되는지 확인한다. 신호는 조립이 DB 접속을 시작하여 신호 등록이 끝난 뒤에만 보낸다. 직접 TLS의 없는 인증서는 진단 파일 준비 전에 거부되어야 하고, 막힌 풀 종료는 기한 안에 실패로 보고되어야 한다. 전체 주소 신뢰 대역은 구성 검증에서 거부하며, 서버 쓰기 마감은 요청 공통·MCP 처리 예산보다 길어야 한다.

저장소 계층 정합성 회귀는 [#160 검토](../reviews/2026-10-31-issue-160.md)의 항목별로 확인한다. 유예 만료·멱등성 정리는 시각을 주입하지 않고 DB 시계 기준으로 유예·만료 시각을 옮겨 판정한다. 자동 삭제 뒤 팀 구성원 추가로 부여 경로가 이어져도 유효 등급·등급 부여가 거부되는지, 웹·권한 트랜잭션의 감싼 DB 오류가 저장소 장애로 분류되는지 확인한다. 저장량 불일치가 불변식 위반 내부 장애로 되돌려지는지, 시스템 관계 제안이 cold 임베딩의 접근 시각·계층을 바꾸지 않고 사용자 조회만 승격하는지도 확인한다. 한 그래프의 관계 해석 실패 뒤에도 다음 그래프의 후보가 정리되어야 한다. 운영 경로에서 쓰지 않는 저장소 패키지 전용 준비 진입점은 `_test.go` 파일에 두어 운영 빌드에 포함하지 않는다.

평가 실행기의 모드 전용 옵션 회귀는 지속·기존 업무 효과 비교에 컨텍스트·질의·단계·색인 대상·예산을, 적응형·일관성·적대적 비교에 단계를 지정한 실행이 입력 읽기·DB 구성 확인 전에 거부되는지 확인한다. 검색 단위·외부 원본 비교의 10회 `-repeat`와 지속 평가의 반복·홉 옵션은 사전 검사를 통과해야 하며, manifest가 만든 지속 평가 인자도 고정 예산 없이 같은 검사를 통과해야 한다. 지속 평가의 품질 회귀·상태 위반 `failed`가 manifest 요약에서 not_accepted로, 독립 단위 부족 보류와 `passed`가 deferred로 남는지 합성 판정으로 대조한다.

HippoRAG 변환 회귀는 원 질문 50개와 각 자립형 홉 둘에서 만든 질의 150개를 10회 반복해도 독립 단위 50개·자유도 49로 집계되는지 확인한다. 원 질문과 홉의 공통 비식별 단위, 입력 개수와 무관한 결정성, 다른 데이터셋의 동일 ID 분리, manifest 코드 형식·실물 checksum·문항 매핑과 준비 보고의 독립 단위를 대조한다. 잘못된 문자·하위 홉의 길이 초과·원 질문과 홉 사이의 ID 충돌·중복 ID는 변환 단계에서 거부한다.

복구 요청 회귀는 생성자·과거 소유자의 반복 요청과 같은 계정·그래프의 동시 최초 요청이 감사 행·최초 요청 시각을 늘리거나 바꾸지 않는지 실제 DB에서 확인한다. 다른 과거 소유자의 요청은 구분하고, 부적격 계정·활성 그래프는 거부하며 운영자 처리 뒤 다시 자동 삭제된 주기에는 새 요청을 허용해야 한다. 대기 목록은 99/100/101건에서 오래된 순서와 최대 100건을 대조하고 처리 후 다음 요청이 나타나는지 확인한다. 웹 HTTP 시험은 반복 POST의 성공 이동, 같은 목록 상한·안내, 표시 범위 밖 처리 확인의 404와 처리 후 다음 요청의 확인 진입을 검증한다.

재색인 진행률 계획은 vector·halfvec의 hot/cold 보관 벡터 1,000/10,000행과 소수 활성 대상 표본에서 확인한다. 실제 ReindexProgress SQL·인자를 수집하여 강제 플래너 설정 없이 EXPLAIN ANALYZE/BUFFERS를 실행하고, 전체/그래프 범위·원천 포함/제외의 옛 모델·미색인·대기·실패 값을 원본과 대조한다. 작은 대상 집합은 두 임베딩 context_id 인덱스를 사용하고 보관 행 전체를 읽지 않아야 한다. 63/64/65건 경계·빈 집합과 활성 대상이 대부분인 표본도 대조하여 작은 UUID 배열과 대량 집계 경로의 결과·실제 행·버퍼를 확인한다. 옛 벡터가 없어도 미색인·대기·실패 진단은 계속 검증한다.

사건 구성원의 순서 회귀는 실제 저장소에서 순서만 바꾼 갱신·본문만 변경한 갱신의 제안 입력 조회 횟수가 0인지 확인한다. 실제 집합 변경과 시작/종료/진행 중 상태 전환에는 기존 제안이 실행되는 양성 대조를 둔다. 생성·갱신 응답과 조회의 member_refs 정렬 및 입력 slice 보존을 대조하고, 실제 MCP 생성·갱신·node_get·다른 저장소 인스턴스의 멱등 재생 결과가 같은 순서인지 확인한다. 재생 뒤 쓰기 fingerprint가 불변이어야 하며, 집합 비교가 중복 구성원을 제거하여 기존 거부를 우회하지 않아야 한다.

원천 중복 판정의 질의 계획은 대상 그래프의 원천 1,000개를 고정하고 다른 그래프에 원천 1,000개·10,000개를 추가한 별도 DB에서 확인한다. 실제 `findSourceWith`가 실행한 질의와 인자를 수집해 `EXPLAIN (ANALYZE, BUFFERS)`로 활성·미존재·폐기 원천을 대조한다. 부분 유일 `context_source_ref_idx` 사용과 Context 실제 읽기 0~1행을 확인하며 인덱스 선택을 강제하지 않는다. 같은 locator의 다른 그래프 원천과 문자열 경계 표본을 포함하고, 기존 생성 경합 시험으로 23505 뒤 기존 원천 반환·정점/색인/감사/활동 상태 불변을 검증한다.

출처 계산의 계층화 회귀는 vector·halfvec 각각의 사건→파생→파생→원천 구조에서 확인한다. 출처만 조회한 파생·사건과 내부 조상의 기존 접근 시각 및 hot/cold 계층을 대조한다. 실제 흐름 검색은 일반 읽기·동기화 스냅숏 모두에서 후보 세 채널이 반환 대상 하나만 선택하도록 구성하여, 반환하지 않은 조상은 불변이고 반환 대상만 접근 시각 갱신·cold→hot 승격되는지 검증한다. 공개 묶음 조회의 접근 기록도 유지되어야 한다.

관계 질의의 계획은 다른 그래프에 네 사건 관계 label별 1,000개·10,000개 간선을 추가한 전용 DB에서 실제 조회·정체성·목록·갱신·후보 정리·순환 검사 질의를 기록해 `EXPLAIN (ANALYZE, BUFFERS)`로 확인한다. 쓰기 계획도 시험 트랜잭션에서 실행 후 롤백한다. 대상 그래프의 결과·끝점 재검사·페이지 완전성을 유지하며 간선 실제 rows·loops·filter와 버퍼를 관찰해 다른 그래프 크기만큼 읽는 회귀를 거부한다. 사건 입력 상한은 1,000건을 넘는 본문·참조 표본으로 대상 제외·정렬·부분 인덱스·상한 뒤 조립·신호별 단일 그래프 잠금·상대 사건 묶음 시간 검증을 대조한다. 새 인덱스는 빈 DB·판올림·반복 적용과 기존 적용 이력 보존으로 함께 검증한다.

키워드 제외 조건은 격리 DB에서 긍정·제외 어휘, 복수 OR 대안, 여러 제외 조건, CLI 플래그와 무관한 본문을 섞어 검증한다. 제외 조건이 전체 긍정 묶음에 적용되고 겹치는 긍정 어휘가 없는 후보를 만들지 않아야 한다. 일반 어휘·인용구의 OR, 제외 인용구, 단독 제외와 빈 입력도 대조한다. 기존 vector·halfvec 진입 채널 시험으로 그래프·활성 상태·유효 기간·순위·상한과 병렬·순차 동등성을 함께 유지한다.

질의 임베딩 지연은 취소까지 대기하는 제공자 대역으로 순차·병렬과 Read Committed·동기화 스냅숏 조합을 대조한다. 임베딩 전용 마감 뒤 의미 채널만 `embedding_unavailable`이 되고 키워드·시간 후보와 살아 있는 요청 context가 유지되어야 한다. 호출자 취소 원인과 더 이른 요청 마감은 전체 오류·빈 본문으로 보존한다. 서버 통합 시험은 실제 `internal/index` HTTPS 호출·검색·DB·MCP 처리기를 연결하고, 지연 제공자의 HTTP 취소와 공통 요청 예산 안의 정상 부분 응답을 확인한다. 실제 외부 제공자의 지연·품질 측정과는 구분한다.

2026-10-28 사용자 화면 정상 확인과 명시적 제외 지시를 이번 TEST-06 인수 범위의 판정으로 사용한다. 기존 Chrome 실제 브라우저/자동 키보드·접근성 트리 인수와 수정 후 회귀를 유지하며, TEST-06의 실제 VoiceOver 음성과 추가 수동 키보드 관찰은 이번 인수 범위에서 제외한다. 미실행을 통과로 표시하지 않으며 이미 실행한 자동 키보드·DOM/접근성 트리·선택 상태와 포커스의 검증 결과는 유지한다. Safari는 실제 확인한 시나리오만 기록한다. 이 제외는 보조 기술 지원 전체나 접근성 구현 요구사항의 삭제를 뜻하지 않는다.

파생 수명주기 모듈은 그래프→정점 잠금 아래 갱신과 근거 전파의 직렬화, 잠금을 우회한 시험용 AGE 변경에 대한 방어적 충돌·전체 롤백, 참조 전이의 실제 잠금 대기와 양쪽 커밋 순서·취소·다른 그래프 독립성, 동일 식별자의 이전 판 스냅숏과 명시적 대체 시점의 대상 판 고정, 시스템 표시·폐기·복구·유지의 이력과 정점/큐/감사의 원자성을 대조한다. 이력 도입 전 데이터는 관찰한 기준 판부터 보존하고 알 수 없는 이전 판을 만들지 않는지 확인한다. 이력 조회도 요청 그래프·대상·판 재검사와 저장 손상 거부를 검증한다.

근거 무효 전파의 공개 API 경합은 원천 폐기·파생 폐기·대체 각각에서 검증한다. 바깥 트랜잭션의 미커밋 파생 갱신을 전파가 실제로 기다리는지 `pg_blocking_pids`로 확인한 뒤 커밋한다. 두 작업의 완료·갱신 본문 보존·직접 파생들의 판 증가와 무효 표시·간접 파생의 무변경을 대조한다. 직접 AGE 변경으로 그래프 잠금을 우회하는 손상 주입은 별도 방어 시험으로 유지한다.

테스트 코드 작성·보강·실행 시점은 [개발 계획](../DEVELOPMENT_PLAN.md#테스트-작성과-실행-시점)을 따른다. 아래 계층은 개발 작업 항목의 모듈 시험과 분야별 통합 테스트에서 수행할 검증 내용을 정하며, 개별 코드 편집마다 시험을 요구하지 않는다.

색인 기동 보충은 현재 모델·옛 모델·벡터 누락과 기존 failed·백오프·리스 작업을 같은 그래프에 섞고 vector·halfvec에서 반복·동시 기동으로 검증한다. 기존 작업의 전체 행 보존, 누락 작업만 생성, 현재 모델·폐기 대상 미등록, 기동 전 확보분의 결과 공개와 명시적 재색인의 초기화를 대조한다. 계층 제외·재포함과 제외 정리의 롤백은 기존 재색인 회귀를 유지한다.

| 계층      | 대상                                                                                                                                                 | 데이터베이스 |
|-----------|------------------------------------------------------------------------------------------------------------------------------------------------------|--------------|
| 단위      | `model`의 계층별 필수 속성과 불변, `plan`의 두 단계 한도 판정, `search`의 순위 역수 합 결합·결정적 질의 라우팅·최단 경로 선택·연결 근거 집합 예산 절단 | 필요 없음    |
| 연산      | 저장 계층의 [트랜잭션 경계](context-lifecycle.md#트랜잭션-경계), [판정의 직렬화](context-lifecycle.md#판정의-직렬화), [연산 계약](mcp.md#연산-계약)의 멱등성                                                  | 필요         |
| 격리 위반 | 저장·조회·검색의 그래프 격리                                                                                                                                       | 필요         |

계층을 이렇게 나누는 근거는 [패키지 경계](architecture.md#패키지-경계)의 단방향 의존이다. `model`과 `plan`이 데이터베이스에 의존하지 않으므로 데이터베이스 없이 검증되고, `store`부터는 AGE가 실제로 어떻게 도는지가 결과를 바꾸므로 실물이 필요하다.

검색 입력 단위 시험은 UTC·미지정·양수/음수 오프셋·별도 영 오프셋을 대조하고 잘못된 입력이 검색 저장소·임베딩 호출 전에 거부되는지 확인한다. 플랜 시험은 같은 계정의 표기만 다른 키를 순서와 값의 동일 여부에 관계없이 거부하고 서로 다른 계정은 유지하는지 확인한다. 구성 시험은 중복 계정 플랜이 기동 전에 거부되는지 확인한다. 웹 HTTP 시험은 등급 부여·회수·복구 요청·운영자 복구의 래핑된 오류별 상태·안내·내부 원문 비노출과 성공 이동을 확인한다.

시각화 회귀는 웹 HTTP 응답의 전체 보기 버튼·홉 레이블·목록 선택 수단을 확인한다. Node.js가 있으면 같은 응답의 스크립트를 저장소의 Cytoscape 자산으로 실행해 고립 노드 선택 뒤 버튼·빈 영역·Esc 복귀, 국소 범위 밖 노드의 목록 선택, 홉 `0`·중간·최댓값과 나가는 `derived_from` 근거 경로 강조를 검사한다. Node.js가 없으면 상태 전이 시험의 건너뜀을 명시한다. 브라우저에서는 실제 노드·버튼·키보드 조작과 표시 복귀를 별도로 확인한다. 저장소의 시각화 조회 시험은 서로 연결되지 않은 대체 시작점과 전역 요약이 결과 노드 수 상한을 넘을 때 `0홉` 절단과 최신 시작점 보존을, 상한과 같은 개수에서 절단이 없음을 확인한다. 시작점 목록 조회 직후 그 시작점을 폐기해도 같은 스냅숏의 결과를 반환하고 읽기 연결을 회수하는지 실제 DB로 확인한다. 삭제·복구 목록은 정수 최댓값 페이지 크기에서 추가 조회가 넘치지 않고 활성·삭제 목록을 잘리지 않은 상태로 반환하는지 확인한다.

웹 브라우저 인수는 `internal/web`의 Go 시험이 격리 DB·서명 세션·TLS 서버와 같은 사이트의 다른 출처 서버를 준비하고, Node.js 실행기가 외부 의존성 없이 Chrome DevTools Protocol로 headless Chrome을 조작한다. 실제 로그인 양식과 세션 쿠키 속성, 목록 필터·페이지, 시각화의 포인터·키보드 선택과 포커스, 자산 재검증, 팀·삭제/복구·감사·연결 관리 제출, 교차 출처 거부, 390px 화면의 가로 넘침과 로그아웃을 확인한 뒤 저장소 상태로 결과를 대조한다. 시험 인증서는 오류 무시가 아니라 SPKI 지문 신뢰로 받아 브라우저 캐시를 유지하며, 재검증은 원시 응답 상태 `304`로 판정한다. `WEB_BROWSER_CHROME`은 Chrome 경로, `WEB_BROWSER_EVIDENCE`는 화면 캡처 보관 경로이고, `WEB_BROWSER_REQUIRED`를 설정하면 Chrome·Node.js 부재를 건너뜀이 아니라 실패로 처리한다. Safari 등 실행하지 않은 브라우저와 실제 스크린리더 음성은 별도 수동 결과로 남긴다. 빈·단일·고립·다중 시작점 표본과 상세 조작 수단 전체의 Tab·Shift+Tab 순서, 잘못된 커서의 실제 오류 화면도 대조한다. CDP 접근성 트리는 선택 전/후·0홉·상세 이동·해제·빈/단일 그래프별로 저장하고, 버튼 이름·pressed·상태 영역의 polite/atomic·슬라이더 수치·제목 포커스·본문/방향이 있는 텍스트 근거를 검사한다. DOM의 단위 안내와 CDP의 값 표현은 각각 기록하며 차이를 실제 음성 결과로 해석하지 않는다.

접근성 회귀는 선택 버튼의 기본 의미·고정 이름·pressed 상태·상세 연결과 상태 안내, 텍스트 근거의 방향·초기화를 대조한다. 실제 브라우저에서 Tab·Shift+Tab·Enter·Space·Esc와 슬라이더 방향키, 상세 이동 링크, 범위 밖 노드 재선택과 포커스 유지를 검사한다. 스크린리더에서는 선택 상태와 짧은 변경 안내, 제목 이동 뒤 본문·텍스트 근거 읽기를 수동 확인한다. DOM·접근성 트리 검사만으로 실제 음성 안내를 검증한 것으로 보고하지 않으며 실행하지 않은 브라우저·보조 기술 조합을 명시한다.

웹 경계 회귀는 로그인·모든 웹 변경 요청의 출처 검사와 내부 오류 비노출을 확인한다. 서명 키·폐기 목록 캐시의 동시 조회·장애 회복, 그래프 잠금 뒤 현재 행위자 등급을 재확인하는 시험을 유지한다. OAuth·MCP 경계 시험은 직접 연결 구현과 함께 추가한다.

MCP 쓰기의 저장 값 해석 장애는 독립 DB의 저장 정점 속성을 모델 검증에 실패하도록 바꿔 주입한다. `node_update`·`node_discard`·`node_restore`에 요청 키를 붙여 `internal` 결과, 거부 감사·재생 기록을 포함한 전체 쓰기 롤백을 대조한다. 저장 값만 복구한 뒤 같은 키의 정상 실행·중복 없는 재생을 확인하고, 실제 입력의 필드 오류는 `invalid_argument`·거부 감사·재생 결과로 유지되는지 별도 표본으로 검증한다.

폐기된 사건 구성원은 실제 DB에서 생성·구성원 변경·본문만 변경·시간만 변경을 각각 요청하여 `invalid_argument`와 `field: member_refs`, 거부 감사·재생 기록 각 1건, 사건 미변경을 대조한다. 구성원 폐기만으로 기존 사건이 폐기되지 않는지, 활성 참조로 고친 갱신은 성공하는지, 이후에도 이전 요청 키가 같은 거부 결과를 업무·감사 중복 없이 재생하는지 확인한다.

전송 본문 상한은 DB 없이 계수 가능한 입력 스트림과 루프백 HTTP 서버로 검증한다. 상한 미만·정확한 상한의 정상 처리, 선언 길이 초과의 읽기 전 거부, 길이 미상·chunked·작게 선언된 입력의 제한, 큰 문자열·배열 해석 중 초과, `413` 오류 외피와 인증·도메인 호출 차단을 대조한다. 선행 Origin·메서드·헤더 검증과 상한 이내 Parse Error, 최대 텍스트·참조의 이스케이프 표현도 회귀에 포함한다. 배열 필터는 빈 배열·상한·중복·상한 초과와 공개 스키마의 일치를 검증한다.

동시성을 다루는 설계는 한 흐름을 순서대로 돌려서는 검증되지 않는다. 다음 여섯 항목은 두 연결 이상을 겹쳐 실행해 확인한다.

| 대상                  | 확인할 동작                                                        |
|-----------------------|--------------------------------------------------------------------|
| 마지막 소유자 판정    | 두 회수가 동시에 들어오면 하나만 통과하고 소유자가 남는다         |
| 마지막 접근 가능 계정 | 등급 회수와 팀 구성원 제거가 겹쳐도 유예가 한 번만 시작된다       |
| 계정당 그래프 수      | 한도 직전의 동시 생성은 하나만 성공한다. 서로 다른 멱등성 키의 생성도 바깥 트랜잭션 커밋까지 직렬화된다 |
| 색인 작업 확보        | 유효한 리스의 작업을 다른 작업자가 건너뛰고, 재등록·리스 만료 후 재확보된 작업의 이전 성공·실패가 임베딩·내용 판·작업 상태를 바꾸지 않는다 |
| 요청 단위 일관 읽기   | 동시 쓰기 중 응답 전체가 하나의 커밋 상태로 설명되고 후보별 자원 비용이 기록된다 |
| 쓰기 멱등성           | 같은 계정·키·요청의 두 쓰기가 업무 변경과 연산 기록을 한 번만 만들고 같은 완료 결과를 받는다 |

이 테스트가 통합 계층이 아니라 연산 계층에 있는 이유는 겹치는 단위가 연산이기 때문이다. 잠금이 걸리는 자리는 `store`지만 검증할 것은 두 연산이 함께 들어왔을 때의 결과이며, 그 결과는 연산 경계에서만 관찰된다.

평가 전 색인 준비는 DB 작업 상태와 로컬 제공자 대역을 조합해 검사한다. 429·503 재시도 대기, 재시도 소진·비재시도 오류·차원 불일치, 실제 다른 작업자의 리스와 행 잠금, 현재 모델 불일치·임베딩 누락을 준비 완료와 구분한다. 원천 제외 구성·삭제된 컨텍스트의 제외와 다른 그래프의 실패 격리도 대조한다. 기본·적응형·지속·적대적·일관성 CLI는 색인 미완료에서 실패 종료하고 정상 보고서 파일을 만들지 않아야 한다.

서버 종료 회귀는 HTTP 요청 종료 성공·실패와 작업자 종료 성공·오류·기한 초과를 조합해 원인 보존, 남은 작업자의 종료 시도와 공유 시간 예산을 확인한다. 정상 종료와 기동 실패 정리에서 풀 종료 조건이 같고 이미 종료를 시도한 작업자가 중복 호출되지 않아야 한다. 취소 뒤에도 DB 연결을 유지하는 실제 주기 작업을 시험 기한으로 대기시켜 종료 실패를 반환하고 풀 종료를 건너뛰는지 검사하며, 시험 자체는 작업을 해제하고 연결 풀을 닫아 자원을 남기지 않는다. 시간별 진단 정리는 과거 회차의 guard DB 실패·파일 실패 뒤 다음 회차가 성공하면 `StopMaintenance`가 오류를 반환하지 않는지 확인한다. DB 실패는 회차 실패로만 세고 stderr 장애 통지·기록기 종료 오류에 넣지 않으며, 종료가 중단한 진행 회차의 동반 실패만 작업자 정리에 반환하는지 대조한다. 정리 회차 진단은 DB·파일·취소·마감·잠금 건너뜀을 고정 원인으로 구분한다.

수신 실패 인수는 실제 연결의 진행 요청을 유지한 채 Accept 오류를 발생시키고 준비 상태 이탈과 요청 완료 대기를 확인한다. embedded/external 배치에서 정상 신호·수신 실패·신호 뒤 수신 오류와 각 작업자의 오류 보존·중복 종료 방지를 대조한다. 실제 요청 30초·작업자 10초와 진단 파일 잠금 경합의 flush 5초를 독립적으로 측정하고 개발·운영 Compose의 50초 강제 종료 구성과 대조한다. 강제 연결 종료 뒤에도 DB 연결을 유지하는 시험 요청은 풀 종료 생략을 확인한 다음 해제하여 시험 자원을 반환한다. 구성 실패의 실제 하위 프로세스 종료 코드도 확인한다. 컨테이너의 강제 종료 실행과 운영 배포는 별도 인수다.

자동 삭제 그래프 복구는 실제 등급 부여·회수·팀 접근 소멸과 유예 만료로 표본을 준비한다. 초기 생성자·직접/상속 소유자 이력, 무자격 요청·직접 삭제·무요청 거부, 가장 오래된 요청과 같은 시각의 감사 ID 순서를 대조한다. 전용 시험 DB의 제약으로 요청 감사·등급·처리 감사 쓰기를 각각 실패시켜 원자성과 재시도를 확인한다. 그래프 잠금 대기는 실제 pg_stat_activity로 관찰하며 대기 뒤 상태 재검사·취소 원인·풀/예약 반환, 두 저장소 인스턴스의 단일 적용과 감사 정리 후 완료 요청의 재등장 방지를 검사한다. 실제 웹 세션·TLS 요청에서 양식의 요청자 식별자로 주체를 바꿀 수 없고 운영자 처리만으로 내용 접근·등급을 얻지 않는지 확인한다.

## 임베딩 제공자 실연결 테스트

Gemini 실연결 시험은 `embedding_live` build tag로 기본 단위·통합 회귀에서 분리한다. 실행 전에 API 이용 계층, 외부 전송과 비용을 허용받고 `GEMINI_API_KEY`를 환경에 주입해야 한다. 태그를 선택했는데 키가 없으면 건너뛰지 않고 실패한다.

기본 회귀의 합성 제공자 시험은 같은 검증 흐름에 로컬 TLS 대역을 주입한다. DB 없는 문서·질의 검증과 새 격리 DB의 색인·검색 검증을 각각 실행하고, URL 경계·호출 상한도 실제 키 없이 검사한다. 공식 주소로 전송하는 진입 시험만 태그 안에 두므로 합성 시험 통과를 실제 API 수용이나 품질·비용 실증으로 표시하지 않는다.

DB 없는 제공자 시험은 운영 본문이나 DB를 읽지 않고 고정된 합성 문서·질의로 공식 HTTPS 주소에 최대 두 번 순차 호출한다. 기존 제공자 호출 경계의 timeout·redirect 차단·안전한 오류 처리를 그대로 사용하고 자동 재시도하지 않는다. 성공은 실제 인증·요청 수용·768차원 유한 비영벡터 반환만 뜻한다. 벡터·키·본문은 출력하지 않으며 검색 품질·비용·관계 임계값·A1 성능이나 운영 전환 가능 여부는 별도 평가한다.

두 실연결 경로는 전송 계층에서 각각 두 번·세 번의 상한을 강제하고 복제한 transport를 정리한다. 반복 실행하는 작업자 루프를 시작하지 않으며 실패한 호출을 자동으로 다시 실행하지 않는다. 시험 DB 정리는 생성 직후 등록하여 후속 조립·시험 실패에도 자신이 만든 DB만 제거한다.

격리 DB 실연결 시험도 같은 태그로 분리하며 키와 루프백 주소의 `TEST_DATABASE_URL`이 모두 있어야 한다. DB URL의 질의 옵션은 `sslmode`만 허용해 주소 검사 이후 `host` 등으로 접속 대상을 바꾸지 못하게 한다. 기존 DB는 생성 권한의 경계로만 사용하고 시험이 새로 생성한 DB에 정식 마이그레이션을 적용한다. 합성 문서 두 개의 색인과 질의 한 개의 검색으로 제공자 호출을 최대 세 번에 제한하며 작업자 반복 실행·자동 재시도는 하지 않는다. 768차원 저장·작업 완료·의미 채널·합성 정답의 상위 반환·다른 그래프 격리를 확인하고 시험 DB만 정리한다. 소량 합성 검색은 기준선 대비 통계적 품질 평가나 운영 채택 판정이 아니다.

## 데이터베이스가 필요한 테스트

| 항목      | 확정                                                                            |
|-----------|---------------------------------------------------------------------------------|
| 접속 정보 | `TEST_DATABASE_URL`로 받는다                                                    |
| 미설정 시 | 해당 테스트를 건너뛴다                                                          |
| 강제 실행 | `TEST_DATABASE_REQUIRED`가 설정되면 건너뛰지 않고 실패시킨다                    |
| 스키마    | [스키마 적용](data.md#스키마-적용)의 마이그레이션이 적용한 것을 그대로 쓰고 테스트가 만들지 않는다 |
| 연결 준비 | [데이터베이스 연결](architecture.md#데이터베이스-연결)과 같은 AGE 준비를 거친 연결을 쓴다                        |

DB 없는 모듈 시험에서 DB가 필요한 시험을 선택적으로 제외할 수 있도록 건너뛰기를 허용한다. 문서 변경은 문서 검증을 수행하며, 테스트 실행 시점은 위 개발 계획을 따른다. DB 계층을 완료 근거로 사용하는 시험에서는 필수 실행 설정을 적용한다.

건너뛰기만 두면 조용한 통과가 생긴다. 변수를 깜빡한 실행이 통합 테스트를 하나도 돌리지 않고 통과로 끝날 수 있다. `TEST_DATABASE_REQUIRED`가 그 구멍을 막는다. 지속 통합 환경은 이 값을 설정하며, 설정한 곳에서는 건너뛴 테스트가 곧 실패다.

스키마를 테스트가 만들지 않는 이유는 마이그레이션이 유일한 스키마 출처이기 때문이다. 테스트가 자기 방식으로 테이블을 만들면 그 스키마가 실제 배포와 어긋나도 테스트는 통과한다.

서명 키 저장·회전 통합 시험은 `TEST_DATABASE_URL`의 DB를 생성 권한의 경계로만 사용한다. 시험마다 고유한 임시 DB를 만들고 정식 마이그레이션으로 스키마를 준비한다. 시험 종료 시 연결 풀을 닫고 자신이 만든 DB만 삭제하며, 실패 시에도 취소된 시험 컨텍스트와 별개의 제한 시간으로 정리한다. 시험 계정에는 DB 생성 권한이 필요하며 권한 부족은 건너뛰지 않고 실패로 보고한다. 공유 DB의 키를 조회·변경하여 시험의 초기 상태를 만들지 않으므로 기존 활성 키의 은퇴와 가짜 키의 잔류를 막는다. [TEST-09](../development-plan/testing.md#test-09)의 최종 통합 인수에서 같은 `TEST_DATABASE_URL`의 `TEST_DATABASE_REQUIRED=1 go test -count=1 -p 1 ./...`를 연속 두 번 실행하여 인가 시험과 함께 확인한다.

홉 탐색 구현 비교도 데이터베이스 통합 계층에서 수행한다. 방향·관계 유형·순환·삭제 노드·여러 시작점·상한 절단을 포함한 같은 표본에 현재 너비 우선 탐색과 AGE 내장 경로 질의를 실행하고, 응답 구성 요소가 모두 같은 경우에만 왕복 횟수와 지연을 비교한다. 결과에는 사용한 AGE 이미지 태그와 digest, 그래프 크기, 홉 수, 관계 유형 수, 반복 횟수와 집계값을 남겨 다음 안정판에서 같은 비교를 반복할 수 있게 한다.

양수 상한의 통계 회귀는 시험별 독립 DB에서만 autovacuum을 끄고 소형 정점·간선 통계를 수집한 뒤 새 2만 간선 허브를 적재한다. 통계를 갱신하지 않은 상태와 갱신한 상태의 양방향·들어오는 방향·상한 2/10을 실행하여 노드·간선·순서·거리·절단과 전체 본문 기준선의 동등성을 확인한다. 후보 SQL의 실제 간선 행·loops와 연결 반환을 대조하며, 최신 통계를 먼저 만들어 실패를 숨기지 않는다. 큰 인접 집합의 관계 판정에는 다른 graph_id의 간선·미확정 관계·삭제 정점·역순 삽입·다중 시작점의 격리도 적용한다.

요청 단위 일관 읽기 비교도 데이터베이스 통합 계층에서 수행한다. 동기화 스냅숏은 조정 연결과 채널 연결이 같은 상태를 보는지, 내용 판 방식은 컨텍스트·관계·색인 공개가 겹칠 때 전체 흐름을 다시 실행하는지 확인한다. 동시 쓰기가 없는 표본에서는 현행 병렬·순차 실행과 결과가 같아야 하며, 쓰기가 있는 표본에서는 응답의 후보·간선·출처가 실제 커밋 상태 하나와 일치해야 한다. 연결 수·보유 시간, 재시도율·연속 재시도 횟수와 지연 분포를 함께 남긴다.

쓰기 멱등성은 순차 재시도와 동시 재시도를 모두 연산 계층에서 검증한다. 같은 계정·키·요청은 최초 결과를 재생하고 업무 변경과 `operation_log`를 한 번만 남겨야 한다. 같은 키를 다른 도구 또는 인자에 쓰면 `invalid_argument`, 만료된 키는 새 요청으로 처리하며, 후속 직접 연결에서 키 없는 쓰기는 별도의 재조회로 결과를 확인한다. 업무 트랜잭션이 롤백되거나 1단계에서 거부된 요청에는 완료 결과가 남지 않아야 하고, 커밋 뒤 응답 전달 실패에는 결과가 남아 재시도로 회수되어야 한다.

연결 예약은 풀 상한을 작게 준 저장소로 데이터베이스 통합 계층에서 검증한다. 풀 상한 이상의 동기화 스냅숏 검색과 멱등성 쓰기를 동시에 실행해도 모든 요청이 제한 시간 안에 끝나야 하며, 경계 안 읽기를 3개보다 많이 겹쳐 열어도 한 스냅숏이 쥐는 연결은 4개를 넘지 않아야 한다. 실제 컨텍스트와 영벡터가 아닌 임베딩을 가진 최소 풀 4개에서 조정 연결과 세 채널의 읽기 연결을 모두 확보한 뒤 후보 조립·접근 기록을 동시에 실행해 완료와 `cold`에서 `hot`으로의 복귀, 접근 시각 갱신을 확인한다. 접근 기록 중에는 새 읽기가 자리를 차지하지 않고, 실패·취소 뒤에는 자리가 반환되어야 한다. 컨텍스트 쓰기는 예약 대기 중 연결을 획득하지 않고, 풀 상한 이상의 쓰기 잠금 대기·판 충돌에서도 현재 상태 재판정이 끝나며 예약을 반납해야 한다. 멱등성 저장점은 바깥 예약을 중복 소비하지 않아야 한다. 같은 노드의 동시 폐기·복구는 한 번만 적용되고 나머지는 `ErrInvalidState`여야 한다.

노드의 복구 채널은 원천·파생·사건 모두에서 MCP 폐기→복구→웹 삭제 순서와 보존 기간 이후의 감사 정리 전후를 비교한다. 잠금 대기 중 웹 복구·재삭제나 새 MCP 폐기가 커밋되면 대기한 복구가 현재 삭제 상태와 채널을 다시 판정해야 한다. 현재 폐기의 근거는 정리 뒤에도 복구를 허용하고, 복구 뒤 만료된 기록은 정리되며, 웹 감사 정리가 MCP 복구 허용으로 이어지지 않아야 한다. 복구 트랜잭션이 롤백되어도 병행 정리가 현재 폐기 근거를 잃지 않는지 검증한다. MCP 응답과 거부 감사 기록은 함께 `not_supported`를 반환·기록하고 웹 대체 채널을 알려야 한다.

권한 화면의 회수 안내는 직접 계정·팀 부여를 실제 회수한 결과와 대조한다. 구성원 없는 팀·삭제된 팀, 같은 계정의 직접·상속 중복과 구성원이 여러 명인 유일한 소유자 팀을 포함하고, 상속 행은 회수 수단을 제공하지 않아야 한다.

팀 부여 양식은 같은 출처의 소유자 요청만 저장소에 전달하고, 없는 팀·삭제된 팀과 내부 장애를 구분한다. 실제 DB에서 팀 부여 뒤 구성원의 그래프 목록·유효 등급·상속 행과 부여 감사 기록을 확인하고, 회수·구성원 제거·팀 삭제 뒤 접근이 사라지는지 검증한다. 빈 팀 부여나 삭제된 팀의 거부가 유예를 취소하지 않는지, 그래프 잠금 대기 중 행위자의 등급 상실이 팀 부여도 막는지 확인한다. 관리자별 구성원 목록의 격리, 정렬과 빈 팀 표시도 검증한다.

### 물리 백업과 시점 복구 시험

[WAL 회귀](../../../../test-wal-archive.sh)와 [격리 PITR](../../../../test-pitr.sh)은 OPS-07 모듈 인수에서 실행한다. 개발 `.env`·기존 볼륨·공개 포트·외부 API를 사용하지 않는 별도 Compose 프로젝트에 합성 데이터를 만든다. 새/기존 볼륨의 보관 경로와 실패 시 미기동·보관 재개·재활용·개발 보존 정리를 확인하고, 기본 데이터와 별도 cold tablespace를 물리 백업한다. manifest·WAL 무결성과 손상 거부를 확인한 뒤 새 볼륨으로 복원한다.

기본 백업 뒤 커밋·복구 지점·목표 뒤 커밋을 분리하여 실제 WAL 재생의 포함·제외를 대조한다. 목표 일시 정지 중 관계형·AGE 정점/파생 관계·임베딩·서명 키·큐의 지문, 실제 AGE 질의, 현재 모델과 양쪽 HNSW 실행 계획, 기존 세션 서명 및 전체 불변식을 검증한다. 승격 후 실제 검색·복원된 대기 작업 소비·`cmd/audit` 전체 감사를 실행한다. 합성 표본의 강제 HNSW 계획은 성능 증거로 사용하지 않으며 실제 운영 백업·외부 보관·복구 시간 보장은 별도 인수 대상이다. 종료 코드에는 이 실행의 컨테이너·볼륨·이미지 정리 결과도 반영한다.

### 기존 서명 키 시험 데이터 정리

이전 시험이 개발 DB에 남긴 가짜 키는 해당 개발 DB에 접속한 `psql`에서 아래 조건으로만 정리한다. `key-*`, `rotate-*`, `active-*`, `duplicate-active-*` 접두사 뒤 UUID가 있고 알고리즘·공개 키·개인 키가 모두 이전 시험의 고정값과 일치하는 행만 대상이다. 먼저 조회 결과를 확인하고 같은 조건의 삭제를 실행한다. 정상 키는 삭제하거나 상태를 바꾸지 않는다.

```sql
SELECT key_id, state, created_at
FROM public.signing_key
WHERE key_id ~ '^(key|rotate|active|duplicate-active)-[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$'
  AND algorithm = 'ES256'
  AND public_key = 'test-public-key'
  AND private_key = 'test-private-key';

DELETE FROM public.signing_key
WHERE key_id ~ '^(key|rotate|active|duplicate-active)-[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$'
  AND algorithm = 'ES256'
  AND public_key = 'test-public-key'
  AND private_key = 'test-private-key'
RETURNING key_id, state;
```

삭제한 가짜 키는 복구할 필요가 없는 시험 자료다. 삭제 후 활성 키가 없으면 다음 토큰·세션 발급 시 정상 키를 생성한다. 이전 회전으로 은퇴한 정상 키는 기존 토큰 검증을 위해 유지한다.

## 필터 없는 패키지 인수

모듈 시험과 분야별 통합 인수를 마칠 때는 대상 패키지를 `-run`·`-skip` 없이 실행한다. 특정 시험의 선별 실행은 진단에 사용할 수 있지만 패키지 인수를 대신하지 않는다. 저장소 시험은 다음 세 조건을 구분한다.

```sh
# DB 없는 입력 검증과 전체 패키지의 정상 종료, DB 시험의 건너뜀 확인
env -u TEST_DATABASE_URL -u TEST_DATABASE_REQUIRED go test -race -count=1 ./internal/store
# 접속 정보 누락을 숨기지 않는지 확인: panic 없이 실패 종료해야 한다.
env -u TEST_DATABASE_URL TEST_DATABASE_REQUIRED=1 go test -race -count=1 ./internal/store
# 격리 시험 DB의 접속 정보를 설정한 뒤 DB 연산 전체 인수
TEST_DATABASE_REQUIRED=1 go test -race -count=1 ./internal/store
```

DB 연결 전 입력 거부 시험은 DB 풀이 없는 `&Store{}`로 호출하고 `model.FieldError`의 필드를 확인한다. nil `*Store`의 메서드 호출 가능 여부를 전제로 삼지 않으며, 반환 시 실행되는 관리 진단을 포함해 panic 없이 끝나야 한다. DB 미설정 실행의 건너뜀과 필수 설정의 예상 실패는 실제 DB 연산 통과로 집계하지 않는다.

## 그래프 불변식 감사 테스트

그래프 불변식 테스트는 규칙마다 정상 표본과 한 규칙만 위반한 표본을 둔다. 쓰기 경로는 영향 주변부 검사로 커밋을 막고, `cmd/audit`는 같은 위반을 같은 규칙 식별자와 위치로 보고해야 한다. 전체 감사가 `body`나 임베딩 값을 출력하지 않고 위반을 자동 변경하지 않는지도 확인한다.

## 관계·경로 오염 적대적 평가와 홉별 진단

`cmd/eval -adversarial -contexts <기준 컨텍스트 집합>.json -queries <질의 집합>.json -attacks <공격 표본>.json -repeat <회차> -out <결과>.json`은 운영 데이터나 MCP 표면을 변경하지 않는 오프라인 평가 실행기다. 기존 `-contexts`, `-queries`, `-repeat`, `-out` 계약을 유지하고 `-adversarial`과 `-attacks`만 추가한다. 기준 컨텍스트 집합·질의 집합·모델·검색 예산을 고정한다. 기준선은 별도 평가 그래프에서 실행하고, 각 공격 표본·반복은 독립된 평가 그래프에 공격을 적용한 뒤 같은 그래프에서 명시적 복구까지 실행한다.

공격 표본 파일은 다음 구조를 갖는다.

| 영역 | 필드와 제약 |
|------|-------------|
| 파일 | `version`과 하나 이상의 `samples`를 필수로 둔다. `version`은 기준 컨텍스트·질의 집합의 판과 일치해야 한다. |
| 표본 식별 | `sample_id`와 `attack_type`을 필수로 두며 파일 안에서 유일해야 한다. |
| 공격 유형 | `relation_injection_enhancement`, `shared_edge`, `hub_swap`, `query_bridge_swap`, `false_event_chain`, `mutual_reinforcement` 여섯 값만 허용한다. |
| 공격 변경 | `add_contexts`는 기존 컨텍스트 항목과 같은 형식, `add_relations`와 `discard_relations`는 `{type, from, to}` 관계 정체성 형식을 쓴다. 기준 집합의 key를 참조하고 중복 정체성을 허용하지 않는다. |
| 대상 질의와 성공 조건 | `target_query_ids`로 질의 집합의 기존 `id`를 참조한다. `success_criteria`는 대상 질의마다 `query_id`, `must_return_refs`, `must_omit_refs`를 두고 두 목록 중 하나 이상을 채운다. 목록 항목은 컨텍스트 key 또는 `{type, from, to}` 관계 정체성이다. 공격 후 두 목록의 조건을 모두 만족해야 성공이며 기준선에서 이미 성공인 표본은 거부한다. |
| 오염 식별자 | `contaminated_refs`는 `add_contexts`의 key 또는 `add_relations`의 관계 정체성만 담고 하나 이상이어야 한다. 오염 근거 비율과 추적 시작점은 이 목록으로만 판정한다. `must_return_refs`, `must_omit_refs`, `contaminated_refs` 각각의 목록 안에서 같은 정규화 식별자를 중복하여 적을 수 없다. |
| 정상 기대 경로 | 대상 질의마다 `expected_paths`를 하나 이상 둔다. 각 항목은 파일 안에서 유일한 `path_id`, 대상 `query_id`와 순서가 있는 기준 사건 컨텍스트 key·확정 사건 관계 정체성 단계로 구성한다. 기준선에서 성립하지 않는 경로는 거부한다. |

공통 파일 검증에 더해 공격 유형별로 다음 조건을 강제한다. 모든 추가·폐기 관계는 기존 그래프 불변식을 만족해야 하며, 구조적 위반을 의미 오염 공격으로 대신 세지 않는다.

| 공격 유형 | 표본 성립 조건 |
|-----------|----------------|
| `relation_injection_enhancement` | `add_relations`가 하나 이상이어야 한다. `add_contexts`가 있으면 추가 사건 중 하나 이상이 추가 관계의 끝점이어야 하고, 나머지 추가 컨텍스트는 그 사건의 선언된 근거 또는 구성원이어야 한다. |
| `shared_edge` | 대상 질의가 둘 이상이어야 하며, 같은 `add_relations` 정체성이 둘 이상의 대상 질의 `must_return_refs`에 들어가야 한다. |
| `hub_swap` | `discard_relations`와 `add_relations`를 각각 하나만 두고 같은 관계 유형을 사용하며 적어도 한 끝점을 다른 사건으로 바꾼다. 폐기 관계의 바뀌는 끝점은 기준 그래프에서 확정 사건 관계 입·출차수 합이 최대인 사건이어야 하며 동률은 모두 허용한다. |
| `query_bridge_swap` | `discard_relations`와 `add_relations`를 각각 하나만 두고 같은 관계 유형을 사용한다. 폐기 관계가 대상 질의의 정상 기대 경로에 있어야 하며, 추가 관계는 적어도 한 끝점을 다른 사건으로 바꾸고 해당 질의의 실제 경로를 우회시켜야 한다. |
| `false_event_chain` | 추가 사건 컨텍스트가 셋 이상이고, 그중 셋 이상을 잇는 추가 관계 둘 이상의 단순 방향 경로가 있어야 한다. |
| `mutual_reinforcement` | 추가 사건 컨텍스트가 둘 이상이고 모든 추가 사건이 하나 이상의 추가 관계에 연결되어 하나의 연결 부분 그래프를 이뤄야 한다. 대상 질의의 성공 조건은 서로 다른 오염 식별자를 둘 이상 반환하도록 요구해야 한다. |

관계 삽입·보조 관계 강화는 `add_contexts`와 `add_relations`로 표현한다. 현재 사건 관계에 가중치가 없으므로 기존 관계에 점수나 가중치 속성을 추가하지 않는다. 기존 고차수 허브와 질의별 브리지의 양 끝 교환은 같은 사건 계층과 관계 유형을 유지한 채 기준 관계를 `discard_relations`에, 교란 관계를 `add_relations`에 둔다. 나머지 세 유형도 동일한 변경 목록으로 재현하되 각 표본은 다른 표본과 독립된 평가 그래프를 쓴다.

평가기의 홉별 진단은 정상 기대 경로와 공격 후 실제 평면 응답의 사건 컨텍스트·확정 사건 관계를 대조해 경로별 첫 불일치만 다음 필드로 남긴다. 반환된 `derived_from`, `supersedes`, `member_refs` 참조의 변화는 영향 질의 수에는 반영하지만 네 경고 코드의 직접 비교 대상에는 넣지 않는다.

| 필드 | 값 |
|------|----|
| `sample_id`, `query_id`, `path_id` | 공격 표본과 기대 경로의 식별자 |
| `hop_index` | `0`부터 시작하는 첫 불일치 홉의 순서 |
| `warning_code` | `missing_expected_context`, `unexpected_context`, `missing_expected_relation`, `unexpected_relation` 중 하나 |
| `expected_refs`, `actual_refs` | 컨텍스트 key 또는 `{type, from, to}` 관계 정체성만 담는 목록 |

구조적으로 유효한 오염 관계는 그래프 불변식을 위반하지 않을 수 있으므로 `cmd/audit`의 규칙 식별자를 진단 경고에 재사용하지 않는다. 결과 JSON에는 데이터셋 판, 통제 조건, 반복 회차, 공격 유형별 집계 지표와 위 경고만 남기고 질의문·컨텍스트 본문·원문 경로를 기록하지 않는다.

공격 성공률, 영향 질의 수, 오염 근거 비율, 추적 완전성, 오탐률과 복구 완전성은 [`SRS.md`](../SRS.md)가 정한 분모와 동일 통제 조건으로 산출한다. 성공 여부는 질의별 `success_criteria`로, 오염 근거와 추적 시작점은 `contaminated_refs`로만 판정해 정상 기대 경로를 오염으로 세지 않는다. 같은 질의·표본의 반복값을 먼저 평균하고 공격 전후의 질의별 또는 표본별 대응 차이로 95% 신뢰구간을 계산한다. 반복 회차를 독립 표본으로 쓰지 않는다. 같은 과업의 질의 묶음·표본 간 중복 질의와 미측정 구간은 [실행·집계 경계](evaluation.md#적대적-평가의-실행집계-경계)를 따른다.

복구 단계는 표본의 `add_relations`를 `relation_discard`로 폐기하고 `add_contexts`가 있을 때만 `node_discard`로 폐기한 뒤 `discard_relations`의 정상 관계를 `relation_confirm`으로 재확정한다. 공격 컨텍스트를 폐기하기 전에 오염 관계를 먼저 폐기해 관계 끝점을 잃지 않는다. 자동 소프트 삭제된 그래프 전체를 되살리는 운영자 복구 요청은 사용하지 않는다. 진단 단계는 검색 자동 제외·감점과 관계 자동 삭제를 하지 않으며, 복구 단계의 변경은 표본 명세가 지시한 관리 연산으로만 수행한다.

적대적 평가 테스트는 공격 유형별 기대 정답·대상 질의·성공 조건·오염 식별자·정상 기대 경로와 변경 목록을 고정한다. 평가기는 같은 기준선·모델·검색 예산으로 공격 전후와 복구 후를 실행하고 여섯 지표와 홉별 첫 불일치를 재현해야 한다. 기준선은 별도 평가 그래프를 쓰고, 각 표본·반복은 새 평가 그래프에서 시작하며 공격 후 복구만 그 공격 그래프에서 이어서 실행한다. 한 실행의 컨텍스트·관계 상태가 다음 표본이나 반복으로 넘어가지 않는지도 검사한다. 기준선에서 성공 조건이 거짓이고 정상 기대 경로가 성립하는지, 정상 경로 항목이 오염 근거로 잘못 집계되지 않는지 확인한다. 공격 유형별 성립 조건과 기존 그래프 불변식을 모두 만족하는지, 관계 강화 표본이 가중치 없이 보조 컨텍스트·관계로 구성되는지, 진단 단계에서 검색 제외·감점·자동 관계 삭제가 발생하지 않는지, 복구 단계가 `relation_discard`·필요한 `node_discard`·정상 관계 `relation_confirm`만 사용하는지도 확인한다. 결과에는 원문 질의·본문·경로가 없어야 한다.

평가기는 그래프 단계를 `relations`로, 전역 전환을 켠 상태로 고정하고 동기화 스냅숏으로 검색한다. 운영 기본값인 `baseline`은 사건 관계를 따라가지 않아 관계·경로 공격이 검색에 닿지 않기 때문이다. 채널 후보 상한과 예산, 홉 상한은 결과의 통제 조건에 함께 남긴다. 파일 검증은 정상 기대 경로가 사건으로 시작해 사건으로 끝나고 사건과 기준 확정 관계가 번갈아 나오며, 관계 단계가 앞뒤 사건을 잇는지도 본다. 표본·반복 그래프의 공격 전 응답을 기준선 그래프 응답과 key·순위·간선·진입점 단위로 견주고 불일치하면 공격을 적용하기 전에 중단하며, 공격 전·공격 후·복구 후마다 `AuditGraph` 전체 감사가 위반 없이 끝나야 다음 단계로 간다.

홉별 진단은 경로를 앞에서부터 대조한다. 사건 단계에서는 그 사건이 반환되지 않으면 `missing_expected_context`, 반환된 확정 사건 관계로 기준 그래프에 없는 사건이 붙으면 `unexpected_context`다. 관계 단계에서는 기대 관계가 반환되지 않으면 `missing_expected_relation`, 바로 앞 사건에서 기준 그래프에 없는 관계가 기준 사건으로 뻗으면 `unexpected_relation`이다. 기준 그래프에 원래 있던 관계와 사건은 기대 밖으로 세지 않는다. 영향 판정은 컨텍스트 순위와 모든 반환 간선을 견주므로 참조 반환 변화가 여기에 들어간다. 추적 완전성은 반환된 첫 오염 항목까지 응답의 진입점에서 반환 간선만으로 닿는지 본다. 첫 오염 항목이 진입점 자신이면 관계 경로 없이 닿은 것이므로 추적 완전성은 SRS 분모대로 유지하되 그 비율을 `trace_entry_ratio`로, 진입점이 아닌 첫 오염 항목만의 추적 완전성을 `relation_trace_completeness`로 따로 남긴다. 시간 필터는 질의와 무관하게 최근 기록을 후보·진입점으로 고르므로, 공격 컨텍스트의 기록 시각은 기준 그래프 생성 시각보다 앞에 두어 적재 순서만으로 시간 채널이나 최근 기록 동점 처리의 이점을 얻지 않게 한다. 오탐률의 통제 질의는 표본의 대상이 아닌 질의이고, 오염 식별자 반환과 그 질의의 정상 기대 경로 경고를 원인별로 따로 기록한다. 공격 성공률·오염 근거 비율·오탐률은 공격 전 값과, 복구 완전성은 공격 후 같은 판정 값과의 대응 차이로 신뢰구간을 계산한다. `cmd/eval -convert own-adversarial`은 이 형식의 기준 세트와 여섯 유형 표본 하나씩을 결정적으로 만든다. 생성 표본의 공격 컨텍스트 본문은 질의 문장의 표식·어휘를 쓰지 않는다. 그래서 키워드 채널에서 본문 어휘만으로 진입점이 되지 않고 추가 관계로만 대상 질의에 닿는다. 의미 채널 진입 여부는 제공자 임베딩에 따라 달라지므로 재측정의 진입점 오염 비율로 확인한다.

2026-09-27 측정에서 여섯 유형의 공격 성공률은 0.714였다. 관계 삽입·공유 간선·허위 연쇄·상호 강화는 모두 성공했고 허브·브리지 교란은 제외 조건 항목이 계속 반환되어 실패했다. 추적 완전성과 복구 완전성은 1, 상태 누출과 불변식 위반은 0이었다. 오탐률 0.759는 모두 대상 밖 질의가 오염 식별자를 실제로 반환한 경우였고 경로 경고 오탐은 0이었다. 측정 조건과 값은 `reviews/2026-09-27-adversarial-eval.md`에 있다. 이 측정은 공격 컨텍스트가 적재 순서로 시간 채널 진입점이 되던 구현의 값이며, 시간 조건 통제와 진입점 분리 전후의 Gemini 임베딩 재측정은 `reviews/2026-10-31-issue-172.md`에 있다.

## 검색 단위 완전성 비교 시험

`FR-AGENT_CONTEXT-160`·[EVAL-09](../development-plan/evaluation.md#eval-09)의 모듈 시험은 [검색 단위 실행 계약](evaluation.md#검색-단위-비교의-실행-입력과-결과)을 대조한다. 주체·조건·예외·부정·선행 참조·다중 턴 결정의 의미 요소와 두 원천을 갖는 대화·코드/문서 표본에서 두 경계 조건의 완전성·근거 연결을 따로 확인한다. 사람 검토와 자동 판정 불일치, stale 검토/trace 해시, 요소 범위 누락, 경계 외 속성 변경, 과업 누락·미측정 비용, 부분 근거 주석과 품질/성공률 하락의 후보 판정을 검사한다. 근거 주석 완전성은 입력 기준으로 대조한다. 기대 경로가 없는 입력은 `complete_retrieval_annotations=false`·보류로, 주석이 완전하지만 첫 노드가 반환되지 않아 경로 연속성이 정의되지 않은 회차는 주석 완전과 해당 지표 표본 제외로 남는지 확인한다.

실제 CLI는 두 표본군·두 조건·각 10회의 새 그래프에서 원천 본문 보존, 색인 HTTP 시도·벡터 행/열 바이트, 전체 검색 지표와 독립 단위 분모를 대조한다. 검색 단위 완전성 0인 파생도 반환 근거 완전성 1일 수 있음을 확인한다. 입력·통제 환경 불일치의 사전 거부, 부분 채널 실패·정리 실패의 정상 보고서 차단과 신호 취소 후 자원 정리를 검증한다. 합성 의미 판정·과업 trace와 고정 벡터는 구현 인수 자료이며 실제 사람 검토·에이전트 업무 효과·공개 검색 효과의 근거로 사용하지 않는다. 판정 단위 시험은 구간이 0을 포함하는 과업 성공률 감소를 거부하지 않고, 독립 단위 1개의 감소는 표본 부족 보류로, 유의한 감소는 `quality_or_task_regression` 거부로 확인한다.

## 외부 원본 재현성 비교 시험

`FR-AGENT_CONTEXT-161`·[EVAL-10](../development-plan/evaluation.md#eval-10)은 [원본 비교 실행 계약](evaluation.md#외부-원본-비교-실행-계약)을 격리 HTTPS 출처에서 검증한다. 고정 판·같은 주소의 내용 변경·이동·삭제·권한 상실·일시 장애와 고정 판 없는 출처를 별도로 구성하고, URI의 판/범위 식별과 응답 판·실제 내용 일치를 각각 대조한다. 같은 내용이 다른 판으로 반환되는 경우와 범위 밖 내용만 바뀌는 경우도 구분한다.

모듈 시험은 경로/query 판 결합·바이트 범위·snapshot checksum·승인 origin·자격 준비·root 밖 symlink·잘못된 JSON/옵션의 사전 거부를 확인한다. HTTP 200만으로 성공시키지 않고 부분 응답·304·본문 절단·크기 초과·지원하지 않는 인코딩·범위 누락·헤더 중복/불일치·헤더/본문 시간 초과·전송 실패·snapshot 미측정을 구분한다. 단일 판정에서 연결 성공과 원본 내용 일치가 같지 않음을 검사한다.

실제 CLI는 DB·임베딩 설정 없이 일곱 통제 유형을 각 10회 조회한다. 총 시도·유형별 실패·미측정과 고정 판 없는 출처의 내용 일치, 고유 표본/독립 단위 분모를 대조한다. redirect를 따라간 추가 접속이 없고 snapshot이 바뀌지 않은 것을 확인하며, 마지막 snapshot 준비 실패가 첫 GET도 막는지 검사한다. 실제 종료 신호는 진행 중 GET을 취소하고 정상 보고서를 만들지 않아야 한다. URI·원문·자격이 결과와 오류에 없는지도 확인한다. 이 합성 검증은 실제 외부 출처의 보존·인가·판 제공 정책을 인수한 증거가 아니다.

## 업무 효과·비용·축소 비교 시험

`FR-AGENT_CONTEXT-116`·`163`·[EVAL-12](../development-plan/evaluation.md#eval-12)의 모듈 시험은 기존 네 업무 지표와 [확장 과업 계약](evaluation.md#에이전트-업무-비용과-축소-비교)을 독립적으로 검증한다. 기존 입력은 최소 세 대응 표본·네 필수 숫자와 0/누락/null을 대조한다. 확장은 조회 없음/있음·무관 컨텍스트·원문/요약/관찰 마스킹을 각각 실행하고 세션 재개·협업 인계·사실·다중 근거와 독립 단위를 구분한다.

성공·실패·timeout·취소의 전체 분모, 전체/성공만 시간·턴·호출·개입, 10회→과업→독립 단위 평균·Student t 구간과 유의한 악화를 대조한다. 같은 과업 해시의 독립 단위 분리, 중복/누락 회차·순환 순서·모델/성공 조건/trace 결합·준비 상태 불일치를 거부한다. 세 비용 구간·다섯 항목의 단가 기준량·배분율·토큰 네 범주 산식, 측정 0·미측정·비해당과 가격 없는 실제 사용량 보존을 확인한다. 요약 준비 토큰/비용을 버리지 않고 필수 근거 재조회 불가·비용/시간 누락·합성 기록·유형별 표본 부족은 판정을 보류한다. 입력 순서만 바뀌면 집계가 같아야 한다.

실제 CLI는 DB·임베딩 접속 없이 세 비교 입력에서 보고서를 생성한다. 잘못된 모드/전용 옵션을 입력 읽기·출력 생성 전에 거부하고 알 수 없는 필드·null·과대 입력·출력 실패를 확인한다. 결과에는 원문/관찰 이력 해시·본문·개인 정보가 없고 비용별 실제 사용·단가·금액과 수입 trace 출처만 남긴다. 이 시험은 합성 기록을 집계한 실행기 인수이며 실제 에이전트 과업을 수행하거나 유료 제공자의 단가·업무 효과를 실증한 근거가 아니다. 전체 평가 분야 통합은 EVAL-13, 저장소 전체 시험은 TEST-09에서 별도로 수행한다.

## manifest 실행·결과 저장·실패 보고 시험

[EVAL-13](../development-plan/evaluation.md#eval-13)은 [manifest 실행 계약](evaluation.md#manifest-실행과-결과-묶음)을 모드별 입력·실제 실행·파일 경계로 인수한다. 직접/준비/복합 입력의 checksum·판·문항/유형/과업/독립 단위·모델·예산·준비/캐시·단가 불일치와 잘못된 옵션을 거부한다. 검증 뒤 원본 파일을 바꾸어도 비공개 스냅숏으로 실행되는지 확인한다. 원본 비교의 공유 수집 파일과 내장 지속 시나리오도 대조한다.

macOS/Linux에서 정상 네 파일·완전한 JSON·권한·같은 ID의 동시 예약·기존 파일/빈 디렉터리/심볼릭 링크의 보존을 검사한다. 부분 JSON·필수 필드 누락·부분 파일 기록·취소·시간/요청/색인 예산 초과·정리 실패는 정상 summary를 만들지 않아야 한다. 실패의 안전한 코드·완료 회차·정리 상태와 실제 그래프/요청/벡터 준비량을 대조한다. 과업 기록 수입을 실제 호출로 세거나 미측정 비용을 0으로 채우지 않는다. manifest 금액과 실제 산정의 불일치도 거부한다.

실제 TLS/DB와 자식 CLI의 SIGINT에서 요청 취소·독립 정리와 연결 반환을 확인한다. 같은 프로세스의 로컬 대역은 표준 CA 캐시의 이전 초기화에 의존하지 않도록 시험 transport에 대역 CA를 주입한다. 판정은 합성/미검증·불충분 표본·미측정의 보류, 유의한 악화/실패의 비채택과 완전한 수입 trace의 채택 분기를 구분하고 기본 활성화를 허용하지 않는다. 전체 평가 실행기 시험은 이 분야 인수에 포함하되 실제 공개 효과·에이전트/유료 비용 실증·전체 저장소 TEST-09와 구분한다.

## 테스트 사이의 격리

각 테스트가 자기 `graph_id`를 만들어 쓴다. 별도의 정리 장치나 데이터베이스 재생성을 두지 않는다.

이것이 성립하는 근거는 [격리 강제의 구현](data.md#격리-강제의-구현)이다. 모든 그래프 질의가 `graph_id`를 필수 인자로 받고 반환 전에 대조하므로, 서로 다른 `graph_id`를 쓰는 테스트는 상대의 데이터를 볼 수 없다. 제품의 격리 설계가 그대로 테스트 격리가 되며, 격리가 깨지면 테스트가 서로 간섭해 그 사실이 드러난다.

그래프에 속하지 않는 `team`, `signing_key`, `revoked_token`은 이 방식이 적용되지 않는다. 테스트마다 자기 식별자만 쓰고 다른 테스트가 넣은 행을 세거나 지우지 않는다.

`index_task`는 `graph_id`를 갖지만 이 방식이 그대로 적용되지 않는 유일한 표다. 색인 작업자가 그래프를 가리지 않고 가장 오래된 대기 작업을 확보하도록 설계되어, 확보 자체가 그래프 경계를 넘는다. 따라서 색인 큐를 쓰는 테스트는 두 가지를 지킨다. 확보는 `ProcessNextIndexTaskInGraph`로 자기 그래프에 한정하고, 대기 시각을 바꾸는 준비 작업도 자기 그래프의 행에만 적용한다. 조건 없이 다른 행을 미루거나 앞당기면 같은 데이터베이스를 쓰는 다른 테스트의 확보 순서가 함께 바뀐다.

그래프를 가리지 않는 `ProcessNextIndexTask`는 운영 색인 작업자가 쓰는 경로이므로 확보 조건이 깨지면 작업자가 조용히 일을 찾지 못한다. 좁힌 확보만 검사하면 그 사실이 드러나지 않으므로 이 진입점도 통합 테스트로 덮되, 대기열 순서로 격리를 지킨다. 검사는 자기 행만 다른 준비 도우미가 쓰는 값보다 더 먼 과거로 당겨 대기열 맨 앞에 두고, 확보 직전에 선두가 실제로 자기 작업인지 확인한 뒤에만 부른다. 선두를 보장할 수 없으면 남의 작업을 집지 않고 건너뛴다.

이 방식이 성립하는 이유는 확보 질의가 `enqueued_at`과 `task_id` 순으로 가장 오래된 하나만 고르기 때문이다. 자기 행이 확실히 앞서면 범위를 지정하지 않아도 남의 작업에 닿지 않으므로, 잠금이나 별도의 데이터베이스 없이 자기 행만 건드린다는 규칙을 지킬 수 있다. 운영 경로의 작업자는 자기 배포의 데이터베이스를 혼자 쓰므로 이 제약을 받지 않는다.

## 격리 위반 테스트

`FR-AGENT_CONTEXT-101`의 검증 방법이 "격리 위반 테스트가 모든 연산을 덮는지 확인"이다. 덮었는지를 사람이 세지 않게 만든다.

| 단계 | 동작                                                                        |
|------|-----------------------------------------------------------------------------|
| 1    | 서로 다른 두 그래프를 만들고 양쪽에 컨텍스트와 관계를 넣는다                |
| 2    | 한쪽 그래프에만 등급을 가진 계정으로 연산 13종을 모두 호출한다              |
| 3    | 응답에 담긴 정점과 간선의 `graph_id`가 모두 요청한 그래프의 것인지 확인한다 |
| 4    | 연산 목록에 있는데 이 테스트에 없는 연산이 있으면 실패시킨다                |

4단계가 핵심이다. 연산 목록을 [SRS MCP 연산 매핑](../SRS.md#mcp-연산-매핑)과 같은 한 곳에서 가져와 테이블 주도로 돌면, 연산을 새로 만들고 격리 테스트를 빠뜨렸을 때 테스트가 스스로 알린다. 목록과 테스트를 따로 두면 둘이 어긋나는 것을 아무도 보지 못한다.

권한 없는 그래프를 `not_found`로 답하는 처리도 여기에서 함께 본다. [요청 처리 순서](mcp.md#요청-처리-순서)가 등급이 아예 없는 그래프의 존재를 노출하지 않기로 했으므로, 상대 그래프를 지정한 요청이 `permission_denied`가 아니라 `not_found`로 돌아오는지 확인한다.

## 대역

임베딩 제공자만 대역으로 바꾼다. [외부 경계](architecture.md#외부-경계)가 이것을 유일한 외부 의존으로 확정했으므로 대역이 필요한 곳도 하나다.

| 대역이 만드는 상황 | 확인할 동작                                                   |
|--------------------|---------------------------------------------------------------|
| 정상 응답          | 색인 작업이 완료로 바뀌고 벡터가 저장된다                     |
| 연속 실패          | [색인 재시도](indexing.md#색인-재시도)의 5회 지수 백오프 뒤 `failed`로 남는다        |
| 차원 불일치        | 재시도하지 않고 즉시 실패한다                                 |
| 색인 호출 지연     | 컨텍스트 저장과 조회의 지연이 늘지 않는다                     |
| 질의 호출 실패     | 의미 유사도 채널만 빠지고 부분 상태로 알린다                  |
| 질의 호출 지연     | 흐름 조회의 지연이 그만큼 늘고 다른 연산은 영향을 받지 않는다 |

색인 호출 지연 항목이 [SRS 색인 처리](../SRS.md#색인-처리)를 비동기로 분리한 이유를 검증한다. 대역이 응답을 늦춰도 컨텍스트 저장과 조회의 지연이 늘지 않아야 한다.

질의 호출 두 항목을 따로 두는 이유는 그 호출만 요청 경로 안에 있기 때문이다. 색인 호출과 달리 지연이 그대로 응답 시간이 되고 실패가 즉시 그 요청에 드러나므로, 같은 대역으로 두 경로를 모두 확인한다. 제공자가 하나이므로 대역도 하나다.

## 첫 Codex CLI 상호운용 시험

`TBD-AGENT_CONTEXT-064`의 선택 기준은 확정되었고 실제 적합성 검증은 대기다. 대상은 macOS의 Codex CLI `0.160.1`, 서버는 Go `1.27.1`, 공식 MCP Go SDK `v1.8.0`, 초기 revision은 `2026-07-28`다. Codex 앱·IDE 표면으로 지원 완료를 확대하지 않는다.

첫 공개 client는 사전 등록 ID를 Codex의 서버별 `oauth.client_id`에 지정한다. callback은 `http://127.0.0.1:49152/callback`, `oauth.callback_url`·`oauth.callback_port`는 같은 URI·포트다. 실제 브라우저 요청 URI와 수신 주소·포트·사전 등록이 정확히 같은지 확인한다. issuer 지원 메타데이터와 성공·오류 응답의 `iss`도 일치해야 한다. 외부 MCP·authorize·token은 HTTPS이고 HTTP 예외는 loopback callback에 한정한다. 이 문서 작업은 실제 호스트 설정·자격 증명을 바꾸지 않는다.

| 재시작 | 호스트 보안 저장 자격 재사용, 서버 교체 후 같은 DB 결합 확인 | 안전한 저장 복원이 없으면 지원 판정 보류 |
| 회전 경합 | 같은 이전 토큰의 소비 성공 1회와 후속 계열 폐기 | 소비 응답 유실·재사용도 폐기 결과 유지, 오류로 폐기 롤백 없음 |
| 명시적 폐기 | 본인 연결 관리 뒤 남은 접근·갱신 차단 | 다른 계정의 조회·폐기와 등록 재사용 거부 |
| 키·저장소 | 회전 키 재조회·기존 유효 키 검증, DB 장애 분류 | 내부 장애가 401이나 재인가 반복으로 위장되지 않음 |
| 불확정 쓰기 | 동일 키 순차·동시 재생·현재 권한 재검사 | 다른 지문 거부, 커밋 뒤 취소·단절이 최초 결과를 지우지 않음 |

계약 시험에서는 시계를 주입하여 수명 경계를 검증하고 실제 호스트 시험에서도 접근 만료·갱신·재시작의 관찰 증거를 남긴다. 결과에는 정확한 판·표면·서버 구성 판·실행 시각·성공/실패 단계와 비식별 상관 ID만 남긴다. 저장 위치의 기능 소개나 CLI 도움말 확인을 OAuth 재사용 성공으로 보고하지 않는다. 모든 필수 흐름이 통과한 대상만 지원으로 판정한다.

2026-10-26 [실제 CLI 전송 검토](../reviews/2026-10-26-test-08.md)에서 macOS/arm64 Codex CLI 0.160.1의 `exec`를 실제 조립 서버에 연결했다. 기본 비활성인 mcp_2026_07_28을 누락한 초기 시험의 지원 실패 판정은 정정했다. 공식 0.147.0부터의 opt-in 지원을 확인하고 `features.mcp_2026_07_28=true`에서 server/discover·tools/list의 요청별 2026-07-28 메타데이터·필수 헤더와 HTTP 200을 인수했다. 비활성 대조는 이전 initialize 요청의 400/-32020 거부다. 별도 CA/서버 인증서의 TLS 검증과 일반 HTTPS 대조를 유지했다. 이는 전송 사전 인수이며 OAuth·저장/갱신·도구 호출과 TUI·앱·IDE는 미인수다. 다음에는 같은 기능 활성 구성에서 나머지 TEST-08 흐름을 실행하며 목표 계약·TBD-064를 유지한다.

[TEST-08 최종 인수](../reviews/2026-10-27-test-08-completion.md)에서 실제 1시간 접근 만료와 CLI 단일 갱신·새 프로세스 재사용, OAuth 결합 거부·403/500·실제 쓰기 취소·현재 권한/지문/판 재검사·중복 쓰기를 확인했다. 관련 267건과 실제 만료 1건, 총 268건이 필수 DB·race에서 실패·건너뜀 없이 통과했다. 선정한 macOS CLI 0.160.1 exec·features.mcp_2026_07_28=true·파일 자격 저장 구성에서 TEST-08을 완료하고 TBD-064를 해소했다. [OPS-09](../reviews/2026-10-27-ops-09.md)는 DB 중단/복구·계층별 선행 검증을 마쳤으며 배포 전체의 조합 장애·회복 인수는 진행 중이다. 실제 1시간 만료는 codex_expiry_live 태그·75분 go test 상한에서 별도 실행한다. 실제 만료 자격의 직접 거부와 호스트 선제 갱신을 구분하고 401을 받은 뒤 갱신하는 경로만 강제하지 않는다.

## 새 설계 분야의 검증 경계

- 진단 파일: [파일 저장 인수](observability.md#파일-저장-인수)의 권한·민감정보·회전·총상한·실패·재시작 시험.
- 공개 평가: [실행 설계](evaluation.md#초기-공개-평가-실행-설계)의 데이터 판·근거 유출 방지·독립 단위·색인 준비·비용 누락·원자적 결과 기록 시험.
- 저장 계층: [온라인 계층화](data.md#저장-계층화)의 hot/cold 직접 검색·접근 기록·병렬 이동·백업 복원 시험.
- 설계 경계: [패키지 경계](architecture.md#패키지-경계)의 허용 import와 실제 의존을 대조한다. 패키지·분야 인수와 전체 기동·실제 호스트 인수는 각각의 실행 근거로 구분한다.

이 문서는 검증 계약을 소유한다. 현재 구현의 실행·완료 근거는 [개발 계획](../DEVELOPMENT_PLAN.md)과 분야별 검토에서 확인하며 문서 링크·추적표 검사를 실행 시험의 합격으로 간주하지 않는다. 진단 파일의 격리 저장 인수는 [OBS-08 검토](../reviews/2026-10-23-obs-08.md)를 따른다. Linux 커널 오류 주입은 시험 자식 프로세스의 특정 파일 쓰기에만 한정하며 호스트 디스크를 채우거나 운영 마운트를 변경하지 않는다. 실제 컨테이너 보존과 운영 배포·다중 호스트·외부 stderr 수집은 별도 증거로 구분한다.


## 임베딩 용도별 비교 시험

[임베딩 비교 실행 계약](evaluation.md#임베딩-비교-실행-계약)의 한 축·조정/최종 분리·환경/스키마 사전 검사와 실제 10회 재색인/정리를 검증한다. 필수 DB 시험은 `TEST_DATABASE_URL`의 vector(768), `TEST_EMBEDDING_SMALL_URL`의 vector(128), `TEST_EMBEDDING_HALF_URL`의 halfvec(768)를 격리 준비하고 `TEST_DATABASE_REQUIRED=1`에서 누락을 실패로 처리한다. 제공자는 합성 HTTPS이며 실제 유료 모델 효과와 구분한다. 판정 단위 시험은 지연 차이 없이 벡터 열 바이트·HTTP 시도 수·실측 금액만 유의하게 줄어든 실제 출처 비교를 비용 개선 후보로, 미계측 금액·증가·비유의·단일 독립 단위·합성 출처를 보류로 확인하고 지연·비용·둘 다의 사유를 구분한다. 후보 구성의 사용 사례별 p95 초과는 단일 독립 단위·합성 출처에서도 `latency_slo_exceeded` 비채택으로, p95에 들지 않는 단일 질의 이상치와 기준 구성의 지연은 SLO 판정 밖으로 확인한다. 그래프 단계·색인 대상 비교의 판정 시험도 독립 단위 1개에서 채널 실패·p95 초과가 표본 부족 보류보다 먼저 비채택되는지 확인한다. 채널 실패 집계는 비활성 채널과 진입점 없는 graph 채널을 제외하고 진입 채널의 실제 실패는 세는지 단위 시험으로, 질의 임베딩만 문서와 직교하는 합성 제공자로 관련 국소 후보가 없는 질의를 포함한 적응형 비교가 격자·판정까지 끝나는지 실제 DB로 확인한다.

알려진 관계/전역 점수·음수 점수·keyword 우선·임계값 경계·상한·분모 없음·회차 중복/누락·독립 단위 변경과 사용 사례별 품질 악화/후보 보류를 대조한다. 최종 표본을 바꿔도 조정값이 바뀌지 않아야 한다. 실제 CLI에서 차원/표현별 전체 재색인·호출/저장량·순환 순서와 본문/locator/자격 비노출을 확인한다. 관계 읽기 전용 선별의 top-1을 실제 제안 연산과 대조하며, 두 번째 스키마 불일치·준비/신호 실패·최종 검색 부분 실패·실제 SIGINT 뒤 정상 보고서 미생성과 그래프 정리를 확인한다. 반복 10회를 독립 표본 수로 늘리거나 미측정 비용을 0으로 보고하지 않는다.

인증·웹 방어 깊이 회귀는 키 목록 정상 갱신 뒤 삭제 키 거부·만료 캐시의 저장 장애 거부, 성공 로그인에서만 낮은 bcrypt 비용 갱신과 높은 비용 보존, 동적 응답의 메서드·출처 거부를 포함한 프레임 차단, TLS/로컬 HTTP 쿠키의 설정·삭제 속성 및 TLS에서 기존 이름 거부를 확인한다. 실제 브라우저의 쿠키 접두사 강제·프레임 차단 인수와 HTTP 합성 응답 검증은 구분한다.

폐기·삭제 원천의 중복 생성 회귀는 실제 DB에서 웹 삭제와 MCP 폐기를 각각 적용한 뒤 같은 locator의 새 생성 요청이 기존 식별자·본문·삭제 시각을 유지하고 정점·색인·활동·감사를 바꾸지 않는지 확인한다. 웹 삭제분의 MCP 복구는 계속 거부하고 MCP 폐기분은 해당 복구 경로를 유지한다. MCP 처리기 시험은 `creation_status=existing_deleted`·삭제 시각·새 생성/복구 아님·활성 근거 사용 불가·조건별 복구 안내와 정상 응답 외피, 활성 원천의 기존 응답 유지를 대조한다.

진단 실패 원인 회귀는 HTTP 401/403/404/405/413/429·일반 5xx·TLS·요청 예산·취소·panic(부분 응답 포함), 기동 완료·구성/DB/인가/스키마 실패와 정상 정리의 분리, HTTP 수신 네트워크 실패의 DB 오분류 방지를 검증한다. MCP의 고정 결과 code·감싼 원인·임의 구조화 값·손상 결과와 원문 비노출, 인증 취소/마감과 순수 저장 실패, 실제 색인 제공자의 401/403·429/5xx·응답 계약·차원 오류의 사유·수준을 대조한다. DB/race 실행은 서버·인증·MCP·색인·진단 패키지 범위로 수행하며 환경 인수의 건너뜀은 별도로 보고한다.

감사 조회의 등급 상세 회귀는 실제 부여·등급 변경·소유권 이전·회수·운영자 복구를 수행한 뒤 없는 등급의 `-` 표시와 이전/이후 순서를 대조한다. 팀 상속 근거는 팀 대상을 유지하면서 구성원 UUID를 상세에 표시하고 구성원 대상 필터에서도 같은 행을 확인한다. 등급 없는 일반 웹 삭제·복구는 상세에 가상의 등급 전이를 만들지 않아야 한다. 소유자 접근·안정 페이지·기간/대상 필터 회귀는 기존 감사 시험을 유지한다.

공백 본문 색인 회귀는 공백·개행·Unicode 공백과 8000자 경계를 문서/질의 양쪽에서 대조한다. 문서는 원문을 기존 접두사 뒤에 전송하고 빈 문자열·잘못된 UTF-8·상한 초과는 거부하며, 질의는 공백만인 입력을 계속 거부한다. 실제 DB에서는 공백 본문의 원천·사건 생성과 사건 갱신 뒤 pending 등록→합성 TLS 제공자 호출→벡터 공개/교체→작업 제거와 completed/INFO 진단을 확인한다. MCP 생성·갱신의 공백 수용·원문 보존과 빈 문자열 거부, 도구 스냅샷도 함께 대조한다.
