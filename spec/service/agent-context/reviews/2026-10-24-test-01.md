## 산출물과 관찰 결과

`internal/store/test_synthetic_test.go`에 고유한 그래프·계정·팀·에이전트·세 계층 컨텍스트와 연결된 참조를 가진 합성 표본을 마련했다. 표본마다 UTC 시계와 가변 참조를 따로 소유한다. 정상 계층, 사건의 정확한 시간 경계와 범위 밖 시각, 다른 그래프의 근거·빈 참조·UTC 위반, 세 등급·미지정/잘못된 등급과 플랜의 정상·한도 일치·초과·무제한·하향 후 축소를 대조했다. 실제 DB에서 세 계층과 팀 상속 등급을 저장·조회하고 전체 불변식 감사가 위반 없이 끝나는지 확인했다.

두 연결이 각각 쓰기를 마친 뒤 커밋 전에 대기하는 도우미를 만들었다. 두 연결 모두 동기화 지점에 도달한 상태에서 외부 조회는 변경을 보지 못하며 해제 뒤 두 커밋이 관찰됐다. 취소한 대기자는 종료하고 시험 정리도 대기자를 해제한다. 대상 계정에만 오류를 내는 시험 트리거를 주입해 실제 SQLSTATE `P0001`과 트랜잭션의 앞선 변경 롤백, 장애 제거 뒤 쓰기 복구를 확인했다. 롤백 오류도 결과에 보존한다.

서명 키와 저장소의 기존 기반을 사용하는 새 하위 프로세스 시험에서 선택 DB 미설정은 건너뜀, 필수 미설정은 실패로 구분했다. 마이그레이션 준비 중 실패와 시험 `t.Fatal` 뒤에는 생성한 DB가 삭제됐다. 생성 권한이 없는 역할은 건너뛰지 않고 실패했다. 이 권한 부족 표본은 고유한 임시 역할을 생성하므로 시험 계정에 `CREATEROLE`도 필요하다. 공유 시험 DB의 활성 키·정상 행·작업을 준비용으로 변경하지 않는다.

URL로 전용 DB를 고르는 기존 시험 도우미 여덟 곳에서 `dbname`·`database` 질의 옵션을 제거하고 `RawPath`를 초기화했다. `internal/store`·`authz`·`index`·`migrate`·`web`과 `cmd/server`의 도우미가 실제 전용 DB인지 스키마 적용 전에 확인한다. 이미 해석한 pgx 설정의 `Database`를 복제·교체하는 새 저장소 도우미도 모든 연결에서 실제 DB를 확인한다. 각 DB는 생성 직후 등록한 정리와 정식 마이그레이션을 사용한다. 색인 큐 정리·연결 종료에도 취소와 독립된 5초 제한을 적용했다.

## 실행 환경과 최종 검증

Go 1.27.1 darwin/arm64, PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6 Linux aarch64에서 실행했다. 이미지 ID는 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`이다. 기존 개발 DB와 분리된 `acs-test01-complete` 컨테이너·tmpfs·임시 loopback 포트·합성 자격을 사용했다. 실제 제공자 API는 호출하지 않았다.

첫 기반 시험은 스키마 없는 기준 DB에서 실행했다. 접속 URL에는 기준 DB를 가리키는 `dbname`·`database` 옵션을 함께 넣어 전용 DB 선택을 덮어쓰지 않는지 확인했다. 색인 큐·서버·웹 소비 시험을 위해 기준 DB에도 정식 마이그레이션 여섯 개를 적용했으며 소비 시험은 각 도우미의 독립 DB 또는 이번 합성 기준 DB만 사용했다.

```sh

# TEST_DATABASE_URL에는 이번 시험 URL과 dbname·database 회귀 옵션을 사용했다.
go test -race -json -count=1 -timeout=240s \
  -run '^Test(Foundation.*|IntegrationDatabasePolicy|IsolatedIntegrationStore.*Integration|SigningKeyIntegration|RotateSigningKeyIntegration|AgentRegistrationDatabase|EmbeddingStorageModelsIntegration|EmbeddingSchemaRejectsIncompleteStorageIntegration|SharedSigningKeyContractIntegration|WorkerReindexProgressWithoutOldVectorsIntegration)$' \
  ./internal/store ./internal/authz ./internal/index
go test -race -json -count=1 -timeout=120s \
  -run '^TestWorkerProposesSimilarEventRelationsAfterIndexIntegration$' ./internal/index
go test -race -json -count=1 -timeout=240s \
  -run '^Test(EmbeddingDimensionMigrationIntegration|PublicAuthenticationAttemptsIntegration|IndexWorkerPlacementsIntegration|PermissionAcceptanceIntegration)$' \
  ./internal/migrate ./cmd/server ./internal/web
GO_BINARY=/Users/alphagone/sdk/go1.27.1/bin/go sh ./check-go.sh
```

- 최종 고유 시험 216건(하위 사례 포함): 저장소 57·인증 5·색인 2·마이그레이션 1·서버 7·웹 144건이 실패·건너뜀 없이 통과했다. 같은 시험의 재실행은 중복 합산하지 않았다.
- 첫 실행에서 새 감사 호출의 필수 인자 누락으로 저장소 빌드가 실패해 보완했다. 이후 소비 시험의 마이그레이션 표본에서 필수 계정 준비 누락이 드러나 고유한 합성 계정을 추가하고 해당 시험을 다시 통과했다. 마지막 롤백 오류 보존 변경 후 동기화·장애 시험도 재검증했다.

- 최종 DB 목록과 역할 목록에서 이번 시험이 생성한 임시 DB·제한 역할의 잔류가 없음을 확인했다.
- 시험 컨테이너를 제거하고 작업 label의 잔류 컨테이너가 없음을 확인했다. 기존 개발 DB·WAL 정리 컨테이너는 보존했다.

## 인수 경계와 DOX pass

TEST-01은 후속 시험에서 사용할 표본·도우미의 모듈 인수다. TEST-02의 논리·구성·결정성·패키지 경계 전수 검사, TEST-03~09의 전체 DB 연산·격리·자원·전송·실제 호스트와 최종 인수를 대신하지 않는다. 제한 역할을 준비하는 권한과 실제 외부 API·운영 인수의 조건을 구분한다.
