# #262 관계 순환 조회의 ID 적재와 재사용

## 원인과 변경

- ConfirmRelation은 relates_to에서도 순환 경로를 읽었으나 모델 판정은 결과를 버렸다. 기존 페이지 조회는 간선과 끝점 본문 전체를 읽고, 순환 금지 유형은 쓰기 불변식 검사에서 같은 간선 ID를 다시 읽었다.
- relates_to의 사전 순환 조회를 생략했다. precedes·causes·part_of는 그래프 행 잠금 뒤 기존 loadAcyclicEdges로 세 label의 확정 끝점 ID만 읽어 판정한다. 실제 확정 결과의 간선을 추가한 지역 경로 함수를 동일 트랜잭션의 불변식 검사에 전달한다. 이미 확정된 관계의 멱등 호출과 다른 쓰기는 기존 지연 ID 조회를 유지한다.
- 쓰기 뒤 속성·격리·시간·정체성 검사용 영향 주변부는 다시 읽고 모든 규칙을 유지한다. relates_to 쓰기 주변부에 다른 순환 금지 유형이 있으면 그 불변식 검사는 계속 수행한다. 전체 감사와 그래프 잠금·감사·내용 판·커밋 경계는 유지한다.
- [수명주기](../sdd/context-lifecycle.md#관계-후보-제안과-확정)·[데이터](../sdd/data.md#그래프-불변식-규칙과-감사)·[시험 설계](../sdd/testing.md)와 [공식 근거](../reference.md#262-관계-순환-조회의-id-적재와-재사용)를 갱신했다. 공개 API·스키마·구성·요구사항·계획·DOX 소유권은 유지했다.

## 질의·필드 전송량 비교

Go 1.27.3·PostgreSQL 18·AGE 1.8.0·`.env`의 TEST_DATABASE_URL·TEST_DATABASE_REQUIRED=1을 사용했다. 유형별 독립 DB에 배경 확정 관계 1,001개와 8,000자 사건 본문을 준비하고 대상 끝점을 배경과 분리했다. 계측은 순환용 페이지 조회와 ID 조회의 횟수·행·RawValues 필드 바이트만 센다. 전체 연산 질의 수·wire 바이트·지연 측정으로 해석하지 않는다. 기준 구현은 b3d3687이며 최종 표본으로 Go overlay 비교도 실행했다.

| 신규 확정 유형 | 이전 조회/행/필드 바이트 | 변경 후 조회/행/필드 바이트 |
|---|---:|---:|
| relates_to | 3 / 1,003 / 49,718,488 | 0 / 0 / 0 |
| precedes | 6 / 2,005 / 49,790,668 | 3 / 1,001 / 76,076 |
| causes | 6 / 2,005 / 49,786,582 | 3 / 1,001 / 76,076 |
| part_of | 6 / 2,005 / 49,788,616 | 3 / 1,001 / 76,076 |

페이지 조회의 행 수는 마지막 행 미리 읽기를 포함한다. 폐기·제안 상태의 재확정도 같은 감소를 보였고, 이미 확정된 관계의 멱등 호출은 relates_to 0회·나머지 3회로 유지됐다. 수정 뒤 모든 측정에서 끝점 본문 전체를 반환한 순환 조회의 행 수는 0이었다.

## 재사용 안전성과 회귀

- 세 순환 금지 유형의 신규 반대 방향 확정과 폐기 후 재확정은 기존 ErrInvalidRelation·relation_type 필드를 유지한다. 다른 유형의 기존 CAUSES 순환이 있는 주변부에서는 PRECEDES 확정도 불변식 오류로 롤백한다.
- 리뷰에서 updateRelation이 같은 relation_id의 다른 정체성까지 갱신하는 경로를 발견했다. A→B/C→D 제안의 ID를 같게 하고 B→C/D→A를 확정한 표본에서 A→B 확정이 C→D의 속성까지 덮어쓰는 것을 재현했다. 그래프·label·ID와 실제 시작/대상 정점을 함께 한정하여 수정했다. A→B만 확정되고 C→D는 원래 proposed 정체성을 유지하며 전체 감사 위반도 0건이다. 재리뷰에서 추가 발견 사항은 없었다.
- 초기 계측 표본은 제안 생성 신호 설정 누락과 part_of 시간 범위를 수정했다. 제안 상태의 준비를 신호 알고리즘과 분리하고 동일 시간 범위의 사건을 사용했으며, 최종 기준/변경 구현을 같은 표본으로 비교했다.

## 검증

최종 실행은 `go test -race -json -count=1 -run '<대상 시험 정규식>' ./internal/store`이며 순환 계측·세 유형 오류 필드·다른 유형 순환·동일 ID 정체성, 동시 반대 방향/중복 확정·폐기 재확정·폐기 끝점·원인 안내·다른 그래프 1,000/10,000개 간선의 계획 범위·관계 롤백·쓰기/전체 감사 대조·주변부 밖 순환 시험을 포함한다. 하위 사례 포함 64건이 실패·건너뜀 없이 통과했다. 정식 마이그레이션을 적용한 새 시험 DB와 시험이 만든 자원만 정리했다.

check-go.sh의 전체 build·vet·gofmt·govulncheck, 독립 코드 재리뷰와 문서 링크·내부 앵커·git diff --check도 통과했다. 전체 저장소 시험·운영 데이터 부하·배포는 수행하지 않았고 사용자 기존 `.env.example`·IDE 변경은 포함하지 않았다.
