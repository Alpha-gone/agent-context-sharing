# #201 후속: 진단 flush 예산 시험의 부하

- 대상: [#201 검토](2026-10-31-issue-201.md)가 기존 fixture 문제로 분리하고 #227·#233·#235가 알려진 기존 실패로 보고한 `TestOPS05DiagnosticFlushBudgetIntegration`. 원래 검토의 당시 검증 기록은 보존한다.
- 기준: `dev`의 `59baf72`, 브랜치 `fix/ops05-diagnostic-flush-budget-test`.

## 원인과 변경

시험은 저장소 공용 잠금을 쥔 채 진단 이벤트 12건을 대기시키고, 종료 flush가 공통 5초 마감으로 끝나기를 기대했다. [기록 루프](../sdd/observability.md#민감정보와-크기-제한)는 #184(PR #216) 이후 수락된 이벤트를 회차마다 최대 128건까지 묶고 회차마다 공용 잠금을 최대 1초 기다린다. 12건과 기동·종료 기록은 두 회차의 잠금 실패로 약 2초 만에 처리되어 5초 마감이 일어나지 않았다. 진단 구현의 최대 5초 flush·누락 집계 계약은 유지되며 결함은 시험 부하다.

대기 이벤트를 900건으로 늘렸다. 회차당 128건이므로 최소 8회차, 회차당 1초의 잠금 대기가 필요해 5초 안에 끝날 수 없다. 대기열 상한 1024건보다 적게 두어 대기열 초과가 아닌 flush 마감으로 남은 대기열을 끝내게 한다. 시험은 누락 원인별 건수를 따로 대조하지 않는다. 원래 기동 오류·기한 초과의 보존, 5~7초 경과, 누락 집계, 풀 종료와 잠금 해제 뒤 기록기 재개방 검증은 그대로다. 구현·정본·구성은 변경하지 않았으며 DOX pass에서 소유권·경로 변경이 없어 기존 DOX를 유지했다.

## 재현과 검증

- Go 1.27.1과 고정 이미지 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`(PostgreSQL 18.6)의 전용 합성 컨테이너에 정식 7개 마이그레이션(vector(8))을 적용했다. 기존 개발·다른 시험 DB는 사용하지 않았다.
- 수정 전 단일 race 시험에서 `진단 정리의 독립 5초 예산: 2.001207542s` 실패를 재현했다.
- 수정 후 같은 단일 시험을 3회 실행해 flush가 각각 5.0034초·5.0021초·5.0048초에 마감하고 통과했다.
- `TEST_DATABASE_REQUIRED=1 go test -race -p 1 -json ./cmd/server -count=1 -timeout=20m`에서 697건이 실패 없이 통과했고 환경 인수 21건은 기존과 같이 건너뛰었다. 건너뛴 인수를 통과로 보고하지 않는다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check`와 변경 문서의 로컬 링크·앵커를 확인했다.
- 시험 종료 후 시험 DB 외 임시 DB와 idle transaction 잔류가 없음을 확인하고 소유 컨테이너만 정리했다. 기존 개발·다른 시험 자원과 개인 IDE 파일, 루트 AGENTS.md 편집은 유지했다.
