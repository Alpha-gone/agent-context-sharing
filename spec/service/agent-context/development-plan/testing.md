## 목표와 구현 범위

새 구현의 단위·DB 연산·격리·장애·브라우저·프로토콜·실제 호스트 인수를 처음부터 구성한다. 기존 테스트나 과거 합격 기록은 실행·지원·효과의 근거로 승계하지 않는다.

- 설계 입력: [시험 계층](../sdd/testing.md#테스트-계층), [DB 시험](../sdd/testing.md#데이터베이스가-필요한-테스트), [시험 격리](../sdd/testing.md#테스트-사이의-격리), [격리 위반](../sdd/testing.md#격리-위반-테스트), [첫 Codex 인수](../sdd/testing.md#첫-codex-cli-상호운용-시험), [이행·복귀](../sdd/testing.md#인수마이그레이션복귀).
- 예정 구현 영역: 각 패키지 시험, 도구 계약·스냅샷·격리 fixture, CI의 필수 DB 실행과 인수 기록.
- 다른 분야와의 경계: 기능별 완료 기준은 해당 계획, 정량 효과·통계는 평가 계획이 소유한다. 이 계획은 실제 시험 실행·증거·미실행 판정을 담당한다.

테스트 코드 작성·보강·실행은 [전체 계획의 시험 시점](../DEVELOPMENT_PLAN.md#테스트-작성과-실행-시점)을 따른다. 아래 작업은 해당 작업의 모듈 시험 또는 관련 분야의 통합 테스트로 수행한다. TEST-09는 전체 저장소·DB 반복 검증을 포함한 최종 통합 인수이며, 각 코드 편집이나 개발 단계마다 반복하는 검사가 아니다.
