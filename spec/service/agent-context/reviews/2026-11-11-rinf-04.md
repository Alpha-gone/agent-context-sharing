# RINF-04 판정·반영 검증

## 범위

공통 판정 경계와 결정적 대역, OpenAI Responses API의 `gpt-6-luna` 구조화 출력 어댑터를 추가했다. 제공자에는 사건 발췌와 고정 지시를 분리해 전달하고 응답 전체 위반과 개별 판정 위반을 구분한다. 별칭·유형·방향·중복·누락과 실제 발췌의 인용을 서버가 재검증한다. 자격 증명·응답 본문은 오류에 넣지 않는다.

결과 저장은 그래프 잠금 뒤 작업 세대·리스·위임 계정·대상 및 후보 판·활성·관계 정체성·시간·순환·부분집합 신호를 재확인한다. `shadow`, `propose`, 지문이 일치하는 `apply`를 구분하며 인과 관계는 자동 확정하지 않는다. 관계 생성·전이와 판정 기록·추론 관리 기록·작업 삭제·내용 판 갱신을 한 트랜잭션에서 처리한다. 이전 세대는 판정 사유를 `stale`로 남기고 그래프와 새 작업을 변경하지 않는다.

## 검증

- 필수 합성 DB의 RINF-04 선별 시험 통과: 모드·프로필 강등, 대역 회차, 근거 거부, 부분집합 방향, 인과 제안, 확정·폐기 정체성, 사건 갱신·폐기, 위임 권한 회수, 중복 작업자, 감사 실패 롤백을 확인했다. 같은 표본의 race 검사도 통과했다.
- Go 1.27.3의 `go build ./...`, `go vet ./...`, `gofmt -l .`, 추론 패키지 전체 race 검사가 통과했다.
- 정식 스키마를 적용한 새 합성 DB에서 `TEST_DATABASE_REQUIRED=1 go test -v -count=1 -p 1 -timeout=35m ./internal/model ./internal/relinfer ./internal/store`가 통과했다. 각각 0.399초, 0.396초, 389.719초였다.
- 첫 전체 시험에서는 기존 `TestEventRelationProposalRules`가 관계 후보 0개로 실패했다. 해당 경로의 저장 후 제안 실행 상한은 1초이며 실패 사례는 1.11초였다. 같은 DB의 단독 재실행은 0.30초에 통과했고, 최종 새 DB 전체 시험에서는 0.18초에 통과했다. 일시적 지연 가능성이 있으나 첫 실패의 정확한 원인은 확정하지 않았다.
- `stale` 등 거부 판정을 유효한 이전 판정으로 오인해 같은 쌍의 재검색을 막지 않도록 후보 제외 조건을 보강하고 실제 DB 회귀를 확인했다.

실제 제공자 호출과 운영 DB 변경은 수행하지 않았다. OpenAI 어댑터는 현재 기본 생성 매개변수만 지원하며 별도 매개변수가 지문에 들어오면 호출 전에 거부한다. 서버·분리 실행기의 작업자 조립, 진단과 분야 통합 인수는 RINF-05의 범위다.
