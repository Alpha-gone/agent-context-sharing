# #196 HippoRAG 하위 홉의 독립 과업과 manifest 매핑

- 대상: [#196](https://github.com/Alpha-gone/agent-context-sharing/issues/196).
- 기준: `dev`의 `117d216`, 브랜치 `fix/196-hipporag-independent-units`.

## 변경과 결정

원 질문과 자립형 하위 홉에 같은 `independent_unit`을 지정한다. 입력은 데이터셋명과 원 질문 ID를 각각 `%q`로 인용한 문자열이며 전체 SHA-256을 `hippo_` 뒤에 붙인다. 다른 데이터셋의 같은 ID는 구분하고 입력 개수·질문 본문·홉 개수·파일 경로에 따라 단위를 바꾸지 않는다. 이 비식별 코드는 익명성이나 외부 효과를 보증하지 않는다.

원 질문 ID는 보존하고 하위 홉 ID는 원래 분해 순서의 `.hopN`을 붙인다. 참조 자리 표시가 있는 비자립형 홉은 계속 제외한다. 생성 ID의 manifest 형식·128자 제한과 고유성을 변환 단계에서 검사하며 원 질문 ID와 다른 질문의 홉 ID 사이의 충돌도 거부한다. 잘못된 ID를 자동으로 재명명하거나 서로 다른 과업을 합치지 않는다.

[평가 정본](../sdd/evaluation.md#반복통계와-실행-순서)·[시험 설계](../sdd/testing.md#테스트-계층)·[SDK 근거](../reference.md#2026-10-31-196-hipporag-독립-과업-코드)를 정합화했다. 이전 변환 데이터는 재변환하고 질의 checksum·manifest 문항/독립 단위를 새 출력에 맞춰야 한다. 과거 측정 결과를 덮어쓰거나 재집계 효과를 이미 검증한 것으로 보고하지 않는다.

DOX pass에서 소유권·경로·구성 경계가 바뀌지 않아 기존 DOX를 유지했다. SRS의 독립 단위 집계 요구를 구현하는 변경이므로 SRS·추적표·개발 계획의 요구사항/작업 상태는 유지한다. 스키마·배포 설정·환경 예시도 변경하지 않는다.

## 재현과 검증

- 기준 코드에서 기존 `q1#hop1`과 회귀 시험의 기대 ID 불일치, 원 질문의 독립 단위 누락, 잘못된 문자·홉의 길이 초과·질문/홉 충돌·중복 ID의 잘못된 허용을 재현했다.
- 합성 원 질문 50개에서 자립형 홉 둘씩을 만들어 총 150개 질의를 사용한다. 각 문항의 공통 단위·다른 데이터셋의 동일 ID 분리·입력 개수 변경 시 결정성을 검사하고, 실제 파일 checksum을 묶은 manifest 입력 검증과 준비 보고의 150문항/50독립 단위를 대조한다. 같은 출력의 10회 대응 반복에서 통계 표본 50개·자유도 49를 검사한다.
- 예비 전체 시험은 882건 통과·실패 2건(하위 시험 하나와 그 부모)·건너뜀 0건이다. `TestEvaluationCommandCleanupFailsExitIntegration/normal/1`의 적응형 정상 실행이 회차 9에서 `pending=1`, 재시도 대기·리스 1, 임베딩 누락 1, 실패 사유 없음으로 멈췄다. 해당 시험은 직접 만든 원천/파생 입력을 사용하며 HippoRAG 변환기를 호출하지 않는다. 이 실패를 이번 변경의 회귀 또는 기존 결함으로 확정하지 않는다. 초기 기록은 `/tmp/acs196-modules.json`이다.
- 기준 `117d216`의 격리 사본에서 해당 시험을 DB 필수·race로 10회 반복해 20건(부모 포함)이 실패·건너뜀 없이 통과했다. `/tmp/acs196-baseline-cleanup.json`에 기록했으며, 초기 색인 대기 실패의 원인을 확정한 증거는 아니다.
- 코드 변경 없이 전체 모듈을 다시 실행해 884건이 실패·건너뜀 없이 통과했다. 앞선 정상 종료 시험도 통과했다. Go 1.27.1과 고정 PostgreSQL/AGE 이미지 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`의 전용 합성 컨테이너에 기본 vector 768·비교 vector 128·halfvec 768 DB를 만들고 각각 정식 7개 마이그레이션을 적용했다. `TEST_DATABASE_URL`, `TEST_EMBEDDING_SMALL_URL`, `TEST_EMBEDDING_HALF_URL`, `TEST_DATABASE_REQUIRED=1`을 지정한 `go test -race -p 1 -json ./cmd/eval -count=1 -timeout=40m` 결과는 `/tmp/acs196-modules-final.json`이다. 재실행 통과가 최초 색인 대기 실패의 원인 해소를 뜻하지 않는다.
- `go build ./...`, `go vet ./...`, `gofmt -l .` 통과. 변경 문서의 로컬 링크·앵커와 Markdown 구조·용어를 검사하고 DOX 경로·색인을 확인했다.
- 시험 종료 후 소유한 세 DB·postgres 외 임시 DB가 없고 idle transaction이 0임을 확인했다. 소유 라벨/ID를 대조한 전용 컨테이너와 연결 익명 볼륨을 정리하고 잔류가 없음을 확인했다.
- 독립 읽기 전용 검토에서 추가 발견 사항이 없었다. 검토자는 테스트·DB를 별도로 실행하지 않았다.

공개 HippoRAG 실물 데이터 재변환·검색 효과 측정·운영 환경 인수는 이번 합성 회귀의 범위가 아니다.
