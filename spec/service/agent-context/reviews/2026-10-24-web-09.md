# WEB-09 웹 화면 전체 기능·표현·상태 분야 인수

- 기준: 2026-10-24, `feat/web-foundation`의 `3df0fed` 이후 작업 트리.
- 대상: [WEB-09](../development-plan/web.md#web-09), [웹 설계](../sdd/web.md), [테스트 계층](../sdd/testing.md#테스트-계층), [요구사항](../SRS.md#화면과-시각화-요구사항).
- 판정: 완료. 웹 9개 작업을 모두 완료해 전체 **93/124개 완료·31개 미착수**다. 실행 조합은 Chrome 155.0.8059.86 headless(macOS 26.6.2)이며 Safari 26.6.2와 실제 스크린리더 음성은 미실행으로 [TEST-06](../development-plan/testing.md#test-06)에서 관찰한다.

## 변경

여섯 업무 화면·로그인/가입·연결 관리의 HTTP 상태를 한 행렬로 검사하는 시험을 추가했다. 실제 브라우저 인수는 Go 시험이 격리 DB·서명 세션·TLS 서버와 같은 사이트의 다른 출처 서버를 준비하고, `browser_acceptance_test.cjs`가 외부 의존성 없이 CDP로 headless Chrome을 조작한다. 브라우저 조작 뒤 노드·그래프 상태, 팀 구성원, 에이전트 등록, 감사 기록을 저장소에서 다시 대조한다.

시험 인증서는 전역 오류 무시 대신 서버 인증서의 SPKI 지문만 신뢰한다. 인증서 오류 상태의 응답은 Chrome이 캐시하지 않아 첫 실행에서 조건부 재검증이 일어나지 않았다. 또 CDP의 `responseReceived`는 재검증된 응답을 캐시 본문의 200으로 보고하므로, 조건부 요청 헤더와 `responseReceivedExtraInfo`의 원시 상태 304로 판정한다.

390px 화면 검토에서 열이 많은 감사·등급 표가 페이지는 넘치지 않지만 셀 내용을 글자 단위로 끊는 것을 발견했다. 감사·등급·운영자 대기 표를 표 제목으로 이름을 연결한 `role=region`·`tabindex=0` 스크롤 영역으로 감싸고 최소 폭을 두어, 단어를 보존하면서 표 영역 안에서 키보드·포인터로 가로 스크롤하게 했다. 웹 DOX·웹 설계·테스트 설계에 실행기와 표 표현을 반영했다.

## 실행 증거

- **HTTP 화면 행렬 39건**: 목록·상세·권한·삭제·감사·운영자·로그인·가입·연결의 정상/빈 목록, 입력 실패 400, 등급 없음 404·등급 부족 403, 자격 불일치 401, 내부 장애 500, 성공 303 위치와 세션 없는 접근의 로그인 이동을 확인했다. 모든 응답의 `no-store`, 내부 원문 비노출, 오류 화면의 한국어 문서를 함께 대조했다.
- **Chrome 실제 브라우저 15개 시나리오**가 모두 통과했다.
  - 로그인 양식 제출로 받은 세션 쿠키가 HttpOnly·Secure·SameSite=Lax이며 스크립트에 보이지 않았다.
  - 이름 필터 3건이 2쪽으로 나뉘고 「더 보기」가 필터와 커서를 유지했다. 열람자 등급 체크박스 필터는 1건이며 선택이 유지됐고, 목록은 시각화 자산을 읽지 않았다.
  - 시각화 노드를 실제 마우스로 누르면 국소 보기가 되고 빈 영역은 전체 보기로 돌아갔다. 목록 버튼의 Enter 선택·Space 해제·Esc 복귀에서 포커스가 유지됐다.
  - 방향키로 홉을 0으로 줄이면 `aria-valuetext`가 0홉이 되고 숨겨진 근거가 텍스트에 남았다. 범위 밖 노드를 재선택할 수 있었고, 상세 이동 링크는 제목으로 포커스를 옮겼다. 전체 보기 버튼은 홉 값을 유지했다.
  - Tab 이동 포커스는 `:focus-visible`이며 2px 실선 윤곽선을 그렸다.
  - 시각화 자산은 `If-None-Match`로 재검증되어 원시 상태 304를 받았다.
  - 팀을 만들고 구성원을 추가했다.
  - 사건 노드를 삭제하자 상세에서 빠졌고, 복구 대상 보기에서 복구됐다. 그래프는 이름 확인으로 삭제한 뒤 목록 진입으로 복구했다.
  - 감사 「더 보기」와 대상 필터가 동작했고, 새 필터는 커서를 싣지 않았다.
  - 본인 에이전트 등록 폐기가 동작했다.
  - 같은 사이트의 다른 출처 자동 제출은 403으로 거부됐다.
  - 390px 화면의 일곱 화면이 모두 가로로 넘치지 않았다. 감사·등급 표는 포커스 가능한 스크롤 영역이고 방향키로 가로 스크롤됐으며, 상세 세 영역은 한 열로 쌓였다.
  - 로그아웃 뒤 업무 화면은 로그인으로 이동했다.
- 모든 방문 화면에서 문서 언어 `ko`·한국어 제목과 비밀번호·세션 값의 HTML 비노출을 확인했다. 브라우저 뒤 저장소 대조에서 사건 노드와 삭제 그래프는 활성, 교차 출처 대상은 미삭제, 팀 구성원 1명, 등록 폐기, 사건의 삭제·복구 감사 2건과 행위자를 확인했다.
- 데스크톱 상세와 일곱 화면의 390px 캡처를 직접 검토했다. 그래프 목록의 등급 값(`owner`)은 좁은 열에서 줄바꿈되지만 넘침은 없어 현재 표현을 유지했다.
- **웹 분야 통합**: `./internal/web ./cmd/server`를 `-race -count=1 -p 1`·필수 DB·필수 브라우저로 실행했다. 웹 811건·서버 596건이 실패 없이 통과했다. 서버의 `TestOPS07PhysicalRecovery`·`TestOPS08Transition`은 각각 `test-pitr.sh`·`test-transition.sh` 전용이라 건너뛰었으며 웹 범위의 근거로 쓰지 않는다.
- `check-go.sh`의 의존성 확인·빌드·vet·gofmt가 통과했다. 웹 DOX·웹/테스트 SDD·개발 계획·설계 진입점·README/서비스 색인·요청 기록·근거를 정합화했다. 요구사항·용어·SQL 스키마·환경 설정·저장소 계약은 바뀌지 않아 해당 정본은 유지했다.

```sh
TEST_DATABASE_URL='<WEB-09 전용 합성 URL>' TEST_DATABASE_REQUIRED=1 WEB_BROWSER_REQUIRED=1 WEB_BROWSER_EVIDENCE='<캡처 경로>' \
  go test -race -json -count=1 -p 1 -timeout=600s ./internal/web ./cmd/server
GO_BINARY="$(command -v go)" sh check-go.sh
```

별도 `acs-web09-20261024` 컨테이너·`agent-context.task=web09` 라벨·tmpfs·임시 IPv4 loopback 포트와 합성 자격을 사용했다. Chrome은 시험별 임시 프로필로 실행하고 종료했다. 종료 후 자식 DB·시험 연결 0, 이 작업의 컨테이너 잔류 없음, headless Chrome 잔류 없음과 기존 개발 컨테이너 보존을 확인했다. 원시 근거는 세션 임시 폴더의 `acs-web09-field.json`·`acs-web09-static.log`와 `web09-evidence/` 캡처다.

첫 브라우저 실행들은 실행기 문제로 실패했다. ETag 헤더 이름의 대소문자, 인증서 오류 상태의 캐시 미보존과 CDP 보고 상태 차이, 삭제된 그래프 화면의 같은 이름 링크 두 개 때문이었다. 헤더를 대소문자 구분 없이 읽고, SPKI 신뢰와 원시 상태로 판정하고, 보기 전환 내비게이션 선택자를 쓰도록 고친 뒤 전체 시나리오가 통과했다. 작은 화면 표 보완 뒤에는 브라우저 인수와 분야 통합 전체를 다시 실행했으며 반복 실행을 중복 합산하지 않았다.

## 남은 범위

Safari 26.6.2의 수동 확인, VoiceOver 등 실제 스크린리더의 상태 안내·제목 이동·본문/근거 읽기, Shift+Tab 역순 이동 전체 점검은 미실행이며 TEST-06에서 수행한다. Chrome headless 결과가 다른 브라우저나 보조 기술 지원을 대신하지 않는다. 실제 호스트·운영 배포는 미실행이며 커밋·푸시는 수행하지 않았다.
