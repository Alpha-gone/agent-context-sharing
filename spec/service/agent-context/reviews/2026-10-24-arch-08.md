## 새 서버 교체 인수

[신규 시험](../../../../cmd/server/architecture_acceptance_test.go)은 정식 마이그레이션을 적용한 같은 DB에 `assembleApplication`으로 두 독립 저장소·인증·웹·MCP·진단·색인 객체를 조립하고 실제 TLS 요청을 보낸다. 외부 임베딩 제공자는 로컬 TLS 대역이다. 계정·동의 후 인가 코드 준비만 실제 인증 서비스 API로 수행하며 브라우저 최초 동의와 호스트 자격 저장은 실행하지 않는다.

- 첫 `tools/call`부터 같은 계정/client의 등록과 그래프 생성 결과를 다른 인스턴스에서 재사용한다. 발견·목록 호출과 MCP 프로토콜 세션 없이 요청별 메타데이터로 처리한다.
- 등급 없는 계정의 `graph_get`은 존재를 숨기는 `not_found`다. 한 저장소에서 등급 부여·회수 뒤 다른 조립 서버가 즉시 허용·거부한다.
- 실제 원천을 생성하고 다른 서버에서 조회한다. 모든 서버를 닫고 embedded/external 구성을 맞바꾼 새 객체로 교체한 뒤 이전 등록·그래프·노드의 최초 결과를 재생한다. 감사·색인 큐의 행 수가 늘지 않고 pending 작업 1개가 보존된다. 이 시나리오에서는 소비 루프를 시작하지 않는다.
- 인가 코드는 서버 1에서 교환하고 갱신 자격은 서버 2에서 회전한다. 전체 서버 교체 뒤에도 이전 갱신 자격을 새 서버에서 회전할 수 있다. 서명 키 회전 뒤 새 키와 기존 키 모두 다른 서버에서 검증된다.
- 웹 세션은 양쪽에서 유효하고 전체 교체 뒤에도 유지된다. 웹 폐기는 정본의 10초 재조회 주기를 지난 뒤 양쪽에서 차단된다. Bearer 계열 폐기는 별도의 대기 없이 양쪽에서 즉시 401이며 등록 폐기는 다른 인스턴스의 쓰기·동일 키 재등록을 차단한다.
- 같은 진단 슬롯은 이전 파일에 이어 쓰되 재시작 전후 boot가 둘로 구분된다. 여섯 종류의 파일에서 이벤트 검증과 instance 일치를 확인하고 모든 발급 access/refresh 자격·웹 세션·제공자 키·업무 원문의 비노출을 검사한다. 이전 조립의 풀 종료도 직접 대조한다.

초기 시험의 부재 오류 기대값, 키 부재 1초·웹 폐기 10초 지역 캐시 주기와 교체 서버의 최상위 시험 정리 수명을 바로잡은 뒤 전체 범위를 재실행했다. 제품 코드·캐시 정책·공개 계약·스키마·설정 기본값은 변경하지 않았다.
