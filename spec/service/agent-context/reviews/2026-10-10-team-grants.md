# 팀 대상 등급 부여와 구성원 표시 검증

## 범위와 처리 결과

2026-10-10에 [GitHub #99](https://github.com/Alpha-gone/agent-context-sharing/issues/99)의 웹 권한 화면과 팀 구성원 표시를 처리했다. 기준 커밋은 원격 `dev`와 같은 `0b3bc2c`이며 기존 사용자 IDE 설정 staging은 보존했다.

기존 화면은 `grant_account`만 제공하고 저장소 호출의 대상 종류도 계정으로 고정했다. 팀 상속 계산과 구성원 추가는 존재했으나 팀 부여 행을 만들 웹 경로가 없었고, 관리 팀 목록은 구성원을 조회하지 않았다.

- 소유자 화면에 활성 팀 이름·식별자 선택과 등급 부여 양식을 추가했다. 같은 이름의 팀을 식별자로 구분하고 다른 계정이 관리하는 팀도 선택할 수 있다. 기존 등급 표와 회수 경로는 팀 부여와 구성원 상속 행을 표시·처리한다.
- 팀 부여는 기존 `GrantGraph` 트랜잭션을 사용한다. 그래프 잠금 뒤 소유자를 재확인하고 없는 팀·삭제된 팀은 `ErrNotFound`로 거부하며, 부여·유예 판정·웹 감사 기록은 같은 트랜잭션에 유지한다. 잘못된 입력은 `400`, 없는 대상은 `404`, 마지막 소유자 충돌은 `409`, 내부 장애는 원문을 숨긴 `500`으로 응답한다.
- 관리 팀 조회는 관리자 범위 안의 현재 구성원 로그인 아이디를 같은 SQL 질의에서 정렬해 읽는다. 삭제된 팀은 보존된 구성원을 표시하고 빈 팀은 안내를 표시한다. 부여 대상 목록에는 구성원 정보를 포함하지 않는다.
- SDD의 「웹 화면 계약」·화면 배치·테스트 전략을 갱신했다. 요구사항은 기존 `FR-AGENT_CONTEXT-040`·`041`·`043`을 따른다. 추가 HTML은 연결된 레이블과 필수 입력, 명시적 POST 경로를 사용한다.

## 검증

IntelliJ IDEA에 등록된 Go 1.27.1 `darwin/arm64` SDK와 시험용 Go 캐시를 사용했다.

- 정식 `001_init` 마이그레이션을 적용한 별도 `issue99_test_20261010` DB에서 `TEST_DATABASE_REQUIRED=1 go test -count=1 -v ./internal/web ./cmd/server ./internal/store`: 종료 코드 0.
- 웹 회귀: 소유자 부여, 비소유자·다른 출처 거부, 잘못된 팀 식별자·등급 거부, 없는 팀·삭제된 팀·내부 장애 분류, 팀 부여·회수 양식과 관리자 구성원·빈 팀·삭제된 팀 표시, HTML 이스케이프, 소유자에게만 활성 팀 조회를 확인했다.
- DB 회귀: 팀 부여 전후 구성원의 그래프 목록·유효 등급·상속 행, 회수·구성원 제거·팀 삭제 후 접근 소멸과 재추가·복구 후 접근 회복, 부여·회수 감사 기록을 확인했다. 없는 팀·삭제된 팀 거부가 등급·감사·유예 상태를 바꾸지 않는지도 확인했다.
- 동시성 회귀: 그래프 잠금 대기 중 직접 등급 하향·팀 구성원 제거·팀 삭제로 소유자 자격을 잃은 행위자의 팀 부여가 등급과 감사 기록 없이 거부됐다.
- 기존 빈 팀·유예 판정 회귀 `TestGraceCancelRequiresAccessibleAccountIntegration`도 통과했다.
- 서버·클라이언트 각각 `go build ./...`와 `go vet ./...`: 통과. 루트 `gofmt -l .`과 `git diff --check`: 출력 없음.

최초 실행은 기본 Go 캐시 쓰기와 로컬 시험 서버 포트의 샌드박스 제약으로 중단됐다. 시험용 캐시와 승인된 로컬 실행으로 검증했다. 시험 DB의 첫 마이그레이션은 잘못된 색인 대상 값 `all`을 거부했으며, DB를 정리하고 계약 값 `all_layers`로 수정해 새 시험 DB에서 다시 실행했다. 제품 구성이나 기존 DB를 바꾸어 우회하지 않았다.

시험용 DB는 종료 후 정리했다. 기존 개발 데이터·볼륨·운영 DB·자격 증명은 변경하지 않았다.

## DOX pass와 제한

웹·서비스 소유 AGENTS와 영향받은 부모 Child DOX Index를 갱신했다. SRS·용어집·공개 MCP 계약·클라이언트·마이그레이션·배포 구성은 요구사항·용어·채널·스키마가 바뀌지 않아 유지했다. 문서의 한국어 표현·맞춤법·Markdown 구조와 참조 경로를 검토했다.

#99 범위의 확인된 미해결 코드 결함은 없다. 브라우저 수동 조작과 운영 DB 확인·배포는 수행하지 않았다. 커밋·푸시·PR 생성·GitHub 이슈 종료는 수행하지 않았으며 변경은 로컬 작업 트리에 있다.
