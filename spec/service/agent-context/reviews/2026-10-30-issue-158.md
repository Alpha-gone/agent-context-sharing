# #158 관계 질의와 사건 후보 적재 범위

- 기준: `dev`의 `04a7ed9`, 브랜치 `perf/158-relation-query-scope`.
- 대상: [이슈 #158](https://github.com/Alpha-gone/agent-context-sharing/issues/158).

## 구현 계획

- [x] 관계 조회·갱신·정리의 실제 질의를 대량 합성 DB에서 관찰하고 label·그래프별 스캔 범위 회귀를 작성한다.
- [x] 네 사건 관계 label에 그래프/관계 ID·양 끝 정체성·역방향 끝점 인덱스를 추가하는 새 마이그레이션을 작성한다. 기존 적용 SQL은 보존한다.
- [x] 알려진 유형은 label을 지정하고 유형 없는 조회는 네 label의 정렬 페이지를 합친다. 순환 검사는 한 번 적재한 인접 맵을 순회한다.
- [x] 사건 시간 검증의 상대 정점 조회를 묶고, 제안 입력은 대상 제외·최신 식별자 순 1,000건으로 제한한 뒤 본문·참조를 조립한다. 신호별 제안은 그래프 잠금을 한 번 잡는다.
- [x] 정점 잠금·활성 존재 확인의 표현식/콜레이션을 인덱스와 맞춘다. 새 사건 후보 인덱스와 상한·선택 정책을 데이터·수명주기 SDD에 반영한다.
- [x] 실제 EXPLAIN ANALYZE/BUFFERS·기존 관계·마이그레이션 및 관련 전체 race 인수, Go 정적 검증, 독립 검토를 마친다.

## 판단

- 기존 확정·폐기·멱등·끝점 재검사·그래프 잠금과 순환 금지 계약을 유지한다. 후보 적재 상한은 제안 생성 수 상한과 구분하며 상한 밖 사건은 이번 제안 입력에서 제외한다. 후보 품질 최적값이나 모든 사건 비교 완료로 표현하지 않는다.
- 계획은 저장소 검토 기록 위치에 보관하며 사용자 지침에 따라 별도 장문 승인 없이 같은 작업에서 실행한다.

## 재현·구현 근거

- [관계 범위 회귀](../../../../internal/store/relation_scope_integration_test.go)는 대상 그래프와 별개인 그래프에 네 label 각각 1,000개·10,000개 간선을 넣고 실제 관계 식별자 조회·정체성·목록·갱신·후보 정리·확정 경로 질의를 기록한다. 원본의 1,000개 표본에서는 다른 그래프의 간선까지 1,001개씩 읽어 실패했다.
- 수정 후 기본 planner 설정의 `EXPLAIN (ANALYZE, BUFFERS, TIMING OFF, FORMAT JSON)`에서 각 label의 실제 rows·loops·filter를 대조했다. 대상 행을 복원한 저장점에서 쓰기 계획도 재생하고 전체 트랜잭션을 롤백한다. 다른 그래프 간선이 10배 늘어도 각 계획의 label별 읽기는 0~1행이었으며 시험은 32행 초과를 회귀로 거부한다.
- 사건 입력 시험은 본문·HAS_MEMBER 참조를 가진 사건을 1,000개 넘게 준비한다. 상한 없는 기존 조회를 시험 overlay로 대조했을 때 1,006건을 적재해 실패했다. 수정 후 1,000건·대상 제외·식별자 내림차순과 본문/참조 조립 5개 질의, `context_active_event_proposal_idx` 사용을 확인했다. 대상 제외 필터를 포함한 실제 정점 읽기는 1,001행이었다.
- 같은 시험은 제안 두 개를 만들 때 신호별 그래프 잠금 한 번, 두 확정 관계의 시간 검증이 상대 사건 묶음 조회를 포함한 5개 질의로 끝남을 확인한다. 정점 잠금은 `context_graph_context_lookup_idx`로 1행만 읽는다. 신규 16건의 최종 race 실행은 11.628초에 실패·건너뜀 없이 통과했다.
- [014 마이그레이션](../../../../migrations/014_relation_query_scope.sql)은 기존 적용 SQL과 checksum을 보존하고 14개 인덱스를 추가한다. 정식 CLI 판올림에서 1개 적용, 재실행에서 0개 적용을 확인했다. 빈 DB·vector/halfvec·기존 이력·구성 보충·전환 시험의 적용 수 기대값도 새 파일을 포함하도록 갱신했다.
- 입력 상한·인덱스는 [데이터 SDD](../sdd/data.md#인덱스), 후보 선택·잠금·시간 검증은 [수명주기 SDD](../sdd/context-lifecycle.md#관계-후보-제안과-확정), 실행 계층은 [테스트 SDD](../sdd/testing.md#테스트-계층), 공급자 계약은 [reference.md](../reference.md#2026-10-30-158-관계-질의-범위)에 유지한다. DOX 소유권·구조와 공개 구성은 바뀌지 않았다.

## 예비 검증의 보완

시험의 원천 구성원 발생 시각은 실제 시간 범위 검증을 받으므로 입력 상한 표본의 구성원을 시간 제한이 없는 파생으로 정합화했다. 연결 초기화 질의를 측정에서 분리했으며, 풀 교체 후 정리 누락으로 남은 두 시험 DB는 교체 풀의 cleanup을 등록한 뒤 해당 생성 이름만 확인해 제거했다.

최초 패키지 병렬 실행에서는 색인 공개 시험의 사건 저장이 저장소 시험의 `data03_fail_index` 장애 주입 트리거와 같은 시각에 실패했다. PostgreSQL 오류 로그와 장애 주입 코드를 대조했으며 최종 패키지 실행을 `-p 1`로 직렬화했다. 마이그레이션 전환·보충의 적용 개수 누락을 보완했고 기존 합성 전환/복귀의 고정 번호 14도 실제 최신 적용 번호 다음을 사용하도록 바꿨다. 예비 실패를 최종 통과로 집계하지 않는다.

## 최종 인수

Go 1.27.1, 고정 PostgreSQL/AGE/pgvector 전용 컨테이너, 정식 마이그레이션과 `TEST_DATABASE_REQUIRED=1`·`TEST_DATABASE_URL`을 사용했다.

```sh
go test -race -count=1 -json -run '^Test(RelationProposalInputBoundIntegration|RelationQueryScopeIntegration)$' ./internal/store
go test -race -count=1 -p 1 -json -timeout=15m ./internal/store ./internal/migrate ./internal/search ./internal/index ./cmd/server
go build ./...
go vet ./...
gofmt -l .
```

필터 없는 순차 패키지 인수에서 다음 결과를 확인했다. 건수에는 하위 사례를 포함한다.

- `internal/store`: 1,727건, 최상위 378건, 491.775초. 실패·건너뜀 없음.
- `internal/migrate`: 81건, 최상위 28건, 7.687초. 실패·건너뜀 없음.
- `internal/search`: 342건, 최상위 69건, 7.169초. 실패·건너뜀 없음.
- `internal/index`: 119건, 최상위 28건, 4.766초. 실패·건너뜀 없음.
- `cmd/server`: 688건, 통과 최상위 107건, 117.595초. 실패 없음. 별도 Codex CLI 시나리오와 물리 복구·이전 인수 21건은 환경 미설정으로 건너뛰었다.

build·vet·gofmt·문서 링크/앵커 234개와 diff 검사, 독립 읽기 전용 코드 검토도 통과했다. 실제 운영 DB에는 적용하지 않았으며 기존 배포는 정식 절차로 014 인덱스 마이그레이션을 적용해야 한다.

최종 시험별 DB 잔류 없음·idle transaction 0개와 생성 컨테이너 ID를 확인한 뒤 이번 시험의 컨테이너·익명 볼륨만 정리했다. 기존 세 컨테이너와 개인 IDE 파일은 보존했다.
