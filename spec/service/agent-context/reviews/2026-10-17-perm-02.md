## 발견 사항과 구현

| ID | 영향도 | 발견 사항 | 처리·검증 |
|---|---|---|---|
| PERM02-R1 | 낮음 | 권한 검사와 유효 등급 조회가 UUIDv7 식별자를 확인하지 않아 잘못된 입력으로 저장소를 호출할 수 있었다. | `perm.Require`와 공통 `effectiveGrade`에서 저장 조회 전에 식별자를 거부한다. DB 핸들이 없는 표본과 호출 시 실패하는 주입 대역으로 조회 전 거부를 확인했다. |
| PERM02-R2 | 낮음 | 주입 저장소가 부재가 아닌 잘못된 등급을 반환하면 `rank=0`으로 처리하여 정상적인 등급 부족 오류로 바뀌었다. | 반환 등급의 유효성을 검사하고 잘못된 상태는 일반 오류로 보존한다. 빈 값·목록 밖 등급이 성공·부재·등급 부족으로 바뀌지 않는지 검증했다. |

- 직접 계정 부여와 활성 팀 구성원 상속을 `UNION ALL`·최고 등급 집계의 한 SQL로 읽는 기존 구현을 대조하고 새 시험으로 검증했다. 이를 과거 완료 근거로 승계하지 않았다. 16개 조합에서 실제 DB를 읽는 `QueryRow` 호출이 한 번임을 확인했다.
- `perm`은 `GradeStore` 인터페이스와 `model`만 사용한다. 에이전트 식별자·토큰 scope를 입력이나 등급 원천으로 추가하지 않았다. 그래프 목록은 현재 유효 등급을 가진 행만 반환하고, 그래프 생성은 기존 등급 검사 없이 생성 계정에 소유자 등급을 부여한다.
- 부여 없는 기존 그래프와 존재하지 않는 그래프는 같은 `NotFoundError`다. 접근 가능한 그래프의 최소 등급 부족만 `DeniedError.Required`를 전달한다. 저장소 장애·취소·마감은 부재나 권한 부족으로 바꾸지 않는다. HTTP/MCP 코드 사상은 기존 진입점과 후속 구현의 책임이다.
- 소프트 삭제 그래프의 등급은 웹 복구를 위해 유지하고 목록에서는 제외하는 기존 계약도 새 모듈 실행에서 재검증했다. 등급과 연산 대상의 활성 상태 판정은 각 소유 계약에 따른다.

## 검증 결과 — 2026-10-17

- Go 1.27.1 darwin/arm64. 저장소의 고정 Dockerfile로 별도 이미지를 빌드하고 소유 라벨·전용 볼륨·임시 IPv4 loopback 포트·합성 자격으로 새 DB를 준비했다. PostgreSQL 18.6 / AGE 1.8.0 / pgvector 0.8.6, Linux aarch64를 확인했다. 기존 개발 DB·볼륨·실제 자격은 사용하지 않았다.
- 새 DB에 정식 `001/009/010/011/012` 다섯 마이그레이션을 적용했다. 구성은 `agent_context`·vector/128·`all_layers`, tablespace 지정 없음이다.
- **고유 시험·하위 시험 55건 통과**: perm 21·store 34, 최상위 12·하위 43. `-race -count=1`, `TEST_DATABASE_REQUIRED=1`로 실행했고 실패·건너뜀은 0이다. 기존 `TestPermissionIntegration`과 선택 범위에 포함된 마지막 소유자 회귀도 함께 실행했다.
- 직접 부여 없음/viewer/editor/owner × 활성 팀 등급 없음/viewer/editor/owner 16개 조합과 최소 등급 3종을 대조했다. 여러 팀의 중복·다른 등급 상속, 삭제 팀·빈 팀·다른 계정만 속한 팀을 함께 두어 상대 그래프와 권한이 노출되지 않음을 확인했다. 목록은 유효 등급과 같은 값을 가지며 중복·누락이 없었다.
- 같은 계정·그래프에서 구성원 제거/재등록, 팀 삭제/복구, 팀 등급 하향, 직접 등급 상향/회수와 마지막 팀 부여 회수 뒤 조회·목록이 바로 바뀌었다. 이 표본의 변경은 시험 SQL이며 PERM-03/04 변경 API의 잠금·감사 인수를 대신하지 않는다.
- 기존 그래프 등급이 전혀 없는 새 계정의 빈 목록과 그래프 생성·소유자 등급 부여를 검증했다. 단위 시험에서는 3×3 최소 등급 비교, 컨텍스트·식별자 전달, 저장 오류·취소·마감의 원인 보존과 잘못된 반환 등급 거부를 대조했다.
