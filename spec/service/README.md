# 서비스 명세 색인

## 목적

이 문서는 프로젝트에서 기획하는 서비스의 범위, 상태와 주요 명세 진입점을 제공한다.

## 서비스 목록

| 서비스                 | 역할                                                                                                                                 | 상태                 | 주요 문서                                                |
|------------------------|--------------------------------------------------------------------------------------------------------------------------------------|----------------------|----------------------------------------------------------|
| 에이전트 컨텍스트 관리 | 공유 컨텍스트 그래프와 호스트 내장 MCP의 직접 연결·표준 OAuth를 제공하는 목표 서비스다. | SRS 확정 및 분야별 SDD 작성, 직접 연결·평가·로그·저장 계층화 변경의 구현·실증 대기 | [SRS](agent-context/SRS.md), [SDD 진입점](agent-context/SDD.md), [분야별 설계](agent-context/sdd/AGENTS.md) |

## 서비스 관계

웹 관리·계정 인증·저장·검색·색인은 하나의 서버 서비스가 소유한다. 호스트 내장 MCP 직접 연결의 요구사항과 목표 설계도 같은 서비스의 SRS·SDD에서 추적하며, 아직 제공하지 않는다.

## 공통 미정 사항

직접 연결 목표의 상세 계약·이행·검증은 [서버 SDD 「호스트 직접 연결 전환 설계」](agent-context/sdd/architecture.md#호스트-직접-연결-전환-설계)가 소유한다. [SRS 「토큰 갱신」](agent-context/SRS.md#토큰-갱신)에서 최대 30일·비활동 7일과 정리 정책을 확정했고 [「직접 연결의 구현 기준과 첫 호스트 시험」](agent-context/SRS.md#직접-연결의-구현-기준과-첫-호스트-시험)에서 공식 Go SDK v1.8.0·초기 revision 2026-07-28·Codex CLI 0.160.1 기준을 선정했다. `TBD-AGENT_CONTEXT-063`은 해소되어 SDD에 동기화했고 `064`의 실제 상호운용 검증은 운영 전 수행해야 한다. 현재 직접 연결과 새 토큰 갱신·재시작·쓰기 인수는 미검증이다.

[MCP-01의 최소 SDK 시험과 보완 후 인수](agent-context/reviews/2026-10-18-mcp-01.md#서비스-진입-경계-보완과-최종-인수)에서 루프백 발견·독립 호출·완료 외피·캐시와 이전 수명주기 거부·오류 형식·Base64 이름 처리의 보완 경계를 확인했다. MCP-01은 완료했으나 실제 서버 연결·직접 연결 제공·호스트 지원은 계속 대기 상태다.

[MCP-03](agent-context/reviews/2026-10-18-mcp-03.md)의 14종 도구 스키마·설명·annotations·공통 instructions와 서버 입력 검증을 구현했다. 합성 처리기의 실제 SDK 목록·호출 인수이며 업무 저장·등록·인증·실제 호스트 연결 완료를 뜻하지 않는다.

[AUTH-01](agent-context/reviews/2026-10-18-auth-01.md)에서 잘못된 UTF-8 가입 비밀번호를 차단하고 계정 입력·현재 저장 형식·레거시 재해시의 모듈 시험을 통과했다. OAuth·Bearer와 실제 MCP 인증 연결은 후속 범위다.

[AUTH-02](agent-context/reviews/2026-10-18-auth-02.md)에서 JWKS·캐시의 ES256 공개 키 검증과 발급 키 쌍 검증을 보완했다. 시험별 DB의 두 인스턴스 초기화·회전·과거 키 보존을 인수했으며 OAuth·Bearer·실제 MCP 인증 연결은 계속 후속 범위다.

[AUTH-03](agent-context/reviews/2026-10-18-auth-03.md)에서 동시 가입·조건부 재해시, 같은 비용의 더미/중복 처리와 자격 불일치·저장 장애·취소를 인수했다. 웹의 인증 장애는 내부 원문 없는 500으로 구분하며 OAuth는 후속 인수다.

[OPS-03](agent-context/reviews/2026-10-19-ops-03.md)에서 TLS 판정을 라우팅 앞으로 옮기고 실제 상대와 전달 헤더의 형식을 보완했다. 직접 TLS·신뢰/비신뢰 프록시의 루프백 교환과 Secure 쿠키를 검증했으며 실제 Tunnel·운영 배포·전 구간 TLS 인수는 별도다.

Air Context와 관련 연구에서 채택한 검색 단위·외부 원본 재현성·임베딩 용도별 비교·에이전트 업무 비용 평가(`FR-AGENT_CONTEXT-160`~`163`)는 SRS에 확정하고 [평가 SDD](agent-context/sdd/evaluation.md#초기-공개-평가-실행-설계)에 반영했다. 요구사항 자체의 미정 사항과 구분하며 [SDD 추적표](agent-context/sdd/traceability.md#요구사항-추적표)에서 추적한다. 데이터 준비·평가 실행·실제 결과는 대기 중이며, 서버 외부 원본 수집·AST 분할·이진 양자화와 관찰 마스킹의 운영 채택을 뜻하지 않는다.

시험 분석용 종류별 파일 저장·흐름 추적·파일 보호(`FR-AGENT_CONTEXT-173`~`175`)는 [SRS 「종류별 진단 로그」](agent-context/SRS.md#종류별-진단-로그)에서 확정했고 [관측성 SDD](agent-context/sdd/observability.md#종류별-진단-로그)가 파일 분류·상관 ID·회전·보존·상한·실패 처리와 검증 절차를 구체화했다. 실제 파일 저장·재시작·다중 인스턴스 검증과 구현은 대기 중이다.

요구사항과 상세 설계가 모두 정한 뒤에도 남아 있는 항목이다.

요구사항 수준은 `SRS.md`의 「미정 사항」이, 설계 선택 수준은 [`sdd/traceability.md`](agent-context/sdd/traceability.md#설계-미정-사항)가 소유한다.

- 인증 고도화. 비밀번호 재설정, 실패 잠금, 다중 요소와 외부 IdP (`TBD-AGENT_CONTEXT-048`)
- 계정 소멸 경로. 탈퇴와 그에 따른 등급 회수 (`TBD-AGENT_CONTEXT-049`)
- 운영자 역할 분리. 검증 단계에서는 인증된 모든 계정이 운영자 자격을 갖는다 (`TBD-AGENT_CONTEXT-052`)
- Client ID Metadata Documents 지원 여부. 사전 등록을 확정했고 명세는 이 방식을 SHOULD로 권고한다 (`TBD-AGENT_CONTEXT-060`)
- 한국어 형태소 분석. 키워드 채널이 `simple` 구성을 쓰며 채널 기여를 측정한 뒤 판단한다 (`TBD-AGENT_CONTEXT-061`)
- 응답 직렬화 형식 (MCP `tools` 응답 규약을 따르며 세부는 구현에서 정한다)
- Row Level Security 채택 (읽기 경로 검증 후 판단)
- 계정 플랜의 이름과 구체 값 (명세는 항목과 기본값만 정하고 값은 운영 구성으로 둔다)

벡터 인덱스의 HNSW 고정과 그래프 정점 파티셔닝 미채택은 [SRS 「임베딩 저장」](agent-context/SRS.md#임베딩-저장)과 [「저장 계층화」](agent-context/SRS.md#저장-계층화)에서 확정했고 SDD에 동기화했다. 임베딩 테이블만 같은 PostgreSQL의 온라인 `hot`·`cold`로 계층화하며 두 계층을 직접 검색한다.

콜드 임베딩은 같은 PostgreSQL의 온라인 영속 저장소로 제한한다. 공개 평가는 [SRS 「초기 공개 평가와 반복 정책」](agent-context/SRS.md#초기-공개-평가와-반복-정책)의 LongMemEval_S·LoCoMo·자체 보완과 조건별 10회·95% 대응 신뢰구간으로 확정했고 SDD가 실행·산출물 설계를 반영했다. 표본 부족·불명확한 결과는 판정 보류하며 실제 성능·비용은 아직 측정하지 않았다.

상세 설계가 확정해 이 목록에서 뺀 항목은 HTTP 서버와 라우팅, 데이터베이스 드라이버와 커넥션 풀, 인가 서버 구현 방식, 색인 작업 큐 구현 방식, 색인 재시도 한계, 화면 배치와 시각 표현 규칙이다. 이후 `source_ref`의 하위 구조, 관계형 테이블의 열 정의와 스키마 적용 방식도 확정했다. 계정·웹 세션·운영자 복구의 정본은 서버 SRS·SDD에 둔다. OAuth 최초 인가·코드 교환·Bearer 보호 인증 경계는 구현했으며 보호 MCP 조립·갱신 회전과 호스트 직접 연결은 후속 범위다.

[AUTH-04](agent-context/reviews/2026-10-19-auth-04.md)에서 공개 로그인·가입의 공유 예산·본문 상한·취소·비밀번호 작업 자리 회복을 인수했다. 686건의 모듈·선별 서버 시험을 통과했다.

[AUTH-05](agent-context/reviews/2026-10-19-auth-05.md)에서 웹 세션의 12시간 만료·갱신 없음·공유 폐기·키 회전과 실제 TLS 쿠키/채널 경계를 인수했다. 검증·폐기 장애는 내부 원문 없는 500으로 구분하고 취소 뒤 성공을 차단한다. OAuth 인가·토큰 처리는 후속 범위다.

[AUTH-06](agent-context/reviews/2026-10-19-auth-06.md)에서 공개 OAuth 메타데이터 두 경로와 사전 등록의 client/callback/resource 대조를 인수했다. 고정 주소·exact/same_ip 포트 정책과 실제 TLS 발견을 검증했다.

[AUTH-07](agent-context/reviews/2026-10-20-auth-07.md)에서 로그인·명시적 동의·최초 코드 교환과 실제 DB의 단일 소비·재사용 계열 폐기·원자적 롤백, TLS·입력 상한·자격 비노출을 인수했다. 중복 제외 923건·race와 전체 정적 검사를 통과했다. 당시 전체 59/124개 완료이며 다음 작업은 AUTH-08 Bearer·보호 리소스 인증이었다. 실제 브라우저·갱신·호스트 직접 연결은 미인수다.

[AUTH-08](agent-context/reviews/2026-10-20-auth-08.md)에서 Bearer 필수 클레임·등록/계열 결합·매 요청 공유 폐기와 401/403/500을 인수했다. 실제 DB의 두 인스턴스·재시작·키 회전·코드 재사용 폐기와 TLS 경계를 포함해 인증 340건·선별 서버 65건, 총 405건·race·전체 정적 검사가 통과했다. 현재 전체 60/124개 완료이며 다음 인증 작업은 AUTH-09 갱신 회전이다. 보호 /mcp 전송 조립과 실제 호스트 인수는 후속 범위다.
