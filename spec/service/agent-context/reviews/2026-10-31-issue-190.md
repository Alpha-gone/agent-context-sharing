# #190 폐기·삭제 원천의 중복 생성 응답

## 결정과 변경

이슈의 선택지 (b)를 적용했다. 같은 source_ref의 기존 원천을 반환하는 FR-AGENT_CONTEXT-146과 자연 키 유일성은 유지한다. 웹 삭제를 에이전트의 생성 요청으로 우회하거나 자동 복구하지 않는다.

`node_create`가 폐기·삭제 원천을 반환하면 기존 node와 deleted_at에 더해 `creation_status=existing_deleted`와 warning을 응답한다. 새 생성·자동 복구가 아니며 활성 근거로 사용할 수 없고, MCP 폐기분은 node_restore, 웹 삭제분은 웹 복구가 필요함을 안내한다. 삭제 채널을 추측하지 않고 두 경로의 조건을 명시한다. 활성 원천·파생·사건의 응답 형식은 유지한다.

추가 안내는 최초 멱등 결과에도 저장·재생된다. 복구 뒤 같은 request_id의 재생은 과거 결과일 수 있으며, 활성 원천은 node_get, 삭제 상태를 포함한 중복 결과는 새 요청 키로 확인한다. 과거에 저장된 멱등 결과는 소급 변경하지 않는다.

SRS·색인/MCP 상세 설계·추적표·시험 설계·배포 도구 스냅샷을 정합화했다. 저장소 구현·부분 유일 인덱스·복구 채널·DOX 소유권·환경 구성은 바뀌지 않아 유지했다.

## 검증 근거

- 수정 전 처리기를 Go overlay로 사용하면 신규 처리기 회귀가 deleted 하위 사례의 missing deleted state로 실패했다. 작업 파일을 되돌리지 않고 결함 검출을 확인했다.
- 독립 코드 검토에서 차단 결함은 없었다. node_get은 삭제 원천을 반환하지 않으므로 복구 후 활성 원천 조회라는 안내로 정확히 좁혔다.
- 실제 DB 회귀는 웹 삭제·MCP 폐기 각각에서 동일 locator 재생성이 기존 식별자·본문·삭제 시각을 유지하고 정점·색인·활동·감사를 변경하지 않는지 확인한다. 웹 삭제분의 MCP 복구 거부와 MCP 폐기분의 복구 가능성도 대조한다.

- Go 1.27.1 `go test -race -json -count=1 -timeout=15m ./internal/store ./internal/mcp`: 전용 합성 PostgreSQL에서 TEST_DATABASE_REQUIRED=1로 실행하여 store 1816·MCP 483개 시험 및 하위 사례가 실패·건너뜀 없이 통과했다. 도구 스냅샷은 UPDATE_TOOL_SNAPSHOT=1로 갱신했다.
- 검토 문구 보강 후 UPDATE_TOOL_SNAPSHOT 없이 MCP 전체 483개 시험 및 하위 사례를 다시 실행하여 스냅샷 일치와 최종 코드 통과를 확인했다.
- `check-go.sh`의 의존성·build·vet·gofmt 검사, diff 공백·변경 문서 링크/Markdown·SRS ID 집합 검사 통과.
- 기존 개발 DB를 사용하지 않고 로컬 캐시 이미지로 만든 #190 전용 컨테이너·볼륨만 사용했다. 실제 호스트·운영 배포는 이번 검증에 포함하지 않는다.
- 검증 후 소유 라벨을 확인하여 전용 컨테이너·볼륨을 제거했고 해당 라벨의 남은 컨테이너가 없음을 확인했다.
