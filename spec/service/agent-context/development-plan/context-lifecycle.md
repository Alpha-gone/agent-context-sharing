# 컨텍스트 수명주기 개발 계획

[전체 계획](../DEVELOPMENT_PLAN.md) · [기준 SDD](../sdd/context-lifecycle.md) · [작업 추적](traceability.md)

## 목표와 구현 범위

그래프·노드 쓰기, 파생 이력·근거, 사건·관계 전이, 소프트 삭제·복구와 관리 기록을 새로 구현한다. 정상 결과뿐 아니라 동시 변경·기록 실패·취소의 원자성을 완료 기준으로 둔다.

- 설계 입력: [파생](../sdd/context-lifecycle.md#파생-생성과-근거-무효화), [사건 재구성](../sdd/context-lifecycle.md#사건-재구성), [관계](../sdd/context-lifecycle.md#관계-후보-제안과-확정), [보관](../sdd/context-lifecycle.md#소프트-삭제-수명주기), [채널](../sdd/context-lifecycle.md#폐기와-복구의-채널), [트랜잭션](../sdd/context-lifecycle.md#트랜잭션-경계), [직렬화](../sdd/context-lifecycle.md#판정의-직렬화).
- 예정 구현 영역: `internal/store`의 도메인 쓰기·관리 기록·상태 판정, 모델 검증과 조립 어댑터.
- 다른 분야와의 경계: 전송 입력·멱등성 외피는 MCP 계획, 플랜·팀은 권한 계획, 시간 경과 처리는 운영 계획이 소유한다.

## 개발 작업

### LIFE-01

- [x] **그래프 생성·메타데이터 갱신을 구현한다.**
- 선행: [DATA-04](data.md#data-04), [PERM-02](authorization.md#perm-02), [PERM-05](authorization.md#perm-05).

1. UUIDv7 그래프 생성과 생성 계정의 직접 소유자 부여를 한 트랜잭션으로 처리한다. 이름 중복은 허용하고 현재 생성 한도를 검사한다.
2. 그래프 갱신은 name·description과 expected_version만 사용하며 판 비교·증가를 원자적으로 수행한다.
3. 사용자 쓰기 안에서 활성 그래프를 다시 확인하고 그래프 생성 계정·소유자·기여 계정의 의미를 구분한다.

- 산출물: 그래프 생성·갱신 저장 API와 원자성·충돌 표본.
- 완료 기준: 실패 뒤 고아 그래프·등급이 남지 않고 같은 판 동시 수정은 한 번만 적용된다. 삭제 그래프에 변경을 커밋하지 않는다.

- 완료 근거: 2026-10-17 [그래프 생성·메타데이터 갱신 모듈 시험](../reviews/2026-10-17-life-01.md). 생성 초기 상태와 실제 생성 계정을 검증하고, 활성 그래프 잠금 뒤 현재 판과 이름·설명을 검증한다. 새 격리 DB에서 같은 이름·초기 소유자·생성/기여 계정의 분리, 생성/갱신 삽입·커밋 실패와 바깥 롤백, 같은 판 8개 동시 수정, 삭제/갱신 잠금 대기 뒤 재판정·취소·자원 회복을 확인했다. 관련 고유 시험·하위 시험 61건·race와 전체 build·vet·형식 검사가 통과했다. 다음 권장 항목은 [LIFE-02](#life-02)이며 MCP 전송·멱등성 외피의 전체 인수는 해당 후속 작업에서 수행한다.

### LIFE-02

- [x] **계층별 노드 생성과 참조 저장을 구현한다.**
- 선행: [LIFE-01](#life-01), [DATA-04](data.md#data-04), [IDX-01](indexing.md#idx-01).

1. 원천·파생·사건의 필수·불변 속성, 기여 계정·등록 행위자, 같은 그래프 참조와 카디널리티를 검증한다.
2. 원천 자연 키의 선조회·부분 유일 경합을 처리하여 기존 원천을 반환한다. 이 경로는 활동 시각·저장량·관리 기록·색인 작업을 늘리지 않는다.
3. 새 정점·참조·현재 대상 계층의 색인 등록·활동 시각·stored_chars·content_revision·적용 관리 기록을 같은 트랜잭션에 넣는다.

- 산출물: node_create 저장 경계와 계층별 생성·중복·실패 표본.
- 완료 기준: 정상 원천 중복은 하나만 남고 어느 저장·참조·큐·감사 실패에서도 부분 적용이 없다.

- 완료 근거: 2026-10-17 [계층별 노드 생성·참조 저장 모듈 시험](../reviews/2026-10-17-life-02.md). 새 노드의 초기 판·기여 계정·감사 주체/대상과 파생 근거·사건 구성원의 중복을 검증한다. 원천 중복의 활성 그래프 재확인과 부분 유일 인덱스 충돌만의 재조회를 보강했다. 새 격리 DB에서 세 계층·두 색인 구성, 실제 원천 자연 키 경합, 정점/참조 질의 실패와 큐·활동·감사·커밋 실패의 원자성·풀 회복을 확인했다. model 149건·store 132건, 총 고유 시험·하위 시험 281건·race와 전체 build·vet·형식 검사가 통과했다. 등록 자격 검증은 MCP의 주입 계약을 따르며 실제 전송·등록·클라이언트 결합 인수는 해당 후속 작업 범위다. 다음 권장 항목은 [LIFE-03](#life-03)이다.

### LIFE-03

- [ ] **파생 갱신·대체·근거 무효·유지를 구현한다.**
- 선행: [LIFE-02](#life-02).

1. 파생의 가변 필드만 갱신하고 기대 판·새 판·이전 판의 대체 연결을 설계대로 보존한다. 정체성이 바뀌는 파생은 새 생성과 대체로 처리한다.
2. body 변경 때만 색인 등록을 수행하고 저장량 증분을 적용한다. 의견 신뢰 상태의 조건부 갱신은 편집자부터 허용한다.
3. 근거 폐기·대체는 직접 연결된 파생 한 단계에 evidence_invalidated를 표시한다. 자동 폐기·연쇄 전파·상충 자동 제외를 넣지 않는다.
4. keep은 가변 필드를 받지 않고 기대 판과 관리 기록만 처리한다. 재생성·폐기·유지 판단은 기록에서 구분한다.

- 산출물: 파생 갱신·대체·근거 표시·유지와 판 이력 시험.
- 완료 기준: 불변 필드 변경·원천 수정이 거부되고 근거 상태·참조·이전 판이 보존된다. 상태 없는 유지도 적용 기록이 남는다.

### LIFE-04

- [ ] **사건 갱신·재구성과 관계 상태 전이를 구현한다.**
- 선행: [LIFE-02](#life-02), [DATA-06](data.md#data-06).

1. 사건 구성원·시간 범위를 바꾸기 전에 그래프→정점 순서로 잠그고 현재 판·확정 관계의 시간 제약을 검사한다.
2. 관계 정체성·끝점 사건 계층·방향·시간·순환을 그래프 잠금 뒤 확인한다. 같은 관계 재확정은 현재 관계를 반환하고 제안·폐기 상태의 재확정도 순환 검사를 수행한다.
3. 사건 병합·분할을 기존 관리 연산의 조합으로 처리하고 같은 judgment_input으로 연결한다. 흡수·폐기 사건에 닿은 확정 관계를 같은 트랜잭션에서 폐기한다.
4. 관계 확정·폐기에 content_revision과 주체·시각·관리 기록을 적용한다. 관계의 수정·버전·시간 유효성·별도 복구 연산을 만들지 않는다.

- 산출물: 사건 수정·관계 확정/폐기와 병합·분할 실행 경계.
- 완료 기준: 동시 역방향 확정이 순환을 만들지 않고 사건 폐기와 관계 확정의 순서에 관계없이 삭제 끝점의 확정 관계가 남지 않는다.

### LIFE-05

- [ ] **관계 후보 신호와 재제안 규칙을 구현한다.**
- 선행: [LIFE-04](#life-04), [IDX-05](indexing.md#idx-05).

1. 사건 저장 커밋 뒤 시간 인접·구성원 진부분집합, 사건 색인 성공 뒤 임베딩 유사도 신호를 실행한다.
2. 신호별 임계값·후보 상한·정렬을 적용하고 같은 정체성의 confirmed/discarded는 다시 제안하지 않는다. causes는 자동 제안하지 않는다.
3. 제안 실패는 사건 저장·색인 성공을 되돌리지 않고 안전한 지표로 남긴다. proposed 보존 정리 후 유효한 정체성은 다음 방아쇠에서 다시 제안할 수 있게 한다.

- 산출물: 신호별 후보 계산·확보 후 콜백과 제안 기록.
- 완료 기준: 같은 구성원은 part_of 후보가 아니며 미확정 제안이 홉·흐름 탐색에 들어가지 않는다. 제안 방아쇠를 별도 주기 작업으로 바꾸지 않는다.

### LIFE-06

- [x] **웹 삭제·보관 유예·재연결 전이를 구현한다.**
- 선행: [DATA-04](data.md#data-04), [PERM-02](authorization.md#perm-02).

1. 그래프·노드의 웹 소프트 삭제와 소유자 판정·연쇄 영향 집계를 구현한다. 영구 삭제·연쇄 삭제는 수행하지 않는다.
2. 마지막 접근 가능한 계정은 직접 등급과 활성 팀 구성원을 함께 계산한다. 등급 회수·구성원 제거·팀 삭제의 그래프 잠금 경계에서 유예 시작·확정 만료를 기록한다.
3. 접근 계정 재연결이면 유예 시각을 즉시 비우고, 빈/삭제 팀 부여는 취소 근거로 사용하지 않는다. 플랜 변경으로 시작된 만료를 소급 계산하지 않는다.
4. 주기 만료 처리와 운영자 복구에 필요한 자동/직접 삭제 구분을 기존 grace 시각·감사로 제공한다.

- 산출물: 웹 삭제·유예 시작/취소·만료 대상 저장 API.
- 완료 기준: 동시 권한·팀 변경에도 유예가 한 번 시작되고 재연결 커밋 후 취소된다. 계정이 남는 그래프는 기본 무기한 보관되며 데이터는 삭제되지 않는다.

- 완료 근거: 2026-10-17 [웹 삭제·유예·재연결 모듈 시험](../reviews/2026-10-17-life-06.md). 그래프·노드의 웹 삭제/복구에서 잠금 뒤 현재 소유자·활성 상태를 재확인하고, 원천·파생은 기존 MCP 정점→그래프 순서를 유지했다. 고유 차단 계정·활성 파생·원천 구성 사건의 영향 집계를 보완했다. 팀 행→ID 순 그래프 잠금으로 새 부여와 구성원/팀 변경을 직렬화하고 구성원 추가도 잠금 뒤 수행하며, 저장할 수 없는 유예 일수의 잘림을 거부했다. 새 격리 DB에서 권한 회수 대기 12개 조합·MCP 갱신과 웹 삭제·새 팀 부여·다중 팀·재연결/만료의 양쪽 순서·확정 유예·비소급·복구 채널·감사 실패 롤백·자원 회복을 확인했다. 고유 시험·하위 시험 96건·race, 전체 build·vet·형식 검사와 문서 검사가 통과했다. 실제 브라우저·운영 배포·팀/권한 전체 인수는 후속 범위이며, 다음 권장 항목은 선행이 준비된 [PERM-03](authorization.md#perm-03)이다.

### LIFE-07

- [ ] **노드 폐기·복구와 현재 채널 판정을 구현한다.**
- 선행: [LIFE-02](#life-02), [LIFE-03](#life-03), [LIFE-04](#life-04), [LIFE-06](#life-06), [PERM-05](authorization.md#perm-05).

1. 대상 정점 잠금 뒤 현재 deleted_at과 같은 대상의 applied discard 기록을 다시 읽는다. 사건은 그래프→정점 순서를 지킨다.
2. 현재 삭제 시각 이후의 적용 폐기 기록만 MCP 복구 근거로 사용하고 웹 삭제는 not_supported와 웹 대체 채널로 안내한다.
3. 폐기·복구의 상태·저장량·내용 판·관리 기록과 복구 색인 등록을 원자적으로 처리한다. 재폐기·재복구는 상태 오류로 거부한다.
4. 일반 보존 정리에서 현재 폐기의 복구 근거를 보호한다. 과거 연산 폐기→복구→새 웹 삭제를 현재 채널로 오인하지 않는다.

- 산출물: discard/restore·기록 기반 채널 판정과 보존 정리 보호 조건.
- 완료 기준: 세 계층에서 잠금 대기 중 전이를 재판정하고 같은 노드 전이는 한 번만 적용된다. 복구 감사 실패·한도 초과는 전체 롤백된다.

### LIFE-08

- [ ] **출처 전달·관리 감사·오염 되짚기를 구현한다.**
- 선행: [LIFE-03](#life-03), [LIFE-04](#life-04), [LIFE-07](#life-07).

1. 적용 기록은 도메인 쓰기에, 거부 기록은 롤백 뒤 별도 경계에 남긴다. 대상 종류·판·실행 계정·agent·판단 입력·결과를 스키마 제약에 맞춘다.
2. 파생·사건의 출처는 응답 조립 시 원천까지 추적해 모든 origin_kind를 전달하고 별도 property·순위 감점으로 저장하지 않는다.
3. 연산 기록을 거슬러 시작점을, 확정 참조·관계를 따라 영향 범위를 조회한다. 감사의 되짚기는 소유자·허용 운영 경계에 두고 MCP 업무 도구로 노출하지 않는다.

- 산출물: 적용·거부 감사 API, 출처 집계·영향 조회.
- 완료 기준: 컨텍스트 폐기 후에도 기록과 주체가 남고 출처가 누락되지 않는다. 영향 조회가 자동 폐기·자동 수정으로 이어지지 않는다.

### LIFE-09

- [ ] **트랜잭션·직렬화·실패 전파를 인수한다.**
