# DATA-07 임베딩·HNSW 저장 모듈 시험

## 범위와 입력

- 대상: [DATA-07](../development-plan/data.md#data-07). 선행 DATA-03·DATA-05 완료. 시작 커밋 `0291ea5`, 브랜치 `feat/data-schema-contract`.
- 정본: [임베딩 스키마](../sdd/data.md#임베딩-스키마), [HNSW 인덱스](../sdd/data.md#인덱스), [색인 설계](../sdd/indexing.md), [시험 시점](../DEVELOPMENT_PLAN.md#테스트-작성과-실행-시점).
- 작업 시작 시 실제 원격 `dev`·추적 ref·HEAD가 `0291ea5`로 같아 앞섬·뒤처짐 0이었다. 사용자 운영 Compose·IDE 변경은 작업 범위에서 제외했다.

## 구현과 검토

- 의미 검색의 `$3::vector` 고정 형 변환을 제거했다. 거리 연산자가 왼쪽 저장 열을 따라 매개변수 타입을 결정하므로 `vector`·`halfvec` 모두 각 코사인 HNSW와 일치하는 거리 정렬을 사용한다.
- `CheckEmbeddingSchema`는 지원 타입·HNSW 차원 상한을 DB 연결 전에 검사한다. 부모 열과 구성의 타입·차원 대조에 더해 필수 일곱 열의 NOT NULL, 영속 LIST 파티션, hot/cold 경계, 각 자식의 `context_id` 유일성과 유효·준비 상태의 코사인 HNSW를 대조한다.
- 단일 결과 저장 경로의 기존 행 제거→hot 삽입→내용 판 증가→불변식 검사를 유지하며 결과 트랜잭션을 공통 `finishWrite`로 정리한다. 실패 시 취소와 별개인 정리 예산으로 작업 삭제·기존 벡터·내용 판을 롤백한다.
- 기존 001·009·010·011과 적용 이력은 변경하지 않았다. 새 DDL 없이 현재 파티션·인덱스 생성 계약을 명세와 대조하고 새 DB에서 검증했다.
- `halfvec(4000)`은 저장소 HNSW 상한 시험이다. Gemini 제공자 자체의 128~3072차원 범위나 실제 배포 구성을 변경한 것이 아니다.

## 환경과 결과

- Go 1.27.1 darwin/arm64, PostgreSQL 18.6 / Apache AGE 1.8.0 / pgvector 0.8.6 / Linux aarch64.
- 저장소 고정 Dockerfile로 `agent-context-data07-db` 이미지·컨테이너·새 볼륨을 만들고 loopback 동적 포트만 공개했다. 타입별·형상 훼손 시험은 다시 각각 임시 DB를 생성하여 정식 001·009·010·011을 적용했다. 기존 `.env`·DB·볼륨·외부 제공자는 사용하지 않았다.
- **고유 모듈·하위 시험 60건 통과**: store 34건·migrate 4건·config 20건·index 2건, 최상위 15개·하위 45개. `-race`·`-count=1`과 DB 필수 실행 설정을 적용했으며 최종 실패·건너뜀은 0이다. 같은 이름의 재실행은 중복 집계하지 않았다.
- 타입별 새 DB 적용 4개·재실행 0개, 부모를 통한 hot/cold 조회, 두 파티션의 실제 중복 쓰기 `23505`, 같은 벡터의 코사인 유사도 1·직교 벡터의 0을 확인했다.
- 각 구성에서 cold의 이전 벡터를 새 모델의 hot 벡터 하나로 교체했다. 잘못된 차원 저장은 실패했고 임베딩 전체 행 지문·그래프 내용 판·대기 작업이 보존됐다. 현재 모델 필터와 다른 그래프 정점을 가리키는 행·고아 임베딩 배제도 대조했다.
- 부모와 자식 형상 훼손 표본은 cold 분리, 자식 유일 인덱스 제거, HNSW 제거, L2 HNSW로 교체, 모델 열의 NOT NULL 제거를 각각 만들었다. 모두 기동 전 검사에서 거부했고 실제 연결·예약이 반환됐다. bit·비양수 차원·vector/2001·halfvec/4001·알 수 없는 타입도 DB 연결 전에 거부했다.
- 관련 저장 회귀는 일반 검색, 작업 재등록·리스 재확보의 이전 결과 차단, 저장 실패 롤백과 스냅숏 안 임베딩 격리를 새 전용 DB에서 실행했다. 신규 스키마와 공급자 구성·모델 식별자·키 없는 메타데이터 검증도 포함했다.
- 최초 회귀 선택식에서 `internal/index`에는 해당 이름의 시험이 없었다. 이를 통과 건수에 넣지 않고 실제 제공자 구성·메타데이터 시험 두 건을 별도 선택하여 실행했다.
- `check-go.sh`의 의존성 검증·전체 build·vet·gofmt를 통과했다. 문서 링크·앵커·계획 수·Markdown·DOX 소유/색인과 `git diff --check`를 확인했다.

### 실행 범위

```sh
TEST_DATABASE_URL='<새 합성 전용 DB URL>' TEST_DATABASE_REQUIRED=1 AGE_GRAPH_NAME=agent_context GOTOOLCHAIN=local \
/Users/alphagone/sdk/go1.27.1/bin/go test -race -json -count=1 -timeout=180s ./internal/store -run '^TestEmbedding'

GOTOOLCHAIN=local /Users/alphagone/sdk/go1.27.1/bin/go test -race -json -count=1 ./internal/index ./internal/config \
  -run '^Test(ProviderConfigAndModelID|ProviderMetadataDoesNotRequireCredentials|GeminiConfiguration)$'

GO_BINARY=/Users/alphagone/sdk/go1.27.1/bin/go sh ./check-go.sh
```

관련 회귀는 `TestIndexAndNonGraphSearchIntegration`, `TestIndexReenqueuedTaskIgnoresStaleResultIntegration`, `TestIndexReclaimedTaskIgnoresStaleResultIntegration`, `TestIndexResultStorageFailureRollsBackTaskIntegration`, `TestIsolationEmbeddingRowsIntegration`, `TestTargetSchemaFreshAndRepeatIntegration`, `TestMigrationTargetsAndHNSWLimits`, `TestEmbeddingProviderSelection`을 선택했다. 파티션 DB 유일성 보강 후 같은 타입별 시험을 다시 실행했다.

## 완료 판정과 남은 범위

- DATA-07의 구현·모듈 시험 완료. 전체 계획은 15/124개 완료·109개 미착수이며 다음은 [DATA-08](../development-plan/data.md#data-08)이다.
- 온라인 이동·접근 기록·동시 파티션 이동은 DATA-08, 실제 제공자 결과 공개·옛 모델 배제의 색인 분야 인수는 IDX-05, 전체 저장 인수는 DATA-10에서 이어 수행한다. 이번 결과를 그 작업의 완료로 승계하지 않는다.
- 운영 DB·실제 제공자 API·복원·전체 저장 인수·호스트·amd64 runtime은 미실행이다. 양자화 bit와 외부 저장소를 추가하지 않았다.
- DOX 구조·소유권·요구사항·설계 계약은 바뀌지 않아 DOX·SRS·SDD·용어집을 유지했다. 커밋·푸시는 수행하지 않았다.
- 타입별 임시 DB는 시험별로 제거했고 남은 임시 DB 0을 확인했다. DATA-07 작업 라벨을 대조한 뒤 전용 컨테이너·볼륨·이미지만 정리했으며 이름으로 다시 조회한 잔여 자원도 0이다.
