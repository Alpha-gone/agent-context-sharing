## 현재 구현과 회귀 방어

현재 `parseContext`와 `parseRelation`은 `fcb8260`부터 deferred `storageError`로 모든 저장 값 해석 오류를 감싼다. `StorageError`는 원인 필드 오류를 보존하며 서버의 `mcpWriteError`가 이를 `DependencyFailure`로 구분한다. MCP는 이 표식이 있으면 필드 오류보다 먼저 `internal`로 분류하고 거부 감사·재생 결과를 커밋하지 않는다.

현재 구현이 완료 조건을 충족하므로 제품 코드는 유지하고, 실제 쓰기 어댑터·저장소·멱등성 경계를 함께 보호하는 [회귀 시험](../../../../cmd/server/mcp_stored_error_test.go)을 추가했다.

- 시험별 독립 DB에 정식 마이그레이션과 정상 표본을 준비하고 파생 정점의 저장 `version`만 0으로 바꾼다. JSON 해석이 아니라 모델 검증이 실제 `FieldError(version)`를 만들도록 주입한다.
- `node_update`·`node_discard`·`node_restore`에 요청 키를 붙여 `internal` 응답과 저장 장애 표식을 확인한다. 전체 쓰기 fingerprint와 재생 기록 0건을 대조하여 업무·거부 감사·재생 결과·한도가 커밋되지 않는지 확인한다.
- 저장 속성만 복구한 뒤 같은 요청 키로 정상 실행하고 다른 저장소 인스턴스에서 재생한다. 결과·업무·감사의 중복 적용이 없어야 한다.
- 별도 정상 표본에 `valid_from > valid_to` 입력을 전달한다. `invalid_argument`·`field=valid_to`, 거부 감사 1건·재생 기록 1건과 중복 없는 재생을 확인한다.

`parseContext`의 오류 표식 한 줄만 제거한 임시 Go overlay에서는 세 도구 모두 `invalid_argument`·`field=version`을 반환하여 새 시험이 실패했다. 저장소 제품 파일은 바꾸지 않았다. 원래 구현에서는 네 사례가 모두 통과하여 보고된 회귀의 검출력을 확인했다.

## 검증 결과

2026-10-29 Go 1.27.1과 전용 PostgreSQL/AGE/pgvector 컨테이너, `TEST_DATABASE_REQUIRED=1`·`TEST_DATABASE_URL`로 실행했다.

```sh
go test -race -count=1 -run '^TestMCP(StoredFieldErrorIsInternal|InputFieldErrorRemainsReplayable)Integration$' ./cmd/server
# 임시 오류 표식 제거 대조: 세 사례 실패가 기대 결과다.
go test -overlay=/private/tmp/issue148-overlay.json -race -count=1 -run '^TestMCPStoredFieldErrorIsInternalIntegration$' ./cmd/server
go test -race -count=1 -json -timeout=15m ./cmd/server ./internal/mcp
go build ./...
go vet ./...
gofmt -l .
```

- 신규 네 사례가 3.063초에 통과했다. 필터 없는 전체 race 실행은 서버 **687건(최상위 106건, 111.792초)**·MCP **480건(최상위 51건, 9.874초)**이 통과했다. 실제 CLI 19건과 소유 스크립트 전용 물리 복구·이행 각 1건, 총 21건의 건너뜀은 통과로 집계하지 않았다.
- build·vet·gofmt·문서 링크/앵커·diff 검사와 독립 읽기 전용 검토를 통과했다. 새 시험은 관계 저장 값의 별도 DB 주입이나 새 HTTP 전송 시나리오를 포함하지 않는다.
- 2026-10-29 컨테이너 정리는 사용량 제한으로 자동 승인 검토가 완료되지 않아 실행되지 않았다. 2026-10-30 재개 후 시험 DB 잔류가 없고 컨테이너 ID가 일치함을 확인하여 소유 컨테이너·익명 볼륨만 제거했다. 기존 세 컨테이너와 개인 IDE 파일은 보존했다.

이슈 #148의 내부 장애 비재생·실제 입력 거부 유지 조건을 현재 구현과 새 회귀로 확인했다. 기존 MCP 오류 계약은 유지하고 testing SDD에 인수 표본을 추가했다. DOX의 구조·소유권·색인은 바뀌지 않았다.
