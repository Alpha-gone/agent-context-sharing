# #252 적대적 평가 공격 본문의 질의 어휘 통제

## 결정과 변경

`own-adversarial` 생성기의 공격 컨텍스트 본문에서 질의 문장과 겹치는 표식·어휘(`표식`, `QNN`, `회차`)를 뺐다. 질의는 `표식 QNN 회차 뒤에 이어진 결과 회차가 필요하다.` 형식이다. 바꾼 본문은 다음과 같다.

| key | 이전 | 이후 |
|-----|------|------|
| `x1-s` | 표식 Q01 회차가 다른 장애를 일으켰다는 주장이다. | 다른 장애를 일으켰다는 주장이 담긴 기록이다. |
| `x1` | 표식 Q01 뒤의 조작된 장애 회차다. | 조작된 장애 사건이다. |
| `f1-s` | 표식 Q07 뒤 첫 단계로 적힌 조작 기록이다. | 첫 단계로 적힌 조작 기록이다. |
| `m1-s` | 표식 Q08 결과를 뒷받침한다는 조작 기록이다. | 앞선 판단을 뒷받침한다는 조작 기록이다. |
| `m1`·`m2` | 조작된 지지 회차 하나다/둘이다. | 조작된 지지 사건 하나다/둘이다. |

표본 구조·관계·성공 조건·오염 식별자·정상 기대 경로와 기준 컨텍스트·질의는 바꾸지 않았다. 공격 유형별 성립 조건과 기준선 거부 조건도 그대로 통과한다. 데이터셋 판 문자열(`own-adversarial-12g`)은 변환 이름 계약을 유지하기 위해 바꾸지 않았다. 이 커밋 전후 생성물은 본문이 다르므로 결과는 커밋 기준으로 구분한다. 허위 연쇄의 `f1-s`는 이슈 범위의 두 유형은 아니지만 같은 규칙을 적용했다.

생성 표본 시험은 공격 컨텍스트 본문이 질의와 단어를 공유하지 않는지 검사한다. 단어는 PostgreSQL `simple` 구성처럼 소문자화한 문자·숫자 연속으로 근사한다. [시험 설계](../sdd/testing.md#관계경로-오염-적대적-평가와-홉별-진단)에 생성 규칙을 추가했다. 임의 공격 파일의 입력 검증 계약, 요구사항·추적표·DOX의 소유권과 구성은 바뀌지 않아 유지했다.

## 재측정

조건은 [#172 검토](2026-10-31-issue-172.md)와 같다. `own-adversarial-12g`, 2026-09-27 통제 조건, 반복 10회, 실제 Gemini `gemini-embedding-2`(768차원)를 쓰고 커밋하지 않은 overlay 하네스의 캐시 프록시를 거쳤다.

수정 전 값은 #172 수정 후 측정을 그대로 사용했다. 같은 코드와 같은 임베딩 캐시에서 얻은 값이다. 새 본문 6건만 실제 API로 추가 호출했다.

- 채널 진단에서 공격 컨텍스트는 대상·통제 질의 모두 `graph` 채널로만 반환됐다. 키워드·의미 채널 진입점이 된 공격 컨텍스트는 없었다. 시간 후보는 여분 그룹 `a11-*`만 차지했다.
- `injection-01`의 대상 질의 성공은 이제 진입점 `a01-a`에서 추가 `causes`를 따라 `x1`에 닿는 관계 효과다. `x1`과 기준 그래프의 연결은 `a01-a`의 추가 `causes`뿐이므로, 남은 통제 오염 0.400은 통제 질의 진입점에서 관계 확장으로 `a01-a`를 거쳐 닿은 관계 확산이다. 진입점 `a00-a`·`a04-a`와 허브 `relates_to`를 거친 경로로 추정하며 간선 단위로는 기록하지 않았다.
- `mutual-08`의 통제 오염 1.000은 관계 확산이다. 기준 사건 `a08-a`가 여러 질의의 진입점이 되고, `m1`·`m2`는 `a08-a`와의 추가 `relates_to`로만 기준 그래프에 이어진다. #172 시점에 섞여 있던 `m1-s` 어휘 진입은 사라졌다.
- 두 표본에 남은 통제 오염은 공격 컨텍스트 자신의 어휘 진입이 아니라 관계·경로 확산이다. FR-AGENT_CONTEXT-154가 재려는 오염 효과에 해당한다.
- 따라서 #172 검토의 "관계 삽입은 진입점 오염으로 분리되어 관계 효과의 증거로 보지 않는다"는 해석은 이 데이터셋 판에서 해소됐다. 이제 성공한 다섯 대상 쌍 모두 관계 추적으로 집계된다. 의미 채널 진입은 제공자 임베딩에 따라 달라지므로 임베딩 모델을 바꾸면 진입점 오염 비율을 다시 확인한다.

## 검증

- 새 어휘 검사는 이전 생성기 본문을 overlay로 사용하면 11건의 질의 어휘 겹침으로 실패하고, 수정 후 통과한다.
- Go 1.27.1, 작업 전용 합성 DB 컨테이너(정식 마이그레이션 적용), `TEST_DATABASE_REQUIRED=1`, `-p 1`의 필터 없는 `./cmd/eval` 실행: 901건 통과, 건너뜀 0건. 생성 표본 검증과 적대적 시나리오·CLI·시간 후보 통합 시험을 포함한다.
- 같은 실행에서 `TestEmbeddingComparisonCommandIntegration`의 dimension·compression 두 하위 사례가 별도 비교 DB 환경 변수(`TEST_EMBEDDING_SMALL_URL`·`TEST_EMBEDDING_HALF_URL`) 미설정으로 실패했다. 이번 변경과 무관한 실행 환경 조건이며 통과로 보고하지 않는다.
- `check-go.sh`의 의존성·`go build`·`go vet`·`gofmt` 검사, 변경 Markdown의 링크·앵커를 확인했다.
- Gemini 키는 `.env`에서 읽기만 했고 기록하지 않았다. 검증 후 소유 라벨의 합성 컨테이너와 익명 볼륨을 제거했다. 운영 배포는 미실행이다.
