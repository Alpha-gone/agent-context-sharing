# #170 검색 단위 비교의 근거 주석 완전성 판단

## 결정과 변경

`units` 모드의 `complete_retrieval_annotations`를 회차 결과의 근거 완전성·경로 연속성 값이 아니라 입력 정답 매핑으로 판단한다. 모든 조건의 정답 매핑에 기대 경로가 있어야 주석 완전이다. 기대 경로는 두 컨텍스트 이상이므로 근거 완전성 분모도 함께 정의된다. 필수 컨텍스트만 있고 기대 경로가 없는 매핑은 경로 연속성을 정의할 수 없으므로 기존과 같이 주석 누락으로 보류한다.

첫 노드 미반환 때문에 `evidenceScore`가 남기는 경로 연속성 `-1`은 기존 판정 집계에서 해당 질의의 해당 지표만 제외한다. 측정·판정 함수와 다른 평가 모드는 변경하지 않았다. [평가 설계](../sdd/evaluation.md#검색-단위-비교의-실행-입력과-결과)와 [시험 설계](../sdd/testing.md#검색-단위-완전성-비교-시험)에 입력 기준 판단과 표본 제외를 명시했다. 요구사항·추적표·DOX의 소유권과 구성은 바뀌지 않아 유지했다.

## 검증

- 수정 전 `unit_metrics.go`를 Go overlay로 사용하면 새 회귀의 `unreturned_path_start`가 실패했다. 이슈와 같은 `complete_retrieval_annotations=false`, `deferred`/`unmeasured_or_insufficient_independent_units`를 재현했다.
- 새 회귀는 주석 완전 + 첫 노드 미반환 표본이 주석 완전·`candidate`로, 기대 경로를 제거한 실제 주석 누락 표본이 주석 누락·보류로 남고 다른 표본군은 오염되지 않는지 대조한다. 결과 값만 바꾸던 기존 `partial_annotation` 사례는 새 회귀로 대체했다.
- Go 1.27.1, 작업 전용 합성 DB 컨테이너(정식 마이그레이션 적용), `TEST_DATABASE_REQUIRED=1`, `-p 1`의 필터 없는 `./cmd/eval` 실행: 900건 통과, 건너뜀 0건. `TestUnitComparisonCommandIntegration`을 포함한 검색 단위 시험은 모두 통과했다.
- 같은 실행에서 `TestEmbeddingComparisonCommandIntegration`의 dimension·compression 두 하위 사례가 별도 비교 DB 환경 변수(`TEST_EMBEDDING_SMALL_URL`·`TEST_EMBEDDING_HALF_URL`) 미설정으로 실패했다. 이번 변경과 무관한 실행 환경 조건이며 통과로 보고하지 않는다.
- `check-go.sh`의 의존성·`go build`·`go vet`·`gofmt` 검사 통과. 변경 Markdown의 링크·앵커를 확인했다.
- 검증 후 소유 라벨의 합성 컨테이너와 그 익명 볼륨을 제거했고 해당 라벨의 잔여 컨테이너가 없음을 확인했다. 실제 외부 제공자·에이전트 trace·운영 배포는 미실행이다.
