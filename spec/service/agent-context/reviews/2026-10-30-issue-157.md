# #157 색인 제공자 장애 중 작업 확보 차단

- 대상: [이슈 #157](https://github.com/Alpha-gone/agent-context-sharing/issues/157).
- 기준: `dev`의 `3b94f5d`, 작업 브랜치 `fix/157-index-provider-circuit`.

## 결정과 구현

Worker가 인증/권한 401·403, 408·429·5xx, 요청 취소가 아닌 전송/timeout 장애를 관측하면 다음 작업 확보를 중단한다. 첫 실패 작업의 즉시 실패·5회 예산은 그대로 반영한다. 차단 중에는 고정 합성 문자열의 같은 모델·차원 임베딩으로만 회복을 확인하여 다른 작업의 시도 횟수·리스·등록 세대를 바꾸지 않는다. 탐침 실패는 차단을 유지하고 성공 때만 확보를 재개한다.

상한 1·2·4·8·15분의 지수 백오프에 50~100% 지터를 두며 Retry-After의 초/HTTP-date 지연을 더 긴 하한으로 사용한다. 로컬 보호 상한은 24시간이다. 원인·차단·회복은 안전한 제공자 상태와 provider_blocked/provider_resumed 진단·구조화 로그로 남긴다. 특정 작업의 호출 진단과 차단 상태 진단을 구분하도록 기존 공개 회귀를 보강했다.

회차와 탐침은 Worker별 비차단 TryLock으로 직렬화하고 기존 취소 가능한 소비 루프를 사용한다. 검색/직접 임베딩은 차단하지 않는다. 상태는 Worker 메모리에 한정되므로 여러 프로세스는 각각 감지하며 재시작 때 초기화된다. 기존 failed 작업의 자동 부활이나 작업별 세대·예산 정책 변경은 없다. 실제 탐침은 제공자 요청량/비용에 포함되며 자격 증명 구성 변경은 새 Worker/프로세스를 따른다.

[색인 정본](../sdd/indexing.md#제공자-장애-중-작업-확보-차단)·[관측성](../sdd/observability.md#처리-지점-계측)에 계약을 명시했다. Retry-After의 표준 형식과 서비스의 로컬 정책 구분은 [공급자 근거](../reference.md#2026-10-30-157-제공자-차단과-retry-after)에 유지했다. 공개 구성·DB 스키마·DOX 소유권과 색인은 바뀌지 않았다.

## 재현과 검증

- 차단 호출만 제거하고 새 타입의 소스 호환은 유지한 Go overlay로 기존 확보 동작을 대조했다. 실제 TLS 제공자·격리 DB의 401·403·429·503 네 사례 모두 장애 중 다른 그래프의 다음 작업을 계속 확보하여 실패했다.
- 수정 후 첫 실패를 반영하고 모든 작업을 DB 시각상 확보 가능하게 만들어도, 반복한 그래프/전역 회차는 HTTP 요청과 큐의 상태·시도 횟수·등록 세대·리스 전체 스냅숏을 바꾸지 않았다. 실패 탐침도 큐를 유지했고 성공 탐침 뒤 작업 하나의 벡터가 공개됐다. 첫 인증 실패의 failed/1회와 일시 실패의 pending/1회, 나머지 작업의 attempts=0을 확인했다.
- 차단/실패 탐침/해제 진단, Retry-After 초·날짜·잘못된 값·오버플로·상한, 지터/백오프 범위, 요청 취소·직접 질의 격리·동시 회차를 검사했다. 탐침 취소는 고정 시간 경합 대신 실제 HTTP 진입을 기다린 뒤 주입한다.

최종 필수 격리 DB·race 결과는 다음과 같다. 건수는 하위 사례를 포함한다.

- `internal/index` 전체: 129건, 5.318초. 실패·건너뜀 없음.
- `internal/diagnostic` 전체: 196건, 23.327초. DB 실행권 시험도 실행했고 실패·건너뜀 없음.
- `internal/search` 전체: 342건, 7.143초. 실패·건너뜀 없음.
- `cmd/server` 전체: 688건 통과, 116.314초. 별도 Codex CLI·물리 복구·이전 인수 21건은 환경 미설정으로 건너뜀.
- Store의 재시도·즉시 실패·세대/리스·실패 롤백 회귀: 76건, 13.171초. 실패·건너뜀 없음.
- 제공자 관련 최종 경계 재검증: 12건, 2.480초. 실패·건너뜀 없음. 위 전체 범위와 겹치므로 고유 건수로 합산하지 않는다.

Go 1.27.1 build·vet·gofmt·diff 검사도 통과했다. 실제 외부 Gemini 호출이나 비용 실측은 하지 않았다. 예비 전체 실행은 새 취소 HTTP 대역의 종료 지연 때문에 해당 시험 프로세스만 중단했다. 요청 본문을 읽고 명시적으로 종료 가능한 대역으로 보완한 뒤 전체 인수를 다시 실행했으며 예비 실행을 통과로 집계하지 않는다.

결과는 `/private/tmp/acs-157-regression.json`, `acs-157-store.json`, `acs-157-provider-final.json`, 원본 대조는 `acs-157-original.txt`, 예비 실행은 `acs-157-preliminary.json`에 보관했다. 생성 DB 잔류 없음·idle transaction 0개와 컨테이너 ID/소유 라벨을 확인하고 시험 컨테이너·익명 볼륨만 정리했다. 기존 세 컨테이너·개발 DB·개인 IDE 파일은 보존했다.
