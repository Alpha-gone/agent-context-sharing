# #184 진단 일괄 기록과 저장량 조회 개선

- 대상: `perf/184-diagnostic-batch`, 기준 `origin/dev`의 `12bbf58`.
- 요구: #184의 반복 inventory·행별 fsync 비용 감소, Written/용량 검사 계약 정합화, Linux 볼륨 처리량 인수.
- 상태: 구현·로컬 인수 완료. 운영 볼륨의 별도 성능 보장으로 확대하지 않는다.

## 변경과 계약

최대 128건·256 KiB의 이미 수락한 이벤트를 추가 대기 없이 묶고 파일 종류별 수락 순서를 보존하여 append·sync한다. 공유 잠금의 한 보유 구간에서 목록의 크기를 재사용하고 실제 append 바이트를 반영한다. 잠금 양보/해제 및 회전·정리·복구·오류 시 캐시를 폐기한다. 묶음 전체를 사전 예약하며 쓰기 전 용량·시각 거부만 나누고 I/O 실패는 재시도하지 않는다. Written은 성공한 묶음의 이벤트 수이며 큐 예약은 완료 또는 실패까지 유지한다. sync 실패의 완전 행이 파일에 남더라도 성공으로 집계하지 않는다. 정본은 [관측성](../sdd/observability.md#민감정보와-크기-제한)에 유지했다.

## 경계 회귀와 검토

종류별 바이트/순서 보존·묶음 내 inventory 1회·다른 기록자의 잠금 해제 후 소비 반영·작은 회전 상한·만료 행 격리·완료 전 큐 예약을 검증했다. 기존 실제 다중 프로세스 총상한 시험은 묶음 공간 부족 시 분할하여 남은 용량을 채우는 동작도 검증한다. 실제 잠금 종료 시험은 1,024건으로 조정하여 일괄 처리 뒤에도 5초 공통 마감과 누락 원인을 확인한다. Linux 자식의 seccomp/RLIMIT로 ENOSPC·EROFS·짧은 쓰기·fsync EIO와 다음 기록 회복을 확인했다.

초기 전체 시험에서 공간 부족 시 묶음 전체를 거부한 문제와 기존 행별 잠금 대기 가정을 발견했다. 공간·시각 거부의 쓰기 전 분할 및 충분한 종료 부하로 보완했다. 독립 검토에서 최초 검증 뒤 만료 경계를 넘는 행이 같은 종류의 새 행을 동반 누락시키는 경계를 재현했고, 분할 및 실제 파일 회귀로 수정했다. 독립 재검토에서 추가 결함은 발견되지 않았다. 단일 행의 커널 sync 실패는 직접 인수했으며 여러 행 묶음의 커널 sync 실패 집계를 별도로 강제한 시험은 없다.

최종 Linux 실행은 `acs-obs08-results-iN4LM0`, 대조는 `acs-obs08-results-bo0XvP` 결과를 사용했다. macOS 최종 원시 결과는 `/tmp/acs184-macos-final.json`이다. 시험 컨테이너·볼륨 잔류 없음과 기존 개인 IDE 파일 보존을 확인했다. DOX pass에서 구조·소유권·실행 경계는 바뀌지 않아 기존 DOX/색인을 유지하고, 동작 계약과 검증 근거만 소유 문서에 갱신했다.
