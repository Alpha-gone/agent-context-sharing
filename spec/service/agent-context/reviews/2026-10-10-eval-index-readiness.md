# 평가 전 색인 준비 검증

## 범위와 처리 결과

2026-10-10에 [GitHub #105](https://github.com/Alpha-gone/agent-context-sharing/issues/105)의 평가 전 색인 완료 판정을 보완했다. 기준 커밋은 원격 `dev`와 일치하는 `8c78952`이며 작업 브랜치는 `fix/issue-105-eval-index-readiness`이다.

기존 `drainIndexQueue`는 작업자의 `Found=false`를 완료로 받아들였다. 확보 질의는 지금 처리 가능한 `pending` 작업만 읽으므로 재시도 대기·리스·행 잠금으로 숨겨진 작업과 `failed` 작업, 작업 없이 누락된 임베딩을 놓쳤다.

- SDD의 「검증을 가능하게 하는 설계」에 평가 전 준비 조건과 실패 정책을 먼저 반영했다. 확보 가능한 작업을 처리한 뒤 남은 작업과 현재 모델 임베딩을 확인한다. 자동 백오프 대기는 두지 않고, 미완료 상태에서는 명시적인 오류로 측정을 중단한다. 기존 처리 회차 상한과 제공자 호출 제한은 유지한다.
- 저장소의 `CheckGraphIndexReady`가 한 SQL 명령의 스냅숏에서 평가 그래프의 전체 `pending`·`failed` 작업과 현재 모델 임베딩 누락을 대조한다. 준비 대상은 현재 색인 대상 계층의 활성 컨텍스트이며 원천 제외 구성과 삭제 상태를 따른다. 다른 그래프의 상태는 포함하지 않는다.
- 같은 모델의 이전 임베딩이 존재해도 새 작업이 남으면 완료로 보지 않는다. 오류는 상태별 건수와 보관된 실패 사유를 전달하고, 평가기가 작업을 임의로 재등록하지 않는다.
- 기본·적응형·지속·적대적·일관성 평가의 기존 큐 비우기 호출을 같은 준비 검사에 연결했다. 마지막 허용 회차에 모든 작업이 끝났다면 완료로 인정한다. 미완료 오류는 기존 그래프 정리와 실패 종료 경계로 전파되어 정상 결과 파일을 기록하지 않는다.

## 검증

Go 1.27.1 SDK와 개발 PostgreSQL의 전용 시험 DB `issue105_test_20261010`을 사용했다. 시험마다 정식 `001_init` 마이그레이션을 적용하고 `TEST_DATABASE_REQUIRED=1`을 설정했으며 종료 뒤 시험 DB를 삭제했다. 임베딩 제공자는 로컬 HTTP 시험 대역만 사용했다.

- 새 DB 회귀 시험: 통과. 제공자의 HTTP 429·503 재시도 대기, HTTP 400 최종 실패, 다섯 번째 실패의 재시도 소진과 차원 불일치를 확인했다. 각 상태에서 정상 완료를 반환하지 않고 작업의 실패 상태·시도 횟수를 보존했다.
- 실제 다른 작업자의 제공자 호출을 대기시킨 리스와 별도 트랜잭션의 작업 행 잠금: 통과. 평가가 확보할 작업을 찾지 못해도 준비 완료를 반환하지 않았다. 다른 작업자가 결과를 커밋한 뒤에는 준비 검사에 통과했다.
- 현재 모델 불일치·임베딩 누락·현재 모델 임베딩이 있는 재색인 대기, 원천 제외 구성·삭제된 원천 제외와 다른 그래프의 실패 격리: 통과.
- 기본·적응형·지속·적대적·일관성 CLI의 색인 미완료 실패 종료와 정상 보고서 파일 미생성: 모두 통과.
- `go test -count=1 -race -p 1 -timeout=180s -json ./cmd/eval ./internal/store ./internal/index`: 시험·하위 시험 455건 통과, 실패 0건, 건너뜀 0건, 종료 코드 0.
- 서버·클라이언트 각각 `go build ./...`, `go vet ./...`: 통과. `gofmt -l .`, `git diff --check`: 출력 없음.

외부 제공자 실연결, 전체 서버의 다른 패키지 및 클라이언트 race 시험은 이번 변경에서 재실행하지 않았다. 기본 회귀에서 분리된 `embedding_live` 시험은 선택하지 않았다.

## DOX pass

루트와 명세·서비스 DOX 체인을 다시 확인하고 측정 전 색인 준비 계약, SDD의 실패 정책·시험 전략과 부모 Child DOX Index를 갱신했다. 한국어 표현·맞춤법·Markdown 구조·경로를 검토했다. 기존 요구사항·용어·공개 도구 계약·저장 스키마·배포 구성이 바뀌지 않아 SRS·용어집·MCP·클라이언트 문서와 마이그레이션·환경 구성은 유지했다. 기존 IDE 설정 staging은 보존했다.
