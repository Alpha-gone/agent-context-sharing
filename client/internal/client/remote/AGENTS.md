# 클라이언트 원격 전송과 계약 캐시

## 목적

- 이 패키지는 원격 HTTP 시도·재시도·호출 상한과 발견·도구 목록의 메모리 캐시를 소유한다.

## 소유권

- 상위 `client/AGENTS.md`가 모듈 계약을, 서비스 SRS·SDD가 전송·인증·멱등성의 정본을 소유한다.
- `authorize`는 검증한 자격 증명과 공유 인가를 소유하고, `host`는 호스트 입력·정책·행위 에이전트 주입·오류 직렬화를 소유한다.

## 로컬 계약

- `NewHTTP`는 검증한 구성·인증 조정자와 HTTP `Source`를 조립하며 생성 시 외부 접근을 하지 않는다. `Close`는 호출 context를 취소하고 소유한 transport를 닫으며 주입 인증 조정자를 닫지 않는다.
- 최초 보호 도전·토큰 준비·재인가는 캐시 gate와 호출 slot 밖에서 수행한다. gate 안에서는 비대화형 주체 조회와 `Apply`만 사용한다. 조회 시작·반영 전에 주체를 대조하고 변경 오류 자체로 재인가·재전송하지 않는다.
- 하나의 논리적 호출이 호스트 context·원격 처리 잔여 시간·전송 재시도 횟수·최대 한 번의 인가를 공유한다. 인가 대기 중에는 원격 처리 시간 예산만 멈추고 `AUTH_TIMEOUT`으로 제한하며 호스트 deadline·취소는 유지한다. 재인가 후 남은 원격 시간을 재사용하고 예산을 초기화하지 않는다.
- `WithinCall`은 호스트 목록 준비와 도구 전송이 같은 호출 예산을 쓰게 한다. 제공한 context는 동기적인 중첩 호출에만 사용한다. 원격 요청은 클라이언트 빌드 판을 `clientInfo`에 포함하며 로그는 내부 생성 상관 ID·고정 결과 범주만 기록한다.
- 초기 익명 `tools/list`는 도전·인가 완료에서 끝내며 인증된 목록을 재전송해 버리지 않는다. 목록 조회·검증·캐시 반영은 정상 발견 경로에서만 수행한다. 인가 뒤 호출 slot을 얻으며 캐시 gate 대기도 8개 실행·128개 FIFO 대기 상한에 포함한다. 재인가 전에 slot을 반환한다.
- 원격 요청은 SDD의 단일 POST·JSON·헤더·요청별 metadata를 지킨다. redirect·세션·SSE·자동 본문 replay를 사용하지 않으며 시도마다 새 원격 UUIDv7·DPoP proof를 만든다.
- 검증된 발견에서만 쓰기 멱등성을 협상한다. 쓰기 8종의 호출별 키는 24시간 안의 재시도·재인가에서만 재사용하고 읽기·비협상 쓰기에 보내지 않는다.
- 본문 reader와 connection trace로 전달 전 실패를 확인한다. 불명확하면 전달 가능성을 인정하며 불확실 쓰기는 SDD에 따라 `ErrIndeterminate`로 분류한다. 전송 재시도는 일시적 실패에만 최대 3회다.
- 요청 256 KiB, 전송·gzip 해제 본문 각각 32 MiB를 제한한다. JSON-RPC 외피·ID·HTTP 상태를 검증한 뒤 갱신 헤더를 적용하며 취소된 응답은 폐기한다. 완전한 오류·도메인 오류·계약 위반·크기 초과를 재시도하지 않는다.
- `ProtocolError.Raw`는 검증된 원격 code·message·data를 호스트 전달용으로만 제공한다. 기본 오류·디버그 표현에 원격 본문·URL·자격 증명을 내보내지 않는다.

## 작업 지침

- 전송과 호스트 직렬화·`serve` 조립의 개발 단계를 구분한다. 비공개 `httpSource`를 우회해 공개 정책이나 호스트 검증을 구현하지 않는다.
- 원격 도구 지문·TTL·인증 범위와 입력 계약은 기존 `contract`·캐시 검증을 재사용한다.

## 검증

- 클라이언트 전체 race, 전송 실패 표, 재인가 예산·키·새 ID/proof, FIFO 상한·취소·크기 경계를 검증한다.
- 주입 transport 시험과 실제 로컬 TLS·loopback 시험을 실제 서비스 서버·외부 계정·시스템 브라우저·WSL2·호스트 종단 간 검증과 구분해 보고한다.
