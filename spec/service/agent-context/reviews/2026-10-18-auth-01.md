## 발견 사항과 반영

기존 가입의 문자 수 검사는 `utf8.RuneCountInString`만 사용하여 잘못된 UTF-8 바이트를 대체 문자로 세고 통과시켰다. 유효한 UTF-8인지 먼저 검사하도록 보완했다. 실제 U+FFFD 코드 포인트는 허용하며 Unicode 코드 포인트 기준 8~128자라는 기존 계약을 유지한다. 로그인 대조에 가입 정책의 조기 거부를 추가하지 않아 레거시 대조와 없는 계정의 더미 작업 경계를 유지했다.

현재 SHA-256·padding 없는 표준 Base64·bcrypt 저장 경로와 레거시 전환은 새 합성 표본으로 검증했다. 시험 실패 메시지 두 곳에서 저장 해시를 출력하던 부분을 제거했다. 비밀번호·저장 해시·더미 값은 새 시험의 이름·실패 메시지·기록에 출력하지 않는다.

## 새 검증 근거

- 계정 입력 18개 하위 시험: 아이디 3/32자·너무 짧음/김·대문자·한글·기호·공백/개행, 비밀번호 빈 값·7/8/128/129개 코드 포인트·한글·이모지·결합 문자·U+FFFD와 잘못된 UTF-8 네 종류를 검사했다. 잘못된 입력에는 해시 생성·계정 저장이 없고 작업 자리가 남지 않는다. 정상 계정의 UUIDv7·아이디 보존·현재 UTC 생성 시각·v2 접두사·구성한 bcrypt 비용과 인증 성공을 확인했다.
- 현재 저장 형식 4개 하위 시험: 72바이트 뒤만 다른 입력과 128개 이모지를 구분했다. SHA-256 결과에 NUL이 있는 합성 비밀번호를 만들고 독립적으로 구성한 43바이트 표준 Base64로 실제 bcrypt 대조를 통과했다. 정규화 전후가 다른 Unicode 입력도 자동으로 같은 비밀번호로 취급하지 않는다.
- 레거시 형식 2개 하위 시험: 직접 bcrypt와 `bcrypt-sha256-v1:`를 새로 생성했다. 나머지 3자리를 점유한 상태에서 실제 bcrypt 대조·현재 형식 생성·조건부 갱신이 모두 네 번째 자리 하나를 유지한다. 잘못된 비밀번호에는 생성·갱신이 없고 성공 때만 같은 계정이 v2로 전환되며 자리를 반환한다. 원시 다이제스트 표본은 NUL도 포함한다.
- 잘못된 저장 형식 7개 하위 시험: 빈 값·잘린 직접 bcrypt·현재/이전 접두사만 있는 값·잘못된 bcrypt 본문·알 수 없는 형식은 인증과 재해시·갱신 없이 거부하고 자리를 반환한다.
