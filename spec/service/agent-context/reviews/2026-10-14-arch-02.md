# ARCH-02 논리 모델 모듈 시험

## 범위와 결과

2026-10-14에 [ARCH-02](../development-plan/architecture.md#arch-02)의 논리 모델을 구현하고 해당 모듈 시험을 수행했다. 입력은 [컨텍스트 모델](../SRS.md#컨텍스트-모델), [관리 연산](../SRS.md#컨텍스트-관리-연산-요구사항), [사건 모델](../SRS.md#사건-모델), [그래프 속성](../SRS.md#컨텍스트-그래프-속성)과 채택된 SDD다. 작업 시작 커밋은 `f9ec4818f32fa9e6c1cc34899aa0669118af8e19`이며 실제 작업 브랜치는 `feat/new-implementation-architecture`다. 브랜치에 upstream이 없어 원격 대비 상태는 확인할 수 없다.

기존 모델·시험의 존재와 과거 측정을 완료 근거로 승계하지 않고 현재 계약을 대조한 구현 변경과 이번 모듈 시험으로 판정했다.

## 구현과 소유 경계

- [id.go](../../../../internal/model/id.go)는 Go 1.27.1 표준 `uuid.NewV7`·`Parse`·`String`·`Compare`를 사용한다. 기존 ID의 배열 표현·NewID 반환 형태·표준/compact 입력 범위를 유지하고 version·variant·UTC 밀리초 시각을 검증한다. 자체 난수 생성·hex 해석 코드는 제거했다.
- [context.go](../../../../internal/model/context.go)는 공통 9개 속성, 계층별 필수·조건부 속성, 파생 근거·선택 대체 참조, 빈 본문·UTF-8·U+0000, UTC와 시간 구간을 검증한다. `ValidateProperties`는 참조 조립 전 속성 검증이고 `Validate`는 필수 참조까지 포함한다. 파생의 근거 집합·대체 참조는 사용자 갱신과 시스템 근거 무효 표시 모두에서 불변이다. 참조 순서 변경은 같은 집합으로 취급한다.
- [validation.go](../../../../internal/model/validation.go)는 그래프 이름·설명 갱신과 불변/시스템 속성 보호, 저장소가 전달한 근거·대체 대상의 소속·계층·식별자 판정을 제공한다. 실제 존재 조회와 경로 탐색을 모델에서 수행하지 않는다.
- [relation.go](../../../../internal/model/relation.go)는 관계 자체의 속성 검증과 전달된 양 끝 사건의 검증을 구분한다. 시간 순서·부분 포함·대칭 정규화와 순환 거부를 확인하며, 순환 함수는 저장소가 조회한 경로의 존재 여부만 받는다. 폐기 관계에는 과거 확정 정보를 보존할 수 있다.
- [operation.go](../../../../internal/model/operation.go)는 다섯 관리 연산, 적용/거부 결과와 실행 기록을 정의한다. 컨텍스트와 관계 대상의 배타성·판 번호·주체·판단 입력·UTC·거부 사유를 검증한다.
- [오류](../../../../internal/model/errors.go)와 [FieldError](../../../../internal/model/field_error.go)는 대상 부재·상태 위반·현재 판을 담는 충돌·위반 필드와 원래 오류의 판별을 지원한다. 저장소는 기존 이름을 alias로 유지한다.

참조 개수·문자 길이의 입력 상한은 SDD의 MCP 입력 계층이 소유한다. 모델은 필수 참조의 최소 개수·식별자·구조를 강제하며 같은 설정값을 복제하지 않는다. 사건 구성원의 실제 조회·파생 근거의 실재성·순환 경로는 저장소가 담당한다.

기존 저장소 호출부는 참조를 조립하기 전 속성 검증과 조립 뒤 전체 검증으로 정합화했다. 생성 입력 검증에서 별도 `derivedFrom`을 복사해 적용하므로 호출자의 속성 객체를 변형하지 않는다. 모델의 저장소 상태 검증 도우미를 신규 데이터/수명주기 경로에 연결하고 SUPERSEDES의 저장·응답 조립을 인수하는 작업은 해당 후속 계획이 담당한다.

## 새 실행 증거

Go 1.27.1 SDK `/Users/alphagone/sdk/go1.27.1/bin/go`를 사용했다. 시험 작성·보강·실행은 ARCH-02 구현이 준비된 모듈 시험 시점에 수행했다.

```sh
GOTOOLCHAIN=local go test -count=1 -race -cover -json ./internal/model
GO_BINARY=/Users/alphagone/sdk/go1.27.1/bin/go sh ./check-go.sh
go list -f '{{join .Imports "\n"}}' ./internal/model
```

- 모델 시험·하위 시험 145건 통과, 실패·건너뜀 0건, 종료 코드 0. race 검사 통과, 문장 커버리지 88.6%.

- 공통 스크립트의 의존성 체크섬·최소 실행 파일 빌드·`go build -mod=readonly ./...`·`go vet -mod=readonly ./...`·같은 SDK의 `gofmt -l .` 통과. 종료 코드 0.

- 변경 문서의 상대 링크·앵커 90개·코드 블록·새 기록의 표 구조와 `git diff --check` 통과. 요구사항 184건·SRS/SDD/용어집 보존과 작업 124개 중 TRACE-01·ARCH-01·ARCH-02만 완료임을 확인했다.

실제 DB·저장소 통합 시험은 실행하지 않았다. 저장소 호출부 변경은 빌드·정적 분석으로 확인했으며 DB·연산·격리·경합의 분야별 인수 완료를 뜻하지 않는다. 원격 CI·MCP·호스트·외부 제공자 실행도 이번 범위에 포함하지 않았다.

## 완료 판정과 DOX pass

SRS·SDD·용어의 확정 계약을 변경하지 않았으며 기존 운영 Compose·IDE 파일을 보존했다. 다음 항목은 [ARCH-03](../development-plan/architecture.md#arch-03)의 패키지 경계·주입 인터페이스다.
