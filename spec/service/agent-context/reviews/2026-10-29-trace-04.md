# TRACE-04 요구사항별 실행 상태와 작업 완료 근거

## 범위와 판정

2026-10-29, TEST-09 커밋 `2a1086093bfaa03b6ca729e2ac950ed789ee6356`을 기준으로 현재 SRS 184건·작업 124개의 증거 연결을 대조했다. 이 문서는 실행 상태의 검토 기록이며 SRS·설계 추적표나 분야별 계획의 소유권을 대신하지 않는다. 코드·명세·기본값·지원 범위를 변경하거나 제품 시험을 새로 실행하지 않았다.

개별 신규 검토가 있는 121개 작업과 TRACE-01의 사용자 기준 확정을 연결했다. TRACE-04의 문서 대조까지 123개 완료, TRACE-05는 미착수다. **작업의 구현/분야 인수 완료와 요구사항의 모든 실환경 실증 완료는 다르다.** 아래 표는 코드/서버 계약·실제 호스트·파일·정량 효과·운영을 별도 열로 유지하며 184건 전체 충족이라는 종합 합격을 선언하지 않는다. 필수 모듈 인수의 새 관찰 근거가 없는 작업을 완료로 추가하지 않았다.

TRACE-01이 배제한 2026-10-14 이전 구현·측정으로 신규 완료를 대신하지 않았다. 이후의 모듈 검토와 TEST-09의 새 전체 실행을 함께 연결한다. 원기록의 당시 실패·수정·최종 결과·버전·표본·명령은 덮어쓰지 않으며 후속 시험으로 해소된 범위도 시점을 나눠 읽는다. 임시 로그가 영구 보관된다고 가정하지 않고 저장소의 커밋된 검토를 지속 근거로 둔다. `.personal` 자료와 자격 증명 원문은 입력·산출물에 포함하지 않았다.

## 증거 묶음과 해석

### R

코드/서버 계약의 최신 공통 근거는 [TEST-09](2026-10-28-test-09.md#최종-판정과-자원-정리)다. Go 1.27.1·macOS/arm64, PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6의 고정 Linux/arm64 이미지에서 vector 768/128·halfvec 768 DB를 정식 적용했다. 같은 접속 정보와 필수 DB·CLI·브라우저 조건으로 `go test -race -count=1 -p 1 -json -timeout=30m ./...`을 두 번 연속 수행했다. 각 6,422건(최상위 1,146건) 통과, 실패 0건이며 1,318.572초·1,594.189초다. 계정·전체 서명 키·스키마 이력 지문이 최초 기준과 같았다. 현재 커밋의 수정 Go 파일 SHA-256도 당시 검증본과 같다.

사례 식별자는 `(package, Test)`를 사용한다. 패키지가 다른 같은 이름의 시험을 하나로 접지 않았고 동적 UUID가 든 하위 사례명 48개/회차는 최상위 시험·개수로 대조했다. 회차·모듈·운영 스크립트의 반복 통과를 서로 더해 고유 시험 수를 늘리지 않았다. 일반 실행의 TestOPS07PhysicalRecovery·TestOPS08Transition 두 건은 O의 실제 실행과 분리한다. cmd/migrate의 시험 파일 부재는 내부 migrate 시험·실제 적용·빌드와 구분한다.

작업 표의 현재 회귀 연결은 함수/파일/명령을 대조한 패키지 또는 전용 실행 근거를 가리킨다. 하나의 함수나 패키지 개수가 작업 전체 완료 기준을 대신하지 않는다. 작업별 전체 표본·최초 실패·최종 합격은 각 원기록이 소유한다.

### S

### H

### B

[TEST-06 조정 범위 인수](2026-10-28-test-06-completion.md)·[선택 강조](2026-10-28-test-06-selection.md)와 TEST-09의 실제 Chrome 156.0.8078.48·Node 26.11.1에 연결한다. 각 회차 WEB09 요약의 20개 시나리오와 스크린샷/접근성 트리 18개 산출물을 대조했다. test06.json의 5개는 전체 중 부분 집합이다. 사용자 화면 정상 확인과 기존 자동 키보드·DOM/접근성 트리 근거를 유지한다. **추가 수동 키보드·실제 VoiceOver 음성은 사용자가 제외한 미실행**이며 통과로 표시하지 않는다. 확인하지 않은 Safari 판·모든 화면 조합으로 확대하지 않는다. 이 범위 조정으로 SRS의 키보드/접근성 구현 계약을 삭제하지 않았다.

### F

## 요구사항별 실행 상태

SRS·설계 추적·기존 개발 대응의 FR 171건/NFR 13건을 각 한 행으로 유지한다. 각 행의 마지막 열은 원래 구현/인수 작업의 합집합이며 해당 작업의 개별 새 검토로 직접 연결한다. 주 책임 SDD와 구현/인수의 역할 구분은 [기존 대응표](../development-plan/traceability.md#요구사항별-개발인수-작업-대응)를 그대로 유지한다.

R은 코드/서버 계약의 관찰 범위, R+Q는 평가 기구/합성 분기까지의 범위다. H·B·F·O는 위 제한된 실행 근거가 해당 행에 관련됨을 뜻하며 실환경 전면 충족을 뜻하지 않는다. Q는 실환경 효과 대기다. `—`는 해당 열을 이 행의 독립 판정 근거로 사용하지 않았다는 뜻이며 시스템 전체의 운영/외부 인수가 완료됐다는 뜻이 아니다. B 행의 제외된 수동 관찰과 H/F/O의 미검증 조합은 원기록의 한계를 함께 적용한다.
