# 클라이언트 불확정 쓰기·호스트 ID·진단 응답 검증

## 범위와 처리 결과

GitHub 이슈 [#84](https://github.com/Alpha-gone/agent-context-sharing/issues/84)의 세 결함을 `fix/issue-84-client-completion-and-host-id`에서 수정했다. SDD의 전송 재시도·호스트 입출력·진단 경계를 먼저 구체화하고 해당 구현과 회귀 시험을 동기화했다.

- 이전 시도에서 응답을 잃은 쓰기는 이후 인증 거부, proof·nonce 오류, 잘못된 응답, 원격 JSON-RPC 오류와 갱신 단계의 자원 오류로 끝나더라도 `client_indeterminate`·`retryable=false`를 우선한다. 읽기·전달 전 실패와 이전 불확정 전송이 없는 완전한 오류 응답의 분류는 유지한다. 성공·도메인 결과를 확보하면 원문을 보존하며 같은 논리적 쓰기의 멱등성 키를 바꾸지 않는다.
- 호스트 요청을 SDK의 숫자 ID 디코더 대신 `encoding/json/v2`로 읽는다. 정확히 표현 가능한 작은 정수는 SDK 정수 ID를 유지하고 큰 정수는 충돌 없는 내부 문자열 키로 보관한 뒤 출력에서 숫자 토큰으로 복원한다. 내부 접두사와 같은 호스트 문자열은 별도로 구분한다. 소수·지수 표기, 명시적 `null`과 기타 ID 형식은 Invalid Request로 거부한다. ID 생략은 기존 알림 동작을 유지하며 취소와 초과 입력의 ID 회수에도 같은 검증을 적용한다.
- 진단 정상 응답은 `Content-Length: 0`을 명시하고 헤더를 flush한 뒤 성공을 게시한다. 전송 실패는 인가 오류로 반환한다. 인가 callback의 기존 정리 계약과 비밀 없는 진단 경로는 유지한다.

## 수정 전 재현

첫 쓰기 본문 전송 뒤 응답을 잃고 두 번째 시도가 인증·프로토콜·자원 오류로 끝나는 여섯 경우에서 불확정 오류 대신 다른 코드가 반환됐다. `9007199254740993`과 음수 ID는 인접한 값으로 바뀌었고 `9223372036854775808`은 다른 정수로 잘렸으며, 소수 ID는 정수로 응답하고 명시적 `null` 요청은 응답 없이 버렸다. 실제 진단 연결의 쓰기를 멈춘 회귀에서는 응답 전송 완료 전에 성공이 반환됐다. 이 실패 실행은 통과 결과에 포함하지 않았다.

## 검증 결과

IntelliJ IDEA에 설치된 Go 1.27.1 SDK로 검증했다.

- 쓰기·읽기 × 전달 전·후 × 종료 오류·성공·도메인 결과의 전송 회귀와 호스트 ID·취소·중복 lifecycle 회귀: race 검사 10회 통과.
- 실제 로컬 loopback 연결의 응답 쓰기를 멈춰 전송 완료 전 성공 게시가 없음을 확인했다. 전송 해제 뒤 완전한 빈 HTTP 응답을 받았으며, 쓰기 실패를 주입한 진단도 성공으로 보고하지 않았다. 두 진단 회귀를 race 검사로 10회 통과했다.
- 발견·초기 연결·ping·목록·호출의 큰 정수·음수·문자열 ID 보존과 잘못된 ID 거부, 인접한 큰 정수·숫자와 문자열·내부 접두사 문자열의 동시 접수, 정확한 큰 ID 취소, 초과 입력의 ID 회수·프레임 복구를 확인했다. 기존 입력·출력 상한·EOF·신호·출력 대기 취소·ID 재사용 시험도 유지했다.
- 클라이언트 전체 `go test -race -count=1 -json ./...`: 테스트 항목 554개 통과, 실패 0개, 테스트 항목 건너뛰기 0개. 테스트 파일 없는 패키지 이벤트와 개별 테스트를 구분했다.
- 서버·클라이언트 각각 `go build ./...`, `go vet ./...`: 통과. 서버 `TestToolManifestMatchesClient`와 `cmd/server` 전체 race 검사: 통과.
- `gofmt -l .`과 `git diff --check`: 통과. 한국어 표현·맞춤법·Markdown 구조와 상대 링크를 점검했다.

서버 추가 회귀의 최초 실행은 샌드박스의 로컬 포트 bind 제한으로 실패했다. 같은 명령을 허용된 환경에서 다시 실행해 통과했으며 환경 차단 실행을 검증 성공으로 기록하지 않았다.

## DOX pass와 제한

루트→`client/`→`host`·`remote`·`authorize`와 루트→`spec/`→`service/`→`agent-context-client/`의 계약을 확인했다. 세 패키지의 소유 DOX와 SDD·개발 계획·요청 기록을 갱신했다. 부모·서비스 DOX와 Child DOX Index는 목적·소유권·경로가 바뀌지 않아 유지했다. 기존 `FR-AGENT_CONTEXT_CLIENT-016`·`019`·`031` 등의 계약을 복원하므로 SRS·공개 도구 manifest·용어집·외부 근거·모듈 의존성·배포 구성은 변경하지 않았다. 개발 계획의 남은 공식 출시 판정도 유지했다.

이번 검증은 모의 원격 HTTP, 실제 로컬 loopback과 stdio 경계에 한정한다. DB·실제 서비스의 `client_live`, 시스템 브라우저·사용자 로그인·WSL2·지원 호스트·공식 conformance와 운영 배포는 실행하지 않았다. 기존 `.env`·개발 DB·볼륨·사용자 IDE staging은 변경하지 않았다. 로컬 구현과 검증 기록이며 커밋·푸시·PR 생성·이슈 직접 종료는 수행하지 않았다.

세션 그래프 저장 요청은 응답 지연으로 완료 여부를 확인하지 못했다. 검증 결과는 이 문서에 보존한다.
