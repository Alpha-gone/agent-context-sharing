# 홉 조회·적재 작업량 보호 검토

## 대상과 계약

- 분석일: 2026-10-10, 기준 `dev`의 `597edf6`, 관련 [#110](https://github.com/Alpha-gone/agent-context-sharing/issues/110).
- 범위: 작은 응답 상한에서 고연결 노드의 전체 이웃 본문·간선 적재 비용. 운영 데이터·관계 삭제, 플랜 값·MCP 스키마·배포 구성·의존성 변경은 제외했다.
- 기존 `hopNeighbors`는 홉마다 이웃 전체의 정점 본문을 읽고 메모리에 담은 뒤 결과 상한을 적용했다. 응답 상한은 내부 조회·메모리 상한이 아니었다.
- SRS 「홉 범위 조회」와 SDD 「고연결 노드의 조회·적재 보호」에 응답 상한·본문 적재·DB 작업 중단의 경계를 명시했다. 정상 부분 응답의 간선 완전성과 절단 표시는 유지한다.

## 구현과 비교 선택

- 양수 상한은 깊이·label별 미방문 활성 이웃의 식별자만 읽는다. 동일 이웃의 최초 기준 정점 식별자와 이웃 식별자를 기준으로 정렬해 기존 발견 순서를 유지하고, 남은 자리와 초과 확인용 한 행까지만 반환한다.
- AGE 집계에 정점 속성을 바로 사용하면 DB가 정점 전체를 정렬했다. 단순 `WITH`나 SQL 서브쿼리는 실행 계획에서 같은 비용이 남아, 식별자만 담는 `MATERIALIZED` CTE와 SQL 집계·`C` 정렬을 사용했다. 탐색 자체는 openCypher로 수행한다.
- 선택한 새 노드의 본문만 묶음 적재하고 반환 노드끼리의 요청 label·확정 상태 간선을 별도로 조회한다. 마지막 깊이의 외부 이웃은 읽지 않으며 초과가 확인되면 후보 확장을 끝내고 내부 간선 조립을 완료한다.
- 양수 상한의 방문 집합·후보 메모리는 O(L), 내부 간선은 최악 O(L²)이다. `limit=0`은 기존 한도 없음으로 전체 이웃 구현을 유지하므로 유한 본문·노드 메모리 상한을 주장하지 않는다.
- 두 공개 홉 진입점은 30초 조회 예산과 호출자의 더 짧은 취소·마감을 적용한다. 중단하면 오류와 빈 결과를 반환하며 불완전한 간선을 정상 부분 응답으로 숨기지 않는다. 종료·스냅숏·연결 예약 계약은 유지하며 DB 취소·정리가 정확히 30초에 완료된다는 실시간 보장은 하지 않는다.

## 측정 조건과 결과

- Go 1.27.1, darwin/arm64, Apple M4 Pro, 실제 개발 PostgreSQL 18.6·Apache AGE 1.8.0. 이미지 기준은 `apache/age:release_PG18_1.8.0@sha256:47a0b054c3663a3e64a25fc0c5a982f1b58348019274b326a691cdf77f78eb58`이다.
- 전용 시험 DB에 정식 `001_init` 마이그레이션을 적용했다. 표본은 원천 허브 하나와 각각 허브를 근거로 삼는 파생 1,000개 또는 20,000개다. 파생 본문은 1,200자·UTF-8 2,800바이트다. 저장소 속성·참조 방향은 실제 형식을 쓰지만 쓰기 정책·색인 성능 표본은 아니며 탐색 비용을 분리하려고 정점·참조를 묶음 생성했다.
- 한 표본에 변경 전 전체 적재 기준선과 최종 식별자 중심 구현을 실행한다. 방향 `in`, 필터 `derived_from`, 1홉, 결과 상한 2·10, 각 5회이며 동일 조건의 평균 지연·Go 할당량과 읽은 행·본문량을 비교한다. 본문 바이트는 선택 정점의 `body` UTF-8 길이 합이며 전체 PostgreSQL 전송량·RSS·최대 힙이 아니다. 질의 수 지표는 확장만 세므로 최종 본문·간선·참조·접근 기록 왕복을 포함하지 않는다.
- 최종 반복 측정 결과는 다음과 같다. 지연과 할당량은 호출당 평균이며 전체 반환 그래프 조립을 포함한다.

| 이웃 수 / 상한 | 전체 적재 지연 → 개선 지연 | Go 할당 바이트 → 개선 | 본문 행 → 개선 | 본문 바이트 → 개선 |
|---|---|---|---|---|
| 1,000 / 2 | 30.676 → 7.514 ms | 11,712,102 → 31,947 | 1,000 → 1 | 2,800,000 → 2,800 |
| 1,000 / 10 | 26.866 → 8.624 ms | 11,735,212 → 153,739 | 1,000 → 9 | 2,800,000 → 25,200 |
| 20,000 / 2 | 496.358 → 116.718 ms | 240,834,756 → 33,932 | 20,000 → 1 | 56,000,000 → 2,800 |
| 20,000 / 10 | 491.659 → 107.493 ms | 240,856,179 → 154,888 | 20,000 → 9 | 56,000,000 → 25,200 |

- 개선 구현의 후보 식별자 행은 상한 2에서 2행, 상한 10에서 10행이다. 읽은 간선 행은 전체 적재의 이웃 수에서 각각 1·9행으로 줄었다. 확장 질의는 2회→1회지만 최종 조립 질의는 별도이므로 전체 왕복 감소를 주장하지 않는다.
- 같은 2만 이웃·상한 2 후보 질의의 `EXPLAIN (ANALYZE, BUFFERS, TIMING OFF)`에서 전체 적재는 20,000행 반환, 공유 버퍼 hit 130,051, 임시 블록 read/write 1,441/1,444, 외부 병합 정렬 11,528 kB, 실행 247.329 ms였다. 개선은 2행 반환, 공유 버퍼 hit 60,346, 임시 블록 read/write 없음, 식별자 집계와 25 kB top-N 정렬, 실행 99.079 ms였다. 내부 간선 스캔과 이웃 정점 조회는 여전히 각각 20,000행이다. 실행 계획은 통계·표본에 따라 달라질 수 있다.

## 검증과 복구 기록

- 기존 방향·상한·AGE 경로 후보 동등성 검사에서 처음 발견한 빈 간선의 nil/빈 슬라이스 차이를 수정한 뒤 관련 검사가 통과했다.
- 최종 코드로 `TEST_DATABASE_REQUIRED=1`, `go test -json -count=1 -race -p 1 ./internal/store ./internal/search ./internal/mcp ./internal/web ./cmd/server`를 실행했다. 테스트·하위 테스트 694건이 실패·건너뜀 없이 통과했다. 900개 요청 조합의 기준선 대조, 2만 이웃의 작은 상한·취소·실행 계획, DB 잠금 대기의 마감과 후속 연결 사용 검사를 포함한다.
- 양쪽 모듈의 `go build ./...`, `go vet ./...`와 루트 `gofmt -l .`, `git diff --check`를 통과했다. 서버 전체 패키지와 클라이언트 전체 race는 실행하지 않았다.
- 대형 표본을 남긴 첫 관련 전체 race 실행은 AGE 경로 비교가 장시간 실행되어 중단했다. 원격 운영 데이터 문제가 아니라 전용 DB의 표본 간섭 가능성으로 분리했다. 중단한 실행은 통과로 보고하지 않는다.
- 표본 정리에 사용한 AGE 정점별 `DETACH DELETE` 대신 시험이 생성한 graph_id의 참조→정점→메타데이터를 한 트랜잭션에서 묶음 정리하도록 보완했다. 잘못된 agtype 비교로 발생한 SQLSTATE 22P02는 기존 텍스트 속성 접근 연산자로 수정했고 최종 시험에서 정리까지 통과했다. 시험의 정확한 소유 범위만 대상으로 하며 운영 삭제 경로에 적용하지 않는다. 사용자 재개 시 이전 실행 로그가 중간에 끝났고 실행 프로세스가 없음을 확인했으므로 완료 상태를 추정하지 않고 재실행했다.

## 미해결 결함과 한계

- DB 후보 단계는 여전히 해당 허브의 간선을 스캔한다. 노드 LIMIT을 스캔 행 수의 절대 상한으로 해석하지 않으며 30초 조회 중단 정책으로 별도 보호한다. 표본보다 큰 그래프의 DB CPU·버퍼·일시적 디스크 비용과 운영 부하는 미측정이다.
- 운영 배포·외부 API·실제 브라우저·클라이언트 전체 race는 실행하지 않는다. 표본 평균을 운영 SLA나 통계적 유의성으로 일반화하지 않는다.
