# 서버 관계 추론 개발 계획

[전체 계획](../DEVELOPMENT_PLAN.md) · [기준 SDD](../sdd/relation-inference.md) · [작업 추적](traceability.md)

## 목표와 구현 범위

#311의 서버 관계 추론을 구현하고 모델별 비교로 자동 확정 활성화 여부를 판정한다. 기존 124개 작업과 LIFE-10의 인수 이력을 승계하지 않으며 모든 작업은 미착수에서 시작한다.

- 설계 입력: [처리 흐름](../sdd/relation-inference.md#처리-흐름), [유형별 정책](../sdd/relation-inference.md#관계-유형별-정책), [후보 검색](../sdd/relation-inference.md#후보-검색), [판정 계약](../sdd/relation-inference.md#판정-계약), [반영 검증](../sdd/relation-inference.md#반영-검증), [추론 작업 큐](../sdd/relation-inference.md#추론-작업-큐), [모델 비교](../sdd/evaluation.md#관계-추론-모델-비교).
- 예정 구현 영역: `internal/model`의 관계 속성·판정 값, `internal/store`의 큐·판정 기록·반영 트랜잭션, 새 `internal/relinfer`, `cmd/server`·`cmd/indexer` 조립, `internal/mcp` 응답·안내, `cmd/eval` 비교 모드, `migrations/`.
- 다른 분야와의 경계: 관계 상태·잠금은 수명주기, 구성 검증은 운영, 진단 필드는 관측성, 비교 실행 공통 계약은 평가 계획이 소유한다.
- 실행 제한: 실제 제공자 호출·비용 발생은 RINF-06에서만 하며 사용자가 제공자·예산을 승인한 뒤 수행한다. 기존 운영 DB에 migration을 적용하지 않는다.

## 개발 작업

### RINF-01

- [ ] **관계 속성·판정 주체와 추론 저장 스키마를 추가한다.**
- 선행: [LIFE-10](context-lifecycle.md#life-10), [DATA-10](data.md#data-10).

1. 모델에 `proposed_by=inference`, `confirmed_source`, `inference_decision_id`와 조건부 필수 규칙을 추가하고 `operation_log`에 판정 주체 열을 더한다.
2. 기존 관계·관리 기록은 재작성하지 않고 판정 주체 없음을 `agent`로 읽는다. 불변식 감사 규칙에 새 조건부 필수를 반영한다.
3. `relation_inference_task`·`relation_inference_run`·`relation_inference_decision` 테이블과 정리·조회 인덱스를 새 migration으로 추가한다.

- 산출물: 모델·migration·저장 API와 이전 데이터 호환 표본.
- 완료 기준: 별도 합성 DB에서 신규/반복 적용과 기존 관계·기록의 판정 주체 해석이 맞고 에이전트 확정 경로의 결과가 바뀌지 않는다.

### RINF-02

- [ ] **추론 작업 등록·확보·재시도와 구성 검증을 구현한다.**
- 선행: [RINF-01](#rinf-01), [IDX-08](indexing.md#idx-08), [OPS-09](operations.md#ops-09).

1. 사건 생성·구성원/시간/본문 갱신·복구 트랜잭션에서 모드가 `off`가 아닐 때만 upsert 등록한다.
2. `SKIP LOCKED` 확보·리스·세대 대조·백오프·출력 위반 재시도·`failed`와 제공자 확보 차단을 색인 큐와 같은 계약으로 구현한다.
3. [서버 관계 추론 구성](../sdd/operations.md#서버-관계-추론-구성)의 키 검증, 허용 목록·두 환경 예시·실행 안내를 갱신한다.

- 산출물: 큐 저장 API·작업자 회차·구성 검증과 경합 표본.
- 완료 기준: `off`에서 작업·제공자가 없고, 등록 실패가 사건 저장과 함께 롤백되며, 중복 작업자·리스 만료·재등록에서 한 세대만 결과를 반영한다.

### RINF-03

- [ ] **제한된 후보 검색과 판정 입력 생성을 구현한다.**
- 선행: [RINF-02](#rinf-02), [SEARCH-10](search.md#search-10).

1. 의미·키워드·구성원·규칙·대화 채널의 사건 한정 후보와 순위 역수 합, 후보·문자 상한을 구현한다.
2. 정해진 정체성·같은 판/프로필로 판정한 쌍·비활성 사건을 제외하고 색인 대기·실패 시 의미 채널을 생략한다.
3. 지역 별칭·구분된 데이터 영역의 판정 입력과 추론 프로필 지문을 만든다.

- 산출물: 후보 조합기·입력 생성기와 채널별 기여 기록.
- 완료 기준: 그래프 전체나 원천·파생 본문이 입력에 들어가지 않고 최근 집합 밖 관련 사건이 후보가 될 수 있으며 같은 입력은 같은 지문을 만든다.

### RINF-04

- [ ] **판정 어댑터 계약·출력 검증·반영 트랜잭션을 구현한다.**
- 선행: [RINF-03](#rinf-03), [LIFE-07](context-lifecycle.md#life-07).

1. 공통 판정 인터페이스와 결정적 대역 어댑터, 출력 스키마·별칭·유형·방향·근거 인용 검증을 구현한다.
2. 그래프 행 잠금 뒤 세대·판·활성·위임 등급·기존 관계 제약·정체성 상태·모드/유형/지문 정책을 다시 검사하고 판정별로 제안·확정·거부를 기록한다.
3. 관계 생성·전이, 판정 기록, 작업 삭제, 내용 판 증가, 판정 주체가 `inference`인 관리 기록을 한 커밋으로 묶는다.

- 산출물: `relinfer` 패키지·반영 저장 API와 정책·경합 표본.
- 완료 기준: [서버 관계 추론 시험](../sdd/testing.md#서버-관계-추론-시험)의 출력 검증·반영·경합 항목이 대역으로 통과하고 실제 제공자 어댑터를 추가해도 검증·저장 코드가 바뀌지 않는다.

### RINF-05

- [ ] **MCP 노출·진단·조립을 연결하고 분야 통합 시험을 수행한다.**
- 선행: [RINF-04](#rinf-04), [MCP-09](mcp.md#mcp-09), [OBS-08](observability.md#obs-08).

1. `relation_list`의 출처 필드와 모드별 instructions 한 문장을 추가하고 공개 도구 정의 크기 예산을 다시 확인한다.
2. 색인·관리 종류의 `relation_inference_` 단계와 허용 필드, 지표를 추가한다.
3. 서버·분리 색인 실행기의 작업자 배치와 종료 정리를 연결한다.

- 산출물: 조립·MCP·진단 변경과 분야 통합 시험 기록.
- 완료 기준: 별도 합성 DB에서 사건 저장부터 대역 판정·반영·조회까지 에이전트의 관계 탐색 없이 확인되고, 격리·권한·로그 금지 필드 검사와 build/vet/gofmt가 통과한다.

### RINF-06

- [ ] **모델 비교를 실행하고 자동 확정 활성화 여부를 판정한다.**
- 선행: [RINF-05](#rinf-05), [EVAL-13](evaluation.md#eval-13), `TBD-AGENT_CONTEXT-065`의 합격선 결정.

1. 비교 표본·고정 판정 입력·후보 검색 정답을 준비하고 작은 모델을 포함한 프로필 목록과 단가 판을 manifest에 고정한다.
2. 프로필별 판정 지표와 후보 검색 지표, 기존 에이전트 방식과의 전체 흐름·총비용을 측정한다.
3. 합격 프로필이 있으면 채택 근거를 기록하고 운영 구성 변경을 제안한다. 없으면 자동 확정을 활성화하지 않고 결과와 남은 조건을 기록한다.

- 산출물: 비교 manifest·결과 묶음·검토 기록과 `TBD-AGENT_CONTEXT-065`의 갱신안.
- 완료 기준: 같은 입력의 재실행으로 결과를 재현할 수 있고, 비용 이전과 총비용 절감이 구분되어 보고되며, 미측정 항목이 통과로 표시되지 않는다.
