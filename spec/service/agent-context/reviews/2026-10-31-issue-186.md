# #186 그래프 상세 시작점 상한·스냅숏 검토

- 대상: [이슈 #186](https://github.com/Alpha-gone/agent-context-sharing/issues/186).
- 기준: `dev`의 `55b39f2`, 브랜치 `fix/186-graph-visualization-truncation`.

## 항목별 처리

| 항목 | 처리 | 내용 |
|---|---|---|
| 시작점 상한 초과의 절단 누락 | 처리 | 결과 노드 수 상한이 있으면 시작점을 상한보다 한 개 더 읽는다. 기존 홉 탐색이 초과 시작점을 `0홉` 경계의 절단으로 표시하므로 시작점끼리 연결되지 않아도 화면에 절단 안내가 남는다. 상한과 같은 개수는 절단이 아니다. 정수 최댓값 상한은 더 읽지 않는다. |
| 시작점 조회와 홉 읽기의 스냅숏 분리 | 처리 | 시작점 목록·본문 조회를 홉 확장과 같은 읽기 전용 REPEATABLE READ 경계 안에서 수행한다. 시작점 조회 직후 폐기가 커밋되어도 조회 시점 상태를 반환하며 `missingContextError`로 시각화 전체가 실패하지 않는다. |
| 대체 시작점 정렬 | 처리 | 전역 요약과 대체 활성 컨텍스트 모두 `context_id` 내림차순(UUIDv7 최신순)으로 고른다. 최근 저장한 컨텍스트가 상한에서 조용히 빠지지 않는다. 오름차순 전용 조회는 사용처가 없어져 하나의 최신순 조회로 정리했다. |

[웹 정본](../sdd/web.md#웹-화면-계약)에 정렬·한 개 추가 조회·`0홉` 절단·같은 스냅숏을 명시하고 [시험 설계](../sdd/testing.md#테스트-계층)에 저장소 시각화 회귀를 추가했다. 웹 처리기·템플릿은 기존 절단 경계 표시를 그대로 사용하므로 변경하지 않았다. DOX pass에서 소유권·경로·작업 흐름 변경이 없어 기존 DOX를 유지했다. 스키마·구성·공개 API는 변경하지 않는다.

## 재현과 검증

- Go 1.27.1과 고정 이미지 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`(PostgreSQL 18.6)의 전용 합성 컨테이너에 정식 7개 마이그레이션(vector(8))을 적용했다. 기존 개발·다른 시험 DB는 사용하지 않았다.
- 기준 코드에서 새 시험의 실패를 재현했다. 고립 대체 시작점 3개·상한 2는 `Truncated=false`, 전역 요약 3개·상한 2는 시작점 절단 대신 1홉 경계 절단으로 표시됐다. 기존 시험용 pgx tracer로 시작점 목록 조회 뒤 본문 묶음 조회 직전에 멈추고 그 시작점을 폐기하면 `컨텍스트 …가 없다` 오류로 실패했다.
- 수정 후 `TEST_DATABASE_REQUIRED=1 go test -race -p 1 -json ./internal/store ./internal/web ./cmd/server -count=1 -timeout=20m`에서 저장소 1,812건·웹 814건이 실패·건너뜀 없이 통과했다. 저장소 기준 1,808건과의 차이는 새 시험·하위 시험 4건이다.
- 서버는 696건 통과·환경 인수 21건 건너뜀·`TestOPS05DiagnosticFlushBudgetIntegration` 1건 실패다. 진단 flush가 2.0초에 끝나 최소 5초 기대에 실패한 것으로, [#201 검토](2026-10-31-issue-201.md)가 기준 코드에서 재현해 분리한 기존 실패와 같으며 이번 저장소 경로를 호출하지 않는다. 별도 기준 worktree의 재실행은 진단 임시 디렉터리 준비 단계에서 다른 원인으로 실패해 동등 재현으로 사용하지 않았다. 서버 전체를 통과로 판정하지 않는다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check`와 변경 문서의 로컬 링크·앵커를 확인했다.
- 시험 종료 후 시험 DB 외 임시 DB 잔류가 없음을 확인하고 소유 컨테이너만 정리했다. 기존 개발·다른 시험 자원과 개인 IDE 파일, 루트 AGENTS.md 편집은 유지했다.

목록 화면의 `graphContextPage`도 같은 한 개 추가 조회를 쓰며 상한이 정수 최댓값이면 넘침이 생길 수 있으나 이번 이슈 범위 밖이라 변경하지 않았다.
