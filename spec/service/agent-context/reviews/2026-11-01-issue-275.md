# #275 비품질 지표의 유의한 증가를 거부하던 평가 판정

## 결정과 변경

검색 단위 비교(`units`)의 거부 기준을 명세대로 완전성·검색 품질과 과업 성공률의 유의한 악화로 한정했다. 검색 품질 지표는 기존 준비 판정과 같은 `recall`·`reciprocal_rank`·`evidence_completeness`·`path_continuity`다. `latency_ms`·`disconnected_ratio`·`hub_concentration`·`duplicate_ratio`·`budget_used`·`budget_per_hit`·`misroute_rate`는 보고만 하며, `budget_used`는 기존과 같이 효율 개선 판단에만 쓴다.

manifest 적응형 요약은 같은 측정을 쓰는 그래프 단계 비교와 같은 악화 기준을 쓰도록 공통 판정 함수(`stageMetricRegressed`)로 묶었다. 측정된 지표의 유의한 악화는 `significant_regression`으로 비채택하되 `budget_used` 증가만으로는 악화로 보지 않는다. 지연 상한·채널 실패 판정과 기본 비교의 동작은 바꾸지 않았다.

[평가 설계](../sdd/evaluation.md#검색-단위-비교의-실행-입력과-결과)와 [manifest 요약](../sdd/evaluation.md#manifest-실행과-결과-묶음), [시험 설계](../sdd/testing.md)에 기준과 회귀 시험을 명시했다. 요구사항·추적표·DOX의 소유권과 구성은 바뀌지 않아 유지했다.

## 검증

- 수정 전 판정 코드로 새 회귀를 실행하면 지연·단절 근거·허브 편중·중복만 유의하게 증가한 검색 단위 비교가 `rejected`/`quality_or_task_regression`으로, 품질 개선과 문자 사용량 증가만 있는 적응형 사용 사례가 `not_accepted`/`significant_regression`으로 판정되어 실패했다. 이슈의 증상과 같다.
- 수정 후 같은 비교는 후보·보류로 남고, `recall`·`path_continuity`의 유의한 악화와 적응형 재현율 악화는 기존 사유로 거부된다.
- Go 1.27.3, 개발 DB 서버에 만든 작업 전용 DB(마이그레이션 001~014 적용), `TEST_DATABASE_REQUIRED=1`, `-p 1`의 필터 없는 `./cmd/eval` 실행: 915건 통과, 3건 실패. 실패는 `TestEmbeddingComparisonCommandIntegration`과 dimension·compression 하위 사례로, 별도 비교 DB(`acs_small`·`acs_half`)가 없는 실행 환경 조건이며 이번 변경과 무관하다. 통과로 보고하지 않는다.
- `check-go.sh`의 의존성 빌드·`go build`·`go vet`·`gofmt`·`govulncheck` 검사 통과.
- 검증 후 작업 전용 DB를 삭제하고 잔여 DB가 없음을 확인했다. 실제 외부 제공자·에이전트 trace·운영 배포는 미실행이다.
