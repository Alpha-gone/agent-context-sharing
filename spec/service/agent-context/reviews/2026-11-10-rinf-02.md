# RINF-02 추론 작업 큐·회차 검증

## 범위와 판정

사건 생성·본문/구성원/시간 변경·복구의 추론 작업 등록을 같은 쓰기 트랜잭션에 연결했다. 기본 `off`, 위임 계정, 중복 등록의 새 세대, DB 시계의 `SKIP LOCKED` 확보·리스, 세대 조건부 실패·결과 소비와 롤백을 구현했다. 구성 허용 목록·검증과 두 환경 예시, 제공자 확보 차단·탐침·백오프 회차도 추가했다.

출력 전체 위반은 입력을 한 번 준비하고 별도 복사본으로 같은 입력을 최대 두 번 전달한다. 두 번 위반하면 실패 상태로 기록하며, 재시도 사이 취소 시 추가 호출하지 않고 리스 회복에 맡긴다. 첫 위반 뒤 제공자 실패가 발생하면 출력 위반과 제공자 실패 횟수를 구분한다. 입력 본문은 작업 큐나 진단 로그에 남기지 않는다.

RINF-02 모듈을 완료한다. 실제 후보 생성·판정 어댑터·결과 반영은 RINF-03·04, 서버·분리 작업자의 조립과 분야 통합 인수는 RINF-05에 남는다. 조립 전 활성 모드는 서버와 분리 실행기에서 기동을 거부한다. 실제 제공자 호출이나 운영 DB 적용은 수행하지 않았다.

## 검증

- Go 1.27.3으로 `go build ./...`, `go vet ./...`, `gofmt -l .`을 실행했다.
- 모델·구성·추론 회차 전체 시험이 통과했다. 입력 버퍼 변형에도 동일 입력을 재전달하는지, 출력 위반 두 번·제공자 장애·취소·탐침 회복을 대역으로 확인했다.
- 정식 스키마를 적용한 별도 합성 DB에서 `TEST_DATABASE_REQUIRED=1 go test -count=1 -p 1 ./internal/store ./cmd/server ./cmd/indexer`가 통과했다. 저장소 398.764초, 서버 103.314초, 분리 실행기 0.482초였다.
- 별도 합성 DB에서 `TEST_DATABASE_REQUIRED=1 go test -race -count=1 -p 1 -timeout=20m ./internal/relinfer ./internal/store`가 통과했다. 추론 회차 1.379초, 저장소 532.670초였다. 취소 표본 추가 후 추론 회차 전체 일반·race 시험도 재실행해 통과했다.
- 저장소 표본은 `off`, 등록 실패 롤백, 동시 확보, 재등록·리스 만료의 이전 세대 거부, 복구 재등록, 결과 소비와 기록의 롤백·커밋, 재시도 소진을 확인했다. 시험용 컨테이너는 정리했다.
