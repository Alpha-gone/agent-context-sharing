# #272 마이그레이션 status 동작과 적용 순서 문서 정정

## 결정과 변경

- `OPERATIONS.md` 최초 배포 절의 `status` 설명을 실제 동작으로 고쳤다. `cmd/migrate`는 #162 이후 자문 잠금 없이 읽기 전용 트랜잭션에서 미적용 파일을 조회하며 이력 테이블을 만들거나 바꾸지 않는다. 같은 문서의 「변경 및 복귀」 절과 `migrations/AGENTS.md`의 설명과도 일치한다.
- `data.md` 「스키마 적용」이 013에서 끝나던 파일 목록을 제거하고 `migrations/`의 파일 번호 순서를 적용 순서의 정본으로 참조하게 했다. `migrations/AGENTS.md`는 과거 SQL이 적용 순서를 설명한다고 정하므로 문서에 목록을 중복하지 않는다. 013·014의 목적을 기존 파일별 설명에 추가했다.
- `OPERATIONS.md` 「변경 및 복귀」의 `001→…→014` 나열도 같은 이유로 번호 순서 참조로 바꿨다.
- 사용자가 디버깅 완료 뒤 개발 마이그레이션을 `001_init.sql`에 통합할 예정이라고 밝혔다. 통합은 `migrations/AGENTS.md`의 사용자 승인 예외로 별도 수행하며, 이번 변경은 파일 목록 중복을 없애 통합 뒤에도 순서 문장이 어긋나지 않게 하는 데 그친다. 통합 자체와 파일별 설명·`test-transition.sh`의 012/013 전제 정리는 통합 작업에서 다룬다.
- 요구사항·추적표·DOX의 소유권과 구성은 바뀌지 않아 유지했다.

## 검증

- `cmd/migrate/main.go`의 `status`가 잠금 없이 읽기 전용으로 조회하는 것과 `migrations/`의 실제 파일(001, 009~014)을 대조했다.
- 변경 Markdown의 문서 내부 앵커(`#신규-구현의-ddl-대응`·`#파생-판-이력`·`#인덱스`)와 `indexing.md#전환복귀-경계` 존재, `git diff --check`를 확인했다.
- 코드·스키마 변경이 없어 Go 시험·마이그레이션 적용은 실행하지 않았다.
