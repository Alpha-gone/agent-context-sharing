## 항목별 처리

| 항목 | 처리 | 내용 |
|---|---|---|
| 종료 취소를 제공자 장애로 기록 | 처리 | `providerOutcome`이 작업 context의 취소·마감을 `canceled`·`deadline_exceeded`(INFO)로, 그 밖의 호출 실패만 `provider_unavailable`(WARN)로 분류한다. 취소된 호출은 ERROR 제공자 실패 로그 대신 INFO 취소 로그를 남긴다. 차단 회로는 기존대로 취소를 원인으로 삼지 않는다. |
| 2xx가 아닌 응답의 본문 미소진 | 처리 | 오류 본문을 해석하지 않고 최대 64 KiB까지 비운 뒤 닫는다. Go 1.27.1은 닫을 때 보수적 상한까지 비동기로 읽으므로 이슈의 "재사용하지 못한다"는 정확히는 "바로 다음 호출이 그 연결을 재사용하지 못한다"이다. 수정 전 같은 서버에 오류 응답 세 번을 받으면 연결 2개를 썼고, 수정 후에는 1개다. |
| 작업당 1초 대기 | 처리 | 명세를 먼저 고쳤다. 작업을 처리한 회차 뒤에는 기다리지 않고 다음 작업을 찾으며, 이어지는 빈 회차는 1초부터 다시 두 배로 늘린다. 처리했지만 확보·결과 공개에 실패한 회차는 연속 재시도를 막도록 1초를 기다린다. 제공자 전체 장애는 기존 차단 회로가 새 확보를 멈춘다. |
| 접기 비교의 반복 계산 | 처리 | 대표 후보의 삼중자 집합을 대표가 될 때 한 번 만들어 보관하고, 후보 본문의 집합도 후보마다 한 번만 만든다. 같은 본문의 유사도 1 판정과 자카드 계산 결과는 바꾸지 않았다. 쓰이지 않게 된 `bodySimilarity`는 제거하고 설명을 `trigramSimilarity`로 옮겼다. |
| 슬롯 정리 중 다른 인스턴스 기동 실패 | 처리 | 기록자 잠금이 사용 중이면 저장소 잠금을 최대 1초 기다려 얻은 뒤 한 번 더 비차단으로 시도한다. 비활성 슬롯 정리는 저장소 잠금 안에서만 그 슬롯의 기록자 잠금을 쥐고 저장소 잠금보다 먼저 놓으므로, 정리 중 기동은 정리가 끝난 뒤 성공한다. 실행 중인 같은 instance는 계속 `instance_busy`다. |

정본은 [색인 조회 간격·제공자 차단·전송](../sdd/indexing.md)·[접기](../sdd/search.md#작업-컨텍스트-흐름-조회)·[기록자 잠금](../sdd/observability.md)·[시험 설계](../sdd/testing.md#테스트-계층)에 반영했다. 새 구성 값·스키마 변경은 없다. DOX pass에서 구조·소유권·색인 변경이 없어 기존 DOX를 유지했다.

## 회귀와 검토

Go 1.27.1, 고정 PostgreSQL/AGE 이미지 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`의 전용 합성 컨테이너에 정식 7개 마이그레이션을 적용하고 `TEST_DATABASE_REQUIRED=1`로 DB 건너뜀을 금지했다. 기존 개발·다른 시험 DB는 사용하지 않았다.

- 기준 `eef4d25`의 저장소 안 임시 worktree에 새 시험을 옮겨 실패를 재현했다. 처리한 회차 뒤에도 1초씩 기다린 조회 시각(`[0s 1s 2s 4s 8s 9s]`), 오류 응답 세 번의 새 연결 2개, 슬롯 정리 중 기동의 즉시 `instance_busy`다. 접기의 다중 대표 시험은 동작을 보존하는 계산 재사용이므로 기준 코드에서도 통과한다. 취소 분류 함수는 기준 코드에 없어 같은 방식의 재현 대신 분류 단위 시험으로 확인했다.
- 소비 루프 시험은 가상 시계로 처리 회차의 무대기와 빈 회차의 1초 재시작을, 기존 시험은 오류가 있는 처리 회차의 1초 대기와 빈 회차 상한을 확인한다. 연결 재사용 시험은 HTTP/1.1 TLS 시험 서버의 새 연결 수를 센다. 슬롯 시험은 저장소 잠금과 다른 슬롯의 기록자 잠금을 별도 파일 설명자로 함께 쥔 상태에서 기동이 기다렸다가, 기록자 잠금 → 저장소 잠금 순으로 놓은 뒤 성공하는지 확인한다.
- `go test -race -p 1 -json ./internal/index ./internal/search ./internal/diagnostic ./cmd/indexer ./cmd/server -count=1 -timeout=30m`에서 색인 132건·검색 343건·진단 213건·색인 실행기 5건이 실패·건너뜀 없이 통과했다. 서버는 696건 통과·1건 실패·21건 건너뜀(108.295초)이다. 건너뜀은 별도 CLI 19건·물리 복구 1건·이전 인수 1건의 환경 미설정이며 통과로 집계하지 않는다. 건수는 하위 사례를 포함한다.
- 서버의 유일한 실패 `TestOPS05DiagnosticFlushBudgetIntegration`은 진단 flush가 2.0007초에 끝나 최소 5초 기대에 실패한 것이다. [#201 검토](2026-10-31-issue-201.md)가 기준 코드에서 재현해 분리한 기존 fixture 실패와 같으며, 이번 변경의 색인·검색·진단 잠금 경로와 관계없다. 서버 전체를 통과로 판정하지 않는다.
- 기존 `internal/diagnostic/test-linux.sh`로 고정 Linux 이미지의 격리 컨테이너 인수를 실행했다. 모듈 222건 통과(새 슬롯 시험 포함)·2건 건너뜀(보조 프로세스용 시험, DB 필요 통합 시험)이고 읽기 전용 마운트·최초/재시작·슬롯 교체·처리량 단계가 통과했다. 스크립트가 만든 볼륨·경로는 남지 않았다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check` 통과. 변경 문서의 상대 링크·앵커를 확인했다.
- 임시 DB·idle transaction 잔류 0개를 확인한 뒤 소유 컨테이너·익명 볼륨과 기준 비교용 worktree를 정리했고 잔류 없음을 확인했다. 기존 자원·개인 IDE 파일과 작업 중 생긴 루트 `AGENTS.md` 편집은 이번 변경에 포함하지 않았다.
