# 평가 실행기의 집계 결정성·상태·통계 회귀 검증

## 대상과 확인 근거

[GitHub #57](https://github.com/Alpha-gone/agent-context-sharing/issues/57)의 여덟 결함을 `cmd/eval`에서 처리했다. `dev`의 `099e02d`에서 시작한 `fix/eval-determinism_#57` 브랜치이며 기존 변경을 보존했다. SDD를 먼저 갱신하고 Go 1.27.1의 Modern Go Guidelines와 코딩 표준을 적용했다.

수정 전 회귀 테스트는 맵 순회에 따른 집계 차이와 동점 후보 오선택, 표본 부족의 0 구간, 자유도 31 이후 1.96 사용, 미측정 지표 일곱 개의 0 비교, 보고서 통제 조건 누락, JSON 맵 키 순서 변경과 `[m1, m1]` 허용에서 실패했다. 처음 테스트 초안의 JSON 타입 오류와 수정 중 import 오류는 시험 코드·컴파일 문제로 수정했으며 결함 재현 근거와 구분한다.

## 해결한 결함

- 집계 결정성: 적응형 격자·품질 평균·임계값 점수와 단계 대응 비교·한계 기여를 식별자 순으로 누적한다. JSON v2 기록에는 결정적 맵 키 정렬을 적용했다. 같은 측정 표본의 집계 256회, 동점 선택 256회, 단계 판정·한계 기여 256회와 파일 기록 32회를 대조한다.
- 구성 초기화: 동시 쓰기 작업자가 멈춘 뒤 폐기한 파생을 복구하고 임시 파생·확정 관계를 폐기한다. 성공한 DB 쓰기만 추적 상태에 반영하며 복구 실패는 다음 구성 실행을 중단한다. 파생·관계·임시 파생의 생성·폐기·복구 실패와 구성 간 반복 초기화를 실물 DB에서 검증했다.
- 실패 정리: 시나리오 적재 성공 직후 실패 정리를 등록하여 색인 실패에도 전용 그래프를 소프트 삭제한다. 취소와 분리한 10초 정리 context를 쓰고 정리 오류를 원래 오류와 함께 전달한다. 제공자 대역이 색인 도중 context를 취소했을 때 생성된 그래프 하나가 삭제 상태임을 확인했다.
- 지표 정의: 지속 평가의 미측정 지표 일곱 개는 `-1`이며 재현율·순위 역수·정답 1건당 문자 수만 비교한다. 실제 검색의 측정 결과와 판정 목록을 각각 검증했다.
- 표본 부족: 표본 0·1개의 표준편차·95% 구간 반폭은 `-1`이다. 두 개 이상의 동일 표본에서만 실제 무분산 구간 0을 허용한다. 구간이 미정의이면 지속·업무 효과 평가를 합격하거나 유의하다고 판정하지 않는다.
- 임계값: 표의 반올림과 자유도 30 이후 정규 근사를 제거하고 정규화 불완전 베타의 연분수·이분법으로 Student t의 0.975 분위수를 구한다. 자유도 1·2·30·31·60·120·121의 기준값 및 자유도 1~120의 독립 확률밀도 Simpson 적분을 대조했다. 자유도 31의 정규 근사가 거짓 유의성을 만드는 경계도 검증했다. 새 외부 의존성은 없다.
- 통제 조건: 적대적·일관성 보고서의 `index_targets`와 일관성 보고서의 `fold_threshold`를 실제 CLI 구성에서 채운다.
- 중복 식별자: 성공 조건·오염 목록 각각에서 같은 컨텍스트 key와 방향 정규화한 관계 정체성의 중복을 거부한다. 상호 강화는 중복이 없는 서로 다른 오염 컨텍스트 식별자 둘 이상을 요구한다.

## 검증

SDK는 `go1.27.1 darwin/arm64`이며 전용 Compose 프로젝트 `eval57-regression`의 새 DB 볼륨과 로컬 임베딩 HTTP 대역을 사용했다. 001·007·008 마이그레이션을 적용한 768차원 `vector` DB에서 `TEST_DATABASE_URL`, `TEST_DATABASE_REQUIRED=1`을 설정했다. `.env`·기존 개발 DB·운영 DB·Ollama·외부 임베딩 API는 사용하지 않았다.

검증 후 프로젝트 소유 label을 확인하여 시험 컨테이너·합성 DB 두 개가 든 볼륨·네트워크와 전용 이미지 태그를 삭제했다. 남은 시험 컨테이너·볼륨·네트워크는 없으며 합성 DB는 마이그레이션과 테스트로 다시 생성할 수 있다. 기존 개발 환경은 변경하지 않았다.

```shell
# DB 필수 환경에서 단위·통합 회귀를 함께 실행
go test -race ./cmd/eval -count=10
# 서버 전체: 새 DB에서 패키지를 순차 실행
go test -race -p 1 -count=1 -json ./...
# 서버 루트와 client/에서 각각
go build ./...
go vet ./...
# client/에서 공유 계약 검사
go test ./internal/client/contract
# 저장소 루트
gofmt -l .
git diff --check
```

평가 패키지의 전체 race 회귀 10회와 양쪽 모듈 build·vet·클라이언트 계약 검사는 통과했다. 서버 전체 검사에서는 다음 시험 환경 문제를 확인했다.

- 평가 반복 검사와 동시에 실행한 첫 시도는 기존 `TestReindexExcludesAndReplacesOutdatedModel`의 DB 전체 옛 모델 행 수가 바뀌어 실패했다(기대 1790, 실제 1814).
- 같은 DB를 재사용한 순차 실행은 이전 저장소 시험의 `test-private-key` 대역 서명 키 때문에 웹 세션·토큰 교환 시험 두 건이 실패했다. 별도 단독 실행에서도 개인 키 JSON 해석 오류를 확인했다.
- 관련 없는 시험 코드·데이터를 수정하지 않고 새 DB `eval57suite`를 만든 뒤 패키지를 순차 실행했다. 서버 테스트 항목 705개가 race 검사에서 통과했고 실패·건너뛰기는 없었다. 최초 실패를 통과로 숨기지 않고 시험 환경과 복구 근거를 함께 기록한다.

## DOX와 적용 경계

루트와 `spec`→`spec/service`→`agent-context`의 DOX 체인을 확인하고, 루트 소유의 평가 도구 계약·SDD·개발 계획·공식 근거·요청 기록을 동기화했다. 서버의 `FR-AGENT_CONTEXT-112` 검증 원칙과 기존 평가 요구사항을 구현하는 결함 수정이며 요구사항·도메인 용어·서비스 역할·파일 경계·공개 MCP 계약·스키마는 변경하지 않았다. 따라서 SRS·DICTIONARY·서비스 색인과 하위 AGENTS·Child DOX Index는 유지한다.

결정성은 같은 측정 표본·구성의 집계와 기록에 적용한다. 새 실행의 시각·실제 지연·동시 쓰기 횟수·그래프 UUID까지 파일 전체가 동일하다고 주장하지 않는다. 본격 검색·적대적 품질 평가, 기존 임계값의 재채택과 운영 배포는 미실행이다. 과거 검증 기록은 당시 기록으로 보존하며 수정된 도구로 품질 비교를 다시 하지 않은 상태에서 기존 운영 기본값의 적합성을 새로 확인했다고 보고하지 않는다. 커밋·푸시·PR 생성·GitHub 이슈 종료도 수행하지 않았다.
