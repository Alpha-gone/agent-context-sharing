# #234 삭제·복구 목록 페이지 크기 넘침 검토

- 대상: [이슈 #234](https://github.com/Alpha-gone/agent-context-sharing/issues/234). [#186 검토](2026-10-31-issue-186.md)가 범위 밖으로 남긴 목록 조회의 넘침이다.
- 기준: `dev`의 `17dc403`, 브랜치 `fix/234-graph-context-page-overflow`.

## 처리

삭제·복구 화면의 활성·삭제 목록은 잘림을 판정하려고 플랜의 `graph_page` 기본값보다 한 건 더 읽는다. 플랜 검증은 양수를 Go `int` 범위까지 허용하므로 기본값이 정수 최댓값이면 추가 조회 값이 음수로 넘쳐 목록 조회가 인자 오류로 실패했다. 관계·그래프 목록과 그래프 상세 시작점 조회처럼 상한이 정수 최댓값보다 작을 때만 한 건 더 읽는다. 그보다 많은 컨텍스트가 있을 수 없으므로 최댓값 상한의 결과는 잘리지 않은 목록이다. 기존 페이지 크기의 추가 조회와 잘림 판정은 유지한다.

감사 조회는 `MaxInt32` 이상의 상한을 이미 거부하고 관계·그래프 목록은 같은 보호가 있어 변경하지 않았다. [웹 정본](../sdd/web.md#화면-배치)에 목록의 추가 조회와 최댓값 처리를, [시험 설계](../sdd/testing.md#테스트-계층)에 회귀를 추가했다. 플랜 검증 범위·웹 처리기·스키마·구성은 변경하지 않았으며 DOX pass에서 소유권·경로 변경이 없어 기존 DOX를 유지했다.

## 재현과 검증

- Go 1.27.1과 고정 이미지 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`(PostgreSQL 18.6)의 전용 합성 컨테이너에 정식 7개 마이그레이션(vector(8))을 적용했다. 기존 개발·다른 시험 DB는 사용하지 않았다.
- 기준 코드에서 새 시험이 정수 최댓값 페이지 크기의 활성 목록 조회에서 `그래프 정점 조회 인자가 올바르지 않다`로 실패하는 것을 재현했다. 활성·삭제 목록은 같은 조회 함수를 사용한다.
- 수정 후 `TEST_DATABASE_REQUIRED=1 go test -race -p 1 -json ./internal/store ./internal/web ./cmd/server -count=1 -timeout=25m`에서 저장소 1,813건·웹 814건이 실패·건너뜀 없이 통과했다. 저장소 기준 1,812건과의 차이는 새 시험이다.
- 서버는 696건 통과·환경 인수 21건 건너뜀·`TestOPS05DiagnosticFlushBudgetIntegration` 1건 실패다. [#201 검토](2026-10-31-issue-201.md)가 분리한 진단 flush 2.0초 종료의 기존 실패와 같으며 목록 조회 경로를 호출하지 않는다. 서버 전체를 통과로 판정하지 않는다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check`와 변경 문서의 로컬 링크·앵커를 확인했다.
- 시험 종료 후 시험 DB 외 임시 DB와 idle transaction 잔류가 없음을 확인하고 소유 컨테이너만 정리했다. 기존 개발·다른 시험 자원과 개인 IDE 파일, 루트 AGENTS.md 편집은 유지했다.
