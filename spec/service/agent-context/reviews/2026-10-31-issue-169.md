# #169 평가 비교의 채널 실패·지연 SLO 판정

- 대상: [이슈 #169](https://github.com/Alpha-gone/agent-context-sharing/issues/169).
- 기준: `dev`의 `dea6c2c`, 브랜치 `fix/169-eval-failure-latency-rejection`.

## 항목별 처리

| 항목 | 처리 | 내용 |
|---|---|---|
| 기본 비교의 실패·초과 우선 | 처리 | 그래프 단계·색인 대상 비교에서 기준·비교 단계의 채널 실패와 비교 단계의 사용 사례별 p95 500ms 초과를 표본 충분성 검사보다 먼저 `rejected`/`channel_failures`·`latency_slo_exceeded`로 판정한다. 나머지 통계 판정에만 독립 단위·필수 지표 충분성을 적용한다. manifest 요약은 기존대로 `rejected`를 출처·독립 단위 검사보다 먼저 not_accepted로 바꾼다. |
| 임베딩 비교의 SLO 기준 | 처리 | 기준 구성을 포함한 모든 질의 중 하나라도 500ms를 넘으면 보류하던 검사를, 후보 구성의 회차별·사용 사례별 p95 검사로 바꿨다. 초과하면 표본 충분성·출처와 관계없이 `rejected`/`latency_slo_exceeded`다. |
| 단일 질의 이상치 | 처리 | p95(nearest-rank)에 들지 않는 단일 질의 지연과 기준 구성의 지연은 SLO 판정에 쓰지 않는다. 지연 악화 자체는 기존 유의성 판정이 계속 다룬다. |
| 보류 사유 구분 | 처리 | 임베딩 비교의 표본/주석 부족 사유를 `insufficient_independent_units_or_annotations`로 바꾸고 SLO 초과는 별도 비채택 사유로 기록한다. |

[평가 정본](../sdd/evaluation.md)의 그래프 단계 비교와 [임베딩 비교 실행 계약](../sdd/evaluation.md#임베딩-비교-실행-계약)에 판정 순서·SLO 기준·사유를, [시험 설계](../sdd/testing.md#테스트-계층)에 회귀를 추가했다. 결과 JSON 필드는 그대로이며 임베딩 비교의 보류 사유 문자열이 바뀐다. DOX pass에서 소유권·경로 변경이 없어 기존 DOX를 유지했다.

## 재현과 검증

- 이슈의 세 표본을 시험으로 구성했다. 기존 코드에서 다음을 재현했다.
  - 독립 단위 1개의 그래프 단계 비교에서 p95 초과·채널 실패, 색인 대상 비교에서 채널 실패가 모두 `deferred`/`insufficient_independent_units`였다.
  - 독립 평가 단위 10개(회차별 사용 사례 질의 20건)의 임베딩 비교에서 후보 질의 한 건만 620ms이고 p95가 200ms인 경우, 기준 구성만 600ms인 경우, 두 구성 모두 501ms라 후보 p95가 초과한 경우가 모두 `deferred`/`insufficient_independent_units_annotations_or_latency_slo`였다.
- 수정 후 기본 비교는 `channel_failures`·`latency_slo_exceeded` 비채택이다. 임베딩 비교의 단일 이상치는 비용 개선 후보, 기준 구성만 느린 경우는 지연·비용 개선 후보, 후보 p95 초과는 실제·합성 출처 모두 `rejected`/`latency_slo_exceeded`다. 판정 단위 시험에서 독립 단위 1개의 p95 초과는 비채택, 정확히 500ms는 표본 부족 보류로 구분된다.
- Go 1.27.1과 고정 이미지 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`(PostgreSQL 18.6)의 전용 합성 컨테이너에 기본 vector 768·비교 vector 128·halfvec 768 DB를 만들고 각각 정식 7개 마이그레이션을 적용했다. 기존 개발·다른 시험 DB는 사용하지 않았다.
- `TEST_DATABASE_URL`, `TEST_EMBEDDING_SMALL_URL`, `TEST_EMBEDDING_HALF_URL`, `TEST_DATABASE_REQUIRED=1`을 지정한 `go test -race -p 1 -json ./cmd/eval -count=1 -timeout=40m`에서 910건이 실패·건너뜀 없이 통과했다. [#168 검토](2026-10-31-issue-168.md)의 899건과의 차이는 새 시험·하위 시험 11건이다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check`와 변경 문서의 로컬 링크·앵커를 확인했다.
- 시험 종료 후 시험 DB 외 임시 DB와 idle transaction 잔류가 없음을 확인하고 소유 컨테이너만 정리했다. 기존 개발·다른 시험 자원과 개인 IDE 파일은 유지했다.
