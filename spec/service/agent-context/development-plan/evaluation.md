# 평가 개발 계획

[전체 계획](../DEVELOPMENT_PLAN.md) · [기준 SDD](../sdd/evaluation.md) · [작업 추적](traceability.md)

## 목표와 구현 범위

새 구현의 검색 품질·구조·업무 효과를 비교하는 평가 실행기·공개 데이터 준비·통계·비용·실패 보고를 구현한다. 평가 기능의 구현 완료와 실제 효과·채택 판정은 별개로 기록한다.

- 설계 입력: [검증 기반](../sdd/evaluation.md#검증을-가능하게-하는-설계), [비그래프 기준선](../sdd/evaluation.md#비그래프-기준선), [공개 평가 실행](../sdd/evaluation.md#초기-공개-평가-실행-설계), [SRS 검증](../SRS.md#검증).
- 예정 구현 영역: `cmd/eval`과 도구 내부 패키지, 데이터 변환·실행 명세·결과 검증·집계.
- 다른 분야와의 경계: 지표 의미·합격 기준은 SRS, 상태·검색 구현은 각 분야, 적대적 표본·실행 검증은 테스트 SDD의 계약을 따른다.

3. 잘못된 모드·own-adversarial의 잘못된 옵션·일관성 후보 상한 24 이하를 입력 읽기·DB·파일 생성 전에 거부한다.

- 완료 기준: 잘못된 실행이 데이터·파일을 만들지 않고 실제 값과 미측정 상태를 구분할 수 있다.

- 완료 근거: [EVAL-01 모듈 인수](../reviews/2026-10-25-eval-01.md). 판 1 manifest 검사·엄격한 JSON·비식별 독립 단위·10회/순서/seed·비용 상태와 실행 전 모드/일관성 옵션 검증을 구현했다. 모듈 229건과 실제 CLI DB 회귀 18건의 고유 246건이 race 조건에서 실패·건너뜀 없이 통과했다. 공개 데이터 준비·checksum 실물 대조·manifest 기반 비교 실행과 효과/비용 판정은 EVAL-02 이후 작업이다.

### EVAL-02

- [x] **공개 데이터와 자체 보완 세트를 준비한다.**
- 선행: [EVAL-01](#eval-01).

1. 공식 저장소 판·파일 checksum·사용 조건을 실제 준비 시 확인하고 LongMemEval_S 500문항·LoCoMo 10개 대화의 텍스트 범위를 고정한다.
2. 원천 발화/턴·시각·origin·source_ref와 비식별 dataset/conversation/task/query 매핑을 변환한다.
3. 질의·정답·근거 주석은 기억/임베딩에서 분리하고 주석 없는 표본의 근거 지표를 미평가로 표시한다. 제외·실패의 수와 이유를 남긴다.
4. 사건·근거·격리·복구·오염·인계의 자체 세트를 별도 판으로 준비한다.

- 산출물: 변환기·고정 입력 명세·근거 매핑·보완 세트.
- 완료 기준: 정답 유출 없이 문항·대화·제외 수가 원본과 맞고 공개 결과에는 원문·개인 식별자가 없다. 과거 자체 세트 결과로 공개 평가를 대체하지 않는다.

- 완료 근거: [EVAL-02 모듈 인수](../reviews/2026-10-25-eval-02.md). 공식 고정 판·SHA-256·사용 조건을 확인하고 LongMemEval_S 500문항(독립 과업 471개)·LoCoMo 10개 대화의 텍스트 1,251문항(이미지 근거 735문항 제외)·자체 보완 여섯 과업을 준비했다. 기억·평가 주석·원본 매핑을 분리하고 빈 원본/부분 주석·미평가 분모를 보존했다. 모듈 272건(최상위 82건)이 race에서 실패·건너뜀 없이 통과했고 전체 원본 발화/정답/근거/시각·checksum·권한을 별도 대조했다. 그래프 적재·색인·비교 실행과 효과 판정은 후속이다.

### EVAL-03

- [x] **평가 그래프·색인 준비·정리를 구현한다.**
- 선행: [EVAL-01](#eval-01), [DATA-04](data.md#data-04), [LIFE-02](context-lifecycle.md#life-02), [IDX-08](indexing.md#idx-08).

1. 조건·표본·회차마다 독립 그래프를 적재하고 현재 대상 계층·모델 임베딩과 전체 pending/failed를 한 읽기로 검사한다.
2. 유한 처리 상한을 적용하고 미래 재시도·다른 작업자 리스/잠금·최종 실패·임베딩 누락을 즉시 준비 실패로 보고한다.
3. 큐가 비었거나 지금 처리할 작업이 없다는 이유로 준비를 통과시키지 않고 평가기가 임의 재등록해 실패를 숨기지 않는다.
4. 성공·적재 실패·색인 실패·취소 모두에서 독립 10초 context로 소프트 삭제를 시도하고 정리 오류를 원래 오류와 함께 전파한다.

- 산출물: 그래프 실행 수명·준비 검사·정리 경계.
- 완료 기준: 미준비 상태에서 측정·정상 결과가 기록되지 않고 남의 그래프·작업을 처리하지 않는다.

- 완료 근거: [EVAL-03 모듈 인수](../reviews/2026-10-25-eval-03.md). 공통 적재·준비·측정·독립 정리 경계, 조건/회차별 그래프 격리와 종료 신호 취소를 구현했다. 영/잘못된 그래프 범위를 작업자 호출 전에 차단하며 정리 실패 시 정상 보고서를 기록하지 않는다. 실제 DB·대역 제공자의 고유 357건(평가 실행기 338·저장 준비 9·작업자 준비 10건)이 race에서 실패·건너뜀 없이 통과했다. 자체 보완 일곱 기억 그룹을 실제 적재·색인·정리했고, 공개 데이터/manifest 기반 비교 실행과 품질·비용 판정은 후속이다.

### EVAL-04

- [x] **지표·결정적 집계·독립 단위 통계를 구현한다.**
- 선행: [EVAL-01](#eval-01), [SEARCH-07](search.md#search-07).

1. 사용 사례별 재현율·순위·문자/지연·근거 완전성·경로 연속성·단절·허브·중복·단계 한계 기여와 경로 오선택률을 SRS 분모로 계산한다.
2. 질의/과업의 10회 값을 먼저 평균하고 같은 대화 문항은 묶어 독립 대화/과업의 대응 차이로 Student t 95% 구간을 계산한다.
3. 자유도 n-1을 사용하고 30 이후 정규 임계값으로 바꾸지 않는다. 둘 미만·미측정은 정의된 -1/미정의 표식과 판정 보류로 처리한다.
4. ID·맵 키·누적 순서를 고정하되 실제 지연·실행 시각·쓰기 수는 측정한다. 반복을 독립 표본으로 늘리지 않는다.

- 산출물: 지표·통계·정렬 집계와 알려진 값/경계 표본.
- 완료 기준: 순서만 바꾼 같은 측정 표본의 집계가 같고 무자료·단일 독립 단위를 통과 판정하지 않는다.

- 완료 근거: [EVAL-04 모듈 인수](../reviews/2026-10-25-eval-04.md). 질의 반복→대화/과업 단위 평균·대응 차이, 10회/질의/단위 검증, 표본 수·자유도·미측정 상태와 결정적 누적을 구현했다. 근거 고유 분모·반환 부분 그래프·허브 지니·회차별 한계 기여도 보완했다. 모듈 296건·실제 기본/적응형 CLI 3건의 고유 299건이 race에서 실패·건너뜀 없이 통과했고 자유도 1~500을 독립 수치 적분으로 대조했다. 공개/manifest 실행 연결·실제 효과·비용 판정은 후속이다.

- 완료 기준: 통제 입력·예산·모델·준비·캐시가 같고 기능 효과와 색인 대상 효과가 섞이지 않는다.

- 완료 근거: [EVAL-05 모듈 인수](../reviews/2026-10-25-eval-05.md). auto 비그래프 기준선·인접 누적 단계·독립 색인 대상 비교, 준비 파일 checksum/독립 단위/기억 그룹 연결과 미주석·비해당 지표 보존을 구현했다. 준비 시간·실제 문서 HTTP 시도·벡터 열 저장량과 사용 사례별 개선/악화·SLO·실패·기본 활성화 보류를 기록한다. 모듈 344건·실제 CLI 8건의 고유 352건(최상위 108건)이 race에서 실패·건너뜀 없이 통과했고 전체 정적 검사도 통과했다. 실제 공개/보완 준비 파일의 입력 연결을 확인했으며 공개 검색 효과·총비용·최종 채택은 후속이다.

### EVAL-06

- [x] **라우팅·일관 읽기·홉 구현의 통제 비교를 구현한다.**
- 선행: [EVAL-05](#eval-05), [SEARCH-08](search.md#search-08), [SEARCH-10](search.md#search-10).

1. 라우팅 비교는 그래프 범위·근거 선택을 고정하고 각 질의를 직접/국소/전역으로 실행해 오프라인 최적 경로를 구한다.
2. 품질 우선·문자·지연 구간·동률 규칙대로 최적 경로와 오선택률을 계산하고 임계값 후보를 초기 신호로 재현한다.
3. 일관성 비교는 시험 전용 Read Committed·동기화 스냅숏·내용 판 후보의 결과·연결·보유 시간·재시도를 측정한다. 다음 조건 전에 임시 상태를 완전히 복구한다.
4. AGE 홉 후보는 결과 동등성 통과 뒤 왕복·행·전송·지연을 비교한다. 미측정 연결·빈 지연은 -1로 남긴다.

- 산출물: 세 종류의 독립 비교·강제 경로·동시 쓰기 도구.
- 완료 기준: 비교 후보를 운영 입력으로 노출하지 않고 동시 쓰기 없는 동등성·쓰기 중 단일 커밋 설명과 비용을 함께 판정한다.

- 선행 근거: [SEARCH-10 비교 인수](../reviews/2026-10-25-search-10.md)는 동일 읽기 경계의 합성 홉 결과·자원·지연과 AGE 후보 보류를 소유한다. 이 작업의 일관성 후보별 연결/재시도·라우팅 품질과 EVAL-05의 근거 선택·색인 대상은 각각 별도 통제 비교로 남긴다. SEARCH-10의 완료로 해당 평가를 완료 처리하지 않는다.

- 완료 근거: [EVAL-06 모듈 인수](../reviews/2026-10-25-eval-06.md). 라우팅의 조회 시각·초기 신호 재현, 시험 전용 내용 판 후보의 30초/3회 재시도, 세 일관성 후보의 동등성 선행 검사·실제 커밋 교차·실패/미계측 자원 구분을 보강했다. 홉은 새 세 표본에서 동등성 통과 뒤 10회 순환하며 SQL 명령·반환 행·프로토콜 수신량·지연을 측정했다. 평가·실제 CLI·DB·홉의 고유 446건(최상위 135건)이 최종 선택 범위에서 실패·건너뜀 없이 통과했다. 후속 조사에서 정리 CLI의 대형 입력 반복 준비를 줄인 뒤 평가 전체 442건(최상위 134건)이 동일한 4분 제한에서 95.648초에 실패·건너뜀 없이 통과했다. 최초 중단·분리 검증·후속 전체 실행의 근거는 검토 기록을 따르며 공개 효과·운영 기본값 채택은 후속이다.

### EVAL-07

- [x] **지속 평가 여섯 시나리오를 구현한다.**
- 선행: [EVAL-05](#eval-05), [LIFE-09](context-lifecycle.md#life-09).

1. 온라인 갱신·재생·전이·복구·망각·상충 해소를 독립 평가 그래프로 실행한다.
2. 전이는 references, 나머지 기본 구성 시나리오는 baseline으로 같은 질의를 전후 측정하고 근거 경로·활성 상태·만료 포함 정책·신뢰 상태를 검사한다.
3. 판단 표식을 관리 기록에 남겨 재확인하고 재현율·순위·정답당 문자의 대응 변화로 회귀를 판정한다.
