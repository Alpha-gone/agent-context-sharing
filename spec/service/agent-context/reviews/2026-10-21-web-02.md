- 기준: 2026-10-21, `feat/web-foundation`의 `640d502` 이후 작업 트리.
- 대상: [WEB-02](../development-plan/web.md#web-02), [웹 요청 처리 순서](../sdd/web.md#웹-요청-처리-순서), [세션 쿠키 검증](../sdd/authentication.md#세션-쿠키-검증).
- 판정: WEB-02 구현·모듈 시험 완료. 전체 **70/124개 완료·54개 미착수**다. 서버 조립의 다음 선행 작업은 [OBS-01](../development-plan/observability.md#obs-01)이며 이후 OBS-02와 ARCH-06으로 이어진다.

## 발견 사항과 보완

| ID | 발견 사항 | 처리·새 증거 |
|---|---|---|
| WEB02-R1 | 출처 검사에서 먼저 거부한 보호 화면의 응답에는 세션 처리기가 설정하는 no-store가 빠졌다. | 내장 공개 자산을 제외한 모든 동적 화면·거부 응답에 no-store를 선행 적용했다. 동의·연결 관리를 포함한 출처 거부에서 본문·세션·변경 호출 없음과 캐시 지시를 대조했다. |
| WEB02-R2 | 상세·삭제 화면의 그래프 조회 장애와 삭제 화면의 개별 컨텍스트 조회 장애를 404로 숨겼다. | 감싸진 ErrNotFound는 404, 저장 장애는 내부 원문 없는 500으로 분리했다. 장애 반환 뒤 후속 조회·부분 본문이 없음을 확인했다. |
| WEB02-R3 | 저장소의 응답 재검사와 별도로 웹 렌더링 경계의 그래프·컨텍스트·간선 범위 대조가 빠졌다. | 요청 그래프 메타데이터의 ID, 시각화·삭제 목록·선택 컨텍스트의 graph_id와 선택 ID, 간선 양 끝의 반환 정점 포함 여부를 대조한다. 다른 그래프·목록 밖 간선·삭제된 시각화 노드는 결과 전체를 고정 500으로 거부한다. |

기존 공개 로그인·가입 보호, 세션 발급·검증·로그아웃과 쿠키 어댑터를 재사용하고 새 실행 근거로 인수했다. 지원하지 않는 메서드는 업무 화면의 세션·조회 전에 405로 거부한다. GET은 화면 조회만 하고 HEAD·OPTIONS로 상태를 변경하지 않는다. 세션 검증 성공 뒤에도 유효한 계정 UUIDv7을 요구하며, Authorization·질의·양식 자격을 웹 쿠키 대신 사용하지 않는다.

진입 전 취소와 등급 검사·그래프 조회·시각화 조회 뒤 취소를 확인해 후속 조회·본문·리디렉션·쿠키를 만들지 않는다. 기존 발급·검증·폐기의 취소·장애 처리와 성공 후 세션 수명 비연장 계약을 유지한다. 400·413 양식 거부에는 해당 계정 화면의 제목을 제공한다.

새 공개 API·패키지 의존·스키마·환경 변수·인증 정책은 추가하지 않았다. 웹 업무 데이터는 단일 store 경계를 사용하고 실제 변경의 권한·감사·한도 재검사는 기존 저장 트랜잭션이 담당한다.

## 검증 — 2026-10-21

- Go 1.27.1 darwin/arm64, Modern Go CLI 대상 버전 지침 전체를 확인했다. 적용 판 SDK의 net/http.CrossOriginProtection.Check·Request.Cookie·ParseForm·SetCookie 계약을 공식 문서/SDK 소스로 대조했다.
- **신규 WEB-02 59건 통과**, 실패·건너뜀 0. 열두 경로의 HEAD·OPTIONS 선행 거부, 공개 GET의 계정/폐기 비호출, 세션→계정→등급→그래프→시각화 순서와 단계별 중단, 내부 오류 비노출, 그래프/컨텍스트/간선 범위 및 취소를 검증했다.
- 기존 출처 시험에 `/authorize`·`/connections`와 no-store 검증을 추가했다. 같은 출처·비브라우저 요청 허용, 공개 인증의 8 KiB·미디어·400/413/429·취소·비밀번호 작업 진입 순서도 웹 회귀에 포함했다.
- **웹 전체 627건·선별 서버 90건, 중복 제외 총 717건 통과**, 실패 0·건너뜀 0, `-race -count=1`. 신규 59건은 웹 전체 수에 포함하며 따로 더하지 않는다.
- 실제 DB·TLS에서 쿠키의 Secure·HttpOnly·SameSite=Lax·호스트 전용·경로·JWT와 같은 만료, 정확한 12시간 수명, 재조회 비갱신, 잘못된 audience·서명·만료·폐기, Bearer/query 대체 자격 거부, 로그아웃과 실제 검증 저장소 장애·공개 인증 주소별 예산을 확인했다. 전송 선행 거부가 양식 해석 전에 일어나는 서버 회귀도 실행했다.
- Node.js가 있어 기존 Cytoscape 선택·국소/전체·키보드 상태 전이 시험도 실행했다. 실제 브라우저·스크린리더 인수와 호스트 직접 연결은 수행하지 않았다.
- `check-go.sh`의 의존성 확인·의존성 빌드·전체 go build·go vet·gofmt가 통과했다.
- 변경 Markdown 9개의 로컬 링크·앵커 320개·코드 블록과 계획 70개 완료·54개 미착수를 대조했다. 새 텍스트 파일의 공백·gofmt와 기존 부모 Child DOX 색인도 확인했다.

## 남은 범위와 DOX pass

공통 요청 경계의 모듈 인수이며 WEB-03~09의 전체 업무 화면·통합 시험, OBS의 실제 진단 기록기, ARCH-06·07의 전체 서버 조립, 브라우저·보조 기술·호스트 인수를 완료한 것은 아니다. WEB-03의 선행도 준비됐으며 전체 서버 조립을 위해 OBS-01→OBS-02를 우선 진행한다.

새 파일은 기존 웹 DOX의 처리기·검증 소유 경계 안에 있어 DOX·Child DOX Index를 유지했다. 웹 SDD의 캐시·응답 재검사 설명, 개발 계획·설계 상태·서비스 색인·공식 근거·요청 기록을 정합화했다. SRS·용어집·마이그레이션·환경 예시는 계약 변경이 없어 유지했다. 브랜치는 upstream이 없으며 기존 Compose·IDE 변경을 보존했다. 이번 작업에서는 commit·push·PR·배포를 수행하지 않았다.
