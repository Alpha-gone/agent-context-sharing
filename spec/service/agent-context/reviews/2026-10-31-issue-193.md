# #193 전역 인증 시도 예산의 정상 사용자 차단 검토

- 대상: [이슈 #193](https://github.com/Alpha-gone/agent-context-sharing/issues/193), 관련 [#109](https://github.com/Alpha-gone/agent-context-sharing/issues/109).
- 기준: `dev`의 `6bffb83`, 브랜치 `fix/193-auth-attempt-availability`.

## 정책 결정

전체 출처를 합산하는 60회/분 예산을 제거한다. 동의 예산만 분리하면 다른 출처의 정상 로그인·가입은 여전히 막히며, 웹 세션 예외는 새로 로그인해야 하는 사용자를 보호하지 못한다. 출처별 10회/60초와 기존 비밀번호 작업 자리 4개·대기열 없음으로 시도·동시 해시 실행을 제한하는 방식을 선택했다.

공개 로그인·가입·동의 POST는 계속 출처별 창을 공유한다. 유효 세션을 가진 동의 요청도 자기 출처가 소진한 창을 우회하지 않는다. IPv4 /32·IPv6 /64 정규화, 신뢰 프록시 검증, 식별 실패의 공통 키, 4096개 출처 상태와 활성 창 비축출, 만료 정리, 본문 8 KiB·출처 검사·취소·고정 안내·Retry-After·no-store와 bcrypt 비용은 유지한다. 삭제한 전역 창의 남은 시간은 재시도 판정에서 빼고 출처 창·용량 상태만 사용한다.

기존 정책은 /56 안 여섯 /64만으로 다른 모든 출처의 로그인·가입·MCP 동의를 남은 60초 창 동안 거부할 수 있었다. 변경 후에도 동시 작업 자리를 점유하는 분산 부하와 같은 NAT·/64의 정상 사용자 경합은 남는다. 4096개 상태가 모두 활성일 때 새 정상 출처도 거부되며 이 메모리 상한은 제거하지 않았다. 동의는 bcrypt를 쓰지 않으므로 이 변경이 동의 코드 발급의 전역 처리량 상한을 별도로 제공하지는 않는다. 가용성 전체를 보장하거나 외부 WAF·Cloudflare 방어를 적용했다고 주장하지 않는다.

[인증 정본](../sdd/authentication.md#공개-로그인가입-자원-보호)을 구현 전에 갱신해 영향·대안·잔여 위험을 명시했다. [시험 설계](../sdd/testing.md#테스트-계층)·[공식 근거](../reference.md#2026-10-31-193-인증-전역-시도-예산과-정상-사용자-가용성)·[운영 안내](../../../../OPERATIONS.md)를 정합화했다. DOX pass에서 경로·소유권·구성 경계가 바뀌지 않아 기존 DOX를 유지했다. SRS·비밀번호 작업 구현·프록시 신뢰·스키마·환경 예시는 변경하지 않는다.

## 재현과 검증

- 수정 전 /56 안 여섯 /64에서 각 10회 잘못된 로그인을 보낸 뒤, 다른 출처의 정상 로그인·가입·동의 허용·거절 네 요청이 모두 429를 반환했다. 동의 코드는 발급되지 않았다. 결과는 `/tmp/acs193-red.json`에 보관한다.
- 수정 후 같은 웹 표본의 네 요청이 303으로 처리되고 동의 허용만 코드 1개를 발급하며 요청 세션 계정이 유지되는 것을 확인했다. 소진된 /64의 다른 주소는 유효한 세션이 있어도 계속 429·Retry-After 60으로 거부된다. 이 표본의 인증·발급은 대역이며 실제 자격·DB 조합은 아래 관련 서버 회귀로 구분한다.
- 120개 출처의 동시 HTTP 실패 요청은 모두 기존 401/400으로 처리되고, 12개 출처의 동시 240개 요청은 출처마다 10개씩 총 120개만 허용된다. 기존 전역 상한 시험을 이 독립성·출처 상한 검증으로 바꿨으며 창 만료·용량·본문·취소 회귀를 유지했다. 관련 웹 시험 53건이 race에서 통과했다. 결과는 `/tmp/acs193-targeted.json`이다.
- Go 1.27.1과 고정 PostgreSQL/AGE 이미지 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`의 소유 합성 컨테이너에 정식 7개 마이그레이션을 적용했다. 필수 DB/race의 `go test -race -p 1 -json ./internal/authz ./internal/web -count=1 -timeout=10m`에서 인증 전체 496건·웹 전체 814건이 실패·건너뜀 없이 통과했다. 비밀번호 작업 자리·없는 계정 더미 대조·중복 가입·취소 뒤 자리 반환과 기존 Chrome 인수도 포함한다.
- `go test -race -json ./cmd/server -run '^Test(ClientAddress|TransportSecurity|PublicAuthentication|OAuthAuthorizationTLS|OPS03.*Transport)' -count=1 -timeout=5m`에서 관련 서버 88건이 실패·건너뜀 없이 통과했다. 실제 신뢰 프록시 주소·로그인·가입·세션·동의·전송 경계를 확인한 범위이며 서버 전체 시험을 실행한 것으로 보고하지 않는다. 결과는 `/tmp/acs193-modules.json`·`/tmp/acs193-server.json`이다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check`와 문서 로컬 링크·앵커를 확인했다.
- 시험 종료 후 기본 시험 DB·postgres 외 임시 DB가 없고 idle transaction이 0임을 확인했다. 소유 컨테이너·연결 익명 볼륨만 정리한 뒤 잔류가 없음을 확인했으며 기존 개발·다른 시험 자원과 개인 IDE 파일은 유지했다.

독립 읽기 전용 검토에서 전역 창만 제거되고 출처·상태 용량·본문·비밀번호 작업 보호가 유지됨을 확인했으며 수정이 필요한 결함은 발견되지 않았다. 검토자는 DB·시험을 별도로 실행하지 않았다. 실제 운영 공격·운영 부하·오탐률과 신규 표본의 별도 브라우저 제출은 측정하지 않았다.
