- 기준: 2026-10-20, `feat/mcp-auth`의 `5f387fb` 이후 작업 트리.
- 대상: [MCP-06](../development-plan/mcp.md#mcp-06), [쓰기 도구 연결](../sdd/mcp.md#쓰기-도구-연결), [트랜잭션 경계](../sdd/context-lifecycle.md#트랜잭션-경계), [권한·한도](../sdd/authorization.md).
- 판정: 여덟 쓰기 도구의 도메인 연결·모듈 인수 완료. 전체 65/124개 완료, 다음 권장 작업은 [MCP-07](../development-plan/mcp.md#mcp-07)이다.

## 구현과 계약

`NewWriteHandlers`가 두 그래프·네 노드·두 관계 쓰기를 실제 주입 인터페이스로 연결한다. 서버 조립의 `mcpWriteStorage`는 기존 Store의 인자·관리 기록·쓰기 한도와 내부 장애 타입만 맞춘다. 모델·저장 패키지는 SDK와 MCP 코드를 생성하지 않는다. 공개 입력은 바꾸지 않았고 미사용 노드 폐기/복구 주입 계약의 기대 판 인자를 제거했으며 거부 기록 주입을 명시했다. 이 내부 계약은 구현 전에 소유 SDD에 반영했다.

HTTP에서 검증한 계정/client를 사용한다. 재생 자문 잠금 뒤 현재 그래프 등급·활성 상태, 활성 등록의 계정/client 결합을 검사한다. 최초 적용은 현재 계정 플랜을 받아 저장 트랜잭션 안에서 그래프 수·본문 저장량·생성/수정 빈도를 검사한다. 재생은 기대 판·한도·감사·색인 등록을 다시 적용하지 않는다.

입력은 같은 공개 스키마로 검증하고 UUID 표기를 통일한다. 수정은 생략·빈 설명·명시 null을 구분하며 현재 값에 병합한다. 원천 자연 키와 불변, 파생의 불변 근거·대체, keep, 사건 구성·시간, 관계 정체성·정규화·재확정, 현재 삭제 채널에 따른 복구를 기존 저장 API로 연결한다. 판단 입력 생략 시 request_id를 제외한 정규화 도구·인자를 기록한다.

성공은 graph/node/relation의 snake_case 객체·문자열 UUID·UTC 시각이다. 도메인 거부는 고정 메시지와 필요한 등급·위반 필드·현재 판·한도·대체 채널을 보존한다. 구조화 결과와 텍스트 값은 같으며 SDK가 complete 외피를 붙인다. 내부 저장 오류에 필드 오류가 들어 있어도 DependencyFailure가 우선하여 입력 거부로 저장하지 않는다. 원인은 Unwrap으로 보존하고 응답에 원문을 싣지 않는다.

최초 결정적 거부는 도메인 저장점 롤백 뒤 관리 거부 기록과 완료 JSON을 같은 바깥 재생 트랜잭션에 저장한다. 생성/확정 거부는 대상을 비우고 기존 노드 거부는 조회한 판 또는 충돌 오류의 현재 판을 기록한다. 결과 저장·커밋·거부 감사 실패는 내부 오류이며 예약·업무·누계·빈도·감사를 함께 롤백한다.

## 검증

- Go 1.27.1, 공식 MCP Go SDK v1.8.0. 외부 근거와 반영 위치는 [reference](../reference.md)에 기록했다.
- MCP 전체 360건, 선별 서버 39건, 부모 시험 포함·중복 제외 총 **399건 통과, 건너뜀 0건**, race 통과.
- 서버는 MCP-06 36건, 기존 Bearer 결합·MCP-02 보호 TLS 2건, 패키지 경계 1건이다. 패키지 경계는 실제 import와 SDD 허용표를 대조한다.
- 실제 DB에서 여덟 도구의 최초/다른 인스턴스 재생/새 키, 같은 키 다른 인자, 16건 동시 적용을 확인했다. 정점·간선·판 이력·그래프·권한·감사·색인 큐·빈도·재생 행을 비교해 재생 중복이 없음을 검증했다.
- 원천 자연 키와 갱신 거부, keep의 판 유지·판단 입력, 대체 간선, 사건 종료 null·다른 계층 필드 거부, 무방향 관계 정체성·시간 제약, 웹 삭제의 대체 복구 채널을 확인했다.
- 유한한 그래프 수·저장 문자 수·쓰기 빈도와 이미 한도를 넘은 상태의 축소, 플랜이 완화되어도 같은 키의 최초 한도 거부 재생을 확인했다.
- 실제 자문 잠금 대기를 pg_stat_activity에서 관찰하고 대기 중 실제 그래프 등급 회수·등록 폐기·취소를 적용했다. 이전 성공 결과가 노출되지 않고 판이 유지되며 종료 뒤 열린 트랜잭션이 없고 후속 쓰기가 완료됨을 확인했다. 모든 풀 자리 반환의 직접 측정을 대신하는 주장으로 확대하지 않는다.
- 결과 UPDATE·지연 COMMIT·거부 감사 INSERT를 각각 실패시켜 모든 업무 상태·예약의 롤백과 같은 키 재시도를 확인했다. 완료 거부 재생에서 감사가 중복되지 않았다.
- 실제 OAuth 코드 교환/Bearer·TLS·서버 라우터·SDK로 그래프 생성/노드 수정과 재생·새 키 판 충돌·401·no-store·자격 비노출을 확인했다. 이 표본의 다른 여섯 도구는 호출하면 실패하는 시험용 처리기이며 전체 14종 기동 인수가 아니다.
- 의존성 확인·전체 `go build ./...`·`go vet ./...`·`gofmt -l .` 통과. 변경 문서 10개·로컬 링크/앵커 337개와 Markdown을 검사해 발견 사항이 없었고, 작업 124개 중 완료 65개·미착수 59개를 대조했다. DOX pass도 수행했다.

초기 로컬 HTTP 수신 시험은 샌드박스의 수신 제한으로 중단되어 허용된 실행 경계에서 재실행했다. TLS 표본의 초기 authz 구성에서 bcrypt 비용 누락을 고친 뒤 해당 표본과 관련 기존 모듈 시험을 다시 통과했다. 실패·미실행을 통과 수에 포함하지 않았다. 문서 수정용 임시 명령의 문자 인코딩 오류는 파일 변경 전에 중단되었고 ASCII 전송으로 복구했다.

DB 시험마다 임의 이름의 suite DB를 만들고 정식 마이그레이션을 적용했다. 각 시험의 자식 DB만 사용했으며 모든 실행에서 소유 DB 정리·suite 부재를 확인했다. 기존 개발 DB·볼륨·적용 이력은 변경하지 않았다.

## 남은 범위와 DOX pass

다섯 읽기 도구·기동 경로의 전체 처리기 조립은 MCP-07, 인증/전송/도메인 오류 전체 계층·시간 예산/단절 통합은 MCP-08, 전체 서버 스냅샷·계약은 MCP-09, 실제 호스트는 TEST-08의 범위다. main에 임시 업무 처리기를 주입하지 않았다. 키 없는 쓰기의 불확정 결과는 여전히 재조회가 필요하다.

소유 SDD와 개발 계획·완료 근거·상태 진입점·요청/근거 기록·README를 갱신했다. 새 디렉터리·소유권·요구사항·프로젝트 용어·물리 스키마는 추가하지 않아 DOX 색인·SRS·용어집·마이그레이션은 유지했다. 사용자 Compose·IDE 변경을 보존했고 pull·commit·push·PR 갱신·배포는 하지 않았다.
