# #183 진단 정리 회차 오류의 종료 고착 검토

- 대상: [이슈 #183](https://github.com/Alpha-gone/agent-context-sharing/issues/183).
- 기준: `dev`의 `c89682a`, 브랜치 `fix/183-maintenance-error-scope`.

## 항목별 처리

| 항목 | 처리 | 내용 |
|---|---|---|
| 과거 회차 오류의 `StopMaintenance` 고착 | 처리 | 회차 오류를 영구 보존하던 `maintenanceErr`를 종료가 중단한 진행 회차의 비취소 오류로만 설정한다. 이미 끝난 회차의 실패는 작업자 정리 결과가 되지 않는다. 진행 회차의 동반 실패를 작업자 정리에 전달하는 기존 계약은 유지한다. |
| DB 실패와 파일 실패 구분 | 처리 | 정리 실행 자체가 반환한 오류만 파일 장애로 보고 stderr 장애 통지·첫 기록 오류에 반영한다. guard의 예약·연결·자문 잠금 실패와 마감은 `MaintenanceFailures`에만 세고, 조립 지점의 guard가 이미 남기는 주기 작업 진단 `store_unavailable`·`deadline_exceeded`를 원인으로 둔다. |
| 과거 실패 뒤 정상 종료 | 처리 | 작업자 정리가 nil을 반환해 조건부 풀 종료가 실행되고, 첫 기록 오류에 DB 실패가 남지 않아 기록기 종료와 프로세스 종료 결과가 과거 회차로 실패하지 않는다. |

정본은 [진단 정리의 실행 범위](../sdd/operations.md#진단-정리의-실행-범위)·[기록기 정리](../sdd/observability.md#회전보존과-총상한)·[시험 설계](../sdd/testing.md#테스트-계층)에 반영했다. 실행권 마감을 `MaintenanceFailures`와 기존 오류·알림 경계로 보고하던 정본 문장은 DB 실패를 주기 작업 진단으로 남기는 계약으로 바꿨다. 기존 시험 두 개의 기대값도 이 계약에 맞췄다. 진행 회차의 guard DB 실패는 작업자 정리에는 반환하되 기록기 종료 오류에는 넣지 않고, 실행권 마감은 기록기 종료 오류로 반환하지 않는다. 진행 회차의 파일 실패는 두 결과 모두에 남는지 함께 확인한다. 공개 API·구성·스키마는 변경하지 않았으며 DOX pass에서 소유권·경로 변경이 없어 기존 DOX를 유지했다.

## 재현과 검증

- 기존 코드에서 새 회귀 시험의 실패를 재현했다. guard DB 실패(`database unavailable`) 회차 뒤 성공 회차에서 stderr 장애 통지가 1건 집계됐고, 파일 실패 회차 뒤 성공 회차에서 `StopMaintenance`가 과거 `file_invalid` 오류를 반환했다.
- 수정 후 두 경우 모두 `StopMaintenance`가 nil이다. DB 실패는 회차 실패 1건·장애 통지 0건·기록기 종료 성공이고, 파일 실패는 회차 실패·장애 통지 1건과 기록기 종료 오류로 남는다.
- 서버의 정리 회차 진단 분류(완료·잠금 건너뜀·DB·파일·마감·취소)를 고정하는 시험을 추가했다. 기존 분류를 고정하는 시험이며 수정 전에도 통과한다.
- Go 1.27.1과 고정 이미지 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`(PostgreSQL 18.6)의 전용 합성 컨테이너에 정식 7개 마이그레이션(vector(8))을 적용했다. 기존 개발·다른 시험 DB는 사용하지 않았다.
- `TEST_DATABASE_REQUIRED=1 go test -race -p 1 -json ./internal/diagnostic ./cmd/server -count=1 -timeout=25m`에서 진단 218건, 서버 704건이 실패 없이 통과했고 서버의 환경 인수 21건은 기존과 같이 건너뛰었다. 건너뛴 인수를 통과로 보고하지 않는다.
- `GO_BINARY=… sh internal/diagnostic/test-linux.sh`의 Linux 기록기 전체·읽기 전용 마운트·컨테이너 재생성·슬롯 교체 인수가 통과했다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check`와 변경 문서의 로컬 링크·앵커를 확인했다.
- 시험 종료 후 시험 DB 외 임시 DB와 idle transaction 잔류가 없음을 확인하고 소유 컨테이너만 정리했다. 기존 개발·다른 시험 자원과 개인 IDE 파일은 유지했다.
