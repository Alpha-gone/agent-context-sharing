# #188 출처 해석의 임베딩 접근 기록 제거

- 대상: [이슈 #188](https://github.com/Alpha-gone/agent-context-sharing/issues/188).
- 기준: `dev`의 `b1b8377`, 작업 브랜치 `fix/188-origin-access`.

## 원인과 변경

`ContextOriginKinds`가 `DERIVED_FROM`·`HAS_MEMBER`의 조상을 읽을 때 공개 `ContextsByIDs`를 사용하여 `touchEmbeddings`를 함께 실행했다. 실제 검색 후보나 응답에 없는 조상까지 `last_accessed_at`이 갱신되고 cold 행이 hot으로 승격되었다.

같은 `enterHopReadScope` 안에서 `contextsByIDs(ctx, s.reader(ctx), ...)`를 사용하여 접근 기록 없이 정점·참조를 조립한다. 깊이별 일괄 처리·방문 공유와 그래프/정점 검증 및 읽기 스냅숏은 유지한다. 내부 호출 오류에는 기존 공개 묶음 조회의 `writeFailure("context_batch")`를 적용해 드라이버 오류의 StorageError 타입·원인 추적·상세 정보 비노출을 보존한다. 공개 묶음 조회·검색 후보 조립·홉 조회의 정상 접근 기록은 변경하지 않았다.

기존 접근 기록 대상 요구사항을 [저장 계층화](../sdd/data.md#저장-계층화)에 구체화하고 [테스트 설계](../sdd/testing.md#테스트-계층)에 회귀 범위를 반영했다. 새 API·설정·스키마·라이브러리 의존을 추가하지 않았다. DOX pass에서 구조·소유권·색인 변경이 없어 기존 DOX를 유지했다.

## 검증

Go 1.27.1과 별도 합성 PostgreSQL/AGE 컨테이너를 사용하고 `TEST_DATABASE_REQUIRED=1`로 DB 건너뜀을 금지했다. 기존 개발·다른 시험 컨테이너와 DB는 사용하지 않았다.

- 수정 전 신규 DB 회귀의 vector·halfvec × 출처 단독 조회·실제 일반 흐름·실제 스냅숏 흐름 6개 사례에서 접근 시각 변경 및 불필요한 cold→hot 승격을 재현했다.
- 수정 후 출처·접근/오류 회귀는 race에서 14건 통과했다. 사건→파생→파생→원천 구조에서 기존 cold/hot 조상의 접근 시각·계층 불변, 파생/사건의 출처 결과, 후보 세 채널 및 응답의 단일 대상, 응답 대상의 접근 기록과 공개 묶음 조회의 승격을 확인했다.
- 독립 검토에서 기존 스냅숏 시험의 출처 접근 기록 기대를 발견하여 접근 기록 장애와 무관한 출처 조회 성공으로 수정했다. PostgreSQL 오류 및 취소 오류의 기존 정규화 누락을 별도 대역으로 재현한 뒤 원인 추적과 상세 비노출을 보완했다. 독립 재검토에서 추가 결함은 발견되지 않았다.
- 최종 `go test -race -p 1 -json ./internal/store ./internal/search -count=1 -timeout=15m` 필수 DB 인수에서 저장소 1,736건(459.204초)·검색 342건(7.159초)이 실패·건너뜀 없이 통과했다. 하위 사례를 포함한 건수다. 예비 전체 실행은 시험 기대와 오류 경계 보완 후 중단하고 새 합성 DB에서 최종 바이너리로 재실행했다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check` 및 `go test ./cmd/server -run '^TestPackageDependenciesMatchDesign$' -count=1` 통과. 데이터·시험 설계·외부 근거·이 문서의 상대 링크/앵커 188개를 검증했다.
- 임시 시험 DB 잔류 없음·idle transaction 0개를 확인한 뒤 컨테이너 및 익명 볼륨의 생성 식별자를 대조하여 정리했다. 생성 컨테이너·볼륨 잔류 없음을 확인했고 기존 자원·개인 IDE 파일은 보존했다.

원시 증거는 `/tmp/acs188-red.log`, `/tmp/acs188-error-red.log`, `/tmp/acs188-green-final.json`, `/tmp/acs188-modules-final.json`에 보관한다. 공개 서비스 배포와 운영 계층 이동은 이번 검증 범위가 아니다.
