# #300 Claude Code localhost callback 검토

- 요청: [#300](https://github.com/Alpha-gone/agent-context-sharing/issues/300)을 별도 브랜치에서 처리하고 PR을 생성한다.
- 기준: dev의 DCR 전용 전환 이후 코드. 이슈 작성 당시의 사전 등록 환경 변수는 복구하지 않는다.
- 결정: 유효한 명시 포트를 가진 소문자 localhost HTTP callback을 DCR에서 허용하되 원문 전체를 완전 일치로 대조한다. IP literal과 치환하거나 localhost의 포트를 바꾸어 허용하지 않는다.

## 변경과 근거

`validRegistrationCallback`은 HTTP의 허용 호스트에 정확한 localhost를 추가한다. 기존 인가의 원문 대조를 재사용하고 sameLoopbackCallback의 IP 파싱은 그대로 유지하여 localhost에 포트 예외가 적용되지 않게 한다. DNS 조회나 서버 주소 해석은 추가하지 않는다. `127.0.0.1`·`::1`의 same_ip·exact와 HTTPS callback의 기존 동작은 유지한다.

SRS FR-147·인증 확정 결정, 인증·운영·시험 설계와 README·두 환경 예시를 갱신했다. Claude Code는 client ID 없이 --callback-port를 지정하여 DCR로 등록한다. [공식 근거](../reference.md#claude-code-localhost-callback-300-2026-11-02)에는 RFC 8252의 IP literal 권고와 호스트 호환성 예외의 선택 이유를 남겼다.

## 검증

- Go 1.27.3의 go build ./...·go vet ./...·gofmt -l .와 변경 문서의 링크·앵커·코드 블록, git diff --check를 통과했다. DCR·OAuth 경계의 race 검사와 필수 DB 설정의 관련 분야 시험도 통과했다. 같은 시험 회차에서 실제 Codex 0.165.0 DCR 초기 흐름을 유지함을 확인했다.

- `TestDCRLocalhostCallbackRequiresExactMatch`: 변경 전 invalid_redirect_uri 실패를 확인한 뒤 등록 성공과 다른 포트·IP·경로·query, 대소문자/후행 점 변형 거부를 확인했다. localhost 하위 이름·사용자 정보·fragment·잘못된 포트도 거부한다.
- 인증 모듈 전체 시험으로 기존 IP literal·Codex 경계와 DCR 자원 보호를 확인했다.
- `TestLocalhostCallbackConsentAndTokenIntegration`: 격리 DB와 TLS에서 DCR 등록, 잘못된 callback의 무리디렉션 거부, 로그인 세션의 동의 화면·명시적 동의, 원문 localhost callback의 state·iss 보존, 다른 포트의 코드 교환 거부, 정상 교환·Bearer 계정 검증을 통과했다.
- `TestLocalhostClaudeCodeRegistrationIntegration`: 실제 Claude Code 2.1.316에서 DCR 201과 client ID·localhost:49153 callback·resource·S256을 사용한 인가 URL 생성을 통과했다. macOS 임시 PTY와 CLAUDE_CONFIG_DIR·시험 전용 CA·DB·TLS 서버만 사용하고 사용자 전역 설정·자격은 변경하지 않았다.
- 실제 CLI는 --no-browser에서 터미널을 요구하므로 macOS script의 PTY를 사용한다. OSC 8 hyperlink의 제어 문자를 경계로 URL을 포착한다. 종료 시 Ctrl-C·입력 닫기·취소·Wait로 시험 프로세스를 수거한다.
- 독립 읽기 전용 검토에서 Critical/Important 결함은 발견되지 않았다.

## 검증 경계

실제 CLI 시험은 discovery→DCR→인가 URL까지다. Claude Code의 실제 브라우저 로그인·동의·callback 수신·토큰 저장·MCP 도구 호출은 실행하지 않았다. 서버의 동의·코드 교환은 별도 HTTP/DB 통합 시험 근거이며 실제 호스트 전체 인수를 대신하지 않는다. 운영 배포도 수행하지 않았다.

DOX 소유 경계는 기존 authz·server·명세·운영 안내와 동일하여 새 DOX는 만들지 않았다. 스키마 변경이나 새 마이그레이션은 없다.
