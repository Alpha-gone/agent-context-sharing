# #177 평가 실행기 낮음 등급 검토

- 대상: [이슈 #177](https://github.com/Alpha-gone/agent-context-sharing/issues/177).
- 기준: `dev`의 `e401630`, 작업 브랜치 `fix/177-eval-runner`. 이슈의 행 번호는 비공개 `3b93aba` 기준이므로 현재 코드에서 항목별로 다시 확인했다.

## 항목별 처리

| 항목 | 처리 | 내용 |
|---|---|---|
| 제공자 HTTP timeout을 시험 기한 초과로 분류 | 처리 | 실패 묶음의 `deadline_exceeded`를 시험 기한이 실제로 지난 경우로 한정한다. 기한 전 감싼 마감 오류는 단계 원인 코드(`execution_failed` 등)로 남는다. |
| 시험 ID 존재 확인이 예약보다 먼저 실행 | 처리 | 예약 디렉터리를 먼저 만든 뒤 기존 결과를 확인하고, 결과가 있으면 자기 예약만 해제한다. 다른 실행의 예약은 지우지 않는다. |
| 입력 복사·공개 단계의 종료 신호 | 처리 | manifest 실행 전체에 `signal.NotifyContext`를 걸고 실행 본문을 `runManifestTrialContext`로 분리했다. 신호는 프로세스를 즉시 끝내지 않고 입력 스냅숏 뒤·실행 뒤 단계에서 `cancelled`로 멈추어 `finish`가 예약과 비공개 입력 사본을 정리한다. 512 MiB 이하 파일 하나의 복사 도중에는 끊지 않고 그 파일 복사가 끝난 뒤 멈춘다. |
| 시험 실패 원인이 로컬 로그에 남지 않음 | 처리 | `trialError.Error()`가 원인 코드 뒤에 내부 원인을 붙인다. 공개 failure.json은 계속 코드만 기록한다. 실행기의 기존 비 manifest 경로도 로컬 로그에 원문 오류를 남기는 관례와 같다. |
| 변환 모드가 검증 전에 출력을 덮어씀 | 처리 | 출력 경로 중복을 변환 전에 거부한다. 컨텍스트·질의·공격 표본을 메모리에서 먼저 검증하고, 같은 디렉터리의 임시 파일에 써서 다시 읽은 검증까지 통과한 뒤에만 rename으로 교체한다. `writeDataset`도 임시 파일과 rename을 쓴다. |
| 적대·지속 평가의 측정 실패가 cleanup으로 보고 | 처리 | 측정 실패를 정리보다 먼저 `measurement`로 기록하는 정리 경계를 `releaseEvaluationGraph`로 묶어 공통 경로·적대 평가·지속 평가가 같이 쓴다. |
| 지속 평가 망각 만료 시각이 벽시계 기준 | 처리(제안과 다름) | 이슈는 `continualAsOf` 기준 고정값을 제안했지만, 의미·키워드 채널의 기본 유효성은 `AsOf`가 아니라 실제 현재 시각으로 판정한다(`internal/search/search.go`). 고정값(2029-12-31T23:00Z)으로 바꾸면 현재 실행에서 기본 검색이 만료 파생을 제외하지 못해 DB 시험 2건이 실패했다. 만료 시각을 현재 시각과 고정 조회 시각 중 이른 쪽의 1시간 전으로 둔다. |
| 확장 업무 과업 판정이 재색인 생략까지 보류 | 처리 | 명세는 보류 조건을 "준비 시간·토큰·총비용 미측정"으로 정하고 `reindex_ms` 생략(-1)을 허용 입력으로 정한다. 재색인 시간만 완전성 요구에서 빼고 실제 표본 수는 결과에 그대로 남긴다. 준비 시간 등 다른 미측정은 계속 보류한다. |
| 적응형 반복 평균의 -1 혼입 | 처리 | 회차별 품질 지표를 자리마다 정의된 값만 평균하고, 어느 회차에서도 정의되지 않으면 미정의 값으로 남긴다. 수정 전 코드는 `[0.5, -1]` 회차를 `-0.25`로 평균했다. |

정본은 [평가 모드·변환](../sdd/evaluation.md#검증을-가능하게-하는-설계)·[지속 평가](../sdd/evaluation.md)·[결과 묶음](../sdd/evaluation.md#반복통계와-실행-순서)·[확장 과업](../sdd/evaluation.md#에이전트-업무-비용과-축소-비교)·[시험 설계](../sdd/testing.md#테스트-계층)에 반영했다. 새 구성 값·스키마 변경은 없다. DOX pass에서 구조·소유권·색인 변경이 없어 기존 DOX를 유지했다.

## 회귀와 검토

Go 1.27.1, 고정 PostgreSQL/AGE 이미지 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`의 전용 합성 컨테이너에 vector(768)·vector(128)·halfvec(768) DB를 만들고 정식 7개 마이그레이션을 적용했다. `TEST_DATABASE_REQUIRED=1`로 DB 건너뜀을 금지했다. 기존 개발·다른 시험 DB는 사용하지 않았다.

- 기준 `e401630`의 저장소 안 임시 worktree에 새 단위 시험 6개를 옮겨 실패를 재현했다. 로컬 원인 누락, 기한 전 제공자 timeout의 `deadline_exceeded`, 다른 실행의 예약보다 기존 결과를 먼저 본 `trial_id_exists`가 나왔다. 같은 출력 경로 변환은 기존 `contexts.json`을 질의 파일로 덮어쓴 뒤 실패했고, 재색인 생략은 `usage_or_cost_unmeasured`, 적응형 평균은 `-0.25`였다. 중복 질의 id는 변환 함수가 아니라 새 메모리 검증에서만 걸리는 것을 별도로 확인했다. 취소 정리·측정 단계 시험은 새로 분리한 함수를 사용하므로 기준 코드에서 같은 방식으로 실행하지 않았다.
- 새 시험은 취소된 context로 입력 스냅숏 뒤 측정 없이 `cancelled` 실패 묶음만 남고 예약·임시 입력이 없어지는지, 직접 준비한 평가 그래프의 측정 실패가 `measurement`·정리 완료로 보고되는지 확인한다. 망각 만료 시각의 2030년 이후 동작은 실제 시계를 바꿀 수 없어 재현하지 않았고 기존 지속 평가 DB 시험의 현재 시각 판정으로 회귀를 확인했다.
- 최종 `go test -race -p 1 -json ./cmd/eval -count=1 -timeout=40m`에서 878건이 실패·건너뜀 없이 통과했다(263.698초). 건수는 하위 사례를 포함한다. 망각 만료 시각을 고정값으로 바꾼 첫 실행에서는 `TestContinualScenarioContractsIntegration/forgetting`과 `TestEvaluationCommandCleanupFailsExitIntegration/normal/2`가 `default_excludes_expired_and_discarded=false`로 실패하여 위 판단으로 수정했다.
- 시험 뒤 활성 평가 그래프 29개가 남았다. 이 DB에서 전체 실행 2회와 정리 거부 시험을 포함한 부분 실행 1회를 했으며, 이름별 수(지속 3·eval03 18·대화 2·적대 6)가 [#200 검토](2026-10-31-issue-200.md)에서 기준 코드로 확인한 1회분 정리 거부 시험 잔류의 합과 같다. idle transaction은 0개였다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check` 통과. 변경 문서의 상대 링크·앵커를 확인했다.
- 소유 컨테이너·익명 볼륨과 기준 비교용 worktree를 정리했고 잔류 없음을 확인했다. 기존 자원·개인 IDE 파일과 작업 전부터 있던 루트 `AGENTS.md` 편집은 이번 변경에 포함하지 않았다.
