# 권한·한도 개발 계획

[전체 계획](../DEVELOPMENT_PLAN.md) · [기준 SDD](../sdd/authorization.md) · [작업 추적](traceability.md)

## 목표와 구현 범위

계정과 그래프의 등급·팀 상속 및 플랜의 요청·누적 한도를 새로 구현한다. 인증된 agent는 별도 권한을 가지지 않는다.

- 설계 입력: [등급 검사](../sdd/authorization.md#등급-검사), [플랜 값](../sdd/authorization.md#계정-플랜-값), [직렬화](../sdd/context-lifecycle.md#판정의-직렬화), [SRS 플랜 항목](../SRS.md#플랜이-정하는-항목).
- 예정 구현 영역: `internal/perm`·`plan`, `internal/store`의 부여·팀·한도 트랜잭션.
- 다른 분야와의 경계: 자격 검증은 인증 계획, 유예 전이는 수명주기 계획, 부여·회수·팀 화면은 웹 계획이 소유한다.

## 개발 작업

### PERM-01

- [x] **플랜 14개 항목과 구성 검증을 구현한다.**
- 선행: [ARCH-02](architecture.md#arch-02).

1. SRS의 항목·기본값·적용 대상과 0의 한도 없음 의미를 구현한다. 기본 홉 4·노드 200·페이지 50/200·예산 20000자 등 확정값은 그대로 사용한다.
2. ACCOUNT_PLAN_LIMITS의 부분 객체, 양수 페이지 기본값·상한, 음수·목록 밖 키·보존 하한과 무기한 대상의 무기한 감사 보존을 검사한다.
3. 계정 식별자를 정규화한 뒤 중복 키를 거부한다. 입력 순서·맵 순회·값의 동일 여부로 임의 선택하지 않는다.

- 산출물: `plan`의 항목·기본값·증가 판정·JSON 검증과 경계 표본.
- 완료 기준: 14개 밖의 플랜 값이 열리지 않고 같은 계정의 표기만 다른 키가 구성 해석 단계에서 거부된다. 값·정책의 미확정 선택은 임의로 확정하지 않는다.

- 완료 근거: 2026-10-15 [플랜 구성·기간 모듈 시험](../reviews/2026-10-15-perm-01.md). 14개 항목·기본값·부분 객체·명시한 0, 정수/페이지/보존 제약과 정규화한 계정 키의 선검사를 구현했다. 기본 거부 보존은 SRS의 달력 6개월로 표현하고 명시한 일수와 구분한다. 플랜 187건·기간 전달 2건의 DB 없는 모듈 시험, race·전체 build·vet·형식 검사가 통과했다. 저장소 한도 경합·실제 감사 삭제·환경 구성 인수는 후속 PERM·OPS·ARCH 작업에서 수행한다.

### PERM-02

- [x] **현재 유효 등급 조회·검사를 구현한다.**
- 선행: [ARCH-03](architecture.md#arch-03), [DATA-03](data.md#data-03).

1. 직접 계정 등급과 활성 팀 구성원 상속을 한 질의로 읽고 owner/editor/viewer의 높은 등급을 적용한다.
2. 등급 없음·대상 없음은 not_found, 접근 가능한 대상의 등급 부족만 permission_denied로 나눈다.
3. graph_list는 권한 있는 결과만 거르고 graph_create는 기존 그래프 등급 검사를 요구하지 않는다. agent·토큰의 scope를 그래프 등급으로 사용하지 않는다.

- 산출물: 저장 등급 조회와 주입 인터페이스를 쓰는 `perm` 검사기.
- 완료 기준: 직접·팀·중복 상속·삭제 팀·무권한 계정 조합이 매 요청 현재 상태로 판정되고 상대 그래프 존재가 노출되지 않는다.

- 완료 근거: 2026-10-17 [현재 유효 등급 모듈 시험](../reviews/2026-10-17-perm-02.md). 권한 검사와 저장 조회에서 UUIDv7 경계를 검증하고 주입 저장소의 잘못된 반환 등급을 권한 부족과 구분해 거부했다. 새 격리 DB에서 직접·활성 팀 등급 16개 조합, 중복 상속·삭제/빈 팀·다른 계정의 제외, 한 질의 집계·부재/등급 부족 분기와 회수·팀 상태 변경의 즉시 반영을 확인했다. 권한 있는 목록만 반환하고 무등급 계정의 그래프 생성·소유자 부여, SQL 취소 뒤 4연결 풀·예약 회복도 검증했다. 고유 시험·하위 시험 55건·race와 전체 build·vet·형식 검사가 통과했다. 전송·실제 토큰·웹 화면 및 등급 변경 API의 신규 인수는 후속 범위다. PERM-03/04는 LIFE-06이 선행하므로 다음 권장 항목은 선행이 준비된 [PERM-05](#perm-05)다.

### PERM-03

- [ ] **등급 부여·회수·작업 인계를 구현한다.**
- 선행: [PERM-02](#perm-02), [LIFE-06](context-lifecycle.md#life-06).

1. 웹 전용 계정·팀 부여와 회수를 구현하고 그래프 잠금 뒤 행위자의 현재 소유자 등급·활성 대상 팀을 다시 확인한다.
2. 회수 뒤 소유자 등급을 쓸 계정이 남는지 직접·상속을 함께 세어 마지막 소유자 제거를 거부한다.
3. 다른 계정에 소유자 등급을 주는 같은 부여 경로로 인계를 수행하고 감사 기록·유예 재연결 판정을 한 트랜잭션에 넣는다.

- 산출물: 부여·회수·인계 저장 API와 현재 소유자 재확인.
- 완료 기준: 병행 마지막 소유자 회수 중 하나만 성공하고 잠금 대기 중 등급을 잃은 행위자의 변경·감사가 커밋되지 않는다.

### PERM-04

- [ ] **팀 생성·구성원·소프트 삭제·복구를 구현한다.**
- 선행: [PERM-02](#perm-02), [LIFE-06](context-lifecycle.md#life-06).

1. 인증 계정의 팀 생성·관리자 고정과 관리자 범위 구성원 추가·제거·조회·정렬을 구현한다.
2. 팀 삭제·복구는 상태만 바꾸고 구성원·부여를 보존한다. 삭제 팀의 상속은 무효이며 다른 관리자의 구성원은 반환하지 않는다.
3. 구성원 제거·삭제로 영향받는 그래프를 ID 오름차순으로 잠그고 마지막 접근 계정·유예를 판정한다. 빈 팀·삭제 팀의 부여는 유예를 취소하지 않는다.

- 산출물: 팀 API·관리자 범위 조회와 다중 그래프 잠금 시험.
- 완료 기준: 그래프 없는 계정도 팀을 만들고, 팀 구성·삭제가 접근에 즉시 반영된다. 두 팀의 겹친 그래프 변경에서 교착·잘못된 유예가 없다.

### PERM-05

- [ ] **요청·누적 한도를 쓰기와 함께 판정한다.**
- 선행: [PERM-01](#perm-01), [DATA-03](data.md#data-03).

1. 홉·노드·페이지·예산 요청 한도를 입력 경계에서 적용하고 누적 증가 여부를 저장소의 같은 쓰기 트랜잭션에서 판정한다.
2. 한도가 있는 그래프 생성은 계정 행 잠금 뒤 별도 명령으로 활성 소유 그래프 수를 센다. 서로 다른 멱등성 키도 바깥 커밋까지 직렬화한다.
3. 생성·본문 수정·노드 복구의 활성 문자 수 증분을 저장량 누계에 대조한다. 웹 복구도 요청 계정 플랜을 전달한다.
4. 상향은 즉시 반영하고 하향 후에는 읽기·축소를 허용하되 추가 증가를 거부한다. 초과 항목·현재/허용 값을 안전하게 반환한다.

- 산출물: 요청·누적 한도 판정과 원자적 증가 API.
- 완료 기준: 한도 직전 병행 쓰기 중 허용 수만 성공하고 누계가 실제 활성 본문과 맞는다. 초과분 삭제·자동 과금은 발생하지 않는다.

### PERM-06

- [ ] **계정별 쓰기 빈도와 보존 조건을 구현한다.**
- 선행: [PERM-01](#perm-01), [DATA-03](data.md#data-03).

1. 제한 계정의 컨텍스트 생성·수정에만 1분 고정 창 카운터를 같은 트랜잭션에서 갱신한다.
2. 한도 없는 계정은 카운터를 만들지 않고 읽기 요청은 세지 않는다. 멱등성 재생은 최초 카운터를 다시 늘리지 않는다.
3. 판정 시점의 플랜 값을 쓰고 이미 기록한 유예 만료를 변경 후 소급 계산하지 않는다. 적용 감사·거부 기록의 다른 보존 조건을 운영 정리에 전달한다.

- 산출물: 카운터·보존 정책 인터페이스와 시간 창 표본.
- 완료 기준: 경계·동시 증가·롤백·한도 없음·재생·플랜 변경이 SDD와 일치한다. 공개 로그인 시도 예산과 이 쓰기 카운터를 혼합하지 않는다.

### PERM-07

- [ ] **등급·팀·한도 전체 행렬을 인수한다.**
- 선행: [PERM-03](#perm-03), [PERM-04](#perm-04), [PERM-05](#perm-05), [PERM-06](#perm-06).

1. 등급별 업무 연산·웹 관리와 graph_create/list 예외를 표로 검증한다.
2. 직접/상속 중복, 유일한 소유자 팀의 여러 구성원, 빈/삭제 팀, 권한 회수·재연결을 대조한다.
3. 부여·한도·감사·유예 실패를 주입하고 변경과 기록의 롤백 및 연결 회복을 검사한다.

- 산출물: 권한·한도 인수 결과와 웹 회수 안내에 전달할 판정 API.
- 완료 기준: 토큰 유효 중 권한 회수가 즉시 적용되고 모든 한도 거부가 해당 항목을 식별한다. 화면의 안내가 실제 잠금 뒤 판정과 같은 기준을 사용한다.
