# #201 사건 구성원의 집합 비교와 응답 순서

- 대상: [이슈 #201](https://github.com/Alpha-gone/agent-context-sharing/issues/201).
- 기준: `dev`의 `e36bd38`, 작업 브랜치 `fix/201-event-member-order`.

## 원인과 변경

`eventProposalInputChanged`가 정렬된 저장 조회의 구성원과 요청 순서의 구성원을 `slices.Equal`로 비교하여 집합이 같아도 후보 제안을 실행했다. 쓰기 응답도 요청 순서의 member_refs를 옮겨 조회 응답과 달랐다.

입력 slice와 공유하지 않는 정렬 helper를 사건의 집합 비교와 공통 참조 조립 `attachReferences`에 사용한다. 생성·갱신·단일/묶음/홉 조회의 사건 구성원은 식별자 오름차순으로 응답한다. 파생 근거의 순서는 이번 변경에 포함하지 않았다. 구성원 순열과 본문만 바꾼 갱신은 제안을 생략하며, 실제 구성원 집합·시작·종료·진행 중 상태 변경은 기존대로 실행한다. 중복을 제거하지 않고 참조 검증·판 갱신·감사·멱등성 경계도 유지한다. 순서만 바꾼 요청의 일반 갱신 자체를 무효 연산으로 바꾸지는 않는다.

정본은 [사건 후보 제안](../sdd/context-lifecycle.md#관계-후보-제안과-확정)과 [시험 설계](../sdd/testing.md#테스트-계층)에 반영했다. 새 쓰기의 재생 결과는 정렬된 응답을 저장하고 이미 보관된 재생 결과는 원래 응답을 유지한다. 스키마·설정·새 공개 API는 추가하지 않았다. DOX pass에서 구조·소유권·색인 변경이 없어 기존 DOX를 유지했다.

## 회귀와 검토

Go 1.27.1, 별도 합성 PostgreSQL/AGE 컨테이너를 사용하고 `TEST_DATABASE_REQUIRED=1`로 DB 건너뜀을 금지했다. 기존 개발·다른 시험 DB를 사용하지 않았다.

- 수정 전 새 DB 시험에서 순서만 바꾼 갱신의 activeEventContexts 조회 1회(기대 0회), 생성/갱신 응답과 조회의 순서 불일치를 재현했다. 집합 비교 단위 시험의 permutation도 실패했다. DB와 실제 MCP 처리기로 수행한 생성·갱신·다른 저장소 인스턴스의 멱등 재생은 모두 요청 역순을 반환했고 node_get은 정렬되어 불일치했다.
- 수정 후 관련 DB/race는 저장소 77건·서버 6건이 실패·건너뜀 없이 통과했다. 실제 제안 입력 SQL을 tracer로 관찰하여 순열/본문 변경의 0회, 구성원 집합/시작/종료/진행 중 전환의 각 1회를 대조했다. 양성 대조는 단순히 tracer가 관찰하지 못해 0으로 통과하는 회귀도 막는다.
- 사건 생성·갱신·단일 조회의 참조 정렬과 호출자 slice 불변을 확인했다. 단위 시험은 순열·교체·추가·제거·중복 구성원 비교를 검증한다. MCP 재생은 첫 응답과 결정적 JSON으로 일치하고 업무·감사·재생 fingerprint를 바꾸지 않았다.
- 읽기 전용 독립 검토에서 수정이 필요한 결함은 발견되지 않았다. 검토자는 추가 DB 시험을 실행하지 않았다.
- 최종 `go test -race -p 1 -json ./internal/store ./internal/mcp ./cmd/server -count=1 -timeout=15m`에서 저장소 1,752건(445.094초)·MCP 480건(10.185초)이 실패·건너뜀 없이 통과했다. 서버는 693건 통과·1건 실패·21건 건너뜀(111.446초)이다. 건너뜀은 별도 CLI 19건·물리 복구 1건·이전 인수 1건의 환경 미설정이며 통과로 집계하지 않는다. 건수는 하위 사례를 포함한다.
- 서버의 유일한 실패 `TestOPS05DiagnosticFlushBudgetIntegration`은 기준 `e36bd38`의 context.go를 Go overlay로 적용한 단독 race 대조에서도 재현했다. 현재 2.001475917초·기준 2.001935292초로 동일한 최소 5초 기대에 실패한다. #184의 최대 128건 배치 이후, 이 시험의 12건(+기동 기록) 부하로는 최대 5초 flush 마감을 강제하지 못한다. 진단 구현의 최대 5초 계약은 유지되며 사건 갱신·정렬을 호출하지 않는 시험이다. 독립 재검토에서도 #201과 무관한 기존 fixture 문제임을 확인했고 저장소 범위 규칙에 따라 이번 변경에서 수정하지 않았다. 서버 전체를 통과로 판정하지 않는다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check` 통과. 수명주기/시험 정본·공식 근거·이 문서의 상대 링크/앵커 119개를 검증했다.
- 임시 DB 잔류 없음·idle transaction 0개와 생성 식별자를 확인한 뒤 소유 컨테이너·익명 볼륨을 정리했고 잔류 없음을 확인했다. 기존 자원·개인 IDE 파일은 보존했다.
