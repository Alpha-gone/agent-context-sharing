## 구현과 발견 사항

- 기존 명시 scope 우선순위, 기준 auto와 적응형 규칙을 유지했다. 적응형은 관련 후보 부재→사건→채널 일치→충분성/분리 폭→국소 경합 순서로 판정하며 같은 초기 후보만 사용한다.
- 환경 구성은 이미 유한 임계값만 허용하지만 검색 생성자의 의미 관련성·직접 충분성·분리 폭 검사는 `NaN`을 허용했다. 내부 서비스 구성이나 평가 구성을 직접 주입할 때 관련성/직접 경로 판정이 조용히 달라질 수 있다. 세 임계값에 `math.IsNaN` 검사를 적용해 기존 0~1 유한 수 계약을 일치시켰다. 비활성 적응형의 전용 임계값은 기존처럼 해석하지 않는다.
- 운영 예시의 `baseline`·전역 전환 `true`·적응형 `false`를 유지했다. 두 적응형 임계값을 임의로 정하거나 운영 기본값을 승격하지 않았다.

## 새 모듈 검증

- `routing_contract_test.go`의 여섯 최상위 시험은 새 하위 표본 114건을 포함한다. 미지정/auto/local/global, 네 그래프 단계, 전역 전환 on/off와 유효한 적응형 조합 56개에서 병렬/순차 응답을 대조했다. 명시 scope는 평가용 강제 경로보다 우선한다. 명시 global은 진입 채널·질의 임베딩을 호출하지 않고 요약만 시작점으로 삼아 `derived_from`을 요청한다.
- 관련 국소 후보가 없는 14개 구성 조합에서 기준 auto의 전역 전환 설정과 적응형의 독립 전역 선택을 대조했다. 전역 진입이 적용되면 시간 후보는 시작점에 섞이지 않으며, 최종 결합에는 남는다. 구성으로 끈 요약 조회는 `disabled`이고 실제 저장 호출을 하지 않는다.
- 다섯 규칙의 우선순위, 정확히 표현 가능한 유사도 0.875와 분리 폭 0.25의 경계, 그다음 float64 값의 하한 미달, 의미 후보 하나와 실패 채널을 대조했다. 사건/채널 일치·의미 충분성·경합·전역 선택의 경로와 이유가 실행 방식에 의존하지 않는다.
- 요약 부재는 성공 빈 채널이고 요약 조회 장애는 실패 채널로 유지한다. 적응형은 두 경우 직접 경로로 돌아가며, 기준 auto는 남은 국소 후보를 보존한다. 명시 global은 국소 후보로 돌아가지 않고 요약 부재는 빈 성공, 요약 채널 장애는 전체 실패다. 오류와 함께 반환한 요약·홉 후보를 채택하지 않는다.
- 진입 셋 모두 실패하면 라우터/요약 조회를 실행하지 않고 확장을 `no_entry_points`로 기록한다. 직접 경로는 그래프 미호출/`disabled`, 적응형 국소는 관련 의미·키워드만 시작점으로 한 홉을 요청한다. 시간/하한 미달 후보의 시작점 제외, 참조 단계의 세 필터·방향·노드 상한 전달을 확인했다.
- 세 평가용 강제 경로는 auto에서만 효력을 발휘한다. 공개 `FlowInput`과 서버 환경 허용 목록에는 강제 경로 필드/키가 없음을 코드로 대조했다. 성공 로그에는 경로·이유 코드가 있고 질의·본문·그래프 식별자 원문은 없음을 새 표본으로 확인했다. 모든 실패 로그의 비노출을 인수했다는 뜻은 아니다.
- 검색 생성자에서 세 임계값의 NaN·양/음 무한대·음수·1 초과·0/1 경계를 대조했다. 기존 설정 시험을 현재 실행해 적응형 기본 비활성·baseline 조합 거부·임계값 미설정/범위 오류·유한 수 검사와 비활성 전용 임계값 무시를 확인했다.
