# #240 전환 시험의 합성 이전 형상 검토

- 대상: [이슈 #240](https://github.com/Alpha-gone/agent-context-sharing/issues/240). [#185 검토](2026-10-31-issue-185.md)가 별도 기존 결함으로 분리한 실패다.
- 기준: `dev`의 `c9fab15`, 브랜치 `fix/240-transition-old-shape`.

## 원인과 변경

`test-transition.sh`(`d75ee6c`)는 현재 소스에서 `013_context_revision.sql`만 제외해 합성 이전 형상을 만들고 012에서 멈춘다고 가정했다. 이후 인덱스만 추가하는 `014_relation_query_scope.sql`(`10dd022`)이 생겨 이전 형상이 014까지 적용되고 "합성 이전 형상이 012가 아니다"로 실패했다. 실행기는 적용된 최대 번호 이하의 미적용 파일을 거부하므로 013만 제외하는 방식으로는 이후 013 적용도 성립하지 않는다. 실패 주입 파일 014·015도 정식 014와 번호가 충돌했다.

이전 형상은 전환 대상 013 이후의 번호를 모두 제외하고, 실패 주입 파일은 현재 최신 번호 뒤의 두 번호로 만든다. 새 형상 적용 뒤 최신 번호가 적용됐는지 확인하는 검사를 추가하고, 파일별 적용 이력·원본 DB 보존 검사와 출력도 계산한 번호를 사용한다. 새 마이그레이션이 추가되어도 같은 전환·실패 롤백·복귀 계약을 검증한다. [운영 안내](../../../../OPERATIONS.md#7-변경-및-복귀)의 전환 시험 설명을 실제 형상에 맞췄다. 운영 정본의 시험 설명은 번호를 고정하지 않아 유지했고, 구현·SQL·구성은 변경하지 않았다. DOX pass에서 소유권·경로 변경이 없어 기존 DOX를 유지했다.

## 재현과 검증

- 수정 전 전체 전환 시험은 이전 이미지의 적용이 `001→009→010→011→012→014`로 끝나 `합성 이전 형상이 012가 아니다`로 종료 코드 1이었다([#185 검토](2026-10-31-issue-185.md)).
- 수정 후 Go 1.27.1·Docker로 `GO_BINARY=… sh test-transition.sh`를 `rg`가 PATH에 없는 상태로 실행해 종료 코드 0과 `PASS: OPS-08 전환·파일 롤백·백업/이미지 복귀·자원 정리`를 확인했다. 이전 형상은 012에서 멈췄고 새 형상 적용은 013·014였으며 출력은 `transition: old=012 new=014 … repeat_noop=true failed_file_rolled_back=true earlier_file_preserved=true`, `restore: old_image=true schema=012 history_preserved=true …`다.
- 시험 종료 뒤 시험 프로젝트의 컨테이너·볼륨·네트워크·이미지와 임시 디렉터리가 남지 않았음을 확인했다. 기존 개발·다른 시험 자원과 개인 IDE 파일은 유지했다.
- `sh -n test-transition.sh`, `git diff --check`와 변경 문서의 로컬 링크·앵커를 확인했다. Go 코드 변경은 없다.
