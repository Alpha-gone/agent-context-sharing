## 새 비교 도구와 조건

[검색 인수 시험·벤치마크](../../../../internal/store/search_acceptance_integration_test.go)를 추가했다. 기존 전체 본문 BFS(`full`), 운영 양수 상한(`bounded`), 시험 전용 가변 길이 간선(`vle`)을 같은 시작점 재조회·읽기 전용 REPEATABLE READ·접근 기록 경계로 실행한다. 공유 표본과 비교 도우미의 인자를 `testing.TB`로 넓혀 시험과 벤치마크가 같은 표본을 사용하게 했다.

허브 1,000/20,000 이웃, 원천·파생·사건·확정 관계로 구성한 희소 100노드, 삭제 중간 노드·제안 관계·중복 시작점이 있는 혼합 표본, 16사건 사이 120개 확정 관계의 조밀 표본을 새로 만들었다. 마지막 표본은 10노드 상한에서도 내부 간선 45개가 모두 반환된다. 노드의 전체 속성·본문·참조·순서, 최단 거리, 내부 간선·방향, 절단 여부·최초 경계를 기준선과 대조한다. 기존 방향·필터·다중 시작점·무제한·63/64/65 전환·최대 참조·동시 폐기·공통 예산·취소·자원 회복 시험도 새로 실행했다.

환경은 Go **1.27.1 darwin/arm64**, Apple M4 Pro, PostgreSQL **18.6 linux/aarch64**, AGE **1.8.0**, pgvector **0.8.6**, 로컬 DB 이미지 **2b6d51048c03**이다. 정식 6개 마이그레이션의 기본 `agent_context`·vector(768)·all_layers를 사용했다. 별도 loopback/tmpfs DB이며 외부 임베딩 제공자를 호출하지 않는다.

지연·할당은 별도 새 DB에서 각 표본을 `ANALYZE`하고 동등성 확인으로 준비한 뒤 측정했다. 순서를 뒤집는 두 회차에서 구현별 5회씩 실행했다. 아래 범위는 **두 회차 평균의 최솟값~최댓값**이며 분위수·신뢰구간이 아니다. 26개 벤치마크 조건의 측정 호출은 총 130회다. 같은 표본의 반복을 독립 표본으로 세지 않는다. 앞서 만든 그래프 일부가 같은 label 테이블에 남으므로 작은 그래프만 있는 DB의 비용으로 해석하지 않는다.

## 전체 본문 기준선과 양수 상한

MB는 1,000,000바이트이며 B/op는 Go의 누적 할당량이지 최대 상주 메모리가 아니다.

| 표본 | full 지연 ms/op | bounded 지연 ms/op | full 할당 MB/op | bounded 할당 MB/op | SQL 명령 수 full→bounded |
|---|---:|---:|---:|---:|---:|
| 허브 1,000·상한 10 | 40.548~40.583 | 4.756~5.027 | 32.955~32.957 | 0.296~0.297 | 9→10 |
| 허브 20,000·상한 10 | 692.573~695.343 | 5.100~5.103 | 663.806~663.814 | 0.297 | 9→10 |
| 희소 100·2홉·상한 10 | 79.527~80.345 | 18.206~19.441 | 0.592~0.596 | 0.527~0.530 | 28→25 |
| 삭제/미확정·다중 시작·상한 6 | 46.459~46.497 | 13.186~13.354 | 0.272 | 0.339~0.342 | 21→23 |
| 조밀 16·1홉·상한 10 | 15.265~17.342 | 6.975~8.235 | 4.626~4.631 | 0.564~0.569 | 9→10 |

혼합 소형 표본에서는 bounded의 할당량과 왕복이 늘었다. 모든 조건의 모든 비용이 줄었다고 판정하지 않는다. 왕복은 pgx tracer가 본 SQL 명령 수이며 BEGIN/ROLLBACK·시작점·참조·접근 기록을 포함한다. 네트워크 패킷 수나 기존 `expansionQueries`와 다르다.

| 표본 | 식별자 행 full→bounded | 본문 행 full→bounded | 본문 UTF-8 바이트 full→bounded | 간선 행 full→bounded | 참조 행 양쪽 | 전체 SQL 반환 행 full→bounded |
|---|---:|---:|---:|---:|---:|---:|
| 허브 1,000 | 0→10 | 1,000→9 | 2,800,000→25,200 | 1,000→9 | 9 | 1,010→38 |
| 허브 20,000 | 0→10 | 20,000→9 | 56,000,000→25,200 | 20,000→9 | 9 | 20,010→38 |
| 희소 100 | 0→9 | 40→8 | 520→104 | 40→10 | 12 | 54→41 |
| 삭제/미확정·다중 시작 | 0→5 | 16→4 | 208→52 | 16→6 | 5 | 23→22 |
| 조밀 16 | 0→9 | 150→8 | 315,000→16,800 | 150→45 | 10 | 162→74 |

full의 본문/간선 행은 반복 방문·제외 후보도 포함한 이웃 행이고, bounded는 새 선택 본문과 반환 끝점 사이 간선 행이다. 식별자는 초과 확인 한 행을 포함한다. 선행 시작점 본문은 이 작업량에서 제외하지만 SQL 반환 행·할당·지연에는 포함한다. 본문 바이트는 프로토콜 전체 전송 바이트가 아니다. 조밀 간선은 노드 수의 선형 상한을 갖지 않으며 `limit=0`의 유한 메모리 상한도 주장하지 않는다.

## 실제 DB 행·버퍼

동등성 호출에서 읽은 SQL을 같은 불변 표본에 `EXPLAIN (ANALYZE, BUFFERS, TIMING OFF, FORMAT JSON)`으로 별도 재실행했다. 아래 값은 지연 벤치마크와 다른 실행이다. 관계 접근 행은 실제 행·필터 제외 행에 loops를 곱한 관측값이며 고유 정점/간선 수가 아니다. 버퍼는 각 질의 root만 합산한다. 접근 기록·트랜잭션 명령은 계획 재실행에서 제외한다.

| 표본/구현 | SQL에서 보이는 정점 접근 행 | 간선 접근 행 | shared hit/read | temp read/write | EXPLAIN 실행 합 ms |
|---|---:|---:|---:|---:|---:|
| 허브 1,000 full | 1,043 | 1,023 | 8,188/0 | 0/0 | 15.157 |
| 허브 1,000 bounded | 3,129 | 1,097 | 11,571/0 | 0/0 | 13.306 |
| 허브 20,000 full | 20,039 | 20,127 | 160,473/0 | 2,244/2,248 | 282.906 |
| 허브 20,000 bounded | 155 | 211 | 557/0 | 0/0 | 0.868 |
| 희소 full / bounded | 1,023 / 1,261 | 954 / 1,767 | 9,450/0 / 4,870/0 | 0/0 | 4.735 / 3.755 |
| 혼합 full / bounded | 97 / 90 | 679 / 875 | 4,233/0 / 383/0 | 0/0 | 2.307 / 1.447 |
| 조밀 full / bounded | 843 / 822 | 1,123 / 1,561 | 3,644/0 / 3,086/0 | 0/0 | 5.286 / 3.154 |

애플리케이션 적재 감소가 DB 내부 행 감소를 보장하지 않는다. 1,000 이웃·희소·조밀 표본은 일부 접근 행이 오히려 늘었다. VLE의 C 내부 캐시/인접 탐색은 SQL 계획에서 모두 보이지 않으므로 그 작업량은 미측정이며, 0으로 간주하지 않는다. 별도 1,000/20,000/50,000 이웃의 식별자 기준선/선택적 후보 계획·버퍼와 인덱스 쓰기 비용도 이번 홉 분야 실행에 포함했다.

## AGE 후보 적합성과 보류

공식 AGE MATCH 문서·PG18 1.8.0 release notes·최단 경로 SRF 구현 설명을 확인하고 고정 이미지에서 파서와 실행을 재검증했다. `shortestPath`·`allShortestPaths` 패턴과 `PRECEDES|CAUSES`는 `42601`로 거부됐다. snake_case 함수와 SQL SRF는 존재하며 label 문자열·배열을 구분하고 알 수 없는 label을 거부했다. 이전의 label 목록 무시 설명을 검색 정본에서 정정했다. 일반 `all()`은 동작하지만 `all(n IN nodes(p) ...)` 표본은 `XX000` 실행 계획 오류여서 경로 정점 필터는 적합성 미확인이다.

새 회귀는 실제 서비스 표본의 제안 `precedes`와 삭제된 파생 중간 정점을 최단 경로 함수가 통과함을 확인한다. 상태/중간 정점 필터 없는 최단 경로를 후처리로 버리기만 하면 더 긴 유효 경로를 놓칠 수 있다. 도달 범위 전체·방문 순서·완전한 내부 간선도 별도로 재현해야 하므로 직접 대체 후보로 채택하지 않는다.

VLE 상위 집합+메모리 BFS는 비교한 세 표본의 결과가 같았다. 측정 범위를 넘는 허브·깊은 조밀/무제한 경로 나열은 새로 실행하지 않았고, 과거 디스크 소진을 이번 실패 수로 재사용하지 않았다.

| 표본 | VLE 지연 ms/op | bounded 지연 ms/op | VLE SQL 명령/반환 행 | VLE 할당 MB/op |
|---|---:|---:|---:|---:|
| 희소 100 | 464.398~468.684 | 18.206~19.441 | 8 / 102 | 0.583~0.587 |
| 삭제/미확정·다중 시작 | 67.953~68.368 | 13.186~13.354 | 8 / 32 | 0.195 |
| 조밀 16 | 115.372~116.378 | 6.975~8.235 | 8 / 284 | 4.498~4.504 |

VLE 본문·식별자·간선별 작업량은 미계측이므로 벤치마크에서 `-1`로 표시했다. 참조 행·전체 SQL 반환 행과 할당은 실제 측정값이다. 왕복은 줄어도 세 표본 모두 지연이 악화되어 현재 BFS/양수 상한 구현을 유지한다. 2026-10-25 공식 release 목록에서 PG18의 다음 안정판을 확인하지 못했으며 이미지 판올림 시 같은 시험·비교를 반복한다.

## 실행 결과·실패·잔여 조건

최종 고유 시험 **572건**(최상위 **98건**, 하위 사례 포함)은 저장소 **241**·검색 **331**이다. 아래 집계는 건너뜀 없는 통과 결과이며, 중간 실패와 조건별 제한은 별도로 기록한다. 하나의 전체 명령이 성공했다고 주장하지 않는다. 첫 저장소 실행에서 통과한 234건, 새 DB 단독 재검증의 허브 1건, 경로 자격 회귀 6건과 검색 331건을 합산했다. 벤치마크 26조건과 중복 실행은 이 수에 더하지 않았다. 마지막 코드의 전체 build·vet·gofmt·의존성 검사가 통과했다. 변경 Markdown 9개·로컬 링크/앵커 424개·계획 103개 완료/21개 미완료와 DOX 정합성을 확인했다.

## 후속 비교·정리·DOX pass

스냅숏/일관성 후보의 연결·보유·재시도와 라우팅의 품질/오선택은 EVAL-06, 근거 경로 선택과 색인 대상은 EVAL-05의 서로 다른 통제 비교로 연결했다. 이번 합성 결과는 해당 작업, 공개 검색 품질·업무 효과, 운영 지연 목표·실제 제공자·다른 확장/CPU 판의 인수를 대체하지 않는다. 기본 라우팅·근거 선택·색인 대상과 공개 API를 변경하지 않았다.

SEARCH-10 전용 컨테이너·DB·임시 capability 그래프만 사용했다. 종료 시 자체 DB 세 개와 클라이언트 연결 0개·capability 그래프 0개를 확인한 뒤 `agent-context.task=search10` 라벨의 전용 tmpfs 컨테이너를 제거했다. 남은 동일 라벨 컨테이너는 없으며 기존 개발 DB/WAL 정리 컨테이너 두 개와 `.idea` 미추적 설정 두 파일은 유지했다. DOX의 소유 경계·스키마·배포 구성·요구사항·용어·패키지 의존은 바뀌지 않아 관련 DOX·SRS·용어집·추적 ID를 유지한다. 검색/평가 정본·계획·진입 상태·요청/근거 기록을 정합화했으며 변경은 미커밋이다.
