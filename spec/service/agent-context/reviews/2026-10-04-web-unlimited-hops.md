# 웹 그래프 상세의 홉 한도 없음 검증

## 원인과 수정

GitHub 이슈 [#52](https://github.com/Alpha-gone/agent-context-sharing/issues/52)은 플랜의 `max_hops=0`에서 그래프 상세의 간선이 사라지고 국소 보기 슬라이더의 상한도 `0`이 되는 문제다. 플랜은 `0`을 한도 없음으로 쓰지만 `GraphVisualization`의 깊이 `0`은 시작점만 반환한다. 웹 처리기가 플랜 값을 변환 없이 넘겨 두 의미를 혼동했다.

`FR-AGENT_CONTEXT-110`과 기존 플랜 계약을 유지하면서 SDD의 「웹 화면 계약」에 조회 깊이와 슬라이더 범위를 먼저 구분했다. 웹은 홉 한도 없음에서 `math.MaxInt`로 조회하고 기존 `max_hop_nodes`와 절단 표시를 유지한다. 슬라이더에는 표시 노드 수가 `n`일 때 `max(0, n-1)`을 상한과 초기값으로 전달한다. 여러 시작점에서 조회 거리가 모두 `0`이어도 임의의 선택 노드에서 국소 탐색할 수 있는 유한 범위다. 빈 그래프와 노드 하나인 그래프의 범위는 `0`이며, 홉 한도가 있는 플랜은 기존 값을 유지한다.

네이티브 range 입력, Cytoscape.js 자산과 클라이언트 탐색 코드는 변경하지 않았다. 새로운 화면 한도·설정·공개 API·스키마·의존성을 추가하지 않았다.

## 재현과 회귀

`TestGraphDetailHopLimits`는 계정별 플랜을 실제로 해석한 웹 서버에 세션 쿠키가 있는 상세 요청을 보내 렌더링 결과를 검사한다. 홉 조회 대역은 전달받은 깊이와 노드 상한을 기록하고 사슬 그래프의 해당 부분 결과를 반환한다. 수정 전 기본 플랜과 유한 홉 플랜은 통과했지만 한도 없는 플랜은 조회 깊이·간선·표시 노드·슬라이더 범위 검사에서 실패했다.

수정 후 다음을 확인했다.

- 기본값과 양수 홉 한도는 기존 조회 깊이와 슬라이더 범위를 유지한다.
- 홉 한도 없음에서 노드와 간선이 시각화 데이터에 실리고 슬라이더 범위는 유한하다.
- 여러 시작점의 조회 거리가 모두 `0`인 결과에도 국소 보기 범위가 남는다.
- 노드 상한이 있는 경우 기존 절단 경계를 표시하고, 홉과 노드 한도가 모두 없는 경우 전체 표본을 표시한다.
- 빈 그래프와 단일 노드는 범위를 `0`으로 렌더링한다.
- 실제 PostgreSQL·AGE 조회에서 최대 정수 깊이는 전역 요약 밖의 근거 원천과 간선을 반환하고 유한한 탐색을 끝낸다. 기존 직접 `0홉` 조회는 여전히 시작점만 반환한다.
- 삭제 노드를 가리키는 간선 제외와 노드 상한·절단 회귀도 유지된다.

## 검증 결과

Go 1.27.1을 사용했고 DB 시험에는 기존 개발 DB 설정을 값 노출 없이 주입하고 `TEST_DATABASE_REQUIRED=1`을 설정했다.

```shell
go test -race ./internal/web ./cmd/server -count=1
go test -race ./internal/store -run '^TestGraphVisualization' -count=10 -v
# 서버 루트
go test -json ./...
go build ./...
go vet ./...
# client/
go test ./...
go build ./...
go vet ./...
# 저장소 루트
gofmt -l .
git diff --check
```

모두 통과했다. 서버 전체 JSON 결과에 실패와 테스트 항목의 건너뛰기는 없었고, 테스트 파일이 없는 `cmd/audit`, `cmd/migrate`, `migrations`만 패키지 수준 `skip`이었다. gofmt 미정리 파일과 diff 공백 오류도 없었다. 최초 일반 실행은 샌드박스의 Go 빌드 캐시 읽기 제한으로 시험을 시작하지 못했으며, 권한을 받은 실행에서 수정 전 실패와 수정 후 통과를 구분해 확인했다.

실제 브라우저에서의 수동 상호작용, 별도 `embedding_live` 제공자 시험과 운영 부하 시험은 실행하지 않았다. 화면 검증 범위는 HTTP 렌더링 결과와 전달된 시각화 데이터다.

## DOX와 범위

루트와 `internal/web/`, `spec/`→`spec/service/`→`agent-context/` DOX 체인을 확인하고 한국어 표현·맞춤법·띄어쓰기와 문서 정합성을 점검했다. 웹 AGENTS에 한도 없음과 슬라이더의 책임을 반영했다. SRS의 기존 요구사항과 플랜 정책은 바뀌지 않아 유지했고, 구조·소유권·Child DOX Index가 바뀌지 않아 부모 및 서비스 AGENTS도 유지했다. 새 기술 계약을 채택하지 않아 `reference.md`와 용어집은 변경하지 않았다.

합성 시험 데이터를 개발 DB에 기록했으며 DB 초기화·볼륨 삭제·운영 권한 변경·외부 임베딩 API 호출·배포는 수행하지 않았다. 로컬 수정과 검증을 완료한 시점의 기록이며 커밋·푸시·PR 생성과 이슈 종료는 아직 수행하지 않았다.
