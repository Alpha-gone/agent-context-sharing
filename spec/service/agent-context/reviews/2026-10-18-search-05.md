- 범위: 양수 상한에서의 후보 선택·본문 묶음·내부 간선·정상 참조 적재 보호 모듈 인수다. 과거 시험 결과나 측정값은 완료 근거로 승계하지 않았다.

## 구현 대조와 새 산출물

- `hopContextsBounded`·`hopCandidateSQL`·`hopIncludedEdges`의 기존 구현을 현재 SRS·SDD와 대조했다. 깊이/label별 활성 미방문 식별자를 최초 기준 정점·이웃 순서로 합쳐 남은 자리와 초과 확인 한 행까지만 받는다. 본문은 선택한 새 노드만 묶음으로 읽으며 초과 확인 노드의 본문은 읽지 않는다. 마지막 깊이에서는 새 이웃 조회를 생략하고 반환 노드 간선은 별도로 모두 조립한다.
- 작은 인접 집합의 표본 정렬과 큰 집합의 정렬된 활성 정점/Cypher 존재 확인 전환, 64 기준과 정수 덧셈 포화, 양방향 `UNION ALL`과 공통 이웃 중복 제거를 유지했다. 새 검증에서 구현 결함은 발견되지 않아 조회 코드·공개 API·스키마를 변경하지 않았다.
- 새 `internal/store/hop_bounded_contract_test.go`에 독립 기대 목록과 간선 집합을 가진 표본을 추가했다. 원천 하나와 중복된 두 시작 사건, 공통 이웃 63·64·65·130개, 뒤 기준 정점에만 연결된 작은 식별자 이웃, 폐기/제안 전용 이웃과 선택 노드 사이 조밀한 확정 관계를 만든다. 정점은 식별자 역순으로 삽입하고 사건 시작 시각은 같게 두어 시간 제약을 지킨다.

## 모듈 검증

- 새 표본의 96개 방향/상한 조합에서 out/in/both, 상한 1·2·3·10·전체 수 전후·`math.MaxInt`를 대조했다. 시작 순서와 기준 정점 정렬의 구분, 앞 기준 정점의 공통 이웃 우선, 폐기/제안 이웃 제외, 중복 시작/공통 이웃 제거, 최단 거리와 최초 절단 경계 0/1을 확인했다. 같은 결과를 전체 이웃 기준선과도 대조했다.
- 각 결과에서 본문 행/UTF-8 바이트를 선택 노드의 명시적 기대값과 비교했다. 식별자는 새 선택 수와 초과 확인 한 행에 한정되고, 시작점에서 이미 잘리면 후보 질의도 없다. 깊이 1의 최대 후보 질의 수는 요청 label 수 2이며 마지막 깊이의 새 이웃 조회가 남지 않는다. 조밀한 상한 10 표본은 내부 간선 44개를 모두 반환한다. 범위 밖 원천을 가리키는 사건 구성원 참조도 모든 반환 사건에서 보존한다.
- 관련 모듈 회귀를 같은 새 DB에서 실행했다. 전체 이웃 기준선과의 900개 매개변수 조합, 전환 경계 63/64/65의 36개 조합, 다중 기준 정점·조밀 간선·삭제/제안·방향/필터의 72개 조합을 대조했다. 이 조합 수는 Go 시험·하위 시험 개수에 더하지 않았다.
- 20,000개 이웃 허브에서 상한 1/2/10의 결과가 전체 이웃 기준선과 같고, 새 본문 적재가 각각 0/1/9행이며 식별자·내부 간선 적재의 검사가 통과했다. 전체 이웃 기준선은 적어도 20,000개 본문 행을 읽는다. 이는 애플리케이션 수신량 검증이며 DB 전체 작업이나 지연 개선폭의 보장이 아니다.
- 최대 정상 참조 표본은 근거 100개·사건 구성원 1,000개를 선택 노드/시작 노드·중복 label 조합에서 절단 없이 보존했다. 예를 들어 사건 선택의 상한 2 결과는 노드 2개·간선 1개, 후보 식별자 1행·새 본문 1행/13바이트·참조 1,000행이었다.

## 실행 결과와 준비 보완

- 고정 Dockerfile로 `agent-context.task=search05` 라벨의 전용 이미지 `agent-context-search05:local`, 컨테이너 `acs-search05`, 볼륨 `acs-search05-data`, loopback 55672 포트를 사용했다. PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6, vector(128) 주 DB와 새 vector(8) 임시 DB에 정식 001/009/010/011/012/013 마이그레이션을 적용했다. 기존 개발 DB는 사용하지 않았다.
- 초기 새 표본은 관계 속성을 `type`으로 조회해 관계를 만들지 못했다. 정식 `relation_type`으로 수정한 뒤 표본 간 고정 식별자의 전역 중복을 발견해 표본별 식별자 범위를 분리했다. 사건 시각도 관계 제약에 맞추고 최종 새 시험을 다시 실행했다. 준비 실패를 통과로 세지 않았다.
- Go 1.27.1 `go test -race -json -count=1 -p 1 -timeout=240s ./internal/store`에서 새 계약 시험과 전체 기준·전체/양수 상한 비교·허브 적재·최대 참조·SQL 경계·전환 경계·조밀 간선의 8개 최상위 시험을 선택했다. 변경된 새 계약 시험은 `-timeout=180s`로 재검증했다.
- `(package, test)`별 마지막 결과는 **최상위 8건·하위 126건, 고유 시험·하위 시험 134건 통과·최종 실패 0건·건너뜀 0건**이다. 반복 실행을 고유 수에 더하지 않았다. 기록은 `/private/tmp/acs-search05-store-final.json`·`acs-search05-recheck.json`이다.

## DOX pass와 후속 범위

- 기존 store 홉 경계의 새 시험과 완료 증거만 추가했다. 동작·설계 계약·패키지·의존성·구성·용어·소유권은 바뀌지 않아 SRS·SDD·DOX·마이그레이션·운영 안내·용어집을 유지했다. 전체/상세 계획·요청 기록·공식 근거를 정합화하고 문서 링크·Markdown·계획 집계와 `git diff --check`를 확인했다.
- 애플리케이션 후보·본문은 양수 상한에 제한되지만 조밀한 내부 간선은 `O(L²)`일 수 있다. `limit=0`은 한도 없음이며 DB의 잔여 스캔·정렬·집계 작업까지 결과 상한에 제한되는 것은 아니다.
- 현재 45/124개 완료·79개 미착수이며 다음은 [SEARCH-06](../development-plan/search.md#search-06)이다. 공통 시간 예산·동시 폐기·자원 회복의 해당 모듈 인수, 검색 분야 최종 통합·SEARCH-10 정량 성능 비교·MCP/호스트·운영 배포·TEST-09 전체 시험은 이번 완료 범위에 포함하지 않았다. 기존 PERM-07 인덱스 계획 후속 사항을 해결한 것으로 표시하지 않는다. 변경은 커밋 전이다.
