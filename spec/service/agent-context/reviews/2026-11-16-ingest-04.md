# INGEST-04 수집 클라이언트 검증

- 작업 범위: 호스트 훅 입력, 프로젝트별 설정, 세션별 대기 파일·중지·재전송, 수집 서버 연결과 실행 안내.
- 합성 로컬 모델을 사용한 실제 호스트 실행: Claude Code 2.1.325의 `UserPromptSubmit`·`Stop` 비동기 훅에서 사용자 발화·마지막 응답·세션 ID를 관찰했다. Codex CLI 0.166.0의 `notify`에서 기본 발화, 표준 입력과 마지막 응답을 관찰했다. 각 호스트에서 구현한 실행 파일을 직접 훅으로 호출해 사용자·에이전트 턴 두 개가 대기열에 기록되는 것도 확인했다. 외부 제공자나 실제 대화는 사용하지 않았다.
- 모듈 시험: `TEST_DATABASE_REQUIRED=1`인 격리 PostgreSQL과 TLS 수집 처리기에서 저장 후 응답 실패·재전송의 멱등성, 중지 중 제외 및 대기열 상태를 확인했다. `go test -race -count=1 ./cmd/ingest`에서 위 DB 시험과 대기열 경합, 401·5xx, 잘못된 응답, 발췌 분할, 거부 기록, 자격·본문 비노출을 함께 실행했다.
- 정적 확인: Go 1.27.4 `go build ./...`, `go vet ./...`, `gofmt -l .`과 변경 문서 상대 파일 링크 및 `git diff --check`가 통과했다. Linux/amd64 대상 교차 빌드도 통과했다.
- 한계: Claude Code의 비대화형 종료는 실행 중인 비동기 훅을 취소할 수 있으며 비동기 훅의 순서가 바뀔 수 있다. Codex의 실행 중 추가 지시를 포함한 모든 입력과 두 호스트의 세션 재개 시 ID 유지는 확인하지 않았다. Codex는 해당 확인 전 지원을 보류한다. 실제 운영 서버와 실제 대화 연결 및 비용 측정은 수행하지 않았다.

2026-11-17 후속 전체 점검에서 일시 중지 경합·대기열 크기·프로젝트 간 순번 충돌을 수정했다. 현재 동작과 재검증은 [INGEST-01~02와 전체 변경 점검](2026-11-17-ingest-01-02-final.md)을 따른다. 위 비동기 훅 실행 결과는 변경 전의 관찰로 보존한다.
