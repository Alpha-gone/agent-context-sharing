# 그래프 불변식 감사

## 목적과 조건

- 측정일: 2026-09-27
- 목적: `FR-AGENT_CONTEXT-153`에 따라 그래프 불변식을 실행 가능한 규칙 목록으로 구현하고, 쓰기 영향 주변부 검사와 전체 감사가 같은 판정을 내는지 확인하며, 정기 주기를 정하기 전에 그래프 크기별 비용을 잰다.
- 데이터베이스: PostgreSQL 18.6, Apache AGE 1.8.0, pgvector 0.8.6, 로컬 Docker 개발 데이터베이스

## 구현

- `internal/store/invariant.go`가 규칙 7개를 한 목록으로 둔다. 규칙은 `graph_membership`, `endpoint_layer`, `reference_cardinality`, `relation_identity`, `relation_acyclic`, `relation_time`, `embedding_link`다.
- 규칙은 저장 상태를 읽은 스냅숏만 보고 판정하는 함수다. 쓰기 검사와 전체 감사는 같은 목록을 부르고 읽는 범위만 다르다. 전체 감사는 그래프의 정점·간선·임베딩과 다른 그래프에 속한 간선 끝을, 쓰기 검사는 쓰기가 만들거나 바꾼 컨텍스트와 그에 닿은 간선·이웃·임베딩을 읽는다.
- 순환 판정은 영향 주변부 밖의 경로로도 닫히므로, 쓰기 검사도 그래프의 확정 `PRECEDES`·`CAUSES`·`PART_OF` 간선을 읽어 전체 감사와 같은 방식으로 답한다.
- `relation_time`은 관계를 만들 때 쓰는 `model.ValidateRelationTime`을 그대로 쓴다.
- 컨텍스트 생성·갱신·폐기·복구, 관계 생성·확정·폐기·후보 제안, 임베딩 공개 트랜잭션이 커밋 전에 영향 주변부를 검사한다. 위반하면 `ErrInvariantViolation`으로 커밋하지 않고, 연산 계층은 내부 오류로 응답한다.
- `cmd/audit`가 모든 활성·삭제 그래프 또는 `-graph-id` 하나를 읽기 전용 `REPEATABLE READ` 트랜잭션에서 감사한다. 출력은 규칙 식별자, `graph_id`, 대상 종류, 라벨과 식별자만 담은 JSON Lines다. 종료 상태는 위반이 없으면 0, 있으면 1, 감사를 끝내지 못하면 2이며 저장 상태를 바꾸지 않는다.

## 검증

- 규칙 단위 테스트: 정상 표본에서 위반이 없고, 규칙마다 한 규칙만 깨진 표본에서 그 규칙과 위치 하나만 보고된다. 쓰기 검사 범위 밖 이웃의 기수성은 판정하지 않는다.
- 통합 테스트: 실제 그래프에서 규칙마다 한 불변식을 저장소에 직접 깨고, 쓰기 검사와 전체 감사가 같은 위반 목록을 내는지 대조했다. 전체 감사를 두 번 실행해 결과가 같아 저장 상태를 바꾸지 않음을 확인했다. 깨진 주변부를 건드리는 관계 확정은 `ErrInvariantViolation`으로 거부되고 관계가 남지 않았다.
- 처음 대조에서 두 가지 차이를 찾아 고쳤다. 전체 감사가 다른 그래프 끝의 계층을 몰라 `graph_membership` 위반을 `endpoint_layer`로도 보고했고, 쓰기 검사의 순환 판정이 관계 속성을 해석하는 경로 질의를 써서 속성이 없는 간선을 놓쳤다. 두 경로가 같은 방식으로 저장 상태를 읽게 맞췄다.
- 개발 데이터베이스 전체 감사: 그래프 620개를 7.6초에 감사했다. 위반 626건 중 608건은 통합 테스트가 시험용 모델 식별자로 만든 임베딩의 `embedding_link`이고, 나머지는 불변식 테스트가 일부러 깨 둔 표본이다. 평가 실행기가 실제 모델로 적재한 그래프 넷은 위반이 없었고 그래프당 31~46ms였다.
- 전체 테스트: `TEST_DATABASE_REQUIRED=1 go test ./...`가 모든 쓰기에 영향 주변부 검사를 켠 상태로 통과했다.

## 비용

`BenchmarkAuditGraphIntegration`으로 조건마다 10회 반복한 평균이다. 표본은 홉 탐색 비교와 같은 사슬 그래프이며 모든 컨텍스트가 임베딩을 가진다. 쓰기 검사는 사건 하나를 범위로 둔 한 번의 검사다.

| 노드 | 전체 감사 | 쓰기 한 번의 영향 주변부 검사 |
|-----:|----------:|------------------------------:|
| 100 | 13.0ms | 14.1ms |
| 400 | 18.6ms | 16.3ms |
| 1,600 | 37.3ms | 20.8ms |

- 전체 감사는 간선·정점·임베딩을 세 번의 질의로 읽고, 다른 그래프 끝이 있을 때만 한 번 더 읽는다. 그래프 크기에 거의 선형이며 1,600노드에서도 40ms 아래다.
- 쓰기 검사는 쓰기마다 질의 셋을 더하고, 범위에 확정 순환 대상 관계가 있으면 label별 질의 셋을 더 한다. 사슬 그래프의 사건처럼 관계가 있는 컨텍스트를 쓰면 쓰기 한 번에 14~21ms가 늘어난다.

## 판정과 후속

- 정기 감사 주기는 정하지 않는다. 계획대로 마이그레이션 적용과 시점 복구 뒤, 서비스를 다시 열기 전에 전체 감사를 실행하는 절차만 둔다. 측정한 비용으로는 하루 한 번 전체 감사를 돌려도 부담이 작지만, 쓰기마다 영향 주변부를 검사하므로 주기를 더할 근거가 아직 없다.
- 쓰기 검사의 추가 지연은 관계가 있는 컨텍스트에서 쓰기 한 번에 약 14~21ms다. 운영 쓰기 지연의 목표가 정해지면 순환 대상 간선 읽기를 관계가 바뀐 쓰기로 좁히는 방안을 비교할 수 있다.
