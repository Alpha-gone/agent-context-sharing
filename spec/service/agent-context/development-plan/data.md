# 데이터 개발 계획

[전체 계획](../DEVELOPMENT_PLAN.md) · [기준 SDD](../sdd/data.md) · [작업 추적](traceability.md)

## 목표와 구현 범위

새 시험 DB에서 단일 AGE 그래프와 관계형 저장소를 만들고, 격리·불변식·벡터·온라인 저장 계층을 구현한다. 기존 스키마가 준비되어 있다고 가정하지 않는다.

- 설계 입력: [물리 배치와 스키마](../sdd/data.md#물리-배치), [스키마 적용](../sdd/data.md#스키마-적용), [인덱스](../sdd/data.md#인덱스), [격리](../sdd/data.md#격리-강제의-구현), [불변식](../sdd/data.md#그래프-불변식-규칙과-감사), [계층화](../sdd/data.md#저장-계층화).
- 예정 구현 영역: `migrations/`, 마이그레이션 실행기, `internal/store`, `cmd/audit`.
- 다른 분야와의 경계: 저장 API는 이 계획, 상태 전이·감사 원자성은 수명주기 계획, 큐 소비·벡터 생성은 색인 계획이 소유한다.

## 개발 작업

### DATA-01

- [x] **논리 모델을 물리 스키마와 제약으로 대응한다.**
- 선행: [ARCH-02](architecture.md#arch-02), [PERM-01](authorization.md#perm-01).

1. 업무 관계형 테이블과 목표 OAuth·에이전트 등록 테이블의 열·키·NULL·참조·유일·조회 조건을 SDD에 대조한다.
2. 단일 `Context` label의 공통·계층 속성과 일곱 간선 label을 정의한다. 참조를 property로 중복하지 않고 `RELATES_TO`의 정규 방향을 유지한다.
3. DB 제약으로 강제할 항목과 모델·저장소 검증 항목을 나눈다. `version`, 내부 `content_revision`, 유예 시각과 저장량의 의미를 분리한다.

- 산출물: 구현할 DDL·property·제약·인덱스 대응 목록과 스키마 검사 표본.
- 완료 기준: SRS의 모든 모델 속성에 저장 위치와 검증 책임이 있으며 관계에 판 번호·시간 유효성이 추가되지 않는다.

- 완료 근거: 2026-10-15 [물리 스키마 대응 검토](../reviews/2026-10-15-data-01.md). 컨텍스트 24개·관계 12개·그래프 10개·계정 4개 속성을 대조하고 목표 17개 테이블의 타입·NULL·키·참조·검증·조회 책임을 정합화했다. OAuth·등록의 열은 각 소유 SDD에서 구체화했으며 후속 DDL의 검사 표본과 기존 SQL 대비 차이를 남겼다. 문서·추적·링크 검증 완료이며 DDL 작성·DB 적용·실제 제약 시험은 DATA-02 이후의 별도 범위다. DATA-02 전에 OPS-01을 진행한다.

### DATA-02

- [x] **스키마 생성·마이그레이션 실행기를 구현한다.**
- 선행: [DATA-01](#data-01), [ARCH-01](architecture.md#arch-01), [ARCH-05](architecture.md#arch-05), [OPS-01](operations.md#ops-01).

1. 도구 자체 연결에 AGE 준비를 적용하고 자문 잠금 아래 적용 이력·번호·checksum을 검사한다. 저장소의 DB 핸들을 가져오지 않는다.
2. 확장→AGE 그래프→정점·간선 label→`public` 관계형 테이블→인덱스·통계 순으로 새 DB를 준비한다.
3. 그래프 이름·벡터 타입·차원·tablespace 치환을 실행 전에 검증하고 잘못된 값이면 SQL을 실행하지 않는다.
4. 적용 파일과 치환 구성을 이력에 남긴다. 기존 번호·checksum은 보존하고 후속 목표 스키마는 새 번호로 추가한다.

- 산출물: 실행기, 정식 마이그레이션, 잠금·이력·치환·부분 실패 시험.
- 완료 기준: 빈 DB의 전체 적용과 반복 실행이 성공하며 동시 실행·잘못된 치환·checksum 불일치가 무단 재적용 없이 처리된다. 운영 DB 적용은 별도 실행이다.

- 완료 근거: 2026-10-15 [마이그레이션 모듈 검토](../reviews/2026-10-15-data-02.md). 새 번호 010으로 목표 17개 업무 테이블·제약·인덱스를 준비하고 잠금·조회·DDL의 연결을 통일했다. vector/768·halfvec/3072의 새 DB 적용·반복, 과거 UUID 키/결과/만료/이력 보존, 제약 위반·취소 롤백, 최소 풀 동시 실행·잠금 반환을 포함한 모듈/하위 시험 49건과 race·전체 build/vet/형식 검사가 통과했다. 실제 CLI status→up→up→status도 통과했으며 운영 DB에는 적용하지 않았다. 다음은 ARCH-04다.

### DATA-04

### DATA-08

- [ ] **온라인 계층 이동·접근 기록을 구현한다.**
- 선행: [DATA-07](#data-07), [ARCH-04](architecture.md#arch-04).

1. 접근 차단과 플랜의 미사용 조건으로 임베딩만 cold로 옮긴다. 원천·파생·사건 정점·본문·간선은 이동하거나 파티셔닝하지 않는다.
2. 활성 반환 컨텍스트의 접근 시각 기록과 cold→hot 되읽기를 같은 문장으로 수행한다. ID 순서 잠금·SKIP LOCKED와 스냅숏 읽기 종료 뒤 기록 경계를 지킨다.
3. 동시 파티션 이동의 `40001`에만 같은 시각·대상으로 새 자동 커밋 문장에서 한 번 재시도한다. 두 번째 실패·다른 장애·취소는 반환한다.
4. 삭제 대상은 복구 조회만으로 hot에 올리지 않고 cold를 직접 검색한다. tablespace 장애를 빈 결과로 숨기지 않는다.

- 산출물: 이동·되읽기·접근 기록 API와 동시 이동·최소 풀 표본.
- 완료 기준: 유실·중복·교착 없이 온라인 조회가 유지되고 실제 연결 점유가 예약 범위를 넘지 않는다. 접근 기록 실패는 정상 부분 결과로 바뀌지 않는다.
