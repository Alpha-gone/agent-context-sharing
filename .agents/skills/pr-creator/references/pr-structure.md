# PR 작성 기준

## 제목

- 실제 변경 결과를 동사형으로 간결하게 표현한다.
- 이슈 제목을 그대로 복사하기보다 diff의 핵심 결과를 반영한다.
- 저장소에 커밋 또는 PR 제목 규칙이 있으면 그 규칙을 우선한다.

## 본문 형식

```text
## 변경 요약

- 실제 diff에서 확인한 핵심 변경을 적습니다.

## 변경 파일

| 파일     | 변경 내용                            |
|:---------|:-------------------------------------|
| `{경로}` | 파일의 역할과 실제 변경을 적습니다. |

## 검증

| 상태   | 명령 또는 확인   | 결과                           |
|:-------|:-----------------|:-------------------------------|
| 성공   | `{실행한 명령}`  | 확인한 결과를 적습니다.        |
| 실패   | `{실행한 명령}`  | 오류와 영향을 적습니다.        |
| 미실행 | `{필요한 검증}`  | 실행하지 못한 이유를 적습니다. |

## 이슈 연결

- `Closes #{번호}` 또는 `Refs #{번호}`

## 남은 작업

- 미구현, 미검증 또는 별도 이슈가 필요한 항목을 적습니다.
```

해당 내용이 없으면 섹션을 삭제할 수 있지만, 실패하거나 미실행인 검증을 숨기기 위해 삭제하지 않는다.

커밋 SHA와 포함 파일은 게시 범위 확인에만 사용한다. PR 본문에는 커밋별 설명이나 별도 `커밋` 섹션을 작성하지 않고 전체 diff의 결과를 변경 요약과 변경 파일에 정리한다.

## 이슈 연결 선택

| 상황                                              | 키워드                                        |
|:--------------------------------------------------|:----------------------------------------------|
| PR 병합으로 이슈의 전체 범위와 인수 조건이 충족됨 | `Closes #<번호>`                              |
| 이슈 일부만 구현하거나 참고 관계만 있음           | `Refs #<번호>`                                |
| 여러 이슈 중 일부만 종료 가능함                   | 종료되는 이슈만 `Closes`, 나머지는 `Refs`     |
| 실제 관련성을 확인할 수 없음                      | 자동 종료 키워드를 쓰지 않고 확인 필요로 남김 |

## 작성 점검

- 본문에 적은 파일이 실제 PR diff에 포함되는가
- 검증 명령과 결과가 실제 실행 기록과 일치하는가
- `Closes` 대상 이슈의 인수 조건이 모두 충족되는가
- 미구현·미검증·보류 항목이 남은 작업에 보존되는가
- 라벨이 저장소에 실제로 존재하며 변경 범위와 일치하는가
- 비밀 정보, 원본 데이터 또는 불필요한 생성 산출물이 포함되지 않았는가
