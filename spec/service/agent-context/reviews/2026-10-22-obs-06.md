## 변경과 관찰 범위

기존 조회는 두 테이블을 UNION ALL로 합쳐 수행 계정으로 정렬한 첫 페이지만 반환했다. `ListAuditEntries`는 이제 요청 계정·기간·대상·커서·페이지 크기를 받아 각 출처에서 유한 조회한 뒤 한 페이지와 다음 커서를 반환한다. 기존 내부 호출·시험 대역을 새 계약으로 맞췄다. 외부 MCP 도구나 DB 스키마를 추가하지 않았다.

- 시각 내림차순·ID 내림차순을 사용한다. 두 테이블의 시각과 ID가 모두 같은 행도 웹·연산 출처로 구분한다. 각 출처에서 페이지 크기+1건만 읽고 반환은 한 페이지로 제한한다. UTC 시작 포함·끝 제외 기간과 대상 필터를 두 질의에 각각 적용한다. 잘못된 커서·기간·ID·페이지 크기는 조회 전에 거부한다.
- 소유자 판정과 두 출처 조회는 하나의 읽기 스냅숏에서 수행한다. 직접·활성 팀 상속 소유자만 허용하고 웹은 기존 perm 검사를 먼저 거쳐 요청 계정의 GraphPage 기본값을 전달한다. 화면 필터와 다음 페이지 연결은 이번에 추가하지 않았다.
- 팀에 소유자 등급을 부여하거나 구성원을 추가하거나 팀을 복구할 때 실제 상속 계정을 같은 변경 트랜잭션의 웹 감사에 남긴다. 팀·그래프·구성원과 after_grade=owner를 기록하며 직접 부여로 위장하지 않는다. 구성원 추가는 추가한 계정에 한정한다. 기존 감사에 없는 과거 구성원을 현재 팀 상태로 추정하거나 이력을 소급 생성하지 않는다.
- 복구 자격 조회는 생성자·직접 소유자 이력과 팀 상속 근거를 구분한다. 복구 요청은 그래프 잠금 뒤 자동 삭제 상태와 자격을 다시 검사한다. 대기 목록·운영자 처리·보존 정리가 공통된 후행 처리 조건을 사용하며 같은 시각은 감사 ID로 순서를 정한다. 별도의 대기 상태를 저장하지 않는다.
- 일반 보존 정리는 직접/상속 소유자 근거와 미처리 요청, 운영자 복구 기록을 유지한다. 현재 폐기의 연산 복구 근거 보호와 적용/웹 기록·거부 기록의 서로 다른 보존 기준도 유지한다. 정리로 운영 복구 기록이 사라져 과거 요청이 다시 대기로 나타나지 않는다.

## 검증 결과

macOS arm64·Go 1.27.1·실제 로컬 PostgreSQL/AGE, TEST_DATABASE_REQUIRED=1을 사용했다. 새 저장소 시험은 기존 helper로 고유 DB를 만들고 정식 마이그레이션을 적용한 뒤 정리한다. 관련 기존 회귀에는 공유 시험 DB를 사용하는 사례도 있다. 원격 Gemini·운영 배포·Linux 인수는 실행하지 않았다.

| 범위 | 통과 | 실행·관찰 내용 |
|---|---:|---|
| store 관련 모듈·회귀 | 102 | OBS-06의 커서·기간·대상·소유자·취소·스냅숏·보존과 관련 팀·운영자 복구·감사·폐기 복구·등급 회수·주기 정리 |
| web 패키지 전체 | 630 | 기존 HTTP 회귀와 소유자 전용 감사 호출·계정/그래프 전달·사용자 플랜 페이지 크기 |
| cmd/server 의존 계약 | 1 | 허용 패키지 의존 양방향 검사 |
| 합계 | **733** | 상위 Test와 하위 사례의 pass 사건 포함, 중복 실행 합산 없음 |

선택 범위의 실패·건너뜀은 0이며 모두 race를 적용했다. 전체 저장소 시험이나 분야 전체 인수를 뜻하지 않는다.

- 페이지 크기 1·2·3·4·5에서 같은 시각·같은 ID를 포함한 네 행을 중복·누락 없이 끝까지 읽었다. 다른 그래프의 기록 제외와 UTC 경계·없는 대상을 대조했다.
- 소유자 확인 직후 다른 연결이 실제 등급과 웹 감사 행을 삭제해도 현재 페이지의 두 출처는 이전 스냅숏을 유지한다. 다음 조회는 현재 권한으로 거부된다. 취소 후 부분 결과가 없으며 풀의 획득 연결이 0으로 돌아옴을 확인했다.
- 팀 부여·구성원 추가·팀 복구의 세 경로에서 생성자가 아닌 팀 소유자의 접근을 제거하고 실제 유예 만료·복구 요청·보존 정리·운영자 복구를 수행했다. 정리 후에도 상속 자격과 미처리 요청이 남았다. 요청과 처리를 같은 시각으로 맞추고 그래프를 다시 자동 삭제 상태로 둬도 완료 요청은 다시 대기로 나타나지 않았다. 이 마지막 재삭제 상태는 시험 SQL로 준비했다.
- 무기한 정리는 삭제 0, 적용/웹 30일·거부 1일 정리는 정확히 3행 삭제를 대조했다. 현재 연산 폐기 뒤 보존 기간을 지난 시점에 정리하고 HasAppliedDiscard 및 실제 RestoreContext 성공으로 근거 보호를 확인했다.
- 기존 팀 감사 실패의 원자성, 겹치는 그래프의 변경·취소, 운영자 복구의 감사 실패·동시 처리·현재 상태와 다른 등급 보존도 관련 회귀에 포함했다.

## 문서·소유권·남은 조건

관측성 SDD는 커서의 출처 동률·기간·스냅숏·상속 근거와 후행 처리 조건, 데이터 SDD는 기존 선택 열의 대상별 의미, 운영 SDD는 과거 소유자 판정을 소유하도록 맞췄다. SRS 요구사항이나 플랜 항목을 추가하지 않았다. DOX pass에서 기존 store·web·명세 경계가 그대로여서 새 AGENTS.md나 Child Index는 만들지 않았다. 계획·진입점·README·서비스 색인은 완료 증거와 후속 범위를 연결한다.

변경 Markdown 11개의 상대 링크·앵커 517개, 코드 블록·UTF-8·공백을 검사했다. 개발 계획의 완료 76개·미착수 48개가 총 124개와 일치한다.

WEB-08의 감사 화면 필터·더 보기와 실제 브라우저 인수, OBS-07의 stderr·부분 쓰기·5초 종료, OBS-08의 실제 파일·배포 통합 인수는 남아 있다. 현재 소유 근거가 없는 과거 팀 이력의 소급 복원은 제공하지 않는다. upstream이 없어 원격 뒤처짐을 확인할 수 없었다. 기존 Compose·IDE 변경은 보존했으며 commit·push·PR·배포는 수행하지 않았다.
