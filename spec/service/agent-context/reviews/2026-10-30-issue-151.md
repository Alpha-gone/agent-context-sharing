# #151 질의 임베딩 전용 마감

- 기준: 2026-10-30 KST, `dev`의 `23e259e`에서 분기한 `fix/151-query-embedding-deadline`.
- 대상: [이슈 #151](https://github.com/Alpha-gone/agent-context-sharing/issues/151), [검색 흐름](../sdd/search.md#작업-컨텍스트-흐름-조회), [시험 계층](../sdd/testing.md#테스트-계층).

## 재현과 수정

[검색 회귀](../../../../internal/search/query_embedding_deadline_test.go)는 취소까지 대기하는 제공자 대역으로 Read Committed·동기화 스냅숏과 순차·병렬 조합을 실행한다. 수정 전 네 조합 모두 8초 부모 요청 마감까지 대기한 뒤 전체 오류와 빈 본문으로 실패했다.

질의 임베딩에만 호출 시작 기준 5초 자식 context를 적용한다. 더 이른 부모 마감이 우선하며 호출 뒤 cancel로 정리한다. 전용 마감의 만료는 의미 채널의 `embedding_unavailable`로 처리하고 키워드·시간·스냅숏 읽기에는 부모 context를 유지한다. 요청 자체의 취소·만료는 전체 오류·빈 본문과 취소 원인을 유지한다. 스냅숏은 제공자 호출이 끝난 뒤 열며 `scope=global`의 임베딩 생략도 보존한다.

5초는 MCP 기본 30초 예산에서 남은 읽기·응답 시간을 확보하기 위한 초기 설계값이다. 실측 최적값이나 제공자 지연 보장이 아니다. 비동기 색인의 HTTP 상한·재시도, 공개 구성과 스키마는 변경하지 않는다. context 계약의 근거는 [reference.md](../reference.md#2026-10-30-151-질의-임베딩-전용-마감)에 기록했다.

## 검증

Go 1.27.1, 고정 PostgreSQL/AGE/pgvector 전용 컨테이너, 정식 마이그레이션과 `TEST_DATABASE_REQUIRED=1`·`TEST_DATABASE_URL`을 사용했다.

```sh
go test -race -count=1 -run '^TestQueryEmbedding' ./internal/search
go test -race -count=1 -json -run '^(TestQueryEmbedding|TestMCPQueryEmbedding)' ./internal/search ./cmd/server
go test -race -count=1 -json -timeout=15m ./internal/search ./internal/mcp ./cmd/server
go build ./...
go vet ./...
gofmt -l .
```

수정 후 검색 회귀는 네 조합의 부분 응답과 두 일관성 모드의 호출자 취소 원인·더 짧은 부모 마감·빈 본문을 검증했다. [MCP 회귀](../../../../cmd/server/mcp_query_embedding_deadline_test.go)는 실제 TLS 지연 제공자·`internal/index` HTTP 호출·검색·DB·MCP 처리기를 연결해 8초 클라이언트 예산 안의 HTTP 200 정상 부분 응답과 제공자 HTTP 취소를 확인했다. 초기 통합 시험의 필수 허용 출처 누락은 시험 조립에서 보완했다.

필터 없는 race 인수 결과는 다음과 같다. 건수에는 하위 사례를 포함한다.

- `internal/search`: 342건, 최상위 69건, 6.911초. 실패·건너뜀 없음.
- `internal/mcp`: 480건, 최상위 51건, 10.397초. 실패·건너뜀 없음.
- `cmd/server`: 688건, 통과 최상위 107건, 117.018초. 실패 없음. 별도 Codex CLI 시나리오와 물리 복구·이전 인수 21건은 해당 실행 환경 미설정으로 건너뛰었다.

build·vet·gofmt·문서 링크/앵커·diff 검사와 독립 읽기 전용 코드 검토를 통과했다. 실제 외부 제공자의 지연·품질 측정은 수행하지 않았다. context 취소를 무시하는 사용자 구현을 별도 goroutine으로 강제 종료하는 기능은 추가하지 않았다.

시험별 DB 잔류 없음과 idle transaction 0개, 생성 컨테이너 ID를 확인한 뒤 이번 작업의 컨테이너·익명 볼륨만 정리했다. 개인 IDE 파일과 기존 자원을 보존했다. 검색 마감은 검색 SDD, 제공자 교차 참조는 색인 SDD, 시험 경계는 테스트 SDD에 유지하며 DOX 소유권·구조 변경은 없다.
