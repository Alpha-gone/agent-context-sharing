## 권장 구조

서비스 특성에 맞게 조정하되 다음 순서를 기본으로 사용한다.

1. 문서 정보
2. 설계 목적과 범위
3. 설계 입력
4. 시스템 컨텍스트
5. 아키텍처
6. 구성 요소 설계
7. 주요 처리 흐름
8. 인터페이스와 API 계약
9. 데이터 모델과 저장 전략
10. 상태, 오류와 복구
11. 보안과 권한
12. 관측성, 배포와 운영
13. 비기능 요구사항 설계
14. 요구사항 추적표
15. 설계 미정 사항
16. 주석

`설계 입력`에는 사용한 `SRS.md`, `reference.md`, `logs/prompt.md`와 채택된 제안 ID를 기록한다. 채택된 제안이 없으면 `없음`으로 명시한다.

## 주석과 이동 링크

보충 설명은 본문에 긴 괄호로 삽입하지 않고 문서 하단 `주석` 섹션에 모은다. HTML 주석은 렌더링되지 않으므로 사용하지 않는다.

본문 표식 예시는 다음과 같다.

```markdown
세션 식별자는 서버 측 상태만 가리킨다.<a id="note-ref-1"></a>[[주석 1]](#note-1)
```

문서 하단 주석 예시는 다음과 같다.

```markdown
## 주석

<a id="note-1"></a>**주석 1.** 세션 식별자 자체에는 사용자 정보를 포함하지 않는다. [본문으로 돌아가기](#note-ref-1)
```

주석 번호는 문서 등장 순서대로 부여한다. 하나의 주석을 여러 위치에서 참조하면 본문 앵커를 각각 만들고 주석에 복귀 링크를 모두 제공한다.

## 추적성

요구사항 추적표는 최소한 다음 열을 포함한다.

| 요구사항 ID | 설계 반영 위치 | 설계 요소 | 검증 방법 | 상태 |
| :- | :- | :- | :- | :- |
| `FR-EXAMPLE-001` | 주요 처리 흐름 | 로그인 시퀀스 | 통합 테스트 | 반영 |

`SRS.md`의 설계 대상 요구사항을 빠뜨리지 않는다. 반영할 수 없는 항목은 `미반영`으로 숨기지 말고 원인과 필요한 결정을 `설계 미정 사항`에 연결한다.
