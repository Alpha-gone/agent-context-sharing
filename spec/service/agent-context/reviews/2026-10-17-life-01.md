- 시작 상태: `feat/implementation-improve`, `5c90597`. 로컬 upstream은 ahead/behind 0이며 원격 조회는 DNS 오류로 실패했다. 기존 Compose·IDE 변경을 보존했다.
- 범위: `store`의 그래프 생성·초기 소유자·메타데이터 갱신과 직접 영향받는 한도·삭제 경합. MCP 처리기·인증·멱등성 외피 전체 인수와 구분한다.

## 발견 사항과 변경

| ID | 영향도 | 발견 사항 | 처리·증거 |
|---|---|---|---|
| LIFE01-R1 | 중간 | 사용자 생성 API가 1이 아닌 초기 판, 비어 있지 않은 저장량, 삭제·유예 상태의 그래프를 허용했다. | `CreateGraphWithOwner`에서 새 그래프의 상태를 검증한다. 잘못된 상태는 DB 호출 전에 필드 오류로 거부한다. 준비된 행만 저장하는 `CreateGraph`와 사용자 생성 경계를 주석으로 구분했다. |
| LIFE01-R2 | 중간 | 그래프 수가 무제한이면 생성 계정의 존재를 확인하지 않아 부재 계정에 그래프·소유자 부여를 생성할 수 있었다. | 최초 부재 계정 시험이 실제 성공을 검출했다. 기존 `requireAccount`를 재사용하고, 한도가 있는 경로의 계정 부재도 `ErrNotFound`로 구분했다. 무제한 경로에는 한도용 계정 잠금·집계를 추가하지 않았다. |
| LIFE01-R3 | 중간 | 그래프 갱신의 입력 검증이 모델의 텍스트 계약과 달랐고, 잘못된 UTF-8·NUL은 DB 장애로 처리될 수 있었다. | 활성 행을 잠근 뒤 현재 판을 비교하고 `ValidateGraphUpdate`로 이름·설명을 검증한다. 잘못된 텍스트는 `FieldError`, 과거 판은 `VersionConflictError`, 삭제·부재는 `ErrNotFound`로 구분한다. |

- 갱신 SQL은 이름·설명·판 번호만 변경한다. 생성 계정·생성 시각·활동 시각·문자 누계·삭제/유예·내용 판 등 시스템 열과 기존 등급을 보존했다.
- 소유권 인계 후에도 그래프의 생성 계정은 고정되고 노드의 기여 계정 및 현재 소유자는 별개임을 실제 저장 상태로 대조했다. 저장 API에 대한 시험이며 향후 MCP 호출자의 권한·인증 결합을 대신하지 않는다.
- 기존 SRS·SDD의 생성·갱신 계약을 구현한 변경이다. 스키마·패키지 경계·주입 인터페이스·DOX 소유권은 바뀌지 않아 해당 정본과 마이그레이션은 유지했다.

## 모듈 시험 행렬

| 경계 | 관찰한 결과 |
|---|---|
| 생성 | 같은/다른 계정의 동명 그래프, UUIDv7·초기 판·UTC 값 왕복, 초기 직접 owner 한 행, 중복 ID의 기존 행 보존 |
| 입력·주체 | 잘못된 생성 초기 상태·이름·설명, 한도 유무 양쪽의 부재 생성 계정, 빈/공백·UTF-8·NUL 갱신 입력과 비양수 기대 판 |
| 갱신·이력 | 생성 계정·노드 기여 계정·현재 소유자 분리, 선택 설명 비우기, 이름·설명·판 외 전체 시스템 열 보존 |
| 원자성 | 소유자 등급 삽입/지연 커밋 실패 뒤 그래프·등급 0행, 메타데이터 갱신/지연 커밋 실패 뒤 이전 값 보존, 같은 ID·기대 판 재시도 성공 |
| 바깥 트랜잭션 | 생성·갱신 저장점 해제 뒤 바깥 롤백이 그래프·등급·판 변경을 모두 취소 |
| 경합 | 4연결 풀에서 같은 기대 판의 8개 동시 갱신 중 1개 적용·7개 현재 판 충돌, 실제 잠금 대기 뒤 앞선 갱신/삭제/롤백 재판정 |
| 취소·회복 | 생성 계정 잠금·갱신 행 잠금 대기 취소 뒤 원상태, 실제 `AcquiredConns=0` 및 연결 예약 반환 |
| 기존 경계 | 동시 생성 한도, 서로 다른 멱등성 키의 바깥 커밋까지 직렬화, 삭제와 사용자 쓰기, 저장 왕복·실패 처리 회귀 |
