# 공개 로그인·가입 자원 보호 검토

## 대상과 근거

- 분석일: 2026-10-10, 기준 `dev`의 `6af6801`, 관련 [#109](https://github.com/Alpha-gone/agent-context-sharing/issues/109).
- 범위: 공개 로그인·가입의 시도 빈도, 비밀번호 작업 동시 실행·본문 상한, 재시도·취소와 프록시 식별 경계.
- 기존 경로는 없는 계정에 더미 bcrypt를 실행하고 가입은 DB 생성 전에 해시했으나 관련 애플리케이션 자원 상한은 없었다. 실제 공격·CPU 고갈·취약한 운영 정책을 확인했다는 의미가 아니다.
- SRS의 `FR-AGENT_CONTEXT-131`에 보호 의무를 반영한 뒤 SDD를 먼저 갱신했다. OWASP·Cloudflare의 공식 근거는 `reference.md`에 기록하고 프로젝트 수치·계정 실정책과 구분했다.

## 보완한 방어 경계

- 출처별 10회·인스턴스별 60회의 60초 고정 창을 로그인·가입 POST가 공유한다. 소스 포트·아이디·쿠키·성공 여부로 예산을 초기화하거나 나누지 않는다. IPv6 /64 합산, 최대 4096개·만료 정리와 활성 제한 비축출을 적용한다.
- 웹은 출처 검사 후·양식 해석 전에 예산을 확인하고 8 KiB 상한을 적용한다. 초과 시 429·정수 초 Retry-After·no-store와 같은 안내를 보내며 본문 초과는 413으로 거부한다.
- 인가 서비스의 비밀번호 작업 자리는 최대 4개·대기열 없음이다. DB 조회 전에 확보하고 등록·중복 가입·더미 대조·정상 대조·구형 재해시가 공유한다. bcrypt 비용·해시 형식·검증·조건부 구형 갱신 계약을 유지한다.
- 시작 전 취소는 즉시 반환하고, 실행 중 취소는 실제 bcrypt 반환 전 자리를 반환하지 않는다. 반환 후 취소를 확인해 계정 생성·해시 갱신·세션 발급을 막고 오류·취소·정상 반환에서 자리를 정리한다.
- 조립 계층이 기존 신뢰 대역·단일 HTTPS 검사를 유지한 채 유효한 단일 CF-Connecting-IP만 사용한다. 직접 TLS·비신뢰 상대·잘못된 헤더는 실제 상대 주소로 합산하고 범용 전달 주소 목록은 신뢰하지 않는다.
- 계정별 실패 잠금은 만들지 않는다. 없는 계정과 틀린 비밀번호의 로그인 안내는 같고 중복 가입은 기존 형식·중복 안내와 해시 비용을 유지한다. 더미 비밀번호와 같은 빈 입력도 없는 계정을 인증하는 결과로 만들지 않는다.

## 검증 결과

- Go 1.27.1의 핵심 `TestPasswordWork*`·`TestMissingAccountNever*`·`TestAuthenticationAttempts*`·`TestClientAddress*`를 세 패키지에서 race 모드로 10회 반복 통과했다.
- 실제 개발 PostgreSQL의 전용 `issue109_test_20261010` DB에 정식 `001_init` 마이그레이션을 적용했다. `TEST_DATABASE_REQUIRED=1`로 `go test -race -count=1 ./internal/authz ./internal/web ./cmd/server`: 테스트·하위 테스트 350건 통과, 실패·건너뜀 0건. 시험 DB를 정상 삭제했다.
- 서버 전체를 같은 방식의 새로운 전용 DB에서 `go test -race -count=1 -p 1 ./...`로 패키지별 순차 실행하여 테스트·하위 테스트 1,156건 통과, 실패·건너뜀 0건을 확인했다. 테스트 파일이 없는 `cmd/migrate`·`migrations` 두 패키지의 표시는 통합 시험 건너뜀과 구분했다. 이 시험 DB도 정상 삭제했다.
- 격리 작업 대역에서 등록·중복 등록·더미·기존 대조 네 작업의 동시 최대값 4, 초과 로그인·가입 즉시 거부와 자리 반환·회복을 확인했다. 구형 재해시가 실행 중 취소되어도 자리를 유지하고 저장 해시를 갱신하지 않는지 확인했다.
- 고정 시계로 두 경로·mapped 주소·소스 포트·아이디 변경의 예산 공유, 60초 회복·밀리초 남은 창 올림, 전체 120개 동시 시도 중 60개 허용, IPv6 /64·4096개 상태의 상한과 만료 회수를 대조했다.
- 양쪽 경로의 교차 출처·취소·본문 초과·잘못된 양식 선행 거부, 작업 초과의 429·헤더·세션 쿠키 미발급, 정상 가입 성공 후 제한 유지와 GET 비제한을 확인했다.
- 실제 웹→서버 어댑터→인가→DB 경로에서 정상 가입·로그인·서명 세션 검증, 중복 가입·없는 계정·비밀번호 불일치, 같은 출처의 열한 번째 시도 거부와 다른 출처의 같은 계정 정상 로그인을 확인했다.
- 서버·클라이언트 각각 `go build ./...`·`go vet ./...` 통과했다. 전체 `gofmt -l .`·`git diff --check`, 변경 문서 12개의 상대 링크·Child DOX Index·요구사항 172건 추적과 한국어 표현·맞춤법을 점검했다. 기존 SDD 추적표 설명의 오래된 168건 표기도 실제 172건으로 정합화했다.
- 통합 시험 초기에 존재하지 않는 `VerifyWebSession` 서비스 메서드를 참조해 빌드가 실패했으며 기존 `Verify` 계약으로 수정한 뒤 반복·DB 검증을 통과했다.
- 최초 서버 전체 패키지 병렬 실행은 1,155건 통과·1건 실패였다. 변경하지 않은 `internal/store/index_integration_test.go:265`의 `TestReindexExcludesAndReplacesOutdatedModel`이 DB 전체 이전 모델 행 수 339를 기대했으나 351을 관측했다. 시험 코드가 전체 행 수를 시작 전후 대조하고 다른 패키지가 같은 DB에 색인 행을 쓰므로 병렬 간섭으로 추정한다. 패키지별 순차 실행에서는 전체 1,156건이 통과했으나 최초 실패를 통과로 바꾸어 보고하지 않으며 기존 시험의 패키지 간 격리 보완은 이번 범위에 섞지 않았다.

## 미해결 결함과 운영 확인

- 이번 범위의 자동 검증에서 추가로 확인한 미해결 결함은 없다. 실제 Cloudflare 계정의 정책·Tunnel 주소 전달, 자체 Worker·Pseudo IPv4·IP 헤더 제거와 운영 부하·오탐률은 미확인이다. 계정 접근 도구·권한이 없어 적용 증거를 확인하지 못했으며 애플리케이션 방어의 전제조건으로 삼지 않았다.
- 범위 밖의 기존 재색인 시험은 패키지 병렬 실행 시 실패가 관측되었고 원인 분리는 순차 실행 통과까지 수행했다. 패키지 간 DB 격리의 보완·병렬 조건 재검증은 남아 있으며 해당 시험·저장소 코드를 수정하지 않았다.
- NAT·공유 프록시·IPv6 /64 사용자가 예산을 공유한다. 누락된 주소 헤더는 프록시 주소로 합산하고 같은 호스트의 신뢰 경로에서는 헤더 위조가 가능하다. 지역 예산은 재시작 시 초기화되며 인스턴스 수만큼 늘어난다. 고정 창 경계의 합산 시도와 분산 공격에 대한 완전한 방어·운영 처리량 보장을 주장하지 않는다.
- 외부 정책·접근 제어·해시 비용은 변경하지 않았으며 운영 공격·CPU 고갈 부하, 실제 브라우저·외부 서비스·운영 배포·클라이언트 전체 race는 실행하지 않았다.

## DOX pass

- 루트·웹·명세 소유 문서와 부모 Child DOX Index를 갱신했다. SRS·SDD·운영 안내·개발 계획을 정합화하며 인증 고도화·계정별 실패 잠금의 미정 범위를 유지했다.
- 공개 MCP 도구·클라이언트 계약·DB 스키마·환경 변수·의존성·README와 기존 용어는 바뀌지 않아 해당 문서를 유지했다.
- 기존 사용자 IDE 파일 staging과 개발 DB·서명 키·컨테이너·볼륨·.env는 보존했다. 커밋·push·PR·이슈 종료는 수행하지 않았다.
