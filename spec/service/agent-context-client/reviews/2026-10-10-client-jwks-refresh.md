# 클라이언트 서명 키 회전 수정 검토

## 대상과 근거

- 분석일: 2026-10-10.
- 관련 이슈: [#107](https://github.com/Alpha-gone/agent-context-sharing/issues/107).
- 기준: `dev`의 `4a90564`, 클라이언트 SRS의 `FR-AGENT_CONTEXT_CLIENT-012`·`-018`·`-024`와 SDD의 「토큰 갱신과 재인증」.
- 범위: `client/internal/client/authorize`의 갱신 검증·JWKS 조회·취소·종료 수명과 `remote`의 실제 로컬 TLS fixture.
- 근거: 기준 코드의 초기 JWKS만 사용하는 경로, 새 키 회전·오류·동시성 회귀와 실제 로컬 TLS·loopback 연결 시험. 실제 서비스 서버나 외부 로그인은 사용하지 않았다.

## 미해결 결함

이번 범위에서 확인한 미해결 결함은 없다. 아래 검증 경계와 조회 간격의 제한은 별도로 유지한다.

## 해결된 결함

- `DEF-20261010-107` — 중간, 기준 코드 `client/internal/client/authorize/authorize.go:315`·`jwt.go:152`: 갱신 JWT를 초기 인가의 JWKS로만 검증하여 새 서명 키의 정상 토큰을 `ErrProtocol`로 거부했다. 원격 응답 처리도 해당 오류로 끝나 정상 도구 응답을 반환하지 못했다. 알 수 없는 `kid`를 구분해 신뢰한 JWKS를 제한적으로 다시 조회하고 한 번 재검증하도록 수정했다. 회전 회귀 및 실제 로컬 TLS fixture에서 새 토큰 저장·응답 보존·후속 요청 적용을 확인했다.

## 수정과 계약 보존

- SDD를 먼저 갱신하고 구현했다. JWT의 `jku`·`x5u`는 사용하지 않으며 발견에서 검증·보관한 `jwks_uri`만 조회한다. 잘못된 JWT 외피·본문과 알려진 키의 서명·claim 실패에는 조회하지 않는다.
- 기존 HTTPS·redirect·응답 크기·공개 EC JWK·중복 `kid` 검증을 재사용한다. 신·구 키 공존은 허용하지만 issuer·resource·첫 계정·프로세스 `cnf.jkt`·만료 및 갱신 헤더 결합은 그대로 검증한다.
- 조정자별 조회 하나, 최대 128명 대기, 시도 시작부터 30초 간격과 공유 실행 10초 기한을 적용한다. 성공·실패 모두 간격을 소비하고 기존 호출 context·원격 처리 잔여 시간을 유지한다. 새 브라우저 인가나 보호 MCP 요청 재전송을 시작하지 않는다.
- 대기자별 취소를 분리하고 마지막 취소·`Close`는 공유 조회 취소와 HTTP 정리를 기다린다. 호출자 취소가 오류 분류보다 우선한다. 새 인가가 발견 정보를 게시하면 오래된 조회가 새 캐시를 덮어쓰지 않는다.
- 조회·검증·계정 결합 실패는 기존 자격 증명을 교체하지 않는다. 만료 비역행·동일 만료 마지막 저장과 비밀 비노출 계약도 유지한다. 공개 도구·환경 변수·서버 API·DB·모듈 의존성은 바꾸지 않았다.

## 검증 결과

- Go `1.27.1`, 클라이언트 `go test -race -count=1 ./...`: 테스트·하위 테스트 579건 통과, 건너뜀 0건, 실패 0건. 기본 패키지의 시험 없는 경로는 실행된 시험 수에 포함하지 않는다.
- `TestRefresh*`와 `TestHTTPWithRealTLSAuthorizationAndConcurrentCalls`의 `-race -count=10` 반복 통과.
- 신·구 키 공존·새 토큰 저장, 알 수 없는 키·잘못된 서명·issuer·resource·계정·DPoP·만료·갱신 헤더·`nbf` 거부를 확인했다. 알려진 키의 잘못된 서명과 잘못된 JWT 외피·본문은 외부 조회 0회다.
- 전송·빈 키·중복 키·개인 키 실패 뒤 토큰·기존 키 캐시 보존, 30초 경계 직전 거부·경계 이후 복구, 128개 동시 갱신의 조회 1회·129번째 거부와 성공 직후 임의 `kid`의 재조회 차단을 확인했다.
- 요청에 최대 10초 공유 deadline이 전달되고 50ms 호출자 deadline·개별 취소·마지막 취소·종료 정리가 동작함을 확인했다. 새 발견 정보 게시 뒤 오래된 조회의 캐시 비덮어쓰기와 동일 발견 경계의 최신 키 재사용·다른 경계 거부도 검증했다.
- 실제 로컬 TLS fixture는 A 키로 인가한 뒤 A·B 키를 제공하고 B 키 갱신을 보냈다. 목록 응답이 보존되고 후속 100개 호출에 B 토큰이 적용됐으며 JWKS는 초기 1회·회전 1회만 조회했다. 기존 PKCE·DPoP·응답 상관·멱등성·계정 전환 회귀도 통과했다.
- 서버·클라이언트 각각 `go build ./...`·`go vet ./...`, 서버의 `TestToolManifestMatchesClient` 통과.
- 저장소 전체 `gofmt -l .`, `git diff --check`, 변경 문서의 상대 링크·한국어 표현·맞춤법과 SRS→SDD 요구사항 추적성을 확인했다.

## 남은 검증 경계와 DOX pass

- 30초 안에 다시 키가 회전하면 두 번째 외부 조회는 거부한다. 자동 예약 재시도는 하지 않으며 간격 이후 새 호출에서 다시 시도한다. 이는 임의 `kid`에 의한 무제한 조회를 막기 위한 고정 정책이다.
- 실제 서비스 서버·DB 통합, 외부 로그인·시스템 브라우저, WSL2·지원 호스트·공식 conformance·배포 판정은 이번에 재실행하지 않았다. 로컬 TLS fixture 결과로 6단계의 미완료 출시 기준을 승격하지 않는다.
- 구현과 서비스 명세의 소유 `AGENTS.md` 및 부모 Child DOX Index를 갱신했다. 지속 경계와 파일 배치는 바꾸지 않았으며 새로운 하위 DOX 문서는 만들지 않았다.
- SRS는 기존 갱신·계정·취소 요구사항을 구현하는 수정이므로 유지했다. 서버 명세·용어집·README·배포 구성도 공개 계약·용어·실행 설정이 바뀌지 않아 유지했다.
- 개발 계획에는 실제 수정·검증 결과만 반영했다. 기존 사용자 변경인 IDE 설정 파일은 수정하거나 작업 산출물에 포함하지 않았다.
