# 서비스 명세 색인

## 목적

이 문서는 프로젝트에서 기획하는 서비스의 범위, 상태와 주요 명세 진입점을 제공한다.

## 서비스 목록

| 서비스                 | 역할                                                                                                                                 | 상태                 | 주요 문서                                                |
|------------------------|--------------------------------------------------------------------------------------------------------------------------------------|----------------------|----------------------------------------------------------|
| 에이전트 컨텍스트 관리 | 공유 컨텍스트 그래프와 호스트 내장 MCP의 직접 연결·표준 OAuth를 제공하는 목표 서비스다. | 직접 연결 설계 채택·구현 예정, 평가 보강 4건·진단 로그 3건 설계 대기 | [SRS](agent-context/SRS.md), [SDD](agent-context/SDD.md) |

## 서비스 관계

웹 관리·계정 인증·저장·검색·색인은 하나의 서버 서비스가 소유한다. 호스트 내장 MCP 직접 연결의 요구사항과 목표 설계도 같은 서비스의 SRS·SDD에서 추적하며, 아직 제공하지 않는다.

## 공통 미정 사항

직접 연결 목표의 상세 계약·이행·검증은 [서버 SDD 「호스트 직접 연결 전환 설계」](agent-context/SDD.md#호스트-직접-연결-전환-설계)가 소유한다. [SRS 「토큰 갱신」](agent-context/SRS.md#토큰-갱신)에서 최대 30일·비활동 7일과 정리 정책을 확정했고 [「직접 연결의 구현 기준과 첫 호스트 시험」](agent-context/SRS.md#직접-연결의-구현-기준과-첫-호스트-시험)에서 공식 Go SDK v1.8.0·초기 revision 2025-11-25·Codex CLI 0.160.1 기준을 선정했다. SDD의 `TBD-AGENT_CONTEXT-063`은 재작성 시 확정으로 동기화하며 `064`의 실제 상호운용 검증은 운영 전 수행해야 한다. 현재 직접 연결과 새 토큰 갱신·재시작·쓰기 인수는 미검증이다.

Air Context와 관련 연구에서 채택한 검색 단위·외부 원본 재현성·임베딩 용도별 비교·에이전트 업무 비용 평가(`FR-AGENT_CONTEXT-160`~`163`)는 요구사항이 확정되었으며 상세 설계와 구현은 대기 중이다. 요구사항 자체의 미정 사항과 구분하며 [SDD 추적표](agent-context/SDD.md#요구사항-추적표)에서 추적한다. 서버 외부 원본 수집, AST 분할, 이진 양자화와 관찰 마스킹의 운영 채택을 뜻하지 않는다.

시험 분석용 종류별 파일 저장·흐름 추적·파일 보호(`FR-AGENT_CONTEXT-173`~`175`)와 여섯 JSON Lines 파일·7일 보존·유한 상한·기동 및 실행 중 실패 정책은 [SRS 「종류별 진단 로그」](agent-context/SRS.md#종류별-진단-로그)에서 확정했다. 사용자 지시에 따라 SDD는 수정하지 않았으며 상세 설계·구현·실제 파일 저장 검증은 대기 중이다.

요구사항과 상세 설계가 모두 정한 뒤에도 남아 있는 항목이다.

요구사항 수준은 `SRS.md`의 「미정 사항」이, 설계 선택 수준은 `SDD.md`의 「설계 미정 사항」이 소유한다.

- 인증 고도화. 비밀번호 재설정, 실패 잠금, 다중 요소와 외부 IdP (`TBD-AGENT_CONTEXT-048`)
- 계정 소멸 경로. 탈퇴와 그에 따른 등급 회수 (`TBD-AGENT_CONTEXT-049`)
- 운영자 역할 분리. 검증 단계에서는 인증된 모든 계정이 운영자 자격을 갖는다 (`TBD-AGENT_CONTEXT-052`)
- Client ID Metadata Documents 지원 여부. 사전 등록을 확정했고 명세는 이 방식을 SHOULD로 권고한다 (`TBD-AGENT_CONTEXT-060`)
- 한국어 형태소 분석. 키워드 채널이 `simple` 구성을 쓰며 채널 기여를 측정한 뒤 판단한다 (`TBD-AGENT_CONTEXT-061`)
- 응답 직렬화 형식 (MCP `tools` 응답 규약을 따르며 세부는 구현에서 정한다)
- Row Level Security 채택 (읽기 경로 검증 후 판단)
- 계정 플랜의 이름과 구체 값 (명세는 항목과 기본값만 정하고 값은 운영 구성으로 둔다)

벡터 인덱스의 HNSW 고정과 그래프 정점 파티셔닝 미채택은 [SRS 「임베딩 저장」](agent-context/SRS.md#임베딩-저장)과 [「저장 계층화」](agent-context/SRS.md#저장-계층화)에서 확정했다. 임베딩 테이블만 `hot`·`cold`로 계층화한다. 사용자 지시에 따라 SDD는 추후 재작성 시 동기화하며 현재 SDD의 해당 미정 서술은 이 결정이 아직 반영되지 않은 상태다.

콜드 임베딩은 같은 PostgreSQL의 온라인 영속 저장소로 제한한다. 공개 평가는 [SRS 「초기 공개 평가와 반복 정책」](agent-context/SRS.md#초기-공개-평가와-반복-정책)의 LongMemEval_S·LoCoMo·자체 보완과 조건별 10회·95% 대응 신뢰구간으로 확정했다. 표본 부족·불명확한 결과는 판정 보류하며 실제 성능·비용은 아직 측정하지 않았다. 이 결정도 SDD 재작성 시 동기화한다.

상세 설계가 확정해 이 목록에서 뺀 항목은 HTTP 서버와 라우팅, 데이터베이스 드라이버와 커넥션 풀, 인가 서버 구현 방식, 색인 작업 큐 구현 방식, 색인 재시도 한계, 화면 배치와 시각 표현 규칙이다. 이후 `source_ref`의 하위 구조, 관계형 테이블의 열 정의와 스키마 적용 방식도 확정했다. 계정·웹 세션·운영자 복구의 정본은 서버 SRS·SDD에 둔다. 표준 OAuth와 호스트 직접 연결은 구현 대기다.
