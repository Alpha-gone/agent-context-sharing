# RINF-06 비교 표본 준비

## 범위

[관계 추론 평가 설계](../sdd/evaluation.md#관계-추론-모델-비교)에 따라 외부 자료나 실제 사용자 데이터를 사용하지 않은 합성 판정 입력 초안을 만들었다. `gpt-6-luna`는 채택 모델이나 실제 호출은 하지 않았다. 이 기록은 품질 평가 결과나 자동 확정 근거가 아니다.

- [고정 입력 초안](rinf-06-draft/inputs.json): SHA-256 `ca5c2f51fdcc7608653baccd80ed4700d930a899aefca6a9868d02316a3a7b37`
- [정답 초안](rinf-06-draft/ground-truth.json): SHA-256 `99c5c3c923bd413c99b1f045414812646ff26c7baed1323eb7ba78e170634265`
- 표본은 조정용 7건과 판정용 7건이며, 각각 관계 세 유형, 유사하지만 무관한 쌍, 인과 근거가 없는 쌍, 판단 보류, 유도 지시를 담는다. `abstain_or_none`은 두 출력 모두 관계를 만들지 않는 정답이라는 평가용 표기다.
- 각 파일은 표본 ID와 순서로 대응한다. 정답은 모델에 전송하지 않는다. checksum은 위 파일 전체 바이트의 SHA-256이며 평가 전에 표본을 고치면 다시 고정해야 한다.

## 제한과 후속 작업

이 작은 초안은 표본 구조와 사례를 검토하기 위한 것으로, 유형별 오류율이나 통계적 합격을 판단하기에 충분하지 않다. `part_of`의 실제 후보 자격을 결정하는 구성원·시간 조건을 재현하는 그래프 입력과 채널별 검색 정답도 아직 없다. `cmd/eval`의 `-check-relation-samples`로 고정 입력이 실제 `BuildInput` 결과와 같은지 확인한다. 이 검사는 합성 식별자와 단일 후보를 사용하므로 실제 DB의 후보 ID·판 대응이나 후보 검색 품질을 검증하지 않는다. 정답의 타당성은 독립적인 검토가 필요하다.

평가 전에는 표본을 검토·확대하고 후보 검색 정답 및 실제 생성 경로를 준비하며, 반복 횟수·프로필 지문·확정된 가격과 유형별 합격선을 manifest에 고정해야 한다. 현재 평가 실행기에는 관계 추론 전용 비교 모드와 결과 묶음이 없다. 에이전트 기준선 과업 trace와 추론·임베딩을 포함한 총비용도 미측정이다.

`TBD-AGENT_CONTEXT-065`의 합격선은 미정이다. 미측정 항목은 통과로 표시하지 않는다. 자동 확정과 운영 구성은 변경하지 않았다.

## 2026-11-14 표본 검사 경로

`go run ./cmd/eval -check-relation-samples <입력 파일> -relation-gold <정답 파일>`은 외부 제공자나 DB 없이 파일 checksum, 조정·판정 분리, 유형·방향·별칭과 입력 생성 결과를 확인하고, 정답으로 구성한 판정이 서버의 `ValidateOutput`을 통과하는지 검사한다. 인용은 합성 본문의 한 글자로 구성하여 검사하며 근거의 의미적 타당성을 검토하지는 않는다. 결과는 표본의 내용과 정답을 포함하지 않으며 `sample_structure_only`와 `default_activation=false`를 기록한다. 첫 검사에서 인과 방향 배열의 순서가 실제 생성 순서와 달라 초안을 생성 순서에 맞게 수정했다. 표본의 의미와 통계적 충분성, 실제 검색과 모델 품질을 보증하지 않는다.

검사 명령을 실행기에 연결한 뒤 Go 1.27.3으로 재실행하여 조정용·판정용 각 7건과 위 checksum을 확인했다. `go build ./...`, `go vet ./...`, `gofmt -l .`도 통과했다. 이는 구조 검사이며 모델 호출 결과가 아니다.

## 실제 제공자 연결 시도

사용자 요청에 따라 조정용 합성 표본 `tune-01` 한 건을 기존 OpenAI 어댑터와 `gpt-6-luna`로 호출했다. 기본 실행 환경에서는 DNS 조회가 실패했고, 네트워크 권한으로 다시 시도한 요청은 HTTP 429를 받았다. 어댑터는 오류 응답 본문을 보존하지 않으므로 할당량 부족과 속도 제한 중 원인은 확인하지 못했다. 유효한 판정 응답·토큰 사용량·비용은 확보하지 못했으며 추가 자동 재시도는 하지 않았다. 이 시도는 모델 품질 평가가 아니다. 표본 확장·독립 정답 검토, 후보 검색 평가 자료와 비교 실행기는 여전히 필요하며 합격선과 자동 확정 판정은 보류한다.

사용자 요청으로 같은 조정 표본을 한 번 재시도한 결과 제공자가 완료 응답을 반환했다. 경과 시간은 4,403ms, 입력 372토큰, 출력 162토큰이다. 연결 확인만 수행했으며 판정 내용의 서버 검증·정답 대조와 금액 산정은 수행하지 않았다. 따라서 이 결과는 품질 평가나 자동 확정 근거가 아니다.

## 조정용 탐색 호출

사용자의 후속 요청에 따라 고정 초안의 조정용 7건을 `gpt-6-luna`와 기존 어댑터로 각 한 번 호출하고, 합성 후보 식별자를 사용한 서버 `ValidateOutput`과 초안 정답에 대조했다. 일회성 탐색 도구를 사용했으며 원시 응답과 본문은 기록하지 않았다. `tune-01`과 `tune-03`은 검증을 통과하고 초안 정답과 일치했다. `tune-05`, `tune-07`, `tune-09`, `tune-11`, `tune-13`은 개별 판정에서 `output_invalid`로 분류되었다. 원시 응답을 보존하지 않아 위반 세부 원인은 이 측정만으로 판별할 수 없다. 따라서 이 다섯 건을 모델의 정답 불일치로 단정하지 않는다.

일곱 호출의 입력 토큰은 2,643개, 출력 토큰은 1,462개다. 실제 단가와 금액, 반복 간 일관성은 측정하지 않았다. 이 결과는 작은 초안과 1회 측정의 탐색 결과이며 판정용 표본 평가·후보 검색·전체 흐름 비용 비교를 대신하지 않는다. 재현 가능한 실행기와 위반 사유의 안전한 집계, 표본 확대 및 정답 독립 검토가 필요하다. 합격선은 미정이며 자동 확정 판정은 보류한다.

## 출력 계약 위반 재현

후속 요청에 따라 이전에 위반된 조정용 5건을 각각 다시 호출하고 본문·인용·이유 원문을 기록하지 않은 채 판정 필드와 서버 검증 결과를 확인했다. 이는 새 응답의 관찰이며 이전 응답의 정확한 원인을 복원한 것은 아니다.

- `tune-05`와 `tune-09`: `causes`에 `none`을 반환하면서 방향을 비웠고 양쪽 근거를 채웠다. 계약은 허용된 방향과 빈 근거를 요구한다.
- `tune-07`: `relates_to`에 `relation`을 반환하면서 방향을 `T_to_C`로 지정했다. 이 유형의 방향은 빈 문자열이어야 한다.
- `tune-13`: `causes`에 `none`과 빈 근거를 반환했지만 방향을 비웠다.
- `tune-11`: 이번에는 `abstain`, 빈 방향과 빈 근거로 검증을 통과했다. 앞선 실행과 결과가 달라 반복 측정이 필요하다.

현재 제공자 지시는 허용 방향을 쓰고 관계 판정에 인용하라고 하지만, 비관계 판정에서도 방향을 채워야 하는 경우와 빈 근거 요구를 명시적으로 설명하지 않는다. 이것이 위반에 기여했을 가능성은 있으나 원인으로 확정하려면 별도 프로필의 통제 비교가 필요하다. 지시 변경은 프로필 판과 지문에 영향을 주므로 기존 측정과 섞거나 소급 적용하지 않는다.

## 프롬프트 판 2 조정용 탐색

방향과 비관계 판정의 빈 근거를 명시한 판 `2`를 별도 제공자 프로필로 추가했다. 기존 실행기의 판 `1`은 유지하고, 제공자와 프로필의 프롬프트 판 불일치는 거부한다. 같은 조정용 표본 7건을 각 1회 호출한 탐색에서 서버 출력 검증은 7건 모두 통과했고 초안 정답에는 5건이 일치했다. `tune-05`는 기대 관계를 `none`으로, `tune-07`은 기대 `none`을 관계로 판정했다. 입력 3,025토큰, 출력 1,098토큰이며 가격·총비용은 미산정이다. 일회성 도구의 측정이며 표본은 작고 독립 검토되지 않아 이 결과를 정식 비교나 자동 확정 근거로 쓰지 않는다.

## 조정 표본 측정 경로

`cmd/eval`의 `-measure-relation`은 조정용 초안만 판 `2`로 한 번씩 호출한다. 호출 전에 표본과 정답의 구조·생성 경로를 확인하고 체크섬과 프로필 지문을 신규 JSONL 파일에 기록하며, 각 호출의 서버 검증·정답 대조 결과와 지연·토큰만 기록한다. 결과 파일을 덮어쓰지 않으며, 실패 시 그 시점까지의 기록을 보존한다. 실행에는 `-relation-gold`와 `-out`, 환경 변수 `RELATION_INFERENCE_API_KEY`가 필요하다. 실제 입력·근거·이유·원시 응답은 결과에 넣지 않는다.

[측정 기록](rinf-06-draft/tune-v2-run.jsonl)은 7건 모두 서버 출력 검증을 통과했고 초안 정답과 4건이 일치했다. 입력 2,637토큰과 출력 1,132토큰을 사용했다. 당시 실행기는 조정 표본 탐색용이며 정식 비교 manifest·판정용 표본·반복·후보 검색·전체 흐름과 총비용을 처리하지 않았다. 자동 확정과 최종 채택은 보류한다. 평가 실행기 패키지 시험은 기본 샌드박스의 로컬 포트 바인딩 제한으로 실패한 뒤 로컬 소켓 접근을 허용해 재실행하여 통과했다.

## 확장 표본 반복 탐색

[초안 2 독립 검토](rinf-06-draft-v2/REVIEW.md)를 거쳐 입력·정답 체크섬을 고정하고 판정용 14건을 프롬프트 판 `1`·`2` 각각 세 차례 측정했다. 실행기는 분할·판·반복 횟수를 선택하며 결과 시작에 입력·정답 체크섬과 프로필 지문, 반복 횟수를 기록한다. 결과는 [판 1](rinf-06-draft-v2/eval-p1-3.jsonl), [판 2](rinf-06-draft-v2/eval-p2-3.jsonl)에 있다.

판 `1`은 42회 중 서버 출력 검증 23회와 초안 정답 일치 21회, 판 `2`는 출력 검증 42회와 초안 정답 일치 36회다. 판 `1`은 14개 표본 중 8개에서 반복 간 판정 또는 검증 상태가 달랐고 판 `2`에서는 없었다. 입력·출력 토큰은 각각 판 `1` 13,753·7,198개, 판 `2` 16,062·5,969개다. 반복은 독립 표본이 아니다. 표본 자체의 제약과 검증 실패를 고려하면 이 숫자는 유형별 품질 합격이나 자동 확정 근거가 아니다.

실행 당시 단가 판을 고정하지 않았고 캐시 세부 사용량을 수집하지 않아 실제 금액은 미측정으로 남긴다. 독립 과업의 에이전트 기준선·후속 검색·임베딩과 후보 검색 데이터가 없어 총비용과 후보 검색 성능도 측정하지 않았다. 이 결과는 정식 결과 묶음의 대체물이 아니며 채택 판정은 보류한다.

### 반복 탐색의 유형별 집계

판 `1`의 `causes`는 15회 중 검증·초안 정답 일치가 각각 5·5회, `part_of`는 6·6회, `relates_to`는 21회 중 12·10회다. 판 `2`는 같은 순서로 15·15회, 6·6회, 21회 중 21·15회다. 판 `1`의 지연 중앙값과 최근접 순위 p95는 2,695ms·4,275ms이고, 판 `2`는 2,359ms·3,279ms다. 각 지표의 분모는 독립 사건이 아닌 3회 반복을 포함한 호출 수다. 지연에는 실제 제공자 호출과 서버 검증이 포함되며, 작은 표본이므로 신뢰구간이나 성능 우위로 해석하지 않는다.

### 남은 전체 흐름 측정의 실행 경계

당시 `business_tasks` 입력은 `lookup`·`irrelevant`·`reduction` 조건만 수용했고 비용 항목에도 서버 관계 추론이 없었다. 해당 실행기는 실제 에이전트를 실행하지 않고 외부 trace를 가져온다. 따라서 관계 탐색과 서버 `apply` 조건을 이 계약에 임의로 끼워 넣거나 추론 비용을 다른 항목에 합산하면 같은 과업의 총비용을 올바르게 대조할 수 없다. 관계 추론 비교 전용 조건·추론 비용 집계와 실제 동일 과업 trace가 필요했다. 당시 Gemini API 키는 비어 있어 실제 임베딩 사용량도 확보하지 못했다. 판정 입력만으로는 후보 검색 포함률을 계산할 수 없다.

### 실제 임베딩과 후보 검색 경로 탐색

후속 요청에 따라 Gemini 키가 설정된 것을 확인했다. 합성 문서 한 건을 `gemini-embedding-2`의 문서 임베딩으로 호출해 768차원 응답을 받았으며 586ms가 걸렸다. 초기 시도의 404는 일회성 확인 도구가 API 버전 경로를 중복한 문제였고 도구의 주소를 바로잡아 재시도했다. 제공자 사용량은 기존 어댑터가 수집하지 않아 금액은 미측정이다.

이어 합성 사건 세 건의 실제 문서 임베딩을 만들고 별도 생성·정리한 시험 DB에서 후보 검색을 한 번 실행했다. 대상과 정답 관계 후보 및 무관 후보에 같은 구성원을 부여했다. 의미 채널은 후보 2건(정답·무관 각 1), 키워드 채널은 정답 1건, 구성원 채널은 후보 2건(정답·무관 각 1)을 반환했고 규칙·대화 채널은 0건이었다. 임시 벡터·시험 도구는 실행 후 제거했다. 같은 구성원을 공유하는 단일 합성 과업의 탐색이며 다채널 후보 검색 포함률이나 독립적인 채널 기여 성능을 추정하는 표본이 아니다. 에이전트 기준선·후속 검색·실제 임베딩 사용량과 총비용은 여전히 미측정이다.

### 6개 합성 과업의 채널 탐색

초안 2 판정용 양성 6건(`eval-02`, `04`, `06`, `22`, `23`, `24`)에서 사건 쌍과 무관 사건의 Gemini 문서 임베딩 총 18개를 만들고, 각 과업을 별도 그래프에 넣어 격리 시험 DB에서 검색했다. 각 그래프의 구성원·시간은 시험용으로 구성했으며 기존 판정 입력에 이 그래프가 포함된 것은 아니다. 모든 과업에 같은 무관 문장을 쓰고 같은 구성원을 공유하게 했으므로 독립 업무 과업이나 모집단 대표 표본이 아니다.

첫 실행에서 `part_of` 두 건의 정답 사건은 검색됐으나 유형 자격이 없었다. 시험 설정이 양쪽 사건에 동일한 구성원 집합을 부여해 진부분집합 조건을 충족하지 않았기 때문이다. 후보 사건에 구성원을 하나 추가하고 같은 벡터로 별도 DB에서 다시 실행한 결과, 정답 사건과 기대 유형은 의미·구성원 채널에서 6/6, 키워드 5/6, 규칙 2/6, 대화 0/6에 나타났다. 정답은 여러 채널에 중복되므로 단독 기여를 입증하지 않는다. 의미·구성원 채널은 여섯 과업 모두 무관 후보도 반환했다. 임베딩 사용량·금액, 후속 검색과 전체 흐름은 수집하지 않았다. 이 결과는 작은 합성 탐색이며 정식 후보 검색 인수나 총비용 비교가 아니다. 일회성 시험 코드와 벡터는 정리해 실행 로그에 남은 관측을 기록한다.

### 임베딩 사용량 수집 경로

Gemini 문서 임베딩 응답의 `usageMetadata.promptTokenCount`를 선택적으로 반환하는 경로를 추가했다. 누락·잘못된 수는 0으로 대체하지 않고 미측정으로 둔다. 실제 합성 문서 한 건에서 768차원과 입력 27토큰을 확인했다. 이는 새 호출의 사용량이며 앞선 18개 벡터의 사용량을 복원한 것이 아니다. 계정의 과금 등급과 실청구 금액은 확인하지 않았고, 에이전트 기준선·후속 검색·전체 흐름 비용은 여전히 미측정이다.

후속 검색 질의에도 사용량을 반환하는 경로를 추가해 합성 질의 한 건으로 실제 호출한 결과 768차원과 입력 26토큰을 확인했다. 이 호출은 벡터 생성만 확인했으며 서버의 후속 검색 또는 에이전트 과업 trace가 아니다. 기존 검색 실행기에서 해당 사용량을 수집·비용에 연결하는 작업과 두 조건의 실제 대응 trace는 남아 있다.

### 전체 흐름 trace 비용 계약 확장

업무 과업 입력 판 `2`에 `agent_relations`·`server_apply` 조건과 별도 `relation_inference` 토큰 비용 항목을 추가했다. 판 `1`과 기존 다섯 비용 항목은 유지한다. 기준선의 추론 비용은 해당 없음이어야 하며 서버 `apply` 실행의 추론 비용을 해당 없음으로 표시할 수 없다. 추론 비용이 미측정이면 총비용도 미측정으로 남기고, manifest와 결과의 여섯 항목을 대조한다. 합격선이 미정이므로 이 비교의 최종 판정은 보류한다. 합성 입력 시험은 비용 항목 누락과 미측정을 검증하지만, 실제 에이전트 trace와 후속 검색을 생성하거나 측정한 것은 아니다.

관계 추론 trace를 수입한 결과 묶음에는 기존 네 파일과 별도로 `relation_inference.json`을 기록하도록 연결했다. 합성 trace를 사용하는 실행 시험에서 파일 생성, 여섯 비용 항목, 미측정 총비용과 보류 판정을 확인했다. 이는 실제 에이전트 실행 기록이나 정식 모델 비교 결과를 생성한 것이 아니다. 실제 두 조건의 대응 trace, 후속 검색, 준비·실행 비용과 가격 근거는 여전히 필요하다.

작업자 조립은 기존에 프롬프트 판 `1`로 고정되어 있어 평가한 판 `2`를 실제 작업자 경로에서 선택할 수 없었다. 평가 조립에서 판을 명시하면 해당 지시와 지문을 함께 사용하도록 수정했다. 배포 조립에서 판을 지정하지 않으면 기존 판 `1`을 유지하며, 지원하지 않는 판을 거부한다. 이 조립 검사는 실제 에이전트나 `apply` 과업을 실행한 근거가 아니다.
