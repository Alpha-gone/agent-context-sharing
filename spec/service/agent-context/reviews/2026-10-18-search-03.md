## 구현과 발견 사항

- `combine`은 이미 `big.Rat`로 각 채널의 `1/rank`를 합산·비교하고 수학적 동점은 `recorded_at` 내림차순→식별자 오름차순으로 정렬했다. 기여 채널을 이름순으로 정렬하고 거리는 최솟값으로 보존했다. 이 구현을 유지하고 임시·최종 결합을 새 표본으로 검증했다.
- `routeSignals`와 국소 진입점 계산은 의미·키워드를 배열의 0·1번 위치로 읽었다. 채널 목록을 재배열하면 순위가 같아도 의미 후보 수·유사도·관련성·국소 진입점이 달라질 수 있었다. 공통 `localChannelCandidates`가 이름으로 두 채널을 찾고 실패 채널을 제외하도록 보강했다. 기존 auto 전환도 같은 입력을 사용한다. 실제 실행기의 고정 슬롯에서 관찰된 운영 오류를 주장하는 발견은 아니다.
- 점수 정규화·가중치·근사 동점 허용값을 추가하지 않았다. 같은 컨텍스트의 본문·기록 시각은 요청 스냅숏에서 같다는 기존 계약을 사용한다.

## 새 모듈 검증

- 새 `ranking_contract_test.go`에서 진입 목록 6개·그래프 추가 최종 목록 24개·실패 목록 6개의 모든 채널 순열을 대조했다. 거리 맵의 삽입 순서도 바꾸고 순위·정확 점수·기여 채널·거리·라우팅 신호·관련 국소 진입점이 같은지 확인했다. 채널 없음·성공 빈 목록·후보를 동반한 실패 목록도 관련성을 만들지 않는다.
- `1+1/2+1/6`과 `1/2+1/6+1`의 정확 동점과 그래프 순위 추가에 따른 재순위화를 확인했다. 기존 기록 시각·동일 시각의 식별자 동점 시험도 이번 search 전체 실행에 포함했다.
- 서로 다른 점수 `1/2000+1/2002`와 `2/2001`은 정확히 `2/(2000×2001×2002)`, 약 2.5×10⁻¹⁰ 차이다. 기록 시각의 우선순위를 반대로 둬도 더 큰 점수가 앞서며 두 채널 입력 순서를 바꿔도 같다. 작은 점수 차이를 동점으로 처리하지 않는 검증이다.
- 실제 `Service.Flow`에 채널 대역을 연결하고 각 채널의 반환을 채널 신호로 제어했다. 여섯 완료 순서 모두 순차 실행과 가변 지연만 제외한 전체 응답이 같다. 시간 지연에 기대는 sleep을 사용하지 않았다.
- 위 흐름에서 임시 1위 사건의 국소 경로 선택과 확장 진입점, 최종 기여 채널/집계, 거리 0·2를 확인했다. 고립 후보가 선택에서 빠진 뒤에도 rank는 `1,3,4,5`를 유지한다. 이는 순위 메타데이터의 모듈 검증이며 근거 선택 전체의 신규 인수는 SEARCH-09 범위다.
