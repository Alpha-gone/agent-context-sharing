# #195 평가 측정의 진입점 없는 graph 채널 집계 검토

- 대상: [이슈 #195](https://github.com/Alpha-gone/agent-context-sharing/issues/195).
- 기준: `dev`의 `56ef60d`, 브랜치 `fix/195-measure-no-entry-points`.

## 원인과 변경

평가의 채널 실패 판정 `countsAsFailure`는 비활성 채널만 제외했다. 지속·적대적 평가는 호출부에서 graph 채널의 `no_entry_points`를 따로 제외했지만, 그래프 단계·검색 단위·임베딩·적응형 비교가 쓰는 `measure`와 일관성 평가에는 예외가 없었다. 적응형 비교에서 관련 국소 후보가 없는 질의를 강제 local로 실행하면 진입점이 비어 graph 채널이 생략되고, 이 정상 빈 결과가 실패로 세어져 `retainRouteSignals`가 실행 전체를 중단했다. 같은 집계가 비교의 `channel_failures`와 manifest 요약의 채널 실패 비채택에도 쓰였다.

판정 함수가 채널 이름을 받아 graph 채널의 `no_entry_points`를 공통으로 제외하게 하고, 측정·일관성·지속·적대적 평가가 모두 같은 함수를 사용하게 했다. 진입 채널의 실제 조회 실패는 그 채널의 실패로 계속 세므로, 진입 채널이 모두 실패해 그래프 확장이 생략된 경우도 진입 채널 실패로 중단·비채택된다. 일관성 평가는 이슈 본문에 없었지만 같은 판정 함수의 같은 결함이라 함께 맞췄다.

[평가 정본](../sdd/evaluation.md)의 그래프 단계 비교·적응형·일관성 설명과 [시험 설계](../sdd/testing.md#테스트-계층)에 반영했다. 시험 helper에 질의 임베딩만 문서와 직교하게 돌려주는 선택지를 추가했으며 기존 호출은 그대로다. 결과 JSON 필드·구성·스키마는 변경하지 않았고 DOX pass에서 소유권·경로 변경이 없어 기존 DOX를 유지했다.

## 재현과 검증

- 질의 임베딩만 문서와 직교하는 합성 제공자와 문서에 없는 단어의 질의로, 관련 국소 후보가 없는 질의를 포함한 적응형 비교를 구성했다. 기준 코드에서 `라우팅 신호 측정 중 채널 실패`로 중단되는 것을 재현했다.
- 수정 후 같은 시험이 임계값 격자·회차·판정까지 생성하고 모든 회차의 graph 채널 실패 수가 0이다. 판정 단위 시험은 비활성 채널·진입점 없는 graph 채널을 제외하고 진입 채널과 graph 채널의 실제 실패, graph가 아닌 채널의 같은 사유는 실패로 센다.
- Go 1.27.1과 고정 이미지 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`(PostgreSQL 18.6)의 전용 합성 컨테이너에 기본 vector 768·비교 vector 128·halfvec 768 DB를 만들고 각각 정식 7개 마이그레이션을 적용했다. 기존 개발·다른 시험 DB는 사용하지 않았다.
- `TEST_DATABASE_URL`, `TEST_EMBEDDING_SMALL_URL`, `TEST_EMBEDDING_HALF_URL`, `TEST_DATABASE_REQUIRED=1`을 지정한 `go test -race -p 1 -json ./cmd/eval -count=1 -timeout=40m`에서 911건이 실패·건너뜀 없이 통과했다. [#169 검토](2026-10-31-issue-169.md)의 910건과의 차이는 새 적응형 시험이다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check`와 변경 문서의 로컬 링크·앵커를 확인했다.
- 시험 종료 후 시험 DB 외 임시 DB와 idle transaction 잔류가 없음을 확인하고 소유 컨테이너만 정리했다. 기존 개발·다른 시험 자원과 개인 IDE 파일은 유지했다.
