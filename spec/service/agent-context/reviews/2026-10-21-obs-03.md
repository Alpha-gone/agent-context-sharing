# OBS-03 유한 대기열·JSON Lines·이벤트 크기 모듈 인수

- 기준: 2026-10-21, `feat/web-foundation`의 `f260ac7` 이후 작업 트리.
- 대상: [OBS-03](../development-plan/observability.md#obs-03), [크기·대기 제한](../sdd/observability.md#민감정보와-크기-제한), [진단 로그 요구사항](../SRS.md#종류별-진단-로그).
- 판정: OBS-03 구현·모듈 인수 완료. 전체 **73/124개 완료·51개 미착수**이며 다음 권장 작업은 OBS-04다.

## 구현과 경계

`NewRecorder`는 OBS-02의 파일 준비를 완료한 뒤 단일 기록 루프를 시작한다. 같은 기동의 Source를 Reporter와 공유하며 기록기가 파일·잠금의 수명을 소유한다. 공개 API에 별도 상한·시계·파일 콜백 설정을 추가하지 않았다.

- `Emit`은 허용 목록·UTC·종류/필드·확인된 ID를 검증하고 같은 instance/boot인지 대조한다. 대기열은 직렬화한 바이트만 소유한다. 요청 context·Event·본문을 가진 goroutine·임의 오류 객체는 대기열에 넣지 않는다. 요청 취소 뒤에도 커밋 결과를 진단할 수 있도록 취소된 context 자체를 누락 사유로 사용하지 않는다.
- 개행 포함 16 KiB를 적용한다. 선택 진단 `fields`를 생략할 때만 `fields_omitted=true`를 생성하며 필수 외피·흐름 식별자는 유지한다. 필수 외피도 넘으면 JSON을 자르지 않고 누락한다. 잘못된 입력은 필드 생략 전에 거부한다.
- 공용 ring 대기열은 쓰는 중인 이벤트까지 포함하여 1024건·16 MiB의 예약을 유지한다. 건수와 바이트 제한을 동시에 검사하고 기록 완료·실패 뒤 자리를 반환한다. 짧은 메모리 임계 구역 안에서 파일 I/O·공유 잠금 대기를 수행하지 않는다.
- 종류별 파일에 한 행을 append·sync한다. `Emit=true`는 수락이며 `Stats.Written`이 완전 기록 성공이다. 종류/고정 원인별 누락을 누적하고 미지원 종류는 빈 종류로 정규화한다. 기록 실패를 회복해도 과거 누락과 첫 기록 오류를 지우지 않는다. 오류 이력을 무한히 쌓지 않는다.
- 기존 마지막 바이트가 개행이 아니면 해당 파일에 새 JSON을 붙이지 않는다. 잘린 행의 격리·복구는 아직 구현하지 않았다. `Close(ctx)`는 신규 수락을 막고 대기열·파일 정리를 기다린다. 호출자 마감은 대기만 끝내며 작업자가 소유한 정리를 이어간다. OBS-07의 5초 종료·잔여 누락·stderr 정책 완료로 간주하지 않는다.

## 검증 — 2026-10-21

- **macOS/arm64 진단 패키지 122건 통과**, race 포함, 실패 0·건너뜀 0. OBS-01/02 회귀와 신규 OBS-03 24건을 포함한다.
- **Linux/arm64 OBS-03 24건 통과**, 실패 0·건너뜀 0. CGO 없는 시험 바이너리를 기존 로컬 이미지에서 일반 UID 501/GID 20으로 실행했다. Linux에서는 race를 실행하지 않았으며 OBS-01/02 전체 회귀를 다시 실행하지 않았다. 두 OS의 같은 항목을 고유 시험 수로 합산하지 않는다.
- **서버 패키지 의존성 검사 1건 통과**, race 포함. diagnostic에 업무 패키지 import가 없으며 기존 허용 import를 유지한다.
- 기본 건수 1024건을 쓰는 중인 이벤트와 함께 소진하여 다음 enqueue가 즉시 false인지 확인했다. 독립 바이트 경계는 시험용 한도를 정확히 두 이벤트 분량으로 축소해 소진·반환·재수락을 검사했다. 현재 허용 필드만으로 유효한 16 KiB 이벤트 또는 16 MiB 대기열을 만들 수 없으므로 그 바이트 경계를 실제 기본값까지 채웠다고 주장하지 않는다.
- 인코더의 개행 포함 정확한 크기·한 바이트 초과·선택 필드 생략 표시·필수 외피 초과 누락과 흐름 보존을 축소 한도로 검사했다. 줄바꿈·CR·과대 문자열은 허용 필드 계약상 입력 단계에서 거부했다. 자유 문자열 필드를 열어 이스케이프 시험을 우회하지 않았다.
- FIFO·호출 후 Event 변경과 독립적인 바이트 소유·ring 자리 재사용·동시 Emit/Stats/Close·단일 기록·종료 후 거부·호출자 마감·파일 종료 오류를 검증했다. 실제 여섯 파일에 INFO/WARN/ERROR를 두 기동에 걸쳐 기록하고 모든 행의 독립 JSON 해석·종류·boot·0600을 대조했다.
- 실제 공용 OS 잠금 보유 중 enqueue가 250 ms 안에 반환하고 기록자는 1초 획득 예산 뒤 누락하는지 확인했다. 잠금 반환 뒤 다음 기록이 성공해도 이전 누락과 Close의 오류가 유지됐다. 잘린 마지막 행에 새 행을 붙이지 않고 다른 종류 기록은 계속함을 확인했다.
- `check-go.sh`: Go 1.27.1 의존성 확인·의존성 빌드·전체 go build·go vet·gofmt 통과. DB를 사용하는 변경이 없어 DB 시험은 실행하지 않았다.

## 범위·문서·남은 조건

회전·7일 보존·종류/인스턴스/저장소 총상한은 OBS-04, 업무 계측은 OBS-05, 구조화 stderr·30초 억제·잘린 행 격리/복구·5초 flush는 OBS-07, 배포 영속성과 전체 파일 저장 통합은 OBS-08에서 이어간다. 생산 서버 기동 경로에는 아직 기록기를 조립하지 않았다.
