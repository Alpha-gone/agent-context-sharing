# 에이전트 컨텍스트 관리 시스템 상세 설계

## 문서 정보

- 서비스 식별자: `AGENT_CONTEXT`
- 기준: 2026-10-11 확정 [SRS](SRS.md), [공식 근거](reference.md), 채택된 결정
- 문서 상태: 분야별 상세 설계 작성. 목표 직접 연결·새 평가·진단 파일의 구현과 실제 인수는 대기
- 이 문서의 책임: 설계 진입점·문서 소유권·상태. 상세 계약은 `sdd/`의 분야별 문서가 소유한다.

## 설계 목적과 범위

AI 에이전트 제텔카스텐을 위한 공유 컨텍스트 그래프의 확정 요구사항을 구현 가능한 구조·데이터·처리·보안·운영·검증 설계로 구체화한다. 요구사항을 신설하거나 채택되지 않은 제안을 확정하지 않는다. FR 171건과 NFR 13건, 총 184건을 [추적표](sdd/traceability.md#요구사항-추적표)로 연결한다.

분야별 문서는 독립된 상세 설계의 정본이다. 같은 계약을 여러 문서에 복사하지 않으며 다른 분야와 만나는 지점은 상대 링크를 사용한다. 변경 시 해당 분야 문서와 영향받은 추적표·상태를 갱신한다. 적용 지침은 [서비스 DOX](AGENTS.md)와 [상세 설계 DOX](sdd/AGENTS.md)를 따른다.

## 구현과 검증 상태

현재 실행 범위는 웹 관리·계정 세션·저장·검색·색인과 기존 평가 실행기다. 과거 검토 결과를 인용한 분야에서는 해당 기록의 시점·표본·제한을 유지한다. 새 설계로 재배치한 것만으로 현재 구현 전체의 검증을 다시 완료했다고 표시하지 않는다.

- OAuth 최초 인가·코드 교환·Bearer 보호 인증 경계와 갱신 회전의 서버 모듈은 인수했다. 보호 MCP 조립·공통 행위자 직접 연결의 구현·실제 호스트 인수는 대기 중이다.
- MCP 최소 SDK: [루프백 적합성 검토](reviews/2026-10-18-mcp-01.md#서비스-진입-경계-보완과-최종-인수)에서 발견·독립 호출·완료 외피·캐시와 이전 수명주기 거부·오류 형식·Base64 이름 처리의 보완 경계를 인수했다. 실제 서버·OAuth·업무 도구 연결과 직접 연결 지원은 후속 범위다.
- MCP 도구 정의: [14종 스키마·설명·annotations·입력 검증](reviews/2026-10-18-mcp-03.md)을 구현하고 합성 처리기를 연결한 실제 SDK 시험으로 인수했다. 인증·등록·업무 저장 연결과 전체 결과 스냅샷은 후속 범위다.
- 검색 단위·외부 원본·임베딩 용도·업무 비용 `FR-160`~`163`: 상세 설계 반영, 추가 평가 입력·데이터 준비·실제 실행 대기.
- 계정 입력·비밀번호 처리: [AUTH-01 모듈 인수](reviews/2026-10-18-auth-01.md)에서 가입 UTF-8·문자 수 검증, 현재 저장 형식과 레거시 두 형식의 동일 작업 자리 재해시를 확인했다. OAuth의 신규 계획 인수는 후속 범위다.
- 공유 키·검증 캐시: [AUTH-02 인수](reviews/2026-10-18-auth-02.md)에서 ES256 공개·발급 키 검증, 두 인스턴스의 초기화 경합·회전·서비스 재생성 후 과거 키 검증과 캐시 장애·병행 조회를 확인했다. 목표 Bearer의 매 요청 폐기 확인은 후속 범위다.
- 등록·자격 대조: [AUTH-03 인수](reviews/2026-10-18-auth-03.md)에서 실제 동시 가입·조건부 재해시, 더미 대조·오류 분류·안전한 오류 문자열·취소 뒤 후속 처리 차단을 확인했다. OAuth는 후속 범위다.
- 공개 인증 보호: [AUTH-04 인수](reviews/2026-10-19-auth-04.md)에서 공유 시도 예산·본문 크기/형식·no-store·출처 합산·취소와 비밀번호 작업 자리 회복을 확인했다. 실제 브라우저·운영 부하·다중 인스턴스·외부 WAF는 후속 범위다.
- 웹 세션: [AUTH-05 인수](reviews/2026-10-19-auth-05.md)에서 필수 클레임·단일 audience·12시간 만료·갱신 없음, 로그아웃·키 회전·두 인스턴스의 폐기·재시작, 실제 TLS 쿠키와 검증/폐기 장애의 500을 확인했다. MCP 보호 리소스의 Bearer 처리와 실제 브라우저 인수는 후속 범위다.
- OAuth 발견·사전 등록: [AUTH-06 인수](reviews/2026-10-19-auth-06.md)에서 고정 메타데이터 두 경로와 등록 결합·exact/same_ip callback 대조, 구성 검증→주입→실제 TLS 응답을 확인했다. 인가 HTTP·코드/토큰·갱신·보호 MCP와 실제 호스트 인수는 후속 범위다.
- 최초 OAuth 인가·코드 교환: [AUTH-07 인수](reviews/2026-10-20-auth-07.md)에서 로그인 복원·명시적 동의·PKCE·60초 코드·최초 접근/갱신 발급과 실제 DB의 단일 소비·재사용 폐기·실패 롤백 및 TLS 흐름을 확인했다. Bearer·갱신 회전·본인 연결 관리·실제 브라우저/호스트 인수는 후속 범위다.
- Bearer 보호 인증: [AUTH-08 인수](reviews/2026-10-20-auth-08.md)에서 ES256·필수 클레임·계열 결합, 매 요청 공유 개별/계열 폐기와 401/403/500, 취소·만료 재검사와 실제 DB/TLS 경계를 확인했다. 실제 /mcp 전송 조립·갱신 회전·호스트 지원은 후속 범위다.
- 갱신 회전: [AUTH-09 인수](reviews/2026-10-20-auth-09.md)에서 30일/7일 수명·단일 소비·재사용 계열 폐기·보존 경계, 경합·서명/저장/커밋 장애·취소와 실제 TLS 흐름을 확인했다. 본인 연결 관리·인증 상태 정리·실제 /mcp와 호스트 인수는 후속 범위다.
- 전송 보안: [OPS-03 모듈 인수](reviews/2026-10-19-ops-03.md)에서 라우팅 전 TLS 판정·단일 ASCII 전달 헤더·실제 상대 해석과 직접 TLS/프록시 루프백·Secure 쿠키·상태 확인 예외를 확인했다. 실제 Tunnel·운영 배포·전 구간 TLS 및 미등록 OAuth·MCP의 업무 인수는 후속 범위다.
- 종류별 진단 파일 `FR-173`~`175`: 상세 설계 반영, 기록기·실제 파일 저장·재시작·다중 인스턴스 인수 대기.
- 저장 계층의 HNSW·임베딩만 이동·온라인 영속 저장소: 확정 계약 반영. 새 저장 장치의 성능·비용과 실제 배포 검증은 별도다.
- 갱신 수명·정리 `TBD-063`: 해소. 실제 SDK·Codex CLI 상호운용 `TBD-064`: 검증 대기.

## 읽기와 변경 순서

1. SRS의 대상 요구사항·확정 결정과 적용 DOX를 확인한다.
2. 위 분야 표에서 주 책임 문서를 읽고 연결된 다른 분야의 계약을 확인한다.
3. 설계 변경은 소유 문서에 반영하고 요구사항 변경이 필요할 때만 SRS를 먼저 갱신한다.
4. 추적표의 설계·검증 연결과 구현/검증 대기 상태를 정합화한다.
5. 파일·앵커 링크·Markdown·용어·DOX를 검사한다. 실제 기능 변경 시 별도 테스트 전략을 따른다.
