## 검사 방법

2단계·3단계 검사와 같이 코드 판독과 실제 실행을 나눠 수행했다. 체크박스 표시를 근거로 삼지 않았다. 검사 시점의 8단계 체크박스는 전부 미표시였다.

| 방법 | 내용 |
|------|------|
| 코드 판독 | 화면별 세션·등급 판정과 저장소 질의를 명세의 확정 값과 하나씩 대조했다 |
| 명세 역확인 | 의심한 항목을 먼저 `SRS.md`·`SDD.md`에서 확인해, 확정된 계약을 결함으로 잘못 적지 않게 했다 |
| 실 데이터베이스 실행 | 통합 테스트가 지나지 않는 저장소 질의를 실제 AGE에 직접 호출했다 |
| 브라우저 자산 실행 | 번들된 Cytoscape.js를 Node.js로 불러 간선 처리와 근거 경로 탐색을 실제로 실행했다 |
| 되돌림 확인 | 추가한 테스트가 각 결함을 실제로 잡는지 수정을 하나씩 되돌려 확인했다 |
| 경쟁 상태 검사 | `-race`로 전체 패키지를 실행했다 |

재현 명령은 다음과 같다.

```shell
set -a
. ./.env
set +a
TEST_DATABASE_URL="${TEST_DATABASE_URL:-$DATABASE_URL}" TEST_DATABASE_REQUIRED=1 go test ./... -count=1
TEST_DATABASE_URL="${TEST_DATABASE_URL:-$DATABASE_URL}" TEST_DATABASE_REQUIRED=1 go test ./... -count=1 -race
```

### 실행으로 확인한 이유

코드 판독만으로는 이번 결함 다수가 드러나지 않았다. 1번부터 3번은 SQL을 읽어서는 정상으로 보이고 실행할 때만 실패하며, 4번은 브라우저 라이브러리의 오류 처리 방식에 달려 있었다. 검사 초기에 판독만으로 "구현됨"으로 분류했던 항목이 실행에서 뒤집혔다.

| 의심한 것 | 확정 근거 |
|-----------|-----------|
| 운영자 화면이 세션만 검사한다 | `FR-AGENT_CONTEXT-135`가 "검증 단계에서 인증된 모든 계정이 운영자 자격을 갖는 것으로 보아야 하며 계정에 별도 판정 값을 두어서는 안 된다"로 확정했다 |

## 발견 사항

처리 상태를 갱신할 수 있도록 체크박스로 둔다. 1번부터 3번은 실행하지 않으면 드러나지 않는 결함이고, 4번부터 10번은 처음 검사에서 보고한 일곱 건이다.

### - [x] 1. `AS grant`가 다시 들어와 권한 화면의 등급 질의가 항상 실패한다

`internal/store/web.go:85`, `:91`

3단계 검사 1번과 같은 결함이 8단계 신규 코드에 다시 들어왔다. `GRANT`는 SQL 예약어라 PostgreSQL이 별칭 자리에서 받지 않는다.

```text
ListGraphGrants: 그래프 등급 목록 조회: ERROR: syntax error at or near "grant" (SQLSTATE 42601)
```

`ListGraphGrants`는 권한과 팀 관리 화면의 등급 표를 만드는 유일한 경로이므로, 그 화면이 소유자에게 항상 오류를 냈다. 직접 등급과 팀 상속 등급의 구분 표시, 마지막 소유자의 회수 수단 비활성이 모두 이 질의에 걸려 있다.

**처리 결과.** 직접 부여 갈래는 `permission`, 팀 상속 갈래는 `team_grant`로 별칭을 나눴다. 3단계 검사가 고른 이름 규칙을 그대로 쓰며, `internal/store/graph.go`의 기존 별칭과도 맞는다.

**재발한 이유.** 3단계 검사는 결함을 고쳤지만 별칭 규칙을 잠그는 장치를 남기지 않았다. 같은 표를 쓰는 새 질의를 다른 파일에 쓰면 규칙을 다시 어길 수 있었고 실제로 그렇게 됐다. 이번에는 질의를 실행하는 통합 테스트를 남겼다.

### - [x] 2. 삭제 영향 질의에 agtype 캐스트가 빠졌다

`internal/store/web.go:418`

1번을 고치자 같은 화면의 다음 질의가 드러났다. AGE 속성 접근에 `::text` 캐스트가 없어 키 리터럴이 agtype으로 해석된다.

```text
DeletionImpact(그래프): 그래프 삭제 영향 조회: ERROR: invalid input syntax for type agtype (SQLSTATE 22P02)
```

`internal/store/index.go`의 같은 형태 질의는 모두 `properties ->> 'graph_id'::text`로 캐스트를 붙이고 있어, 이 파일만 관례에서 벗어나 있었다.

**처리 결과.** `graph_id`와 `deleted_at` 키에 `::text`를 붙였다.

### - [x] 3. 한 파라미터가 텍스트와 uuid 문맥에 함께 쓰여 타입 추론이 충돌한다

`internal/store/web.go:419`~`:420`

2번을 고치자 같은 질의의 세 번째 층이 드러났다.

```text
DeletionImpact(그래프): 그래프 삭제 영향 조회: ERROR: operator does not exist: uuid = text (SQLSTATE 42883)
```

`$1`이 첫 하위 질의에서 agtype 속성과 비교되어 텍스트로 추론되는데, 이어지는 하위 질의는 uuid 열과 비교한다. 같은 파일의 `ListOwnedDeletedGraphs`가 같은 값을 문제없이 쓰는 이유는 그 질의의 `$1`이 uuid 문맥에만 쓰이기 때문이다.

**처리 결과.** uuid 열 비교에 `$1::uuid`를 명시했다. 삭제와 복구 화면의 연쇄 영향 안내가 이로써 실행된다.

**세 결함이 한 자리에 겹친 이유.** 권한 화면의 등급 표와 삭제 화면의 영향 집계는 8단계 검사 전까지 어느 테스트도 지나지 않았다. 웹 단위 테스트는 저장소를 가짜로 대체하고, 저장소 통합 테스트는 8단계 함수를 하나도 부르지 않았다. 판독으로는 세 결함 모두 정상으로 보였다.

### - [x] 4. 소프트 삭제된 컨텍스트가 있으면 시각화가 그려지지 않는다

검사 시점의 `internal/store/web.go`의 `ListGraphContexts`

정점은 `deleted_at IS NULL`로 걸렀으나 연결선 질의는 `graph_id`만 보고 끝점의 삭제 여부를 보지 않았다. 실제 AGE에서 원천을 소프트 삭제한 뒤 확인한 결과다.

```text
컨텍스트 1개, 연결선 1개
응답에 없는 컨텍스트를 가리키는 연결선: 01a0…f2d9 -[derived_from]-> 01a0…1b785
```

번들된 Cytoscape.js를 Node.js로 불러 그 간선을 넣어 확인했다.

```text
RESULT: 예외 발생 -> Can not create edge `0-derived_from` with nonexistent target `deleted-source`
```

해당 경로의 오류 함수가 `function(e){throw new Error(e)}`이고 템플릿의 시각화 즉시 실행 함수에 try/catch가 없다. 그래프가 그려지지 않고 노드 선택, 근거 경로 강조, 국소 보기가 모두 동작하지 않는다. 삭제된 컨텍스트의 식별자와 연결 관계가 페이지에 실리는 문제도 함께 있었다.

**처리 결과.** 5번과 함께 처리했다. 홉 탐색은 삭제된 이웃을 간선 기록 전에 건너뛰고, 상한으로 잘린 정점은 방문 집합 기준 필터가 걸러낸다.

### - [x] 5. 그래프 상세가 확정된 조회 규칙을 쓰지 않았다

`SDD.md` 「웹 화면 계약」은 그래프 상세의 데이터를 「홉 범위 조회」와 전역 요약 파생으로 확정하고 "화면이 쓰는 데이터는 새로 만들지 않고 확정된 조회 규칙을 그대로 쓴다"고 두었다. `FR-AGENT_CONTEXT-105`도 같다.

구현은 `ListGraphContexts`라는 화면 전용 전체 조회를 새로 만들었고, 그 결과 다음이 빠졌다.

| 빠진 것 | 영향 |
|---------|------|
| 결과 상한 | `max_hop_nodes`가 이 화면에 걸리지 않아 그래프의 활성 컨텍스트 전부가 한 응답과 브라우저로 실린다 |
| 절단 경계 | 잘렸는지 알릴 표시가 없다 |
| 전역 요약 시작점 | `FR-AGENT_CONTEXT-110`의 "전체 보기는 전역 요약을 함께 보여주고"가 성립하지 않는다 |

**처리 결과.** `ListGraphContexts`를 지우고 `GraphVisualization`을 두었다. 전역 요약 파생을 시작점으로 `HopContextsFrom`을 `max_hops`·`max_hop_nodes`로 수행하며, 절단 경계는 「부가 정보의 출처」가 홉 경계에 확정한 표시로 화면에 남긴다.

**되돌림 확인.** 상한 전달을 되돌리자 `상한 적용 결과 = 5개, 절단 false`로, 방문 집합 기준 간선 필터를 되돌리자 `응답에 없는 시작 컨텍스트를 가리키는 연결선: …`으로 각각 실패했다.

**명세에 없던 결정.** 전역 요약 파생이 없는 그래프의 시작점은 확정된 곳이 없었다. 전역 요약으로만 제한하면 요약을 만들지 않은 그래프의 상세 화면이 비므로, 활성 컨텍스트를 시작점으로 삼는 되돌림을 두고 `SDD.md` 「웹 화면 계약」에 근거와 함께 적었다. 되돌림에도 같은 상한과 절단 규칙이 걸리므로 조회 규칙은 하나로 유지된다.

### - [x] 6. 노드의 삭제·복구 화면이 없다

개발 계획의 "그래프와 노드의 삭제·복구 화면을 구현한다" 가운데 노드 경로가 없었다. `SetContextDeleted`는 `GraphStore` 인터페이스에 선언됐지만 호출하는 곳이 없고, `DeletionImpact`는 `model.ID{}`로만 불려 컨텍스트 영향 분기가 웹에서 도달 불가였다.

`SDD.md` 「운영자 복구」가 "사용자 직접 삭제는 운영자 복구 대상이 아니며 소유자가 웹에서 복구한다"로 확정했으므로 웹에 그 경로가 있어야 한다.

**처리 결과.** 삭제와 복구 화면이 그래프와 노드를 함께 다룬다. 활성 컨텍스트 목록에서 대상을 고르면 그 노드의 연쇄 영향을 보여주고(`FR-AGENT_CONTEXT-107`), 삭제된 컨텍스트 목록에서 복구한다. 삭제된 컨텍스트가 보이는 자리는 「화면 접근 제어」가 정한 대로 이 화면뿐이다.

### - [x] 7. 팀 관리가 그래프 소유자 등급 뒤에 잠겨 있었다

`FR-AGENT_CONTEXT-043`은 "인증된 계정이 팀을 생성해 팀 관리자가 되고 웹 페이지에서 구성원을 추가·제거할 수 있도록 해야 한다"로 확정했다. 구현은 팀 동작 전부를 `/graphs/{id}/access`에 두고 화면 전체를 `requireGrade(..., Owner)`로 잠갔다. 그래프 소유자가 아닌 계정은 팀을 만들 수단이 없었다.

**처리 결과.** 화면 접근은 세션까지만 요구한다. 등급 부여·회수와 등급 표는 `FR-AGENT_CONTEXT-041` 대로 소유자만 보고, 팀 동작의 관리자 판정은 저장소가 계속 한다. 그래프를 갖지 않은 계정을 위해 같은 화면을 `/access`로도 받으며, 화면이 늘어나는 것이 아니라 등급 영역이 빠진다. `SDD.md` 「웹 화면 계약」에 두 영역의 경계를 적었다.

**되돌림 확인.** 소유자 잠금을 되돌리자 `열람자의 권한 화면 응답 = 403, want 200`과 `팀 생성 응답 = 404`로 실패했다.

### - [x] 8. 직접 삭제한 그래프의 복구 링크가 없었다

`ListGraphs`는 `deleted_at IS NULL`로 걸러내고 `ListRestoreEligibleGraphs`는 자동 삭제분만 낸다. 소유자가 직접 삭제한 그래프는 어느 목록에도 나오지 않아 주소를 직접 입력해야만 복구할 수 있었다.

**처리 결과.** `ListOwnedDeletedGraphs`를 더했다. `deleted_at IS NOT NULL AND grace_started_at IS NULL`과 소유자 등급으로 판정해 자동 삭제 경로와 나뉘며, 그래프 목록 화면에 복구 링크를 둔다.

### - [x] 9. 근거 경로 강조가 양방향으로 퍼졌다

`DERIVED_FROM`은 파생에서 근거로 향하는데(`internal/store/context.go:265`), 강조 코드가 나가는 간선과 들어오는 간선을 함께 넓혀 근거뿐 아니라 그 노드에 기대는 파생 후손까지 칠했다. 「시각 표현 규칙」은 "고른 노드에서 근거 원천까지의 연결선을 강조한다"로 확정했다.

Node.js로 같은 그래프에 두 구현을 돌려 대조했다.

```text
수정 후 강조된 간선: e0,e1    (child → mid → origin, 근거 원천까지)
수정 전 강조된 간선: e0,e2    (후손 간선을 칠하고 원천 간선은 놓쳤다)
```

**처리 결과.** 나가는 간선만 따라가고 그 간선의 대상 노드로 다음 경계를 만든다. 수정 전 구현은 후손을 강조하는 것에 더해 실제 원천으로 가는 간선을 놓치고 있었다.

### - [x] 10. 국소 보기에 죽은 코드가 있었다

`applyScope`의 `visible` 계산은 결과를 쓰지 않고, 그 안의 필터 콜백은 인자를 무시하고 상수 조건을 돌려준다. 실제 범위 계산은 뒤의 `closedNeighborhood()` 반복이 한다.

**처리 결과.** 쓰이지 않는 계산을 지웠다. 범위 계산은 그대로다.

### - [ ] 11. 확정된 서체가 반영되지 않았다

`SDD.md` 「시각 표현 규칙」이 `TBD-AGENT_CONTEXT-045`를 확정하며 "Pretendard를 저장소에 넣어 서버가 내보낸다"로 두었으나, 화면은 `system-ui, sans-serif` 스택을 쓰고 폰트 자산이 없다.

확정 근거가 "`system-ui` 계열 스택은 운영체제마다 다른 한국어 글꼴이 잡혀 같은 화면이 다르게 보인다"이고 「검증」이 통제 조건에서 환경을 바꾸지 말라고 요구하는 것과 같은 판단이므로, 검증 단계의 화면 고정 의도와 어긋난다. Cytoscape.js 자산과 같은 방식으로 폰트와 라이선스 전문을 함께 두면 해결된다.

개발 계획 8단계의 작업 항목은 계층 색, 상태 표식, 연결선만 요구하므로 이 항목은 그 체크박스와 별개다.

## 개발 계획 체크박스

발견 사항 1번부터 10번의 수정을 확인한 뒤 8단계의 작업 18개와 완료 기준 5개를 모두 표시했다. 표시 근거는 항목별로 위 「확인된 계약」과 「보강한 테스트」에 있다.

## 종합

8단계의 접근 경계는 대체로 제대로 구현되어 있었다. 웹 세션과 MCP 토큰의 분리, 웹 전용 동작의 MCP 비노출, 운영자 복구의 대상 제한, 시각화의 `graph_id` 경계, 팀 동작의 관리자 판정은 모두 확정된 계약대로였다.

문제는 실행되지 않은 코드에 몰려 있었다. 발견 사항 11건 가운데 1번부터 4번은 코드를 읽어서는 정상으로 보이고 실행할 때만 드러나는 결함이며, 그 넷이 모두 통합 테스트가 닿지 않는 자리에 있었다. 권한과 팀 관리 화면의 등급 표와 삭제와 복구 화면의 영향 집계는 실행 시 항상 실패하는 상태였고, 그래프 상세의 시각화는 소프트 삭제된 컨텍스트가 하나만 있어도 그려지지 않았다.

3단계 검사 1번과 같은 결함이 다시 들어온 것이 이 단계에서 가장 되짚을 점이다. 결함을 고치는 것과 규칙을 잠그는 것이 다른 일이며, 이번에는 질의를 실행하는 통합 테스트를 남겼다.
