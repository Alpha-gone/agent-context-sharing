## 변경

감사 화면은 필터 없이 기본 페이지만 읽고 다음 커서를 버리고 있었다. 기간·대상 GET 양식과 다음 페이지를 연결했다. 시작일·종료일은 UTC 날짜이고 둘 다 포함하며, 종료일 다음 날 0시를 저장소의 제외 경계로 전달한다. 대상은 UUIDv7만 받는다. 알 수 없거나 중복된 매개변수, 날짜 형식, 역순 기간과 잘못된 대상은 저장소 호출 전에 400으로 거부한다.

저장소의 잘못된 커서는 유효한 필터를 유지한 400, 조회 중 소유자 등급 상실은 404, 입력 계약 위반은 400, 저장 장애는 고정 안내의 500으로 사상한다. 취소되면 렌더링하지 않는다. 페이지 크기는 계정 플랜의 그래프 목록 값을 해석해 쓴다.

감사 표에 제목·열 머리글과 기록 출처(웹 관리·관리 연산)·행위 계정 열을 추가했다. 「더 보기」는 현재 기간·대상과 서버가 발급한 다음 커서를 유지하고, 새 필터 제출에는 이전 커서를 싣지 않는다.

연결 관리의 목록·폐기와 입력·본문·출처·세션 경계는 AUTH-10 구현을 이번 웹 시험으로 다시 인수했다. 두 목록 절의 `aria-labelledby`가 불필요한 region 영역을 만들어 제거하고 제목으로만 구분했다.

## 실행 증거

- **신규 18건 포함 웹 770건 통과**: 최상위 94개·하위 676개, `-race -count=1`·필수 DB 설정. 실패·건너뜀 0, race 없음. 신규는 최상위 5개·하위 13개다.
- 단위 시험은 날짜의 UTC 시작·다음 날 제외 경계, 대상·커서·플랜 페이지 크기 전달, 필터 재표시와 출처·행위 계정·이스케이프 표시를 확인했다. 다음 페이지 주소는 경로·기간·대상·새 커서만 담는다. 입력 오류 여덟 표본은 저장소 호출 없이 400이고, 저장소 오류 다섯 표본은 상태 구분·필터 유지·원문 비노출과 취소 중단을 확인했다.
- 실제 DB·서명 세션·TLS에서 관리 연산 기록과 웹 삭제/복구·등급 기록을 만들고 플랜 페이지 크기 2로 모든 「더 보기」를 따라갔다. 화면 행의 시각·출처·종류·동작·행위 계정·대상·상세 순서가 저장소 한 번 조회와 같았다.
- 대상 필터는 해당 컨텍스트의 연산·삭제·복구 세 행만 반환했고 다음 페이지마다 대상과 커서가 유지됐다. 오늘 하루의 기간은 같은 범위의 저장소 결과와 일치했고 어제까지의 기간은 오늘 기록을 포함하지 않았다. 잘못된 커서는 필터를 유지한 400, 역순 기간은 400, 열람자는 403, 무등급 계정은 404, 조회 직전 등급을 잃은 공동 소유자는 404였다.
- 실제 OAuth 코드 교환으로 본인 계열 둘·다른 계정 계열 하나와 각 에이전트 등록을 만들었다. 연결 화면은 본인 계열·등록만 표시하고 접근·갱신 자격·등록 키·웹 세션 값을 노출하지 않았다. 다른 계정 대상의 계열·등록 폐기는 404이며 해당 자격과 등록이 유지됐다.
- 계열 폐기는 그 계열의 접근 자격과 갱신을 차단하고 다른 계열·에이전트 등록·웹 세션을 유지했다. 반복 폐기는 최초 폐기 시각을 유지하고 화면에 폐기 상태를 표시했다. 등록 폐기는 그 등록을 무효화하고 남은 계열을 유지했으며 활성 등록 목록에서 사라졌다.
- `check-go.sh`의 의존성 확인·빌드·vet·gofmt가 통과했다. 웹 SDD·개발 계획·설계 진입점·README/서비스 색인·요청 기록·근거를 정합화했다. 처리기·템플릿은 기존 웹 DOX 소유 안의 변경이므로 DOX와 부모 색인을 유지했다. 요구사항·용어·SQL 스키마·환경 설정·저장소 계약은 바뀌지 않아 해당 정본은 유지했다.

```sh
TEST_DATABASE_URL='<WEB-08 전용 합성 URL>' TEST_DATABASE_REQUIRED=1 go test -race -json -count=1 -timeout=240s ./internal/web
GO_BINARY="$(command -v go)" sh check-go.sh
```

별도 `acs-web08-20261024` 컨테이너·`agent-context.task=web08` 라벨·tmpfs·임시 IPv4 loopback 포트와 합성 자격을 사용했다. 종료 후 자식 DB·시험 연결 0과 이 작업의 컨테이너 잔류 없음, 기존 개발 컨테이너 보존을 확인했다. 원시 근거는 세션 임시 폴더의 `acs-web08-web.json`·`acs-web08-static.log`다.

첫 감사 통합 실행은 시험의 관리 연산 기록에 판단 입력이 없어 저장소 검증에서 실패했다. 판단 입력을 지정한 뒤 해당 시험과 전체 모듈 실행이 통과했으며 반복 실행을 중복 합산하지 않았다.

Modern Web Guidance의 `forms`·`accessibility`에서 명시적 레이블, 안내 연결, 표 제목·열 머리글과 이름 붙인 `section`의 region 남용 금지를 확인해 반영했다.

## 남은 범위

전체 웹 분야 통합과 실제 브라우저의 날짜 입력·필터 제출·페이지 이동·폐기 제출, 실제 호스트·운영 배포는 미실행이다. 실제 브라우저 인수는 WEB-09에서 CDP로 조작하는 headless Chrome과 수동 Safari로 수행한다. 커밋·푸시는 수행하지 않았다.
