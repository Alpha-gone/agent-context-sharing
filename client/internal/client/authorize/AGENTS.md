# 클라이언트 인증과 DPoP

## 목적

- 이 패키지는 브라우저 인가·발견, 프로세스 키, 검증한 토큰과 공유 인가 수명을 소유한다.

## 소유권

- 상위 `client/AGENTS.md`가 클라이언트 모듈 계약을, 서비스 SRS·SDD가 인증 동작의 정본을 소유한다.
- 이 패키지는 도구 목록·호출·호스트 직렬화를 알지 않는다. HTTP 재전송과 요청 횟수는 `remote`가 소유한다.

## 로컬 계약

- 키·토큰·인가 URL·PKCE·코드를 파일·로그·오류에 노출하지 않는다. 자격 증명은 검증된 구성의 MCP POST 헤더에만 적용한다.
- 검증 전 토큰을 저장하지 않으며 첫 계정의 결합은 만료·무효화 뒤에도 유지한다. 계정 전환은 새 프로세스가 필요하다.
- 발견에서 검증한 리소스 식별자를 인가·토큰 요청과 JWT audience에 일관되게 사용한다. 갱신으로 현재 토큰의 만료 시각을 앞당기지 않는다.
- `Identity`는 현재 사용 가능한 주체만 조회하며 인가를 시작하지 않는다. 토큰 사용·저장에는 SDD의 만료 여유를 적용한다.
- `Apply`는 비대화형 현재 토큰·새 proof 적용 경계다. 명시적 `Credentials`·`Authenticate`·`Reauthorize`와 분리해 캐시 잠금 안에서 브라우저 대기를 시작하지 않는다.
- 대기자 취소는 공유 실행과 분리한다. 마지막 대기자·전체 시간 초과·종료는 수신기 정리가 끝난 뒤 반환한다.
- callback 응답을 완전히 전송한 뒤 종료하고, 수신기 정리는 헤더 없는 사전 연결을 기다리지 않는다. 연결·Serve 실행을 정리하고 callback 잠금으로 일회성 값 접근을 차단한 뒤 참조를 폐기한다.
- opener 반환과 callback 수신은 독립적으로 기다리며 모든 종료 경로에서 opener 실행도 회수한다. 주입한 opener는 context 취소에 응답해야 한다.
- 발견·JWKS 요청에는 자격 증명을 싣지 않고 토큰 교환은 redirect하지 않는다. 시험 transport 주입을 운영의 HTTPS·URL 검증 완화 옵션으로 바꾸지 않는다.
- 보호 리소스 도전 위치가 없으면 경로별 well-known의 `404`에서만 루트 위치를 시도한다. 명시된 위치·잘못된 문서·TLS·전송 실패는 대체 조회로 숨기지 않는다.
- 진단은 보호 리소스·인가 서버 검증을 별도로 재사용하고 브라우저·루프백에 비밀 없는 임시 경로를 사용한다. 검증된 발견 정보는 불투명 값으로 전달하고 URL을 기본 출력하지 않는다.
- 정상 진단 HTTP 응답은 빈 본문 길이를 명시하고 헤더 전송을 완료한 뒤 성공을 게시한다. 전송 실패는 진단 실패이며 결과 게시 뒤 수신기 종료가 정상 응답을 끊지 않아야 한다.
- `Close`는 소유한 실행·기본 HTTP transport와 비밀 참조를 정리한다. 주입된 transport의 수명은 주입자가 소유한다.

## 작업 지침

- 서비스 SDD의 ES256·JWT·callback·갱신·오류 계약을 먼저 확인한다. OAuth grant나 nonce·계정 전환 기능을 임의로 추가하지 않는다.

## 검증

- 인증 회귀 시험은 실제 로컬 루프백과 교체 가능한 HTTP·opener 경계를 사용한다. 외부 계정 로그인과 실제 시스템 브라우저를 자동으로 실행하지 않는다.
- 변경 시 클라이언트 전체 race 시험과 계약의 metadata·JWT·proof·callback·공유 취소·갱신·비밀 비노출 시험을 실행한다. 실제 서버·WSL2·호스트 통합 결과와 구분한다.
