# 검색·웹·플랜 입력과 오류 처리 회귀 검증

## 대상과 확인 근거

[GitHub #60](https://github.com/Alpha-gone/agent-context-sharing/issues/60)의 세 항목을 `dev`의 `bacf792`에서 만든 `fix/search-web-plan_#60` 브랜치에서 처리했다. 처음에는 `dev`가 원격보다 두 커밋 뒤처져 작업을 멈췄으며, 사용자의 pull 완료 안내 뒤 upstream과 0/0, 깨끗한 작업 트리를 확인했다. 적용 DOX 체인과 용어를 읽고 코딩 표준·Modern Go 지침을 구현·검증에, service-design을 SDD 정합화에, work-history를 진행·요청·검증 기록에 적용했다.

수정 전 테스트에서 양수·음수·별도 영 오프셋 시각이 검색에 허용되고, 같은 UUID의 대문자·하이픈 없는 키가 순서·값에 관계없이 허용되는 것을 재현했다. 웹 HTTP 시험은 없는 등급과 내부 장애가 마지막 소유자 `409`로, 복구 요청의 모든 오류가 `403`으로, 운영자 복구의 모든 오류가 고정 안내 `409`로 표시되는 것을 확인했다.

## 해결 및 유지한 계약

- 검색은 `AsOf.Location() == time.UTC`를 검사한다. 미지정은 기존처럼 현재 UTC로 채우며, 검증은 저장소·임베딩·읽기 스냅숏 사용 전에 수행한다. MCP 입력이나 공개 도구 계약은 변경하지 않았다.
- 계정 플랜은 `model.ID`로 해석한 뒤 이미 등록한 계정인지 검사한다. 표기만 다른 중복은 같은 값이어도 거부하고, 서로 다른 계정의 대소문자 표기는 허용한다. JSON 해석기·UUID 파서·플랜 항목·기본값은 유지한다.
- 등급 회수의 `ErrLastOwner`만 마지막 소유자 `409`로 표시한다. 세 경로의 `ErrNotFound`는 `404`, 복구의 `ErrInvalidState`는 `409`, 나머지 저장소 장애는 안전한 작업 실패 안내와 `500`으로 표시한다. 복구 요청의 없는 대상과 권한·자동 삭제 조건 불충족을 구분해 노출하지 않는다. `errors.Is`로 래핑을 지원하고 성공 시 기존 `303` 이동을 유지한다.
- 변경은 이슈가 지목한 세 웹 쓰기 경로에 한정했다. 다른 관리 경로의 오류 처리나 실제 권한·복구·트랜잭션 판정은 변경하지 않았다.

## 검증

Go 1.27.1 `darwin/arm64`를 사용했다.

- 검색·플랜·웹 패키지 전체 `go test -race ... -count=10`: 통과. 구성 패키지 전체 race 10회도 통과했다.
- 검색 회귀는 UTC·미지정·양수/음수 오프셋·별도 영 오프셋과 잘못된 시각의 검색·임베딩 호출 차단을 확인했다.
- 플랜 회귀는 대문자·하이픈 없는 중복의 정방향/역방향과 동일/다른 값, 서로 다른 계정과 기동 전 거부를 확인했다.
- 웹 회귀는 원본·래핑 오류 18개 조합의 상태·안내·내부 원문 비노출과 성공 이동 세 경로를 확인했다.
- 기존 개발 DB와 분리한 새 `issue60_final`에 정식 001·007·008 마이그레이션을 적용하고 `TEST_DATABASE_REQUIRED=1`로 서버 전체 `go test -race -p 1 -count=1 -json ./...` 실행: 테스트 항목 804개 통과, 실패·테스트 건너뛰기 없음. 테스트 파일 없는 패키지의 이벤트는 개별 테스트와 구분했다.
- 첫 `issue60_suite` 전체 실행은 기동 실패 시험에서 개발 설정의 768차원을 읽어 시험 DB `vector(1024)`와 불일치했다. 실패 원인을 확인하고 시험 차원을 1024로 맞춘 뒤 새 DB에서 전체 재실행했다. 제품 코드 수정이나 기존 DB 스키마 변경으로 우회하지 않았다.
- 클라이언트 전체 `go test -race -count=1 ./...`, 서버·클라이언트 각각 `go build ./...`, `go vet ./...`, 루트 `gofmt -l .`과 `git diff --check`: 통과했다.

## DOX pass와 제한

- SDD의 플랜 구성·검색 입력·웹 오류 처리·테스트 전략, 웹 DOX의 오류 분류 경계를 갱신했다. 개발 계획·요청 기록·공식 작성 기준을 동기화하고 한국어 표현·맞춤법·Markdown 표·상대 링크를 검토했다.
- 루트·spec 부모·서비스 AGENTS와 Child DOX Index는 경계·소유권·지속 구조가 바뀌지 않아 유지했다. SRS·용어집·공개 도구 계약·클라이언트·마이그레이션은 요구사항·용어·API·스키마 변경이 없어 유지했다. 새 의존성이나 배포 구성은 없다.
- 시험용 DB만 생성·정리하고 기존 개발 DB·볼륨·`.env`·비밀·Ollama 모델·운영 환경은 변경하지 않았다. 접속 정보나 비밀값은 출력·기록하지 않았다.
- 브라우저 수동 시험·`client_live` 실제 종단 간 시험·외부 임베딩 API·운영 배포·커밋·푸시·PR·이슈 종료는 수행하지 않았다. #60 범위의 미해결 항목은 없다.
