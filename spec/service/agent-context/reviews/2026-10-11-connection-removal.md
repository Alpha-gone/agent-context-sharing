# 연결 전용 구현 제거 검증

## 범위와 결과

- 사용자 요청에 따라 독립 클라이언트 모듈·설치 스크립트·배포 산출물·서비스 명세와 수작업 MCP 전송 구현을 제거했다.
- 연결 전용 발급·교환·요청 갱신·증명 검증·저장·주기 정리·설정 및 관련 시험·문서·기록을 제거했다. 제거된 HTTP 경로가 `404`인지 회귀 시험으로 확인한다.
- 계정·비밀번호·웹 세션·권한·서명 키·JWKS·폐기 목록·그래프·멱등성 및 색인·검색·평가 기능은 유지한다. 웹 세션의 12시간 수명은 바꾸지 않으며, 사용처가 없어진 인증 시각 승계 필드만 제거했다.
- SRS·SDD·개발 계획·용어집·안내와 DOX 경계를 정리했다. 호스트 직접 연결·표준 OAuth는 목표 설계이며 현재 구현하지 않았다.
- 적용된 초기 마이그레이션은 체크섬을 보존한다. 과거 사용 번호 002~008을 재사용하지 않고 `009_remove_legacy_connection.sql`로 연결 전용 테이블 두 개만 제거한다. 실제 서비스 DB에는 적용하지 않았다.
- 로컬의 구형 실행 파일·설정·제거한 환경 설정은 제한된 권한의 임시 폴더에 보관했다. 소스와 문서는 Git 이력으로 복원할 수 있으며, 비밀값과 로컬 절대 경로는 이 기록에 포함하지 않는다.

## 검증

- Go 1.27.1 `go test -race -count=1 -json ./...`: 614건 통과, 실패 0건, DB 설정이 필요한 204건 건너뜀. 전체 DB 통합 통과로 해석하지 않는다.
- 제거 SQL의 범위·격리 DB의 초기 적용·재적용·기존 번호와의 공존·공유 테이블 보존 시험: 실제 PostgreSQL에서 race 검사 통과. 합성 시험 DB는 정리했으며 시험으로 재생성할 수 있다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `test-dev-compose.sh`: 통과.
- `test-prod-compose.sh`: 작업 전부터 있던 운영 DB 포트 공개 변경 때문에 실패했다. 해당 사용자 변경과 기존 IDE staging은 보존했다.
- 잔여 연결 식별자 검색, Markdown 상대 링크·요구사항 추적·DOX Child Index·문서 구조·한국어 표현 및 `git diff --check`를 검사했다. 초기 DDL·제거 SQL·제거 회귀 시험에만 옛 저장 구조의 식별자가 남는다.

## 후속 경계

- 직접 연결 SDK·OAuth·갱신 계열·호스트 인수 시험은 별도 구현이 필요하다. 현재 서버는 웹 관리와 상태 확인·공개 키 경로만 제공한다.
- 제거 마이그레이션은 서비스·작업자 정지와 백업 후 명시적으로 적용해야 한다. 이 작업에서는 실행 중인 서비스·호스트 등록·운영 배포·Git 이력을 변경하지 않았다.
- 루트·명세·서비스·웹 소유 DOX는 책임 변경에 맞춰 갱신했다. 마이그레이션 DOX는 기존 번호 추가·체크섬 보존·격리 시험 계약이 그대로 적용되어 변경하지 않았다.
