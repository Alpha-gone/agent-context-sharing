- 정본: [연결·예약](../sdd/architecture.md#데이터베이스-연결), [일관 읽기](../sdd/search.md#요청-단위-일관-읽기-구현-비교), [시험 설계](../sdd/testing.md#데이터베이스가-필요한-테스트), [시험 시점](../DEVELOPMENT_PLAN.md#테스트-작성과-실행-시점).
- 시작 커밋: `3dbcbe3`, 브랜치 `feat/data-schema-contract`. fetch 후 origin/dev 대비 뒤처짐 0·앞섬 3이다.
- 과거 결과를 승계하지 않고 현재 코드와 새 합성 DB에서 해당 작업의 연결·예약·해석·종료 경계를 다시 검증했다.

## 구현

- 연결별 AfterConnect에서 AGE 적재·ag_catalog search_path·UTC를 준비한다. 준비 실패 연결은 풀에 편입하지 않는다. 그래프 식별자는 63바이트 한계를 지킨다.
- 최소 풀 4개, 스냅숏 4개·멱등성/충돌 재조회/주기 작업 2개 예약과 `max(4, pool_max_conns - 4)` 총량을 적용한다. 예약 대기 중에는 연결을 획득하지 않는다.
- 읽기 3자리는 읽기 연결 반환 뒤 접근 기록이 끝날 때까지 유지한다. 중첩 읽기와 멱등성 저장점은 바깥 경계를 공유한다. agtype 해석은 store 내부의 단일 경계에서 수행한다.
- 스냅숏 Close는 통계와 오류를 반환하고 반복 호출해도 정리·예약 반납을 한 번만 수행한다. WithReadSnapshot은 읽기 오류와 종료 오류를 함께 전달한다.
- 롤백과 세션 잠금 해제에 요청 취소와 독립된 5초 정리 예산을 적용한다. 드라이버 오류·표준 취소/마감·호출자 지정 원인을 함께 보존한다. 주기 잠금 응답이 불명확하거나 해제에 실패하면 해당 세션을 폐기한다.

## 실행 환경과 결과

- Go 1.27.1, macOS/arm64, pgx/pgxpool v5.10.0, x/sync v0.22.0. 공급자 API와 고정 판의 로컬 모듈 소스를 대조했다. Modern Go Guidelines의 Go 1.27 전체 목록을 적용했다.
- 전용 프로젝트 `arch04-db-mvypcr5b`의 새 볼륨·loopback 동적 포트·합성 DB만 사용했다. 실제 환경 파일은 읽지 않았다. 고정 Dockerfile을 캐시 허용 빌드했다.
- 실제 DB: PostgreSQL 18.6, AGE 1.8.0, pgvector 0.8.6, Linux/aarch64. 빈 시험 DB에 001·009·010을 적용했다.

| 검증 | 관찰 결과 |
|---|---|
| 연결 준비·실패 배제 | 실제 연결 4개 각각에서 AGE cypher·agtype·search_path·UTC를 확인했다. 권한 없는 시험 로그인은 LOAD 실패 후 획득 연결 0이었다. |
| 예약·획득 대기 | 풀 상한 1~3·64바이트 그래프를 연결 전에 거부했다. 상한 4~64의 총량과 사용자 지정 취소 원인을 검증했다. 예약 대기 중 연결 0, 실제 풀 포화에서 조정/읽기 획득 취소 후 예약·자리가 회복됐다. |
| 경합·읽기 상한 | 풀 4개에서 스냅숏 8개+멱등성 8개, 스냅숏 8개+주기 작업 8개가 유한 시간 안에 종료했다. 컨텍스트 생성/갱신/폐기/복구 예약·AGE 충돌 경합, 저장점의 바깥 예약 공유를 확인했다. |
| 접근 기록·스냅숏 | 조정 연결+읽기 3개의 실제 점유 4를 직접 확인했다. 실제 비영 임베딩의 cold→hot 및 접근 시각 갱신, 접근 기록 중 자리 유지, 이후 새 읽기 진행을 확인했다. 스냅숏은 후속 커밋을 숨겼고 중첩 읽기는 연결·자리를 추가 소비하지 않았다. |
| 실패와 회복 | 잘못된 스냅숏 가져오기·SQL 오류·요청 취소·접근 기록 실패·종료 SQL 취소·멱등성 취소·잠금 세션 강제 종료를 검사했다. 읽기와 종료 오류를 함께 보존하고 취소된 멱등성 행은 남지 않았다. 연결·활성 읽기·자리·전체 예약량을 직접 대조했다. |
| 모듈 시험 | 대상 범위 최상위 30개+하위 21개, 합계 51건 PASS, 실패 0·건너뜀 0, race PASS. 전체 store 업무 시험이나 분야 통합 인수로 확대 해석하지 않는다. |
| 정적 검사 | check-go.sh의 의존성 검증·전체 build·vet·gofmt PASS. |
| 시험 정리 | 전용 Compose down --volumes --rmi local 완료. 프로젝트 label로 컨테이너·볼륨·네트워크 잔여 0을 확인했다. |

최종 모듈 명령은 다음과 같다. TEST_DATABASE_URL은 해당 시험의 일회성 합성 DB 주소를 사용했고 TEST_DATABASE_REQUIRED=1·AGE_GRAPH_NAME=agent_context를 함께 설정했다.

```sh
go test -race -json -count=1 ./internal/store -run 'Test(Connection|ReadSnapshot|Snapshot|ContextWritesReserve|ContextAGEConflicts|ContextWriteReservation|NewReservations|WithTryAdvisoryLock|ParseContext|Cursor|DollarString|EncodeProperties|GraphNamePattern)'
```

세션 강제 종료의 최초 시험에서는 풀 통계가 즉시 0이 되지 않았다. 공급자 구현의 비동기 폐기를 반영해 최대 5초 안에 실제 획득 연결 수가 기준값으로 회복되는지 직접 대조하도록 보완했으며 최종 대상 범위 51건을 다시 통과했다. 정리 예산은 DB 취소·OS 수준 처리의 정확한 벽시계 상한을 보장한다는 의미가 아니다.

## 완료와 남은 범위

ARCH-04를 완료한다. 다음 항목은 [DATA-03](../development-plan/data.md#data-03)의 단일 접근 계층·격리 구현이다. 기존 저장 기능 전체, 권한·쓰기 정책 전체, 검색/데이터 분야 통합, 외부 제공자·실제 서버/호스트·운영 DB·amd64 runtime 인수는 수행하지 않았다.

DOX pass 결과 패키지·정본 소유권·구조·색인·요구사항·용어 변경이 없어 DOX·SRS·SDD를 유지했다. 기존 운영 Compose와 IDE 변경은 작업 범위에 포함하지 않았다. 커밋·푸시는 수행하지 않았다.
