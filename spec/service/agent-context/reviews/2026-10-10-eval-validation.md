# 평가 입력·정리 실패·일관성 판정 검증

## 범위와 근거

[GitHub #85](https://github.com/Alpha-gone/agent-context-sharing/issues/85)의 여섯 항목을 `fix/issue-85-eval-validation`에서 처리했다. 동기화된 `dev`에서 시작했으며 기존 사용자 IDE staging을 보존했다. SDD의 「검증을 가능하게 하는 설계」를 먼저 구체화하고 Go 1.27.1·Modern Go Guidelines·코딩 표준을 적용했다.

수정 전 회귀에서 업무 효과의 두 조건 각각에 재작업·세션 재개·협업 활용 지표가 없거나 `null`이어도 허용됐다. 같은 질의의 약한 성공 조건을 먼저 넣은 공격 표본도 허용됐고, 공격 세트의 사용 사례 필터 실패 후 출력 파일이 남았다. 여섯 모드의 15개 충돌 조합은 입력 처리 전에 거부되지 않았으며 빈 지연 표본은 0으로 기록됐다. 완료 시간의 누락·`null`은 기존 양수 검증이 이미 거부했으며, 실패 재현과 통과한 검사를 구분했다.

## 처리 결과

- 업무 효과: 네 지표를 JSON 포인터로 읽어 누락·`null`을 거부하고 모두 확보한 뒤 측정값에 대입한다. 허용하지 않은 필드와 기존 범위 검사도 유지한다. 명시적 0은 허용하고 두 조건·네 지표·누락 및 `null`의 16개 조합을 검증한다.
- 공격 표본: `success_criteria`에서 같은 `query_id`가 다시 나오면 거부한다. 목록 내부 식별자의 기존 중복 검증과 상호 강화의 서로 다른 오염 식별자 둘 이상 계약도 유지한다.
- 정리: 공통 `dropGraph`가 취소와 독립된 10초 context로 소프트 삭제한다. 기본·적응형·일관성·지속·적대적 기준선·공격 회차 및 적재·색인 실패에서 오류를 `errors.Join`으로 보존하며 `main`이 실패 종료하도록 한다.
- 판정 전제: 동시 쓰기 표본의 최대 활성 컨텍스트 수를 파생 20개·허브 원천 하나·사건 둘·임시 파생 하나인 24개로 계산한다. 후보 상한이 이를 초과하지 않으면 DB 접속·그래프 생성 전에 거부하며 `runConsistency` 경계에서도 확인한다.
- 미측정: 빈 지연 요약은 모든 값을 `-1`로 둔다. Read Committed의 스냅숏 보유 시간과 전 요청 실패의 요청당 연결·최대 연결도 `-1`이다. 실제 측정된 0과 성공 요청·스냅숏의 실제 측정값은 유지한다.
- CLI: 변환·업무 효과·지속·적응형·일관성·적대적 모드 중 둘 이상을 지정하면 입출력 전에 거부한다. 여섯 공격 유형을 함께 만드는 `own-adversarial`의 사용 사례 필터는 출력 전에 거부하며, 공격 파일도 공통 검증이 끝난 뒤 기록한다.

## 개발 DB 검증

2026-10-10에 `.env`의 로컬 접속 정보를 메모리에서 읽고 기존 개발 PostgreSQL 인스턴스의 별도 `issue85_fzlbrl_20261010` 시험 DB를 생성했다. `age 1.8.0`·`vector 0.8.6`, 정식 `001_init` 마이그레이션 적용 및 두 번째 실행의 미적용 상태를 확인했다. 768차원 `vector`와 로컬 임베딩 HTTP 대역만 사용했으며 외부 API와 기존 개발 그래프는 사용하지 않았다. 접속 정보와 자격 증명은 기록하지 않았다.

- 핵심 단위 회귀 `go test -race -count=10`의 지정 시험: 통과.
- 최초 평가 패키지 DB race 실행: 당시 테스트 항목 152개 통과, 실패 0개, 건너뛰기 0개.
- 실제 `main` 종료 경로·색인 및 정리의 동시 실패·후보 상한 허용 경계를 보강한 최종 `TEST_DATABASE_REQUIRED=1 go test -json -race -p 1 -count=1 -timeout=300s ./...`: 테스트 항목 1,024개 통과, 실패 0개, 건너뛰기 0개. 이 안의 평가 패키지는 154개이며 합계에 중복하여 더하지 않는다.
- DB 시험 전용 트리거가 평가 그래프의 소프트 삭제를 거부할 때 기본·적응형·지속·일관성의 실제 `main` 경로가 종료 코드 1을 반환했다. 트리거 없는 동일 경로는 정상 종료했다. 적대적 기준선·공격 회차의 반환 오류와 색인 취소·정리 거부가 함께 보존되는지도 확인했다.
- 후보 상한 24와 접속할 수 없는 DB 주소를 함께 주어 DB 접속 전에 전제 오류가 반환되는지 확인했다. 후보 상한 25의 정상 실행도 확인했다. 실제 동시 쓰기 검색에서 전 요청 실패와 성공 요청의 지표·Read Committed 및 스냅숏의 보유 시간 표기를 구분했다.
- 서버·클라이언트 각각 `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check` 및 문서 상대 링크·한국어 표현·맞춤법: 확인.

최초 DB 실행의 Go 시험은 종료 코드 0이었으나 결과 집계용 임시 스크립트가 시스템 Ruby에서 지원하지 않는 `filter_map`을 사용해 후처리에 실패했다. 저장된 Go 로그에서 152개 통과·실패와 건너뛰기 0개를 확인하고 호환되는 집계로 수정했다. 이후 최종 전체 실행의 집계와 종료 코드도 정상 확인했다. DB 없이 먼저 실행한 패키지 시험은 통합 계층을 건너뛰었으므로 DB 검증 통과로 사용하지 않았다.

검증 종료 후 시험 DB 연결이 0개임을 확인하고 이번 작업의 시험 DB만 삭제했다. 시험 DB가 없음을 재확인했으며 기존 개발 컨테이너 ID와 기동 시각도 유지됐다. 실패 주입 트리거·합성 그래프 등은 시험 DB에만 있었고 테스트 정리 및 시험 DB 삭제로 제거했다. 기존 개발 데이터·볼륨·`.env`·사용자 IDE staging은 보존했다.

## DOX pass와 제한

루트 및 `spec/`→`service/`→`agent-context/`의 DOX를 확인했다. 루트의 평가 계약 안내와 소유 SDD·개발 계획·요청 기록을 갱신했다. 서비스 DOX·부모 Child DOX Index는 목적·소유권·경로가 바뀌지 않아 유지했다. 기존 요구사항의 검증 정확성을 복원하므로 SRS·공개 도구 계약·마이그레이션·의존성·배포 구성·용어집은 변경하지 않았다.

이 결과는 합성 데이터와 로컬 임베딩 대역을 사용한 회귀 검증이며 본격 검색 품질·공격 성공률·외부 제공자·운영 배포·공식 출시 판정이 아니다. 실제 DB에서 적대적 기준선·공격 회차의 정리 경계를 확인했지만 여섯 공격 유형의 전후·복구 품질 평가를 새로 수행한 것은 아니다. 커밋·푸시·PR 생성·이슈 직접 종료는 수행하지 않았다.
