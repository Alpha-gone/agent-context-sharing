## 변경과 통계 경계

기존 단계별 추정은 회차별 사용 사례 평균을, 대응 비교는 개별 질의 평균을 표본으로 사용했다. 새 집계는 질의별 반복 평균→같은 대화·과업의 문항 평균→독립 단위별 대응 차이 순서다. 대화의 문항 수가 달라도 독립 단위에는 같은 가중치를 준다. 비교 양쪽에서 같은 질의·지표가 유효한 경우만 대응시켜 서로 다른 문항 집합을 비교하지 않는다. 지표의 열 회차 중 하나라도 미측정이면 해당 질의의 그 지표를 비교에서 제외한다.

직접 질의 입력과 질의별 측정값에 선택적인 `independent_unit`을 추가했다. 비식별 코드만 허용하며 생략한 기존 자체 입력은 질의 ID별 독립 과업으로 해석한다. 공개 데이터에는 EVAL-02의 독립 단위를 연결해야 하며 자동 실행 연결은 후속 EVAL-05 범위다. 기본·적응형 CLI는 집계 전에 조건별 정확히 열 회차, 1~10의 회차 번호, 회차별 고유 질의, 동일 질의·사용 사례·독립 단위 매핑과 유한 지표를 검증한다. 누락·중복·단위 변경은 정상 결과 기록을 중단한다.

단계별 추정 JSON의 `samples`는 독립 단위 수이며 종전 `repeats`를 대체한다. 추정·비교에 자유도와 `measured`/`insufficient_units`/`unmeasured` 상태를 남긴다. 독립 단위가 없으면 평균·차이·구간을 `-1`, 하나면 평균·차이는 보존하고 표준편차·구간을 `-1`로 기록한다. 빈 대응·길이가 다른 대응·NaN/무한대·음수 미측정을 유효한 차이로 계산하지 않는다. 구간이 미정의이면 유의성을 인정하지 않는다. 지속 평가도 같은 과업의 반복을 하나의 단위로 묶으므로 현재 시나리오당 과업 하나만으로 품질 유지 합격을 낼 수 없다. 여러 독립 과업의 준비·실행은 EVAL-07에서 수행한다.

문자 사용량을 별도 지표로 보존하고 근거 분모의 필수 컨텍스트·필수 관계를 고유 집합으로 센다. 단절 비율은 반환된 노드로만 연결한 부분 그래프를 사용한다. 허브 차수의 지니 계수는 정렬한 차수로 계산하여 정수 곱·차이 합의 오버플로와 이중 순회를 없앴다. 한계 기여의 새 회수·손실은 같은 회차의 집합 차이를 먼저 질의별 평균하며 첫 회차만으로 전체를 대표하지 않는다. 해당 회수 집합이나 지연을 측정하지 않은 경우도 `-1`로 보존한다. 지연 차이에는 유효 질의 수 `latency_queries`를 함께 남겨 실제 -1ms 변화와 미측정을 구분한다.

질의 실행·반복 누적·숫자 평균의 순서를 고정하며 맵 키는 기존 결정적 JSON 기록을 따른다. 동일 측정값의 입력 순서를 바꾸는 것과 실제 지연·시각·쓰기 횟수가 달라지는 것은 구분한다. 시간을 고정값으로 대체하지 않았다.

## 검증

```sh
go test -race -count=1 -json -timeout=240s -skip Integration ./cmd/eval
TEST_DATABASE_URL=<격리 DB> TEST_DATABASE_REQUIRED=1 go test -race -count=1 -json -timeout=360s -run '^TestEvaluationCommandCleanupFailsExitIntegration$/^normal$/^[01]$' ./cmd/eval
sh check-go.sh
```

Go 1.27.1에서 최종 고유 시험 **299건**(최상위 **95건**, 하위 사례 포함)이 실패·건너뜀 없이 통과했다. DB 없는 모듈 시험 **296건**과 기본/적응형 실제 CLI **3건**을 합산했다. 중간 실행을 다시 더하지 않았다. 모듈 명령은 `Integration` 이름의 DB 시험을 선택하지 않았으며 전체 DB·분야 통합을 실행했다고 주장하지 않는다. 실제 CLI는 별도 PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6 linux/aarch64 컨테이너의 정식 스키마와 768차원 대역 Gemini를 사용했다. 외부 모델 호출은 없다. 전체 의존성·build·vet·gofmt 검사도 통과했다.

- 새 집계 시험 23건에서 대화별 동일 가중치·단일 독립 대화·일부 지표 미측정의 동일 문항 대응·무자료·측정 0·중복/누락 회차·질의/단위 변경·비정상 숫자·비식별 코드 입력을 확인했다.
- 회차·질의 순서를 64회 섞어 단계 추정·대응 비교·한계 기여의 JSON과 적응형 질의 평균이 같은지 대조했다.
- 알려진 대응 차이 `[1,2,3]`의 평균 2·95% 구간 반폭 약 2.4841377117과 독립 대화 두 개의 자유도 1 통계를 확인했다. 자유도 1~500의 분위수를 연분수 구현과 별개의 확률밀도 Simpson 적분으로 대조했다. 자유도 31의 정규 근사 거짓 유의성 회귀도 통과했다.
- 겹친 근거 분모, 반환되지 않은 중간 노드의 잘못된 연결, 큰 차수의 지니 계수, 회차별 회수 변동과 단일 지속 과업의 판정 보류를 확인했다.
- 실제 기본 10개·적응형 60개 그래프의 정상 실행·정리와 새 집계 검증 경계의 연결을 확인했다. 실제 공개 벤치마크 개선·성능 인수나 기본값 채택으로 확대하지 않는다.

## 중간 실패·남은 조건·DOX

첫 모듈 실행에서 순서 변경 시험이 비공개 필드만 있는 내부 `queryOutcome`을 JSON으로 직렬화하여 실패했다. 공개 결과 JSON만 직렬화하고 내부 평균은 값 비교로 대조하도록 시험을 수정한 뒤 재검증했다. 이 실패를 통과에 합산하지 않았다.

실제 CLI 시험 종료 뒤 잔류 연결 0개를 확인하고 자체 시험 컨테이너·익명 볼륨만 제거했다. 공개 데이터의 독립 단위 매핑을 실제 비교 실행에 자동 연결하는 작업, 공격 표본의 새 통제 실행·인수와 업무 효과·비용 판정은 후속이다. 기존 자체 입력의 독립성은 입력 작성자의 과업 경계에 달려 있으며, 같은 대화의 문항은 반드시 같은 `independent_unit`을 지정해야 한다. 출력 추정의 `repeats`→`samples` 변경과 한계 기여 회수 수의 반복 평균은 후속 결과 소비자가 반영해야 한다.

평가 SDD는 집계·누락·단위 계약의 정본으로, 계획/SDD 진입점·서비스 색인은 구현 상태로, 요청·공식 근거·이 문서는 새 증거 위치로 유지한다. 패키지·지속 경계·소유권이 바뀌지 않아 DOX 수정은 필요하지 않음을 확인했다. 변경 Markdown 8개·로컬 링크/앵커 426개와 작업 124개/완료 107개의 정합성을 확인했다. 전체 계획은 **107/124개 완료·1개 진행·16개 미착수**이며 다음은 EVAL-05다. 변경은 미커밋이며 기존 개인 `.idea` 두 파일은 제외한다.
