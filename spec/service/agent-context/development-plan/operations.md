# 운영 개발 계획

[전체 계획](../DEVELOPMENT_PLAN.md) · [기준 SDD](../sdd/operations.md) · [작업 추적](traceability.md)

## 목표와 구현 범위

개발·운영 실행 구성, 전송 보안, 아홉 주기 작업, 기동·종료·장애·복구를 새로 구현한다. 격리 시험의 실행 결과와 실제 운영 배포·외부 공개를 구분한다.

- 설계 입력: [주기 작업](../sdd/operations.md#주기-작업), [기동·종료](../sdd/operations.md#기동과-종료), [배포 구성](../sdd/operations.md#배포-구성), [환경 경계](../sdd/operations.md#개발운영-환경-경계), [복구](../sdd/operations.md#복구), [백업](../sdd/operations.md#백업과-복구), [목표 구성](../sdd/operations.md#목표-추가-구성).
- 예정 구현 영역: 루트 Dockerfile·Compose·환경 예시·검사 스크립트, `cmd/server`의 생명주기, `internal/store`의 주기 처리, 운영 안내.
- 다른 분야와의 경계: 트랜잭션·저장 모델은 데이터/수명주기, 진단 회전은 관측성, 실제 사용자·호스트 인수는 테스트 계획이 소유한다.

## 개발 작업

### OPS-01

- [x] **고정 이미지·개발 DB·격리 실행 환경을 준비한다.**
- 선행: [ARCH-01](architecture.md#arch-01).

1. SDD의 PostgreSQL 18·AGE 1.8.0·pgvector 완전 패키지 판과 이미지 tag/digest를 고정하고 DB 이미지·기동 래퍼를 작성한다.
2. compose.dev.yaml의 기본 DB·WAL 정리와 목표 server profile을 구현한다. DB 공개는 127.0.0.1, 서버는 localhost:80→컨테이너 HTTP 8080을 사용한다.
3. 기본/재정의 포트·server 의존 순서·터널 네트워크·10.204.0.1/32 신뢰를 검사하고 별도 모델 서비스·profile·볼륨을 두지 않는다.
4. .env.example과 정적 검사, 별도 프로젝트·합성 자격·볼륨의 DB runtime 검사를 준비한다. 기존 .env·컨테이너·볼륨은 사용하지 않는다.

- 산출물: 개발 이미지·Compose·환경 예시·test-dev-compose.sh와 격리 DB.
- 완료 기준: 기본 기동에서 서버가 제외되고 캐시 없는 DB 빌드·설치 판·loopback 공개·SQL 응답을 검증한다. server 이미지·실제 Tunnel 인수는 별도다.

- 완료 근거: 2026-10-15 [개발 DB 격리 환경 검토](../reviews/2026-10-15-ops-01.md). 정적 구성·합성 fixture 6건과 새 프로젝트의 두 DB 이미지 캐시 없는 빌드·기동·설치 판·loopback·WAL 경로 권한·벡터/AGE 질의·자원 정리가 통과했다. 서버 이미지·실제 Tunnel·WAL 보관 재개와 시점 복구·운영 배포는 후속 인수 범위다. 다음은 DATA-02다.

### OPS-02

- [x] **운영 템플릿·목표 구성·진단 볼륨을 구현한다.**
- 선행: [OPS-01](#ops-01), [ARCH-05](architecture.md#arch-05), [OBS-01](observability.md#obs-01).

1. Dockerfile.server에 서버·마이그레이션·감사 실행기를 포함하고 베이스 tag/digest·Go 도구 체인을 고정한다.
2. 운영의 DB 비공개·서버 127.0.0.1 HTTP_PORT 기본 80·10.203.0.1/32 신뢰·DB→migrate→server 순서를 구성한다.
3. MCP_RESOURCE_URL·MCP_ALLOWED_ORIGINS·OAUTH_CLIENT_REGISTRATIONS와 세 진단 키를 두 환경 예시·검증·서버 주입에 연결한다.
4. 영속 진단 볼륨·안정 instance 슬롯·권한을 구성하고 운영 WAL 자동 정리를 두지 않는다. 정적 검사는 실제 .env·빌드·컨테이너 없이 실행한다.

- 산출물: 운영 Compose·애플리케이션 이미지·.env.prod.example·test-prod-compose.sh.
- 완료 기준: 미지원 키·잘못된 등록·진단 ID·비밀 누락을 안전하게 거부하고 고정 loopback·신뢰 경로가 임의 CIDR/종단 값으로 우회되지 않는다.

- 완료 근거: 2026-10-24 [OPS-02 모듈 인수](../reviews/2026-10-24-ops-02.md). 운영·개발 server profile에 영속 진단 볼륨과 안정 슬롯을 연결하고 이미지의 UID 10001·0700 준비를 추가했다. 구성 303건·race, 운영/개발 정적 검사와 별도 서버 이미지 빌드·실제 권한/중복 거부·재생성 append·새 boot·자원 정리가 통과했다. 사용자 지시에 따라 기존 DB 공개 두 줄을 제거하여 실제 운영 구성의 비공개·loopback·고정 신뢰·기동 순서·볼륨 검사를 통과했다. 전체 Go 정적 검사도 통과했으며 다음 권장은 OPS-08이다. 실제 운영 배포·프록시 상대·Tunnel·외부 제공자 인수는 후속 범위다.

### OPS-03

- [x] **TLS·신뢰 프록시·실제 상대 해석을 구현한다.**
- 선행: [ARCH-03](architecture.md#arch-03), [ARCH-05](architecture.md#arch-05).

1. direct/proxy 종단 조합을 검증하고 상태 확인 외에는 직접 TLS 또는 좁은 실제 접속 상대·단일 HTTPS 전달 헤더를 요구한다.
2. visitor 헤더는 전송 신뢰 근거로 쓰지 않는다. 자원 보호용 주소도 검증한 상대 경로에서만 해석해 인증·권한과 분리한다.
3. 미등록·공개 로그인·메타데이터·MCP·웹에 같은 보안 판정을 연결하고 healthz/readyz의 인증·TLS 판정 예외를 구현한다.
4. 호스트 cloudflared→로컬 HTTP의 시험 운영 구간과 외부 HTTPS를 구분하고 전체 Docker/Cloudflare 대역 신뢰를 추가하지 않는다.

- 산출물: transportSecurity·쿠키 전송 보안·프록시 위반 시험.
- 완료 기준: 헤더 위조·복수 전달·대역 밖 요청·평문이 거부된다. 로컬 HTTP 시험을 전 구간 TLS나 NFR-013 충족 증거로 보고하지 않는다.
- 완료 근거: [OPS-03 검토](../reviews/2026-10-19-ops-03.md). 라우터 정규화보다 먼저 TLS를 판정하고 전달 헤더·실제 상대의 형식을 보완했다. 직접 TLS와 신뢰/비신뢰 프록시의 실제 루프백 교환·Secure 쿠키·상태 확인 예외·거부 전 양식 미처리를 검증했다. 서버 전송 195건·구성 303건, 총 498건·race와 전체 build·vet·형식 검사를 통과했다. 실제 Tunnel·운영 배포·전 구간 TLS 인수는 후속이다.

### OPS-04

- [x] **아홉 주기 작업과 실행권·보존 조건을 구현한다.**
- 선행: [ARCH-04](architecture.md#arch-04), [LIFE-06](context-lifecycle.md#life-06), [LIFE-07](context-lifecycle.md#life-07), [AUTH-09](authentication.md#auth-09), [MCP-05](mcp.md#mcp-05), [IDX-07](indexing.md#idx-07), [OBS-04](observability.md#obs-04), [OBS-06](observability.md#obs-06).

1. 유예·멱등성·폐기 목록·빈도 창·OAuth 상태·진단 정리는 매시간, 제안·감사·임베딩 이동은 매일로 구현하고 기동 직후 첫 회차를 실행한다.
2. DB 작업은 자문 잠금 연결과 본문 연결의 2개 예약을 먼저 확보하고 잠금 실패 회차를 건너뛴다. 종료·오류에 실행권·연결을 반환한다.
3. 현재 노드 폐기·소유자 이력·미처리 복구·완료 복구 근거와 OAuth 재사용 탐지의 retain_until을 정리에서 보호한다.
4. 진단 회차의 실행권은 로그 저장소·instance 범위를 사용하고 공유 파일 잠금 정책과 결합한다. 다른 저장소의 정리가 전역 DB 잠금으로 계속 제외되지 않게 한다.

- 산출물: 주기 스케줄·각 처리 API·잠금·건수·실패/건너뜀 지표.
- 완료 기준: 두 인스턴스가 같은 범위 회차를 중복 처리하지 않고 실패 다음 회차가 남은 조건을 다시 처리한다. 정리가 늦어도 자격·키 수명이 연장되지 않는다.

- 완료 근거: 2026-10-23 [OPS-04 모듈 인수](../reviews/2026-10-23-ops-04.md). 여덟 DB 작업과 기록기 소유의 시간별 파일 정리를 연결했다. OAuth는 계열 잠금 뒤 보존 시각을 재검사하고 자식과 계열을 원자적으로 정리하며 진단은 저장소 실체·instance별 실행권과 공유 파일 잠금을 유지한다. 최소 풀 4개에서 여덟 기동 회차, 두 인스턴스의 경합/취소/재획득·보존 연장·롤백/다음 회차·128개 후보 페이지와 기존 감사/복구 근거·OAuth 수명을 확인했다. 서버 580건·진단 168건·저장 6건·인증 48건, 총 802건(하위 사례 포함), race·전체 정적 검사·Linux 대상 빌드가 통과했다. 다음 권장은 OPS-05다. 전체 운영 실패·Linux runtime·배포 인수는 후속 범위다.

### OPS-05

- [x] **기동·수신 실패·정상 종료의 공통 정리를 구현한다.**
- 선행: [ARCH-06](architecture.md#arch-06), [ARCH-07](architecture.md#arch-07), [IDX-06](indexing.md#idx-06), [OPS-04](#ops-04), [OBS-07](observability.md#obs-07).

1. 구성 검증·진단 파일 준비·DB/서비스 조립·작업자 시작·수신 순서를 만들고 시작 전에 종료 책임을 등록한다.
2. 종료 때 readyz 이탈→새 요청 중단→최대 30초 진행 요청 대기→독립 공용 10초 작업자 종료→안전한 풀 종료→최대 5초 진단 flush를 적용한다.
3. 요청 종료 실패면 HTTP 연결을 닫아 취소하고 모든 작업자 정리를 시도한다. 요청/작업자 정리 실패면 풀 종료를 생략해 미반환 연결을 무한 기다리지 않는다.
4. 시작·수신·요청·각 작업자의 오류를 함께 보존하고 실패 종료 코드 1을 반환한다. 이미 종료 시도한 작업자를 다시 닫지 않는다.

- 산출물: 실행 생명주기·오류 집계·공통 정리와 기동 단계별 장애 표본.
- 완료 기준: 정리 예산 30/10/5초가 구분되고 50초 강제 종료 구성과 대조된다. 요청·작업자 성공 때만 풀을 닫으며 정리 중 오류가 원래 오류를 가리지 않는다.

- 완료 근거: 2026-10-23 [OPS-05 모듈 인수](../reviews/2026-10-23-ops-05.md). 수신 실패도 준비 상태 이탈·요청 대기·작업자 종료·조건부 풀 종료·진단 flush를 거치며 신호 뒤의 수신 오류도 함께 보존한다. embedded/external의 실제 진행 요청·수신 실패·중복 종료 방지, 기동 단계별 실패와 실제 프로세스 종료 코드 1을 확인했다. DB 연결을 유지한 요청의 30초 대기·독립 작업자 10초와 파일 잠금 경합의 flush 5초를 실측하고 Compose의 50초 구성과 대조했다. 서버 595건·진단 168건, 총 763건(하위 사례 포함), race·전체 정적 검사·Linux 대상 빌드가 통과했다. 다음 권장은 OPS-06이며 컨테이너 강제 종료·Linux runtime·전체 운영 장애/배포 인수는 후속 범위다.

### OPS-06

- [x] **자동 삭제 그래프의 요청·운영자 복구를 구현한다.**
- 선행: [LIFE-06](context-lifecycle.md#life-06), [LIFE-07](context-lifecycle.md#life-07), [OBS-06](observability.md#obs-06), [PERM-03](authorization.md#perm-03).

1. 초기 생성자·owner 부여 이력으로 요청 자격을 확인하고 자동 삭제 상태의 요청 기록을 남긴다.
2. 그래프 잠금 뒤 자동 삭제와 가장 오래된 미처리 요청을 다시 읽고 시각 동률은 감사 ID로 정렬한다.
3. 해당 요청자에게 직접 owner를 upsert하고 삭제·유예 시각 해제·운영자/요청자·이전/이후 등급 감사 기록을 한 트랜잭션으로 적용한다.
4. 내용 조회·팀 변경·운영자 자신의 등급 확대 없이 처리하고 감사·등급 저장 실패는 그래프 복구까지 롤백한다.

- 산출물: 복구 요청·대기 확인·원자적 운영자 복구 API.
- 완료 기준: 요청 없는 복구·타 계정 요청·직접 삭제 대상이 거부되고 동시 처리는 한 번만 적용된다. 정리 후 처리 완료 요청이 다시 대기로 나오지 않는다.

- 완료 근거: 2026-10-23 [OPS-06 모듈 인수](../reviews/2026-10-23-ops-06.md). 요청·대기 목록·운영자 복구의 기존 연결에 취소와 독립된 롤백 및 원인 보존을 보완했다. 실제 초기 생성자/과거 직접·상속 소유자 이력과 거부, 시각·감사 ID 순서, 저장 실패·재시도, 잠금 대기 뒤 상태 재검사·연결 반환, 두 저장소 인스턴스의 단일 적용과 감사 정리 뒤 재등장 방지를 확인했다. 실제 세션·TLS 요청에서 요청자 위조·출처 위반·무요청/중복 처리를 거부하고 처리 운영자에게 등급이나 본문을 노출하지 않았다. 신규 17건을 포함한 저장소 52건·서버 1건, 총 53건(하위 사례 포함), race·전체 정적 검사·Linux 대상 빌드가 통과했다. 다음 권장은 OPS-07이다. 전체 운영 장애·실제 브라우저·Linux runtime·배포 인수는 후속 범위다.

### OPS-07

- [x] **WAL 보관·물리 백업·시점 복구를 구현·시험한다.**
- 선행: [OPS-01](#ops-01), [DATA-06](data.md#data-06), [DATA-08](data.md#data-08).

1. 볼륨 마운트 뒤 보관 디렉터리 준비·소유·0700·실패 시 DB 미기동을 구현하고 새/기존 시험 볼륨의 보관 재개를 검사한다.
2. 기본 물리 백업·WAL·AGE·관계형 데이터·hot/cold tablespace 연결을 함께 보존한다. 논리 덤프를 AGE 전체 복구 수단으로 쓰지 않는다.
3. 별도 시험 프로젝트에서 정해진 시점으로 복구하고 AGE 질의·현재 모델·양쪽 HNSW·서명 상태·큐·전체 불변식을 검사한다.
4. 개발 시간 기준 WAL 정리와 운영의 기본 백업 기반 수동 보존을 나누고 시험이 만든 자원만 정리한다.

- 산출물: 기동 래퍼·격리 WAL 회귀·백업/복구 절차와 시험 기록.
- 완료 기준: 기존 데이터를 지우지 않고 보관을 회복하며 복원한 그래프 질의와 전체 감사가 성공한다. 실제 운영 백업·보관본 삭제는 실행 범위를 별도로 확인한다.

- 완료 근거: 2026-10-23 [OPS-07 모듈 인수](../reviews/2026-10-23-ops-07.md). 기존 기동 래퍼와 격리 WAL 회귀를 새로 실행하고 별도 cold tablespace를 포함한 물리 백업·manifest/WAL 검증·손상 거부·이름 있는 복구 지점의 일시 정지/승격을 인수했다. 기본 백업 뒤 변경은 포함하고 목표 뒤 변경은 제외했으며 AGE 정점/파생 관계·관계형 상태·현재 모델·양쪽 HNSW·기존 세션 서명·큐와 전체 불변식을 확인했다. 승격 후 실제 검색·대기 작업 소비·cmd/audit도 성공했다. 두 격리 실행과 전체 정적 검사가 통과했고 생성 자원만 정리했다. 다음 권장은 OPS-08의 선행인 OPS-02다. 실제 운영 백업·외부 보관·보관본 삭제·배포와 복구 시간 보장은 후속 범위다.
