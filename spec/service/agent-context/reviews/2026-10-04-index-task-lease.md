# 색인 작업 리스 회귀 검증

## 대상과 결함

- 대상: GitHub 이슈 [#47](https://github.com/Alpha-gone/agent-context-sharing/issues/47), `internal/store/index.go`의 작업 확보·결과 저장·실패 기록과 색인 대상 제외 경로.
- 해결된 결함: 확보 뒤 본문이 갱신되어 작업이 재등록돼도 이전 결과가 임베딩을 교체하고, 이전 실패가 새 작업의 시도 횟수·상태·다음 시도 시각을 변경했다. 결과 저장은 작업 삭제 시에만 등록 시각을 비교했고, 실패 기록은 작업 식별자만 비교했다.
- 수정 전 실제 개발 DB에서 재등록 회귀를 실행해 이전 성공의 저장과 이전 실패의 새 작업 상태 변경을 확인했다.

## 수정

확보 시점의 등록 시각과 DB가 저장한 리스 시각을 보존한다. 성공 경로는 작업 식별자·등록 시각·리스 시각·대기 상태가 일치하는 행을 먼저 삭제하고, 같은 트랜잭션에서 임베딩 교체·내용 판 증가·불변식 검사를 수행한다. 작업이 재등록·재확보되거나 삭제됐으면 아무 결과도 저장하지 않고 `Succeeded=false`로 반환한다. 저장 오류 시 작업 삭제와 기존 임베딩 제거도 롤백한다.

실패 기록도 같은 조건에 맞는 확보분에만 적용한다. 색인 대상에서 빠진 계층을 정리할 때도 작업 행부터 임베딩 순서로 잠가 결과 저장과 잠금 순서를 맞춘다. 공개 도구 계약·스키마·의존성은 바뀌지 않았다.

## 검증 결과

Go 1.27.1과 실행 중인 PostgreSQL·AGE 개발 DB에서 다음 명령을 실행했다. `TEST_DATABASE_URL`을 설정하고 `TEST_DATABASE_REQUIRED=1`로 DB 테스트를 건너뛰지 않게 했다.

```shell
go test -race ./internal/store -run 'Test(Index|ProcessNextIndexTask|ReindexGraphDropsExcludedEmbeddingsIntegration|ReindexExcludesAndReplacesOutdatedModel)' -count=1 -v
```

최상위 테스트 15개가 모두 통과했고 race 검사에서 문제가 보고되지 않았다.

- 재등록 뒤 이전 성공·재시도 가능 실패·영구 실패·시도 한계 실패를 새 작업 대기 중과 새 작업 완료 후에 각각 대조했다. 8개 조합에서 작업 상태·내용 판과 최종 임베딩을 검증했다.
- 등록 시각을 유지한 채 리스를 만료시키고 새 작업자가 재확보한 뒤, 이전 성공·영구 실패가 새 재시도 상태를 변경하지 않는지 검증했다.
- 임베딩 차원 오류로 저장을 실패시켜 작업 행·기존 임베딩·내용 판의 롤백을 검증했다.
- 제공자 호출 중 원천 제외 재색인을 실행해 이전 결과가 삭제된 임베딩을 되살리지 않는지 검증했다.
- 기존 작업 확보·재시도·그래프 범위·색인 대상·의미 검색·모델 재색인 회귀와 제공자 지연 중 본문 저장 테스트를 함께 실행했다.

새 회귀는 테스트별 그래프와 합성 본문을 사용하며 남긴 색인 작업을 정리한다. 즉시 확보할 작업은 등록 시각을 보존하고 `next_attempt_at`만 DB 시각으로 맞춰 호스트와 DB 시계 차이에 따른 테스트 실패를 피한다. 기존 모델 재색인 테스트는 원래의 전체 그래프 재등록 경로를 사용한다. 실제 임베딩 제공자를 호출하지 않았으며 DB 전체 초기화·볼륨 삭제·마이그레이션은 수행하지 않았다.

서버와 클라이언트의 `go build ./...`, `go vet ./...`, 루트 `gofmt -l .` 및 `git diff --check`를 확인했다. 서버의 DB 없는 전체 `go test ./...`도 실행했으며, 그 실행에서는 DB가 필요한 계층을 건너뛰었다. DB 전체 통합·연산·격리 위반 테스트를 모두 실행한 결과는 아니며 실제 DB 검증 범위는 위의 색인 회귀다.

## DOX와 제한

루트와 `spec/`→`spec/service/`→`agent-context/` 계약을 확인하고 SDD의 「색인 작업 큐」·동시성 검증 및 서비스 AGENTS의 유효 확보분 계약을 동기화했다. 요구사항·모듈 경계·문서 소유권·Child DOX Index가 바뀌지 않아 SRS와 상위 AGENTS는 유지했다. 한국어 표현·맞춤법과 상대 경로를 검토했다.

로컬 `dev`와 저장된 `origin/dev`는 작업 시작 시 같았으나 원격 조회는 DNS 오류로 실패해 최신 upstream 상태를 확인하지 못했다. 커밋·푸시·PR 생성·이슈 종료는 수행하지 않았다.
