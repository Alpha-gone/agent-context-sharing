# 검색 개발 계획

[전체 계획](../DEVELOPMENT_PLAN.md) · [기준 SDD](../sdd/search.md) · [작업 추적](traceability.md)

## 목표와 구현 범위

네 검색 채널, 일관 읽기, 홉 탐색·적재 보호, 결정적 결합·접기·예산과 평면 작업 컨텍스트 흐름을 새로 구현한다. SDD가 채택한 방식은 따르되 과거 측정값을 새 구현의 성능 근거로 사용하지 않는다.

- 설계 입력: [실행기](../sdd/search.md#검색-채널-실행기), [일관 읽기](../sdd/search.md#요청-단위-일관-읽기-구현-비교), [채널](../sdd/search.md#채널-구현), [홉 보호](../sdd/search.md#고연결-노드의-조회적재-보호), [라우팅](../sdd/search.md#질의-적응형-라우팅), [근거 선택](../sdd/search.md#근거-경로-보존-선택), [흐름](../sdd/search.md#작업-컨텍스트-흐름-조회).
- 예정 구현 영역: `internal/search`, `internal/store`의 SQL 검색·Cypher 홉·스냅숏 읽기, 서버의 인터페이스 주입.
- 다른 분야와의 경계: 임베딩 생성은 색인 계획, 외부 스키마는 MCP 계획, 채택 조건·정량 판정은 평가 계획이 소유한다.

### SEARCH-02

- [x] **세 진입 채널과 독립 실패 처리를 구현한다.**
- 선행: [SEARCH-01](#search-01), [DATA-05](data.md#data-05), [DATA-07](data.md#data-07), [IDX-03](indexing.md#idx-03).

1. 의미 채널은 현재 모델·graph·활성·유효 조건과 거리 순서로 HNSW를 조회한다. 지원 판에서는 strict_order를 해당 트랜잭션에만 적용한다.
2. 키워드는 색인과 같은 simple 구성, 어휘 OR 조립·websearch_to_tsquery·ts_rank_cd를 사용한다. 시간 채널은 as_of 유효 조건과 recorded_at 내림차순을 적용한다.
3. 각 채널의 후보 상한·안정적 동점을 처리하고 병렬·순차 실행에서 같은 목록을 만들며 성공 빈 결과·장애·disabled를 나눈다.
4. 질의 임베딩 실패는 의미 채널만 실패로 기록한다. 진입 모두 실패하면 확장을 진입점 없음으로 실패 처리하고 전체 실패 조건을 판단한다.

- 산출물: 세 채널 질의·실행기·부분 상태와 대역/DB 표본.
- 완료 기준: 채널별 범위·순위·실패가 분리되고 풀 연결에 HNSW 설정이 남지 않는다. 시간 후보·하한 미달 의미 후보를 관련성 판정과 혼동하지 않는다.

- 완료 근거: 2026-10-18 [세 진입 채널·독립 실패 검토](../reviews/2026-10-18-search-02.md). 따옴표 구문을 보존하는 OR 조립, 실패 채널의 부분 후보 배제, 저장 조회의 UTC/미지정 시각 검사와 의미 질의의 취소 독립 정리를 보강했다. vector·halfvec에서 모델/그래프·활성·만료·전역 요약 제외, 시각 경계·채널별 순서/상한·실제 검색기의 병렬/순차 목록 동등성, HNSW 카탈로그/이용 가능 계획·strict_order 범위와 실패/잠금 취소 뒤 원인·풀 회복을 확인했다. search 100건·store 26건, 고유 시험·하위 시험 126건의 최종 결과와 race·전체 build·vet·형식 검사가 통과했다. 반복 실행은 고유 수에 더하지 않았다. 성능·재현율·실제 제공자/호스트·전체 검색 인수는 후속 범위이며 다음 권장 항목은 [SEARCH-03](#search-03)이다.
