## 구현

- `internal/mcp/tool_schemas.go`: 공통 instructions와 업무 13종·agent_register의 이름·설명·annotations·입력 스키마를 소유한다. 모든 객체는 additionalProperties=false이며 source_ref의 하위 객체도 닫혀 있다. 계층별 필수·금지 속성, summary/opinion의 조건부 속성, keep의 가변 필드 금지를 스키마로 표현한다.
- 원천의 정정과 파생 대체·기대 판·등록 키 재사용·선택 request_id의 24시간 재생·불확정 결과 재조회·삭제/권한/팀의 웹 채널·정상 부분 결과를 설명한다. annotations와 호스트 승인이 서버 권한을 대체하지 않는다고 안내한다. 원천·파생·사건의 현재 상태 판정은 모델·저장 계층에 남긴다.
- 읽기 5종은 readOnly, agent_register·relation_confirm은 변경 도구 중 idempotent다. 원천 중복이나 선택 request_id가 일부 재시도를 안전하게 한다는 이유로 모든 쓰기를 idempotent로 표시하지 않는다. 파생 대체·근거 무효 영향을 포함한 node_create는 destructive 가능성을 표시한다. 모든 도구는 공유 그래프의 닫힌 영역을 다루며 외부 원본을 수집하지 않는다.
- `internal/mcp/tool_catalog.go`: 동일 스키마를 미리 resolve하여 서버 입력 검증에 사용한다. 적용 판에서 format이 주석인 점을 보완해 UUIDv7·실제 달력의 UTC 시각·scheme URI·커서 인코딩을 검사한다. 커서 내부 값의 구조와 소속·현재 상태는 기존 저장 계층이 재검증한다. 부적합 URI를 따라 외부에 접속하지 않는다.
- 기대 판을 float64로 변환하지 않고 int64로 해석한다. JSON Schema의 정수인 1.0·지수 표기도 처리하며 큰 지수에 비례해 0을 무제한 할당하지 않는다. 문자열은 UTF-8 코드 포인트 길이로 검사하고 NUL을 거부한다.
- 모든 처리기가 준비됐는지 먼저 확인한 뒤 SDK에 등록한다. 스키마 위반은 업무 처리기를 호출하지 않고 complete/isError와 invalid_argument·고정 메시지·위반 필드를 반환하며 text와 structuredContent는 같은 값이다. 임시 성공 처리기나 인증 우회 경로를 운영 서버에 연결하지 않았다.
- 기존 전이 의존성이던 `github.com/google/jsonschema-go v0.4.3`을 직접 의존성으로 표시했다. 새 모듈·버전 변경·go.sum 변경은 없다.

## 모듈 검증

`internal/mcp/tool_catalog_test.go`에서 다음을 확인했다.

- 독립된 예상 목록과 14종 이름·읽기/변경 annotations·설명·닫힌 객체를 대조했다. 삭제·권한·팀·별도 검색 도구와 서비스 전용 필수 헤더는 없다.
- 14종의 표면 형식상 정상 입력과 필수 누락·null·알 수 없는 필드를 검사했다. 같은 ID를 쓰는 합성 표본은 실제 대상의 존재·관계 자기 참조·계층 제약을 인수한 자료가 아니다.
- 이름 200자·설명 2000자·본문/작업/판단 8000자의 빈 값·한계·초과·한글·NUL과 이름/작업의 Unicode 공백을 대조했다. 판단 입력은 비어 있지 않은 문자열이어야 한다.
- 파생 참조 1/100/101개·사건 참조 1/1000/1001개와 빈 목록, 등급/상태 각 3개·탐색 7개·유형 4개 상한을 검사했다. 필터 중복도 상한에 포함하고 빈 필터는 허용한다. 참조의 실제 중복·소속·시간 범위는 모델·저장 검증의 후속 범위다.
- 등록·쓰기 키의 15/16/128/129자·허용 ASCII와 부적합 문자, UUIDv7의 표준/32자 형식·v4 거부, URI 1024/1025자·잘못된 scheme/escape, UTC Z/+00:00·실제 달력 오류·지역 시각과 커서 인코딩을 대조했다.
- source/derived/event·요약·의견의 조건부 입력, 불변 필드 거부, keep에 가변 필드를 함께 넣는 요청의 거부와 일반 갱신의 선택 시각 null을 확인했다. 시간 순서·현재 계층은 표면 검증으로 재구현하지 않는다.
- 기대 판·페이지·홉·예산의 정수/양수 경계와 2^53을 넘는 판의 보존·int64 상한·소수/지수 표기·과대 지수를 검사했다.
- 루프백 SDK에서 발견 전에 tools/list를 조회하여 14종과 private/0 캐시를 확인했다. 이어 각 도구의 형식상 정상 호출 14회가 해당 합성 처리기로 연결되고 잘못된 호출 14회는 처리기를 추가 호출하지 않는지 확인했다. 오류의 입력 원문 비노출·필드·complete 외피·text/structuredContent 동등성과 server/discover의 instructions도 확인했다.
