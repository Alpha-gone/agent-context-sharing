# EVAL-06 라우팅·일관 읽기·홉 구현 통제 비교

## 범위와 판정

[EVAL-06](../development-plan/evaluation.md#eval-06)의 비교 실행 기능을 인수한다. 선행 EVAL-05·SEARCH-08·SEARCH-10의 과거 결과를 완료 근거로 승계하지 않고 새 그래프·새 실행으로 확인했다. 공개 데이터의 검색 효과·비용·운영 기본값 채택은 이 모듈 인수와 구분한다.

## 구현

라우팅은 그래프 관계 범위·근거 선택·색인 대상·모델·문자/홉 예산을 고정하고 직접·국소·전역의 강제 실행과 auto를 회차 안에서 순환한다. 생략된 조회 시각은 실행 시작으로 고정하며 원본 입력을 변경하지 않는다. 강제 경로의 초기 신호는 모든 조건·회차에서 같아야 하고 채널 실패·질의 집합 변화·신호 변화는 임계값 재현을 중단한다. 기존 품질 우선·문자·겹치지 않는 지연 구간·직접/국소/전역 동률 규칙을 새 시험에서 대조했다. 품질이 모두 미측정이거나 사용 사례가 없는 격자를 임계값 채택 근거로 쓰지 않는다. 같은 조정 표본에서 고른 임계값은 최종 평가·운영 승격 근거가 아니다.

일관성은 Read Committed·동기화 스냅숏·내용 판 후보와 병렬/순차의 여섯 조건이다. 내용 판 후보는 실행기 어댑터에만 두며 운영 검색의 허용 값·MCP·환경 변수에 추가하지 않았다. 저장소는 그래프 범위를 검증하는 읽기 전용 내용 판 조회만 제공한다. 내용 판 대조가 실패하면 조립한 응답을 버리고 DB 읽기를 전체 재실행한다. 외부 질의 임베딩은 한 번만 실행한다. 최대 3회 재시도와 30초 요청 예산·호출자의 더 짧은 마감을 적용한다. 재시도 요청 수·총 재시도·최대 연속 재시도·상한 소진·시간 초과·채널 실패와 실제 성공한 쓰기를 구분한다.

쓰기 없는 동등성은 컨텍스트의 본문·속성·참조까지 포함한 응답 서명을 비교한다. 불일치나 채널 실패가 있으면 부하·동시 쓰기를 시작하지 않는다. 동시 쓰기 전용 조건은 문자/노드 예산의 절단을 제거하고 최소 1홉과 24개보다 큰 후보 상한을 사용한다. 원래 사용자 입력의 부하 조건과 이 전용 조건을 보고서에서 구분한다. 모든 후보 뒤에는 임시 파생·폐기 상태·확정 관계를 복구하고 정리 실패·평가 취소를 호출자에게 전파한다. 스냅숏의 연결/보유 시간은 실측하며 RC·내용 판 후보의 미계측 연결/보유 시간과 빈 지연은 `-1`이다.

단일 커밋 설명은 원천 하나·파생 하나의 실제 DB 표본에서 진입 읽기 직후 파생 복구를 커밋하여 검증했다. RC는 그래프 채널에만 나타나는 파생으로 혼합 상태를 드러내고, 스냅숏은 이전 상태를 유지하며 내용 판은 정확히 한 번 재시도하여 새 상태를 반환한다. 상한 소진 시에는 본문 없는 오류를 반환한다. 일반 동시 쓰기 보고서의 `inconsistent`는 그래프 전용 후보라는 관찰 가능한 혼합 상태의 증거 수이며, 이 값이 0이라는 사실만으로 임의 그래프의 모든 단일 커밋 상태를 증명하지 않는다.

홉은 기존 시험 전용 실행 경계와 SQL tracer를 재사용하고 공개 옵션을 늘리지 않았다. 새 희소·삭제/제안/다중 시작점·조밀 표본에서 full·bounded·VLE를 먼저 대조한 뒤 각 10회 순환했다. 연결 풀의 소켓 수신 바이트는 프로토콜 제어 응답도 포함하며 SQL 명령 수·SQL 반환 행·본문 바이트와 별도다. VLE 내부의 본문·식별자·간선별 작업량은 `-1`을 유지한다.

## 실행 결과·실패 이력

최종 고유 시험 **446건**(최상위 **135건**, 하위 사례 포함)은 평가 실행기 **442건**·저장소 **4건**이다. 최종 모듈 431건, 이전 전체 회귀에서 통과한 대형 CLI 세 조건, 별도 완료한 나머지 CLI 조건과 홉 시험을 식별자별로 중복 제거했다. 선택해 실행한 시험에는 실패·건너뜀이 없으며 하나의 전체 명령 성공으로 표현하지 않는다.

- 환경: Go 1.27.1, 직접 생성한 `acs-eval06-db`의 PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6, vector 768과 정식 마이그레이션 6개. Gemini는 로컬 HTTPS 대역만 사용했다.
- 평가 실행기: `go test -race -count=1 -json`으로 단위·통제 비교·실제 CLI·종료 신호·정리·미계측 경계를 검사했다. `TEST_DATABASE_URL`·`TEST_DATABASE_REQUIRED=1`을 설정하여 DB 미실행을 통과로 처리하지 않았다.
- 홉: `TestEVAL06HopControlledComparisonIntegration`의 세 표본·90회에서 결과 동등성·SQL/수신량/지연과 풀 연결 회복을 확인했다.
- 정적 검사: `GO_BINARY=/Users/alphagone/sdk/go1.27.1/bin/go sh check-go.sh`의 의존성·전체 build·vet·gofmt, 문서 링크·앵커·계획 상태와 `git diff --check`가 통과했다.

최종 평가 명령은 `-timeout=240s -skip '^TestEvaluationCommandCleanupFailsExitIntegration$' ./cmd/eval`이다. 나머지 CLI는 `-timeout=180s`와 각각 `-run '^TestEvaluationCommandCleanupFailsExitIntegration$/^normal$/^3$'`, `-run '^TestEvaluationCommandCleanupFailsExitIntegration$/^(candidate_boundary|candidate_preflight|cleanup_failure)$'`로 완료했다. 세 명령 모두 `go test -race -count=1 -json`을 사용했다. 대형 CLI의 normal/0~2는 시간 제한 이전 통과 결과를 사용했다.

시험 종료 뒤 전용 DB의 잔여 연결 0개를 확인하고 직접 만든 컨테이너와 익명 볼륨을 정리했다. 기존 개발 DB는 변경하지 않았다. 변경 Markdown 9개·로컬 링크/앵커 466개·계획 ID 124개/완료 109개를 대조했다.

초기 빌드에서 비교 실행기의 반환 경계 변경에 맞지 않는 시험 호출부를 수정했다. 기존 미계측 자원 시험은 RC의 연결을 0 이상으로 기대하고 취소를 성공 반환으로 기대했으므로 `-1`·취소 전파 계약으로 수정했다. 지속 지표 시험의 배열 시작 위치도 새 지표가 추가된 상태와 달라 보완했다. 실제 RC 동시 쓰기에서 관측되는 부분 채널 실패는 스냅숏 성공과 구분해 보고하며 이를 숨기거나 정상 동등성으로 처리하지 않는다.

첫 전체 평가 회귀는 4분 제한에 도달했다. 10개 그래프의 기본 CLI(20.06초)·60개 그래프의 대형 라우팅 CLI(141.13초)·지속 CLI(7.12초)는 통과했고 이후 일관성 CLI 중에 중단됐다. 이후 통과한 긴 표본은 중복 실행하지 않고 나머지 모듈 431건과 마지막 CLI 조건을 분리하여 검증했다. 중간 실패·중복 실행은 최종 고유 시험 수에 더하지 않는다.

## 남은 조건과 문서 경계

실제 공개 데이터·유료 제공자의 품질·총비용과 최종 채택은 후속이다. 내용 판의 미측정 연결 수를 실제 절감량으로 주장하지 않으며, 합성 동시 쓰기의 결과를 운영 쓰기 빈도 전체로 일반화하지 않는다. 다음 작업은 EVAL-07의 지속 평가 여섯 시나리오다.

DOX pass에서 패키지·환경 변수·마이그레이션·소유 경계 변경이 없음을 확인하여 기존 DOX를 유지했다. 평가 정본·검색의 평가 전용 후보 설명·계획·서비스 색인·요청/공식 근거 기록을 함께 갱신했다. `feat/evaluation`에는 upstream이 없고 변경은 미커밋이며 개인 IDE 두 파일은 제외한다.
