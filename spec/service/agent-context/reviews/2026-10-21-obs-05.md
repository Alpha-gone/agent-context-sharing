# OBS-05 처리 지점 계측·흐름 연결 모듈 인수

- 기준: 2026-10-21, `feat/web-foundation`의 `d569ffb` 이후 작업 트리.
- 대상: [OBS-05](../development-plan/observability.md#obs-05), [진단 흐름](../sdd/observability.md#처리-지점-계측), [요구사항](../SRS.md#종류별-진단-로그).
- 판정: OBS-05 구현·모듈 인수 완료. 전체 **75/124개 완료·49개 미착수**, 다음은 OBS-06이다. 기존 색인 시험 3개 그룹의 실패를 아래에서 구분하며 전체 시험 통과를 주장하지 않는다.

## 구현과 관찰 경계

- 서버의 수신 Trace를 model 상관 context에도 전달하여 저장 시 큐에 같은 ID가 들어간다. 요청 헤더·멱등성 키를 상관 ID로 쓰지 않는다. 요청은 고정 route/method·최종 HTTP 상태·지연, 웹 세션/등급과 MCP 도구는 실제 인증·권한·dispatch/응답 경계를 기록한다. 응답 감싸기는 최초 최종 상태와 Unwrap을 유지한다. 경로·panic 원문과 스택을 운영 로그에 복제하지 않는다.
- 가입·로그인·세션 발급/검증·폐기·인가 코드/교환·Bearer·갱신의 실제 결과를 수집한다. 외부 오류 형식은 유지하면서 만료·개별/계열 폐기·유휴 만료·재사용·결합 위반·저장소 장애를 구분한다. 확인한 계열은 flow_id로 연결하고 계열이 아직 없는 코드 발급에는 식별자를 유도·추정하지 않는다. 미확인 거부의 대상 ID도 생략한다.
- 검색은 결합 전의 채널별 후보/지연/실패와 라우팅 경로/이유, 선택 전후 후보·노드·간선, 실제 문자 수·절단을 수집한다. 요청·결과 객체와 본문·질의·경로를 전달하지 않는다. 기존 코드 전용 소비자에는 최종 flow 사건만 유지하여 호출 횟수 계약을 보존했다.
- 노드·관계·그래프와 웹 등급·팀·삭제/복구는 실제 트랜잭션 결과를 전달한다. 관계 실패는 인자·행위자·권한·끝점·계층·시간·순환·쓰기·감사·커밋 위치를 구분하고 확인된 ID·필드·계층 값만 기록한다. DB 내부 장애의 원인 체인에 FieldError가 있어도 도메인 거부로 바꾸지 않는다.
- 저장점 해제는 성공 커밋으로 기록하지 않는다. 바깥 멱등성 트랜잭션 종료 뒤 committed/rolled_back/unknown을 전달하고, 커밋 응답을 확인할 수 없으면 unknown을 유지한다. 진단 수신기가 false를 반환해도 업무 결과·감사·저장 결과를 바꾸지 않는다.
- 큐 등록의 RETURNING에서 실제 task_id·DB 정밀도의 enqueued_at을 얻고 등록 종료 뒤 이벤트를 전달한다. 확보한 세대의 상관 ID·등록 시각·시도 횟수와 새 job_id를 제공자/적용/재시도에 유지한다. 제공자 HTTP 상태는 실제 응답에서 얻고 무효 확보는 stale_generation으로 기록한다. 현재 행의 새 세대·상관 ID를 과거 작업이 덮지 않는다.
- 서버·별도 색인 실행기는 한 Source와 종류별 Reporter를 조립한다. 최소 로그 수준을 적용하고, 주기 회차는 자체 job_id·고정 작업 이름·처리 수·실패/건너뜀을 기록한다. diagnostic은 업무 패키지를 import하지 않으며 소비자는 허용 필드·Trace·좁은 인터페이스만 사용한다. DB 스키마·배포 키·외부 모듈은 추가하지 않았다.

## 검증 결과

macOS/arm64, Go 1.27.1, 실제 로컬 PostgreSQL/AGE와 시험용 TLS 제공자를 사용했다. TEST_DATABASE_REQUIRED=1로 필수 DB 시험의 건너뜀을 막았다. 새 DB 시험과 기동 실패 시험은 기존 격리 생성/정리 helper를 사용한다. 원격 Gemini나 운영 배포는 호출하지 않았다.

최종 관련 범위는 **2753건 통과**했다. 이 수는 상위 Test와 하위 사례의 pass 사건을 포함하며 중복 실행은 합산하지 않았다. 선택 범위의 실패·건너뜀은 0이며 race를 적용했다.

- 실제 등록 중 새 세대가 들어오는 제공자 콜백을 사용하여 오래된 결과 미공개와 새 correlation_id 보존, 새 세대의 후속 정상 공개를 대조했다. 확보/적용 사건의 세대는 각 DB 등록 시각과 직접 비교했다.
- 관계의 실제 커밋·순환 실패 롤백, 바깥 쓰기의 커밋/롤백 전 이벤트 미전달, 진단 수락 실패 후 업무 보존을 확인했다. unknown은 응답 실패·닫힌 tx를 주입한 모듈 시험이며 실제 DB 네트워크 단절 실험은 아니다.
- 실제 JWT 만료와 공유 개별/계열 폐기, 7일 유휴·30일 절대 만료·재사용·결합·저장 장애를 검사했다. 코드 교환/갱신 재사용의 flow_id를 대조하고 자격·callback URI가 이벤트에 없는지 확인했다.
- 실제 파일에 수신/응답 두 JSON 행을 기록하여 서버 발급 상관 ID·model context·고정 route·최초 HTTP 상태와 누락 0을 확인했다. 원문 URI·질의·본문·자격 표본은 구조화 이벤트에 남지 않았다. 여섯 종류 전체의 배포 파일 통합 인수는 OBS-08에서 별도로 수행한다.
- check-go.sh의 의존 확인/빌드·전체 go build·go vet·gofmt와 diff 공백 검사를 수행했다. Linux와 실제 호스트·운영 로그 볼륨 인수는 이번에 실행하지 않았다.

최초 모듈 실행에서 검색의 기존 코드 전용 소비자 호출 횟수가 바뀐 회귀를 발견해 최종 flow만 전달하도록 복원했다. 새 인증 시험의 switch 안 오류 변수 가림과 기존 기동 시험의 누락된 진단/OAuth 구성도 수정했다. 기동 시험을 전용 DB로 격리한 뒤 관련 모듈을 재실행했다.

## 기존 시험 실패의 대조

최초 확대 실행에서는 기존 색인 준비·배치 시험도 실패했다. 현재 변경과 구분하기 위해 `git archive d569ffb`를 임시 디렉터리에 풀어 같은 Go·DB 환경에서 다음 세 그룹만 실행했다. **세 그룹 모두 같은 실패를 재현했으며 상위/하위 사례 포함 16개 fail 사건**이 발생했다.

- TestIndexReadinessProviderAcceptanceIntegration: 준비 자료 생성에서 실제 계정이 없어 `대상을 찾지 못했다`로 종료한다.
- TestIndexReadinessDelayAndCancellationIntegration: 같은 준비 자료 생성 오류다.
- TestIndexWorkerPlacementsIntegration: 정식 마이그레이션 6개에 대해 과거 5개 기대값을 사용한다.

이 파일들의 기존 실패를 수정하거나 성공으로 처리하지 않았다. 최종 index·cmd/server 실행에서는 해당 이름을 -skip으로 제외했다. 위 관련 모듈 통과 수는 이 제외를 전제로 한다. 전체 색인/배치 인수 때 준비 자료·마이그레이션 기대값을 보완해야 한다.

```sh
# 공통: GOTOOLCHAIN=local, GOCACHE=/private/tmp/acs-obs02-go-cache,
# Go=/Users/alphagone/sdk/go1.27.1/bin/go, TEST_DATABASE_REQUIRED=1
# .env의 TEST_DATABASE_URL은 실행 환경으로만 전달하며 값은 기록하지 않는다.
go test -race -json -count=1 -p=1 -timeout=180s ./internal/authz ./internal/mcp ./internal/diagnostic ./internal/search ./internal/web ./cmd/indexer
go test -race -json -count=1 -p=1 -timeout=180s ./internal/index -skip '^(TestIndexReadinessProviderAcceptanceIntegration|TestIndexReadinessDelayAndCancellationIntegration)$'
go test -race -json -count=1 -p=1 -timeout=180s ./cmd/server -skip '^TestIndexWorkerPlacementsIntegration$'
go test -race -json -count=1 -p=1 -timeout=180s ./internal/store -run '^(TestOBS05|TestMCP05|TestIndexClaim|TestIndexRegistration|TestNodeCreation|TestLifeNode|TestGrant|TestTeam|TestGraphGrantsAndDeletionImpact|TestContextDeletionAndRestore)'
go test -race -json -count=1 ./internal/store ./internal/mcp -run '^TestOBS05(StorageFailure|UncertainCommit|MCP)'
```

## 문서·소유권·남은 조건

아키텍처는 소비자의 diagnostic 값·인터페이스 의존을, 관측성 SDD는 실제 계측·흐름·트랜잭션 경계와 제한을, 계획은 완료 증거·다음 항목을 소유하도록 유지했다. 기존 internal·cmd DOX의 책임과 디렉터리 경계는 유지되어 새 DOX나 Child Index를 만들지 않았다. 적용 정본과 허용 import를 양방향 검사했다. 변경 Markdown 10개·상대 링크/앵커 362개·코드 블록·공백과 계획의 75개 완료/49개 미착수를 확인했다.

OBS-06의 감사 통합 조회·보존 예외·복구 대기, OBS-07의 stderr·부분 쓰기·5초 종료와 잔여 누락, OBS-08의 영속 볼륨·여섯 실제 파일·배포 통합 인수는 대기다. 현재 Close 호출의 5초 대기는 OBS-07의 잔여 폐기/보고 정책을 대신하지 않는다. MCP·검색의 전면 기동 조립과 호스트 지원도 ARCH-06·07/MCP-09 등의 별도 인수다.

upstream이 없어 원격 뒤처짐을 확인하지 못했다. 기존 Compose·IDE 변경은 보존했고 commit·push·PR·배포는 수행하지 않았다.
