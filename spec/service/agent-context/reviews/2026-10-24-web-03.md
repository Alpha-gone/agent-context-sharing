## 변경

조회에 전달하는 등급과 다음 페이지 주소를 소유자·편집자·열람자의 중복 없는 선택 집합으로 정규화했다. 빈 값은 모든 등급의 기존 의미를 유지하며 체크박스·이름 재제출·더 보기와 같은 집합을 사용한다. 잘못된 커서는 저장 장애와 구분한 400과 유효 필터 양식을 제공하고 이전 커서 없이 다시 적용할 수 있게 했다. 활성·자동 삭제·직접 삭제 목록의 각 조회 뒤에 취소를 확인하여 남은 조회·렌더링을 멈춘다.

이름은 기본 `search` 입력·검색 키 힌트·자동 교정 비활성화를 적용했다. GET 필터와 POST 복구 요청, 레이블·fieldset/legend·선택 없음 안내를 유지했다. 저장소의 현재 권한·복구 자격 판정과 감사 트랜잭션을 재사용하며 API·SQL·환경 키는 바꾸지 않았다.

## 실행 증거

- Go 1.27.1 darwin/arm64·Modern Go CLI 대상 버전 목록 전체를 확인했다. Modern Web Guidance의 `forms`를 조회했고 GET 조회/POST 변경·기본 다중 체크박스·검색 입력 교정 규칙을 적용했다. 범용 지침의 추가 CSRF 토큰·AJAX 예제로 저장소의 CrossOriginProtection·서버 렌더링 계약을 변경하지 않았다.
- **신규 12건 포함 웹 642건 통과**, 최상위 70개·하위 572개, `-race -count=1`·필수 DB 설정. 최종 고유 시험 결과의 실패·건너뜀 0이며 race가 없다. Node.js 기반 기존 시각화·키보드 상태 시험도 실행했다. 전체 서버·전체 웹·실제 브라우저 인수와 구분한다.
- 신규 단위 표본은 계정 플랜 기본 페이지 2개·중복/빈/역순 등급 정규화, 커서 오류의 400·안전한 원문 제외·유효 필터 보존, 세 조회 지점의 저장 장애/취소·후속 조회 중단을 대조했다. 기존 필터 시험에서 모든/단일/복수 등급 표시·선택 해제·새 제출의 커서 제거·이름과 다음 커서 유지를 새로 실행했다.
- 새 전용 DB에 정식 SQL을 적용하고 실제 TLS·서명 세션으로 두 페이지의 최근 활동/동률 ID 순서·마지막 페이지의 더 보기 없음·특수문자 `%_+`의 이름 부분 일치·직접/팀 상속 최고 등급 필터를 확인했다. 페이지 사이 열람자 권한을 회수한 뒤 같은 다음 커서 요청에서 대상이 제외됐다.
- 생성자·과거 직접 소유자의 자동 삭제 그래프는 복구 요청 진입에 표시하고, 과거 열람자·다른 계정의 그래프 이름/ID는 표시하지 않았다. 직접 삭제 그래프는 별도 삭제/복구 링크만 표시했다. TLS POST로 두 자격 대상의 요청·세션 계정·감사 대기 2건을 대조하고 자격 없는 자동 삭제/직접 삭제 요청은 404로 거부했다.
- 첫 새 통합 시험에서 직접 삭제 요청의 기대값을 409로 적어 실패했다. 저장소가 자동 삭제/과거 소유자 조건에 맞지 않는 대상을 `ErrNotFound`로 숨기는 계약을 확인한 뒤 기대값만 404로 고쳤다. 해당 최상위 시험과 두 하위 사례를 새 격리 DB에서 재실행하여 통과했다. 전체 실행의 나머지 결과와 이 최종 결과를 이름별로 합쳐 **642개**이며 중복 합산하지 않았다.
- `check-go.sh`의 의존성 확인·빌드·vet·gofmt가 통과했다. Markdown 링크·앵커·계획 수·DOX 경계를 확인했다. 구현은 기존 웹 DOX 소유 안에 있어 DOX·부모 색인은 유지했다. 웹 SDD·진행 계획·진입점·서비스 색인·공식 근거·요청 기록을 정합화했고 SRS·용어집·마이그레이션·환경 예시는 계약 변경이 없어 보존했다.

## 남은 범위

WEB-04~09의 나머지 화면·전체 웹 분야 통합, 실제 브라우저 제출/키보드/보조 기술·외부 호스트·Tunnel·운영 배포는 미실행이다. 이번 표본은 웹 모듈의 실제 DB/TLS 인수이며 서버 전송 보안·전체 운영 장애 인수를 대신하지 않는다. 브랜치 upstream이 없어 원격 차이는 확인하지 않았으며 커밋·푸시·배포는 수행하지 않았다.
