# #174 후속: 조회 총 예산과 가상 시간 회귀

- 대상: 사용자가 요청한 [#174](https://github.com/Alpha-gone/agent-context-sharing/issues/174) 후속 개선. 원래 [검토](2026-10-31-issue-174.md)의 당시 검증 기록은 보존한다.
- 기준: `dev`의 `5d40300`, 브랜치 `fix/174-cache-lookup-budget`.

## 변경과 결정

공개 키와 웹 폐기 목록의 캐시 미스마다 대기·재시도·적재에 공통으로 사용하는 5초 예산을 한 번 생성한다. 취소된 적재를 기다린 뒤 자신이 적재자가 되어도 타이머를 새로 시작하지 않는다. 부모 요청의 더 이른 마감은 유지하고, 정상 키·폐기 목록·정상 부재의 캐시 적중에는 타이머를 만들지 않는다. 별도 비동기 적재 goroutine·요청과 분리된 context·배포 설정을 추가하지 않았다.

두 조회가 사용하는 적재 결과 값에 저장소 반환 시점의 오류와 재시도 분류를 함께 보존한다. 결과 공개 직전에는 성공 결과만 취소로 무효화하고 기존 저장소 오류는 늦은 취소로 재분류하지 않는다. 마감 시각이 지났지만 타이머의 Done 통지가 아직 실행되지 않은 경우도 새 재시도를 막는다. TTL·키 회전·로컬 폐기 세대 검사는 유지한다.

예산은 각 캐시 미스에 별도로 적용한다. JWT 검증 전체의 무조건적인 5초 완료나 비협조적인 저장소·장시간 mutex 보유를 강제 중단한다고 주장하지 않는다. 전달된 context를 저장소가 준수해야 하며, 예산이 남은 다른 요청은 적재자의 취소·예산 소진 뒤에도 재조회할 수 있다.

[인증 정본](../sdd/authentication.md#토큰-검증)·[시험 설계](../sdd/testing.md#테스트-계층)·[SDK 근거](../reference.md#2026-10-31-174-후속-조회-예산과-가상-시간)를 정합화했다. DOX pass에서 소유권·경로·구성 경계 변경이 없어 기존 DOX를 유지했다. 스키마·환경 예시·공개 API는 변경하지 않는다.

## 재현과 검증

- 기존 코드의 가상 시간 표본에서 취소된 두 적재를 각각 2초씩 기다린 뒤, 새 적재가 다시 5초를 받아 총 9초 대기하는 것을 키·폐기 목록 모두 재현했다. 수정 후 남은 저장소 예산은 1초, 총 대기는 5초다. 앞선 두 취소는 완료된 cacheLoad 결과로 재현하며 실제 요청 취소의 단일 적재 전이는 기존 서명 JWT 병행 시험을 유지한다. `/tmp/acs174-budget-red.json`에 결과를 보관한다.
- 기존 취소·마감·상한 15건을 각각 synctest bubble로 전환했다. 새 시험은 연속 취소의 총 예산, 완료/취소가 모두 준비된 대기, 저장소 오류 공개 후 취소, 오류 결과 확정과 공개 사이의 취소, 성공 결과의 늦은 취소와 타이머 통지 전 경과한 마감을 검증한다. 저장소 오류 분류 값의 경계는 단위 시험으로 직접 구성하며 실제 mutex 대기의 스케줄러 순서를 추측하지 않는다.
- 예비 20회 반복에서 같은 마감 시각의 타이머 콜백 순서 때문에 기존 상한 표본의 추가 읽기·성공이 간헐적으로 발생했다. ctx.Err뿐 아니라 절대 마감도 확인하도록 보완했다. 최종 관련 24건을 race로 50회 반복한 총 1,200건이 실패·건너뜀 없이 통과했다. 결과는 `/tmp/acs174-budget-repeat-final.json`에 보관한다.
- Go 1.27.1과 고정 PostgreSQL/AGE 이미지 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`의 전용 합성 컨테이너에 정식 7개 마이그레이션을 적용했다. `TEST_DATABASE_REQUIRED=1 go test -race -p 1 -json ./internal/authz ./internal/web ./internal/mcp -count=1 -timeout=10m`에서 최종 인증 전체 505건·웹 814건·MCP 480건이 실패·건너뜀 없이 통과했다. 결과는 `/tmp/acs174-budget-modules-final.json`이다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check`와 변경 문서 5개의 로컬 링크·앵커 152개를 확인했다.
- 시험 종료 후 기본 시험 DB·postgres 외 임시 DB가 없고 idle transaction이 0임을 확인했다. 소유 컨테이너·연결 익명 볼륨만 정리한 뒤 잔류가 없음을 확인했으며 기존 개발·다른 시험 자원과 개인 IDE 파일은 유지했다.

독립 읽기 전용 검토에서 오류 분류의 기존 시험이 공개 완료 후 취소만 검증한다는 지적을 받아 공유 적재 결과 값과 정밀 단위 시험을 보강했다. 재검토에서 검증 공백이 해소됐고 예산·타이머 해제·적중 경로·세대 검사·마감 통지 경계의 추가 결함은 발견되지 않았다. 검토자는 DB·시험을 별도로 실행하지 않았다. 실제 브라우저 연결 단절·운영 지연·비밀번호 부하의 추가 인수로 확대하지 않는다.
