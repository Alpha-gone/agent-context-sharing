# #146 색인 결과 저장·노드 쓰기 잠금 순서

- 기준: 2026-10-29 KST, `dev`의 `065006c`에서 분기한 `fix/146-index-lock-order`.
- 대상: [이슈 #146](https://github.com/Alpha-gone/agent-context-sharing/issues/146), [판정의 직렬화](../sdd/context-lifecycle.md#판정의-직렬화), [색인 작업 큐](../sdd/indexing.md#색인-작업-큐).

## 재현과 원인

별도 PostgreSQL 18·AGE 1.8.0·pgvector 0.8.6 컨테이너에 정식 마이그레이션을 적용했다. 신규 시험은 그 안에서 다시 시험별 독립 DB를 만들고 종료 시 삭제한다. 기존 개발 DB·WAL·OAuth 시험 컨테이너는 사용하거나 변경하지 않는다.

[경합 회귀 시험](../../../../internal/store/index_lock_order_integration_test.go)은 실제 작업을 확보한 뒤 바깥 트랜잭션으로 그래프 행을 잠근다. 별도 연결의 결과 저장이 그 연결을 기다리는 것을 `pg_blocking_pids`로 확인하고, 바깥 트랜잭션에서 노드 갱신 또는 복구를 실행한다. 시간 지연만으로 실행 순서를 추정하지 않는다.

수정 전 사건·파생 갱신과 원천·파생·사건 복구의 다섯 사례 모두 실패했다. 시험 DB 로그에서 `deadlock detected`와 그래프 내용 판 UPDATE ↔ 작업 등록 upsert의 순환 대기를 직접 확인했다. 작업자가 작업 행을 가진 채 그래프를 기다리고, 노드 쓰기가 그래프를 가진 채 작업 행을 기다렸다. 재색인 선행 잠금 시험도 그래프 잠금 해제 전에 재색인이 완료되어 실패했다.

## 수정

- 공통 잠금 순서의 정본은 수명주기의 「판정의 직렬화」로 두고 색인 SDD에서 참조한다. 기존 참조 전이 자문 잠금·빈도 행의 선행 순서와 그래프→AGE/정점 순서를 유지한다.
- `storeIndexResult`는 그래프를 먼저 잠근 뒤 기존 세대 조건부 작업 삭제·임베딩 교체·내용 판 증가를 수행한다. 대기 뒤 재등록된 작업의 이전 확보분은 거부한다.
- `ReindexGraph`는 대상 목록 조회 전에 그래프를 잠근다. 작업 등록과 제외 작업/임베딩 삭제가 같은 그래프의 노드 쓰기·결과 저장과 직렬화된다.
- 사건·파생 갱신과 모든 계층의 복구는 이미 그래프를 먼저 잠그므로 해당 구현은 보존했다. 확보·실패 기록은 그래프를 추가로 잠그지 않으며 제공자 호출은 트랜잭션 밖에 유지한다.
- 스키마·리스·재시도 정책은 변경하지 않았다. 공식 잠금·저장점 근거는 [reference.md](../reference.md#2026-10-29-146-색인-잠금-순서)에 연결한다.

## 검증

Go 1.27.1에서 `TEST_DATABASE_REQUIRED=1`과 시험 전용 `TEST_DATABASE_URL`을 사용했다.

```sh
go test -race -count=1 -run 'Test(IndexResultSerializesWithContextWrites|ReindexLocksGraphBeforeTasks)Integration' ./internal/store
go test -race -count=1 -json -timeout=15m ./internal/store
go build ./...
go vet ./...
gofmt -l .
```

신규 경합 여섯 사례는 수정 후 3.365초에 통과했다. 다섯 노드 쓰기 사례에서 재등록 뒤 이전 확보분의 미저장, 임베딩 0건·새 작업 1건과 노드 쓰기만의 내용 판 증가를 대조하고, 새 작업을 실제 처리하여 완료와 큐 제거를 확인했다. 재색인 사례는 그래프 대기 중 작업 행을 선점하지 않는 것을 `FOR UPDATE NOWAIT`로 확인했다.

필터 없는 전체 `store` 패키지는 417.389초에 **1,676건(최상위 374건)**이 실패·건너뜀 없이 통과했다. 기존 색인 확보·리스·재등록·실패 롤백·재색인과 수명주기·경합·불변식·검색 회귀를 포함한다. build·vet·gofmt 검사와 새 문서 링크/앵커 검증도 통과했다. 시험별 격리 DB 잔류 0개를 확인한 뒤 이번에 생성한 컨테이너와 익명 볼륨만 제거했고 기존 세 컨테이너는 보존했다.

독립 읽기 전용 검토에서 Critical·Important·Minor 발견 사항은 없었다. DOX의 소유권·구조·작업 경계가 바뀌지 않아 기존 계약과 색인을 유지한다. 이슈 #146의 잠금 순서·구현·경합 검증 완료 조건을 충족한다.

운영 배포·실제 외부 제공자·검색 품질·성능 인수로 결과를 확대하지 않는다.
