# 질의 적응형 검색 통제 비교

## 목적과 통제 조건

- 측정일: 2026-09-27
- 목적: `FR-AGENT_CONTEXT-151`의 규칙 기반 라우터를 기존 `scope=auto` 전환 규칙과 통제 비교해 `SEARCH_QUERY_ADAPTIVE_ROUTING_ENABLED`의 운영 기본값을 판정한다.
- 비교 구성: 기존 `auto`와 적응형 라우팅. 두 구성 모두 `SEARCH_GRAPH_STAGE=relations`, 근거 경로 보존 선택 비활성이다. 적응형 라우팅은 `baseline`과 함께 쓸 수 없으므로 확정 참조와 사건 관계를 모두 켠 가장 작은 단계를 골랐다. 근거 경로 보존 선택은 [12단계 판정](2026-09-27-evidence-path-selection.md)의 운영값을 따랐다.
- 공통 조건: 문자 예산 4,000, 채널별 후보 상한 50, 최대 4홉, 홉 노드 상한 200, 의미 유사도 하한 0.50, 원천 포함 색인, 구성마다 3회 반복
- 오프라인 최적 경로: 같은 질의에 직접·국소 확장·전역 진입을 강제로 실행해 품질, 문자 수, 지연 순으로 고른다. 사실 검색은 재현율·순위 품질, 연상 검색과 전역 요약은 근거 완전성·경로 연속성을 품질로 쓰고, 기대 근거가 없는 질의는 사실 검색과 같은 품질을 쓴다. 전역 요약이 없어 직접 경로로 되돌아간 강제 전역 실행은 후보에서 뺀다.
- 임계값: 직접 충분성 하한 `0.5, 0.6, 0.7, 0.8`과 분리 폭 `0, 0.02, 0.05, 0.1`의 16개 조합을 강제 실행 결과와 라우터 신호로 오프라인에서 견줬다. 모든 사용 사례의 품질 평균이 기존 `auto` 이상인 조합 중 오선택률이 가장 낮은 것을 골라 적응형 구성을 실제로 3회 실행했다.
- 판정: 같은 질의의 반복 평균을 두 구성 사이에 대응시키고 차이의 95% 신뢰구간이 0을 포함하지 않을 때 유의한 차이로 본다.

```shell
go run ./cmd/eval -adaptive -contexts <컨텍스트 집합>.json -queries <질의 집합>.json \
  -repeat 3 -budget 4000 -max-hops 4 -max-hop-nodes 200 -out <결과>.json
```

## 데이터셋

[근거 경로 보존 선택 통제 비교](2026-09-27-evidence-path-selection.md)와 같은 세 세트를 썼다. 사건 세트와 MuSiQue 세트의 질의는 모두 `auto`이고 자동 전역 세트는 `auto` 판이다.

## 결과

| 세트·사용 사례 | 오프라인 최적 경로 | 기존 `auto` 경로 | 적응형 경로와 이유 | 품질 | 지연 차이 | 오선택률 |
|------|------|------|------|------|------|------|
| 사건 사실 | 직접 12, 국소 13 | 국소 25 | 모든 조합에서 직접 25, `cross_channel_agreement` 25 | 같음 | 실행하지 않음 | 0.48 → 0.52 (격자) |
| 사건 연상 | 직접 13, 국소 12 | 국소 25 | 모든 조합에서 직접 25, `cross_channel_agreement` 25 | 근거 완전성 0.360 → 0.347, 경로 연속성 1.0 → 0 | 실행하지 않음 | 0.52 → 0.48 (격자) |

| MuSiQue 연상 | 직접 47, 국소 3 | 국소 50 | 직접 42, 국소 8 | 같음 | `-20.2 ± 2.3ms` 유의 | 0.940 → 0.180 유의 |

사건 세트에서는 16개 조합 모두 품질 비악화를 지키지 못해 적응형 구성을 실행하지 않았다. 사건 세트의 질의는 마무리 사건의 완료 표식을 담아 의미 유사도와 키워드가 같은 마무리 사건을 1위로 올리므로 모든 질의가 2번 규칙 `cross_channel_agreement`로 직접 경로를 탄다. 직접 경로는 그래프를 확장하지 않아 정답 사건과 마무리 사건을 잇는 `precedes`를 응답에 싣지 못한다. 그래서 근거 완전성이 낮아지고, 정답 사건이 반환된 한 질의의 경로도 끊긴다. 임계값은 3번 규칙에만 쓰이므로 이 실패를 바꿀 수 없다.

MuSiQue는 원천만 있어 국소 확장이 더할 관계가 없고, 기존 `auto`가 모든 질의에서 실행한 확장은 지연만 늘렸다. 적응형은 같은 품질로 지연을 약 13~15% 줄이고 오선택률을 크게 낮췄다. 자동 전역 세트는 두 구성이 같은 경로를 골랐고 지연 차이는 2ms 남짓이다.

고른 임계값은 자동 전역 세트가 `0.6 / 0.02`, MuSiQue가 `0.5 / 0`이었다. 자동 전역 세트는 모든 조합의 경로가 같아 지연 잡음이 고른 값이므로 의미가 없다.

## 판정

- `SEARCH_QUERY_ADAPTIVE_ROUTING_ENABLED=false`를 운영 기본값으로 유지한다. 승격 조건인 사용 사례별 품질 비악화를 사건 세트의 연상 검색이 어느 임계값에서도 지키지 못했다.
- 직접 충분성 하한과 분리 폭은 운영 구성에 정하지 않는다. 라우터를 켜지 않으므로 값이 쓰이지 않고, 세트마다 고른 값이 달라 하나로 정할 근거도 없다.
- 실패 원인은 임계값이 아니라 2번 규칙이다. 두 채널이 같은 컨텍스트를 1위로 올려도 그 컨텍스트에서 관계를 따라가야 정답에 닿는 연상 질의가 있다. 규칙을 바꾸려면 `SRS.md`의 「질의 적응형 검색 정책」을 먼저 고쳐야 하므로 이 단계에서 바꾸지 않았다.

## 한계와 후속 확인

- 비교 기준인 기존 `auto`는 `relations` 단계다. 현재 운영 구성은 `baseline`과 자동 전역 전환이므로 이미 관련 국소 후보가 있으면 직접 경로와 같게 동작한다. MuSiQue에서 본 지연·오선택 개선은 운영 구성 대비 개선이 아니다.
- 오프라인 최적 경로는 품질과 문자 수가 같으면 지연으로 정한다. MuSiQue의 국소 확장은 결과가 직접 경로와 같은데도 지연 잡음으로 최적이 된 질의가 사실 5건, 연상 3건 있었다. 이 몫만큼 두 구성의 오선택률이 부풀었다.
- 사건 세트의 연상 재현율은 0.040으로 이전 측정과 같다. 경로 연속성은 정답 사건이 반환된 한 질의에서만 정의되어 대응 비교가 성립하지 않았다.
- 2번 규칙이 관계 확장이 필요한 연상 질의를 가려내도록 고칠지는 이 문서의 범위 밖이며, 고친다면 요구사항 수준의 변경으로 따로 판단해야 한다.

## 규칙 개정 뒤 재비교

첫 비교의 실패 원인을 고친 정책으로 같은 조건에서 다시 비교했다. 바꾼 것은 셋이다.

- 통합 순위 1위가 사건이면 직접 경로 규칙보다 먼저 국소 확장을 고르는 `event_anchor` 규칙을 SRS·SDD·라우터에 더했다.
- 오프라인 최적 경로의 지연 차이는 반복 측정의 95% 신뢰구간이 겹치지 않을 때만 인정하고, 겹치면 직접, 국소 확장, 전역 진입 순으로 고르게 했다.
- 평가 실행기가 구성의 실행 순서를 회차마다 돌리고, 판정용 기존 `auto`를 적응형과 같은 회차에서 다시 재게 했다.

| 세트·사용 사례 | 오프라인 최적 경로 | 적응형 경로와 이유 | 품질 | 지연 차이 | 오선택률 |
|------|------|------|------|------|------|
| 사건 사실 | 직접 12, 국소 13 | 직접 25, `cross_channel_agreement` | 같음 | 실행하지 않음 | 격자 계산만 함 |
| 사건 연상 | 직접 13, 국소 12 | 국소 25, `event_anchor` | 근거 완전성 0.360 → 0.347, 경로 연속성 1 → 0 | 실행하지 않음 | 격자 계산만 함 |
| 자동 전역 | 전역 50 | 전역 50, `no_relevant_local` | 같음 | `-0.66 ± 0.74ms` 유의하지 않음 | 0 → 0 |
| MuSiQue 사실 | 직접 56 | 직접 55, 국소 1 | 같음 | `-5.87 ± 0.72ms` 유의 | 1.000 → 0.018 유의 |
| MuSiQue 연상 | 직접 50 | 직접 42, 국소 8 | 같음 | `-5.35 ± 1.12ms` 유의 | 1.000 → 0.160 유의 |

새 규칙은 의도대로 동작했다. 사건 세트의 연상 질의 25개가 모두 국소 확장을 탔다. 지연 동률 보정으로 MuSiQue의 오프라인 최적 경로는 모두 직접 경로가 되어, 첫 비교에서 잡음으로 국소 확장이 최적이 되던 질의 8개가 사라졌다.

그래도 사건 세트는 16개 임계값 조합 모두 품질 유지 조건을 넘지 못했다. 차이는 질의 25개 중 `own-a-0049` 하나에서만 났다. 기존 `auto`는 모든 진입 후보에서 4홉까지 확장해 정답 사건, 마무리 사건과 둘을 잇는 `precedes`를 모두 싣는다. 강제 국소 확장은 관련 후보에서 1홉만 확장한다. 두 사건은 시간 필터로 응답에 들어오지만, 홉 노드 상한 200이 `has_member` 이웃으로 먼저 차서 `precedes` 간선이 결과에 남지 않는다. 경로를 어떻게 고르든 같은 결과이므로 라우팅 규칙으로는 고칠 수 없다.

판정은 `SEARCH_QUERY_ADAPTIVE_ROUTING_ENABLED=false` 유지다. 다음 두 가지는 따로 판단해야 한다.

- 임계값 선택 규칙의 "품질 유지"는 평균이 기준 이상인 것으로 구현했다. 운영 승격 조건은 "유의하게 나빠지지 않음"이다. 질의 하나의 차이는 유의하지 않으므로 해석을 승격 조건과 맞추면 결과가 달라질 수 있다. 이는 `SRS.md`의 해석을 정하는 일이라 이번에 바꾸지 않았다.
- 적응형 라우팅은 `SEARCH_GRAPH_STAGE=baseline`과 함께 쓸 수 없다. 비교 기준인 기존 `auto`는 `relations` 단계인데, 현재 운영 구성은 `baseline`과 자동 전역 전환이라 이미 직접 경로처럼 동작한다. 승격하려면 운영 그래프 단계도 함께 바꿔야 하며, 그 비교는 이번 범위 밖이다.
