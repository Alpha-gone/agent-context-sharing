# EVAL-09 검색 단위 완전성 비교 모듈 인수

## 범위와 판정

[EVAL-09](../development-plan/evaluation.md#eval-09)·[FR-160 검색 단위 비교](../SRS.md#검색-단위-비교)의 두 에이전트 파생 경계 정책, 필수 의미 요소·실제 근거, 검색 품질·준비량·외부 과업 trace 집계를 인수했다. [실행 계약](../sdd/evaluation.md#검색-단위-비교의-실행-입력과-결과)과 [시험 설계](../sdd/testing.md#검색-단위-완전성-비교-시험)를 대조했다. 과거 자체 세트의 측정을 이번 완료 근거로 승계하지 않는다.

`-unit-comparison`의 구현·모듈 인수는 완료했다. 공개 데이터에 대한 실제 경계 생성·자동 판정기 호출·사람 검토·에이전트 업무 효과를 실행한 결과는 아니다. 이번 실행은 합성 의미 판정·과업 trace와 고정 벡터 HTTPS 대역을 사용했다. 통제 비교 후보와 운영 기본값 승격을 구분하며 실제 최종 채택은 EVAL-13의 후속 범위다.

## 구현과 경계

- 표본 하나에 원천 집합·공유 질의·조회 시각·필수 의미 요소를 고정하고 `current`·`semantic` 조건의 파생과 대응 정답만 바꾼다. 생성 에이전트·프롬프트 계열·검색 설정과 경계 외 파생 속성을 고정한다. 대화와 코드/문서 표본은 별도로 적재·집계하며 같은 과업의 질의는 표본 하나로 묶는다.
- 주체·조건·예외·부정·선행 참조·다중 턴 결정의 요소 명세와 원천 근거를 검토 입력에 포함한다. 모든 파생의 필요한/보존한 요소·사람 검토와 입력 SHA-256을 연결하고, 원천·파생·요소·판정기 판이 달라지면 stale 검토를 거부한다. 요소 전체 범위를 검토하지 않거나 경계 외 속성이 바뀐 입력도 거부한다.
- 완전성은 필요한 의미 요소와 해당 원천 `derived_from`을 모두 보존한 파생의 비율이다. 사람 판정이 있으면 우선하고 자동 판정과 불일치 수를 남긴다. 검토 기록에는 판·코드·해시만 포함하며 요소 설명·본문·질의·locator는 보고서에서 제외한다. 원천과 파생만 그래프에 적재하며 판정·정답 주석을 임베딩하지 않는다.
- 과업 trace의 회차 1~10·입력 해시·trace 판을 검사한다. 과업 성공과 총비용은 외부 실행 기록에서 가져온 값이며 검색 정답 반환을 성공으로 대체하지 않는다. 생성 에이전트·원천·질의·파생·경계·검색 설정·정답 매핑과 표본 코드를 해시에 연결한다. 미측정 성공/비용은 `-1`이며 한 회차의 미측정을 반복 평균으로 숨기지 않는다.
- 조건·표본·회차마다 새 그래프에서 색인을 준비하고 실제 준비 시간·문서 임베딩 HTTP 시도·벡터 행/열 바이트를 측정한다. 같은 회차 안에서 조건 순서를 바꿔 순환한다. 부분 채널 실패·취소·정리 실패를 정상 보고서로 기록하지 않는다. 서버 자동 요약·AST 분할·원천 수정은 추가하지 않았다.

## 실제 CLI와 집계

대화 한 표본과 코드/문서 한 표본에 원천 두 개·여섯 의미 요소·질의 두 개를 각각 구성했다. 현행 조건의 파생 둘과 의미 완결 조건의 파생 하나를 조건별 10회 실행했다. 총 **40개 독립 그래프**와 **220회 HTTP 호출**을 대조했고, 성공 실행의 그래프 40개가 모두 삭제 상태인 것과 원천 본문 **80개**가 입력과 동일한 것을 직접 조회했다. 각 그래프의 벡터 행과 문서 HTTP 시도는 현행 4·의미 완결 3이며, 벡터 열 바이트도 의미 완결 조건에서 줄었다. 질의 두 개의 검색 결과도 매회 측정했다.

합성 검토에서 현행 파생의 단위 완전성은 0, 의미 완결 조건은 1이다. 같은 실행의 검색 재현율·반환 근거 완전성은 두 조건 모두 1이어서 두 완전성 지표가 같지 않음을 확인했다. 과업 성공 1과 비용 10/5는 입력한 합성 trace 값이며 이번 CLI의 실측 업무 효과·비용으로 주장하지 않는다. 표본군별 독립 단위는 하나여서 구간은 `-1`이고 판정은 보류다.

여러 질의·10회 반복을 독립 표본으로 세지 않는다. 별도 순수 집계 시험은 표본군별 두 과업과 각 두 질의·10회를 사용해 독립 단위가 2인 것을 대조했다. 고유 파생 총계와 과업별 완전성 평균의 분모를 구분하고, 대응 차이·95% 구간은 독립 과업별 반복 평균에서 구한다. 사람 검토 부재/불일치·부분 근거 주석·미측정 성공/비용·표본 부족은 보류하고 의미/검색 품질의 유의한 악화나 성공률 하락은 거부한다. 실제 trace와 모든 조건을 충족하는 합성 집계에서는 후보만 표시하며 `default_activation`은 false다.

실제 CLI의 모드/직접 입력 충돌·예산 flag·반복 9회 사전 거부, 질의 임베딩 장애 뒤 그래프 정리와 보고서 차단, 삭제 거부 trigger의 정리 오류 전파를 확인했다. 새 모드의 실제 종료 신호 시험은 최종 전체 명령에서 실행·통과한 것을 확인했다.

## 실행 결과와 남은 조건

최종 평가 패키지 전체의 단일 명령은 고유 **554건**(최상위 **156건**, 하위 사례 포함)을 실패·건너뜀 없이 **201.863초**에 통과했다. 기존 509건에 추가한 45건을 포함하며 중복 실행은 합산하지 않는다. 기존 **240초** 제한을 유지했고 실제 새 CLI 시험은 **6.28초**, 새 모드 신호 취소는 **0.14초**였다.

- Go 1.27.1, 직접 생성한 `acs-eval09-db`의 새 `eval09_verified` DB에서 PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6, vector 768·정식 마이그레이션 6개를 사용했다.
- `TEST_DATABASE_URL`·`TEST_DATABASE_REQUIRED=1`과 `go test -race -count=1 -json -timeout=240s ./cmd/eval`을 사용했다. 최종 범위를 `-run`·`-skip`으로 줄이지 않았다.
- `GO_BINARY=/Users/alphagone/sdk/go1.27.1/bin/go sh check-go.sh`의 의존성 확인·전체 build·vet·gofmt가 통과했다. 최초 샌드박스 모듈 명령은 Go 캐시 접근 거부로 준비 단계에서 실패했으며 통과로 세지 않았다. 개발 환경 실행 권한으로 복구한 후 모듈·최종 전체 검증을 완료했다.

시험 뒤 두 합성 DB의 잔여 클라이언트 연결 0개를 확인하고 직접 만든 컨테이너·익명 볼륨만 정리했다. 기존 개발 컨테이너 두 개는 보존했다. DOX pass에서 패키지·마이그레이션·환경 변수·소유 경계가 바뀌지 않아 기존 DOX를 유지했다. 평가·시험 정본은 실행/시험 계약을, 계획·진입점·서비스 색인은 완료 상태를, 공식 근거·요청 기록은 검증 출처와 이번 결과를 유지하기 위해 갱신했다.

전체 계획은 **112개 완료·1개 진행·11개 미착수**이며 다음은 EVAL-10 외부 원본 재현성 비교다. `feat/evaluation`에는 upstream이 없어 원격 대비 상태를 확인하지 못했다. 변경은 미커밋이며 개인 `.idea` 파일 두 개는 제외한다. 실제 에이전트 경계 생성·자동 판정/사람 검토·공개 품질/총비용과 최종 채택은 후속이다.
