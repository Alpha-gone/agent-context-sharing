# 클라이언트 독립 진단

## 목적

- MCP 도구와 분리된 순차 진단과 사람 읽기·JSON 출력을 소유한다.

## 소유권

- 상위 `client/AGENTS.md`와 클라이언트 SDD가 모듈·진단 계약을 소유한다.
- 구성·인증·원격 계약은 각 패키지의 검증 경계를 재사용한다.

## 로컬 계약

- SDD의 여덟 검사를 순서대로 수행한다. 실패에 종속된 후속 검사는 실행하지 않고 `skipped`로 기록한다.
- 도메인 도구를 읽거나 쓰지 않으며 `serve`의 stdin을 사용하거나 도구로 등록되지 않는다.
- 네트워크·메타데이터·원격 계약은 요청 제한 시간, 브라우저·인가는 인증 제한 시간을 적용한다. 상위 취소가 우선한다.
- DNS·TLS 검사는 원격 HTTP transport의 프록시 경로·TLS 검증을 재사용한다. 자격 증명 없는 `HEAD`만 보내고 리디렉션을 따라가거나 JSON-RPC를 호출하지 않는다. HTTP 상태 자체를 연결 실패로 해석하지 않는다.
- 결과는 고정 검사명·상태·소요 시간·안전한 조치 문구만 포함한다. URL·토큰·인가 코드·PKCE·proof·본문을 출력하지 않는다.
- 성공 `0`, 검사 실패 `1`, 건너뜀 `3`을 반환하며 사용법 오류 `2`는 명령 경계가 소유한다.
- 생성한 인증 조정자와 원격 클라이언트는 진단 종료 때 닫고 상태를 영속화하지 않는다.

## 작업 지침

- 시험에서 외부 계정이나 시스템 브라우저를 자동 실행하지 않는다. 브라우저 대역·로컬 TLS와 실제 운영체제 검증을 구분한다.

## 검증

- 여덟 단계의 순서·단계별 실패·종속 건너뜀·제한 시간·취소·출력 실패·JSON 외피·종료 코드를 시험한다.
- 로컬 TLS·루프백·실제 토큰 교환 경로에서 도구 미호출·비밀 비노출과 재실행의 새 키·토큰·닫힌 callback을 확인한다.
- 프록시 전용 연결·독립 프로세스의 `HTTPS_PROXY` 환경 적용과 프록시 경로의 TLS 호스트 검증 실패를 확인한다.
