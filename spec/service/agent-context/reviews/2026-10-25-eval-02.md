- LoCoMo: 공식 [고정 파일](https://github.com/snap-research/locomo/blob/3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376/data/locomo10.json), 2,805,274바이트, SHA-256 `79fa87e90f04081343b8c8debecb80a9a6842b76a7aa537dc9fdf651ea698ff4`. Maharana 외, Evaluating Very Long-Term Conversational Memory of LLM Agents (ACL 2024)을 출처로 남기고 비상업·출처 표시·변환 정책을 기록한다. 원본·변환 본문은 저장소에 추가하거나 공개하지 않았다.

## 변환 결과·근거 분모

- LongMemEval: 500문항·500개 기억 그래프 묶음·독립 과업 471개, 원천 246,918개. `_abs`와 원 문항을 같은 과업으로 묶었다. 유형은 원래 사실/선호/시간/갱신/다중 세션을 유지하고 답변 유보 30문항을 별도 구분했다. 근거는 438문항에 주석이 완전하며, 정답 세션 일부에 턴 주석이 없는 32문항은 근거 지표 미평가, 답변 유보 30문항은 비해당이다. 부분 주석으로 완전한 정답 집합을 꾸미지 않았다.
- LongMemEval의 원본 25,112세션·246,930턴을 대조했다. 빈 세션 1,230개·반복 세션 식별자 15개·빈 발화 12개는 원래 위치·역할·시각과 함께 비공개 매핑에 남겼다. 반복 세션의 발화를 합치지 않았고 빈 발화의 본문을 만들어 색인하지 않았다.
- LoCoMo: 10개 대화·272개 본문 세션·원천 5,882개, 시각만 있는 세션 16개의 매핑을 보존했다. 전체 1,986문항 중 이미지 연결 턴을 근거로 지정한 735문항을 `image_evidence`로 제외하고 1,251문항을 유지했다. 유지 유형은 단일 홉 607·다중 홉 93·시간 182·상식 52·답변 유보 317이다. 근거 주석 924문항, 미평가 10문항(빈 주석 4·비정규/없는 참조 6), 비해당 317문항을 구분했다. 이미지 설명·검색어·요약·관찰과 `adversarial_answer`를 기억 또는 정답으로 넣지 않았다.
- 자체 `own-supplement-v1`: 사건·근거 상태·다른 그래프 격리·복구·오염·인계의 독립 과업 여섯 개, 격리 대조 그래프를 포함한 일곱 묶음·컨텍스트 115개다. 초기 행위자/권한과 연산·기대 상태를 준비했다. 해당 연산의 실제 실행·합격 판정은 이번 데이터 준비 검증에 포함하지 않는다.

## 검증

```sh
go test -race -count=1 -json -timeout=180s -skip Integration ./cmd/eval
go build ./...
go vet ./...
gofmt -l .
```

Go 1.27.1의 최종 모듈 시험 **272건**(최상위 **82건**, 하위 사례 포함)이 실패·건너뜀 없이 통과했다. 새 데이터 준비 시험은 43건이다. 원문/주석 분리·답변 유보·부분/없는 주석·빈 세션/발화·반복 ID·잘못된 시각/역할/필드/문항 수·발화자 매핑·checksum·중복 JSON·뒤따르는 JSON·출력 권한·기존 파일 보존과 실제 CLI의 모드 배타성/DB 미접속을 확인했다. 전체 build·vet·gofmt도 통과했다. DB 의존 시험은 이번 작업의 대상이 아니며 `-skip Integration`으로 선택하지 않았다.

실제 공식 파일 두 개와 자체 세트를 준비 모드로 실행한 뒤 별도 Python 대조로 모든 발화의 원문 순서·전체 문항 수·정답·원본 근거 참조·원본 시각·답변 유보·이미지 제외와 독립 단위를 확인했다. 네 파일의 권한과 실제 파일 SHA-256도 대조했다. `memory.json`·`evaluation-private.json`·`mapping-private.json`은 평가 전용이며, 공개 가능한 `preparation.json`은 비식별 코드·수·판·사용 조건·파일 checksum만 가진다. 자동 다운로드·외부 모델 호출·DB 접속은 준비 실행기에 추가하지 않았다.

재현 명령은 다음과 같다. `$INPUT_DIR`에는 위 checksum의 로컬 원본을 두며 각 출력 경로는 존재하지 않아야 한다.

```sh
go run ./cmd/eval -prepare-data longmemeval -prepare-source "$INPUT_DIR/longmemeval_s.json" -prepare-out "$OUTPUT_DIR/longmemeval"
go run ./cmd/eval -prepare-data locomo -prepare-source "$INPUT_DIR/locomo10.json" -prepare-out "$OUTPUT_DIR/locomo"
go run ./cmd/eval -prepare-data own-supplement -prepare-out "$OUTPUT_DIR/supplement"
```

고정 입력의 `preparation.json` SHA-256은 다음과 같다. 보고서 내부의 세 비공개 파일 checksum과 함께 출력 판을 재확인할 수 있다.

- `longmemeval`: `05aee179ccdb97cd38828549d60e3582f699f146f9d416dea29239234eb0a69e`
- `locomo`: `b3dfaad92b05c2a5146a93587111d124a9dc5055fe3f715606deec73cfec4586`
- `supplement`: `26b55e016feda7c4a9e9a67e908f2f2383c0ad89d4da21a63cb15a00a01f1dd2`

## 중간 실패·남은 조건·DOX

초기 변환의 빈 세션/발화·반복 세션 ID·시각만 있는 세션 거부는 전체 원본 대조로 원인을 확인한 뒤, 위 명시적 보존 정책으로 수정했다. 최초 모듈 명령은 sandbox의 기본 Go 캐시 접근 제한으로 실행 전 실패했고 같은 검증을 허용된 실행 권한으로 수행했다. 미실행을 통과에 합산하지 않았다.

실제 데이터는 임시 평가 경로에만 유지한다. 고정 checksum과 다른 판은 거부하며 자동으로 최신/cleaned 판을 대신 쓰지 않는다. LoCoMo의 보수적 이미지 제외와 원본 주석 오류는 이 판의 해석 제한이다. 데이터 준비 통과는 검색 품질·비용·서비스 수준 목표의 통과가 아니다. EVAL-03의 그래프 수명·준비와 이후 비교 실행에서 이 입력을 연결한다.

전체 계획은 **105/124개 완료·1개 진행·18개 미착수**이며 다음 권장은 EVAL-03이다. 평가 SDD는 준비 모드·분리·원본 이상 처리의 정본으로, 계획/SDD 진입점과 서비스 색인은 구현 상태로, 요청/출처/검토 기록은 새 증거의 위치로 갱신했다. 변경 Markdown 8개·로컬 링크/앵커 415개와 개발 작업 124개/완료 105개의 정합성을 확인했다. 패키지·지속 경계·소유권은 바뀌지 않아 DOX 수정은 필요하지 않음을 확인했다. 변경은 미커밋이며 기존 개인 `.idea` 두 파일은 작업에서 제외했다.
