# 용어 정리집

## 서비스 용어

| 단어                   | 정의                                                                                                                                                   | 비고                                                                                                                                                         |
|------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------|
| AI 에이전트 제텔카스텐 | AI 에이전트가 이후 작업에서 다시 활용할 수 있도록 지식과 작업 맥락을 지속적으로 축적하고 연결하는 시스템이다.                                          | 서비스의 궁극적인 목표이며 컨텍스트 단위, 연결 원칙과 지식 성장 정책은 후속 기획에서 정의한다.                                                               |
| 계정                   | 작업자를 식별하는 단위이자 인증 주체이며 컨텍스트 보관 정책의 판정 대상이 되는 서비스 이용 주체다.                                                     | 식별자는 UUIDv7을 사용한다. 컨텍스트 그래프 단위로 권한 등급을 부여하며 부여·회수는 웹 페이지에서 수행한다.                                                  |
| 계정 플랜              | 계정에 적용되는 서비스 이용 조건과 데이터 보관 정책의 묶음이다.                                                                                        | 향후 비즈니스 모델과 연결해 플랜별 소프트 삭제 전 보관 기간 및 변경 적용 기준을 정의한다.                                                                    |
| 공유 컨텍스트 그래프   | 여러 작업자가 권한 범위 안에서 공동으로 접근해 컨텍스트와 관계를 기여·조회·활용하는 하나의 그래프다.                                                   | 권한은 계정과 그래프의 조합에 등급으로 부여하며 부여·회수는 그래프 소유자가 웹 페이지에서 수행한다.                                                          |
| 국소 그래프 보기       | 현재 선택한 컨텍스트를 중심으로 지정된 관계 깊이 안의 컨텍스트와 관계를 표시하는 시각화 방식이다.                                                      | 탐색 깊이와 표시 규칙은 후속 기획에서 정의한다.                                                                                                              |
| 권한 등급              | 계정이 컨텍스트 그래프에 대해 수행할 수 있는 연산의 범위를 나타내는 구분이다.                                                                          | 소유자, 편집자, 열람자를 사용하며 등급별 허용 연산과 부여·회수 절차는 `SRS.md`의 「격리와 권한 요구사항」이 정의한다.                                        |
| 근거 상태              | 컨텍스트가 원천 사실 또는 관찰·경험·의견 성격의 파생 정보 중 어디에 해당하는지 나타내고 의견이나 해석을 뒷받침하는 근거와 신뢰 상태를 연결하는 정보다. | 분류 규칙, 근거 연결 스키마, 신뢰 상태 값·계산 방식과 상충 처리 정책은 후속 기획에서 정의한다.                                                               |
| 비지속 요청-응답       | MCP 클라이언트의 각 요청을 지속 연결이나 프로토콜 세션 상태에 의존하지 않고 독립적으로 처리하고 응답하는 상호작용 방식이다.                            | 사용자 표현인 `단발성 연결`을 명세에서 정규화한 용어다.                                                                                                      |
| 사건 컨텍스트          | 하나의 상호작용이나 경험에서 함께 해석해야 하는 정보를 묶은 컨텍스트 단위다.                                                                           | 사건 사이 시간·인과·부분·의미 관계를 최소 후보로 실험하며 분할·중첩·병합 기준과 관계별 정의·방향·제약은 미정이다.                                            |
| 소유권 이전            | 그래프 소유자가 다른 계정에 소유자 등급을 부여해 작업 단위를 넘기는 절차다.                                                                            | 작업 인계에 해당하며 그래프에는 소유자가 최소 하나 유지된다.                                                                                                 |
| 소프트 삭제            | 데이터를 영구 제거하지 않고 사용자 접근 대상에서 제외하는 삭제 방식이다.                                                                               | 사용자 직접 삭제와 계정 접근 소멸 후 자동 삭제에 적용하며 영구 삭제는 수행하지 않는다.                                                                       |
| 시간 유효성            | 컨텍스트나 관계가 사실로 간주되는 시점 또는 기간과 대체 여부를 나타내는 특성이다.                                                                      | 속성명, 시간 정밀도와 이력 정책은 후속 기획에서 정의한다.                                                                                                    |
| 업무 연속성            | 작업자와 에이전트가 이전 상호작용과 공유된 관련 컨텍스트를 활용해 작업 상태와 흐름을 이어가는 특성이다.                                                | 평가 시나리오, 지표와 합격 기준은 후속 기획에서 정의한다.                                                                                                    |
| 에이전트 컨텍스트      | 에이전트가 작업을 해석하거나 이어가기 위해 사용하는 정보 단위와 그 관계를 통칭한다.                                                                    | 최소 단위와 필수 속성은 후속 기획에서 정의한다.                                                                                                              |
| 연상 검색              | 시작 컨텍스트에서 그래프 관계를 따라 관련 정보를 찾는 검색 방식이다.                                                                                   | 그래프 확장과 순위화 알고리즘은 미정이다.                                                                                                                    |
| 원천 컨텍스트          | 에이전트 상호작용이나 외부 입력에서 수집해 출처와 함께 보존하는 원본 정보다.                                                                           | 최소 단위는 하나의 발화 또는 턴이며 생성 후 불변이다. 본문 형식과 보존 기간은 미정이다.                                                                      |
| 유예 기간              | 마지막 접근 가능 계정이 사라진 뒤 자동 소프트 삭제를 보류하는 30일의 기간이다.                                                                         | 기간 안에 접근 가능한 계정이 다시 연결되면 예정된 소프트 삭제를 취소한다.                                                                                    |
| 작업 컨텍스트 흐름     | 에이전트가 현재 작업을 이해하고 이어가기 위해 사용하는 관련 컨텍스트, 관계와 근거 경로의 기계 판독형 묶음이다.                                         | 사용자용 그래프 UI 또는 컨텍스트 시각화와 구분한다.                                                                                                          |
| 작업자                 | 공유 컨텍스트 그래프에 접근해 컨텍스트를 기여·조회·활용하며 공동 업무를 수행하는 협업 주체다.                                                          | 계정 단위로 식별하며 인간 사용자는 계정을 사용하는 사람의 역할이다. 팀은 작업자가 아니라 계정을 묶는 권한 그룹으로 다룬다.                                   |
| 전역 요약              | 개별 항목이 아니라 관련 컨텍스트 집단이나 전체 그래프에서 도출한 상위 수준의 요약이다.                                                                 | 제공 여부, 집단 구성과 갱신 정책은 검토가 필요하다.                                                                                                          |
| 전체 그래프 보기       | 사용자가 접근할 수 있는 전체 컨텍스트와 관계를 한 범위에서 표시하는 시각화 방식이다.                                                                   | 표시 규모, 필터와 집계 정책은 후속 기획에서 정의한다.                                                                                                        |
| 접근 가능한 계정       | 특정 컨텍스트 그래프에 소유자·편집자·열람자 중 유효한 등급을 가진 계정이다.                                                                            | 하나 이상 존재하면 기본 무기한 보관하며 마지막 계정이 사라지면 30일 유예 기간을 시작한다.                                                                    |
| 접근 토큰              | 인증된 MCP 클라이언트가 보호된 MCP 요청을 수행할 권한을 증명하기 위해 사용하는 단기 Bearer 자격 증명이다.                                              | 유효기간은 발급 또는 갱신 시점부터 1시간이며 클라이언트 프로세스 메모리에 보관한다.                                                                          |
| 컨텍스트 계층          | 컨텍스트를 원천, 파생, 사건으로 구분하는 구조 구분이다.                                                                                                | 계층별 필수 속성과 불변·가변 규칙은 `SRS.md`의 「컨텍스트 모델」이 정의한다.                                                                                 |
| 컨텍스트 관계          | 두 컨텍스트 또는 컨텍스트와 관련 주체 사이의 연결이다.                                                                                                 | Apache AGE 그래프로 표현하며 관계 유형과 방향은 미정이다.                                                                                                    |
| 컨텍스트 관리          | 에이전트 컨텍스트의 저장, 조회, 관계와 수명주기를 다루는 기능 범주다.                                                                                  | 구체적인 관리 동작은 미정이다.                                                                                                                               |
| 컨텍스트 관리 연산     | 컨텍스트의 추가, 갱신, 대체, 폐기 또는 유지를 판단하고 적용하는 명시적 동작이다.                                                                       | 허용 조건, 실행 주체와 자동화 범위는 미정이다.                                                                                                               |
| 컨텍스트 그래프        | 컨텍스트 노드와 그 관계를 하나의 선택·관리 단위로 구성한 그래프다.                                                                                     | AI 에이전트 제텔카스텐을 구현하기 위한 현재의 핵심 접근 방식이며 격리 단위이자 작업자가 작업하는 단위다. 식별자, 이름과 메타데이터는 후속 기획에서 정의한다. |
| 컨텍스트 노드          | 컨텍스트 그래프에서 하나의 컨텍스트 항목을 나타내는 노드다.                                                                                            | 최소 단위, 필수 속성과 관계 제약은 후속 기획에서 정의한다.                                                                                                   |
| 컨텍스트 시각화        | 컨텍스트와 그 관계를 작업자가 시각적으로 이해하고 탐색할 수 있도록 표현하는 기능이다.                                                                  | 표현 형식, 렌더링 주체와 상호작용 방식은 미정이다.                                                                                                           |
| 컨텍스트 식별자        | 컨텍스트 그래프를 넘어 전역으로 고유하며 생성 후 변경되지 않는 컨텍스트의 식별 값이다.                                                                 | UUIDv7을 사용하며 파생 컨텍스트는 식별자와 판 번호의 조합을 식별 단위로 삼는다.                                                                              |
| 컨텍스트 예산          | 한 번의 검색 결과나 모델 입력에 포함할 수 있는 컨텍스트의 허용량이다.                                                                                  | 단위, 기본값과 서비스 수준 목표는 후속 기획에서 정의한다.                                                                                                    |
| 팀                     | 계정을 묶어 권한을 함께 부여하기 위한 그룹이다.                                                                                                        | 작업자가 아니며 팀에 부여한 등급은 소속 계정에 적용된다. 인증된 계정이 생성하며 생성 계정이 팀 관리자가 된다.                                                |
| 팀 관리자              | 팀을 생성한 계정으로서 팀 구성원을 추가·제거하는 주체다.                                                                                               | 팀 관리는 웹 페이지에서만 수행한다.                                                                                                                          |
| 파생 컨텍스트          | 하나 이상의 원천 컨텍스트에서 생성한 요약, 성찰 또는 구조화된 정보다.                                                                                  | 근거 원천과 생성 이력을 추적하며 갱신 시 판 번호와 대체 관계를 남긴다. 생성 정책은 미정이다.                                                                 |
| 하이브리드 검색        | 직접 후보 검색과 그래프 기반 연상 검색을 조합하는 검색 방식이다.                                                                                       | 각 단계의 알고리즘과 결합 방식은 후속 기획에서 정의한다.                                                                                                     |
| 행위 에이전트          | 계정을 대행해 컨텍스트를 실제로 기록한 에이전트다.                                                                                                     | 기여 계정과 함께 `created_by_agent`로 기록해 감사에 사용한다.                                                                                                |
| 홉 범위 조회           | 시작 노드에서 관계를 따라 지정한 홉 수 이내의 연결된 노드를 조회하는 방식이다.                                                                         | `0홉`은 시작 노드만 반환하는 단일 노드 조회와 동일하다.                                                                                                      |

## 기획 용어

| 단어              | 정의                                                                                                     | 비고                                                                                                  |
|-------------------|----------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------|
| `AGENTS.md`       | 특정 디렉터리와 그 하위 트리에서 작업자가 따라야 하는 작업 계약 문서다.                                  | 루트와 지속 경계별 하위 경로에 둘 수 있다.                                                            |
| Apache AGE        | PostgreSQL에 그래프 데이터베이스 기능을 제공하는 확장이다.                                               | 이 프로젝트의 컨텍스트 데이터베이스로 사용한다.                                                       |
| `Child DOX Index` | 부모 `AGENTS.md`가 직접 소유하는 하위 작업 계약 문서의 목록이다.                                         | 하위 `AGENTS.md`를 생성·이동·삭제·이름 변경할 때 갱신한다.                                            |
| DOX               | 계층형 `AGENTS.md` 문서로 작업 맥락과 계약을 관리하는 프레임워크다.                                      | 런타임이나 외부 의존성을 요구하지 않는다.                                                             |
| Effective Go      | 명확하고 관용적인 Go 코드 작성 방법을 설명하는 공식 Go 문서다.                                           | https://go.dev/doc/effective_go                                                                       |
| GitHub 이슈       | 명세에 근거한 구현, 조사 또는 결정 작업을 추적하는 GitHub 작업 단위다.                                   | 생성·수정 전 사용자 승인이 필요하다.                                                                  |
| GraphRAG          | 지식 그래프와 관련 집단의 요약을 이용해 국소 검색과 전역 질문을 다루는 그래프 기반 RAG 접근법이다.       | 현재는 전역 요약의 연구 근거이며 채택 여부는 확정하지 않았다.                                         |
| MCP               | AI 애플리케이션과 외부 데이터·기능 사이의 컨텍스트 교환을 표준화하는 Model Context Protocol이다.         | 이 시스템은 MCP 서버를 담당하며 primitive, transport와 protocol revision은 미정이다.                  |
| Mermaid           | Markdown 코드 블록에서 구조, 흐름과 관계를 표현하는 다이어그램 문법이다.                                 | 명세에 확인된 요소와 관계만 표현한다.                                                                 |
| openCypher        | property graph의 패턴과 관계를 질의하는 그래프 질의 언어다.                                              | Apache AGE의 그래프 질의에 사용 가능하며 구체 사용 범위는 미정이다.                                   |
| Pull Request      | 검증된 브랜치 변경을 기본 브랜치에 병합하도록 제안하는 GitHub 협업 단위다.                               | 문서에서는 필요할 때 `PR`로 줄여 쓴다.                                                                |
| SDD               | 확정된 요구사항을 아키텍처, 인터페이스, 데이터와 처리 흐름으로 구체화한 상세 설계 문서다.                | `spec/service/{서비스 경로}/SDD.md`                                                                   |
| SRS               | 서비스의 기능·비기능 요구사항, 정책, 제약과 미정 사항을 정의하는 요구사항 명세 문서다.                   | `spec/service/{서비스 경로}/SRS.md`                                                                   |
| 명세 문서         | 서비스 요구사항, 설계, 계약처럼 프로젝트의 지속적인 사실을 기록하는 문서다.                              | `spec/`에 보관한다.                                                                                   |
| 비그래프 기준선   | 그래프 구조를 사용하지 않고 동일한 입력·표현·검색 예산과 평가 조건을 적용해 구성한 비교 대상 시스템이다. | 그래프 기능의 효과를 통제 비교하기 위해 먼저 구성하며 구성 방식과 채택 기준은 후속 기획에서 정의한다. |
| 스킬              | 특정 작업의 입력, 절차, 승인 경계와 검증 기준을 정의하는 프로젝트 로컬 작업 지침이다.                    | `.agents/skills/{스킬명}/SKILL.md`                                                                    |
| 요구사항 ID       | 요구사항과 설계·이슈 간 추적성을 유지하기 위한 고유 식별자다.                                            | 기존 ID는 상태가 바뀌어도 재번호화하지 않는다.                                                        |
| 용어 정리집       | 프로젝트에서 쓰는 서비스 용어와 기획 용어의 표준 표기와 정의를 모은 문서다.                              | `spec/DICTIONARY.md`                                                                                  |
| 작업 로그         | 사용자 명령, 처리 결과와 변경 내역을 날짜별로 기록하는 비공개 운영 문서다.                               | `.personal/logs/YYYY-MM-DD 작업 내용.md`                                                              |
| 프로젝트 이력     | 서비스 요청 기록과 제안을 날짜별로 요약한 공개 가능한 명세 작업 이력이다.                                | `spec/history/`에 보관하며 `.personal/` 내용은 포함하지 않는다.                                       |
