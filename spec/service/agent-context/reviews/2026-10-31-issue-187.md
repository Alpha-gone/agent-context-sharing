# #187 감사 조회의 등급·상속 상세

## 변경

이전·이후 등급 중 하나라도 있으면 없는 쪽을 `-`로 표시하여 신규 부여·소유권 이전·회수·운영자 복구의 등급 전이가 빈칸이 되지 않게 했다. 등급이 모두 없는 일반 삭제·복구 행은 전이를 만들지 않는다. 팀 상속 근거는 기존 팀 대상을 유지하면서 상세에 구성원 계정 UUID를 추가한다. 두 정보가 모두 있으면 ` / `로 구분한다.

변경은 auditWebSQL의 상세 투영식뿐이며 대상 선택·소유자 접근·기간/대상 필터·정렬·페이지와 감사 저장 값은 유지한다. SRS의 기존 감사 항목을 충족하는 표시 수정이므로 SRS 요구사항·DB 스키마·API 형식·DOX 소유권은 유지했다. 상세 표기 계약은 [관측성](../sdd/observability.md#감사-기록의-조회)에 두고 웹 정본은 이를 참조한다.

## 검증 근거

- 실제 API로 계정 부여·등급 변경·소유권 이전·회수, 팀 소유자 부여와 상속, 웹 삭제·복구, 운영자 복구를 수행하고 ListAuditEntries 결과의 대상·상세를 대조했다. 구성원 대상 필터도 팀 대상과 구성원 상세를 유지한다.
- 수정 전 audit_query.go를 Go overlay로 실행하면 두 신규 DB 회귀가 실패했다. 신규/회수 등급 상세·상속 구성원·운영자 복구 상세 누락을 실제로 검출했고 수정된 SQL의 같은 회귀는 통과했다.
- 독립 코드 검토에서 차단 결함은 없었다. 실제 브라우저 수동 인수는 이번 범위가 아니다.

- Go 1.27.1, 작업 전용 합성 PostgreSQL, TEST_DATABASE_REQUIRED=1의 `go test -race -json -count=1 -timeout=15m ./internal/store ./internal/web`: store 1818·web 816개 시험 및 하위 사례가 실패·건너뜀 없이 통과했다.
- check-go.sh의 의존성·build·vet·gofmt, diff 공백·변경 Markdown 링크/구조 검사를 통과했다.
- 기존 개발 DB 대신 작업 소유 합성 컨테이너·볼륨만 사용했다.
- 검증 후 소유 라벨을 확인하여 전용 컨테이너·볼륨을 제거했고 해당 라벨의 잔여 컨테이너가 없음을 확인했다.
