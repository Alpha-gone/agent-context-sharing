# 임베딩 제공자 범위 축소 검증

## 변경

사용자 요청에 따라 로컬 모델 제공자의 코드·구성·명세·안내와 관련된 과거 상세 기록을 제거했다. 임베딩 호출은 `EMBEDDING_PROVIDER=gemini`만 허용하며 제공자 생략과 다른 값은 서버·평가·감사에서 외부 호출 전에 거부한다.

- `internal/index`의 요청·응답·색인 식별자는 Gemini 단일 경로다. HTTPS·문서/질의 입력 구분·API 키 헤더·응답 상한·취소·재시도·차원 검증은 유지한다.
- 개발 Compose에서 모델 서비스·profile·볼륨을 제거했다. `.env.example`과 로컬 `.env`의 사용하지 않는 포트 구성만 제거하고 자격 증명은 변경하지 않았다. 개발 기본 기동은 DB·WAL 정리이며 `server` profile은 마이그레이션·서버를 추가한다.
- 테스트 대역은 로컬 HTTPS와 Gemini 응답 형식을 사용한다. 별도 평가 시험 프로세스에는 시험 인증서를 임시 파일로 제공해 TLS 검증을 유지한다.
- 차원 전환·복원 회귀는 Gemini의 768↔1024차원을 사용한다. 기존 마이그레이션 파일·checksum·DB 이력과 원본 보존 계약은 바꾸지 않았다.
- SRS·분야별 SDD·개발 계획·안내·DOX와 추적표를 동기화했다. 과거 기록의 해당 제공자 상세를 제거했으며 남아 있는 측정을 Gemini로 재실행한 결과로 바꾸지 않았다.

## 검증

2026-10-12, IntelliJ IDEA에 등록된 Go `1.27.1 darwin/arm64` SDK를 사용했다. 실제 임베딩 API는 호출하지 않았다.

- 전체 `go test ./...`: 606개 시험·하위 시험 통과, DB 접속 정보를 지정하지 않은 DB 시험 204개 건너뜀. 이 결과만으로 DB 통합 성공을 주장하지 않는다.
- 영향받은 `internal/index`, `internal/config`, `internal/migrate`, `cmd/eval`, `cmd/audit`, `cmd/server`: 새 격리 DB에 정식 마이그레이션을 적용하고 `go test -race -count=1`로 329개 시험·하위 시험 통과, 건너뜀 없음.
- 격리 DB 회귀에는 색인 작업·관계 제안·차원 전환과 복원·실패 재시도·평가 subprocess·기동 실패 정리가 포함된다. 모든 임베딩은 합성 자료와 로컬 HTTPS 대역으로 처리했다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `sh -n test-dev-compose.sh`, 개발 Compose 정적 검사, 문서 링크·앵커·Markdown 구조·요구사항 추적 및 `git diff --check` 통과.
- 작업 파일에서 제거 대상의 이름·포트·전용 endpoint·모델·이미지 digest가 남아 있지 않은지 숨김·비추적 파일을 포함해 확인했다. Git 이력은 검사·수정 대상에서 제외했다.

전체 DB 패키지 회귀, 개발 Compose의 캐시 없는 `--runtime` 빌드와 실제 API 품질·비용 평가는 이번 검증에 포함하지 않았다. 운영 Compose의 기존 사용자 변경은 이번 작업과 분리해 유지했다.

## 정리와 DOX

격리 Compose 프로젝트의 DB·네트워크·볼륨을 정리하고 잔여 컨테이너·볼륨이 없음을 확인했다. 기존 개발·운영 컨테이너·모델 데이터·DB·이미지는 변경하지 않았다.

루트와 `spec`→`service`→`agent-context`→`sdd`의 DOX 체인을 확인했다. 루트·서비스·분야별 로컬 계약을 현재 제공자와 구성에 맞췄으며 부모의 경계·파일 경로·Child DOX Index와 용어 정의는 바뀌지 않아 유지했다. SQL 파일과 마이그레이션 계약은 기존 내용으로 유지했다. 커밋·푸시와 호스트 설정 변경은 수행하지 않았으며 현재 브랜치에는 upstream이 없어 원격 대비 상태를 확인할 수 없다.
