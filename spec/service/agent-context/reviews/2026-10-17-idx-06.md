# IDX-06 소비 루프·embedded/external 배치 모듈 시험

## 범위와 구현

- 대상: [IDX-06](../development-plan/indexing.md#idx-06). IDX-05 완료, 시작 커밋 `aa41598`, 브랜치 `feat/index-retry-budget`. upstream `origin/dev`의 로컬 추적 ref 대비 앞섬 3·뒤처짐 0이다.
- 정본: [색인 소비·리스](../sdd/indexing.md#색인-작업-큐), [배치 조합](../sdd/architecture.md#배치-조합), [기동과 종료](../sdd/operations.md#기동과-종료), [모듈 시험 시점](../DEVELOPMENT_PLAN.md#테스트-작성과-실행-시점). Go 1.27.1의 Timer.Reset·signal.NotifyContext·testing/synctest 공식 reference를 확인했다.
- **해결된 결함 IDX06-R1 / 중간:** 처리 회차가 대기 없이 다음 회차를 호출하는 경로를 제거했다. 처리 뒤 1초, 빈 회차는 2·4·8·16·30초로 증가하고 30초에서 유지한다. 처리한 회차는 간격을 1초로 되돌린다. 확보 오류도 유휴 백오프를 사용한다. 시작·회차 전후에 취소를 확인해 취소 뒤 새 작업을 확보하지 않는다.
- `cmd/indexer`는 서버와 같은 검증된 배포 구성·저장소·Gemini 제공자·DB 형상 검사를 사용한다. external만 허용하고 HTTP 수신기·주기 작업 없이 소비 루프를 실행한다. SIGINT·SIGTERM 뒤 별도의 최대 10초 예산으로 작업자를 닫고 성공한 때 풀을 닫는다. 종료 실패는 원인을 합쳐 반환하고 풀 종료 대기로 무기한 막히지 않도록 한다.
- 서버는 embedded에서만 색인 소비를 시작한다. external도 생성한 제공자 transport를 소유하므로 기동 실패·정상 종료의 공통 정리 목록에는 등록한다. 기존 중복 종료 방지·요청과 작업자 예산 분리를 유지한다. 소비·재색인 루프와 새 실행기의 오류 로그는 원문 대신 고정 원인 코드를 사용한다.
- DOX pass: 새 실행기 소유권을 cmd DOX와 부모 색인에 추가하고 아키텍처의 실행기 목록·README 호스트 분리 실행·환경 예시의 배치 안내를 정합화했다. 애플리케이션 패키지 수·의존 방향·SRS·벡터 스키마·마이그레이션·환경 키·기본값·용어는 유지한다. 서버 컨테이너 이미지는 기존 server 실행용이며 새 실행기의 컨테이너 배포를 완료한 것으로 표시하지 않는다. 미해결 결함은 확인되지 않았다.

## 검증 결과 — 10:40 KST

- Go 1.27.1 darwin/arm64. 고정 Dockerfile의 전용 컨테이너·새 볼륨·loopback 임시 포트·합성 자격으로 PostgreSQL 18.6 / AGE 1.8.0 / pgvector 0.8.6 / Linux aarch64를 확인했다.
- **고유 시험·하위 시험 33건 통과**: index 7·config 1·server 20·indexer 5, 최상위 17개·하위 16개. 신규 모듈 17건·관련 회귀 16건이며 `-race -count=1`, `TEST_DATABASE_REQUIRED=1`을 적용했다. 실패·건너뜀은 0이다.
- 가상 시계로 실제 소비 루프의 회차 시각 0·1·3·7·15·31·61·91·92·93초를 대조했다. 성공 뒤 1초, 유휴 증가·30초 상한·처리 후 초기화를 확인했다. 기동 전·유휴 대기·회차 처리 중 취소 뒤 추가 호출과 고루틴 잔류가 없었다. 32개 작업자 각각에서 Start·Close를 16회씩 겹쳐도 race·중복 종료 panic이 없었다.
- 실제 서버·색인 실행기를 race 바이너리로 만들어 로컬 TLS 제공자 인증서를 신뢰 루트로 주입했다. TLS 검증을 비활성화하지 않았다. embedded 서버와 external 서버+실행기에서 같은 합성 원천 세 건의 모델·벡터 공개 결과가 같았다. external 서버만 기동한 동안 큐·임베딩·제공자 호출은 변하지 않았다.
- 두 색인 프로세스가 동시에 호출을 대기한 동안 서로 다른 유효 리스 두 건과 미공개 상태를 확인했다. 대기 해제 뒤 각 본문이 한 번만 호출되고 세 건이 모두 공개됐다. 제공자 호출 중 SIGTERM을 보내 실제 HTTP 취소·정상 프로세스 종료·attempts=0의 pending 리스 보존을 확인했다. 다른 프로세스는 유효 리스를 건너뛰고 만료 뒤 같은 작업을 공개했다. 2분 실시간 대기 대신 자기 시험 DB의 유일한 리스 시각을 과거로 바꿨다.
- 구성 검증은 잘못된 제공자·배치와 별도 실행기의 embedded 선택을 자원 조립 전에 거부하고 조립 오류 원인을 보존했다. 실제 DB 128차원과 실행기 256차원의 불일치는 외부 호출 전에 종료 코드 1로 끝났고 큐를 보존했다. 기동 조립·HTTP 수신 실패 정리, 요청/작업자 종료 오류·취소와 공유 종료 예산의 회귀도 통과했다.
- 최종 검토에서 시험별 DB를 기본 DB 복제 대신 빈 DB 생성과 정식 001·009·010·011 적용으로 보강했다. 다른 시험의 그래프·큐를 복사하지 않으며 다섯 임시 DB에서 최초 4개·반복 0개 적용을 확인했다. 변경한 실제 배치 시험 6건을 별도로 다시 실행해 모두 통과했다. 위 33건에 중복 합산하지 않는다. 임시 DB 잔여 0과 라벨 확인 후 전용 컨테이너·볼륨·이미지 정리·잔여 자원 0을 확인했다.
