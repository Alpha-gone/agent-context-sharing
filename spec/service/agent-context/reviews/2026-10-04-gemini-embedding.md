# Gemini 임베딩 제공자 전환 검토

- 날짜: 2026-10-04
- 범위: [#41](https://github.com/Alpha-gone/agent-context-sharing/issues/41)의 제공자 교체 구현·로컬 검증과 이후 합성 입력 두 번의 실제 API 확인. 사용자가 DB 차원 변경을 승인했으며 기존 A1 서버의 인프라·배포는 제외했다.
- 계약: [SDD](../SDD.md)의 「임베딩 제공자 전환」, [개발 계획](../DEVELOPMENT_PLAN.md)의 20단계

## 구현

- 개발 기본 구성은 `gemini-embedding-2`·768차원·`vector`다. Gemini 연결은 API 키 헤더, 문서/질의 입력 형식, 단일 벡터와 자동 절단 금지를 사용한다. 기존 제공자 선택을 생략한 구성과 Ollama의 식별자·요청은 유지한다.
- 키·원문·제공자 오류 본문을 공개하지 않고 유한 timeout·취소·응답 상한·redirect 차단·수치 검증을 적용했다. 색인은 408·429·5xx·전송 장애를 기존 예산으로 재시도하며 인증·입력·차원·응답 계약 위반은 즉시 실패한다. 질의 실패는 의미 유사도 채널만 제외한다.
- 서버·평가·감사 조립을 연결하고 기동 시 DB 열과 벡터 구성의 일치를 확인한다. 모델·입력 형식 판을 포함한 새 식별자로 이전 벡터 혼용을 막는다.
- `007_embedding_dimensions.sql`과 이력의 `render_config`를 추가했다. 기존 SQL과 checksum은 바꾸지 않는다. 차원이 달라지면 원본을 보존하고 옛 파생 벡터 제거·작업 등록·열 변경·HNSW 재생성을 한 트랜잭션으로 실행한다. 원천 제외 구성의 등록과 기존 작업 제거도 반영한다. 이후 전환·복귀는 새 번호를 추가해야 한다.

## 확인한 결과

Go 1.27.1 프로젝트 SDK를 사용했다. 별도로 생성한 로컬 DB에 현재 마이그레이션을 적용했으며 기존 개발 DB·운영 DB에는 적용하지 않았다.

검증 후 이번 작업에서 만든 두 개의 전체 회귀용 DB를 제거했다. 개별 전환 시험용 DB는 각 시험의 정리 경로에서 제거했으며 남은 시험 DB가 없음을 확인했다. 삭제 대상은 합성 시험 데이터뿐이며 같은 검증 절차로 다시 생성할 수 있다.

- 제공자 대역: 동시 문서·질의 형식, API 키 헤더, 차원·영벡터·수치 범위, UTF-8·8000자 경계, token 초과 HTTP 400, 401·403·404·408·429·503, 응답 해석, redirect 미추적, 취소·timeout, 키·본문 비노출 — 통과.
- 실제 AGE·pgvector DB: 구형 이력의 치환 구성 복원과 checksum 보존, 1024→768, cold 파티션 벡터 제거, 원본 보존, 작업 등록, HNSW 재생성, 실패 주입의 트랜잭션 롤백, 반복 실행, 대역을 통한 새 차원의 색인·검색 — 통과.
- 실제 DB의 호출 연결: 429가 검색의 의미 채널만 제외하고 색인 작업은 재시도 대기로 남으며, 400은 failed로 남고 원문·키를 기록하지 않음 — 통과.
- 복귀: 같은 전환 SQL을 다음 번호의 시험 파일로 적용해 768→1024와 Ollama 재색인 복귀 및 과거 이력 보존 — 통과. 운영용 복귀 파일을 생성하거나 적용한 것은 아니다.
- 원천 제외: 다음 번호 시험 파일의 768차원 전환에서 원천 등록을 건너뛰고 기존 원천 작업을 제거하되 본문을 보존 — 통과.
- 서버 `TEST_DATABASE_REQUIRED=1 go test -race ./...` — 통과. DB 통합 계층은 건너뛰지 않았다. 색인·검색 통합 시험이 1024차원을 고정해 768차원 DB에서 실패하던 문제를 DB 열 차원 조회로 고쳤고, 768차원 DB 전체와 1024차원 DB의 `internal/index`·`internal/store`에서 다시 통과했다.
- 클라이언트 `go test -race ./...` — 통과. 서버와 클라이언트의 공유 도구 계약은 유지했다.
- 양쪽 모듈 `go build ./...`, `go vet ./...`, 루트 `gofmt -l .` — 통과.
- 서버 `GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build ./...` — 통과. A1 실기동·부하 검증을 뜻하지 않는다.
- 실행기 CLI: 최종 SQL의 빈 DB up과 환경 차원 변경 후 status에서 당시 구성의 checksum 보존 — 통과. 이미 적용한 007 이후의 환경 변경만으로 DB 열을 다시 바꾸지 않으며 기동의 열 검사와 다음 번호 마이그레이션이 필요하다.

확장한 DB 시험을 반복했고, 앱·DB 시계 차이에 민감했던 초기 작업 확보 fixture는 현재 시험 그래프의 대기 시각을 명시해 안정화했다. 생산 코드의 시계 정책은 변경하지 않았다.

## 미실행과 운영 경계

- 초기 구현·준비 검증에서는 Google API를 호출하지 않았다. 이후 합성 입력 두 번의 실제 확인은 아래 「실제 API 확인 결과」에 분리한다. 운영 데이터 전송·설정 적용·재색인·배포는 미실행이며 API 키를 새로 발급하거나 파일에 저장하지 않았다.
- 실제 검색 품질·반복/부하 지연·비용, 768/1536 비교, 관계 제안 임계값과 A1 자원 지표는 미검증이다. 대역의 합성 벡터나 두 번의 실연결 결과를 모델 품질이나 #41의 완료 근거로 사용하지 않는다.
- 기존 DB의 파일·checksum이 이미 어긋나거나 치환 구성을 복원할 수 없으면 자동 덮어쓰지 않는다. 적용 전 운영 환경의 status 결과와 원래 마이그레이션 자료를 확인해야 한다.
- 적용 시 서비스·색인 작업자를 정지하고 전환 뒤 새 모델의 재색인을 확인해야 한다. 외부 API 이용 계층·전송 정책·비용 한도는 실제 호출 전에 확인해야 한다.
- 공식 MCP conformance와 `client_live` 실연결 시험은 이번 임베딩 변경 검증으로 수행하지 않았다.

## DOX와 문서 점검

루트→spec→service→agent-context 및 migrations 계약을 다시 확인했다. 마이그레이션의 지속 workflow는 `migrations/AGENTS.md`와 루트 Child DOX Index에 갱신했다. 서비스 문서의 소유권·기존 입력/격리·제공자 배포 선택은 유지되어 해당 AGENTS 및 spec 부모는 변경하지 않았다. 클라이언트 구현·명세·도구 manifest·기존 SQL·의존성도 변경하지 않았다. 한국어 표현과 맞춤법을 검토했고 상대 링크 30개, 추적표 FR 159개·NFR 13개의 단일 행 커버리지, 계획의 미완료 표시와 diff를 확인했다.

## 연동 준비 절차

사용자의 커밋·연동 준비 요청에 따라 기본 회귀에서 제외되는 [실연결 시험](../../../../internal/index/embedding_live_test.go)을 추가했다. `embedding_live` 태그를 명시한 실행만 Google API에 접근하며, 키가 없으면 실패한다. 호출 주소·모델·768차원은 고정하고 문서와 질의에 합성 한국어 입력만 쓴다. DB를 읽거나 쓰지 않고 자동 재시도하지 않으며 첫 실패에서 중단해 최대 두 번만 호출한다. 성공 로그에는 단계·차원·지연만 남긴다.

### 1. 호출 전에 필요한 결정과 설정

- API 이용 계층과 합성 입력의 외부 전송·최대 두 번 호출을 허용받는다. 키가 있다고 비용·전송 허용을 추정하지 않는다. 실제 과금액은 제공자의 사용량·청구 기록으로 확인하며 시험 로그의 지연만으로 추정하지 않는다.
- 사용자가 기존 비밀 관리 경로로 `GEMINI_API_KEY`를 시험 프로세스 환경에 주입한다. 키 원문을 채팅·명령 인자·셸 이력·Git·검증 기록에 넣지 않는다. `.env.example`의 키는 빈 값으로 유지하고 기존 `.env`는 덮어쓰지 않는다.
- Go 1.27.1을 사용한다. 실연결 시험은 자체 고정 구성으로 호출하므로 `DATABASE_URL`이나 운영 데이터가 필요 없다.
- 일반 `go test ./...`에는 실연결 시험이 없다. 실제 호출 명령을 CI의 기본 검증에 추가하지 않는다.

### 2. API 호출 없이 시험 컴파일

저장소 루트에서 실행한다. 키 유무와 관계없이 시험 함수가 실행되지 않는다.

```shell
go test -tags embedding_live ./internal/index -run '^$'
```

### 3. 허용받은 뒤 소량 실연결

아래는 실연결 실행 명령이다. 초기 준비에서는 실행하지 않았으며 이후 사용자 확인 뒤의 결과는 아래에 분리한다. API 키를 안전하게 주입한 셸에서만 실행하고 셸의 명령 추적 기능을 켜지 않는다. `-count=1`로 이전 성공 캐시를 재사용하지 않는다.

```shell
go test -tags embedding_live ./internal/index \
  -run '^TestGeminiLiveEmbeddingContract$' -count=1 -timeout=90s -v
```

두 입력 모두 성공하면 실제 인증·요청 수용·768차원 유한 비영벡터 반환을 확인한 것이다. 짧은 입력 두 개의 성공은 8000자/token 경계, 자동 절단 금지의 서버 처리, 검색 품질이나 부하에서의 지연을 검증한 것이 아니다. 실패하면 안전한 오류의 상태 분류를 확인하고 키 권한·이용 계층·모델 접근·네트워크를 점검한다. 요청·응답 원문을 출력하거나 반복 호출로 복구하지 않는다.

### 4. 격리 DB의 실제 임베딩 평가

별도 허용과 호출 예산을 정한 뒤 운영 DB가 아닌 빈 시험 DB에 구성과 마이그레이션을 적용한다. 배포 구성은 `.env.example`의 `EMBEDDING_PROVIDER=gemini`, 공식 `EMBEDDING_BASE_URL`, `EMBEDDING_MODEL=gemini-embedding-2`, `EMBEDDING_VECTOR_TYPE=vector`, `EMBEDDING_DIMENSION=768`을 사용하며 계층 선택은 기존 `INDEX_TARGET_LAYERS`를 명시한다.

승인된 합성 컨텍스트·질의로 색인 저장과 검색의 의미 채널 성공을 확인한 뒤 기존 `cmd/eval`의 통제 평가를 사용한다. 데이터셋·반복 횟수·호출 규모는 비용 허용 전에 실행하지 않는다. 검색 품질·관계 제안 임계값·이용량·지연을 기록하고 모의 벡터 결과와 구분한다. 차원이 다른 비교는 같은 DB의 환경만 바꾸지 말고 별도 DB 또는 새 번호 마이그레이션을 사용한다.

### 5. 운영 전환 전 점검

- 실제 API·품질 평가 뒤 운영 적용·실제 본문 전송·전체 재색인을 별도로 허용받는다. A1 운영 접속·서비스 관리 방식·배포 형상은 이번 변경에서 설정하지 않는다.
- 원본 DB의 백업·복구 방법과 마이그레이션 이력·원래 SQL·벡터 열·cold tablespace를 먼저 확인한다. `migrate status`도 이력 테이블 준비와 구형 치환 구성 보충으로 DB를 수정할 수 있으므로 운영 읽기 전용 점검으로 취급하지 않는다.
- 서비스와 모든 색인 작업자를 정지한 뒤 승인된 운영 구성으로 미적용 007을 적용한다. 이미 007이 적용되어 있으면 해당 파일을 수정하거나 이력을 지우지 않고 다음 번호 전환을 준비한다. 실패 시 checksum을 덮어쓰지 않는다.
- DB 열 일치와 기동을 확인하고 새 `model_id`의 재색인 진행·failed 작업·의미 채널·API 사용량·A1 자원을 관측한다. 완료 전에는 미색인 노드가 의미 채널에서 빠질 수 있다.
- 복귀 시 기존 001·007을 고치거나 환경만 1024로 되돌리지 않는다. 다음 번호의 전환과 Ollama 재색인 또는 별도 승인된 백업 복구를 준비한다.

준비 상태와 실제 성공은 분리한다. 사용자가 키를 설정하고 무료 계층임을 확인한 뒤 허용 범위의 실제 두 번 호출은 통과했다. 추가 평가의 전송 범위·호출 예산과 운영 적용은 별도 확인이 필요하다.

### 준비 변경 검증

Go 1.27.1로 관련 `config`·`index`·`migrate` race 회귀, 양쪽 모듈 build·vet, 실연결 태그 포함 컴파일·vet와 `gofmt`를 확인했다. 키를 환경에서 제거한 실연결 실행은 HTTP 호출 전에 의도대로 실패했다. 준비 변경의 회귀에서는 DB 통합 계층을 다시 실행하지 않았으며, 앞 절의 별도 DB 전체 검증 결과와 구분한다. 준비 단계 당시에는 실제 Google API 성공을 확인하지 않았다.

SDD 테스트 전략·개발 계획·검토 기록을 동기화했다. 실연결 시험은 기존 제공자 경계와 문서의 외부 호출 승인 원칙을 따르며 서비스 소유권·배포 형상은 바꾸지 않으므로 추가 AGENTS 변경은 필요하지 않았다.

## 실제 API 확인 결과

2026-10-04 09:14 KST, 사용자가 `.env`에 키를 설정하고 무료 계층이며 비용 발생이 시스템에서 차단된다고 확인했다. 이를 합성 입력 최대 두 번 호출의 허용으로 받아 Go 1.27.1의 `TestGeminiLiveEmbeddingContract`를 `-count=1`로 실행했다. 과금 차단 설정·청구 기록은 직접 조회하지 않았다.

- 공식 HTTPS 주소의 `gemini-embedding-2`에 문서·질의를 순차 호출한 실제 요청 두 번 — 모두 성공.
- 문서 응답 — 768차원 유한 비영벡터, 단일 호출 지연 594ms.
