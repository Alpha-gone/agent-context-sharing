## 새 인수 행렬

`lifecycle_acceptance_integration_test.go`는 아래 여덟 쓰기에 같은 실제 `ReplayIdempotent` 경계를 적용한다. 각 쓰기의 업무 저장점이 성공한 뒤 별도 연결에서 업무 지문이 그대로인지 확인하고, 바깥 커밋/롤백·결과 저장 실패·지연 커밋 실패·취소를 각각 실행한다. 성공 재생은 한 번만 호출되며 실패 뒤에는 같은 ID·기대 판·빈도 한도로 재시도한다.

| 업무 쓰기 | 함께 확인한 저장 구성 |
|---|---|
| graph_create | 그래프·초기 소유자 등급·계정별 생성 한도·재생 결과 |
| graph_update | 메타데이터·판 비교/증가·재생 결과 |
| node_create | 파생 정점·근거 간선·판 이력·색인 큐·그래프 누계/내용 판/활동·감사·빈도 |
| node_update | 본문·새 판/이전 판·색인 재등록·문자 수 증분·내용 판·감사·빈도 |
| node_discard | 삭제 상태·직접 후속 파생의 근거 무효 표시/이력·문자 수 감소·내용 판·감사 |
| node_restore | 삭제 해제·판 이력·문자 수 증가·내용 판·복구 색인·감사 |
| relation_confirm | 관계 간선·정체성/상태·내용 판·판 없는 감사 |
| relation_discard | 관계 상태·삭제 시각·내용 판·판 없는 감사 |

업무 지문은 정점·간선·파생 이력·큐·임베딩·그래프·관리/웹 감사에 `graph_grant`·`request_rate`·`idempotency_record`를 더한다. 실패 후 부분 변경이 없고 성공 재생 전후 지문이 같은지 비교한다. 결과 저장 실패는 예약 INSERT 뒤 UPDATE에서, 커밋 실패는 같은 UPDATE의 지연 제약 trigger로 주입하여 업무 callback까지 실행된 것을 확인했다.

- 여덟 쓰기별로 저장점 성공 후 다른 연결의 그래프 행 잠금 요청이 실제로 대기하는지 확인한다. 새 그래프는 계정 행을 사용한다. 바깥 커밋 뒤에만 후행 잠금이 풀린다.
- 사건 폐기/복구·유지·갱신의 잠금 후 현재 상태 조회에 DB 오류와 취소 원인을 주입한다. 원래 DB 오류·저장 오류 분류·취소와 사용자 원인을 보존하며, 저장점 롤백 뒤 바깥 커밋이 성공해도 부분 적용이 없고 재시도·연결/예약 회복이 가능하다.
- 새 인수 시험은 최상위 3건·하위 56건, 총 59건이다. 코드 수준에서 필요한 저장 계약을 이미 충족하여 실행 코드를 수정하지 않았다.

## 실행 결과와 정리

- 전용 Docker 이미지·컨테이너·볼륨에서 합성 데이터만 사용했다. loopback 별도 포트, PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6, 기본 `vector(128)`·`all_layers`와 정식 001/009/010/011/012/013 마이그레이션 6개를 사용했다. 관련 모듈이 만든 vector/halfvec 임시 DB는 각 시험의 정식 준비/정리 경계를 사용했다. 기존 개발 DB는 사용하지 않았다.
- Go 1.27.1, `TEST_DATABASE_REQUIRED=1`, `go test -race -json -count=1 -p 1`로 실행했다. 새 행렬 묶음은 59건 통과했다. 이후 21개 파일의 통합 실행은 656건 통과·2건 실패·0건 건너뜀으로 전체 명령이 실패했다. 실패는 위 시험과 그 상위 시험이었다. 보완 뒤 해당 묶음만 다시 실행하여 4건이 통과했다.
- `(package, test)`별 마지막 결과는 **고유 시험·하위 시험 658건 통과·최종 실패 0건·건너뜀 0건**이다. 최상위 130건·하위 528건이다. 새 묶음과 통합 실행·재검증의 반복은 고유 수에 더하지 않았다. 기본 실행 마감은 새 행렬 240초·통합 300초·관련 재검증 180초다.
- 최종 `GO_BINARY=/Users/alphagone/sdk/go1.27.1/bin/go sh ./check-go.sh`에서 의존성 검증/빌드·전체 `go build ./...`·`go vet ./...`·`gofmt -l .`이 통과했다. 문서 링크·Markdown·계획 집계와 `git diff --check`를 확인했다.
