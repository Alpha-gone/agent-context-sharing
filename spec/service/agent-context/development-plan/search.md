# 검색 개발 계획

[전체 계획](../DEVELOPMENT_PLAN.md) · [기준 SDD](../sdd/search.md) · [작업 추적](traceability.md)

## 목표와 구현 범위

네 검색 채널, 일관 읽기, 홉 탐색·적재 보호, 결정적 결합·접기·예산과 평면 작업 컨텍스트 흐름을 새로 구현한다. SDD가 채택한 방식은 따르되 과거 측정값을 새 구현의 성능 근거로 사용하지 않는다.

- 설계 입력: [실행기](../sdd/search.md#검색-채널-실행기), [일관 읽기](../sdd/search.md#요청-단위-일관-읽기-구현-비교), [채널](../sdd/search.md#채널-구현), [홉 보호](../sdd/search.md#고연결-노드의-조회적재-보호), [라우팅](../sdd/search.md#질의-적응형-라우팅), [근거 선택](../sdd/search.md#근거-경로-보존-선택), [흐름](../sdd/search.md#작업-컨텍스트-흐름-조회).
- 예정 구현 영역: `internal/search`, `internal/store`의 SQL 검색·Cypher 홉·스냅숏 읽기, 서버의 인터페이스 주입.
- 다른 분야와의 경계: 임베딩 생성은 색인 계획, 외부 스키마는 MCP 계획, 채택 조건·정량 판정은 평가 계획이 소유한다.

## 개발 작업

### SEARCH-01

- [x] **검색 입력·주입 경계·동기화 스냅숏을 구현한다.**
- 선행: [ARCH-03](architecture.md#arch-03), [ARCH-04](architecture.md#arch-04), [DATA-03](data.md#data-03).

1. work_context·as_of·scope·budget를 검증하고 미지정 시각은 현재 UTC로 처리한다. 잘못된 시간대·음수·문자열은 DB·제공자 호출 전에 거부한다.
2. 저장·질의 임베딩 인터페이스를 정의한다. 질의 임베딩은 DB 경계 밖에서 생성한 뒤 읽기 전용 REPEATABLE READ 조정 스냅숏을 연다.
3. 각 읽기는 첫 질의 전에 같은 스냅숏을 가져오고 후보·홉·참조·출처를 한 커밋 상태로 조립한다. 읽기 연결·접근 기록·자리 반환은 아키텍처 경계를 사용한다.

- 산출물: 검색 입력·인터페이스·요청 읽기 경계.
- 완료 기준: 제공자 대기 중 스냅숏 연결을 점유하지 않고 읽기마다 같은 상태를 사용한다. 운영에 내용 판 재시도·읽기 방식 구성 키를 추가하지 않는다.

- 완료 근거: 2026-10-18 [검색 입력·동기화 스냅숏 경계 검토](../reviews/2026-10-18-search-01.md). 공통 모델의 입력 검증과 필드 오류를 연결하고 공백·문자 수·UTF-8·UTC·scope·음수를 DB/제공자 호출 전에 거부한다. 제공자 대기·실패·취소, 스냅숏 종료 실패·조립 취소의 원인 보존과 결과 비우기를 검증했다. 새 격리 DB에서 여섯 읽기의 후속 커밋 격리와 읽기 전용 REPEATABLE READ, 최소 풀의 연결/예약·읽기 자리 회복을 확인했다. search 90건·model 149건·store 20건, 고유 시험·하위 시험 259건의 최종 결과와 race·전체 build·vet·형식 검사가 통과했다. 실제 MCP 원문 해석·호스트·전체 검색 인수는 후속 범위이며 다음 권장 항목은 [SEARCH-02](#search-02)다.

### SEARCH-02

- [ ] **세 진입 채널과 독립 실패 처리를 구현한다.**
- 선행: [SEARCH-01](#search-01), [DATA-05](data.md#data-05), [DATA-07](data.md#data-07), [IDX-03](indexing.md#idx-03).

1. 의미 채널은 현재 모델·graph·활성·유효 조건과 거리 순서로 HNSW를 조회한다. 지원 판에서는 strict_order를 해당 트랜잭션에만 적용한다.
2. 키워드는 색인과 같은 simple 구성, 어휘 OR 조립·websearch_to_tsquery·ts_rank_cd를 사용한다. 시간 채널은 as_of 유효 조건과 recorded_at 내림차순을 적용한다.
3. 각 채널의 후보 상한·안정적 동점을 처리하고 병렬·순차 실행에서 같은 목록을 만들며 성공 빈 결과·장애·disabled를 나눈다.
4. 질의 임베딩 실패는 의미 채널만 실패로 기록한다. 진입 모두 실패하면 확장을 진입점 없음으로 실패 처리하고 전체 실패 조건을 판단한다.

- 산출물: 세 채널 질의·실행기·부분 상태와 대역/DB 표본.
- 완료 기준: 채널별 범위·순위·실패가 분리되고 풀 연결에 HNSW 설정이 남지 않는다. 시간 후보·하한 미달 의미 후보를 관련성 판정과 혼동하지 않는다.

### SEARCH-03

- [ ] **순위 역수 합과 결정적 정렬을 구현한다.**
- 선행: [ARCH-02](architecture.md#arch-02).

1. 채널별 순위 역수의 정확한 유리수 합을 비교하고 수학적 동점을 기록 시각 내림차순·식별자 오름차순으로 정렬한다.
2. 임시 진입 순위와 최종 순위에 같은 기준을 적용하고 기여 채널·진입점 거리·선택 전 rank를 보존한다.
3. 채널 입력 순서·맵 순회·병행 완료 순서를 바꾼 표본을 대조한다. 점수 정규화·채널 가중치·근사 동점 허용값은 두지 않는다.

- 산출물: 결합·정렬·메타데이터와 정확 동점 표본.
- 완료 기준: 같은 채널 목록은 실행 순서에 무관하게 같은 순위·기여·라우팅 입력을 만든다.

### SEARCH-04

- [ ] **정확한 홉 탐색 기준 구현을 만든다.**
- 선행: [DATA-04](data.md#data-04), [LIFE-04](context-lifecycle.md#life-04).

1. 깊이·label별 너비 우선 탐색으로 단일·다중 시작점, 방향·유형 필터, 세 참조·확정 사건 관계를 처리한다.
2. graph 경계·활성 상태·방문 집합·최단 거리를 강제하고 0홉은 시작 노드만 반환한다. 순환·동일 이웃은 한 번만 반환한다.
3. 한도 없음의 전체 이웃 기준 구현에서 반환 노드 사이 내부 간선과 최대 정상 참조를 완전하게 조립하고 안정적 순서·절단 경계를 정의한다.

- 산출물: 정확성 기준 홉 조회와 방향·순환·삭제·다중 진입 표본.
- 완료 기준: 참조·관계·거리·순서·절단이 SRS와 일치하며 응답 부분 그래프에 맞지 않는 간선이 섞이지 않는다.

### SEARCH-05

- [ ] **양수 상한의 후보 선택·본문·간선 적재 보호를 구현한다.**
- 선행: [SEARCH-04](#search-04), [DATA-05](data.md#data-05).

1. 활성 미방문 이웃 식별자만 최초 기준 정점·이웃 순으로 선택하고 남은 자리와 초과 확인 한 행까지만 읽는다. 초과 확인 노드의 본문은 적재하지 않는다.
2. 선택 노드의 본문을 묶음 조회하고 요청 label·확정 상태의 반환 노드 간선을 별도로 모두 조립한다. 마지막 홉의 불필요한 새 이웃 조회를 생략한다.
3. 작은 인접 표본과 정렬된 활성 후보·Cypher 존재 확인의 전환 전략을 구현한다. 기준 64는 결과 상한이 아니며 초과 덧셈은 포화 처리한다.
4. 양방향 질의·중복·다중 시작점을 합쳐 기준 구현과 같은 발견 순서·최초 절단을 보존한다.

- 산출물: 상한 후보·본문 묶음·내부 간선 질의와 전환 전략.
- 완료 기준: 작은 L에서 식별자 후보·본문 적재가 반환 범위에 제한되고 간선·참조는 완전하다. 내부 간선 O(L²), limit=0와 잔여 DB 스캔의 한계를 기록한다.

### SEARCH-06

- [ ] **홉 일관 읽기·공통 시간 예산·자원 회복을 구현한다.**
- 선행: [SEARCH-01](#search-01), [SEARCH-05](#search-05), [DATA-08](data.md#data-08).

1. 독립 홉은 시작 확인부터 본문·간선·참조까지 단일 읽기 전용 트랜잭션으로 처리하고 검색 홉은 기존 요청 스냅숏을 가져온다.
2. 두 홉 진입점에 시작·자리 대기·질의·조립 전체의 30초 예산을 적용하고 호출자의 더 짧은 마감·취소를 우선한다.
3. 후보/본문·확장/참조 사이 별도 폐기 커밋을 동기화하여 이전 커밋의 완전한 결과와 새 조회의 제외를 대조한다.
4. 실제 질의 마감·잠금 대기·내부 예산 소진을 관찰하고 오류의 빈 결과, 풀·읽기 자리·활성 트랜잭션 회복을 직접 검사한다.

- 산출물: 홉 읽기·시간 예산 경계와 동시 폐기·최소 풀 회귀.
- 완료 기준: 중단·읽기 종료·접근 기록 실패를 정상 truncated로 바꾸지 않고 최초 시작 부재/폐기는 not_found다. 독립 홉에 불필요한 4개 예약을 추가하지 않는다.

### SEARCH-07

- [ ] **접기·문자 예산·평면 흐름 응답을 구현한다.**
- 선행: [SEARCH-02](#search-02), [SEARCH-03](#search-03), [SEARCH-06](#search-06), [LIFE-08](context-lifecycle.md#life-08), [PERM-05](authorization.md#perm-05).

1. 결합 뒤 같은 근거·종류의 유사 파생을 대표 하나로 접고 접힌 수를 남긴다. 저장 노드·관리 기록은 삭제하지 않는다.
2. body의 유니코드 문자만 예산으로 센다. 상위 선택 단위가 처음 초과하면 멈추고 뒤의 짧은 후보로 채우지 않는다.
3. contexts·references·relations·검색 메타데이터를 평면 구조로 조립하고 반환 노드를 잇는 간선만 남긴다. rank·기여 채널·거리·출처·근거 상태·절단을 전달한다.
4. 일부 채널 실패·빈 결과·예산 절단·홉 상한 절단을 다른 부분 상태로 반환하고 모든 채널 실패만 오류로 다룬다.

- 산출물: 작업 흐름 서비스·접기·예산·출처 조립.
- 완료 기준: 출력이 예산·격리·정렬을 지키고 원문 경로 배열을 새로 추가하지 않는다. 상충·근거 무효·만료의 조회별 포함 정책이 유지된다.

### SEARCH-08

- [ ] **scope·전역 진입·질의 적응형 라우팅을 구현한다.**
- 선행: [SEARCH-07](#search-07).

1. local/global/auto의 진입점을 구현한다. 명시 global은 구성과 무관하게 전역 요약의 derived_from을 탐색한다.
2. 기본 auto와 baseline·global fallback의 설계 기본값을 적용한다. 전환 시 시간 후보가 상한을 먼저 차지하지 않게 전역 요약만 시작점으로 사용한다.
3. 적응형 옵션은 같은 초기 후보로 충분성·분산·사건·채널 일치 규칙을 결정적으로 적용하고 경로·이유 코드를 남긴다.
4. disabled·실패·요약 없음·의미 후보 하나·부족 임계값을 구분하고 적응형+baseline의 구성 위반을 거부한다. 평가용 강제 경로는 공개 입력으로 열지 않는다.

- 산출물: 진입점·라우터·이유 코드와 분기 표본.
- 완료 기준: 명시 scope가 우선하고 적응형 비활성은 기준 auto와 같다. 기본 활성화는 새 통제 평가를 통과한 뒤 별도 결정한다.

### SEARCH-09

- [ ] **근거 경로 보존 선택을 구현한다.**
- 선행: [SEARCH-07](#search-07), [SEARCH-08](#search-08).

1. 결합·접기된 후보 안의 확정 참조·관계만 사용하여 대표 후보에서 가까운 진입점/원천까지 경로를 찾는다.
2. 동률은 신규 연결 노드 수→후보 차수 합→context_id 배열 사전순으로 결정하고 경로 없는 비진입 후보를 제외한다.
3. 연결 근거 집합 전체를 대표 순위로 예산에 담고 최초 초과 집합에서 멈춘다. 후보 밖 탐색·새 점수·경로 배열을 추가하지 않는다.

- 산출물: 후보 부분 그래프 선택기와 결정성·예산·단절 표본.
- 완료 기준: 비활성은 개별 순위 절단과 같고 활성에서는 선택 경로가 예산 적용으로 끊기지 않는다. 운영 기본 false와 선택 전 rank를 유지한다.

### SEARCH-10

- [ ] **정확성·성능·채택 비교를 새로 측정한다.**
- 선행: [SEARCH-09](#search-09), [TEST-03](testing.md#test-03).

1. 기준/양수 상한 조회를 같은 허브·희소·조밀·삭제/미확정·다중 시작점 표본으로 비교하고 노드·본문·간선·참조·거리·순서·절단을 대조한다.
2. 식별자·본문·간선·참조 행, 본문 바이트, Go 할당·왕복·실제 DB 행/버퍼·지연을 각각 측정한다. 응답량과 DB 내부 비용을 구분한다.
3. AGE 경로 질의 후보는 고정 이미지의 공식 기능·파서 적합성을 확인한 뒤 같은 결과 조건에서 비교한다. 다음 안정판에서는 같은 비교를 반복한다.
4. 스냅숏·일관성, 라우팅·근거 선택·색인 대상은 평가 계획의 서로 다른 통제 비교로 연결한다.

- 산출물: 검색 정확성·자원·지연 측정과 후보 채택/보류 근거.
- 완료 기준: 새 측정의 조건·표본·실패·미측정을 기록하며 과거 구현의 숫자를 재사용하지 않는다. 개선 없는 후보를 운영 기본값으로 승격하지 않는다.
