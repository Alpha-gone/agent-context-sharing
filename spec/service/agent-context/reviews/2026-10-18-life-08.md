두 차이는 변경 전 코드와 계약의 대조로 확인했다. 변경 전 실행 재현을 수행했다고 주장하지 않으며 아래는 변경 후 실행 증거다.

- `OperationHistory`는 컨텍스트/관계 중 하나로 한정하고 같은 스냅숏에서 직접·팀 상속 소유자를 판정한다. 적용·거부를 시각/ID 순으로 읽어 판단 입력·계정·agent·대상 판·결과를 전달하며 그래프/대상을 재검사한다. 소프트 삭제 후에도 이력을 읽을 수 있다. 판단 입력은 불투명한 텍스트로 보존하여 원래 근거를 사람이 되짚도록 하며 ID 자동 추출·외부 원본 접근을 하지 않는다.
- `ContextImpact`는 역방향 `DERIVED_FROM`·`HAS_MEMBER`와 양방향 확정 관계를 너비 우선으로 탐색한다. 깊이·플랜·결과 수 제한으로 자르지 않으며 중복·순환을 방문 집합으로 종료한다. 폐기된 시작점은 허용하고 이웃은 기존 홉의 삭제 판정을 유지한다. `SUPERSEDES`·미확정/폐기 관계는 영향 확장에 쓰지 않는다. 기존 홉 실행 마감과 취소를 사용하며 실패 시 부분 결과를 반환하지 않는다. 조회는 상태·색인 접근 시각·업무 감사를 쓰지 않는다.
- 적용 기록은 기존 도메인 쓰기 트랜잭션에 남긴다. 거부 기록은 도메인 롤백 뒤 별도로 저장하며 멱등성 경계에서는 되돌린 저장점 밖의 같은 바깥 트랜잭션에 남길 수 있다. 거부 감사의 DB 장애는 저장 오류로, 취소는 원인을 보존하여 전달한다.
- 출처는 참조를 따라 원천까지 모아 정렬·중복 제거한다. 삭제된 원천도 출처 근거로 유지하며 파생·사건의 property나 순위 감점으로 저장하지 않는다. 기존 검색 응답의 출처 조회 실패 시 부분 응답 계약은 이번 작업에서 바꾸지 않았다.

## 실행 증거

전용 Docker 이미지·컨테이너·볼륨에 합성 데이터만 사용했다. loopback 별도 포트, PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6, `vector(128)`·`all_layers` 구성에서 정식 001/009/010/011/012/013 마이그레이션 6개를 적용했다. 기존 개발 DB는 사용하지 않았다.

| 검증 | 확인한 결과 |
|---|---|
| 적용·거부 이력 | 생성/갱신/폐기 후 판단 입력·판·계정·서로 다른 agent·UTC 결과 보존, 낙관적 충돌 후 독립 거부 기록, 관계의 판 없는 이력 |
| 저장 경계 | 바깥 롤백 시 적용 기록 제거, 저장점 실패 뒤 거부/완료 결과 커밋, 재생 시 한 번 기록, 단독/멱등성 거부 감사 실패의 부분 변경 없음·오류 분류·재시도 |
| 출처 | 세 출처·여러 근거·중첩 파생/사건·반복 입력·삭제된 원천의 집계, 다른 그래프/누락 대상 거부, 단독 호출 중 실제 참조 변경의 일관 읽기 |
| 영향 | 원천에서 12단계 파생·사건·확정 관계까지 완전 조회, 의미 관계 순환 종료, 역방향 참조·삭제/제안/폐기/대체 필터, 무변경 지문 |
| 접근·손상 | viewer/editor/다른 계정 거부, 직접·활성 팀 소유자 허용/팀 삭제 거부·복구 후 허용, 삭제 그래프 감사, 잘못된 감사 agent·판단/사유 거부 |
| 취소·반환 | 실제 PostgreSQL 테이블 잠금 대기 확인 뒤 세 조회 취소, 취소와 사용자 원인 동시 보존, 연결·예약 회복 |
| 관련 회귀 | 기존 현재 복구 채널·감사 보존·폐기 감사 결합·파생 이력 실패·요청 빈도·읽기 스냅숏과 검색 응답 조립 |

- Go 1.27.1의 `go test -race -json -count=1 -p 1 -timeout=180s`로 관련 모듈만 실행했다. 새 시험의 최초 빌드에서 존재하지 않는 helper 호출을 실제 API로 고쳤다. 이후 최초 묶음은 17건 통과·2건 실패·0건 건너뜀으로 전체 명령이 실패했다. 합성 시험의 판 증가·소유자 부여를 고쳐 두 시험만 다시 실행했으며 1건 통과·1건 실패였다. 남은 실패는 허용되지 않는 `node_keep` 멱등성 도구 이름을 `node_update`로 수정했다. 이후 수정·추가 묶음 8건과 관련 회귀 58건이 통과했다.
- `(package, test)`별 마지막 결과를 합쳐 **고유 시험·하위 시험 83건 통과·최종 실패 0건·건너뜀 0건**이다. 최상위 22건·하위 61건이며 store 66건·model 15건·search 2건이다. 새 LIFE-08 시험은 최상위 13건·하위 16건, 총 29건이다. 반복 실행은 고유 수에 더하지 않았다.
- `GO_BINARY=/Users/alphagone/sdk/go1.27.1/bin/go sh ./check-go.sh`의 최종 코드에서 의존성 검증·의존성 빌드·전체 `go build ./...`·`go vet ./...`·`gofmt -l .`이 통과했다. 문서 링크·Markdown·계획 집계와 `git diff --check`도 확인했다. 전체 저장소 시험은 실행하지 않았다.

- `internal/AGENTS.md`의 store·model 소유권과 기존 쓰기·읽기 경계를 유지한다. 새 스키마·설정·외부 API·프로젝트 용어·문서 경계는 없어 SRS·SDD·DOX·마이그레이션·용어집·운영 안내를 변경할 필요가 없었다. 개발 계획과 요청 기록을 갱신했다.
