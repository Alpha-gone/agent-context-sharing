## 변경

삭제와 복구 화면을 `삭제` 보기와 `?tab=restore`의 `복구 대상` 보기로 나눴다. 두 보기는 `aria-current="page"`를 단 기본 링크로 전환하고 각 보기는 자기 목록만 읽는다. 삭제 보기는 그래프 영향·이름 확인 양식·활성 노드를, 복구 대상 보기는 그래프 복구 수단과 웹 삭제·에이전트 폐기 노드를 함께 보여 준다. 목록 상한 밖의 삭제 노드도 `context_id`로 직접 열어 복구할 수 있다.

노드 삭제 안내는 SRS 「연쇄 영향 안내」의 계층별 항목만 표시한다. 원천은 근거로 삼는 활성 파생과 구성원으로 갖는 활성 사건, 파생은 근거로 삼는 활성 파생, 사건은 확정 관계 수이며 근거 무효 표시·관계 폐기 효과를 함께 알린다. 그래프 이름 확인은 명시적 레이블·입력 위 안내·자동 완성/교정 비활성화를 적용했고 정확히 같은 이름만 삭제를 호출한다.

삭제된 그래프에서는 노드 삭제·복구 수단을 표시하지 않고 그래프 복구를 먼저 안내한다. 직접 삭제만 웹 복구 수단을 제공하고, 자동 삭제는 그래프 목록의 복구 요청과 운영자 처리 경로를 안내한다. 노드 조작 뒤에는 조작한 보기로 303 이동한다. 조회 단계마다 취소를 확인하여 후속 조회와 렌더링을 중단한다.

운영자 화면은 대기 요청의 그래프 이름·식별자와 요청 계정·시각만 표시하고 행 선택으로 처리 확인에 들어간다. 확인은 같은 그래프의 가장 오래된 요청과 처리 효과를 보여 주며 목록에서 바로 처리하지 않는다. 마지막 소유자 오류는 삭제·복구와 운영자 처리 모두 409로 사상했다. 상태 변경은 기존 저장소의 그래프 잠금 뒤 소유자·상태·요청 재판정과 감사 트랜잭션을 그대로 사용한다.

## 실행 증거

- **신규 81건 포함 웹 743건 통과**: 최상위 84개·하위 659개, `-race -count=1`·필수 DB 설정. 실패·건너뜀 0, race 없음. 신규는 최상위 10개·하위 71개다. 기존 Node.js 시각화·키보드 합성 시험도 실행했다.
- 삭제·복구 단위 6건은 두 보기의 목록·수단 분리, 잘못된 보기 400, 보기와 맞지 않는 선택 404, 삭제된 그래프의 수단 제거와 직접/자동 삭제의 복구 안내, 계층별 영향 항목을 확인했다. 네 동작×여섯 결과×래핑 여부에서 상태·고정 안내·내부 원문 비노출과 성공 이동, 이름 불일치의 호출 생략, 여섯 조회 지점의 장애/취소 중단도 확인했다.
- 운영자 단위 시험은 그래프·컨텍스트·시각화 조회 없이 목록과 처리 확인을 그리고, 같은 그래프의 가장 오래된 요청을 선택하며 없는 요청 404·잘못된 식별자 400과 처리 오류의 래핑 사상을 확인했다.
- 실제 DB·서명 세션·TLS에서 그래프 영향(활성 3·관계 0·차단 계정 2)과 원천·사건 영향, 원천 삭제의 근거 무효·비연쇄를 확인했다. 저장량을 줄이는 삭제는 한도 초과 계정에서도 통과하고 복구는 409로 거부됐으며, 한도 없는 복구는 저장량을 원래 값으로 되돌렸다. 반복 복구는 409, 열람자의 GET/POST는 403이다.
- 이름 불일치 400 뒤 정확한 이름의 직접 삭제가 유예 시각 없이 저장됐다. 삭제된 그래프의 노드 삭제는 409로 거부되고 그래프 복구는 303으로 적용됐다. 화면 인가 뒤 저장 변경 직전에 공동 소유자의 등급을 회수하면 노드·그래프 변경 모두 404로 거부되고 상태가 바뀌지 않았다.
- 실제 자동 삭제 그래프에서 요청 전 운영자 처리는 404였다. 과거 소유자와 생성자의 요청 뒤 목록에 두 요청이 표시되고 본문 표식은 나오지 않았으며, 처리 확인은 먼저 요청한 과거 소유자를 가리켰다. 요청 없는 직접 삭제 그래프는 확인·처리 모두 404로 상태가 유지됐다.
- 운영자 처리 뒤 삭제·유예 상태가 해제되고 직접 소유자는 요청자 하나였다. 운영자·생성자는 등급이 없고 운영자는 그래프 상세에서 404다. `operator_restore` 감사의 행위자가 운영자이며 처리된 요청은 대기 목록에서 사라지고 재처리는 404다.
- `check-go.sh`의 의존성 확인·빌드·vet·gofmt가 통과했다. 웹 SDD·개발 계획·설계 진입점·README/서비스 색인·요청 기록·근거를 정합화했다. 처리기·템플릿·스타일은 기존 웹 DOX 소유 안의 변경이므로 DOX와 부모 색인을 유지했다. 요구사항·용어·SQL 스키마·환경 설정·저장소 계약은 바뀌지 않아 해당 정본은 유지했다.

```sh
TEST_DATABASE_URL='<WEB-05 전용 합성 URL>' TEST_DATABASE_REQUIRED=1 go test -race -json -count=1 -timeout=240s ./internal/web
GO_BINARY="$(command -v go)" sh check-go.sh
```

공유 DB 이미지에서 PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6을 확인했다. 별도 `acs-web05-20261024` 컨테이너·`agent-context.task=web05` 라벨·tmpfs·임시 IPv4 loopback 포트와 합성 자격을 사용했다. 시험별 자식 DB를 정식 마이그레이션으로 준비하고 종료 후 자식 DB·시험 연결 0, 이 작업의 컨테이너/볼륨 잔류 없음과 기존 개발 컨테이너 보존을 확인했다. 원시 근거는 세션 임시 폴더의 `acs-web05-web.json`·`acs-web05-static.log`다.

첫 운영자 통합 실행은 시험 DB의 유예 기간을 지정하지 않아 자동 삭제 준비 단계에서 실패했다. WEB-03 인수와 같은 1일 유예 정책을 지정한 뒤 해당 시험과 전체 모듈 실행이 통과했으며 반복 실행을 중복 합산하지 않았다. 기존 WEB-02 조회 경계 시험의 삭제 목록 표본은 목록을 읽는 복구 대상 보기로 대상을 옮겼다.

Modern Web Guidance의 `accessibility`·`forms`에서 탭 역할을 흉내 내지 않는 기본 링크 전환, 명시적 `label for`, 입력 위 안내와 `aria-describedby`, 표 제목·열 머리글을 확인해 반영했다. 키보드 동작이 없는 `role=tab`·이름 붙인 `section` 영역은 추가하지 않았다.

## 남은 범위

WEB-06~09의 나머지 화면과 전체 웹 분야 통합, 실제 브라우저 제출·Tab/키보드·스크린리더 음성, 실제 호스트·Tunnel·운영 배포는 미실행이다. 실제 브라우저 인수는 WEB-09에서 CDP로 조작하는 headless Chrome과 수동 Safari로 수행할 예정이다. DB/TLS·합성 HTML 검사가 실제 브라우저나 보조 기술 인수를 대신하지 않는다. 현재 브랜치 upstream이 없어 원격 차이는 확인하지 않았으며 커밋·푸시·배포는 수행하지 않았다.
