# #273 임베딩 비교 전역 전환 신호의 유효성 기준 시각

## 결정과 변경

임베딩 비교의 신호 단계가 의미·키워드 후보를 입력의 고정 조회 시각(`as_of`)으로 조회하던 동작을 실제 검색과 같은 현재 시각 기준으로 바꿨다. `service.flow`는 두 채널의 파생 유효성(`valid_to >= current`)을 실행 시점의 현재 시각으로 판정하고 `as_of`는 시간 채널에만 쓴다. 신호가 `as_of`를 쓰면 그 시각과 현재 사이에 만료된 파생이 신호에만 남아, 조정 단계의 전역 하한과 오통과·오탈락이 실제 전환 규칙과 다른 후보 집합에서 계산된다.

질의 하나의 신호 계산을 `embeddingQuerySignal`로 분리했다. 임베딩 호출 수·후보 상한·신호 필드와 측정 단계는 바꾸지 않았다. 신호와 측정의 질의 임베딩 중복(#274)은 이 변경 범위 밖이다. [평가 설계](../sdd/evaluation.md#임베딩-비교-실행-계약)와 [시험 설계](../sdd/testing.md)에 기준 시각과 회귀 시험을 명시했다. 요구사항·추적표·DOX의 소유권과 구성은 바뀌지 않아 유지했다.

## 검증

- 새 통합 시험은 현재보다 한 시간 전에 만료된 파생만 질의어와 일치하는 그래프를 만든다. 만료 전 시각의 키워드 조회로 표본이 유효함을 먼저 확인하고, 신호가 이 파생을 키워드 후보로 세지 않는지 대조한다.
- 신호의 기준 시각을 과거 고정 시각(현재-30일)으로 덧씌우면 같은 시험이 `Keyword:true`로 실패했다. 이슈의 증상과 같다.
- Go 1.27.3, 개발 DB 서버의 작업 전용 기준 DB vector(768)와 `.env`의 비교 DB `acs_small` vector(128)·`acs_half` halfvec(768)(각각 마이그레이션 001~014 적용), `TEST_DATABASE_REQUIRED=1`, `-p 1`의 필터 없는 `./cmd/eval` 실행: 933건이 실패·건너뜀 없이 통과했다.
- `check-go.sh`의 의존성 빌드·`go build`·`go vet`·`gofmt`·`govulncheck` 검사 통과.
- 검증 후 작업 전용 기준 DB를 삭제했다. 실제 외부 제공자·운영 배포는 미실행이다.
