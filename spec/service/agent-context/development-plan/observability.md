# 관측성 개발 계획

[전체 계획](../DEVELOPMENT_PLAN.md) · [기준 SDD](../sdd/observability.md) · [작업 추적](traceability.md)

## 목표와 구현 범위

업무 감사와 별개인 구조화 지표·여섯 진단 파일·흐름 연결·보존·상한·실패 처리를 새로 구현한다. 파일의 실제 저장·재시작 보존과 정보 비노출을 완료 기준으로 둔다.

- 설계 입력: [지표](../sdd/observability.md#지표-수집-지점), [감사 조회](../sdd/observability.md#감사-기록의-조회), [진단](../sdd/observability.md#종류별-진단-로그), [경로](../sdd/observability.md#경로권한다중-인스턴스), [상한](../sdd/observability.md#회전보존과-총상한), [실패](../sdd/observability.md#기동실행-중-실패와-종료).
- 예정 구현 영역: `internal/diagnostic`, 각 처리 경계의 이벤트 인터페이스, 감사 조회 API와 로그 볼륨 구성.
- 다른 분야와의 경계: 업무 감사 저장은 도메인 트랜잭션, 시간 회차는 운영, 감사 화면은 웹 계획이 소유한다.

## 개발 작업

### OBS-01

- [ ] **종류·허용 필드·흐름 식별자 계약을 구현한다.**
- 선행: [ARCH-03](architecture.md#arch-03).

1. request/auth/search/index/management/system 종류와 공통 UTC 시각·instance·boot·stage·result·reason_code를 정의한다.
2. 서버 요청 correlation_id, 인가 flow_id, 비동기/주기 job_id, test_run_id를 구분한다. request_id·토큰·해시를 상관 키로 사용하지 않는다.
3. 계정·대상 확인 전에는 검증되지 않은 ID를 기록하지 않고 identity_verified=false·단계·필드만 허용한다.
4. 호출자가 요청·응답·error·URL·헤더·본문 객체를 넘길 수 없는 좁은 이벤트 인터페이스를 만든다.

- 산출물: 이벤트 타입·허용 목록·종류별 파일 대응과 안전 필드 시험.
- 완료 기준: 업무 패키지 import 없는 diagnostic 경계가 민감정보 원문·임의 오류를 입력으로 받지 않는다.

### OBS-02

- [ ] **영속 파일·권한·단일 기록자·공유 잠금을 구현한다.**
- 선행: [OBS-01](#obs-01), [ARCH-05](architecture.md#arch-05).

1. 설정한 루트/instance 아래 여섯 basename을 만들고 디렉터리 0700·파일 0600, 소유·영속성·경로를 기동 전에 검사한다.
2. 경로 구분자·점 경로·심볼릭 링크를 거부하고 instance별 기록자 잠금으로 동시 같은 ID 기동을 차단한다.
3. 저장소 전체의 별도 공유 파일 잠금을 최대 1초로 획득하여 검사·정리·쓰기 예약을 직렬화한다.
4. 재시작은 기존 파일에 append하고 이전 boot와 새 boot를 구분한다. 기존 파일을 덮어쓰거나 공개 자산에 연결하지 않는다.

- 산출물: 파일 준비·잠금·권한·재시작 처리.
- 완료 기준: 준비 실패는 요청 수신 전에 실패하고 중복 instance·경로 위조·권한 오류가 기존 로그를 변경하지 않는다.

### OBS-03

- [ ] **유한 대기열·JSON Lines·이벤트 크기를 구현한다.**
- 선행: [OBS-02](#obs-02).

1. 인스턴스 공용 대기열에 최대 1024건·16 MiB 두 상한을 동시에 적용하고 enqueue 실패를 즉시 누락으로 집계한다.
2. 개행 포함 16 KiB 이벤트를 한 JSON 줄로 기록하고 선택 필드를 줄여 fields_omitted를 표시한다. 필수 외피도 못 담으면 누락한다.
3. 파일 쓰기를 직렬화하고 요청 goroutine·본문을 대기열에 넣지 않는다. 문자열 줄바꿈·과대 필드·잘못된 이벤트를 시험한다.

- 산출물: 기록 루프·대기 상한·인코더·누락 집계.
- 완료 기준: 포화 상태가 업무 요청을 무한 대기시키지 않고 모든 정상 행이 독립 JSON으로 해석된다.

### OBS-04

- [ ] **날짜·크기 회전·보존·전체 상한을 구현한다.**
- 선행: [OBS-03](#obs-03).

1. 다음 이벤트로 10 MiB에 도달하기 전 또는 UTC 날짜 변경 때 닫기·고유 회전명·새 활성 파일 생성을 수행한다.
2. 7일 보존·물리 정리 최대 1시간, 종류별 활성 포함 10개/100 MiB, instance 600 MiB, 저장소 전체 1 GiB를 적용한다.
3. 기동·회전·매시간·새 기록 전의 동일 정책을 사용하고 이전 instance 디렉터리도 전체 계산에 포함한다.
4. 혼합 유효/만료 파일은 유효 이벤트를 보존하는 제한된 정리로 처리한다. 사용 중 활성 파일은 삭제하지 않고 공간이 부족하면 기록을 누락한다.

- 산출물: 회전·만료·크기 정리·공유 쓰기 예약.
- 완료 기준: 동시 instance 쓰기에도 총상한을 넘지 않고 유효 로그를 잘못 제거하지 않는다. 고정 정책을 새 배포 키로 열지 않는다.

### OBS-05

- [ ] **요청·인증·검색·색인·관리 흐름을 계측한다.**
- 선행: [OBS-03](#obs-03), [MCP-08](mcp.md#mcp-08), [AUTH-09](authentication.md#auth-09), [SEARCH-07](search.md#search-07), [IDX-05](indexing.md#idx-05), [LIFE-08](context-lifecycle.md#life-08).

1. 수신·인증·등급·도메인·검색·색인·응답의 단계별 지표를 원래 처리 지점에서 얻어 종류별 이벤트로 전달한다.
2. 관계 실패를 인자·행위자·권한·끝점·계층·시간·순환·쓰기·감사·커밋으로 구분하고 실제 결과만 committed/rolled_back/unknown으로 기록한다.
3. 인증 실패·만료·개별/계열 폐기·유휴·재사용·결합·저장 장애를 분리한다. 검색의 채널·경로·이유·후보·선택·문자 집계는 결합 전후에 수집한다.
4. 색인 큐 상관 ID는 등록 세대와 같이 전달하고 무효 확보가 새 세대 ID를 덮지 않게 한다. 요청 없는 회차는 job_id로 추적한다.

- 산출물: 종류별 계측·흐름 연결과 안전 원인 코드.
- 완료 기준: 로그인 반복·관계 실패·비동기 색인의 원인과 경계를 연결할 수 있으며 원문·URI·지문·저장 결과가 파일에 복제되지 않는다.

### OBS-06

- [ ] **감사 통합 조회·보존 예외·복구 대기를 구현한다.**
- 선행: [DATA-03](data.md#data-03), [LIFE-07](context-lifecycle.md#life-07), [PERM-02](authorization.md#perm-02).

1. operation_log와 web_audit_log를 각각 graph·기간·시각/ID 커서로 읽고 한 페이지 크기로 합친다.
2. 소유자 접근과 플랜의 그래프 페이지 값을 적용한다. 직접/상속 소유자 근거·미처리 요청·운영 복구 부여 기록을 보존 정리에서 보호한다.
3. restore_request와 후행 operator_restore의 차이로 대기를 계산하고 별도 대기 상태를 저장하지 않는다.

- 산출물: 감사 조회·페이지·복구 대기와 정리 보호 API.
- 완료 기준: 같은 시각의 두 기록을 안정적으로 이어 읽고 일반 정리 뒤 현재 폐기 복구·처리 완료 판정이 바뀌지 않는다.

### OBS-07

- [ ] **파일 장애·stderr·부분 쓰기·종료를 구현한다.**
- 선행: [OBS-04](#obs-04).

1. 파일·회전·정리·용량·대기 실패를 종류·원인·누적 누락으로 stderr에 알리고 같은 원인은 30초에 한 번만 출력한다.
2. 실행 중 진단 실패가 이미 커밋된 업무를 되돌리지 않게 하고 억제 기간의 누락도 합산한다.
3. 부분 쓰기의 잘린 마지막 행을 다음 append 전에 격리·보고한다. 종료는 최대 5초 flush 후 남은 이벤트를 누락으로 보고한다.

- 산출물: 안전한 실패 출력·복구·flush 경계.
- 완료 기준: 파일·stderr에 같은 민감정보 제한이 적용되고 누락을 사후 성공으로 바꾸지 않는다. 실제 stderr 수집이 없으면 전달 완료를 주장하지 않는다.

### OBS-08

- [ ] **실제 파일·재시작·다중 instance 인수를 수행한다.**
- 선행: [OBS-05](#obs-05), [OBS-06](#obs-06), [OBS-07](#obs-07).

1. 여섯 종류의 정상·경고·실패를 실제 파일에 기록하고 분류·JSON·권한·흐름·boot를 검사한다.
2. 시험 시계·용량 주입으로 각 상한·회전·7일 만료·공유 잠금 경합·재시작 append·슬롯 교체를 소진한다.
3. 읽기 전용·디스크 부족·부분 쓰기·잠금 실패·5초 flush와 토큰/본문/질의/URI 표본의 비노출을 파일·stderr 모두에서 검증한다.

- 산출물: 실제 진단 저장 인수와 누락·회복·총상한 결과.
- 완료 기준: 파일 저장·보존·보호가 새 기록기에서 관찰되고 DB 감사 성공으로 파일 인수를 대신하지 않는다.
