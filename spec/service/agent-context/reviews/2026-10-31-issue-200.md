# #200 평가 실행기 모드 전용 옵션과 지속 평가 판정 매핑

- 대상: [이슈 #200](https://github.com/Alpha-gone/agent-context-sharing/issues/200).
- 기준: `dev`의 `9cda9e5`, 작업 브랜치 `fix/200-eval-mode-options`.

## 원인과 변경

검색 단위·외부 원본 비교의 허용 목록에 실제 플래그 `repeat` 대신 `repeats`가 있어 `-repeat 10`을 함께 지정하면 통제 조건 위반으로 거부했다. 지속 평가와 기존 업무 효과 비교는 쓰지 않는 컨텍스트·질의·단계·색인 대상·예산을 받아도 무시했고, 적응형·일관성·적대적 비교도 `-stages`를 무시했다. manifest의 지속 평가 판정은 상태·기록 위반만 not_accepted로 바꾸어 `failed/quality_regression`이 출처·독립 단위 검사를 거쳐 deferred가 되었다.

허용 목록을 `repeat`으로 정정했다. 지속 평가는 `-repeat`·`-max-hops`·`-max-hop-nodes`·`-out`만, 기존 업무 효과 비교는 `-business`·`-out`만 받도록 기존 확장 과업·입력 고정 비교와 같은 방식의 허용 목록을 입력 읽기·DB 구성 확인 전에 둔다. 적응형·일관성·적대적 비교에 지정한 `-stages`는 기존 모드 전용 옵션 검사에서 거부한다. manifest가 만든 지속 평가 인자는 이미 입력 연결에서 고정 예산 512와 대조한 `-budget`을 전달하지 않는다. 지속 평가의 `failed`는 품질 회귀와 상태·기록 위반을 구분하지 않고 not_accepted로 요약한다.

정본은 [평가 모드 배타성](../sdd/evaluation.md#검증을-가능하게-하는-설계)·[manifest 결과 묶음](../sdd/evaluation.md#반복통계와-실행-순서)과 [시험 설계](../sdd/testing.md#테스트-계층)에 반영했다. 변환 모드가 쓰지 않는 검색 옵션은 이슈 범위 밖이라 바꾸지 않았다. 스키마·설정·공개 API는 변경하지 않았다. DOX pass에서 구조·소유권·색인 변경이 없어 기존 DOX를 유지했다.

## 회귀와 검토

Go 1.27.1, 고정 PostgreSQL/AGE 이미지 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`의 전용 합성 컨테이너를 사용했다. 정식 7개 마이그레이션을 vector(768)·vector(128)·halfvec(768) DB에 각각 적용하고 `TEST_DATABASE_REQUIRED=1`로 DB 건너뜀을 금지했다. 기존 개발·다른 시험 DB는 사용하지 않았다.

- 수정 전 코드에 새 단위 시험 3개를 적용하여 모두 실패를 재현했다. `-continual -contexts`가 DB 구성 확인까지 진행했고, manifest 지속 평가 인자에 `-budget=512`가 포함됐으며, `failed/quality_regression`이 deferred로 요약됐다.
- 수정 후 지속·업무 효과 비교의 다섯 데이터·검색 옵션과 적응형·일관성·적대적 비교의 `-stages`가 입력 전에 거부된다. 검색 단위·외부 원본 비교의 `-repeat=10`, 지속 평가의 반복·홉 옵션과 manifest 지속 평가 인자는 사전 검사를 통과한다. 합성 판정에서 품질 회귀·상태 위반 `failed`는 not_accepted, 독립 단위 부족 보류와 `passed`는 deferred다.
- 지속·비교 모드에 공통 `-contexts`·`-stages`를 넘기던 정리 실패·색인 미완료·신호 취소 DB 시험 세 개는 모드별 인자로 조정했다.
- `go test -race -p 1 -json ./cmd/eval -count=1 -timeout=40m`에서 868건이 실패·건너뜀 없이 통과했다(231.38초). 기준 `9cda9e5`의 같은 실행은 865건 통과이며 차이는 새 시험 3건이다. 건수는 하위 사례를 포함한다.
- 시험 뒤 기본 합성 DB에 활성 평가 그래프 12개가 남았다. 기준 코드의 별도 합성 DB에서도 같은 이름 구성의 12개가 남아 기존 정리 실패 시험의 잔류로 확인했고 이번 변경에서 다루지 않았다. idle transaction은 0개였다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check` 통과. 변경 문서의 상대 링크·앵커를 확인했다.
- 두 소유 컨테이너·익명 볼륨과 기준 비교용 worktree를 정리했고 잔류 없음을 확인했다. 기존 자원·개인 IDE 파일은 보존했다.
