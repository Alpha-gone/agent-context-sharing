# IDX-08 색인 준비·시험 경계 모듈 인수

- 기준: [IDX-08](../development-plan/indexing.md#idx-08), [색인 큐](../sdd/indexing.md#색인-작업-큐), [테스트 설계](../sdd/testing.md#임베딩-제공자-실연결-테스트).
- 범위: 그래프 준비 API, 현재 구현의 공개·소비·평가 연결과 합성 제공자 인수, 실제 API 시험의 실행 경계. 실제 Gemini 전송·품질/비용 측정은 범위 밖이다.

## 발견 사항과 변경

| ID | 영향도 | 발견 사항 | 처리와 검증 |
|---|---|---|---|
| IDX08-R1 | 중간 | DB 없는 실연결 시험의 최대 두 번 호출이 순차 코드에만 의존했고 URL·DB 호출 예산 시험은 태그 안에 있어 기본 회귀에 포함되지 않았다. | 두 실제 진입 시험만 태그에 두고 같은 검증 흐름을 로컬 TLS 합성 시험에 사용한다. 전송 계층에서 2/3회 상한을 강제하고 URL 옵션·fragment·중복 sslmode를 검증한다. 기본 빌드 제외, 실제 수신 횟수와 자격·주소 거부를 확인했다. |
| IDX08-R2 | 중간 | 격리 DB 생성 뒤 주소/풀 조립이 실패하면 정리 등록 전에 끝날 수 있었다. | DB 생성 직후 정리를 등록하고 연결 풀 종료가 먼저 실행되도록 한다. 성공한 색인·검색과 형상 전환/롤백 회귀 뒤 임시 DB 잔여 0을 확인했다. |

- 위 사항은 수정·검증 완료다. 준비 API는 기존 단일 SQL 계약을 유지하며 새 인수 표본으로 검증했다. 제공자·저장소 운영 동작과 환경 키·기본값·벡터 스키마·마이그레이션은 변경하지 않았다. 확인된 미해결 결함은 없다.
- 실연결은 합성 문서·질의만 사용하고 고정 공식 HTTPS 주소·인증서 검증·유한 timeout·redirect 거부를 유지한다. 복제 transport의 연결 재사용을 끄고 호출 상한을 강제하며 작업자 반복 루프·자동 재시도를 사용하지 않는다. 제공자 자원과 시험 DB는 실패·종료 정리 경계를 가진다.
- DOX pass: 새 패키지·실행기·소유권 경계가 없어 DOX는 유지한다. 테스트 SDD와 README의 합성/실연결 설명을 정합화하고 기존 용어·SRS·평가 계약·과거 기록을 보존했다. index의 기존 임시 DB 준비 코드를 이번 모듈 시험에서도 재사용하도록 정리했다.

## 검증 결과 — 2026-10-17 14:19 KST

- Go 1.27.1 darwin/arm64, 고정 Dockerfile의 전용 컨테이너·새 볼륨·loopback 임시 포트·합성 자격에서 PostgreSQL 18.6 / AGE 1.8.0 / pgvector 0.8.6 / Linux aarch64를 사용했다.
- **고유 시험·하위 시험 55건 통과**: store 9·index 13·migrate 15·eval 18, 최상위 17개·하위 38개. 신규 모듈 33건·관련 회귀 22건이며 `-race -count=1`, `TEST_DATABASE_REQUIRED=1`을 적용했다. 최종 범위의 실패·건너뜀은 0이다.
- 실제 INSERT가 자문 잠금에서 대기하는 동안 작업 삭제·벡터 교체를 숨긴 커밋 전 상태를 읽어 pending·현재 모델 누락을 함께 판정했다. 커밋 뒤에는 준비 완료가 됐다. vector·halfvec 양쪽에서 각 준비 판정이 SQL 한 번임을 tracer로 확인했다. 빈 큐의 미색인·옛 모델, 현재 벡터가 있는 pending/failed, 두 계층 구성·삭제 제외·복구 후 누락과 취소·연결/예약 회복도 대조했다.
- 로컬 TLS 대역의 지연 중 유효 리스는 중복 호출되지 않았고 공개 뒤 준비 완료가 됐다. 취소는 HTTP 요청에 전달되며 미완료 리스는 준비 완료가 되지 않았다. 429/503은 한 번 호출 뒤 재시도 대기로, 비일시 오류·차원 불일치·다섯 번째 실패는 failed로 남았다. 다른 그래프의 실패 상태·예산을 보존하고 준비 판정에 섞지 않았다.
- 실제 행 잠금으로 확보되지 않는 작업도 평가 준비를 거부했다. 기본·지속·적대적·일관성·적응형의 다섯 평가 CLI는 미완료 색인에서 종료 코드 1이고 정상 보고서를 생성하지 않았다. 상한의 마지막 회차 성공은 준비 완료로 인정했다.
- 태그 안 실연결과 같은 흐름을 합성 TLS로 실행해 문서·질의 768차원 검증은 2회, 새 DB의 두 문서 색인·질의 검색은 3회로 끝났다. 현재 모델 저장·큐 완료·의미 채널 기여·합성 정답 1위·다른 그래프 결과 없음과 실제 수신 횟수를 확인했다. 추가 호출은 전송 전에 거부됐다. 합성 순위는 실제 모델 품질 실증이 아니다.
- **태그 보호 경계 3건은 예상된 실패로 별도 확인**했다. 실제 키를 제거한 두 진입 시험은 키 부재로 실패했고 합성 키·비루프백 DB 주소는 DB 연결 전에 실패했다. 기본 빌드에는 두 실제 진입 시험이 없었다. 이 세 거부는 위 55건의 통과 수에 합산하지 않는다. 실제 Gemini API를 호출하지 않았다.
- 최초 취소 표본은 대역이 요청 본문을 읽지 않은 채 대기하여 서버 쪽 취소 통지를 확인하지 못했다. 본문 수신 뒤 대기로 수정하고 영향받은 index 모듈 13건을 재실행해 통과했다. 위 55건에는 최종 결과만 반영하고 중복 합산하지 않는다. 나머지 42건은 코드가 바뀌지 않아 첫 실행 결과를 유지했다.
- 전체 의존성·build·vet·gofmt와 문서 상대 링크·앵커 150개·계획 수·diff 검사를 통과했다. 시험별 DB를 모두 정리한 뒤 기본 idx08·postgres만 남은 것을 확인했고 소유 라벨을 확인한 컨테이너·볼륨·이미지를 정리하여 잔여 0을 확인했다. 사용자 Compose·IDE 변경을 보존했으며 커밋·푸시는 수행하지 않았다. 전체 24/124개 완료·100개 미착수이며 다음은 DATA-09다.
