# #267 웹 토큰별 폐기 조회와 제한 캐시

## 원인과 변경

- 웹 검증의 캐시 만료 시 전체 유효 폐기 ID를 읽어 map을 바꿨다. 검증 요청 하나가 DB 폐기 행 수만큼 조회·할당하는 구조였다. authStore의 목록 조회를 IsTokenRevoked 단건 조회로 교체했다.
- 정상 판정과 정상 부재를 jti별 10초 동안 캐시하고 완료 캐시는 최대 4,096개 FIFO로 제한한다. 같은 토큰의 동시 미스만 합치며 다른 토큰은 독립적으로 조회한다. 진행 중 적재 슬롯은 성공·실패 모두 제거한다. 캐시 축출은 다음 단건 조회로 이어지고 인증을 우회하지 않는다.
- 로컬 Revoke가 공유 DB에 커밋된 뒤 즉시 양성 판정을 넣고 같은 jti의 진행 중 적재에도 폐기를 표시한다. 해당 판정이 FIFO에서 축출돼도 오래된 부재 결과가 폐기를 되돌리지 못한다. 원격 폐기의 10초 경계·재시작 반영, 5초 누적 조회 예산·대기자 재시도·취소·ErrUnavailable 분류를 유지한다.
- 실패는 정상 부재로 캐시하지 않는다. 실패한 jti의 적재자·대기자는 fail closed하고, 다른 jti의 유효 캐시는 계속 사용할 수 있다. DB 장애의 HTTP 500 사상·원문 비노출과 공개 키/Bearer 정책은 유지한다.
- [인증 정본](../sdd/authentication.md#토큰-검증)·[시험 설계](../sdd/testing.md)와 [공식 근거](../reference.md#267-웹-토큰별-폐기-조회와-제한-캐시)를 갱신했다. 스키마·환경 키·예시 값·요구사항·개발 계획·DOX 소유권은 유지했다. 기존 목록 함수는 소규모 보존/만료 시험용으로 남기고 운영 웹 검증의 인터페이스에서 제외했다.

## 100만 행 표본

`.env`의 TEST_DATABASE_URL·TEST_DATABASE_REQUIRED=1로 시험별 DB를 생성하고 정식 마이그레이션을 적용했다. 유효 폐기 행 0개·1,000,000개를 순서대로 준비하고 검증 캐시가 빈 서비스에서 측정했다. 실제 폐기된 서명 세션 하나도 표본에 포함했다. 자기 DB만 정리하며 공유 DB의 기존 스키마·폐기 행은 변경하지 않았다.

| 구현·판정 | 폐기 행 수 | 검증 시간 | 조회 | 캐시 판정 수 |
|---|---:|---:|---|---:|
| 기준 정상 세션 | 1,000,000 | 217.158083ms | 전체 목록 1회 | 1,000,000 |
| 변경 후 정상 세션 | 0 | 2.202417ms | 단건 1회 | 1 |
| 변경 후 정상 세션 | 1,000,000 | 2.817250ms | 단건 1회 | 1 |
| 변경 후 폐기 세션 | 1,000,000 | 0.956042ms | 단건 1회 | 2 |

기준 측정은 race 없이, 변경 후는 race로 실행했다. 단일 로컬 합성 표본의 관찰값이며 지연 개선률이나 운영 SLO로 일반화하지 않는다. 이 환경에서는 기존 100만 행도 5초를 넘지 않아 500 타임아웃 자체는 재현하지 않았고, 전체 행 적재·메모리 증가와 새 구현의 5초 안 판정·단건 동작을 확인했다. EXPLAIN (ANALYZE, BUFFERS, TIMING OFF)은 revoked_token_pkey의 Index Scan, 실제 반환 1행을 보였다.

## 회귀·검증

- 서로 다른 8,193개 jti를 조회해 완료 map·FIFO가 4,096개를 넘지 않으며 최신 항목 적중·축출 항목 단건 재조회를 확인했다.
- 과거 DB 부재 결과를 대기시킨 상태에서 로컬 폐기하고 그 양성 항목을 FIFO에서 축출한 뒤에도 진행 중·후속 요청이 거부된다. 다른 jti는 느린 조회를 기다리지 않고 해당 실패도 전파받지 않는다. 실패한 토큰을 정상 부재로 적재하지 않는다.
- 기존 실제 DB의 로컬 즉시 거부·원격 10초 직전/경계·재시작·서명 키 회전·12시간 만료와 단일 적재/대기자·5초 누적 예산·취소/저장소 오류 분류 시험이 모두 통과했다.
- Go 1.27.3, `go test -race -json -count=1 ./internal/authz`: 하위 사례 포함 520건 통과.
- 같은 DB 설정의 `go test -race -json -count=1 -run '^TestWebSession(ClosedStoreHTTPIntegration|HTTPContractIntegration|RoundTripIntegration)$' ./cmd/server`: 13건 통과. 실제 쿠키·로그아웃 재사용 거부·폐기/검증 장애의 500과 원문 비노출을 확인했다.

합계 533건이며 실패·건너뜀은 없다. check-go.sh의 전체 build·vet·gofmt·govulncheck, 독립 코드 리뷰와 변경 문서 링크·내부 앵커·git diff --check도 통과했다. 리뷰의 발견 사항은 없었다.

전체 저장소 시험·실제 운영 부하·배포는 수행하지 않았다. 사용자 기존 `.env.example`·IDE 변경은 포함하지 않는다.
