## 재개 검증

Go 1.27.1과 고정 이미지 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`의 소유 합성 컨테이너를 사용했다. 실제 판은 PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6이며, 기본 vector(8) DB와 별도 status DB를 준비했다. 기존 개발·다른 시험 DB는 사용하지 않았다.

- `pg_get_keywords()`의 실제 분류는 R 78개·T 23개·C 63개·U 330개였다. 새 카탈로그 회귀는 모든 키워드의 그래프·tablespace 수용/거부를 대조한다. 허용하는 `between` 그래프는 012를 포함한 7개 마이그레이션을 모두 적용한다.
- 실제 status CLI를 `default_transaction_read_only=on` 연결로 실행했다. 빈 DB에서 미적용 7건을 보여 주고 이력 테이블을 만들지 않았다. 정식 적용 후 render_config 열을 제거한 구형 이력 표본에서도 적용 7건·미적용 0건을 표시했다.
- 구형 표본에서 다른 연결이 적용 자문 잠금을 30초간 보유하는 동안 status는 즉시 성공했다. 종료 직후 잠금이 여전히 1개였으며, 구성 열은 0개였다. 전후 이력 JSON을 cmp로 대조해 checksum·적용 시각·버전·파일명이 모두 불변임을 확인했다. `/tmp/acs162-status-empty.log`, `/tmp/acs162-status-legacy.log`, `/tmp/acs162-status-history-before.json`, `/tmp/acs162-status-history-after.json`에 결과를 보관한다.
- 미등록 정점·관계·임베딩의 규칙·위치와 등록 그래프 제외, CLI 전체/지정 범위·JSON Lines·본문 비노출·출력 실패 전파를 회귀 시험으로 확인했다. 감사는 고아 행을 자동 복구하거나 삭제하지 않는다.
- `TEST_DATABASE_REQUIRED=1 go test -race -p 1 -json ./internal/migrate ./internal/store ./cmd/audit ./cmd/migrate -count=1 -timeout=15m`에서 저장소 전체 1,808건·감사 실행기 21건이 통과했고, 마이그레이션은 83건 통과·아래 기존 실패 1건이었다. 시험 사례 건너뜀은 없으며 cmd/migrate는 시험 파일이 없어 패키지 skip으로 표시됐다. 해당 경로는 위 실제 CLI로 별도 확인했다. 전체 명령 종료 상태는 1이며 전체 통과로 보고하지 않는다. 로그는 `/tmp/acs162-modules.json`이다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check`와 변경 문서 7개의 로컬 링크·앵커 259개를 확인했다.
- 별도 status DB를 정리하고 기본 시험 DB·postgres 외 임시 DB와 idle transaction이 없음을 확인했다. 소유 컨테이너·연결 익명 볼륨만 정리한 뒤 잔류가 없음을 확인했으며, 기존 개발·다른 시험 자원과 개인 IDE 파일은 유지했다.

## 기존 실패와 검증 한계

전체 마이그레이션 시험 중 `TestEmbeddingDimensionMigrationIntegration`이 실패했다. 429 처리 뒤 같은 Worker로 400 표본을 즉시 실행하면서 제공자 대기 중 회차도 작업을 처리했다고 기대하는 기존 fixture 가정이다. 기준 `7f18999`의 변경 Go 파일 10개를 overlay로 복원한 단일 시험에서도 같은 `configuration_test.go:305: 장애의 작업 처리: <nil>` 실패를 재현했다. `/tmp/acs162-baseline-failure.json`과 `/tmp/acs162-baseline/overlay.json`을 보관한다. #162의 키워드·이력 조회·감사 변경과 분리했으며, 관련 없는 제공자 대기 시험을 이번 변경에 섞지 않았다. 전체 마이그레이션 시험 통과로 보고하지 않는다.

읽기 전용 검증은 트랜잭션·세션 모드에 대한 것이다. 권한이 낮은 별도 DB role은 시험하지 않았으며 기존 연결 초기화의 LOAD 'age' 권한을 바꾸지 않았다. 자문 잠금을 사용하지 않는다는 계약을 모든 DDL 잠금 대기까지 없다는 보장으로 확대하지 않는다. 미등록 감사는 서비스가 사용하는 Context·일곱 간선 label·임베딩 범위이며 등록 그래프 감사와 각각의 스냅숏을 사용한다.

독립 읽기 전용 검토에서 키워드 문법, 메모리 구성 복원과 checksum 검증, 감사 대상·출력 범위를 확인했고 수정이 필요한 중요한 결함은 발견되지 않았다. 검토자는 DB·시험을 실행하지 않았다.
