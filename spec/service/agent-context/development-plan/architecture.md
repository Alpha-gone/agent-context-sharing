# 아키텍처 개발 계획

[전체 계획](../DEVELOPMENT_PLAN.md) · [기준 SDD](../sdd/architecture.md) · [작업 추적](traceability.md)

## 목표와 구현 범위

빈 애플리케이션에서 시작하여 열한 업무 패키지의 경계, 데이터 접근 자원, HTTP 표면과 조립을 구현한다. 기존 소스의 존재·동작·검증 결과를 전제하지 않는다.

- 설계 입력: [구현 기술 기준](../sdd/architecture.md#구현-기술-기준), [패키지 경계](../sdd/architecture.md#패키지-경계), [DB 연결](../sdd/architecture.md#데이터베이스-연결), [목표 추가 패키지](../sdd/architecture.md#목표-추가-패키지와-조립).
- 예정 구현 영역: 루트 Go 모듈, `internal/model`·`config`, 각 업무 패키지의 인터페이스, `internal/store`의 연결 관리, `cmd/server`의 조립.
- 다른 분야와의 경계: 스키마·질의는 데이터 계획, 도메인 전이는 수명주기 계획, 프로세스 기동·종료는 운영 계획이 소유한다.

## 개발 작업

### ARCH-01

- [x] **도구 체인·모듈·외부 계약을 준비한다.**
- 선행: [TRACE-01](traceability.md#trace-01).

1. `agent_context_sharing` 모듈과 Go `1.27.1` 기준을 준비하고 개발·CI에서 같은 도구 체인을 선택한다. 기본 PATH에 없으면 프로젝트 IDE SDK의 실행 환경을 확인한다.
2. pgx/pgxpool, go-jose/v4, 공식 MCP Go SDK `v1.8.0`과 AGE·pgvector의 사용 판에 맞는 공식 문서·API를 확인하고 의존 판을 고정한다.
3. Go·PostgreSQL·AGE·pgvector의 설계 범위와 개발 이미지 고정값을 구분한다. 문서 확인·다운로드·실제 빌드 결과를 각각 기록하고 확인할 수 없는 조합을 지원 완료로 표시하지 않는다.

- 산출물: 모듈·의존성 잠금, 도구 체인 선택 절차, 버전별 공식 근거와 검증 대기 목록.
- 완료 기준: Go 기준과 의존 판이 일치하고 최소 실행 파일을 빌드할 수 있다. MCP revision의 실제 SDK 적합성은 [MCP-01](mcp.md#mcp-01)로 별도 확인한다.

- 완료 근거: 2026-10-14 [도구 체인·의존성 준비 검증](../reviews/2026-10-14-arch-01.md). Go 1.27.1로 pgx/pgxpool·go-jose·MCP SDK를 포함한 최소 실행 파일과 전체 패키지를 macOS/arm64·Linux/amd64 대상으로 새로 빌드했다. 공통 검사 스크립트와 같은 Go 판을 선택하는 CI 구성을 준비했다. 원격 CI 실행·DB 이미지 runtime·MCP 전송·실제 호스트 인수는 후속 작업의 검증 대기다.

### ARCH-02

- [ ] **저장 방식에 의존하지 않는 논리 모델을 구현한다.**
- 선행: [ARCH-01](#arch-01).

1. UUIDv7 식별자, UTC 시각, 그래프·원천·파생·사건·참조·사건 관계·등급·관리 연산과 판별 가능한 오류 타입을 정의한다.
2. SRS의 공통 9개 속성, 계층별 필수·조건부 속성, 참조 기수성, 불변·가변, 시간·방향 규칙을 구현한다. 원천의 판은 1로 고정하고 UTF-8·U+0000 검사를 포함한다.
3. 형식·논리 검증과 저장 상태 검증을 나눈다. 다른 그래프 참조·실제 존재·순환 경로는 저장소가 조회한 상태로 판정하며 모델에 DB·HTTP·임베딩 의존을 넣지 않는다.

- 산출물: `internal/model`의 타입·검증·오류와 정상·경계·위반 표본.
- 완료 기준: 모든 계층의 필수·불변·시간 규칙이 DB 없는 단위 시험으로 구분되고 모델의 프로젝트 내부 의존이 없다.

### ARCH-03

- [ ] **패키지 경계와 주입 인터페이스를 구현한다.**
- 선행: [ARCH-02](#arch-02).

1. `model`, `plan`, `store`, `perm`, `index`, `authz`, `search`, `web`, `config`, `mcp`, `diagnostic`의 책임과 허용 import를 SDD 표대로 구성한다.
2. `perm`·`search`·`mcp`가 필요한 저장·등급·임베딩·등록 기능을 좁은 인터페이스로 받게 하고, 진단 이벤트도 인터페이스로 전달한다.
3. `store`의 DB 핸들·트랜잭션·질의 실행기를 비공개로 유지한다. 스키마 실행기는 별도 도구 경계로 두고 업무 감사는 저장 트랜잭션에 남긴다.

- 산출물: 열한 패키지의 경계와 인터페이스, 조립 계약, import 허용표.
- 완료 기준: 실제 프로젝트 내부 import와 SDD 표를 양방향으로 검사하며 누락·추가 의존과 순환을 탐지한다. `diagnostic`은 업무 패키지에 의존하지 않는다.

### ARCH-04

- [ ] **AGE 연결 준비와 연결 예약을 구현한다.**
- 선행: [ARCH-03](#arch-03), [DATA-02](data.md#data-02).

1. `pgxpool` 연결 생성 시 AGE 적재·search_path 준비를 수행하고 `agtype` 해석을 저장소 한곳에 모은다. 준비 실패 연결은 사용하지 않는다.
2. 풀 최소 4개를 검증하고 스냅숏 4개, 멱등성·충돌 재조회·DB 주기 작업 2개의 최대 동시 점유를 연결 획득 전에 예약한다. 예약 총량은 SDD 계산을 그대로 적용한다.
3. 스냅숏 읽기 자리는 3개로 제한한다. 읽기 연결을 반환한 뒤 같은 자리에서 접근 기록을 처리하고, 저장점·중첩 읽기는 바깥 예약·종료 경계를 공유한다.
4. 대기 취소·DB 오류·접근 기록 실패의 원인을 보존하고 모든 경로에서 연결·예약·읽기 자리를 반환한다.

- 산출물: 풀 준비·자원 예약·스냅숏 자리·해석기와 최소 풀 통합 시험.
- 완료 기준: 풀 상한보다 많은 병행 요청이 유한 시간 안에 종료하고, 스냅숏 최대 점유 4개와 실패 후 획득 연결·자리의 기준값 회복을 직접 확인한다.

### ARCH-05

- [ ] **구성 해석과 기동 전 검증을 구현한다.**
- 선행: [ARCH-03](#arch-03), [PERM-01](authorization.md#perm-01).

1. 운영 SDD의 기존·목표 구성만 읽는 `config`를 구현하고 유효한 값을 각 패키지 조립 입력으로 변환한다.
2. Gemini 명시·HTTPS 주소·모델·차원·저장 타입, 플랜 JSON, 검색 조합, TLS 종단·프록시, issuer·resource·Origin·OAuth 등록과 진단 경로·슬롯을 검증한다.
3. 잘못된 구성은 DB 연결·제공자 호출·수신 시작 전에 거부한다. 오류에는 비밀·입력 URL·구성 원문을 넣지 않고 환경 예시를 [OPS-01](operations.md#ops-01)·[OPS-02](operations.md#ops-02)와 동기화한다.

- 산출물: 구성 타입·검증기, 허용 키 목록과 오류 표본.
- 완료 기준: 누락·미지원 값·상충 조합·정규화 후 중복 계정이 외부 부작용 전에 거부되고 `config`의 업무 의존은 `plan`만 사용한다.

### ARCH-06

- [ ] **애플리케이션 조립을 구현한다.**
- 선행: [ARCH-04](#arch-04), [ARCH-05](#arch-05), [AUTH-08](authentication.md#auth-08), [MCP-08](mcp.md#mcp-08), [SEARCH-07](search.md#search-07), [WEB-02](web.md#web-02), [OBS-02](observability.md#obs-02).

1. `cmd/server`에서 기록기·저장소·인가·권한·플랜·검색·색인·웹·MCP를 조립하고 인터페이스 구현을 주입한다.
2. 임베딩 본문·질의 호출은 같은 `index` 제공자 경계에 연결한다. 외부 색인 배치에서는 소비 루프를 시작하지 않고 주기 작업은 내장한다.
3. 획득한 자원의 종료 책임을 즉시 등록하고 중간 조립 실패를 운영 계획의 공통 정리 경계로 전달한다. 조립 함수에서 요청을 받거나 배포 설정을 변경하지 않는다.

- 산출물: 서버 조립과 실행기별 구성 주입, 실패 단계별 정리 책임 목록.
- 완료 기준: 같은 구성으로 같은 의존이 연결되고 조립 단계 오류가 원인과 함께 반환된다. 부분 조립의 작업자·풀·기록기 정리는 [OPS-05](operations.md#ops-05)에서 검증한다.

### ARCH-07

- [ ] **HTTP 진입점과 공통 요청 경계를 구현한다.**
- 선행: [ARCH-06](#arch-06), [AUTH-07](authentication.md#auth-07), [MCP-02](mcp.md#mcp-02), [OPS-03](operations.md#ops-03).

1. `net/http.ServeMux`로 SDD의 웹·상태·JWKS와 목표 MCP·OAuth·연결 관리 경로를 등록하고 메서드를 제한한다.
2. 상태 확인을 제외한 경로에 전송 보안 판정을 적용한다. 미등록 경로도 판정 뒤 `404`를 반환하고 MCP·웹의 인증·출처·오류 매핑을 채널별로 연결한다.
3. 요청 상관 ID·시간 예산·본문 상한·취소 전파를 적용한다. 공개 메타데이터와 issuer를 사용자 Host에서 만들지 않는다.

- 산출물: 경로·메서드 표와 서버 HTTP 처리기.
- 완료 기준: 선언 경로의 등록·메서드·상태·보안 예외가 계약과 일치하고 평문·미등록·과대 본문·취소 요청의 처리 순서를 관찰할 수 있다.

### ARCH-08

- [ ] **무상태성·배치 조합·비기능 경계를 인수한다.**
- 선행: [ARCH-07](#arch-07), [OPS-05](operations.md#ops-05), [TEST-02](testing.md#test-02), [TEST-04](testing.md#test-04).

1. 같은 DB를 쓰는 두 애플리케이션에서 계정·등급·인가 계열·등록·멱등성·색인·서명 키·폐기를 공유하는지 확인한다.
2. embedded/external 색인 배치와 서버 교체·재시작을 대조하고 MCP 발견 이력·프로토콜 세션에 의존하는 상태가 없는지 검사한다.
3. NFR의 추적성·설명 가능성·문자 예산·감사·일관성·자격 보호를 해당 분야 인수에 연결한다. 지역 시도 예산·검증 캐시·작업 자리는 공유 영속 상태와 구분한다.

- 산출물: 아키텍처 인수 결과, 배치별 책임·자원 표, 비기능 요구사항의 실행 증거 링크.
- 완료 기준: 열한 업무 패키지의 경계와 두 인스턴스의 상태 공유를 새 구현에서 확인한다. 실제 호스트 지원과 효과·성능 판정은 테스트·평가 계획의 인수가 추가로 필요하다.
