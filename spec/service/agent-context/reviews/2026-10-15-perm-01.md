# PERM-01 플랜 구성·기간 모듈 시험

2026-10-15에 [PERM-01](../development-plan/authorization.md#perm-01)의 플랜 14개 항목과 구성 검증을 구현하고 모듈 시험을 완료했다. 시작 커밋은 `327fd5d`, 브랜치는 `feat/new-implementation-architecture`다. upstream이 없어 원격 대비 상태는 확인할 수 없다.

ARCH-03 다음의 ARCH-04는 DATA-02가 선행이며 DATA-02에는 DATA-01·ARCH-05·OPS-01이 필요하다. DATA-01과 ARCH-05가 요구하는 PERM-01을 이번 항목으로 선택했다. 선행 ARCH-02는 완료 상태이고 기존 플랜 코드·과거 시험을 새 완료 근거로 승계하지 않았다. 다음 준비된 아키텍처 항목은 [ARCH-05](../development-plan/architecture.md#arch-05)다.

## 구현과 계약 대응

기준은 [SRS 플랜 항목](../SRS.md#플랜이-정하는-항목), [기록 보존](../SRS.md#기록-보존), [계정 플랜 값](../sdd/authorization.md#계정-플랜-값)과 [플랜 변경](../SRS.md#플랜-변경)이다.

- [plan.go](../../../../internal/plan/plan.go)는 14개 항목만 정의하고 홉 4·노드 200·페이지 50/200·예산 20000·유예 30일·제안 90일과 무제한/무기한 기본값을 대조한다. 계정별 부분 객체와 없는 계정은 기본값을 사용하며 값 복사·독립 구성 해석으로 기존 집합을 바꾸지 않는다.
- 구성 해석은 `encoding/json/v2`·`jsontext.Value`로 생략·정수 0·명시한 null을 구분한다. 계정/페이지 값의 객체 형식, 14개 목록 밖 키·대소문자를 바꾼 필드·중복 JSON 멤버·정수가 아닌 값·음수·정수 범위 초과를 거부한다. 페이지 기본값은 양수이며 상한 0만 무제한으로 허용한다.
- 모든 계정 키를 정렬·UUIDv7 정규화한 뒤 중복을 먼저 거부한다. 대소문자·하이픈 별칭의 값이 같거나 잘못되어도 중복 계정 중 하나를 임의로 선택하지 않는다. 값 적용 중 오류가 나면 부분 플랜을 반환하지 않는다.
- `model.FieldError`에 알려진 필드·고정 메시지와 원인을 담는다. Error 문자열에는 계정 키·입력 값·구성 원문·알 수 없는 필드명을 복사하지 않으며 JSON의 unknown-member/duplicate 원인은 Unwrap으로 판별된다.
- 감사 보존은 무기한 대상이면 무기한이고 유한 대상보다 짧을 수 없다. 요청 한도는 경계·0 무제한을, 누적 한도는 증가만 제한하고 하향 뒤 읽기·축소를 허용한다. 음수 현재 값·한도는 거부하고 int64 최댓값 주변에서도 합산 오버플로 없이 판정한다. 저장소가 현재 값을 얻고 같은 쓰기에서 적용하는 실행 경계는 PERM-05~06의 후속 인수다.

기존 거부 기록 기본값은 183일이었으나 SRS `FR-AGENT_CONTEXT-120`은 6개월이다. [기간 타입](../../../../internal/plan/retention.go)은 기본 달력 6개월과 구성으로 명시한 일수를 같은 항목 안에서 구분한다. 월 단위 설정 키·새 플랜 항목을 추가하지 않으며 `rejected_operation_days=0`은 무기한이다. Limits의 해당 필드를 `RejectedOperationRetention`으로 바꾸고 소유 SDD의 사상을 먼저 정합화했다.

UTC 기준점에서 여섯 달을 빼고 같은 일이 없는 달은 말일로 제한한다. 2024-10-31은 2024-04-30까지 184일이며 윤년 8월 말은 2월 29일을 사용한다. Go Date/AddDate의 다음 달 정규화를 그대로 사용해 보존 중인 기록을 일찍 지우지 않는다. [서버 전달](../../../../cmd/server/periodic.go)은 회차 시각을 한 번 읽고 계산한 실제 일수를 기존 저장소 정리 인터페이스에 넘긴다. 실제 DB 삭제·보존 예외·주기 작업의 전체 인수는 이번 범위가 아니다.

## 완료 판정과 DOX pass

PERM-01의 14개 항목·기본값·증가 판정·구성 검증·경계 표본과 정규화 후 중복 거부 완료 기준을 충족했다. 플랜 값/이름·자동 과금·추가 한도·미정 정책은 신설하지 않았다. 완료 상태는 TRACE-01·ARCH-01~03·PERM-01 다섯 항목이며 나머지 119개는 미착수다.

권한 SDD에 형식/기간 사상을 정합화하고 개발 계획·근거·요청 기록을 갱신했다. 공개 환경 키·JSON 항목은 같아 환경 예시를 유지했다. 패키지·파일 소유권과 지속 경계가 같으므로 루트·cmd·internal·spec DOX와 Child DOX Index는 유지했다. SRS·용어집·나머지 상세 설계와 과거 시점별 기록은 보존했다. 변경 문서 링크·앵커 86개·Markdown·표, 184건 추적·124개 작업 상태·설정 14개 SDD/코드 일치와 diff 검증이 통과했다. 기존 Compose·IDE 파일은 보존하며 커밋은 별도 요청 시 수행한다.
