# #147 MCP 도구 panic 복구

- 기준: 2026-10-29 KST, `dev`의 `0206e31`에서 분기한 `fix/147-mcp-tool-panic`.
- 대상: [이슈 #147](https://github.com/Alpha-gone/agent-context-sharing/issues/147), [MCP 오류 계약](../sdd/mcp.md#오류의-생성과-전달), [관측성 계측](../sdd/observability.md#지표-수집-지점).

## 재현과 수정

[HTTP 회귀](../../../../internal/mcp/tool_panic_test.go)는 실제 SDK v1.8.0과 보호 HTTP 경로에 시험 처리기를 주입한다. 수정 전에는 첫 도구 호출의 합성 문자열 panic이 SDK의 jsonrpc2 goroutine을 통해 전파되어 시험 프로세스를 종료했다. HTTP 바깥의 recover로 잡을 수 없는 실행 경계임을 고정 판 SDK 원본과 실패 스택에서 확인했다.

도구 등록 콜백에 직접 deferred recover를 두어 입력 검증·주입 처리기와 의존의 panic을 고정 `internal` 도구 완료 결과로 바꾼다. panic 값은 보관하거나 문자열화하지 않고 스택도 응답·진단에 넣지 않는다. 요청 진단에는 허용 목록의 고정 코드 `handler_panic`과 `ERROR`·`response`·`failed`·도구 이름만 전달한다. 기존 도메인 오류와 정상 결과의 사상은 유지한다.

독립 검토에서 복구 중 진단 observer가 다시 panic하면 프로세스가 종료될 수 있음을 지적했다. 진단 sink의 두 번째 panic으로 프로세스가 종료되는 실패를 추가 재현한 뒤, 고정 결과 설정 다음에 진단 호출 전용 중첩 recover를 두었다. 진단 실패는 결과를 덮어쓰거나 SDK goroutine 밖으로 전파되지 않는다. 재검토에서 남은 Critical·Important·Minor 지적은 없었다.

## 검증

Go 1.27.1에서 실행했다.

```sh
go test -race -count=1 -run '^TestMCPToolPanicHTTP$' ./internal/mcp
go test -race -count=1 -run '^TestMCPToolPanicHTTP/diagnostic_panic' ./internal/mcp
go test -race -count=1 -json ./internal/mcp ./internal/diagnostic
# 처리기와 진단 sink 양쪽 원문에 대한 비노출 검사 보강 후
go test -race -count=1 -json ./internal/mcp
go build ./...
go vet ./...
gofmt -l .
```

- 신규 시험은 14종 도구 각각에 문자열 panic·진단 수락 실패, nil panic·진단 미주입, 복구 중 진단 재panic의 **42개 조합**을 적용한다. 각 조합은 같은 서버에서 실패 호출 다음 정상 호출이 성공하고 인증/업무 호출 횟수가 맞는지 대조한다.
- 오류는 HTTP 200의 `resultType=complete`·`isError=true`·`code=internal`이다. JSON-RPC 오류·재인가 헤더가 없고 `no-store`를 유지하며 합성 panic 원문·시험 파일 경로·goroutine 스택이 노출되지 않는다. 진단 이벤트의 필드 검증과 도구별 고정 실패 이벤트 1건도 대조한다.
- 최종 필터 없는 race 실행에서 MCP **480건(9.916초)**, 진단 **167건(21.469초)**이 통과했다(하위 사례 포함). 진단의 `TestOPS04MaintenanceStorageScopeIntegration` 1건은 `TEST_DATABASE_URL` 미설정으로 건너뛰었으며 통과로 집계하지 않았다. DB 연산은 이번 변경 범위가 아니다.
- build·vet·gofmt, 새 문서 링크/앵커·diff 검사를 통과했다. DOX의 구조·소유권이 바뀌지 않아 기존 계약과 색인을 유지한다.

이슈 #147의 등록 경계 복구·원문/스택 비노출·다음 요청 처리 조건을 충족한다. 처리기가 자체 생성한 별도 goroutine, SDK 내부·인증 진입점의 panic이나 치명적 런타임 종료까지 복구하는 계약으로 확대하지 않는다. 공식 근거는 [reference.md](../reference.md#2026-10-29-147-mcp-도구-panic-복구)에 연결한다.
