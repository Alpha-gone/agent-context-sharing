# 색인 개발 계획

[전체 계획](../DEVELOPMENT_PLAN.md) · [기준 SDD](../sdd/indexing.md) · [작업 추적](traceability.md)

## 목표와 구현 범위

본문·질의의 Gemini 호출, DB 작업 등록·확보·리스·재시도·결과 공개와 재색인을 새로 구현한다. 컨텍스트 저장 성공과 임베딩 생성 성공은 서로 다른 경계다.

- 설계 입력: [저장과 색인](../sdd/indexing.md#컨텍스트-저장과-색인), [큐](../sdd/indexing.md#색인-작업-큐), [재시도](../sdd/indexing.md#색인-재시도), [제공자](../sdd/indexing.md#임베딩-제공자-전환), [재색인](../sdd/indexing.md#재색인), [상관 ID](../sdd/indexing.md#진단-상관-메타데이터).
- 예정 구현 영역: `internal/index`, `internal/store`의 큐·벡터 반영·준비 검사, 별도 색인 실행기와 서버 조립.
- 다른 분야와의 경계: 벡터 형상은 데이터 계획, 본문 저장은 수명주기 계획, 검색 실패 매핑은 검색 계획, 실제 API 실행 조건은 테스트 계획이 소유한다.

### IDX-01

- [x] **저장 트랜잭션의 작업 등록을 구현한다.**
- 선행: [DATA-03](data.md#data-03), [ARCH-05](architecture.md#arch-05).

1. context당 한 index_task를 upsert하고 enqueued_at·next_attempt_at·attempts·pending·상관 ID를 갱신한다.
2. 생성·body 갱신·복구·재색인의 현재 대상 계층에만 등록한다. 원천 중복·body 불변 갱신·제외 계층에는 새 작업을 만들지 않는다.
3. all_layers/without_source에서 정점·간선·관리 기록은 동일하게 저장되도록 하고 큐 등록 실패는 저장을 롤백한다.

- 산출물: 등록 API·대상 계층 판정과 upsert 시험.
- 완료 기준: 같은 컨텍스트의 여러 저장이 작업 하나로 합쳐지고 failed도 새 등록으로 pending에 돌아온다.

- 완료 근거: 2026-10-17 [작업 등록 모듈 시험](../reviews/2026-10-17-idx-01.md). 서버 UUIDv7 상관 ID의 공통 전달과 등록·재등록 시 갱신·NULL 초기화를 구현하고 다른 그래프 작업의 upsert·잘못된 계층을 거부했다. 두 계층 구성에서 생성·본문 변경·복구·재색인의 단일 등록, 실패 상태 초기화, 원천 중복·본문 불변 갱신의 작업 보존, 관리 기록·참조 보존과 등록 장애의 전체 롤백을 검증했다. 새 격리 DB의 대상 모듈·하위 시험 47건·race와 전체 build·vet·형식 검사가 통과했다. 상관 ID 확보·무효 확보 격리, 취소·연결·예약 회복도 확인했다. HTTP 진입점의 발급·진단 파일 연결과 색인 전체 인수는 후속 범위이며 다음은 [IDX-02](#idx-02)다.

### IDX-05

- [x] **성공 결과의 세대 검증과 원자적 공개를 구현한다.**
- 선행: [IDX-04](#idx-04), [DATA-07](data.md#data-07).

1. 현재 확보 세대의 작업 삭제로 잠근 뒤 같은 트랜잭션에서 이전 계층 벡터 교체·현재 모델 저장·내용 판 증가를 수행한다.
2. 저장 실패면 작업 삭제도 롤백하고 같은 예산으로 실패를 반영한다. 이미 없거나 세대가 다른 작업의 성공·실패는 임베딩·판·상태를 바꾸지 않는다.
3. 성공한 사건 색인 후 관계 후보 신호를 호출할 인터페이스를 제공하고 요청 상관 ID와 작업 ID를 분리해 진단한다.

- 산출물: 조건부 결과 반영·벡터 공개·무효 확보 처리.
- 완료 기준: 느린 이전 결과가 새 본문·새 리스·제외된 계층의 벡터를 덮거나 되살리지 못하며 원자적 반영을 두 작업자로 검증한다.

- 완료 근거: 2026-10-17 [결과 공개 모듈 시험](../reviews/2026-10-17-idx-05.md). 확보한 본문의 계층을 결과에 전달하고 사건의 공개 커밋 뒤에만 관계 후보 신호를 호출하는 주입 인터페이스를 제공했다. 제공자·공개·후속 신호 진단에서 작업 ID와 요청 상관 ID를 분리하며 신호 실패의 원문은 기록하지 않는다. vector·halfvec에서 두 작업자의 본문 재등록·리스 재확보·계층 제외·작업 제거가 겹칠 때 이전 성공·실패가 벡터·내용 판·새 작업을 바꾸지 않음을 확인했다. 실제 INSERT 대기 중 커밋 전 상태 보존과 커밋 뒤 cold→hot 교체·현재 모델·내용 판 증가·작업 삭제의 동시 공개, 내용 판 갱신·COMMIT 장애의 전체 롤백을 검증했다. 새 모듈과 관련 회귀의 고유 시험·하위 시험 82건·race와 전체 build·vet·형식 검사가 통과했다. 전체 색인 인수는 후속 범위이며 다음은 [IDX-06](#idx-06)이다.

### IDX-06

- [x] **소비 루프와 embedded/external 배치를 구현한다.**
- 선행: [IDX-05](#idx-05).

1. 처리한 회차는 1초, 빈 회차는 두 배 증가·최대 30초의 조회 간격을 적용한다.
2. embedded는 서버에 소비 루프를 연결하고 external은 서버 소비를 시작하지 않는다. 같은 DB 작업·제공자 구현을 사용한다.
3. 시작·취소·종료 API와 미완료 리스 복귀를 운영 정리에 연결한다. 무한 제공자 대기나 이미 정리한 작업자의 중복 종료를 만들지 않는다.

- 완료 기준: 두 배치에서 결과가 같고 다중 작업자가 유효 리스를 중복 처리하지 않는다. 중단한 작업은 리스 경계 뒤 회복된다.

- 완료 근거: 2026-10-17 [소비·배치 모듈 시험](../reviews/2026-10-17-idx-06.md). 처리 뒤 1초 대기를 보장하고 빈 회차는 2·4·8·16·30초로 늘리며 취소를 회차 전후에 확인한다. 같은 구성·저장소·제공자를 사용하는 `cmd/indexer`를 추가하고 서버의 external 소비 중단과 시작 여부에 독립된 정리를 연결했다. 가상 시간의 간격·상한·초기화와 시작/종료 경합, 실제 별도 프로세스의 두 배치 결과 일치·두 작업자 리스 격리·SIGTERM 제공자 취소·만료 뒤 회복·DB 형상 불일치 차단을 검증했다. 새 모듈·관련 회귀의 고유 시험·하위 시험 33건·race와 전체 build·vet·형식 검사가 통과했다. 시험별 빈 DB의 정식 마이그레이션과 배치 6건 재검증도 통과했다. 전체 색인 인수·운영 분리 배포는 후속 범위이며 다음은 [IDX-07](#idx-07)이다.

### IDX-07

- [ ] **전체 재색인과 형상 변경의 작업 전이를 구현한다.**
- 선행: [IDX-05](#idx-05), [DATA-07](data.md#data-07).

1. 모델·입력 판·차원·압축 변경 뒤 현재 대상 계층을 upsert하고 옛 model_id를 의미 검색·관계 제안에서 배제한다.
