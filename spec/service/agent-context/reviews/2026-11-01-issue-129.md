# #129 반복 인가 로그 조사와 연속 사용 회귀

## 조사 결과와 미확정 사항

[이슈 댓글의 서버 로그](https://github.com/Alpha-gone/agent-context-sharing/issues/129#issuecomment-6107159464)에는 2026-10-11 `/mcp` 401 15회, `/authorize` 17회(302 16회·303 1회), `/token` 200 16회와 `/mcp` 200 47회가 있다. 최초 교환 성공 뒤 4초 만에 다음 401이 나타나며 여러 인가·교환이 짧은 간격으로 겹치는 구간도 있다. 반복된 HTTP 흐름 자체는 확인되지만, 요청의 인증 헤더 존재·실패 사유·호스트 PID가 없어 같은 유효 자격이 거부된 것인지 새 프로세스의 무자격 탐색인지 구분할 수 없다.

당시 전용 클라이언트는 `4217d92`에서 제거되었다. 제거 전 Manager는 프로세스 메모리에 자격과 키를 보관하며 새 Manager가 새 키를 만든다. 프로세스 재생성은 반복 인가를 설명할 수 있는 조건이나, 이슈 당시 실제 발생 조건으로 확정할 수 없다. 현재 직접 연결 전환이나 TEST-08 통과만으로 과거 데스크톱 결함의 해결을 선언하지 않는다.

#58은 토큰 교환 저장 장애의 invalid_grant 오분류를 다뤘지만 이 로그의 교환은 모두 200이다. #61의 callback 정리 지연도 로그만으로 연결할 수 없다. 두 이슈와 같은 원인이라고 판단하지 않았다. 현재 Codex 데스크톱에서의 재현·호스트 로그는 확보하지 못했으므로 원인 확정과 이슈 종료는 보류한다.

## 변경

제품 인증·수명·폐기·오류 사상은 변경하지 않았다. `TestIssue129ContinuousOAuthSessionIntegration`과 공통 OAuth 시험 관찰을 보강했다.

- 실제 CLI 프로세스 하나가 등록·그래프 조회/생성·노드 생성/조회·그래프 읽기/갱신 등 도구 8회를 실행한다. 최초 인가 뒤 서버의 추가 `/authorize` 요청·토큰 교환·401이 없고 자격 파일 바이트가 유지되는지 직접 확인한다.
- 클라이언트의 시험용 만료 표본으로 정상 갱신을 실행할 때 토큰 교환은 한 번 증가하고 서버에 추가 인가 요청은 없어야 한다.
- 403/500 및 복구 시험은 기존 자격·토큰 교환 불변에 더해 서버에 도착한 인가 요청도 확인한다.

`BROWSER=/usr/bin/true`·`mcp login --no-browser` 구성에서는 서버에 도착하지 않은 브라우저 실행 시도를 직접 계수할 수 없다. 시험용 opener를 추가한 대조에서도 이 CLI 판의 실행 호출을 관찰하지 못하여 해당 장치를 제거하고 검증 주장을 HTTP 관찰 범위로 제한했다. 자동 열기와 별개로 최초 로그인·동의·callback은 실제 Chrome이 수행한다.

## 검증과 범위

Go 1.27.3·macOS/arm64·Codex CLI 0.160.1 exec·`features.mcp_2026_07_28=true`·파일 자격 저장·실제 Chrome·로컬 모델 대역과 `.env`의 시험 DB 접속 정보를 사용했다. 각 시험은 최신 마이그레이션의 별도 DB와 임시 CODEX_HOME을 생성·정리하며 사용자 자격·설정·기존 DB 스키마를 변경하지 않는다. 유료 추론·Gemini 호출은 하지 않는다.

```sh
go test -race -json -count=1 \
  -run '^Test(Issue129ContinuousOAuthSessionIntegration|TEST08CodexCLIOAuthIntegration|TEST08CodexCLIHTTPFailuresIntegration)$' \
  ./cmd/server
```

선택 회귀는 하위 사례 포함 11건이며 최초 코드 교환·같은 프로세스 연속 호출·새 프로세스 저장 자격 재사용·갱신·서버 교체·키 회전·폐기·유휴/절대 만료·응답 유실·갱신 경합·403/500을 대조한다. 강제 클라이언트 만료 표본과 실제 자연 만료 1시간 대기는 구분하며 이번에는 자연 만료 대기를 실행하지 않는다. 실제 데스크톱·IDE·keyring 인수로 확대하지 않는다.

기존 SRS·제품 계약·DOX 소유권과 구조는 유지하고 시험 정본과 [외부 근거](../reference.md#129-반복-인가-조사에서-확인한-외부-경계)·작업 기록만 동기화한다. 최종 race 회귀는 11건 통과·실패/건너뜀 0건이었다. `check-go.sh`의 전체 build·vet·gofmt·govulncheck와 변경 Markdown 상대 링크·`git diff --check`도 통과했다. 독립 리뷰에서 발견한 브라우저 실행 관찰 한계는 위와 같이 명시하고 HTTP 관찰 범위로 한정했다.

## 이슈 완료 조건 대조

- 반복 조건의 로그 확인: HTTP 반복 흐름 확인, 직접 원인은 미확정이다.
- 유효 인증의 연속 호출: 위 CLI 범위에서 회귀로 검증한다. 데스크톱 원보고의 재현을 대신하지 않는다.
- 정당한 만료·폐기: 기존 실제 호스트 경계 회귀를 유지한다.
- 원인 회귀: 원인 확정 전이므로 관찰된 반복 패턴의 방지 조건을 보강한 상태다. 원인 수정 완료로 표시하지 않는다.
