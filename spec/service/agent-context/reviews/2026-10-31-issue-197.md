# #197 검색 단위 비교의 과업 성공률 판정 검토

- 대상: [이슈 #197](https://github.com/Alpha-gone/agent-context-sharing/issues/197).
- 기준: `dev`의 `fd93761`, 브랜치 `fix/197-unit-success-significance`.

## 원인과 변경

검색 단위 비교는 과업 성공률 평균 차이가 음수이고 표본이 하나라도 있으면 유의성·표본 충분성과 관계없이 `rejected`/`quality_or_task_regression`을 반환했다. 이 판정이 표본 충분성 검사보다 앞서고, manifest 요약은 `rejected`를 출처·독립 단위 검사보다 먼저 not_accepted로 바꾸므로 독립 단위 1개의 하락이나 구간이 0을 포함하는 감소도 비채택됐다.

과업 성공률 하락의 거부를 확장 업무 판정과 같은 `유의함 ∧ 비개선` 조건으로 한정했다. 유의성은 독립 단위 대응 Student t 구간이 0을 벗어난 차이이며 독립 단위 2개 이상에서만 성립한다. 따라서 독립 단위가 부족한 감소는 기존 표본 부족 보류로, 구간이 0을 포함하는 감소는 나머지 판정 순서로 이어진다. 완전성·검색 품질의 유의한 악화 거부와 비용·예산 판정은 바꾸지 않았다.

[평가 정본](../sdd/evaluation.md#검색-단위-비교의-실행-입력과-결과)의 "유의한 악화 또는 과업 성공률 하락" 문구를 과업 성공률의 유의한 하락으로 확정하고 확장 업무 판정과 같은 기준임을 명시했다. [시험 설계](../sdd/testing.md#검색-단위-완전성-비교-시험)에 판정 회귀를 추가했다. 결과 JSON 필드·사유 문자열·구성은 변경하지 않았으며 DOX pass에서 소유권·경로 변경이 없어 기존 DOX를 유지했다.

## 재현과 검증

- 실제 집계로 만든 후보 cohort에서 과업 성공률 비교만 바꾼 판정 시험을 추가했다. 기준 코드에서 구간이 0을 포함하는 -0.01 감소와 독립 단위 1개의 -0.1 감소가 모두 `rejected`/`quality_or_task_regression`인 것을 재현했다.
- 수정 후 비유의 감소는 원래 후보 판정, 단위 부족은 `deferred`/`unmeasured_or_insufficient_independent_units`, 유의한 감소는 `rejected`/`quality_or_task_regression`이다. 기존 집계 시험의 모든 독립 단위 성공률 1→0 하락은 계속 거부된다.
- Go 1.27.1과 고정 이미지 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`(PostgreSQL 18.6)의 전용 합성 컨테이너에 기본 vector 768·비교 vector 128·halfvec 768 DB를 만들고 각각 정식 7개 마이그레이션을 적용했다. 기존 개발·다른 시험 DB는 사용하지 않았다.
- `TEST_DATABASE_URL`, `TEST_EMBEDDING_SMALL_URL`, `TEST_EMBEDDING_HALF_URL`, `TEST_DATABASE_REQUIRED=1`을 지정한 `go test -race -p 1 -json ./cmd/eval -count=1 -timeout=40m`에서 915건이 실패·건너뜀 없이 통과했다. [#195 검토](2026-10-31-issue-195.md)의 911건과의 차이는 새 시험·하위 시험 4건이다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check`와 변경 문서의 로컬 링크·앵커를 확인했다.
- 시험 종료 후 시험 DB 외 임시 DB와 idle transaction 잔류가 없음을 확인하고 소유 컨테이너만 정리했다. 기존 개발·다른 시험 자원과 개인 IDE 파일은 유지했다.
