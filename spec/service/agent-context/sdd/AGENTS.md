# 분야별 상세 설계 영역

## 목적

- 이 영역은 확정 요구사항을 분야별 상세 설계로 구체화한다.

## 소유권

- [SDD 진입점](../SDD.md)은 문서별 책임·상태를, 각 분야 문서는 상세 계약을 소유한다.
- [traceability.md](traceability.md)는 요구사항의 주 책임 설계·검증 추적과 설계 미정 사항을 소유한다.

## 로컬 계약

- 각 계약은 한 문서만 소유하고 다른 분야는 상대 링크로 참조한다. 여러 분야가 관련된 요구사항도 주 책임 설계 문서는 하나로 정한다.
- 요구사항·확정 결정은 [SRS.md](../SRS.md)를 따른다. 설계 상세는 분야 파일에 두고 진입점에 합치지 않는다.
- 현재 구현·채택된 목표·검증 대기를 구분하며 문서 작성만으로 지원·성능·실제 동작을 완료로 표시하지 않는다.
- 외부 계약의 설계 근거는 [reference.md](../reference.md)에 기록한다. SDK·모듈의 공식 자료 확인은 루트 공통 계약을 따른다.
- 개발 작업·선행 조건·완료 증거는 [개발 계획](../DEVELOPMENT_PLAN.md)이 소유한다. 계획의 진행 상태로 설계 채택 상태를 바꾸지 않는다.

## 작업 지침

- 대상 SRS와 교차 분야 계약을 확인하고 구현과 달라져야 하는 설계는 소유 문서에서 먼저 갱신한다.
- 분야 추가·책임 이동 시 진입점·추적표·분야 간 참조와 계획 대응을 함께 갱신한다.
- 절의 단순 이동을 결정 변경으로 기록하지 않는다. 과거 검토 기록의 시점·범위는 보존한다.

## 검증

- SRS에서 폐기된 항목을 제외한 설계 대상 ID 집합과 추적 행이 중복·누락 없이 일치하는지 확인한다.
- 요구사항 미정·설계 선택·실제 상호운용 검증 대기를 현재 정본 상태로 구분한다.
- 파일 간 데이터·시간·권한·오류·트랜잭션·자원 상한과 제목 앵커가 일치하는지 확인한다.
