# IDX-01 저장 트랜잭션의 작업 등록 모듈 시험

## 범위와 입력

- 대상: [IDX-01](../development-plan/indexing.md#idx-01). DATA-03·ARCH-05 완료. 시작 커밋 `9c3d52b`, 브랜치 `feat/data-schema-contract`.
- DATA-09는 IDX-07이 선행하므로 DATA-08 뒤 색인 작업 등록부터 진행했다. 원격 `dev`와 추적 ref는 `0291ea5`로 같으며 현재 브랜치는 2커밋 앞서고 뒤처짐은 0이었다.
- 정본: [SRS 색인 처리](../SRS.md#색인-처리), [색인 대상 비교](../SRS.md#색인-대상-비교), [저장·등록](../sdd/indexing.md#컨텍스트-저장과-색인), [색인 큐](../sdd/indexing.md#색인-작업-큐), [상관 메타데이터](../sdd/indexing.md#진단-상관-메타데이터), [시험 시점](../DEVELOPMENT_PLAN.md#테스트-작성과-실행-시점).

## 구현과 검토

- `model.WithCorrelationID`·`CorrelationID`는 서버 UUIDv7 상관 ID를 비공개 context key로 전달한다. 잘못된 판·variant·영값을 거부하며 사용자 쓰기 키를 상관 ID로 대입하지 않는 호출 계약을 명시했다. 요청 없는 실행은 영값을 반환한다. 저장소·HTTP 객체 의존은 추가하지 않았다.
- 공통 `enqueueIndexTask`는 생성·본문 변경·복구·재색인에서 동일하게 호출된다. INSERT·충돌 갱신에 상관 ID를 포함해 새 요청 값으로 바꾸며, 요청 없는 등록은 이전 요청을 물려받지 않고 NULL로 초기화한다.
- 기존 task ID를 유지하면서 컨텍스트당 한 행에 합친다. 등록·다음 시각을 같게 갱신하고 attempts 0·pending·last_error NULL로 되돌린다. 그래프가 다른 충돌 행은 갱신하지 않고 저장 장애로 반환한다. 알 수 없는 계층은 SQL 실행 전에 거부한다.
- `ReindexGraph`의 등록 트랜잭션은 공통 `finishWrite`로 정리하여 요청 취소와 독립된 정리 예산으로 롤백하고 원인을 보존한다. 전체 재색인 정책·형상 전환의 완료는 IDX-07에서 따로 판정한다.
- 원천 중복과 본문 불변 갱신은 작업·상관 ID를 바꾸지 않는다. 원천 제외 구성은 등록만 건너뛰며 정점·근거/구성원 간선·관리 기록은 그대로 저장한다.
- 마이그레이션·적용 이력·의존성을 변경하지 않았다. 기존 nullable text 열에 검증된 UUIDv7 표준 문자열을 저장한다.

## 환경과 결과

- Go 1.27.1 darwin/arm64, PostgreSQL 18.6 / Apache AGE 1.8.0 / pgvector 0.8.6 / Linux aarch64.
- 저장소 고정 Dockerfile로 IDX-01 전용 이미지·컨테이너·새 볼륨을 준비하고 loopback 동적 포트만 열었다. 신규 DB 시험은 공통 격리 도우미로 임시 DB 18개에 정식 001·009·010·011 적용과 반복 실행을 수행했다. 관련 회귀는 같은 전용 컨테이너의 별도 기본 DB에 정식 적용한 뒤 실행했다.
- **고유 모듈·하위 시험 47건 통과**: store 42건·model 4건·서버 조립 1건, 최상위 14개·하위 33개. `-race -count=1`과 `TEST_DATABASE_REQUIRED=1`을 적용했으며 실패·건너뜀은 0이다.
- 신규 본 시험 28건, 상관 ID 확보·취소 보완 2건, 관련 회귀 17건을 실행했다. 패키지별로 해당 이름이 없는 실행을 통과 건수에 넣지 않았다.
- all_layers·without_source 각각 원천·파생·사건 생성과 관리 기록을 대조했다. 원천의 중복 등록 요청은 전체 업무 지문을 보존했고, 파생·사건의 본문 불변 판 갱신은 작업 전체 필드를 보존했다. 본문 변경·MCP 복구·요청 없는 재색인은 같은 task ID와 현재 상관 ID/NULL을 사용했다. failed·미래 재시도·마지막 오류는 새 등록으로 초기화됐다.
- 두 구성에서 파생/사건 생성·본문 변경·MCP 복구·웹 복구·재색인의 등록에 실제 DB 트리거 오류를 주입했다. 재색인은 두 번째 INSERT 시도에서 실패시켜 앞선 등록까지 롤백됨을 확인했다. AGE 정점·간선, 그래프 전체 행·저장량, 큐·임베딩·관리 기록·웹 감사의 업무 행 지문이 모두 보존됐다.
- 잘못된 그래프의 큐 행을 준비한 본문 갱신은 거부됐고 정점·기존 작업·그래프·감사 지문이 보존됐다. 8개 동시 등록자가 총 80회 upsert해도 기존 task ID의 작업 하나가 유지됐다.
- 실제 확보가 최초 상관 ID를 전달한 뒤 새 본문·새 상관 ID로 재등록했다. 이전 확보분의 실패는 새 작업을 변경하지 않았으며 다음 확보는 새 본문·상관 ID를 전달했다. 이는 등록 메타데이터의 연동 증거이며 IDX-02~05의 전체 모듈 인수를 대신하지 않는다.
- DB 트리거 대기 중 재색인 요청 마감을 소진시켜 취소·전체 롤백·풀과 예약 회복을 직접 확인했다. 공통 context 전달도 부모 취소와 요청별 값 격리를 유지했다.
- 기존 계층 등록·제외 계층 제거, 재등록 후 이전 성공/실패 차단, 제공자 대기 중 저장, 복구 재등록·한도와 패키지 의존 경계를 새로 검증했다.
- `check-go.sh`의 의존성 검증·전체 build·vet·gofmt를 통과했다. 문서 링크·앵커·계획 수·Markdown·용어·DOX 소유/색인과 `git diff --check`를 확인했다.

## 완료 판정과 남은 범위

- IDX-01 구현·모듈 시험 완료. 전체 17/124개 완료·107개 미착수이며 다음은 [IDX-02](../development-plan/indexing.md#idx-02)다.
- HTTP 진입점의 상관 ID 발급·공통 context 연결과 진단 파일 기록은 관측성·서버 조립 작업에서 이어 수행한다. 이번 작업은 그 값을 받는 저장 API와 큐 메타데이터의 범위다. 사용자 쓰기 키를 자동 복사하거나 상관 ID를 생성하는 임시 HTTP 경로를 추가하지 않았다.
- 전체 재색인·전환·색인 인수·운영 DB·외부 제공자 API·실제 호스트·amd64 runtime은 미실행이다. 실제 비용·지연·품질을 주장하지 않는다.
- DOX 구조·패키지 의존·업무 계약·용어가 바뀌지 않아 DOX·SRS·SDD·용어집은 유지했다. 사용자 Compose·IDE 변경을 보존했으며 커밋·푸시는 수행하지 않았다.
- 작업 종료 전 외부에서 upstream이 `origin/feat/data-schema-contract`로 바뀌었다. 실제 원격·추적 ref·HEAD가 모두 `9c3d52b`이며 앞섬·뒤처짐은 0이다. 당시 실제 원격 dev는 `d7af8e4`였다. 이 작업에서 Git 동기화·이력 변경은 수행하지 않았다.
- 임시 DB 잔여 0을 확인하고 IDX-01 라벨을 대조한 전용 컨테이너·볼륨·이미지만 정리했다. 이름으로 다시 조회한 잔여 자원도 0이다.
