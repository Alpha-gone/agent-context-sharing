# #261 삭제 영향과 유사 사건 정체성 질의 범위

## 원인과 변경

- 삭제 영향의 확정 관계 집계는 label 없는 MATCH로 모든 간선 label을 읽은 뒤 relation_type 조건으로 참조 간선을 버렸다. PRECEDES·CAUSES·PART_OF·RELATES_TO만 읽도록 바꾸고 네 count를 한 SQL UNION ALL/sum으로 합쳤다. 한 번의 왕복·문장 스냅숏, 실제 Context 끝점 및 지정 사건의 양쪽 끝점 판정·confirmed 필터를 유지했다.
- 유사 사건 후보의 기존 정체성 제외는 SQL `->>`를 사용해 마이그레이션 014의 agtype 표현식 인덱스와 맞지 않았다. graph_id·from_context_id·to_context_id를 같은 `agtype_access_operator`로 비교하고 오른쪽 UUID 문자열은 to_jsonb로 인코딩해 agtype으로 변환했다. 끝점 정규화, proposed·confirmed·discarded 전부의 제외와 LIMIT 앞 판정은 유지했다.
- 새로운 스키마·인덱스·설정·공개 API는 없다. 기존 데이터·색인 설계의 계약을 구현하는 변경이므로 정본의 동작·소유권과 DOX 구조는 유지하고 시험 범위와 [공식 근거](../reference.md#261-삭제-영향과-유사-사건-정체성-질의-범위)를 보강했다.

## 실행 계획 대조

Go 1.27.3·PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6·race·`.env`의 필수 시험 DB 접속 설정을 사용했다. 새 계획 시험은 최신 마이그레이션을 적용한 별도 DB에서 실행하고 자신이 생성한 DB만 정리한다. 대상 그래프의 데이터는 고정하고 다른 그래프의 네 사건 관계와 세 참조 label별 간선을 0→1,000→10,000개로 늘렸다. 플래너 선택을 강제하지 않고 실제 제품 질의를 기록하여 EXPLAIN (ANALYZE, BUFFERS, TIMING OFF)로 관찰했다.

- 그래프 전체·시작 사건·대상 사건 삭제 영향 모두 확정 관계 수는 4였다. proposed/discarded를 포함해 PRECEDES·RELATES_TO 각각 2행, CAUSES·PART_OF 각각 1행의 읽기가 모든 크기에서 유지됐고 참조 세 label의 읽기는 0이었다. 같은 표본의 기존 질의와 집계 결과가 일치했다. 관계 없는 사건은 0이었다.
- 기존 삭제 집계는 label별 10,000개 표본에서 참조 간선 30,005행을 읽었다. 수정 질의는 해당 참조 label을 읽지 않았다.
- 유사 사건 후보는 confirmed·discarded·proposed의 세 기존 정체성을 제외하고 같은 유효 사건 하나만 반환했다. RELATES_TO 읽기는 0·1,000·10,000개 표본에서 모두 3행이었다. 같은 표본에서 기존 SQL 표현식으로 되돌린 질의도 같은 사건을 반환했지만 10,009행을 읽었다.
- 이 표본의 플래너는 정체성 인덱스와 같은 graph_id 접두사를 가진 `relates_to_graph_target_idx`를 선택했다. 시험은 이름을 강제하지 않고 정체성/target 범위 인덱스 및 실제 읽기 행 수를 확인한다. 특정 인덱스 사용이나 전체 지연의 일반적 개선률로 확대하지 않는다.

## 검증

```sh
go test -race -json -count=1 \
  -run '^Test(DeletionImpactRelationScopeIntegration|SimilarProposalIdentityScopeIntegration|LifeProposalSimilarityIntegration|LifeDeletionImpactAndPreservationIntegration|GraphGrantsAndDeletionImpactExecute|RelationQueryScopeIntegration|RelationProposalInputBoundIntegration)$' \
  ./internal/store
```

하위 사례 포함 23건 통과, 실패·건너뜀 0건이다. 새 계획 시험과 기존 삭제 영향·vector/halfvec 유사 제안·관계 범위·제안 입력 상한 회귀를 포함한다. 독립 코드 리뷰에서 중요한 추가 지적은 없었다. `check-go.sh`의 전체 build·vet·gofmt·govulncheck와 문서 링크·`git diff --check`도 통과했다. 전체 저장소 시험·실제 운영 데이터의 부하 측정·배포는 수행하지 않았다.
