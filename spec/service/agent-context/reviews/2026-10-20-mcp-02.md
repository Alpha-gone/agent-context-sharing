# 보호 HTTP 전송·발견·요청 검증 인수

- 기준: [MCP-02](../development-plan/mcp.md#mcp-02), [표준 MCP 경계](../sdd/mcp.md#표준-mcp-경계), FR-AGENT_CONTEXT-028·095·149·164·166·168, NFR-AGENT_CONTEXT-012·013.
- 대상: `feat/mcp-auth`의 `ec52898` 이후 작업 트리. MCP-01·ARCH-03·AUTH-08의 선행 조건을 확인했다. 원격 fetch 뒤 upstream 뒤처짐은 0건이다.
- 범위: 보호 전송 생성자·서버 라우터 주입·실제 OAuth/TLS 연결의 모듈 인수다. 기동 경로의 업무 13종 연결·MCP 분야 전체 통합·실제 호스트·Tunnel·운영 배포는 후속 범위다.

## 구현 결과

`mcp.NewHandler`는 허용 Origin 목록·Bearer 보호 함수·14종 도구 처리기를 모두 요구한다. 누락·nil·추가 도구와 불완전한 인증 조립은 생성 시 거부한다. Origin과 처리기 입력은 생성 뒤의 변경과 분리해 보관한다. `cmd/server.newMCPHandler`가 authz.ProtectBearer의 검증된 계정·client를 Principal로 전달하고 application의 선택 /mcp 슬롯을 기존 TLS 판정 아래에 연결한다. 도구 인자나 clientInfo는 인증 주체를 만들지 않는다.

Origin이 있으면 원문을 허용 목록과 정확히 대조한다. 빈 값·null·중복·목록·다른 출처는 403이다. POST 외에는 Allow: POST와 405, 단일 application/json 이외의 Content-Type은 415다. Accept는 JSON·SSE를 함께 지원해야 하며 잘못된 매개변수·q=0·구체적인 거부 범위를 검사한다. 표준 헤더의 단일 ASCII 형식과 필요한 이름의 Base64 sentinel을 먼저 확인한다.

SDK v1.8.0의 4 MiB 상한을 유지한다. 알려진 Content-Length 초과는 본문을 읽기 전에 거부하고, 길이 미상·chunked·작게 선언한 길이도 최대 상한+1 바이트의 제한된 읽기로 413을 반환한다. 이 단계는 JSON을 해석하지 않으며 초과 요청은 인증·업무 처리기를 호출하지 않는다. Bearer를 검증한 뒤 단일 JSON-RPC·필수 메타데이터·헤더와 본문의 대조·지원 revision·허용 RPC를 확인한다. 400/-32602·400/-32020·400/-32022·404/-32601을 구분하고 지원/요청 revision을 보존한다. 이전 초기화·알림·응답 POST·batch는 수용하지 않는다.

공식 SDK의 Stateless·JSONResponse·지원 revision 제한과 SetCacheable을 사용한다. 발견은 고정 supportedVersions·tools capability·serverInfo·instructions를 제공하고 발견/list에는 ttlMs=0·private를 둔다. 도구 호출은 발견 없이 독립 실행한다. SDK가 설정하는 HTTP 캐시 헤더는 실제 전송 시 no-store로 유지한다. SSE·프로토콜 세션·서비스 전용 필수 헤더를 추가하지 않는다.

공개 Host를 loopback 프록시로 전달할 수 있도록 보호 생성자에서만 SDK의 자동 localhost Host 거부를 해제한다. Origin·Bearer와 바깥 서버의 TLS 검사는 유지하며 Host나 전달 헤더로 계정·OAuth resource를 만들지 않는다. 인증 없는 비공개 SDK 관찰 처리기의 기본 Host 보호는 유지한다. SDK의 PropagateRequestCancellation을 명시해 원래 요청 취소가 실행 중 처리기의 context까지 전달되는지 확인했다. 실제 DB 업무의 시간 예산·단절 후 쓰기/재생 복구 인수는 MCP-08이 담당한다.

## 모듈 시험과 검증

Go 1.27.1에서 `-race -json -count=1 -timeout=120s`로 실행했다.

- MCP **283건**: `go test ./internal/mcp`. 기존 SDK·스키마·등록 경계와 새 전송 생성·Origin·메서드·미디어 타입·표준 외피·본문 크기·캐시·요청 주체·취소를 검증했다. 상한 미만/정확한 상한의 정상 JSON, 선언 길이/미상/축소 선언/실제 chunked의 초과, 큰 문자열·배열, 해석 오류, 8000자 Unicode escape·1000개 참조를 포함한다.
- 서버 **161건**: `go test -run '^Test(MCP02ProtectedTLSIntegration|PackageDependenciesMatchDesign|OPS03.*)$' ./cmd/server`. 기존 TLS·신뢰 프록시·주소·경로 보호와 패키지 경계를 회귀했다. 두 TLS 인스턴스에서 실제 코드 교환·서명 검증·공유 폐기·계정/client 분리·자격 부재/오류 401과 저장 장애 500을 확인했다. 공개 Host·허용 Origin, 발견 생략 호출·private 캐시와 실제 agent_register의 안정적인 ID를 대조했다.
- 인증 **92건**: `go test -run '^TestBearer.*' ./internal/authz`. 필수 클레임·서명·키·매 요청 공유 상태와 401/403/500 사상을 회귀했다.
- **중복 제외 536건 통과, 실패·건너뜀 0건, race 통과**. 전체 저장소 시험은 실행하지 않았다.
- 루트 `check-go.sh`: 의존성 검증·SDK 링크·전체 build·vet·gofmt 통과. 로그 `/private/tmp/acs-mcp02-check-go.log`.
- 시험 로그: `/private/tmp/acs-mcp02-mcp-final.json`, `acs-mcp02-server.json`, `acs-mcp02-authz.json`.

최초 컴파일의 UUID 메서드 이름을 기존 IsV7으로 수정했다. 첫 실행이 확인한 Accept 범위 판정 오류와 SDK의 캐시 헤더 덮어쓰기를 보완한 뒤 모듈을 재검증했다. 적용 SDK의 기본 취소 분리도 명시적 전파 설정과 실행 중 취소 시험으로 보완했다. 실패 실행은 위 완료 건수에 포함하지 않는다.

DB 실행마다 무작위 mcp02_suite DB에 TEST_DATABASE_URL과 TEST_DATABASE_REQUIRED=1을 고정했다. 실제 서버 시험은 다시 시험별 자식 DB를 만들고 연결 DB명·정식 마이그레이션을 확인했다. 기존 개발/운영 DB의 계정·토큰·키를 준비에 사용하지 않았으며 각 실행이 만든 DB만 정리하고 suite DB의 부재를 확인했다.

## 완료 판정과 후속

MCP-02의 보호 HTTP·발견·외피 검증 모듈을 완료했다. 서버 시험의 업무 13종은 합성 처리기이며 agent_register만 실제 등록 API를 호출한다. 생성자는 14종을 요구하므로 현재 main의 기동 경로에는 임시 처리기를 넣지 않는다. MCP-06·07에서 실제 업무 처리기를 조립하고 MCP-09에서 전체 서버 계약을 인수한다.

전체 개발 항목은 **63/124개 완료·61개 미착수**다. 다음 권장 작업은 [MCP-05](../development-plan/mcp.md#mcp-05)의 8종 쓰기 키·24시간 재생이다. AUTH-10·MCP-07도 선행 조건을 충족한다. 본인 연결 관리 화면·실제 Codex·Tunnel·운영 배포 인수는 별도다.

DOX pass에서 구조·소유권·허용 import의 변화가 없음을 확인했다. 분야별 SDD·계획·README·근거·요청 기록을 갱신하고 요구사항·용어·추적 ID는 유지했다. 기존 Compose·IDE 변경을 보존했으며 commit·push·PR 갱신·배포는 수행하지 않았다.
