# ARCH-01 도구 체인·의존성 준비 검증

## 범위와 결과

2026-10-14에 [ARCH-01](../development-plan/architecture.md#arch-01)을 수행했다. 입력은 [TRACE-01](../development-plan/traceability.md#trace-01)이 확정한 현재 SRS·분야별 SDD다. 작업 브랜치는 `feat/new-implementation`이며 작업 시작 커밋은 `8a99bd49c0619ff45d6d2e77dbd9d6be885fe476`이다. upstream은 설정되어 있지 않아 해당 브랜치의 원격 대비 상태는 확인할 수 없다.

기존 파일·의존성의 존재를 완료 근거로 승계하지 않고 이번 작업에서 실제 다운로드·체크섬 검증·빌드를 수행했다. Go 1.27.1 기준을 유지하고 공식 MCP SDK v1.8.0과 필요한 전이 의존성을 `go.mod`·`go.sum`에 고정했다.

## 산출물과 실행 방법

- [check-go.sh](../../../../check-go.sh)는 `go.mod`의 Go 판과 선택된 SDK의 정확한 판을 대조한다. `GOTOOLCHAIN=local`·`GOWORK=off`로 다른 도구 체인이나 외부 workspace로의 전환을 막고, 모듈 다운로드·체크섬·의존성 최소 실행 파일·전체 빌드·vet·형식을 검사한다. 빌드는 `-mod=readonly`를 사용한다.
- 기본 PATH에 Go가 없으면 `GO_BINARY`에 등록된 SDK의 `bin/go` 절대 경로를 지정한다. 이번 실행은 `/Users/alphagone/sdk/go1.27.1/bin/go`를 사용했다. IntelliJ 터미널 도구가 시간 내 결과를 반환하지 않아 같은 로컬 SDK의 명시적 경로로 검증했다.
- [.github/workflows/go.yml](../../../../.github/workflows/go.yml)은 `go-version-file: go.mod`로 같은 판을 선택하고 공통 스크립트를 실행한다. checkout v5.0.0과 setup-go v6.0.0은 공식 릴리스 커밋 SHA로 고정했다.
- [README](../../../../README.md#go-도구-체인과-빌드-검사)에 SDK 선택·명령·후속 시험 경계를 안내했다. 공식 근거는 [reference.md](../reference.md)의 2026-10-14 조회 행에 기록했다.

```sh
GO_BINARY=/Users/alphagone/sdk/go1.27.1/bin/go sh ./check-go.sh
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 \
  GO_BINARY=/Users/alphagone/sdk/go1.27.1/bin/go sh ./check-go.sh
```

## 새 실행 증거

- macOS/arm64: Go 1.27.1 확인, `go mod download`·`go mod verify`, pgx/pgxpool·go-jose·MCP SDK를 함께 링크한 최소 실행 파일 빌드, `go build -mod=readonly ./...`·`go vet -mod=readonly ./...`·같은 SDK의 `gofmt -l .` 통과. 종료 코드 0.
- Linux/amd64 교차 빌드: 위 스크립트를 GOOS·GOARCH·CGO_ENABLED 조건으로 실행해 동일 검사 통과. 종료 코드 0. Linux에서의 실제 실행·원격 CI 실행은 수행하지 않았다.
- 다른 SDK 거부: Go 1.26.1을 `GO_BINARY`로 지정했을 때 Go 1.27.1 필요 오류와 종료 코드 1을 반환했다. 모듈 다운로드·빌드 전에 거부했다.
- `sh -n check-go.sh` 통과. CI YAML의 문법·PR/dev/main 트리거·모듈 기준 SDK 선택·공통 실행 명령·contents read 권한·checkout 자격 비영속 설정을 확인했다.
- 변경 문서의 상대 링크·앵커 117개·코드 블록·새 기록의 표 구조와 `git diff --check` 통과. 요구사항 184건·기존 SRS/SDD/용어집 보존과 작업 124개 중 TRACE-01·ARCH-01만 완료임을 확인했다.
- 임시 Go 소스와 최소 실행 파일은 스크립트가 자신이 만든 디렉터리에서만 생성하고 종료 시 정리했다. DB·외부 제공자·수신 서버를 시작하지 않았다.

첫 MCP 모듈 다운로드는 샌드박스 DNS 제한으로 실패했으며 허용된 네트워크 실행에서 다운로드와 체크섬 확인을 완료했다. Modern Go Guidelines의 Go 1.27 전체 지침 목록을 확인했으며 생성한 최소 Go 소스는 import와 빈 main만 포함한다.

## 완료 판정과 후속 경계

ARCH-01의 도구 체인 선택·모듈/의존 판 고정·공식 근거·최소 실행 파일 빌드 완료 기준을 충족했다. 원격 CI 실행, 실제 DB 이미지·확장 runtime, SDK의 revision 제한·무상태 transport·캐시·취소 동작과 실제 Codex CLI 지원은 해당 후속 작업의 검증 대기다. [MCP-01](../development-plan/mcp.md#mcp-01)·[OPS-03](../development-plan/operations.md#ops-03)·실제 호스트 인수의 완료 상태를 승격하지 않았다. 업무 모듈·DB·호스트 시험은 이번 도구 체인 작업에서 실행하지 않았다.
