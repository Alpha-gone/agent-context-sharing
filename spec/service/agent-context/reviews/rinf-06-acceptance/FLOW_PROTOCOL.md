## 대응 조건

`agent_relations`와 `server_apply`는 같은 모델 `gpt-6-luna`, 본문, 사건 시각, 구성원 구조, 후보 채널, 문자·후보 예산, 관계 유형·방향 범위를 사용한다. 매 조건은 새 격리 DB와 새 그래프를 준비하며, 초기 추론 관계는 없다. 반복 홀수 회차는 에이전트 조건부터, 짝수 회차는 서버 조건부터 실행한다. 명시적인 캐시 예열·캐시 강제 삭제는 하지 않으며 제공자·DB/OS 공유 캐시는 통제 불가능한 공통 실행 조건으로 남긴다.

- 공통 프로필: prompt `2`, schema `1`, 다섯 채널 `semantic/keyword/member/rule/conversation`, 후보 8, 대상 2,000자, 후보 800자, 전체 9,000자, 색인 대기 1분, 시간 인접 1시간.
- 공통 생성 매개변수: `max_output_tokens=1536`, `service_tier=default`. 프로필 지문에 두 값 모두 포함하고 실제 어댑터 검증 및 wire 요청에서 대조한다. 유료 호출을 시작하기 전에 프로필·과업 checksum을 manifest에 내구 기록한다.
- 에이전트는 실제 Responses 함수 도구 중 `list_events`와 `confirm_relations`를 선택한다. 첫 도구는 실제 저장소 후보를 읽고, 두 번째 도구는 공통 출력·근거 검증 뒤 실제 저장소 관계 연산을 실행한다. 정답 후보·정답 유형은 모델에 제공하지 않는다. 최대 모델 호출 네 번이며 첫 목록 조회 전 관계 반영은 실패다.
- 서버는 실제 `DecisionProcessor`와 `Worker.RunOnce`를 실행해 후보 준비·판정·검증·반영을 거친다. 출력 오류 재시도는 기존 작업자의 최대 두 번만 허용하고, 추가 회차로 재시도를 숨기지 않는다.
- 두 조건 모두 `relates_to`·`part_of`를 확정할 수 있고 `causes`는 제안만 가능하다. 서버의 시험용 accepted 지문은 이 격리 DB 실행에서만 사용하며 운영 설정을 변경하지 않는다.

## 준비와 후속 조회

전체 시간은 격리 DB 생성·마이그레이션 **전**부터 잰다. 각 조건에서 원천·두 파생·세 사건 전체를 같은 Gemini 제공자로 임베딩하고 실제 색인 큐·벡터 저장을 거친다. `CheckGraphIndexReady`가 전체 그래프의 현재 모델·대기 작업 경계를 확인해야 관계 과업으로 진행한다. 최초 준비 비용을 버리거나 서버 조건에만 준비 비용을 전가하지 않는다.

후속 질의도 Gemini에 실제 전송하여 질의 벡터를 생성하고 `SemanticCandidates`를 호출한다. 이어 같은 대상에서 `SearchHopContextsFrom`으로 확정 관계의 실제 1홉을 조회한다. 의미 검색 후보 수와 관련·무관 홉 결과를 따로 기록하므로 의미 검색만의 적중을 관계 과업 성공으로 바꾸지 않는다. 마지막으로 저장소 관계의 유형·상태·방향을 사전 정답과 대조한다. 성공은 정상 종료, 모든 기대 관계 일치, 추가 오관계 0건, 기대 홉 반환 및 무관 홉 미반환의 교집합이다. 실패·시간 초과·출력 위반도 분모에 남긴다.

임베딩 경로는 기존 어댑터와 같은 Gemini `embedContent`, 768차원, `autoTruncate=false`, 문서/질의 접두어를 사용한다. `store` 시험에서 `index`를 import하면 순환 의존이 생겨 HTTP 경계만 시험 파일에 둔다. API·사용량 계약은 [Google Embeddings API](https://ai.google.dev/api/embeddings)를 따른다.

## 외부 제공자 사용량과 고정 단가

단가 판은 `2026-11-15-standard-272k-local-allocation-v1`, 통화는 USD다. 공급자 청구서를 확보한 금액과 구분하여 **실제 응답 사용량에 고정 공개 단가를 적용한 제공자 금액**으로 보고한다. 세금·조직 할인·무료 할당은 적용하지 않는다.

2026-11-15 확인한 [OpenAI 가격](https://developers.openai.com/api/docs/pricing)과 [프롬프트 캐시 계약](https://developers.openai.com/api/docs/guides/prompt-caching)에 따라 `gpt-6-luna` Standard 272k 이하 100만 token당 일반 입력 $0.10, 캐시 읽기 $0.01, 30분 캐시 쓰기 $0.125, 12시간 캐시 쓰기 $0.25, 출력 $0.50을 고정한다. 일반 입력은 전체 입력에서 읽기·두 TTL 쓰기를 뺀 값이며, 쓰기를 전체 입력에 다시 더하지 않는다. 두 TTL의 합이 `cache_write_tokens`와 다르거나 전체 입력보다 캐시 합이 크면 사용량 불완전이다. 출력에는 공급자가 출력으로 청구한 reasoning tokens가 이미 포함되므로 별도 가산하지 않는다.

Gemini `gemini-embedding-2` Standard 텍스트 입력은 [Google 가격](https://ai.google.dev/gemini-api/docs/pricing)에 따라 100만 token당 $0.20으로 고정한다. 준비 문서와 후속 질의의 `usageMetadata.promptTokenCount`를 모두 합산한다. 이 임베딩 경로에는 출력·프롬프트 캐시 요금 항목을 적용하지 않으며 해당 필드는 `null`이다. 요약 모델은 호출하지 않으므로 요약 비용은 명시적으로 적용 대상이 아니다.

모든 HTTP 시도는 호출 전 `provider_start`, 응답 뒤 `provider_end`로 기록하며 HTTP 상태·실측 지연·입출력·캐시 읽기·TTL별 쓰기·단가 적용액을 남긴다. 오류·불완전 응답의 사용량도 원시 본문 없이 해석 가능한 항목만 기록하고 미측정을 0으로 바꾸지 않는다. 입력 또는 캐시 구분을 확인하지 못하거나 전송/기록이 실패하면 후속 유료 호출을 즉시 막고 완전한 총비용을 주장하지 않는다.

이 실행기의 외부 호출 한도는 **$1**이다. 각 호출 전 UTF-8 요청 바이트 수와 framing 1,024 token, 최대 쓰기 단가, 최대 출력 1,536 token으로 상한을 예약하고, 완전한 실제 사용량을 받은 경우에만 차액을 반환한다. 사용량을 확인할 수 없는 시도는 예약을 유지한다. 키는 `RELATION_INFERENCE_API_KEY`·`EMBEDDING_API_KEY` 환경 변수에서만 읽으며 키·본문·원시 응답을 결과나 오류에 남기지 않는다.

## 로컬 검색·저장·계산 자원 배분 시나리오

실제 로컬 전기료나 클라우드 청구 단가를 확인한 것으로 표현하지 않는다. 측정 전에 다음 **가상 자원 배분 단가**를 고정하고, 측정한 과업 시간·DB 바이트에 적용한 배분 추정치를 제공자 금액과 분리한다.

- 애플리케이션과 DB를 합쳐 예약 vCPU 2개, 메모리 2 GiB를 각 과업에 전액 배분한다. vCPU-second당 $0.00001, GiB-second당 $0.000001이다. 준비·제공자 대기·색인·쓰기·검색의 전체 벽시계를 모두 포함하므로 DB CPU 실측을 0으로 대신하지 않는다.
- 저장은 각 단계에서 `pg_database_size`를 실측한 최댓값에 전체 시간과 최소 1일 중 큰 보관 시간을 곱한다. 단가는 GiB-month당 $0.10이고 1 month는 2,592,000초다. 별도 그래프 행만 계산하여 공통 색인 비용을 누락하지 않도록 격리 DB 전체 바이트를 배분한다. 이 값은 **최대 표본 저장량**이며 순간 물리 최대치라는 주장은 하지 않는다.
- 이 시나리오는 예약 자원에 준비·색인·검색·쓰기 CPU/I/O를 포함하고 별도 쿼리 종량 요금을 부과하지 않는다. 따라서 같은 작업을 쿼리 수와 CPU로 중복 과금하지 않는다. 계측 풀의 실제 SQL 명령 수는 마이그레이션 이후의 보조 관측값이다. 마이그레이션 SQL 수를 측정했다고 표현하지 않는다.
- 애플리케이션 프로세스 CPU는 지원 환경에서 `getrusage`의 사용자·시스템 CPU 차이를 별도로 실측한다. DB CPU는 `null`로 남긴다. CPU 측정값 대신 위의 예약 자원 단가를 금액의 기준으로 사용한다.

`total_cost_under_tariff_usd = provider_cost_usd + 2 × whole_seconds × 0.00001 + 2 × whole_seconds × 0.000001 + sampled_peak_db_bytes / 2^30 × max(whole_seconds, 86400) / 2592000 × 0.10`이다. 준비·반영·후속 검색까지의 실제 과업 범위에 대한 산식이며 시험 종료 후 격리 DB 제거는 측정 밖의 하네스 정리다. 외부 API 사용량이나 DB 저장량이 미측정이면 총액은 `null`이다. 이 총액을 실제 공급자 청구 총액으로 바꾸어 부르지 않는다.

## 실행·산출물·판정 경계

실행은 `TEST_DATABASE_REQUIRED=1`과 `TEST_DATABASE_URL`, 두 환경 키, 아직 존재하지 않는 `RINF_ACCEPTANCE_FLOW_DIR`를 지정한 뒤 `go test ./internal/store -run '^TestRelationAcceptanceFlow$' -count=1 -timeout 90m`으로 요청한다. 기존 결과 경로를 덮어쓰지 않으며 새 디렉터리 0700·새 파일 `O_EXCL` 0600을 사용한다. `flow.jsonl`은 manifest, run 시작, 호출 시작/종료, run 결과를 한 줄씩 `Sync`한다. 원시 응답·본문·개인 식별자는 저장하지 않는다. 실패한 호출 시작만 남아도 완료된 측정으로 해석하지 않는다. 생성 DB는 기존 격리 시험 helper가 자신이 만든 DB만 제거한다.

최종 분석에서는 과업별 열 회차 평균을 먼저 구하고 여섯 독립 단위의 대응 차이와 Student t 95% 구간을 계산한다. 전체/성공만 결과, 성공률·관계 오류·후속 검색·턴·지연·제공자 항목별 비용·배분 추정치·총비용을 함께 공개한다. 에이전트 token 절약만으로 총비용 절감을 주장하지 않는다. 성공률 악화나 추가 비용도 숨기지 않는다.

이 시험은 실제 모델과 저장소를 연결한 **합성 과업 전체 흐름 측정**이다. MCP 전송·호스트 상호운용, 일반 업무의 운영 효과, 실제 청구서의 완전한 인수로 확대하지 않는다. 품질 표본·독립 정답 검토·후보 검색·프로필 일치 검증과 함께 판단하며 `default_activation=false`를 유지한다. 이 문서를 작성하거나 비유료 산술 시험을 통과한 사실만으로 실제 흐름 측정 완료를 선언하지 않는다.
