## 구현과 검토

- 일곱 공통 규칙을 명세와 대조하고 새 표본으로 실행했다. 파생 근거 1~100개·대체 0~1개·사건 구성원 1~1000개의 저장 상태 경계, 쓰기 범위 정점의 존재·그래프 소속과 hot/cold 중복 임베딩을 보강했다.
- 정상 Cypher 조회는 실제 양 끝점이 모두 있어야 간선을 반환한다. 우회 SQL 삭제로 끝점이 사라진 간선을 놓치지 않도록 일곱 label의 SQL LEFT JOIN 보충 조회를 쓰기·전체 감사의 같은 스냅숏 적재 경로에 넣었다. 소실된 공개 식별자 대신 `age:<내부 graphid>` 위치를 보고하며 본문·벡터를 읽거나 출력하지 않는다.
- 보충 조회의 쓰기 범위는 `context_id` agtype 표현식으로 실제 끝점 id를 구한 뒤 `start_id/end_id` 조건으로 제한한다. SQL 속성 키의 `::text`는 AGE `search_path`에서 agtype 연산자로 잘못 해석되는 것을 막는다.
- 순환 검사는 기존 영향 주변부 적재와 그래프 전체의 확정 관계 경로 판정을 함께 사용한다. 네 사건의 순환에서 쓰기 범위에 직접 닿은 두 간선과 전체 감사의 네 간선이 같은 규칙·위치로 보고되는지 새로 확인했다.
- `AuditGraph`는 읽기 전용 REPEATABLE READ 안에서 그래프 존재를 확인한다. 없는 그래프를 정상 감사로 처리하지 않고 `ErrNotFound`를 반환한다. 요청 취소와 별개인 유한 예산으로 롤백하고 원인·종료 실패를 보존하며, 종료에 실패하면 정상 결과를 반환하지 않는다.
- 감사 CLI는 전역 flag 상태 대신 호출별 입력을 해석한다. 그래프 식별자·불필요한 위치 인자를 DB 연결 전에 검사하고 SIGINT를 요청 컨텍스트로 전달한다. JSON Lines 출력 실패도 감사 완료 불가로 반환한다. 제공자 메타데이터만 검증하고 외부 임베딩 API는 호출하지 않는다.
- 마이그레이션·복구 후 전체 감사와 실패 시 서비스 개방 중단은 [운영 매뉴얼](../../../../OPERATIONS.md)의 기존 실행 절차를 확인했다. 자동 수정·삭제는 추가하지 않았다.

## 환경과 결과

- Go 1.27.1 darwin/arm64, PostgreSQL 18.6 / Apache AGE 1.8.0 / pgvector 0.8.6 / Linux aarch64.
- 저장소 Dockerfile의 고정 이미지·패키지로 `agent-context-data06-db`를 빌드했다. 같은 이름의 새 컨테이너·볼륨을 만들고 loopback 동적 포트만 공개했다. 일반 모듈 DB와 별도 CLI DB 모두 정식 001·009·010·011을 적용했다. 기존 `.env`·DB·볼륨·자격 증명과 외부 API는 사용하지 않았다.
- 대상 모듈·하위 시험 **63건 통과**: store 46건·audit 17건, 최상위 19개·하위 44개. `TEST_DATABASE_REQUIRED=1`, `-race`, `-count=1`을 적용했고 최종 판정의 실패·건너뜀은 0이다. 전체 저장소 시험이나 분야 통합 인수 결과가 아니다.
- 일곱 규칙별 단독 위반에서 쓰기 검사와 전체 감사의 규칙 ID·위치를 대조했다. 실제 쓰기 거부·롤백, 기수성 상한 수용과 초과 거부, 두 파티션 중복 임베딩, 소실된 끝점, 주변부 밖 순환을 확인했다.
- 감사 트랜잭션 도중 취소와 롤백 SQL 실패를 실제 pgx 경계에서 유도했다. 취소 원인·종료 오류 보존과 실제 획득 연결·예약의 반환을 확인했다. 정상 반복 감사도 같은 위반 위치를 유지했다.
- CLI 모듈 시험에서 활성·삭제 그래프의 전체/단일 범위, 유효한 JSON Lines, 원문 비노출과 출력 장치 실패를 확인했다. Gemini 키 없이 실행했다.
- 별도 DB에서 실제 감사 실행 파일을 실행했다. 빈 DB·정상 그래프·도움말은 0, 전체 범위의 삭제 그래프 위반과 해당 단일 그래프는 1, 부재 그래프·잘못된 식별자·불필요한 인자·미지원 제공자는 2였다. 감사 전후 관계형 그래프 행과 AGE 정점 property의 정렬된 지문이 같았다.
- 최초 시험에서 보충 SQL의 속성 키가 agtype으로 해석되어 실패했다. `::text`를 명시한 뒤 관련 모듈을 다시 검증했다. 같은 원인의 우회 삭제 fixture도 수정하고 고아 간선 회귀를 통과시켰다.
- `check-go.sh`의 의존성 검증·전체 build·vet·gofmt를 통과했다. 문서 링크·작업 수·Markdown·DOX 소유/색인과 `git diff --check`를 대조했다.

### 보충 조회의 실제 실행 계획

다른 그래프를 함께 둔 합성 허브 표본에서 실제 보충 SQL을 EXPLAIN ANALYZE·BUFFERS로 검사했다. 아래는 단일 실행 표본이며 운영 지연·개선율을 보장하지 않는다.

| 그래프당 이웃 | 반환 행 | Context 스캔 | DERIVED_FROM 스캔 | 공유 hit/read | 실행 ms |
|---|---:|---:|---:|---:|---:|
| 1,000 | 0 | 13 | 1 | 62/0 | 3.897 |
| 10,000 | 0 | 14 | 1 | 65/0 | 4.738 |

기존 정방향·역방향·정점·정렬 홉 조회의 인덱스 및 전체 스캔 회귀도 함께 통과했다. 응답 행 수를 DB 스캔 상한으로 대체하지 않았다.

## 완료 판정과 남은 범위

- DATA-06의 구현·모듈 시험 완료. 전체 계획은 14/124개 완료·110개 미착수이며 다음은 [DATA-07](../development-plan/data.md#data-07)이다.
- DOX 구조·소유권·공개 계약은 바뀌지 않아 DOX·SRS·SDD·용어집을 유지했다. 기존 SQL과 적용 이력도 변경하지 않았다.
- 운영 DB·실제 복원 후 전체 감사·전체 저장 인수·외부 API·호스트·amd64 runtime은 미실행이다. 마이그레이션·복구 후 감사는 절차 연결 확인과 새 DB CLI 검증 범위다.
- 시험 자원은 작업 라벨을 대조한 뒤 이 작업이 만든 컨테이너·볼륨·이미지만 정리했다. 이름으로 다시 조회하여 잔여 자원 0을 확인했다. 커밋·푸시는 수행하지 않았다.
