# TEST-08 실제 Codex CLI 전송 검토

## 정정과 현재 판정

**macOS/arm64 Codex CLI 0.160.1 `exec`는 `features.mcp_2026_07_28=true`에서 MCP 2026-07-28 발견·목록 전송을 통과했다.** 이전 시험은 기본 비활성인 기능 플래그를 누락했다. 그때 관찰한 initialize·2025-06-18의 거부는 사실이지만 이를 호스트의 지원 실패로 일반화한 판단은 잘못이었다. 초기 지원 실패 판정과 호스트/revision 재선정이 필요하다는 결론을 철회한다.

공식 OpenAI [변경 이력](https://learn.chatgpt.com/docs/changelog)의 **2026-08-07 Codex CLI 0.147.0** 항목이 MCP 2026-07-28의 opt-in 지원을 명시한다. 설치된 0.160.1의 `codex features list`에서도 `mcp_2026_07_28`이 under development·false로 표시되었다. 기능을 포함한 판과 활성화한 실행 구성을 구분해야 한다. 사용자 지적 뒤 이 설정을 확인하고 같은 설치 판·서버 revision으로 재검증했다.

전송 사전 인수만 완료했다. TEST-08과 TBD-064의 전체 지원 판정은 진행 중이다. 목표 revision·SDK·호스트 판과 [시험 계약](../sdd/testing.md#첫-codex-cli-상호운용-시험)을 유지하며 이전 revision을 허용하거나 어댑터를 추가하지 않았다. TUI·Codex 앱·IDE는 이번 실행 대상이 아니다.

## 실행 범위와 격리

`cmd/server/codex_interop_test.go`에서 실제 CLI 자식 프로세스를 전체 조립 TLS 서버에 연결했다. Go 1.27.1·SDK v1.8.0·PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6을 사용했다. 수정한 서버/호스트 시험 구성 판은 `test08-transport-v2`다. 합성 계정과 사전 등록 codex-cli-first-test·정확한 127.0.0.1:49152/callback 결합으로 직접 발급한 시험 Bearer를 사용했다. 이는 호스트의 최초 OAuth 인가를 수행한 증거가 아니다.

자식은 별도 임시 Codex 상태 루트와 환경 허용 목록을 사용한다. 부모의 API 키·프록시·기존 Codex 자격을 전달하지 않고 모든 모델 요청은 로컬 거부 대역으로 보낸다. 외부 모델 추론·운영 공개·기존 사용자 설정 변경은 수행하지 않았다. 관찰에는 토큰·코드·계정·URI·본문·CLI 원문을 남기지 않고 판·단계·시각·비식별 상관 ID와 프로토콜 필드만 사용한다. 이번 기능 플래그도 임시 시험 구성에만 기록했다.

## 같은 판의 비활성·활성 대조

최종 실행 시각은 **2026-10-26 23:43:57 KST**, 비식별 상관 ID는 `transport-1`이다. 같은 CA/서버 인증서를 쓰는 일반 HTTPS 대조에는 1회 도달했고 TLS 인증서 거부는 0회였다.

- `features.mcp_2026_07_28=false`: 이전 `initialize`·2025-06-18 요청이 HTTP 400/-32020으로 거부되는 것을 예상한 비활성 대조로 확인했다. 이 거부는 호스트의 해당 revision 미지원 판정이 아니다.
- `features.mcp_2026_07_28=true`: 이전 초기화 없이 `server/discover`·`tools/list`를 보냈다. 두 요청 모두 2026-07-28의 요청별 메타데이터·clientCapabilities와 MCP-Protocol-Version·Mcp-Method가 일치하고 HTTP 200으로 통과했다.

활성 구성에서 실제로 관찰한 안전한 필드는 다음과 같다.

```json
[
  {
    "http_method": "POST",
    "rpc_method": "server/discover",
    "header_revision": "2026-07-28",
    "header_method": "server/discover",
    "initialize_revision": "",
    "revision": "2026-07-28",
    "capabilities": true,
    "status": 200,
    "error_code": 0
  },
  {
    "http_method": "POST",
    "rpc_method": "tools/list",
    "header_revision": "2026-07-28",
    "header_method": "tools/list",
    "initialize_revision": "",
    "revision": "2026-07-28",
    "capabilities": true,
    "status": 200,
    "error_code": 0
  }
]
```

모델 대역은 의도적으로 요청을 거부하므로 CLI 프로세스 자체는 정상 과업 완료를 보고하지 않는다. 시험 합격의 범위는 실제 MCP 발견·도구 목록 전송까지다. 최초 브라우저 동의·callback 수신·issuer 응답·호스트 안전 저장/복원·접근 만료/회전·유휴·재시작·폐기·키 회전·저장 장애·다중 인스턴스·응답 유실·동시 갱신·등록/읽기/쓰기/재조회는 **호스트 미실행**이다. 다음 인수에서는 동일한 기능 활성 구성에서 이 흐름을 수행해야 한다.

## 명령과 결과

```sh
TEST_DATABASE_URL='<격리 시험 DB>' TEST_DATABASE_REQUIRED=1 \
TEST_CODEX_BINARY='<설치된 Codex CLI 0.160.1 실행 파일>' \
TEST_CODEX_REQUIRED=1 GOCACHE=/private/tmp/acs-eval12-go-cache \
/Users/alphagone/sdk/go1.27.1/bin/go test -race -count=1 \
  -run '^TestTEST08' -v -timeout=120s ./cmd/server
```

- 최종 실제 CLI 전송 시험 **1건 통과**, 실패·건너뜀 없음, 패키지 **2.632초**. 같은 시험에서 비활성 대조·활성 발견/목록과 일반 HTTPS 대조를 실행했다. 결과는 `/private/tmp/acs-test08-flag-final.log`다.
- 최종 의존성 검증·전체 build·vet·gofmt가 통과했다. 결과는 `/private/tmp/acs-test08-flag-static-final.log`다.
- 앞선 23:23 실행의 서버 계약/TLS 관련 회귀 **104건**(최상위 2건, 하위 사례 포함)은 **2.996초**에 필수 DB·race에서 실패·건너뜀 없이 통과했다. 서버 제품 코드는 이후 변경하지 않았다. 이 결과는 `/private/tmp/acs-test08-server-regression.json`에 남긴 당시 서버 근거이며 이번 호스트 시험 수에 중복 합산하지 않는다. TEST-09 전체 시험은 실행하지 않았다.

초기 비승격 실행은 loopback DB 접근 제한 때문에 실패하여 생성 권한과 실행 환경을 확인했다. httptest 기본 인증서를 사용한 초기 TLS 표본도 거부되어 별도 임시 CA와 CA=false 서버 인증서로 교체했고, 그 뒤 일반 HTTPS 도달과 MCP 요청 수신을 확인했다. 이 예비 실패들과 기능 비활성 상태에서 얻은 `/private/tmp/acs-test08-final.log`의 23:23 실패 기록은 보존하되 최종 지원 실패 근거로 사용하지 않는다. 최종 원인은 제품 미지원이 아니라 시험의 기능 활성화 누락이었다. 자식 취소는 interrupt와 유한 대기로 처리하고 각 실행·전체 시험의 시간 상한을 유지했다.
