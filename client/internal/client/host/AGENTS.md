# 클라이언트 호스트 중계

## 목적

- 호스트 MCP stdio, 공개 정책·입력 검증, 응답 보존과 요청별 취소를 소유한다.

## 소유권

- 상위 `client/AGENTS.md`와 클라이언트 SDD가 모듈·동작 계약을 소유한다.
- 인증·HTTP 전송은 원격 인터페이스에 맡기고 서버 내부 패키지를 사용하지 않는다.

## 로컬 계약

- 발견은 SDK가 처리하고 도구 요청은 `Tools`가 처리한다. 원격의 완전한 13종 검증 없이 부분 목록을 공개하지 않는다.
- 발견·도구는 진행 중 ID 충돌을 접수 단계에서 거절한다. SDK 발견 응답은 접수한 ID의 대기만 해제하며 단일 writer의 기록 시작 직전에 ID를 해제한다. SDK 출력 실패는 입력과 호출 수명을 끝내고 EOF 응답 대기를 중단해 SDK가 응답을 쓰지 않는 후속 발견으로 종료가 멈추지 않게 한다.
- 목록과 호출에 같은 구성 정책을 적용하며 여섯 도구에는 구성의 행위 에이전트만 주입한다. 목록 준비와 전송에 원격 호출 범위를 공유한다.
- 결과·원격 오류는 줄 프레이밍 공백만 제거하고 도구 본문의 필드·순서·숫자·문자열을 재해석하지 않는다. 호스트 ID와 MCP 외피의 클라이언트 `serverInfo`·`complete` 결과 유형만 적용한다.
- 로컬 호출 오류는 `structuredContent.client_error`, 목록 오류는 JSON-RPC `-32603`의 `data.client_error`에 일곱 코드를 담는다. SDK 목록 API가 실패를 빈 성공 목록으로 해석하지 않아야 한다. 검증된 원격 JSON-RPC 오류는 원격 오류 객체로 반환하고 도메인 오류는 재포장하지 않는다.
- stdin EOF는 원격 호출을 취소한 뒤 접수한 응답을 기록한다. 명시적 취소 통지를 받은 요청은 출력 대기 중이거나 뒤늦게 성공해도 아직 기록하지 않은 응답을 생략한다. 요청별 취소는 해당 호출에만 적용하며 응답 기록 또는 생략 직전 완료한 ID를 해제한다. 오래된 호출의 정리가 새 호출을 지우지 않는다.
- 입력·출력 상한과 단일 writer를 유지한다. 로그에는 내부 생성 상관 ID와 허용된 도구 이름·결과 범주만 사용한다.
- 초과 입력의 ID는 입력 상한 안에서 완전한 토큰만 회수한다. 숫자는 뒤쪽 JSON 구분자, 문자열은 닫는 따옴표를 확인하지 못하면 `id=null`로 반환한다.
- 원격 호출 범위와 slot은 호스트 응답 기록 또는 취소에 따른 생략까지 유지한다. 호스트 미기록 도구 요청은 최대 136개로 제한하고 초과 응답에는 출력 backpressure를 적용한다.

## 작업 지침

- SDK의 구조체 변환이나 자동 도구 등록으로 원격 결과·호스트 스키마를 바꾸지 않는다.

## 검증

- 실제 stdio 왕복으로 세 정책·13종·여섯 주입·우회 거부·일곱 오류·원격 오류·평면 응답을 검증한다.
- 공식 SDK로 목록 성공·일곱 오류 노출을 확인한다. 동시 ID, ID 재사용, 프레임 상한·복구, 요청 취소·뒤늦은 성공·출력 대기 취소·EOF·신호와 race 시험을 수행한다.
- 발견의 숫자·문자열 중복 ID 뒤 EOF, 발견·도구 간 양방향 ID 충돌, 완료 뒤 ID 재사용, 다른 ID 응답의 대기 보존과 SDK 출력 실패·부분 쓰기 뒤 종료를 확인한다.
