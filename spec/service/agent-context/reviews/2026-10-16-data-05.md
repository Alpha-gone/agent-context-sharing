# DATA-05 조회 인덱스·통계 모듈 시험

## 범위와 입력

- 대상: [DATA-05](../development-plan/data.md#data-05), 선행 DATA-02·DATA-03 완료. 시작 커밋 `693a88d`, 브랜치 `feat/data-schema-contract`.
- 정본: [인덱스](../sdd/data.md#인덱스), [방향별 영향 주변부](../sdd/data.md#그래프-불변식-규칙과-감사), [시험 시점](../DEVELOPMENT_PLAN.md#테스트-작성과-실행-시점).
- 원격 `dev`의 실제 HEAD와 로컬 `origin/dev`가 `d7af8e4`로 같으며 현재 브랜치는 앞섬 6·뒤처짐 0이다. pull·커밋·푸시는 수행하지 않았다.

## 구현과 검토

- 설계의 필수 인덱스와 현재 DDL을 대조하여 누락된 `revoked_token(expires_at)`을 새 `011_query_statistics.sql`에 추가했다. 기존 001·009·010과 적용 이력은 변경하지 않았다.
- 011에서 업무 테이블·임베딩 부모와 파티션·AGE 정점과 일곱 간선의 통계를 같은 적용에 수집한다. 이미 존재하는 PK·UNIQUE·조회 인덱스를 중복 생성하지 않았다.
- `pg_index`와 `pg_get_indexdef`로 37개 인덱스의 소유 스키마·테이블·유일성·사용 가능 상태·열 순서·부분 조건·agtype 표현식·C 정렬을 검증했다. vector/halfvec 양쪽 HNSW는 영향받은 목표 스키마 시험에서 확인했다.
- 원천 자연 키·로그인·활성 서명 키·색인 작업의 중복 쓰기를 두 연결에서 겹쳤다. 실제 `pg_blocking_pids` 대기 관찰 후 첫 연결을 커밋하고 두 번째 쓰기가 정확한 인덱스의 `23505`로 거절되는지 확인했다. 저장소 호출 전 검증이나 직렬 호출만으로 DB 경합을 대신하지 않았다.
- 쓰기 주변부의 실제 `loadAuditSnapshot` 질의를 관찰하는 시험 어댑터와 실제 `hopCandidateSQL`을 사용해 실행 계획을 측정했다. 방향별 간선 조회·합치기와 정렬된 후보 질의는 기존 구현이 현재 계약을 충족함을 새로 검증했다.
- 관련 회귀의 조밀한 간선 fixture가 관계 식별자·끝점·제안/확정 주체·시각 없이 간선을 만들어 DATA-04의 `relation_decode` 검증에 거부됐다. 현재 모델의 속성을 생성·검증하도록 fixture를 보완하고 동일 회귀를 다시 통과시켰다. AGE 1.8.0의 map SET 입력은 중간 WITH 별칭으로 전달했다. 운영 검증을 완화하지 않았다.

## 환경과 결과

- Go 1.27.1 darwin/arm64, Docker 29.8.2. 별도 컨테이너 `data05-db`, 새 볼륨과 loopback 동적 포트를 사용했다. 합성 계정·그래프·토큰만 생성했고 실제 `.env`·기존 DB·볼륨·외부 API는 사용하지 않았다.
- 저장소 Dockerfile의 고정 이미지와 패키지로 빌드했다. 실제 PostgreSQL 18.6 / AGE 1.8.0 / pgvector 0.8.6 / Linux aarch64를 확인했다.
- 새 DB에 정식 001·009·010·011 적용, CLI up 재실행·status의 추가 적용 없음, 010→011 전환의 토큰 1,000건·만료·기존 이력 보존, 같은 적용의 행 통계, SQL 직접 반복 실행을 확인했다. vector/768·halfvec/3072 신규 적용과 기존 형상 이행·실패 롤백·단일 연결 동시 적용도 통과했다.
- 대상 모듈·하위 시험 **114건 통과**: store 83건·migrate 31건, 최상위 17개·하위 97개. 최초 선택 실행의 조밀한 간선 fixture 실패는 수정 후 해당 시험의 race 재실행으로 해소했다. 최종 판정에서 실패·건너뜀 0이며 전체 저장소 시험을 의미하지 않는다.
- `check-go.sh`의 의존성 검증·전체 build·vet·gofmt 통과. 변경 문서 링크·작업 수·Markdown·DOX 색인과 `git diff --check`를 검증했다.

### 실제 실행 계획

합성 허브당 이웃 1,000·10,000개와 같은 크기의 다른 그래프를 함께 배치했다. 다음은 재검증에서 얻은 단일 실행 표본이며 운영 지연이나 개선율을 보장하지 않는다. 스캔 행은 실행 계획의 실제 행·필터 탈락 행·반복을 집계하고 버퍼는 최상위 누계다.

| 이웃/그래프 | 질의 | 반환 행 | Context 스캔 | DERIVED_FROM 스캔 | 공유 hit/read | 실행 ms |
|---|---|---:|---:|---:|---:|---:|
| 1,000 | 주변부 정방향 | 1 | 2 | 1 | 24/0 | 0.040 |
| 1,000 | 주변부 역방향 | 0 | 1 | 0 | 20/0 | 0.021 |
| 1,000 | 주변부 정점 | 2 | 2 | 0 | 4/0 | 0.018 |
| 1,000 | 정렬 홉 후보 | 10 | 98 | 75 | 324/0 | 0.604 |
| 10,000 | 주변부 정방향 | 1 | 2 | 1 | 24/0 | 0.035 |
| 10,000 | 주변부 역방향 | 0 | 1 | 0 | 20/0 | 0.027 |
| 10,000 | 주변부 정점 | 2 | 2 | 0 | 4/0 | 0.019 |
| 10,000 | 정렬 홉 후보 | 10 | 98 | 75 | 320/0 | 0.448 |

- 주변부 시작점은 `context_context_id_agtype_idx`, 정렬 홉은 `context_active_graph_context_idx`와 `derived_from_hop_endpoints_idx`를 실제 사용했다. 후보의 메모리 정렬·행·버퍼·임시 I/O도 기록했으며 위 표본의 임시 read/write는 모두 0이다.
- 첫 작은 표본의 역방향 질의는 2,000개 간선 순차 스캔을 선택했다. 뒤의 큰 표본·관련 홉 회귀 수행 이후에는 작은 표본도 끝점 인덱스를 선택했다. 통계·테이블 상태에 따른 이 차이를 보존하며 작은 테이블에 특정 계획을 강제하지 않는다. 큰 표본의 전체 스캔 회귀는 시험에서 거부한다.
- 별도로 1,000·10,000행의 관계형 fixture에서 로그인·그래프 목록·등급·팀 구성원·대기 작업·컨텍스트/관계/그래프 감사·웹/팀 감사·만료 토큰 삭제의 11종 질의가 해당 인덱스를 실제 사용하는지 확인했다. 실행 범위는 0.004~0.119ms, 임시 I/O는 0이었다. 감사의 그래프별 결과는 표본에 따라 10·100행으로 증가했으며 LIMIT를 스캔 상한으로 보고하지 않았다. 삭제를 포함한 fixture는 트랜잭션 롤백으로 정리했다.
- 관련 홉 회귀는 이웃 1,000·20,000·50,000, 후보 probe 경계, 다중 시작점·조밀한 내부 간선·제안/삭제 제외와 결과 동등성을 확인했다. 연결 점유·예약 반환도 대조했다.

실행 명령에서 합성 DB URL은 생략했다. 첫 명령의 조밀한 간선 fixture 실패를 수정한 뒤 두 번째 명령으로 해당 범위를 재검증했다.

```sh
TEST_DATABASE_URL='<새 합성 전용 DB URL>' TEST_DATABASE_REQUIRED=1 AGE_GRAPH_NAME=agent_context GOTOOLCHAIN=local \

-run 'Test(Query|TargetSchema|MigrationRollbackAndInvalidPreparation|ConcurrentMigrationSingleConnection|HopSelective|HopHubBoundedWork|HopCandidateSQLBoundaries|InvariantViolationBlocksWrite)'

TEST_DATABASE_URL='<같은 합성 전용 DB URL>' TEST_DATABASE_REQUIRED=1 AGE_GRAPH_NAME=agent_context GOTOOLCHAIN=local \
/Users/alphagone/sdk/go1.27.1/bin/go test -race -json -count=1 -timeout=120s ./internal/store \
```

## 완료 판정과 남은 범위

- DATA-05의 인덱스·통계와 실제 실행 계획 모듈 시험을 완료했다. 다음은 [DATA-06](../development-plan/data.md#data-06)의 공통 그래프 불변식·읽기 전용 감사 신규 구현과 검증이다.
- DATA-07 이후의 벡터·온라인 계층 전체 검증, DATA-10 저장 전체 인수, 운영 DB 적용·실제 호스트·외부 API·amd64 runtime은 미실행이다.
- DOX pass: 소유권·패키지 경계·작업 흐름·요구사항·설계·용어는 유지하므로 DOX·SRS·SDD·용어집을 변경하지 않았다. 필수 인덱스를 기존 설계대로 보충했으며 완료 근거·계획·출처·요청 기록을 갱신했다. 기존 사용자 Compose·IDE 변경은 보존했다.
- 이번 시험에서 만든 컨테이너·볼륨·이미지를 정리하고 해당 이름·label의 잔여 자원 0을 확인했다. 공유 Docker 네트워크·기존 이미지·다른 작업의 자원은 보존했다.
