# 분야별 개발 계획 영역

## 목적

- 이 영역은 분야별 SDD를 처음부터 구현하기 위한 작업·선행 조건·산출물·완료 기준을 관리한다.

## 소유권

- [DEVELOPMENT_PLAN.md](../DEVELOPMENT_PLAN.md)는 전체 계획의 진입점·분야 색인·단계 의존성·시험 시점을 소유한다.
- 각 계획 파일은 같은 이름의 `../sdd/*.md`에 대응하는 개발 작업을 소유한다.
- [traceability.md](traceability.md)는 요구사항과 개발·인수 작업의 대응 및 계획 상태 검증을 소유한다. 설계 추적·미정 사항의 정본은 [설계 추적표](../sdd/traceability.md)다.

## 로컬 계약

- 현재 SRS와 채택된 SDD를 기준으로 새로 구현한다. 기존 코드·테스트·완료 표시·과거 측정을 신규 구현의 완료 근거로 사용하지 않는다.
- 모든 신규 작업은 미착수에서 시작하며 새 산출물과 검증 증거를 확보한 뒤에만 완료 상태를 갱신한다.
- 테스트 코드 작성·보강·실행은 루트 검증 계약과 [계획의 시험 시점](../DEVELOPMENT_PLAN.md#테스트-작성과-실행-시점)을 따른다. 분야 계획의 시험 요구·완료 기준은 해당 작업의 모듈 시험 또는 분야별 통합 테스트에 배치한다.
- 작업 ID는 분야 접두사·두 자리 번호로 유지한다. 선행 관계·추적표는 작업 ID 앵커로 연결하고 각 작업에 선행 조건·구체 작업·산출물·관찰 가능한 완료 기준을 둔다.
- 일정·담당자·지원·성능을 근거 없이 확정하지 않는다. 계약·미정 사항·운영 기본값의 변경은 소유 SRS·SDD에서 먼저 수행한다.
- 계획 작성·검증과 실제 구현·실증은 구분한다. 계획 문서가 구현·DB·배포·호스트 설정의 실행 권한을 추가하거나 기존 데이터·적용 이력 삭제와 마이그레이션 재번호화를 전제하지 않는다.

## 작업 지침

- 대상 SDD와 교차 분야 계약을 확인하고 작업 추가·분리·이동 시 진입점·선행 링크·요구사항 대응을 함께 갱신한다.
- 완료 증거는 검토·기록 관례로 연결하며 과거 기록의 시점·범위는 보존한다.

## 검증

- SDD 분야와 계획의 대응, 진입점 링크 및 폐기된 항목을 제외한 설계 대상 ID의 개발·인수 대응을 확인한다.
- 작업 ID·선행 링크·요구사항 ID와 선행 관계의 순환을 검사한다.
- 미실행·건너뜀·실패·통과를 구분하고 호스트 지원·평가 채택에 필요한 실증 조건을 보존한다.
