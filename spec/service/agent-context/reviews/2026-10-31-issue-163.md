# #163 인증·웹 방어 깊이 처리

## 범위와 판정

- bcrypt: 현재 형식의 저장 비용이 구성 비용보다 낮으면 성공 로그인에서 기존 조건부 갱신 경계를 사용해 재해시한다. 실패 로그인과 더 높은 비용은 변경하지 않는다. 비용 혼재의 시간 신호와 4~31 상단 비용의 기동 지연은 남긴다. 모든 비용 대조·고정 지연은 작업 점유를 늘리며 장비 실측 없이 새 상한을 정하지 않는다.
- 공개 키: 정상 적재 후 10초가 지나면 알려진 키도 다시 읽고 목록을 교체한다. 저장된 은퇴 키는 유지하며 삭제 키는 제거한다. 재조회 장애에는 오래된 키를 사용하지 않고 세대가 바뀐 적재는 게시하지 않는다.
- 프레임: 모든 동적 응답에 출처·세션 검사 전 DENY와 frame-ancestors none을 적용한다. 자산 캐시 계약은 유지한다.
- 쿠키: TLS는 __Host- 이름을 읽고 설정·삭제한다. 기존 이름으로 대체 인증하지 않아 전환 시 재로그인이 필요하다. 허용된 로컬 HTTP 시험의 기존 이름은 유지한다.
- token·JWKS: 이번에는 선행 키 준비·요청별 DB 조회와 빈도 제한 부재를 유지한다. 잠금 중 추가 연결 확보를 피하는 발급 계약과 최초 키 초기화를 보존한다. 별도 출처 예산·정상 갱신 오탐을 검증하지 않은 전역 제한은 도입하지 않는다. 반복 공개 요청 비용은 해소된 것으로 간주하지 않는다.

이슈가 허용한 항목별 미적용 사유를 위에 기록했다. [인증 정본](../sdd/authentication.md)과 [웹 정본](../sdd/web.md)에 지속되는 동작·잔여 경계를 반영했다. SRS 요구사항·환경 구성·스키마·DOX 소유권은 바뀌지 않아 유지했다.

## 검증

- Go 1.27.1의 `check-go.sh`: 의존성 확인·링크, build·vet·gofmt 통과.
- `go test -race -json -count=1 ./internal/authz ./internal/web ./cmd/server`: 인증 435·웹 646·서버 312개 시험 및 하위 사례 통과, 각각 10·15·83개 건너뜀. TEST_DATABASE_URL·별도 환경 인수 조건이 없어 실제 DB·브라우저·외부 호스트 인수 완료를 뜻하지 않는다.
- 삭제 키·재조회 장애·비용 상향/보존·실패 로그인 불변·프레임 헤더·쿠키 속성·TLS의 기존 이름 거부를 회귀 검증했다.
- 독립 코드 검토에서 차단 결함은 없었다. 신규 시험의 조회 오류 확인 제안은 반영했다.
- `node --check internal/web/browser_acceptance_test.cjs`와 diff 공백·변경 문서 상대 링크 검사 통과. 실제 브라우저 인수는 미실행이다.
- 최초 샌드박스 실행은 HTTPS 리스너·Go 캐시 접근 제한으로 중단되었고 허용 환경에서 재실행했다.
