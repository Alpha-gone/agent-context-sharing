## 구현과 보호 경계

`NewRecorder`는 파일 준비 뒤 저장 정책의 기동 회차를 성공시킨 다음 기록 루프·시간 회차를 시작한다. 기동·회전·시간 회차·새 쓰기는 같은 저장소 공유 잠금과 정책을 사용한다. 정책·시계·시험 회차는 비공개 경계이며 새 환경 변수·외부 의존성을 추가하지 않았다.

- 다음 행을 더해 활성 파일이 10 MiB에 도달하기 전 또는 UTC 날짜 변경 때 close·고유 이름의 배타적 rename·0600 활성 파일 생성을 수행한다. Linux와 macOS 각각의 덮어쓰기 금지 rename을 사용한다. 같은 날짜의 재시작은 기존 행에 append한다.
- 활성 포함 종류별 10개/100 MiB·instance 600 MiB·전체 1 GiB를 매번 계산한다. 이전 슬롯과 임시 정리 파일도 포함하며 추가 쓰기·회전·임시 복사 공간을 먼저 예약한다. 상한을 넘으면 해당 제한에 걸린 가장 오래된 회전 파일부터 제거한다. 활성 파일은 용량 확보를 위해 삭제하지 않는다. 바이트 합산은 포화 계산으로 정수 범위 초과를 차단한다.
- 이벤트 시각으로 7일 경계를 판정하고, 전부 만료된 회전 파일은 제거한다. 혼합 파일은 16 KiB 행 버퍼로 순회하여 유효 행의 원래 바이트·순서를 임시 파일에 보존한 뒤 sync·교체한다. 임시 바이트·개수 예약이 부족하면 원본을 변경하지 않고 실패한다. 중단된 교체의 정형 임시 파일은 다음 회차에 제거한다.
- 자기 활성 파일은 기록 핸들과 동기화하여 회전한다. 다른 살아 있는 기록자의 활성 파일은 변경하지 않는다. 이전 비활성 슬롯은 비차단 기록자 잠금을 얻은 동안 회전·만료 정리한다. 저장소 잠금 안에서 다른 기록자 잠금을 기다리지 않는다.
- 시간 회차는 요청·대기열이 없는 상태와 기록 처리 사이에도 실행한다. `MaintenanceFailures`는 회차 실패를 이벤트 누락과 별도로 누적하며 첫 오류를 Close까지 보존한다. 이미 만료된 새 이벤트도 기록하지 않는다.
- 목록은 fd·NOFOLLOW·소유권·0700/0600·단일 링크를 검사한다. 이름을 128개씩 읽고 목록에 16384개 상한을 두며 알 수 없는 이름·손상된 행을 정책 실패로 처리한다. 부분 행을 만료로 간주하지 않으며 실제 격리·복구는 OBS-07의 범위다.

## 검증 — 2026-10-21

- **macOS/arm64 진단 패키지 145건 통과**, race 포함, 실패 0·건너뜀 0. OBS-01~03 회귀와 OBS-04의 신규 23건을 포함한다.
- **Linux/arm64 OBS-03/04 47건 통과**, 실패 0·건너뜀 0. 기존 로컬 이미지에서 CGO 없는 바이너리를 UID 501/GID 20으로 실행했다. Linux에서는 race와 OBS-01/02 전체 회귀를 다시 실행하지 않았다. 두 OS의 같은 시험을 고유 항목 수로 합산하지 않는다.
- **서버 패키지 의존성 검사 1건 통과**, race 포함. diagnostic의 업무 패키지 의존 없음과 기존 허용 import를 확인했다.
- 날짜 변경·같은 날짜의 두 기동 append와 여섯 종류 회전, 다음 행의 정확한 크기 경계·활성 포함 개수·종류 바이트·instance 바이트를 검사했다. 기본 개수 10개는 이전 슬롯의 회전 파일 11개와 활성 파일을 준비하여 가장 오래된 두 회전 파일만 제거하는지 확인했다.
- 보존 경계의 정확히 7일인 행과 1 ns 덜 지난 행, 혼합 행의 원래 바이트·순서·0600 교체를 대조했다. 임시 공간의 정확한 경계와 1바이트 부족에서 원본 보존, 정형 고아 임시 파일 제거를 확인했다. 다른 기록자의 활성 파일 보호·자기 회전·비활성 슬롯 정리를 대조했다.
- 실제 두 자식 프로세스를 별도 슬롯으로 준비한 뒤 함께 시작시켰다. 각각 16건을 수락하고 공유 저장소 상한을 여덟 행 크기로 축소했다. 두 슬롯 합계가 정확히 여덟 독립 JSON 행·예약 바이트 안에 머물며 나머지는 실패로 남고 출처가 섞이지 않음을 확인했다. 부모 goroutine만의 병행 시험으로 대신하지 않았다.
- 요청 없는 시간 회차는 시험 시계와 tick을 주입하여 만료 정리·회차 실패 집계를 확인했다. 용량은 시험용 작은 한도로 소진했다. 실제 10 MiB·100 MiB·600 MiB·1 GiB나 실제 7일/1시간을 기다린 시험으로 주장하지 않는다. 큰 저장량의 정수 범위 초과도 별도로 검사했다.
- 최초 모듈 실행에서는 시험의 중간 상태 관찰과 자식 stdout/stderr 공유 버퍼 때문에 유휴 완료 판정 실패·race가 발생했다. 명시적인 회차 완료 신호와 별도 출력 버퍼로 시험을 수정한 뒤 전체 진단 패키지·race를 다시 실행해 통과했다.
- Go 1.27.1 `check-go.sh`: 의존성 확인·의존성 빌드·전체 go build·go vet·gofmt 통과. DB를 사용하는 변경이 없어 DB 시험은 실행하지 않았다.

## 범위·문서·남은 조건

업무 계측은 OBS-05, 감사 조회는 OBS-06, 안전한 stderr·30초 억제·부분 행 격리/복구·5초 flush와 잔여 누락은 OBS-07, 실제 배포 영속성과 전체 파일 저장 통합은 OBS-08에서 이어간다. 생산 서버 기동 경로 조립도 후속이다. 파일 시스템의 rename·공유 잠금은 이번 두 로컬 환경의 결과이며 다중 호스트 공유 파일 시스템 지원으로 확대하지 않는다.

관측성 SDD는 실제 정책·보호 경계와 검증 한계를, 계획은 완료 상태·다음 항목을, 이 기록은 모듈 인수 근거를 유지한다. 기존 internal DOX의 diagnostic 소유권·무업무 의존 계약과 디렉터리 경계가 유지되므로 DOX·Child Index를 추가하지 않았다. upstream이 없어 원격 뒤처짐은 확인하지 못했다. 기존 Compose·IDE 변경을 보존했으며 commit·push·PR·배포는 수행하지 않았다.
