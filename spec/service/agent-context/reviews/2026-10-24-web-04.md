## 변경

등급 표에 대상 식별자·표 제목·행/열 머리글을 표시했다. 직접 부여의 마지막 소유자 회수 불가 이유는 `title` 대신 본문에 표시하고 비활성 기본 버튼의 설명으로 연결했다. 유일 소유자 팀은 팀 부여 전체를 회수하면 사용할 계정이 남지 않음을 설명한다. 상속 행에는 회수 양식을 두지 않고 변경 경로를 안내한다.

관리 팀에 부여된 그래프 식별자·등급과 등급 없는 빈 상태를 추가했다. 삭제 팀의 구성원·부여를 보존해 표시하고 상속 무효와 복구 효과를 안내한다. 관리자 범위의 팀·정렬된 구성원·그래프 부여를 같은 질의에서 읽어 팀별로 묶으며, 그래프 이름·본문이나 관리자 자신의 그래프 접근 권한을 추가하지 않는다. 모델의 `TeamGraphGrant`는 이 조회 결과를 전달하는 값이다. 반복 팀 양식은 명시적 제출 경로·팀별 입력 식별자와 레이블·로그인 아이디 교정 비활성화를 적용했다.

등급·직접 부여·활성 팀 선택·관리 팀 조회 후 취소를 확인해 후속 조회와 렌더링을 중단한다. 상태 변경은 기존 저장소의 잠금 뒤 현재 소유자·팀 관리자·대상 활성 상태 재검사와 감사 트랜잭션을 계속 사용한다.

## 실행 증거

- **신규 20건 포함 웹 662건 통과**: 최상위 74개·하위 588개, `-race -count=1`·필수 DB 설정. 최종 전체 실행의 실패·건너뜀 0, race 없음. 기존 Node.js 시각화·키보드 합성 시험도 실행했다.
- 단위 9건은 네 조회 지점의 장애/취소에서 후속 호출 중단·고정 500·내부 원문 비노출과 취소 시 렌더링 중단을 확인했다.
- 실제 DB·서명 세션·TLS의 회수 표본은 단독 직접 소유자, 구성원 둘을 가진 유일 소유자 팀, 빈/삭제 팀이 대안인 경우, 같은 계정의 직접/팀 상속 중복, 다른 직접 소유자다. 각 표본의 대상 행·직접/상속 구분·회수 양식과 저장소 `CanRevoke`를 실제 POST 회수의 303/409 결과와 대조했고 마지막 부여 강등도 409로 거부했다. 상속 행은 회수 양식이 없다.
- 그래프 없는 `/access`에서 팀 생성·구성원 추가/제거·삭제/복구의 303과 현재 상태를 확인했다. 비구성원 관리자의 그래프 읽기는 404다. 구성원 정렬, 빈 팀 안내와 두 그래프의 부여를 한 팀으로 묶는 결과, 삭제 중 구성원/등급 보존·상속 무효·복구 후 유효성을 대조했다. 다른 관리자 팀의 구성원·식별자를 관리 영역에 노출하지 않고 변경도 404로 거부했다.
- 그래프 소유자의 활성 팀 선택에서 같은 이름의 두 팀을 식별자로 구분하고, 관리자가 다른 팀에 HTTP POST로 등급을 부여하여 실제 구성원 상속과 관리자 화면의 등급 표시를 확인했다.
- 정상 화면 조회 후 웹 소유자 사전 검사와 저장 변경 사이에 실제 DB의 행위자 등급을 회수하거나 대상 팀을 삭제했다. 저장소가 현재 상태를 다시 확인하여 부여를 404와 고정 안내로 거부하고 대상 구성원의 등급이 생기지 않았다. 이는 새 웹 어댑터 인수이며 두 연결의 잠금 대기 시험을 새로 수행했다는 뜻은 아니다.
- 첫 실행은 새 시험 대역을 구체 타입 전용 도우미에 넘겨 컴파일에 실패했다. 기존 생성자 인터페이스를 직접 사용하는 도우미로 고친 뒤 전체 모듈 실행을 통과했다. HTTP 성공 경로를 보강한 최종 전체 실행도 통과했으며 반복 실행을 중복 합산하지 않았다.
- `check-go.sh`의 의존성 확인·빌드·vet·gofmt가 통과했다. Markdown 링크·앵커·계획 수와 DOX 경계를 확인했다. 모델·저장·웹은 기존 DOX 소유 안의 변경이므로 DOX와 부모 색인을 유지했다. 웹 SDD·개발 계획·설계 진입점·README/서비스 색인·요청 기록·공식 근거를 정합화했다. 요구사항·용어·SQL 스키마·환경 설정 계약은 바뀌지 않아 해당 정본은 유지했다.

```sh
TEST_DATABASE_URL='<WEB-04 전용 합성 URL>' TEST_DATABASE_REQUIRED=1 GOCACHE=/private/tmp/acs-obs02-go-cache /Users/alphagone/sdk/go1.27.1/bin/go test -race -json -count=1 -timeout=240s ./internal/web
GO_BINARY=/Users/alphagone/sdk/go1.27.1/bin/go GOCACHE=/private/tmp/acs-obs02-go-cache sh check-go.sh
```

공유 DB 이미지에서 PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6을 확인했다. 별도 `acs-web04-20261024` 컨테이너·`agent-context.task=web04` 라벨·tmpfs·임시 IPv4 loopback 포트와 합성 자격을 사용했다. 시험별 자식 DB를 정식 마이그레이션으로 준비하고 종료 후 자식 DB·시험 연결 0, 이 작업의 컨테이너/볼륨 잔류 없음과 기존 개발 컨테이너 보존을 확인했다. 최종 원시 근거는 `/private/tmp/acs-web04-web-accepted.json`·`acs-web04-runtime-accepted.log`·`acs-web04-static-accepted.log`다.

Modern Go CLI의 Go 1.27 전체 목록, Modern Web Guidance의 `forms`·`accessibility`, MDN의 비활성 수단과 적용 pgx 5.10.0의 행 수집·오류 계약을 확인했다. 네이티브 POST 양식·명시적 레이블·식별자 교정 비활성화·표 의미와 보이는 회수 불가 설명에 반영했다. 기존 CrossOriginProtection·서버 렌더링을 다른 CSRF/AJAX 구조로 교체하지 않았다.

## 남은 범위

WEB-05~09의 나머지 화면과 전체 웹 분야 통합, 실제 브라우저 제출·Tab/키보드·스크린리더 음성, 실제 호스트·Tunnel·운영 배포는 미실행이다. DB/TLS·합성 HTML 검사가 실제 브라우저나 보조 기술 인수를 대신하지 않는다. 현재 브랜치 upstream이 없어 원격 차이는 확인하지 않았으며 커밋·푸시·배포는 수행하지 않았다.
