# 쓰기 키·24시간 결과 재생 인수

- 기준: [MCP-05](../development-plan/mcp.md#mcp-05), [멱등성 저장과 경합](../sdd/mcp.md#멱등성-저장과-경합), FR-AGENT_CONTEXT-094·155·170과 NFR-AGENT_CONTEXT-012·013.
- 대상: `feat/mcp-auth`의 `b835a1a` 이후 작업 트리. MCP-04·ARCH-04·PERM-06·DATA-03의 선행과 fetch 후 upstream 뒤처짐 0건을 확인했다.
- 범위: 정규화·현재 검사·공유 재생 실행 경계의 모듈 인수다. 실제 MCP 여덟 쓰기의 인자·도메인 오류/결과 변환·전체 HTTP 조립은 MCP-06 이후에 인수한다.

## 구현 결과

`mcp.WriteRunner`는 공개 도구 스키마로 여덟 쓰기의 입력을 검사하고 request_id를 분리한다. 객체 키 순서·JSON escape·정수 표기와 UUID의 허용 표기를 통일하고 도구·agent·기대 판·판단 입력을 포함한 결정적 JSON을 만든다. 배열 순서·중복·선택 필드의 생략은 유지한다. 알 수 없는 외피·client·토큰 인자는 닫힌 스키마로 거부하며 정규화 인자 원문은 DB에 저장하지 않는다.

미사용 WriteResult 전용 주입 계약을 도메인 완료 객체 JSON 바이트의 `WriteExecutor.ExecuteWrite`로 구체화했다. Store가 이 계약을 직접 구현하므로 DB 핸들·트랜잭션·MCP SDK를 주입 인터페이스로 내보내지 않는다. 기존 UUID의 ReplayIdempotent는 같은 내부 경계에 위임하며 기존 행·지문·결과를 재작성하지 않는다. 문자열 키는 계정 범위·대소문자 구분이며 같은 키의 다른 도구/지문은 request_id FieldError와 원인을 가진다.

필수 Check는 자문 잠금을 얻은 뒤 재생 조회 전에 현재 인증·등급을 읽기 전용으로 재검사한다. WriteRunner는 이어 여섯 쓰기의 활성 agent와 계정/client 결합을 확인한다. Check가 실패하거나 등록이 폐기되면 과거 결과도 반환하지 않는다. 인증·등급 판정의 실제 도구별 연결은 MCP-06에서 주입하며 이번 잠금 시험의 등급 상실은 Check 콜백의 현재 거부 신호로 검증했다.

잠금·예약 트랜잭션은 2개 연결 예산을 선점하고 도메인 저장점과 예약을 공유한다. 잠금 대기 뒤 DB clock_timestamp로 24시간 수명을 판정한다. 만료 행은 같은 바깥 트랜잭션에서 교체하고 재생으로 received_at·expires_at을 갱신하지 않는다. SHA-256 지문과 PK의 계정/키 결합을 함께 대조한다.

예약 INSERT의 실제 삽입 여부로 새 요청과 재생을 구분한다. 빈 JSON 객체를 미완료 예약으로 사용하되 빈 완료 객체·null·배열·잘못된 JSON·표준 외피·명백한 자격 필드는 커밋하지 않는다. 도메인 성공/결정적 거부 객체만 결과를 채워 커밋하며 최초 응답도 UPDATE RETURNING의 jsonb 표현을 사용해 재생 바이트와 일치한다. Apply의 error와 내부 저장·커밋·취소 실패는 예약·업무·감사·큐·누계를 함께 되돌린다. 결정적 거부는 업무 저장점의 롤백 뒤 거부 감사와 완료 객체를 같은 바깥 커밋에 넣는다.

키 없는 호출은 현재 검사 뒤 일반 업무 함수를 실행하고 재생 행·예약을 만들지 않는다. 미완료 결과·내부 오류·취소의 반환 계약은 유지한다. 키 없는 업무 함수가 이미 커밋한 뒤 결과 직렬화나 전달이 실패한 경우의 재시도 안전성은 보장하지 않으며 현재 상태를 재조회한다. 중첩 재생 경계는 거부하여 같은 예약/키를 다시 기다리는 교착을 막는다.

## 모듈 시험과 검증

Go 1.27.1에서 `-race -json -count=1`을 사용했다. MCP는 timeout=120s, 저장은 timeout=240s이며 DB 시험은 TEST_DATABASE_URL과 TEST_DATABASE_REQUIRED=1을 함께 설정했다.

- MCP **334건**: `go test ./internal/mcp`. 기존 283건에 정규화·필드 변경 지문·여덟 도구의 키 유무/현재 거부/등록 폐기/입력/취소와 외피 차단 등 51건을 추가했다.
- 저장 **111건**: 새 `TestMCP05.*` **49건**과 바깥 트랜잭션/저장점 잠금·쓰기 빈도·거부 감사 실패·연결 취소/예약·다른 키의 그래프 상한 등 기존 **62건**을 함께 실행했다. 명령의 선별 범위는 아래와 같다.
- 패키지 경계 **1건**: `go test -run '^TestPackageDependenciesMatchDesign$' ./cmd/server`. 업무 패키지의 허용 import 변화가 없다.
- **중복 제외 총 446건 통과·실패 0건·건너뜀 0건·race 통과**. 전체 저장소 시험·전체 MCP/호스트 인수와 구분한다.
- 루트 check-go.sh: 의존성 검증·SDK 링크·전체 build·vet·gofmt 통과. `/private/tmp/acs-mcp05-check-go.log`.
- 시험 로그: `/private/tmp/acs-mcp05-mcp.json`, `acs-mcp05-store.json`, `acs-mcp05-server.json`, `acs-mcp05-migrations.log`.

```sh
go test -race -json -count=1 -timeout=240s -run '^Test(MCP05.*|LifeWriteOuterTransactionMatrixIntegration|LifeWriteLockSurvivesSavepointIntegration|WriteRateAtomicReplayIntegration|LifeRejectedAuditFailureIntegration|ConnectionIdempotencyCancelRecoversIntegration|ConnectionReservationPreventsPoolStarvationIntegration|GraphCountLimitWithDistinctIdempotencyKeysIntegration)$' ./internal/store
```

실제 DB에서 여덟 도메인 쓰기의 최초 결과·다른 인스턴스 재생·상태/감사/큐/빈도 불변을 확인했다. 같은 키 16건은 한 번 실행되고 현재 검사는 16번 수행됐다. 다른 계정·대소문자·키 생략·UUID 기존 행·키 혼용·24시간 수명/만료와 잠금 대기 후 만료를 대조했다. 잠금 대기는 pg_stat_activity로 관찰한 뒤 현재 등록 폐기·Check 거부·취소를 적용했다. 결과 저장/지연 COMMIT 오류·잘못된 완료 객체·중첩 실행은 부분 적용 없이 롤백되고 같은 키·판·한도로 다시 실행됐다. 커밋 후 취소는 실제 업무와 최초 결과를 보존했고 재시도는 다시 적용하지 않았다. 판 충돌의 거부 감사와 결과도 한 번만 남았다.

초기 저장 시험의 감사 인자 타입과 시험 준비의 색인 계층 설정을 수정했다. 시험 준비 실패 실행도 생성한 suite DB를 정리했으며 실패 실행은 위 건수에 포함하지 않는다. 키 없는 호출의 결과/오류/취소를 보완한 뒤 영향받은 저장 모듈·정적 검사를 다시 통과했다.

각 실행은 무작위 mcp05_suite DB에만 접속하고 정식 마이그레이션을 적용했다. 새 DB 경합 시험은 다시 두 개의 pool_max_conns=4 저장소를 가진 자식 DB를 만들고 DB명·마이그레이션을 대조했다. 기존 개발/운영 DB의 업무·키를 시험 준비에 사용하지 않았으며 실행별 자식·suite DB만 정리하고 suite DB의 부재를 확인했다.

## 완료와 후속

MCP-05 실행 경계를 완료하여 전체 **64/124개 완료·60개 미착수**다. 다음 권장 작업은 [MCP-06](../development-plan/mcp.md#mcp-06)의 여덟 쓰기 도구 어댑터다. 이번 여덟 쓰기 시험은 실제 도메인 API를 공통 실행기에 넣은 모듈 시험이며 전체 MCP 입력/결과 변환·현재 권한 조회·거부 분류·실제 HTTP 쓰기 인수는 후속 범위다.

service-design의 내부 Contract Change 모드로 주입 계약을 구체화했고 공개 도구 스키마·SRS·SQL 스키마는 유지했다. DOX pass에서 소유권·허용 import·폴더 경계 변화가 없음을 확인했다. 분야별 SDD·계획·상태·README·근거·요청 기록을 갱신했다. 기존 Compose·IDE 변경을 보존했으며 commit·push·PR 갱신·배포는 하지 않았다.
