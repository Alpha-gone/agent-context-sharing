# INGEST-05 분야 통합 시험과 합성 전송량 측정

## 범위와 방법

운영 DB와 자격을 사용하지 않고 작업 전용 PostgreSQL/AGE 컨테이너에서 별도 합성 DB를 만들었다. 네 턴(사용자 2개, 에이전트 2개)의 같은 본문을 두 경로로 기록했다. 기준 경로는 MCP `node_create`로 원천 네 개와 동일한 사용자 발화 발췌의 사건 한 개를 만들었다. 수집 경로는 턴별 HTTP 요청 네 개를 보내고 서버 구간화 작업자가 사건을 만들었다. 수집 자격 발급·검증부터 저장, 작업 확보, 사건 구성, 관계 추론 작업 등록, MCP `node_get`의 사건 및 구성원 조회까지 확인했다.

유효한 자격으로 다른 계정의 실제 그래프에 쓰는 요청은 404, 잘못된 자격은 401이었다. 마지막 턴을 재전송하면 `existing`으로 판정했다. 수집 응답과 실제 진단 파일에서 합성 본문, 대화 식별자, 자격 원문·SHA-256 해시·구분용 이름이 나오지 않는지 확인했다. 이전 INGEST-04의 클라이언트 합성 DB 시험은 전송 실패 뒤 재전송과 일시 중지 중 제외를 별도로 검사한다.

## 관찰값

2026-11-17의 한 회차. UTF-8 JSON 직렬화 결과의 바이트 수다. 네 턴을 개별 전송했으며 실패·재전송, 인증 발급, 그래프 준비 및 조회 호출은 비교 횟수와 크기에서 제외했다.

| 경로 | 기록 호출 | 요청 크기 | 응답 크기 |
|---|---:|---:|---:|
| MCP 에이전트 도구 | 5회 | 도구 인자 JSON 합계 2,021바이트 | 도구 결과 객체 JSON 합계 6,251바이트 |
| 수집 HTTP | 4회 | 요청 본문 합계 860바이트 | 응답 본문 합계 392바이트 |

두 크기는 서로 다른 경계다. MCP 측은 JSON-RPC 외피·전송 프레임·도구 정의를 포함하지 않고, HTTP 측은 헤더·TLS·클라이언트 훅 입력을 포함하지 않는다. MCP 결과의 동적 식별자와 시각 표현에 따라 크기가 조금 달라질 수 있다. 따라서 이 수치는 해당 합성 표본의 호출 및 JSON 크기 관찰값이며 모델 입력·출력 토큰, 달러 비용, 전체 네트워크 사용량의 절감률이 아니다. 실제 호스트의 모델 토큰, 청구액, 검색 활용도와 품질은 **미측정**이다.

## 실행 결과와 한계

- 관련 패키지 필터 없는 시험: `TEST_DATABASE_REQUIRED=1 go test -p 1 -count=1 -v ./cmd/server ./cmd/ingest ./internal/ingest`. 시험 DB는 이 작업이 만든 격리 컨테이너다.
- 분리 작업자 전체: `TEST_DATABASE_REQUIRED=1 go test -race -count=1 ./cmd/indexer` 통과. 최초에는 격리 기본 DB에 마이그레이션이 없어 실패했고 15개 마이그레이션을 적용한 뒤 재실행했다.
- 새 통합 시나리오의 `-race` 시험과 Go 1.27.4 `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check`를 확인했다.
- 호스트 인증·운영 복구와 이전 TEST-08 등 별도 실행 환경이 필요한 기존 시험의 건너뜀은 이 수집 분야 시험의 통과로 대체하지 않는다. 실제 호스트의 추가 지시 완전성·실제 서비스 배포 및 운영 데이터 사용은 검증하지 않았다.
