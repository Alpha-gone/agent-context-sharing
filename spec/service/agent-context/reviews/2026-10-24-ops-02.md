# OPS-02 운영 템플릿·진단 볼륨 모듈 인수

- 기준: 2026-10-24, `feat/web-foundation`의 `13b86ac` 이후 작업 트리.
- 대상: [OPS-02](../development-plan/operations.md#ops-02), [운영 구성](../sdd/operations.md#운영-터널-구성), [진단 경로·권한](../sdd/observability.md#경로권한다중-인스턴스).
- 상태: **모듈 인수 완료**. 사용자 지시에 따라 DB 공개 설정을 제거하고 실제 운영 정적 검사를 통과했다. 전체 85개 완료·39개 미착수이며 다음 권장은 OPS-08이다.

## 구현

- `Dockerfile.server`의 서버·마이그레이션·감사 실행기와 고정 베이스를 유지하고 UID 10001 소유·0700의 `/var/log/agent-context`를 준비했다.
- 운영과 개발 server profile에 프로젝트별 `diagnostic_logs` 볼륨을 연결했다. 경로는 Compose에서 고정한다. 운영 instance 슬롯은 명시적으로 필수이며 개발은 `development` 기본값을 사용한다. 재생성 시 같은 슬롯을 유지한다.
- 기존 볼륨의 소유·권한을 자동 교정하거나 정상 자료를 지우지 않는다. 기록기가 잘못된 권한·중복 슬롯을 기존 계약에 따라 거부한다.
- 두 환경 예시의 진단 설명을 실제 구성에 맞추고 `test-prod-compose.sh`에 슬롯 필수·고정 경로·볼륨·기동/종료 경계를 추가했다. 개발 정적 검사도 볼륨을 대조한다.
- 새 `test-prod-runtime.sh`는 실제 `.env` 없이 운영 예시에 합성 자격만 채운다. 공개 포트와 고정 네트워크를 격리 설정으로 바꾸고 전용 이미지·DB/WAL/진단 볼륨을 만든다. 색인 배치를 external로 두어 외부 제공자를 호출하지 않는다. 실제 운영의 공개 범위 검사와 구분한다.

| `sh test-prod-compose.sh` | **통과**. DB 비공개·loopback·고정 신뢰·기동/종료·진단 볼륨/슬롯·WAL·버전 고정 |
| `sh test-prod-runtime.sh` | 고정 베이스의 DB/서버 이미지 빌드, 마이그레이션과 실제 준비 상태·실행기 존재 확인, 진단 권한·중복/권한 거부·재생성 보존·자원 정리 통과 |
| `GO_BINARY=/Users/alphagone/sdk/go1.27.1/bin/go GOCACHE=/private/tmp/acs-obs02-go-cache sh check-go.sh` | 전체 build·vet·gofmt·의존성 검사 통과 |
| 세 실행기의 `sh -n` | 통과 |

격리 실행은 실제 서버 UID 10001, 루트 0700과 여섯 파일의 UID 10001·0600을 대조했다. 동일 슬롯의 두 번째 서버는 종료 코드 1로 거부됐다. 시험이 만든 루트를 0755로 바꾼 표본도 코드 1로 거부되고 자동 교정되지 않았다. 권한을 시험에서 복원한 뒤 컨테이너를 재생성하자 이전 시스템 로그의 바이트 접두가 같고 같은 instance에 새 boot가 추가됐다. 생성한 컨테이너·볼륨·네트워크·이미지를 정리했다.

첫 runtime은 이미지와 서버 기동 이후 실행 중인 스크립트를 수정해 후반 문법 처리가 중단됐다. 당시의 통과 안내를 정정했고, 모든 검사를 끝내야 설정되는 완료 플래그를 추가했다. 수정이 끝난 최종 실행은 `runtime: uid=10001 root=0700 files=0600 stable_slot=true append_preserved=true new_boot=true`와 자원 정리 통과를 모두 확인하고 종료 코드 0으로 끝났다. 앞선 불완전한 실행은 완료 근거에서 제외한다. 최종 로그는 `/private/tmp/acs-ops02-runtime-final.log`, 구성 결과는 `/private/tmp/acs-ops02-config.json`, 정적 결과는 `/private/tmp/acs-ops02-static.log`에 남겼다.

## DB 공개 설정 처리와 범위

작업 시작 전부터 `compose.prod.yaml`에 사용자 변경으로 `ports: ["7777:5432"]`가 있어 운영 정적 검사가 실패했다. 처음에는 해당 두 줄을 제외한 임시 사본만 통과했으며 실제 구성의 통과로 승격하지 않았다. 이후 사용자가 명시적으로 삭제를 지시하여 두 줄을 제거했다. 실제 작업 트리의 `sh test-prod-compose.sh`를 다시 실행해 종료 코드 0으로 통과했고 OPS-02를 완료 처리했다. 최종 로그는 `/private/tmp/acs-ops02-prod-final.log`에 남겼다. 기존 IDE 변경은 보존했다. 실행 중인 운영 컨테이너의 공개 포트나 배치를 변경한 것은 아니다.

운영 배포·실제 프록시 상대·Cloudflare Tunnel·외부 제공자·성능·전체 운영 장애 인수는 수행하지 않았다. 루트 DOX에 새 격리 실행기의 소유권을 기록하고 운영 SDD·매뉴얼·환경 예시와 계획·진행 기록을 동기화했다. 새 지속 영역·애플리케이션 환경 키·SRS 요구사항은 추가하지 않아 하위 DOX·Child DOX Index·SRS는 유지한다. upstream이 없어 원격 비교·push는 하지 않았다. 변경은 미커밋이다.
