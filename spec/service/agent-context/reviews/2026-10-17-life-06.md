- 노드 권한 재확인을 처음에 그래프 잠금부터 수행하면 원천·파생의 MCP 갱신과 정점/그래프 순서가 반대가 된다. 최종 구현은 계층별 기존 순서를 유지하고 그래프 활동·저장량 갱신 전 현재 소유자·활성 상태를 검사한다. 거부 시 앞선 미커밋 정점 변경도 롤백한다. 사건은 기존 그래프→정점 순서를 유지한다.
- 사용자 직접 그래프 삭제는 유예 시각을 비워 자동 삭제와 구분한다. 자동 삭제의 일반 웹 복구 거부, 요청·운영자 복구 경로, 현재 폐기의 복구 근거는 유지했다. 물리·연쇄 삭제를 추가하지 않았다.
- 유예 시작은 잠금 뒤 최종 판정 시각에 시작·만료를 함께 계산해 같은 커밋으로 확정한다. 실제 커밋 완료 뒤 시각을 다시 기록한다는 뜻으로 오해되지 않게 SDD를 명확히 했다. 저장된 만료는 플랜 변경 뒤에도 재계산하지 않는다.
- 테스트의 기존 삭제 준비에도 실제 소유자 부여를 명시했다. 일반 그래프 준비 헬퍼를 모든 시험에서 소유자로 바꾸지 않았으며 권한이 없는 표본의 의미를 유지했다.
- 패키지 의존·문서 소유권·SQL 스키마가 바뀌지 않아 DOX와 마이그레이션은 유지했다. 동작 정본은 수명주기·웹 SDD에서 정합화했다.

## 검증 결과 — 2026-10-17

- Go 1.27.1 darwin/arm64. 고정 Dockerfile의 전용 이미지·컨테이너·새 볼륨·임시 IPv4 loopback 포트·합성 자격을 사용했다. PostgreSQL 18.6 / AGE 1.8.0 / pgvector 0.8.6, Linux aarch64를 확인했다. 기존 개발 DB·볼륨·실제 자격은 사용하지 않았다.
- 새 DB에 정식 `001/009/010/011/012`를 적용했다. `agent_context`·vector/128·`all_layers`, tablespace 지정 없음이다.
- **고유 시험·하위 시험 96건 통과**: store 80·web 16, 최상위 37·하위 59. `-race -count=1`, DB 범위에 `TEST_DATABASE_REQUIRED=1`을 지정했다. 최종 실패·건너뜀은 0이며 재실행 결과를 교체해 중복 합산하지 않았다.
- 웹 그래프 삭제/복구·노드 삭제/복구가 잠금 대기 중 직접 소유자 강등·팀 구성원 제거·팀 삭제를 다시 읽어 거부했다. 그래프 상태·정점·누계·색인·감사 지문이 보존됐다.
- 원천·파생 정점 잠금을 가진 MCP 수정이 웹 삭제와 겹쳐도 완료됐다. 웹 삭제는 기다린 뒤 새 본문·판을 읽어 적용하며 원천·파생과 사건의 잠금 순서를 유지했다.
- 직접·팀 상속이 겹친 계정은 한 번만 세고 삭제 팀은 제외했다. 이미 삭제된 파생은 활성 영향에서 제외하고 원천 구성 사건 두 개를 집계했다. 원천 삭제 뒤 파생은 활성 상태와 근거 무효 표시를 유지하고, 그래프 삭제 뒤 정점 행은 보존됐다. 삭제된 그래프의 노드 복구는 거부됐다.
- 팀 행 대기 중 새 작은 ID 그래프 부여가 커밋된 뒤 구성원 제거가 두 그래프를 모두 판정했다. 실제 구성원 재추가 뒤 두 유예 시각이 모두 지워졌다. 두 팀의 겹친 그래프 제거도 교착 없이 유예를 한 번만 시작했다.
- 재연결이 그래프 잠금을 먼저 가진 경우 대기한 만료 UPDATE가 새 상태를 재검사해 삭제하지 않았다. 만료가 먼저 확정된 경우 구성원 재추가는 자동 삭제·유예 표식을 지우지 않았다. 양쪽 순서를 실제 연결과 명시적인 잠금 보유로 통제했다. 기존 고정 만료·비소급·무기한·빈 팀·삭제 팀 계약도 대조했다.
- 그래프/노드 삭제의 웹 감사 삽입 실패를 자기 그래프에만 주입해 상태·누계·큐·감사가 함께 롤백됨을 확인했다. 장애 주입 트리거를 정리했으며 관련 시험 종료 뒤 잔여는 0이었다.
- 활성/웹 삭제/요청 없는 자동 삭제의 운영자 복구 거부, 자동 삭제와 직접 삭제의 일반 웹 복구 구분, 원천/파생/사건의 복구 채널·색인·한도·내용 판과 그래프 삭제 대기 회귀를 실행했다. 웹 대역은 같은 출처 POST와 현재 소유자 선행 인가 뒤 저장소 오류의 404/409/500 및 내부 원문 비노출을 확인했다.
- 최초 새 모듈·관련 권한/웹 55건은 통과했다. MCP 잠금 순서 보강 뒤 영향을 받은 회귀에서 운영자 복구 시험의 추가 소유자 준비가 기존 무등급 기대와 충돌했다. 삭제 준비 때만 소유자를 부여하고 준비 후 회수해 원래 표본을 유지했으며 해당 범위와 웹 복구 색인 롤백·그래프 삭제 경합을 재검증했다.
- 최종 `check-go.sh`의 의존성 확인·전체 build·vet·gofmt 검사가 통과했다. 시험 DB 연결 0·장애 주입 트리거 0과 소유 라벨을 확인한 뒤 자신이 만든 컨테이너·볼륨·이미지만 정리했다. 라벨별 잔여 자원은 0이다.
