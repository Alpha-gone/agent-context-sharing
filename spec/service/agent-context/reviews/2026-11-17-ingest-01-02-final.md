# INGEST-01~02 검증과 전체 변경 점검

## 범위

작업 전용 PostgreSQL/AGE 컨테이너와 합성 계정·자격·대화만 사용했다. 기존 운영 DB, 실제 자격과 대화는 사용하지 않았다. INGEST-01~05의 기존 미커밋 변경을 유지한 상태에서 정본과 완료 기준을 대조하고 독립 코드 리뷰와 후속 확인을 수행했다.

## INGEST-01~02

- 수집 자격의 해시 저장, 계정별 20개와 활성 등록 128개 상한, 비활동 30일·절대 1년 만료, 다른 계정의 폐기 거부와 폐기 후 검증 거부를 저장소 시험으로 확인했다. 같은 등록 키의 `agent_register`가 수집 결합 등록을 재사용하지 않고 그 등록이 MCP 쓰기 행위자로 거부되는지도 확인했다.
- 합성 TLS 서버에서 웹 연결 관리의 수집 자격 발급·목록의 원문 비노출·폐기를 확인했다. 수집 자격의 `/mcp`·웹 인증 거부, OAuth 토큰의 수집 경로 거부와 폐기 후 수집 요청 거부도 같은 경로에서 확인했다.
- HTTP 요청 형식·크기·출처·TLS 조립, 원천과 작업 등록의 원자성, 묶음의 재전송·부분 거부, 실제 열람자와 저장 한도 초과의 MCP·수집 양쪽 거부를 검사했다. 거부 시 새 구간화 작업이 생기지 않는다. MCP 도구 스냅숏을 포함한 MCP 패키지 전체도 검증했다.

## 리뷰에서 수정한 사항

- 100턴 이하더라도 JSON 이스케이프 뒤 4 MiB를 넘으면 서버의 413으로 대기열이 정체될 수 있어 인코딩된 크기와 턴 수를 함께 제한했다. 8,000개 제어문자씩 100턴인 합성 표본을 나누어 확인했다.
- 프로젝트별로 순번 상태를 나누면서 서버 대화 식별자에 프로젝트를 포함하지 않아 같은 그래프·호스트 세션에서 충돌할 수 있었다. 프로젝트·호스트·세션의 안정적인 지문을 대화 식별자에 포함하고 두 프로젝트의 독립 저장을 검증했다.
- Claude 비동기 훅과 네트워크 대기 중 공유 잠금 때문에 중지 중 입력이 재개 뒤 기록될 수 있었다. 사용자 결정에 따라 동기 로컬 기록과 분리 프로세스 전송으로 바꾸고, 전송 잠금과 상태 잠금을 분리하며 중지 이력을 판정한다. 지연 훅, 전송 중 중지·재개, 중지 이전 훅 보존, 실제 분리 프로세스를 시험했다. 최종 실행기를 Claude Code 2.1.325와 합성 로컬 모델에 연결해 두 훅의 대기 기록을 확인했다.
- Codex는 지연 알림에 발화 시각이 없고 추가 지시 완전성도 미검증이다. 중지한 Codex 세션의 재개를 명시적으로 거부하고 새 세션을 안내한다. 지원은 보류 상태다. Claude도 이전 `async: true` 설정은 제거해야 하며 중지 중 발화의 동기 훅이 끝나기 전에 다른 터미널에서 재개하면 입력 발생 시각을 판별할 수 없다.
- 웹 SDD의 수집 경로 구현 상태와 실행 안내를 정합화했다. 독립 후속 리뷰에서 추가로 확인된 중대한 문제는 없었다.

## 시험과 남은 범위

- `TEST_DATABASE_REQUIRED=1 go test -p 1 -count=1 -v -timeout=20m ./cmd/server ./internal/ingest ./internal/web ./internal/config ./internal/migrate` 통과. 별도 인수 조건이 없는 실제 호스트·브라우저·운영 복구 관련 시험은 건너뛰었다.
- `TEST_DATABASE_REQUIRED=1 go test -race -count=1 ./cmd/ingest`, `go test -race -count=1 ./internal/mcp ./cmd/indexer` 및 새 자격·권한 통합 표본의 `-race`가 통과했다. Go 1.27.4 `go build ./...`, `go vet ./...`, `gofmt -l .`과 Linux/amd64 교차 빌드를 확인했다.
- `TEST_DATABASE_REQUIRED=1 go test -count=1 -timeout=20m ./internal/store`는 다른 시험과 분리한 신규 컨테이너에서 397.275초에 통과했다. 동시 실행한 이전 회차에서는 `TestPlanParallelGrowthIntegration/update`가 PostgreSQL 공유 잠금 오류로 한 번 실패했고, 새 전용 컨테이너에서 같은 시험과 수집 자격 시험의 개별 재실행은 통과했다. 오류의 정확한 원인은 확정하지 않는다.
- 실제 운영 배포·실제 대화 수집, 실제 모델 토큰·청구액·검색 활용도는 검증하지 않았다. [INGEST-05 합성 비교](2026-11-17-ingest-05.md)의 크기는 실제 모델 비용으로 환산하지 않는다.
