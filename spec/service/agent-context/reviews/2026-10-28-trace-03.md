# TRACE-03 미정과 조건부 채택의 실행 범위 검토

## 범위와 판정

2026-10-28 TRACE-02 문서 변경을 5f93d521ae967a50055805e209be00532893d9d4으로 커밋한 뒤 현재 정본·설정·진입점·스키마를 정적으로 대조했다. 요구사항 미정 5건과 해소된 설계 선택 2건, 비교 구현과 운영 승격의 구분을 확인해 TRACE-03을 완료했다. 미정 항목을 새로 확정하거나 기존 제품 동작·기본값·지원 범위를 변경하지 않았다.

## 미정 5건의 현재 범위와 후속 조건

소유 정본은 [SRS 미정 사항](../SRS.md#미정-사항)이며 다섯 ID의 상태·번호를 유지한다.

- **TBD-048 인증 고도화:** 현재 로그인 아이디·bcrypt 비밀번호·웹 세션/OAuth와 출처별/전체 요청 예산·해시 실행 상한을 유지한다. 비밀번호 재설정·계정 실패 잠금·MFA·외부 IdP는 제텔카스텐 동작 검증 뒤 결정한다. 공개 요청의 일시 제한은 계정 상태를 바꾸는 실패 잠금과 다르다. 인증/웹 진입점과 account 스키마를 대조했다.
- **TBD-049 계정 소멸:** 팀 구성원 제거·등급 회수에 따른 접근 가능 계정 0명과 보관 유예의 현재 동작을 유지한다. 탈퇴·계정 삭제 경로는 검증 뒤 별도로 결정한다. 그래프/팀 소프트 삭제를 계정 탈퇴로 해석하지 않는다.
- **TBD-052 운영자 역할 분리:** 현재 검증 단계에서는 인증된 모든 계정이 복구 운영자 자격을 갖는다. 웹 세션 판정 뒤 대기 복구 요청을 처리하고 컨텍스트 본문을 열람하지 않는 경로를 확인했다. 별도 운영자 역할·계정 속성을 추가하지 않았다. 실제 역할 분리는 동작 검증 뒤 결정한다.
- **TBD-060 CIMD:** 사전 등록 client·callback/resource 대조를 유지한다. ValidateAuthorizationTarget은 등록 맵을 대조하며 외부 메타데이터 URL을 조회하지 않는다. 클라이언트가 늘어날 때 외부 조회 실패·지연·SSRF 경계를 포함해 지원 여부를 결정한다.
- **TBD-061 한국어 형태소 분석:** 키워드 SQL의 to_tsvector/websearch_to_tsquery에 simple 구성을 유지한다. 형태소 확장을 추가하지 않았으며 조사가 붙은 한국어 표기의 일치 한계는 정본대로 남긴다. 실제 채널 기여를 측정한 뒤 확장 의존과 버전 호환을 함께 판단한다.

[설계 미정/해소 목록](../sdd/traceability.md#설계-미정-사항)과 [서비스 색인](../../README.md#공통-미정-사항)도 같은 다섯 요구사항 미정을 가리킨다. 현재 설계 수준 미정은 0건이다. RLS는 도입하지 않고 store의 graph_id·유효 등급·응답 재검사 경계를 유지한다. 플랜은 [확정된 14개 항목과 기본값](../sdd/authorization.md#계정-플랜-값)을 사용하고 ACCOUNT_PLAN_LIMITS로 계정별 값을 덮어쓴다. 플랜 이름·계정별 운영 값을 명세에 고정하거나 과금 정책을 추가하지 않았다. 확정 기본값을 미정으로 되돌리지 않도록 TRACE-03의 표현을 명확히 했다.

## 비교 구현과 운영 승격

[평가 계약](../sdd/evaluation.md#manifest-실행과-결과-묶음)과 [EVAL-13 분야 인수](2026-10-26-eval-13.md)는 실제 통제 비교의 accepted/not_accepted/deferred와 운영 활성화를 나눈다. 출처가 synthetic/unverified이거나 독립 단위·필수 지표·실제 비용이 부족하면 보류한다. 품질/성공률 악화·채널 실패·지연 초과·격리/복구 실패는 비채택이다. 완전한 실제 과업 근거와 비용을 갖춘 유의한 개선만 해당 비교의 채택 후보가 되며 default_activation은 false를 유지한다.

- **근거 경로 선택·적응형 라우팅:** 구성 해석과 개발/운영 예시에서 SEARCH_EVIDENCE_PATH_SELECTION_ENABLED=false·SEARCH_QUERY_ADAPTIVE_ROUTING_ENABLED=false를 확인했다. 켜는 실험 구성과 운영 기본값의 승격은 구분한다.
- **색인 대상:** 예시는 all_layers다. without_source 비교의 구현 완료나 합성 사례의 성공을 운영 채택 근거로 사용하지 않는다.
- **모델·차원·압축:** 예시는 기존 gemini-embedding-2·vector·768을 유지한다. 별도 DB의 차원/halfvec 비교와 모델 임계값 조정 구현은 지원 범위·품질·완전한 비용의 실측을 대신하지 않는다.
- **그래프 단계:** 예시의 SEARCH_GRAPH_STAGE=baseline과 기존 global fallback 구성을 유지한다. references/relations/global의 통제 비교·채택 분기 시험으로 운영 기본값을 바꾸지 않았다. [SEARCH-10 검토](2026-10-25-search-10.md#age-후보-적합성과-보류)의 AGE 최단 경로/VLE 후보 보류와 범위 밖 허브·깊은 조밀 표본의 제한도 유지한다.

## 새 정적 대조와 변경

`python3 /private/tmp/acs-trace03-audit.py`는 요구사항 미정 ID 집합·설계 해소 목록·플랜 항목 수·예시 구성·OAuth 수명/등록 대조·키워드 SQL·평가 판정/자동 활성화 경계를 검사했다. 마이그레이션 6개와 비시험 인증/웹/저장 Go 파일 56개에서 계정 삭제·고도화 속성·RLS 정책 관련 패턴을 조사하고 실제 웹 라우터·운영자 복구 진입점·등록 검증을 읽었다. 음성 관찰이나 배포 실행의 결과로 해석하지 않는다. 원시는 /private/tmp/acs-trace03-boundaries.json이며 입력 파일별 SHA-256을 포함한다. 임시 스크립트는 영구 실행 도구로 추가하지 않았다.

개발 계획의 TRACE-03 완료 근거·현재 상태와 README/서비스 색인·요청 기록을 맞췄다. 요구사항·설계 정본·코드·예시 환경·DB를 변경하지 않았고 새 런타임 시험도 실행하지 않았다. DOX pass에서 계약·구조·소유권 변경이 없어 기존 DOX를 유지했다. 요구사항 184건·작업 124개·선행 341개와 완료 120개의 선행 상태를 다시 확인했다. 추적 범위 18개 문서의 로컬 링크 1,797개와 변경/신규 문서 6개의 로컬 링크 1,119개·앵커·Markdown 구조, DOX 색인과 git diff --check를 통과했다. 두 링크 수는 서로 다른 범위이므로 합산하지 않는다. 추적 원시는 /private/tmp/acs-trace03-traceability.json이다.
