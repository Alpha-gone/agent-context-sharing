# #174 인증 캐시 적재 취소 격리 검토

- 대상: [이슈 #174](https://github.com/Alpha-gone/agent-context-sharing/issues/174).
- 기준: `dev`의 `0acf8d6`, 브랜치 `fix/174-auth-cache-cancellation`.

## 변경과 결정

공개 키·웹 폐기 목록의 단일 적재를 요청 context로 실행하던 구조에서 적재자의 취소 오류를 모든 대기자에게 저장소 장애로 전달했다. 단일 적재 구조는 유지하되 적재자의 실제 취소·마감과 일치하는 오류만 재시도 표식으로 공개한다. 살아 있는 대기 요청은 루프에서 mutex와 단일 적재 판정을 다시 거쳐 하나의 새 조회를 수행한다. 취소된 요청은 자신의 취소를 반환한다. 별도 비동기 적재 goroutine이나 요청과 분리된 context를 도입하지 않아 기존 요청·연결 수명을 유지한다.

각 저장소 적재에는 요청 context를 부모로 하는 5초 상한을 둔다. 부모 마감이 더 이르면 그 마감이 우선한다. 부모가 정상인 상태에서 저장소가 반환한 오류·취소·마감과 적재 자체의 상한 초과는 그대로 `ErrUnavailable`로 전달한다. 오류를 무조건 재시도하거나 정상 부재로 캐시하지 않는다. 실패 후 단일 적재 자리를 해제하여 다음 요청이 회복할 수 있다.

완료된 적재와 요청 취소가 겹쳐도 대기자 자신의 취소를 우선하고, 재진입 전에 취소를 확인하여 취소된 요청이 새 적재자가 되지 않게 한다. 공개 키의 부재 제한·세대 검사, 폐기 TTL·로컬 폐기 병합, Bearer의 매 요청 공유 폐기 조회는 유지한다. 상한은 한 적재의 저장소 호출에 대한 것이며 요청 전체의 무조건적인 5초 완료 보장은 아니다. 저장소는 context 취소를 준수해야 한다.

[토큰 검증 정본](../sdd/authentication.md#토큰-검증)을 구현 전에 갱신하고 [시험 설계](../sdd/testing.md#테스트-계층)·[공식 근거](../reference.md#2026-10-31-174-인증-캐시-적재-취소-격리)를 유지했다. DOX pass에서 새 패키지·소유권·공개 설정·경로 변경이 없어 기존 DOX를 유지했다.

## 재현과 검증

- 수정 전 키/폐기 목록 × 취소/마감의 네 표본에서 각 정상 대기자 3개가 모두 `ErrUnavailable`을 받았고 저장소 조회는 재시도 없이 1회였다. 두 상한 표본은 source context에 독립 마감이 없었다. 부모가 정상인 저장소 오류 6개 표본은 기존에도 장애로 공유됐다. 결과는 `/tmp/acs174-red.json`에 보관한다.
- 수정 후 새 회귀 15건이 race에서 통과했다. 서명된 실제 JWT를 Verify하여 적재자의 취소·마감만 반환하고 정상 대기자 3개가 모두 성공하며 총 조회가 2회인 것을 확인한다. Done 채널 평가 장벽으로 실제 대기 진입을 확인하며 sleep으로 경쟁을 추측하지 않는다.
- 저장소의 일반 오류·context.Canceled·context.DeadlineExceeded를 정상 부모 아래 반환하면 적재자와 대기자 모두 계속 `ErrUnavailable`과 원인을 받으며 추가 조회를 하지 않는다. 실제 5초 상한 표본은 대기자도 함께 오류로 종료하고 부모가 취소되지 않으며 다음 요청이 성공하는 것을 확인한다. 단위 결과는 `/tmp/acs174-targeted.json`에 보관한다.
- Go 1.27.1과 고정 PostgreSQL/AGE 이미지 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`의 전용 합성 컨테이너에 정식 7개 마이그레이션을 적용했다. `TEST_DATABASE_REQUIRED=1 go test -race -p 1 -json ./internal/authz ./internal/web ./internal/mcp -count=1 -timeout=10m`에서 인증 전체 496건·웹 813건·MCP 480건이 실패·건너뜀 없이 통과했다. 결과는 `/tmp/acs174-modules.json`에 보관한다.
- 기존 단일 적재·대기자 취소·키 회전·로컬 폐기와 공유 DB 폐기, 웹/Bearer 오류 사상·진단·응답 비노출을 함께 회귀했다. 기존 headless Chrome 인수도 통과했다. 새 취소 표본 자체는 인증 서비스의 병행 검증 시험이며 실제 브라우저 연결 단절이나 Safari·스크린리더 인수를 추가한 것으로 확대하지 않는다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check`와 변경 문서 5개의 로컬 링크·앵커 145개를 확인했다.
- 시험 종료 후 기본 시험 DB·postgres 외 임시 DB가 없고 idle transaction이 0임을 확인했다. 소유 컨테이너·연결 익명 볼륨만 정리한 뒤 잔류가 없음을 확인했으며 기존 개발·다른 시험 자원과 개인 IDE 파일은 유지했다.

독립 읽기 전용 검토에서 done 채널을 통한 결과 공개, 재시도 시 단일 적재 재진입, 부모 취소 분류·실제 오류 보존과 상한을 확인했고 중요한 결함이나 필수 시험 누락은 발견되지 않았다. 검토자는 DB·시험을 별도로 실행하지 않았다.
