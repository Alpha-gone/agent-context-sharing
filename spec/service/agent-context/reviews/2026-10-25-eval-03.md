## 변경과 판단

적재→색인 준비→측정→독립 정리를 공통 경계로 묶었다. 준비 실패는 측정 콜백을 실행하지 않으며, 정리 실패는 원래 오류와 함께 반환한다. 기본·적응형 CLI는 회차와 조건마다 새 그래프를 적재한다. 적대적 기준선도 회차마다 새 그래프를 쓰고 공격 표본·지속 시나리오는 기존 회차 격리를 같은 준비 경계에 연결했다. 일관성 부하와 동시 쓰기 조건도 각각 독립 그래프를 쓰며, 동일 식별자의 응답을 비교하는 일관 읽기 동등성 표본만 한 그래프 안에서 비교한다.

색인 준비는 기존 저장 계층의 한 SQL 명령으로 해당 그래프의 전체 pending/failed와 현재 대상 계층·모델 임베딩을 함께 대조한다. 재시도 대기·다른 작업자 리스·행 잠금·최종 실패·임베딩 누락을 준비 완료로 처리하지 않는다. 유한 처리 상한의 마지막 회차에 끝난 작업은 준비 검사를 통과하고, 남은 작업은 즉시 실패한다. 평가기는 실패를 숨기기 위한 재등록·백오프 대기를 추가하지 않는다. 영 식별자나 UUIDv7이 아닌 범위는 작업자 호출 전에 거부하여 전체 큐 확보로 이어지지 않게 했다.

취소·적재 실패·색인 실패·측정 실패와 성공 모두에서 취소와 독립적인 10초 context로 소프트 삭제한다. SIGINT·SIGTERM은 평가 context를 취소하며 같은 정리 경계를 거친다. 기본·적응형·일관성의 정상 보고서는 그래프 정리 성공 뒤에만 기록한다. 측정 시간에는 그래프 적재·색인·정리 시간이 섞이지 않으며 검색 실행의 실제 경과 시간을 유지한다.

## 검증

```sh
TEST_DATABASE_URL=<격리 DB> TEST_DATABASE_REQUIRED=1 go test -race -count=1 -json -timeout=600s ./cmd/eval
TEST_DATABASE_URL=<별도 격리 DB> TEST_DATABASE_REQUIRED=1 go test -race -count=1 -json -timeout=180s -p 1 -run 'Test(CheckGraphIndexReady|IndexReadiness)' ./internal/store ./internal/index
sh check-go.sh
```

Go 1.27.1, PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6, linux/aarch64 DB와 768차원 대역 Gemini 응답으로 실행했다. 실행 중인 개발 DB와 별도의 자체 컨테이너에 정식 마이그레이션을 적용했고 CLI 시험 DB와 준비 SQL/작업자 시험 DB도 분리했다. 외부 모델은 호출하지 않았다.

최종 고유 시험 **357건**(최상위 **107건**, 하위 사례 포함)이 실패·건너뜀 없이 통과했다. 평가 실행기 **338건**, 저장 계층 준비 **9건**, 색인 작업자 준비 **10건**이다. 선행으로 실행한 수명 시험 23건은 최종 실행에 포함되므로 중복 합산하지 않았다. 전체 의존성 검증·build·vet·gofmt도 통과했다.

- 새 수명·범위·종료 신호 시험 29건에서 정상·적재/관계/색인/측정 실패·취소·정리 실패의 원인 보존과 측정 차단을 확인했다.
- 2표본×2회차×2조건의 그래프 식별자가 모두 다르고 매번 소프트 삭제되는지 확인했다. 다른 그래프의 pending 2건·시도 횟수 0·임베딩 0건을 그대로 보존했다.
- 자체 보완 데이터의 일곱 기억 그룹·컨텍스트 115개를 실제로 적재·색인·정리했다. 연산 시나리오의 업무 효과 인수로 확대하지 않는다.
- 실제 CLI 정상 실행에서 기본 10개·적응형 60개 독립 그래프의 생성과 전량 정리를 대조했다. 다섯 모드의 미준비 상태·다섯 모드의 색인 중 종료 신호·기본/적응형/지속/일관성의 정리 실패가 정상 보고서를 기록하지 않는지 확인했다.
- 준비 SQL의 원천 포함/제외·삭제 대상·이전 모델·오래된 임베딩 위의 새 pending·원자적 임베딩 공개와 큐 제거, 작업자 확보·재시도·제공자 실패·취소 경계를 재검증했다.

## 중간 실패·남은 조건·DOX

첫 새 시험 빌드는 지역 변수 재선언과 미사용 import로 실패했고 수정했다. 최초 합성 DB의 3차원 설정은 Gemini 구성 검증이 거부하므로 시험 본문에 도달하지 못했다. 스키마 이력을 덮어쓰지 않고 별도 768차원 DB를 정식 적용한 뒤 전체 시험을 재실행했다. 이 실패들을 통과에 합산하지 않았다.

모든 시험 종료 뒤 평가 DB의 잔류 연결 0개를 확인했다. 실패 주입으로 남은 합성 행을 포함하여 자체 컨테이너·익명 볼륨만 제거했고 기존 개발 DB는 변경하지 않았다. 공개 데이터 준비 파일을 자동으로 비교 실행하는 연결, manifest 통제값의 실행 적용, 독립 단위 통계와 실제 모델·품질·비용 비교는 후속 EVAL-04~13의 범위다. 새 그래프마다 재색인하므로 반복 비용·캐시 조건은 이후 비교의 명세와 결과에서 따로 통제·기록해야 한다.

평가 SDD에는 수명·표본 경계·실패 시 결과 기록 중단을, 계획·SDD 진입점·서비스 색인에는 구현 상태를 반영했다. 요청·공식 API 근거·검토 기록은 새 증거 위치를 남긴다. 패키지·지속 경계·소유권은 바뀌지 않아 DOX 수정은 필요하지 않음을 확인했다. 변경 Markdown 8개·로컬 링크/앵커 420개와 개발 작업 124개/완료 106개의 정합성을 확인했다. 전체 계획은 **106/124개 완료·1개 진행·17개 미착수**이며 다음은 EVAL-04다. 변경은 미커밋이며 기존 개인 `.idea` 두 파일은 제외한다.
