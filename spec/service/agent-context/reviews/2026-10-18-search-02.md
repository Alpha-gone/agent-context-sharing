- 범위: 세 진입 채널의 SQL·실행기·부분 상태와 실패/자원 경계다. 기존 코드·과거 측정값을 완료 근거로 승계하지 않고 다음 모듈을 새 격리 DB에서 실행했다.

## 구현과 발견 사항

| 항목 | 근거·처리 | 상태 |
|---|---|---|
| 따옴표 구문 변형 | 공백마다 OR를 삽입하면 `"alpha beta"`가 `"alpha OR beta"`로 바뀌었다. 따옴표 밖의 공백에서만 OR로 묶어 구문 안의 인접 어휘와 부정을 PostgreSQL 파서에 그대로 전달한다. | 해결 |
| 실패 채널의 부분 후보 사용 | Store가 후보와 오류를 함께 반환하면 실패한 후보도 결합·라우팅·확장에 들어갔다. 실패한 진입 채널의 후보를 버리고 기여·후보 수는 0으로 둔다. | 해결 |
| 저장 조회의 UTC 검사 | `value.UTC().Equal(value)`는 같은 순간을 비교하여 잘못된 시간대를 거부하지 못했다. 키워드·시간·의미 및 같은 인자 경계의 전역 조회에서 미지정/비UTC 시각을 DB 호출 전에 거부한다. | 해결 |
| 독립 의미 질의의 취소 정리 | 요청 context로 직접 Rollback하던 종료를 독립된 유한 정리 예산으로 바꿨다. DB/취소 원인과 정리 오류를 보존하고 오류 결과를 비운다. | 해결 |

기존 의미 SQL의 graph/model·활성·만료·전역 요약 제외와 코사인 거리/ID 순서, 키워드의 simple·websearch_to_tsquery·ts_rank_cd/기록 시각/ID 순서, 시간의 as_of 범위·기록 시각/ID 순서와 각 상한을 새 표본으로 인수했다. 만료 판정은 valid_to 기준이고 미래 valid_from은 기본 의미/키워드에서 제외하지 않으며 시간 채널에서만 구간 판정한다. 해당 구분은 [시간 유효성](../SRS.md#검색에서의-취급)을 따른다.

## 새 모듈 검증

- 검색 대역은 8개 진입 채널 실패 조합을 병렬·순차로 대조한다. 오류와 함께 반환된 후보가 결과·기여에 섞이지 않고, 모두 실패할 때만 전체 오류/확장 진입점 없음이 되며, 구성상 disabled와 성공 빈 목록을 구분한다. 실패한 의미/키워드 후보와 건강한 시간 후보만으로 관련성을 만들지 않는지도 확인했다. 기존 제공자 오류·낮은 의미 유사도·시간 후보·전역 전환 시험을 포함해 search 패키지 전체를 새로 실행했다.
- DB 표본은 vector(8)·halfvec(8) 전용 임시 DB에서 원천·국소 파생·사건·전역 요약·다른 모델/그래프·폐기·만료·미래/경계 시각을 준비한다. 세 채널의 상한 1/3/20, 동점 ID 순서·기록 시각과 의미 거리 순서, 과거 유효 시각을 대조했다. 따옴표 인접 구문·부정·빈 질의·무일치도 실제 SQL 결과로 확인했다.
- 실제 검색 서비스의 순차·병렬 호출에서 세 채널이 내놓은 목록과 결합·부분 상태를 대조했다. 가변 지연·읽기 자원 계측만 비교에서 제외했다.
- 실제 의미 SQL을 계측하여 테스트 트랜잭션 안에서만 seqscan/sort를 억제한 EXPLAIN을 실행했다. 두 hot/cold 파티션의 인덱스가 카탈로그상 HNSW이며 이용 가능 계획에 쓰이는 것을 확인했다. 이는 기본 비용 기반 선택이나 성능 우위를 주장하는 검증이 아니다.
- 요청 스냅숏 안의 의미 읽기에서 strict_order를 확인하고 정상·잘못된 차원 오류 뒤 풀 연결에 설정이 남지 않는지 대조했다. 별도 ACCESS EXCLUSIVE 잠금의 실제 대기를 관찰한 뒤 독립/스냅숏 의미 질의를 취소하여 Canceled·사용자 원인·빈 후보와 연결/예약 회복을 확인했다.

## 실행 결과와 시험 준비 보완

전용 이미지 `agent-context-search02:local`, 컨테이너 `acs-search02`, 볼륨 `acs-search02-data`에 `agent-context.task=search02` 소유 라벨을 적용했다. loopback 별도 포트·합성 자료, PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6과 정식 001/009/010/011/012/013 마이그레이션을 사용했다. 기존 개발 DB는 사용하지 않았다. vector/halfvec 임시 DB도 정식 마이그레이션 helper로 준비·정리했다.

- Go 1.27.1 `go test -race -json -count=1`, search 전체는 120초, store 선택 범위는 `TEST_DATABASE_REQUIRED=1`, `-p 1`, 180초 마감으로 실행했다.
- search는 최상위 44건·하위 56건, **100건 통과**했다. store는 새 인자/채널 묶음과 기존 색인·비그래프 검색·전역 요약·스냅숏·접근 기록의 최상위 7건·하위 19건, **26건의 최종 결과가 통과**했다.
- 초기 store 실행은 미사용 import로 빌드하지 못했다. 이후 새 표본의 사건 구성원을 derived_from 인자로 넘긴 오류와 소유자 등급 누락을 보완했다. 부정 구문의 ts_rank_cd를 모두 0점으로 가정한 기대 순서와 인덱스 이름에 hnsw가 들어간다고 가정한 검증도 실제 순위·카탈로그에 맞게 고쳤다. 하위 시험은 해당 t에 실패를 전달하도록 보완했다. 이 과정의 실패를 숨기지 않으며 해당 묶음의 재검증을 완료했다.
- `(package, test)`별 마지막 결과는 **고유 시험·하위 시험 126건 통과·최종 실패 0건·건너뜀 0건**이다. 반복 실행은 고유 수에 더하지 않았다. 전체 저장소·검색 분야 최종 통합 인수로 확대하지 않았다.
- 최종 `GO_BINARY=/Users/alphagone/sdk/go1.27.1/bin/go sh ./check-go.sh`: 의존성 검증/빌드·전체 build·vet·gofmt 통과. 문서 링크·Markdown·계획 집계와 `git diff --check`를 확인했다.
- 시험 종료 뒤 다른 DB 연결·시험 임시 DB 잔여 0개와 소유 라벨을 확인했다. 전용 컨테이너·볼륨·이미지만 정리했고 같은 라벨의 잔여 자원은 없다.
