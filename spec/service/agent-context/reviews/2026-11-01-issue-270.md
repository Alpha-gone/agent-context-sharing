# #270 그래프별 전체 감사 범위 제한

## 원인과 변경

전체 감사가 그래프마다 label 없는 양 끝점 MATCH에 세 소속 조건을 OR로 적용하고, 별도의 고아 간선 검사도 모든 label 테이블과 정점을 조인했다. 정점 조건도 기존 text graph_id 표현식 인덱스와 다른 agtype 표현식이었다. 등록 그래프 수에 전체 DB 크기가 곱해지는 경로였다.

정점은 기존 text graph_id 인덱스로 읽고, 모든 물리 정점 식별자를 보존한다. 일곱 label마다 간선 소속·시작점·끝점으로 행을 먼저 고른 뒤 UNION으로 합친다. 행에 물리 간선 ID가 포함되므로 세 조건에 중복 일치한 행은 한 번만, 같은 속성의 다른 간선은 각각 유지한다. 끝점은 이 범위 안에서 LATERAL PK 조회하여 다른 그래프의 전체 정점 해시 조인을 막고, 누락 끝점도 같은 조회에서 검출한다. 별도의 전역 고아 간선 스캔은 전체 감사 경로에서 제거했다. 미등록 그래프 검사는 기존 cmd/audit가 전체 순회 뒤 한 번 실행하는 단계를 유지한다.

새 015 마이그레이션은 일곱 label에 SQL text graph_id 인덱스를 추가하고 ANALYZE한다. 기존 SQL·checksum·agtype 인덱스는 바꾸지 않는다. [데이터 설계](../sdd/data.md#그래프-불변식-규칙과-감사)·[시험 설계](../sdd/testing.md#그래프-불변식-감사-테스트)·[외부 근거](../reference.md#270-그래프별-전체-감사-범위와-인덱스)를 갱신했다. 요구사항·개발 계획·환경 키·DOX 소유권은 변경할 이유가 없어 유지했다.

## 스캔 범위 재현과 수정

Go 1.27.3, darwin/arm64, Apple M4 Pro, PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6의 전용 시험 DB를 사용했다. .env에서 TEST_DATABASE_URL·TEST_DATABASE_REQUIRED=1만 읽고, 별도 DB를 생성해 전체 마이그레이션을 적용하고 자신이 만든 DB만 정리했다. 공유 DB 스키마는 변경하지 않았다.

대상 그래프는 정점 7개·간선 6개다. 초기 재현 표본의 다른 그래프 정점 900개·각 label 간선 900개에서 기존 감사는 실제 정점·간선 스캔 합계 28,048행이었다. 처음 범위를 나눈 수정도 끝점 해시 조인 때문에 5,473행을 읽어 실패했고, 끝점 조회 경계를 고쳐 해결했다. 이후 회귀 표본은 다른 그래프의 정점을 정확히 1,000개·10,000개, 각 label 간선도 같은 수로 고정했다.

| 최종 구현의 다른 그래프 정점 수 | 다른 그래프 간선 합계 | 실제 정점·간선 스캔 합계 | Shared Hit + Read 블록 | 조회 수 |
|---:|---:|---:|---:|---:|
| 1,000 | 7,000 | 37 | 101 | 4 |
| 10,000 | 70,000 | 37 | 109 | 4 |

EXPLAIN (ANALYZE, BUFFERS, TIMING OFF, FORMAT JSON)에서 행 수는 각 테이블 스캔의 (Actual Rows + Rows Removed by Filter) × Actual Loops를 합쳤다. 시스템 카탈로그·임베딩 행은 이 정점·간선 합계에서 제외하고, 버퍼는 네 질의 root의 Hit·Read 합계다. 반환 행 수만 검사하거나 인덱스 사용을 강제한 결과가 아니다.

## 다중 그래프 측정

BenchmarkAuditMultipleGraphsIntegration, -run '^$' -benchtime=20x -count=1, race 없이 측정했다. 각 그래프는 같은 사슬 표본 정점 40개이며 매 크기별로 새 DB를 사용하고 통계를 모았다. 선택 감사는 첫 그래프 하나를, 전체 감사는 목록 조회·등록 그래프 순회·미등록 그래프 검사 한 번을 실행한다. 외부 임베딩 제공자를 호출하지 않으며 이 벤치마크는 색인하지 않은 표본의 위반 보고 비용도 포함한다.

| 그래프 수 | 선택 감사 ms/op | 전체 감사 ms/op | 전체 감사 ms/graph |
|---:|---:|---:|---:|
| 1 | 11.246 | 11.113 | 11.113 |
| 8 | 3.269 | 32.362 | 4.045 |
| 32 | 3.690 | 104.340 | 3.261 |

다른 그래프 수가 늘 때 선택 감사 시간이 함께 증가하지 않았고, 전체 비용도 그래프 수와 전체 크기의 곱으로 증가하지 않았다. 로컬 합성 표본의 관찰값이며 실행 계획 전환·워밍업·동시 호스트 부하가 포함된 단일 측정이다. 정확한 비례 계수나 운영 지연 보장은 아니다. 예상 밖 label에는 계약 인덱스를 만들지 않으므로 비정상 테이블의 조회 비용까지 이 수치로 보장하지 않는다.

## 손상 보고와 검증

- 일곱 label 각각에서 간선 소속만 일치·시작점만 일치·끝점만 일치·교차 그래프 연결·같은 속성의 다른 물리 간선·중복 context_id 물리 정점·양쪽 끝점 누락을 주입했다. 기존 OR 조회와 고아 보충을 참조하여 규칙 식별자·위치·보고 중복 수가 일치함을 확인했다. 기존 한쪽 끝점 누락·순환·기수성·임베딩·쓰기 차단 시험도 통과했다.
- 독립 리뷰에서 예상 밖 label 누락과 숫자 속성의 문자열화를 P2로 발견했다. 카탈로그의 계약 밖 label과 기본 무명 간선을 ONLY로 포함하고 agtype JSON 엄격 판독을 복원했다. UNKNOWN·무명 간선 보고를 기존 Cypher와 대조하고 숫자 relation_id·state가 오류로 거부되는 회귀를 추가했다. 재리뷰에서 두 발견 사항이 해소되었고 추가 결함은 없었다.
- Go 1.27.3에서 필수 DB 설정으로 `go test -race -json -count=1 -run 'Test(Audit|Invariant|TargetSchema|ConcurrentMigration|MigrationRollbackAndInvalid)' ./internal/store ./cmd/audit ./internal/migrate`를 실행했다. 저장소 61건·감사 실행기 21건·마이그레이션 30건, 하위 사례 포함 112건이 실패·건너뜀 없이 통과했다.
- 빈 vector·halfvec DB에서 새 인덱스 일곱 개와 전체 적용, 두 번째 무변경·015 SQL 재실행을 검증했다. 구형 이력과 기존 행의 보존, 동시 적용·실패 원자성도 확인했다. 새 파일 때문에 달라진 적용 수 기대값을 함께 갱신했다.
- check-go.sh의 의존성 검증·전체 build·vet·gofmt·govulncheck가 통과했다. 리뷰·문서 링크/앵커·git diff --check도 확인했다.

기존 .env.example·IDE 변경은 포함하지 않는다. 전체 저장소 테스트·실제 운영 부하·운영 DB 마이그레이션·배포는 수행하지 않았다.
