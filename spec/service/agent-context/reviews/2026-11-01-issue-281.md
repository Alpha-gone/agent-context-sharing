# #281 DATABASE_URL과 pgx 해석 정합화

## 원인과 변경

- 구성은 net/url, 실제 접속은 pgx v5.12.0의 libpq 호환 해석기를 사용했다. %00·잘못된 풀 옵션을 통과시키고 기본/다중 host 등 실제 드라이버가 받는 URI를 거부했다. 반복 query와 +의 의미도 달랐다.
- config는 store.ValidateDatabaseURL에 검증을 맡긴다. 저장소가 pgxpool.ParseConfig를 호출하고 구성 경계에는 고정 오류만 전달한다. DATABASE_URL은 postgres://·postgresql:// URI만 받으며 원문을 변경하지 않는다. 해석 실패는 config.Error의 DATABASE_URL 필드로 보고하고 드라이버 오류·원문·비밀번호를 감싸거나 보존하지 않는다.
- 드라이버 import·DB 핸들은 기존처럼 store/마이그레이션에 한정한다. config→store의 검증 의존을 아키텍처 표·Mermaid·설명과 ARCH-05 검증에 반영했다. pgx의 PG 환경 기본값·서비스/비밀번호/TLS 파일 읽기는 검증 중에도 발생할 수 있으므로 Load를 외부 자원을 전혀 읽지 않는 검사로 표현하지 않는다. DB 연결·풀 생성·제공자 호출·수신은 검증 뒤에 수행한다.
- 기본/다중/Unix 소켓 host와 URI 경로의 #는 pgx 의미를 따른다. net/url host·fragment 규칙으로 다시 제한하지 않는다. HTTP·OAuth URL 검증은 그대로 유지했다.
- 풀 상한은 문자열 포함 대신 pgx가 해석한 RuntimeParams의 키로 판정한다. 비밀번호/다른 값에 pool_max_conns가 등장해도 기본 하한을 적용하며 인코딩·반복 키의 실제 최종 값을 존중한다. pgxpool이 키를 제거하기 전 정보를 얻기 위해 기동 단계에서 pgx 해석을 별도로 수행한다.

## 회귀와 실제 연결

변경 전 새 구성 회귀에서 %00·잘못된 마지막 풀 값·기본/다중 host·# 경로·잘못된 풀 수명/TLS 값 등 9개 하위 사례가 실패했다. 변경 후에는 다음을 확인했다.

- 첫 @가 userinfo를 끝내는 원문과 인코딩한 @ 비밀번호의 실제 해석, %00 거부, 반복 키의 마지막 유효/무효 값, +와 %2B의 수락 및 application_name의 + 보존.
- 기본/다중 host·# 경로의 드라이버 수락과 잘못된 escape·풀 수명·TLS 모드의 거부. 거부 시 고정 필드·사유와 원인 비노출, 기동 조립 호출 0회.
- 풀 상한의 비밀번호/다른 값 부분 문자열·다른 키·인코딩된 키·반복 키·기존 keyword/value 저장소 호출. 풀 옵션은 PostgreSQL 시작 파라미터에 남지 않는다.
- `.env`의 TEST_DATABASE_URL·TEST_DATABASE_REQUIRED=1로 시험별 격리 DB에 정식 마이그레이션을 적용하고 인코딩된 상한 4와 application_name=acs+281로 실제 연결했다. pool 상한·실제 DB 이름·+ 값 보존을 확인했다. 공유 DB의 스키마·데이터는 준비용으로 변경하지 않았고 자신이 만든 DB만 정리했다.

## 검증 결과

Go 1.27.3에서 다음 시험을 race·count=1·JSON으로 실행했다.

- `./internal/config` 전체: 하위 사례 포함 343건 통과.
- `./internal/store`의 PoolConfigUsesParsedMaximumKey·DatabaseURLPoolIntegration·ConnectionConfigurationBeforeDial·ConnectionBudgetRangeAndCancelCause·ConnectionPreparationEverySessionIntegration: 17건 통과.
- `./cmd/server`의 Configuration 계열·DatabaseURLRejectsBeforeResourceStartup·PackageDependenciesMatchDesign·DatabaseHandleStaysInStore: 16건 통과.

총 376건이며 실패·건너뜀 0건이다. 첫 구현 검증에서 사용하지 않는 strings import로 빌드가 실패한 뒤 제거하고 구성 전체를 다시 실행했다. check-go.sh의 build·vet·gofmt·govulncheck와 변경 문서 링크·내부 앵커·git diff --check가 통과했다. 독립 리뷰에서 지적한 기존 plan 단독 의존 설명·Mermaid 누락을 수정했고 남은 발견 사항은 없었다.

요구사항·환경 변수 키·예시 값·DOX 소유권은 유지했다. 동작·경계·검증 정본과 ARCH-05만 현재 구현에 맞췄으며 과거 완료 기록은 당시 증거로 보존했다. 전체 저장소 시험·운영 배포는 미실행이고 기존 사용자 `.env.example`·IDE 설정 변경은 포함하지 않는다.
