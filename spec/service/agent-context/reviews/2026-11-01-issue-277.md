# #277 의존성 취약점 검사와 Go 보안 판올림

## 범위와 결정

- 공통 `check-go.sh`와 CI에 `govulncheck v1.9.0`의 기본 symbol 분석을 추가했다. 기본 텍스트 출력의 비정상 종료를 CI에 전달하며, 내부 Go 호출도 `GO_BINARY`가 선택한 SDK를 사용한다.
- 첫 검사에서 Go 1.27.1 표준 라이브러리 14건과 go-jose 1건이 호출 경로상 검출되었다. 사용자의 승인으로 Go 1.27.3을 개발·CI·이미지·시험 기준에 반영했다. 빌드 이미지 태그와 공식 다중 아키텍처 digest 및 운영 정적 검사 기대값을 함께 갱신했다.
- 사용자의 전체 의존성 최신화 요청에 따라 go-jose v4.1.7·pgx v5.12.0·x/crypto v0.58.0 및 oauth2·puddle·segmentio/asm·x/sync·x/sys·x/text·x/time의 최신 안정 판을 적용했다. `go get -u -t ./...`와 `go mod tidy` 후 공식 프록시의 업데이트 정보와 빌드·시험 패키지의 모듈을 대조했다. 실제 사용 모듈 16개에는 추가 업데이트가 없었다. 미사용 상위 모듈 메타데이터의 항목 7개는 불필요하게 직접 의존성으로 추가하지 않았다. [공식 근거](../reference.md#277-의존성-취약점-검사와-go-보안-판올림)를 기록했다.
- 현재 기준 문서를 동기화했다. 기존 Go 1.27.1 호스트 인수 기록은 당시 결과로 보존하고 Go 1.27.3 실제 호스트 재인수로 확대하지 않았다. DOX 소유권은 그대로 두고 루트 검사 책임에 취약점 검사를 명시했다.

## 검증

- Go 1.27.3 공식 SDK 배포 SHA256과 golang:1.27.3-trixie의 공식 manifest digest를 확인했다.
- Go 1.27.3에서 `check-go.sh` 전체가 통과했다. 모듈 다운로드·체크섬 검증·SDK 의존성 빌드·전체 build·vet·gofmt·govulncheck를 포함한다. 호출 경로상 취약점은 15건에서 0건이 되었다.
- x/crypto의 미사용 OpenPGP 패키지에 대한 모듈 수준 경고 [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932) 1건은 남는다. 해당 패키지를 import하거나 호출하지 않으며 검사 예외를 추가하지 않았다.
- `.env`의 시험 DB 접속 정보로 생성한 별도 DB에 마이그레이션 001~014를 적용하고 미적용 파일이 없음을 확인했다. `go test -json -count=1 ./internal/authz ./internal/store ./internal/web ./internal/mcp ./cmd/server`에서 5개 패키지, 하위 사례 포함 4,436건 통과·21건 건너뜀·실패 0건이었다. 생성한 DB의 정리도 완료했다.
- 최초 기존 시험 DB의 저장소 시험은 마이그레이션 014가 만드는 인덱스 14개 누락으로 카탈로그 확인에 실패했다. 기존 DB 스키마는 변경하지 않았고 위 최신 스키마의 별도 DB로 재검증했다.
- `test-prod-compose.sh`, 수정 셸 스크립트 4개의 `sh -n`, `go mod tidy -diff`, 변경 Markdown 상대 링크와 `git diff --check`가 통과했다. 별도 코드 리뷰에서 중요한 추가 지적은 없었다.

## 제한

실제 Codex CLI·물리 복구·추가 환경 의존 인수의 건너뜀 21건은 통과로 집계하지 않았다. 새 Docker 이미지의 실제 빌드·배포는 수행하지 않았으며 레지스트리 digest·운영 정적 검사와 같은 SDK의 전체 Go 빌드로 검증했다. 기존 개인 IDE 설정은 변경하지 않았다.
