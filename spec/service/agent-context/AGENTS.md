# 에이전트 컨텍스트 관리 서비스

## 목적

- 이 영역은 AI 에이전트를 위한 제텔카스텐을 공유 컨텍스트 그래프로 구현하고, 여러 작업자가 에이전트와 MCP로 컨텍스트를 공유·활용하며 협업하는 서비스의 요구사항, 상세 설계, 근거와 요청 기록을 보관한다.

## 소유권

- `spec/service/AGENTS.md`가 서비스 명세 공통 계약과 이 서비스 경계를 소유한다.
- 이 문서는 `agent-context/` 하위 문서의 서비스별 계약을 소유한다.
- `SRS.md`가 요구사항과 확정된 결정을, `SDD.md`가 그 요구사항의 상세 설계를 소유한다.

## 로컬 계약

- 서비스의 궁극적인 목적은 AI 에이전트가 지식과 작업 맥락을 지속적으로 축적·연결·재활용할 수 있는 제텔카스텐 시스템을 구축하는 것이다.
- 공유 컨텍스트 그래프는 AI 에이전트 제텔카스텐을 실현하기 위한 현재의 핵심 접근 방식이며, 여러 작업자의 컨텍스트 공유와 협업은 핵심 활용 목표다.
- 에이전트는 사용자 입력과 관련된 컨텍스트를 MCP로 조회·활용해 업무 연속성과 작업자 간 협업을 지원한다.
- 컨텍스트 데이터베이스는 Apache AGE를 사용한다.
- AGE 그래프는 하나만 두고 컨텍스트 그래프는 `graph_id` 속성으로 구분한다. 그래프 메타데이터는 AGE 그래프가 아니라 일반 테이블에 둔다.
- 논리 격리이므로 단일 접근 계층의 필수 `graph_id` 인자, 응답 재검사, 격리 위반 테스트로 격리를 강제한다. Row Level Security 채택은 읽기 경로를 검증한 뒤 판단한다.
- 그래프 불변식은 실행 가능한 공통 규칙 목록으로 관리하고 쓰기 시 영향 주변부와 복구·마이그레이션 뒤 전체 그래프를 검사한다. 첫 단계는 위반 위치와 규칙 식별자만 보고하며 자동 삭제·수정하지 않는다.
- 관계·경로 오염 적대적 평가는 기존 평가 데이터셋과 별도 공격 표본 명세를 쓰는 `cmd/eval -adversarial` 및 홉별 진단으로 수행한다. 공격 표본은 유형별 성립 조건을 만족하고 질의별 성공 조건, 오염 식별자와 기준선의 정상 기대 사건 경로를 분리한다. 홉별 진단은 사건 컨텍스트·확정 사건 관계만 직접 대조하고 참조 반환 변화는 영향 지표에만 반영한다. 관계 강화는 가중치가 아니라 보조 컨텍스트·관계 추가로 표현한다. 기준선과 표본·반복의 평가 그래프를 격리하고, 진단 단계는 경고만 남기며 검색 자동 제외·감점·관계 자동 삭제를 하지 않고, 복구 단계는 관계·컨텍스트 관리 연산만 사용하며 운영자 그래프 복구를 사용하지 않는다.
- 컨텍스트는 `Context` vertex label 하나에 `layer` 속성으로 계층을 구분하고, 확정된 참조와 사건 관계는 각각 edge label로 둔다. 참조를 property로 중복 저장하지 않는다.
- `RELATES_TO`는 정규화한 순서로 한 방향만 저장하고 탐색에서 양방향으로 다룬다.
- 사건 관계에는 버전과 시간 유효성을 두지 않는다.
- 임베딩은 AGE 그래프 밖의 별도 테이블에 `context_id`와 `graph_id`로 저장한다.
- 탐색만 openCypher로 처리하고 목록·필터·페이지 처리와 벡터·키워드 검색은 SQL로 처리한다.
- 사용자 입력, 에이전트의 MCP 기반 컨텍스트 조회, 여러 작업자의 공유 그래프 접근, 후속 업무 활용과 컨텍스트 시각화는 서비스의 확정 범위다.
- 시스템은 에이전트 측 MCP 클라이언트의 요청을 기다리는 MCP 서버 역할을 담당한다.
- MCP 요청에 포함된 현재 작업 컨텍스트를 기준으로 연결된 작업 컨텍스트 흐름을 반환하며, 지속 연결이나 프로토콜 세션 상태에 의존하지 않는 요청별 상호작용을 지향한다.
- 작업 컨텍스트 흐름은 에이전트가 사용하는 기계 판독형 결과이며 사용자에게 제공하는 컨텍스트 시각화와 구분한다.
- MCP는 컨텍스트 그래프와 컨텍스트 노드의 생성·조회·수정을 제공하며 노드 조회에서 `0홉`은 단일 노드 조회와 동일하다.
- 컨텍스트 그래프와 컨텍스트 노드의 사용자 직접 삭제는 MCP에 노출하지 않고 웹 페이지에서 소프트 삭제로 수행한다.
- 계정 플랜별 보관 정책이 적용되기 전에는 접근 가능한 계정이 하나 이상 있는 컨텍스트를 사용자 직접 삭제 전까지 무기한 보관한다.
- 마지막 접근 가능 계정이 사라지면 30일의 소프트 삭제 유예 기간을 시작하고, 기간 안에 접근 가능한 계정이 다시 연결되면 예정된 소프트 삭제를 취소한다.
- 유예 기간이 만료되면 컨텍스트를 소프트 삭제하고 사용자 접근을 차단하며 영구 삭제는 수행하지 않는다.
- 유예 시작 시각은 `context_graph.grace_started_at`에 두며 이 값의 유무가 웹 직접 삭제와 자동 삭제를 구분한다.
- 시간 경과가 방아쇠인 처리는 주기 작업 일곱 종으로 모으고 애플리케이션 인스턴스에 내장한다. 회차마다 자문 잠금을 얻은 인스턴스 하나만 실행하며 주기는 설계가 고정한다.
- 상호작용은 사건 컨텍스트로 묶고 사건 사이의 시간·인과·부분·의미 관계를 최소 관계 후보로 실험한다.
- 원천 사실과 관찰·경험·의견 성격의 파생 정보를 구분하고 의견이나 해석에는 근거와 신뢰 상태를 연결한다.
- 그래프 구조의 효과는 가정하지 않고, 비그래프 기준선을 먼저 구성한 뒤 동일한 입력·표현·검색 예산과 평가 조건에서 그래프 기능을 단계별로 추가해 비교한다.
- 컨텍스트는 원천·파생·사건 세 계층으로 구성하며, 원천의 최소 단위는 하나의 발화 또는 턴이고 생성 후 불변이다. 검색용 명제는 파생으로 생성한다.
- 파생은 갱신 시 판 번호를 증가시키고 이전 판을 대체 관계로 연결하며, 컨텍스트 식별자는 전역 고유한 UUIDv7을 사용한다.
- 파생에서 `derivation_kind`, `summary_scope`, `derived_from`은 불변이며 가변은 `body`, `confidence_state`, `valid_from`, `valid_to`뿐이다.
- 같은 그래프에서 `source_ref`가 같은 원천은 중복으로 보고 기존 것을 반환한다. 별도의 멱등성 키를 두지 않는다.
- 계층별 필수 속성, 불변·가변 규칙, 식별 방식과 참조 카디널리티의 기준 문서는 `SRS.md`의 「컨텍스트 모델」이다.
- 작업자는 계정 단위로 식별하며 계정이 인증 주체다. 접근 토큰은 계정을 대표하고 에이전트와 MCP 클라이언트는 계정을 대행한다.
- 계정은 로그인 아이디와 비밀번호로 인가 서버에서 생성하며 비밀번호는 단방향 해시만 보존한다. 이는 제텔카스텐 동작 검증을 위한 최소 범위이고 인증 고도화는 `TBD-AGENT_CONTEXT-048`이 소유한다.
- 계정을 없애는 경로를 두지 않는다. 접근 가능한 계정이 0이 되는 경로는 등급을 가진 팀의 구성원이 모두 제거되는 경우이며 탈퇴 경로는 `TBD-AGENT_CONTEXT-049`가 소유한다.
- 웹 화면은 인가 서버가 발급한 서명된 세션 쿠키로 인증하며 수명은 12시간이고 갱신하지 않는다. 세션을 서버에 저장하지 않고 로그아웃은 폐기 목록으로 처리한다.
- 웹 세션과 MCP 접근 토큰은 `aud`로 나누며 한쪽을 다른 쪽 채널에 제시하면 인증 실패로 다룬다.
- 검증 단계에서는 인증된 모든 계정이 운영자 자격을 갖는 것으로 보고 계정에 역할 값을 두지 않는다. 실제 역할 분리는 `TBD-AGENT_CONTEXT-052`가 소유한다.
- 소유자였던 계정이 자동 삭제된 그래프의 복구를 요청하고 운영자 화면은 대기 중인 요청만 보여준다. 대기 여부는 요청 기록과 처리 기록의 차이로 계산한다.
- 컨텍스트에는 기여 계정을 `created_by`로, 실제 기록 에이전트를 `created_by_agent`로 함께 기록한다. 계정과 에이전트의 식별자는 UUIDv7을 사용한다.
- 팀은 작업자가 아니라 계정을 묶는 권한 그룹으로 다루며 팀에 부여한 등급은 소속 계정에 적용된다.
- 컨텍스트 그래프가 격리 단위이자 작업자의 작업 단위이며 그 위에 별도 묶음 계층을 두지 않는다.
- 권한은 계정과 그래프의 조합에 소유자·편집자·열람자 등급으로 부여하고 노드 단위 권한은 두지 않는다.
- 에이전트는 고유 권한 없이 대행 계정의 등급을 상속하며 `created_by_agent`는 권한 판정에 쓰지 않는다.
- 그래프를 생성한 계정이 소유자가 되고 사용자 직접 삭제는 소유자만 요청할 수 있다.
- 권한 부여·회수와 팀 관리는 웹 페이지에서만 수행하며 MCP에 노출하지 않는다.
- 소유자가 다른 계정에 소유자 등급을 부여하는 것이 작업 인계이며 그래프에는 소유자가 최소 하나 유지된다.
- 인증된 계정이 팀을 생성해 팀 관리자가 되고 구성원을 관리한다.
- 기여한 컨텍스트를 승인받는 검토 흐름은 두지 않는다. 신뢰 수준은 파생 컨텍스트의 근거 상태와 신뢰 상태로 표현한다.
- 원천은 `origin_kind`로 사용자 발화, 에이전트 응답, 외부 내용을 구분하며 생성 후 바꾸지 않는다.
- 출처 구분으로 검색 순위를 바꾸거나 결과에서 빼지 않고 흐름 응답에 담아 받은 에이전트가 판단하게 한다.
- 오염은 연산 기록과 감사 기록으로 시작점과 전파 범위를 되짚고 폐기로 정리하며 연쇄 폐기는 하지 않는다.
- 응답을 구성할 때 같은 근거와 같은 종류의 유사한 파생을 대표 하나로 접고 접힌 수를 알린다. 저장된 파생은 거부하지 않는다.
- 동시 갱신은 낙관적 잠금으로 다룬다. 수정 요청은 기대 버전을 포함하고 현재 버전과 다르면 거부하며 명시적 잠금 연산은 제공하지 않는다.
- 충돌한 수정을 자동으로 병합하지 않으며 재시도는 호출자의 책임이다. MCP 요청 하나가 트랜잭션 하나다.
- 격리 수준은 Read Committed이며, 마지막 소유자와 마지막 접근 가능 계정처럼 소멸을 세는 판정만 대상 그래프 행을 잠근 뒤 센다. 여러 그래프를 잠글 때는 `graph_id` 오름차순을 지킨다.
- `version`은 모든 컨텍스트와 컨텍스트 그래프의 공통 속성이며 원천 컨텍스트는 불변이라 1로 고정된다.
- 수명주기 변화는 추가·갱신·대체·폐기·유지의 관리 연산으로 다루며 판단 입력, 실행 주체와 적용 결과를 기록한다. 거부된 연산도 남긴다.
- 원천 컨텍스트는 갱신과 대체의 대상이 아니며 `유지`도 기록 대상이다.
- 검색은 의미 유사도·키워드·시간 필터를 진입 채널로, 그래프 경로를 확장 채널로 실행하고 네 채널의 결과를 결합한다. 채널의 독립성은 순위 산정과 실패 처리에만 해당하며 실행 순서에는 해당하지 않는다.
- 요청 단위 일관 읽기는 후보 수집부터 홉 확장·출처 조립까지 한 커밋 상태를 읽는 동기화 스냅숏과 내용 판 재시도를 현행 `Read Committed` 검색과 비교한다. 결과 동등성·일관성·연결 점유·재시도율·지연을 판정하기 전 운영 기본값은 현행 검색이다.
- 검색은 `context_flow_get`의 내부 단계이며 별도 검색 연산을 두지 않는다.
- 흐름 조회는 현재 작업 컨텍스트를 `work_context` 텍스트 하나로 받고 별도의 진입점 지정 수단을 두지 않는다.
- `body`와 `work_context`의 상한은 8000자이며 컨텍스트 예산의 기본값보다 작게 유지한다. 상한이 예산보다 크면 그 컨텍스트가 흐름 응답에 실릴 수 없다.
- 채널의 병렬과 순차 실행은 배포 구성으로 정하며 기본은 병렬이고 결과는 같다. 순차 채택은 채널별 지연을 측정한 뒤 정한다.
- 그래프 경로 채널은 진입 채널의 결과를 입력으로 받으므로 병렬화 대상이 아니며 실행 방식과 무관하게 뒤에 실행된다.
- 진입 채널이 모두 실패하면 그래프 경로를 `진입점 없음` 사유로 실패한 채널에 넣으며, 시간 필터가 남아 있으므로 검색 전체를 오류로 만들지 않는다.
- 채널 결과는 채널별 순위의 역수 합으로 재순위화하며 채널 가중치와 점수 정규화를 두지 않고 기여 채널을 결과에 남긴다.
- 통합 순위 산정과 중복 파생 접기 뒤 예산 적용 전에, 후보 부분 그래프의 확정 참조·확정 사건 관계로 진입점 또는 원천까지 이어지는 연결 근거 집합을 고르는 구성을 비교할 수 있어야 한다. 통제 비교를 통과하기 전 운영 기본값은 기존 통합 순위 절단이다.
- `scope=auto`에서는 초기 직접 후보의 충분성과 분산으로 직접 검색, 최대 1홉 국소 확장과 전역 요약 진입 중 하나를 고르는 결정적 규칙 기반 정책을 비교할 수 있어야 한다. 명시적 `local`·`global`은 항상 우선하고 통제 비교를 통과하기 전 운영 기본값은 기존 `auto` 규칙이다.
- 채널의 순위 기준은 의미 유사도가 거리, 키워드가 `ts_rank_cd`, 시간 필터가 `recorded_at` 내림차순, 그래프 경로가 최단 홉 거리다. 후보 상한은 배포 구성이 정한다.
- 키워드 채널의 텍스트 검색 구성은 `simple`이며 색인과 질의가 같은 값을 쓴다. 조사가 붙은 한국어 표기가 일치하지 않는 한계를 지고 가며 형태소 분석 도입은 `TBD-AGENT_CONTEXT-061`이 소유한다.
- 의미 유사도 채널의 임베딩은 시스템이 컨텍스트를 저장할 때 `body`로 생성하고 `body` 갱신 시 다시 만든다. 임베딩은 컨텍스트가 아니라 검색 색인이다.
- 색인은 컨텍스트 저장과 한 트랜잭션으로 작업만 등록한 뒤 비동기로 생성한다. 색인 실패는 컨텍스트 저장을 되돌리지 않고 작업자가 재시도한다.
- 미색인 컨텍스트는 의미 유사도 채널에서만 빠지며 색인 미완료를 응답에 표시하지 않고 관측 지표로 드러낸다.
- 색인 작업은 컨텍스트마다 한 행이며 재등록과 재색인을 upsert로 합친다. 작업자는 `next_attempt_at`이 지난 행을 `FOR UPDATE SKIP LOCKED`로 확보하고 처리 중 상태를 두지 않는다.
- 임베딩 모델명과 저장 압축 방식은 명세가 고정하지 않고 배포 구성 값으로 둔다. 하나의 그래프에서는 같은 모델·차원·압축을 쓰고 바꾸면 그래프 전체를 재색인한다.
- 재색인 중이라는 표시를 따로 두지 않는다. 현재 구성과 다른 `model_id`를 가진 임베딩 행이 남아 있는 것이 곧 재색인 중이며 그 행 수가 진행률이다.
- 색인 대상은 계층을 구분하지 않되 원천 제외 구성과 비교해 재현율 손실이 유의하지 않으면 원천 제외를 기본으로 삼는다.
- 접근이 차단된 컨텍스트와 일정 기간 쓰이지 않은 활성 컨텍스트는 값싼 저장 계층으로 옮길 수 있으며 계층 이동은 삭제가 아니다. 활성 컨텍스트는 조회 시 즉시 되읽을 수 있어야 한다.
- transport는 HTTP 기반 Streamable HTTP, protocol revision은 2026-07-28을 사용하며 SSE 스트리밍과 프로토콜 세션을 두지 않는다.
- MCP는 `/mcp` 단일 엔드포인트에서 POST만 받고 GET·DELETE는 `405`로 답한다. `Origin` 검증과 헤더·본문 대조를 지난 뒤에야 인증을 본다.
- 전송 계층 오류는 HTTP 상태와 JSON-RPC 오류 코드로, 도메인 오류 8종은 `tools` 결과 안으로 나눈다. 두 층을 섞지 않는다. 인증 실패는 도메인 오류가 아니라 HTTP `401`이다.
- `tools/list`가 연산 13종의 `inputSchema`를 내며 스키마가 검증을 대신하지 않는다. `x-mcp-header`는 쓰지 않는다.
- 애플리케이션과 데이터베이스를 분리해 배포하고 애플리케이션은 무상태라 인스턴스를 늘려 확장한다. 색인 작업자는 애플리케이션 안에 두거나 분리할 수 있으며 어느 쪽이든 요청 경로 밖에서 처리한다.
- 요청·검색·색인·관리 연산의 지표를 남기되 접근 토큰 원문과 컨텍스트 본문은 로그에 남기지 않는다.
- 지표는 구조화 로그로만 내보내고 지표 엔드포인트를 두지 않는다. 요청 지표가 그래프 식별자를 담으므로 노출하면 격리가 운영 경로로 우회된다.
- 생존 확인과 준비 확인을 나눠 두고 인증을 요구하지 않는다. 정상 종료는 트래픽 이탈·요청 완료·잠금 해제·풀 종료 순서다.
- 마이그레이션 실행기는 적용 전에 자문 잠금을 잡아 여러 인스턴스가 동시에 기동해도 한 번만 적용한다.
- 그래프 경로 채널은 진입 채널이 찾은 노드에서 출발하며 탐색 규칙은 「홉 범위 조회」를 그대로 따른다.
- 만료 조회는 `as_of`로 지정하고 시간 필터 채널에만 적용하며 별도의 만료 포함 플래그를 두지 않는다.
- 국소 구성으로 시작하고 유사도 하한을 넘은 의미 후보와 키워드 후보가 모두 없으면 전역 요약을 진입점으로 함께 쓴다. 시간 후보와 하한 미달 의미 후보는 결과에는 남기되 전환을 막지 않는다. 호출자는 `scope`로 강제할 수 있고 기본은 `auto`다.
- 사건 관계 후보는 시간 인접, 구성원 부분집합과 임베딩 유사도로 제안하며 `causes`는 자동 제안하지 않는다.
- 컨텍스트 예산의 단위는 응답에 담기는 `body`의 유니코드 문자 수이며 식별자와 메타데이터는 세지 않는다. 기본값은 20000자이고 호출자가 `budget`으로 낮출 수 있다.
- 예산은 채널별로 배분하지 않고 통합 순위 또는 연결 근거 집합의 대표 순위 상위부터 채우며 채널별 후보 수 상한으로 결합 단계의 계산량을 제한한다.
- 작업 컨텍스트 흐름 응답은 컨텍스트·참조·관계와 검색 메타데이터로 구성하고 경로를 미리 펼치지 않는다. 각 컨텍스트에 진입점 홉 거리, 기여 채널과 통합 순위를 담는다.
- 흐름 응답의 컨텍스트 정렬은 통합 순위로 고정한다. 예산 적용은 통합 순위 또는 연결 근거 집합의 대표 순위로 수행하며, 예산을 넘기는 선택 단위부터 제외하고 뒤 순위의 짧은 단위로 채우지 않는다. 담긴 컨텍스트를 잇는 참조와 관계만 남긴다.
- 컨텍스트 그래프의 이름 중복은 허용한다. 전역 유일로 두면 중복 응답이 다른 계정 그래프의 존재를 노출해 격리가 깨진다.
- 그래프 수정 대상은 `name`과 `description`뿐이며 나머지 속성은 시스템이 관리한다.
- 그래프 목록은 요청 계정이 권한을 가진 것만 마지막 활동 시각 내림차순으로 커서 기반 페이지 처리로 반환한다.
- `last_activity_at`과 저장량 누계 `stored_chars`는 컨텍스트를 만들거나 고치는 트랜잭션에서 한 번에 갱신한다. 원천 중복으로 기존 것을 돌려주는 경로는 갱신하지 않는다.
- 홉 범위 조회는 시작 노드의 `graph_id` 안에서만 탐색하고 확정된 참조 `derived_from`, `supersedes`, `member_refs`와 `confirmed` 상태의 사건 관계를 따라간다. 방향은 요청에서 지정하며 기본은 양방향이다.
- 방문한 노드를 다시 방문하지 않고 최단 홉 거리로 한 번만 반환하며 삭제된 노드는 제외한다. 부분 그래프이므로 페이지 처리를 제공하지 않고 상한 초과 시 절단 사실을 표시한다.
- 홉 탐색은 현재 깊이별·관계 label별 너비 우선 탐색을 기본으로 유지하고 Apache AGE 내장 경로 질의와 같은 결과 조건에서 비교한다. 결과가 같고 실제 배포 이미지에서 왕복 횟수와 지연이 개선될 때만 대체하며, 다음 PG18 호환 공식 안정판으로 올릴 때 같은 비교를 반복한다.
- 계정 플랜은 명세가 이름과 값을 고정하지 않고 운영 구성으로 두며, 명세는 플랜이 정할 수 있는 열네 항목과 기본값만 확정한다.
- 상태 확인 경로를 뺀 모든 HTTP 통신을 TLS로 보호하고 평문 요청을 처리하지 않는다. `/healthz`와 `/readyz`는 자격 증명도 본문도 담지 않으므로 프로브가 프록시를 거치지 않아도 응답한다.
- 임베딩 생성을 위해 `body`가 제공자에게 전달되며 이것이 본문이 격리 경계를 나가는 유일한 경로다. 검색의 질의 텍스트도 같은 제공자에 같은 모델로 전달된다. 제공자는 배포 구성으로 두며 자체 호스팅을 고르면 경계 밖 전송이 없어진다.
- 미확정 관계 제안은 보존 기간이 지나면 정리하며, 정리된 정체성은 여전히 유효하면 다시 제안된다.
- `relation_list`는 `graph_list`와 같은 커서 기반 페이지 처리를 쓴다.
- 팀은 팀 관리자가 소프트 삭제하고 복구하며 삭제된 팀의 등급은 무효가 된다. 팀 관리자 이전은 두지 않는다.
- 플랜 상향은 즉시 적용하고 하향은 이미 초과한 상태에서 새 생성과 확장만 거부하며 초과분을 삭제하지 않는다.
- 보관 기간 변경은 변경 시점 이후의 판정에만 적용하고 소급하지 않는다.
- 한도를 넘는 요청은 `limit_exceeded`로 거부하며 자동 과금을 두지 않고 과금 정책은 명세 밖이다.
- 누적 한도의 현재 값은 집계하지 않고 누적해 둔 값에서 읽는다. 요청 빈도는 컨텍스트를 만들거나 고치는 연산만 1분 고정 창으로 세며 한도가 없는 계정은 카운터를 만들지 않는다.
- 적용된 연산 기록과 감사 기록은 대상 컨텍스트의 보관 기간 이상 유지한다. 거부된 연산 기록은 하한을 적용하지 않고 별도 기간을 두며 기본값은 6개월이다.
- 「지속 평가」의 측정 기간은 거부된 연산 기록의 보존 기간을 넘지 않는다.
- 만료된 파생을 자동으로 정리하지 않는다. 만료는 삭제 사유가 아니다.
- MCP primitive는 `tools`만 사용하고 연산은 `대상_동작` 형태의 snake_case로 둔다. 삭제와 권한 관리는 연산으로 노출하지 않는다.
- 오류는 구조화된 코드로 반환해 호출자가 재시도 가능 여부를 구분할 수 있게 하며 상황별 매핑은 「예외와 오류 처리」를 따른다.
- 결과 절단, 빈 결과와 일부 검색 채널 실패는 오류가 아니라 정상 응답의 부분 상태로 다룬다.
- 파생의 유효 시점은 에이전트가 명시하며 대체는 만료를 일으키지 않는다. 원천 컨텍스트는 유효기간을 갖지 않는다.
- 만료된 파생은 기본 검색에서만 제외하고 시간 필터, 홉 범위 조회와 직접 조회에서는 반환한다.
- 관리 연산 다섯 종은 에이전트가 판단해 자율 실행한다. 모두 되돌릴 수 있고 판단이 기록에 남기 때문이다.
- 노드 폐기와 복구는 연산으로 제공하되 복구는 폐기한 채널로 제한한다. 웹에서 삭제된 컨텍스트는 연산으로 복구하지 않는다.
- 컨텍스트 그래프의 삭제는 웹 전용을 유지하며 에이전트의 폐기는 노드에만 적용한다.
- 연산 기록은 대상 컨텍스트가 소프트 삭제되어도 남긴다.
- 사건 간 관계는 시스템이 후보를 제안하고 명시적 관리 연산으로 확정하며 제안과 확정을 모두 기록한다.
- 사건은 하나의 작업 목표를 공유하고 시간적으로 이어지는 상호작용을 묶으며 경계는 에이전트가 판단하고 판단 입력을 기록한다.
- 같은 컨텍스트는 여러 사건의 구성원이 될 수 있고 사건은 다른 사건을 `member_refs`로 갖지 않으며 포함은 `part_of` 관계로 표현한다.
- 사건의 시간 범위는 에이전트가 명시하고 시스템은 원천 구성원의 `occurred_at`이 범위 안에 드는지 검증한다.
- 관계는 사건 사이에만 두고 `precedes`, `causes`, `part_of`, `relates_to` 네 종을 정해진 방향과 순환·시간 제약으로 관리한다.
- 관계는 `proposed`, `confirmed`, `discarded` 상태를 가지며 확정된 관계만 홉 탐색과 작업 컨텍스트 흐름에서 따라간다.
- 관계 연산은 `relation_list`, `relation_confirm`, `relation_discard` 세 종이며 갱신·대체와 복구 연산은 두지 않고 재확정이 복구를 대신한다.
- 관계는 갱신하지 않으므로 낙관적 잠금의 검사 대상이 아니다.
- 파생 재생성과 사건 병합 같은 재구성도 관리 연산으로 수행하고 기록한다.
- 사건 병합은 남길 사건을 갱신하고 흡수된 사건을 폐기하며, 분할은 새 사건을 추가하고 원래 사건을 갱신한다. 폐기된 사건의 확정 관계도 함께 폐기한다.
- 제텔카스텐 비전의 충족은 `NFR-AGENT_CONTEXT-005`, `NFR-AGENT_CONTEXT-007`, `NFR-AGENT_CONTEXT-009`로 판정하며 만족하지 못하면 그래프 접근을 재검토한다.
- 검증의 합격 기준은 절대 점수가 아니라 기준선 대비 개선폭과 통계적 유의성으로 정한다.
- 평가 데이터셋은 공개 장기 기억 벤치마크를 기준으로 쓰고 사건 관계·근거 상태 같은 고유 구조는 자체 세트로 보완한다.
- 그래프 효과는 기준선에 그래프 경로, 사건 관계, 전역 요약 진입점과 근거 경로 보존 선택을 순서대로 더해 비교하고 개선이 없는 단계는 기본 구성에서 뺀다. 질의 적응형 검색은 그래프 관계 범위와 근거 경로 선택 값을 고정한 별도 통제 비교로 판정한다.
- 검색 품질 평가는 재현율·순위·예산뿐 아니라 근거 완전성, 경로 연속성, 단절 근거 비율, 허브 편중, 중복 컨텍스트 비율, 확장 단계의 한계 기여와 검색 경로 오선택률을 구조·검색·비용으로 나눠 측정한다.
- 지속 평가는 온라인 갱신, 재생, 전이, 복구, 망각과 상충 해소 여섯 시나리오로 수행한다.
- 업무 효과는 통제 과업과 집계 실사용 지표로 재며 컨텍스트 본문과 개인 식별 정보는 수집하지 않는다.
- 파생 컨텍스트는 에이전트만 생성하며 근거와 종류를 반드시 명시한다. 시스템의 주기적 자동 생성은 두지 않는다.
- 요약 파생은 `summary_scope`로 국소·전역을 구분하고 전역 요약은 사용자 개관과 에이전트 검색 진입점으로 함께 쓴다.
- 근거가 폐기·대체되면 파생에 표시하고 자동 폐기하지 않으며 재생성·폐기·유지는 관리 연산으로 판단한다.
- 파생의 `evidence_state`는 `observation`, `experience`, `opinion` 세 값이며 에이전트가 명시하고 생성 후 변경하지 않는다.
- 근거 연결은 `derived_from`을 그대로 쓰고 의견 전용 참조를 따로 두지 않는다.
- `confidence_state`는 `opinion` 파생만 가지며 `supported`, `uncertain`, `disputed` 중 하나를 에이전트가 명시하고 시스템은 계산하지 않는다.
- 상충은 `disputed` 표시와 관리 연산 기록으로 다루며 상충 전용 참조와 검색 자동 제외를 두지 않는다.
- 신뢰 상태 갱신은 편집자부터 `node_update`로 수행하며 원 작성 계정으로 제한하지 않는다.
- 시스템과 함께 배치되는 인증 서버는 MCP 클라이언트의 인증 정보를 검증해 1시간 동안 유효한 접근 토큰을 발급한다.
- MCP 클라이언트는 모든 보호된 MCP 요청에 접근 토큰을 포함하며, 만료 10초 전부터 만료 전까지 유효한 요청이 도착하면 토큰을 1시간 단위로 자동 갱신한다.
- MCP 클라이언트의 접근 토큰은 프로세스 메모리에 보관하고 임시 파일은 운영 기본 저장소로 사용하지 않는다.
- 인증은 OAuth 2.1 Authorization Code with PKCE를 쓰고 MCP 클라이언트를 공개 클라이언트로 다룬다. Client Credentials는 두지 않는다.
- 토큰의 `sub`에 계정 식별자를 담고 scope는 단일로 둔다. 그래프 권한은 토큰이 아니라 요청 시점에 판정한다.
- 갱신 토큰을 두지 않고 확정된 자동 갱신 구간만 갱신 통로로 쓴다. 갱신된 토큰은 HTTP 응답 헤더로 전달하고 응답 본문에 담지 않는다.
- 기존 토큰은 원래 만료 시각까지 유효하며 겹친 갱신과 갱신 실패는 오류가 아니다. 최초 인증부터 12시간이 최대 연속 사용 기간이다.
- 접근 토큰은 서명된 JWT이며 리소스 서버가 JWKS로 검증한다. 서버는 토큰 원문을 저장하지 않고 `jti` 폐기 목록만 해당 토큰의 `exp`까지 유지한다.
- 인스턴스 사이에는 JWKS와 폐기 목록만 공유하고 세션 상태와 발급 이력은 공유하지 않는다.
- 사전 등록한 공개 클라이언트만 인가하고 `redirect_uri`를 허용 목록과 완전 일치로 검증한다. 루프백은 포트만 예외이며 Client ID Metadata Documents 지원은 `TBD-AGENT_CONTEXT-060`이 소유한다.
- 인가 코드는 원문을 저장하지 않고 해시로 두며 60초 안에 한 번만 교환된다. 재사용을 만나면 그 코드로 발급한 토큰을 폐기 목록에 넣는다.
- 발급 이력과 달리 인가 코드는 인스턴스 사이에 공유한다. 한 번만 교환되어야 하므로 어느 인스턴스가 썼는지 모두가 알아야 한다.
- 컨텍스트 시각화는 Obsidian Graph view를 참고 모델로 사용하되 동일한 UI와 기능 전체를 복제하는 것으로 해석하지 않는다.
- 시각화는 시스템의 웹 페이지가 렌더링하며 MCP는 시각화를 제공하지 않는다.
- 전체 보기와 국소 보기는 그래프 하나 안에서만 제공하고 전체 보기는 전역 요약을 함께 보여준다. 타임라인 보기는 두지 않는다.
- 소프트 삭제된 컨텍스트는 복구 화면 외에 표시하지 않고 `disputed`와 `evidence_invalidated` 파생은 감추지 않고 별도로 표시한다.
- 웹은 그래프 목록·상세, 권한과 팀 관리, 삭제와 복구, 감사 기록 화면을 제공하며 접근은 「등급별 허용 연산」을 그대로 따른다.
- 권한 화면은 직접 등급과 팀 상속 등급을 구분해 보이고 마지막 소유자의 회수 수단을 제공하지 않는다.
- 소유권 이전은 부여 양식에서 소유자 등급을 주는 것이며 별도 수단을 두지 않는다.
- 로그인과 계정 등록은 세션 없이 닿는 화면이라 웹 화면 여섯 종과 구분하며 「웹 요청 처리 순서」를 지나지 않는다.
- 감사 기록 화면은 마지막 행의 시각과 식별자를 담은 커서로 이어 읽고 페이지 크기는 그래프 목록 값을 쓴다.
- 삭제는 연쇄 영향을 안내하고 그래프 삭제에만 이름 입력을 받는다. 재인증과 연쇄 삭제는 두지 않는다.
- 운영자 복구는 유예 만료로 자동 소프트 삭제된 그래프에 한해 소유자였던 계정의 요청이 있을 때만 내용 열람 없이 수행한다. 웹 화면은 여섯 종이며 운영자 복구 화면만 등급이 아니라 자격을 본다.
- 권한·팀 관리와 웹 삭제·복구는 컨텍스트 관리 연산 기록과 별도인 웹 감사 기록으로 남긴다.
- 작업자 모델, 컨텍스트 단위, 그래프 모델, 접근 제어, 동시 갱신, 협업 정책, 검색, 계정 플랜별 소프트 삭제 전 보관 기간과 AI 에이전트 제텔카스텐 운영 모델은 사용자 결정 없이 확정하지 않는다.
- 현재 요구사항의 기준 문서는 `SRS.md`다.
- 공식 기술 근거는 `reference.md`, 사용자 요청과 반영 결과는 `logs/prompt.md`에 기록한다.

## 작업 지침

- 새 요구사항은 기존 ID와 상태를 확인한 뒤 가장 좁은 책임으로 추가한다.
- AI 에이전트 제텔카스텐이라는 서비스 비전과 이를 구현하는 현재 접근 방식인 공유 컨텍스트 그래프를 구분한다.
- 확정된 AGE 사상·격리 강제 장치·질의 경계를 아직 미정인 Row Level Security 채택, 벡터 인덱스 방식과 버전 호환성에서 구분한다.
- 확정된 그래프·노드 CRUD 기능, 소프트 삭제·보관 수명주기, 홉 탐색 정책과 연산 스키마를 플랜이 값을 정하는 보관 기간·한도와 구분한다.
- 확정된 사건 경계·관계 네 종의 정의·방향·제약·확정 절차·병합과 분할 방식이 「검색」의 제안 신호 및 「그래프 모델」의 AGE 사상과 어긋나지 않게 유지한다.
- 확정된 근거 상태 세 값·신뢰 상태 세 값·상충 처리 방식을 「검색 품질 평가」가 판단할 정량 지표 전환과 구분한다.
- 확정된 검증 원칙·데이터셋 구성·비교 단계·색인 대상 비교·시나리오·측정 방법을 아직 미정인 공개 벤치마크 선정 및 반복 횟수 조정과 구분한다.
- 「색인 대상 비교」와 「그래프 효과 비교」는 통제 조건이 다르므로 한 비교에 섞지 않는다.
- 확정된 컨텍스트 구조와 아직 미정인 값 체계를 구분한다. 파생 생성 정책은 `TBD-AGENT_CONTEXT-011`, 작업자 식별자 형식은 `TBD-AGENT_CONTEXT-021`이 소유하고 근거·신뢰 상태 값은 「근거 상태」, 사건 경계는 「사건 모델」이 확정했다.
- 컨텍스트의 저장 구조는 `TBD-AGENT_CONTEXT-003`, 지식의 축적·갱신·재구성·재활용 운영 정책은 `TBD-AGENT_CONTEXT-034`가 소유하도록 구분한다.
- 확정된 격리 단위·권한 등급·상속 규칙·관리 절차·동시성 제어·웹 화면 흐름을 아직 미정인 화면 배치와 시각 디자인에서 구분한다. 관계는 갱신하지 않으므로 충돌 검사 대상이 아니다.
- 확정된 관리 연산 종류·기록 항목·운영 원칙·판단 주체·허용 조건·자동화 범위와 「계정 플랜」이 값을 정하는 기록 보존 기간을 구분한다.
- 「제텔카스텐 운영 모델」은 원칙과 충족 기준만, 「파생 정책」은 파생의 생성·범위·무효화만 소유한다. 사건 관계 스키마는 「사건 모델」, 제안·진입점 알고리즘은 「검색」, 판단 기준은 `TBD-AGENT_CONTEXT-015`, 지표와 합격선은 「검증」이 소유한다.

- 확정된 그래프 속성·목록 계약·홉 조회 규칙·연산 매핑·흐름 응답 구성·transport를 아직 미정인 직렬화 형식과 구분한다. 플랜별 한도 값은 운영 구성이다.
- 확정된 토큰 수명·갱신 구간·클라이언트 메모리 보관·OAuth 매핑·갱신 정책·토큰 형식·transport를 아직 미정인 재시도 한계와 구분한다.
- 상세 설계는 `SDD.md`에 `service-design` 스킬로 작성한다. `SRS.md`가 `확정`이므로 착수 조건은 충족되었다.
- 구현 언어는 Go이고 기준 버전은 1.27.1이다. 이는 `SRS.md`가 아니라 `SDD.md`의 「구현 기술 기준」이 소유하는 설계 결정이다.
- Go 코드의 최신 관용구는 Modern Go Guidelines CLI로 대상 버전을 확인해 적용하며, 개별 관용구를 명세에 옮겨 적지 않는다. 루트 `AGENTS.md`의 `Effective Go` 기준은 그대로 유지한다.
- `SRS.md`가 `후속 기획`으로 미룬 배포 형상·운영 자동화, Apache AGE 스키마와 질의, 화면 배치와 시각 디자인은 `SDD.md`가 인수한다.
- `SDD.md`의 설계 미정 사항은 `TBD-AGENT_CONTEXT-040`부터 부여한다. 설계 선택 때문에 `SRS.md`의 「미정 사항」 절을 다시 열지 않으며, 요구사항 수준의 미정이 새로 생길 때만 그 절이 다시 열린다.
- 상세 설계는 절별로 파일을 나누지 않고 `SDD.md` 하나로 유지한다. 다섯 곳의 계약과 스킬이 단일 경로를 전제하고, 절 참조·추적표 커버리지·표 정합성 검증이 문서 안에서 성립하기 때문이다.
