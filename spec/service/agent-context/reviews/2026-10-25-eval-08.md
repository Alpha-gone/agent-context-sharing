# EVAL-08 적대적 평가·홉별 진단·명시적 복구 모듈 인수

## 범위와 판정

[EVAL-08](../development-plan/evaluation.md#eval-08)의 여섯 공격 유형, 첫 불일치 진단, 명시적 복구와 여섯 지표를 대상으로 한다. [SRS 적대적 평가](../SRS.md#관계경로-오염-적대적-평가), [시험 설계](../sdd/testing.md#관계경로-오염-적대적-평가와-홉별-진단), [실행·집계 경계](../sdd/evaluation.md#적대적-평가의-실행집계-경계)를 대조했다. 기존 실행기와 과거 측정 결과를 이번 완료 근거로 승계하지 않는다.

실제 CLI는 여섯 유형을 각각 10회 실행하고 별도 기준선 10개를 포함한 70개 그래프를 모두 정리했다. 복구 완전성은 1이며 60회 모두 복구 연산의 적용 성공 기록을 확인했다. 입력은 작은 합성 표본·고정 벡터 HTTPS 대역이므로 공격 저항성이나 공개 품질을 입증하지 않는다. 같은 과업의 두 대상 질의를 독립 단위 하나로 묶어 대상 질의 기반 지표의 평균을 보존하고 신뢰구간은 `-1`로 남겼다. 통제 질의의 독립 단위 수와 구간은 별도로 계산한다.

## 구현과 경계

- 공통 입력은 대상 ID 중복·중복 성공 조건·반환/제외 동시 요구·기준/추가 목록에 없는 관계 성공 조건과 관계 없는 기대 경로를 거부한다. 사건·관계의 정규화 정체성과 여섯 유형의 성립 조건을 검사한다.
- 관계 삽입의 추가 컨텍스트는 관계 끝점인 추가 사건에서 구성원·파생 근거를 따라 도달해야 한다. 관계 끝점과 무관한 추가 사건은 거부하고 간접 근거는 허용한다. 상호 강화의 서로 다른 오염 식별자는 컨텍스트와 관계를 모두 인정한다.
- 반복은 10회로 제한하고 생략한 조회 시각을 실행 시작 시각으로 고정한다. 기준선·공격 전·공격 후·복구 후의 전체 `AuditGraph`를 통과해야 다음 단계로 진행한다. 공격 전 key·순위·간선·진입점이 기준선과 다르면 공격 적용 전에 실패한다.
- 일부 검색 채널 실패는 측정을 중단한다. 비활성 채널과 진입점이 없는 정상 빈 결과를 장애로 세지 않는다. 취소와 정리 실패를 호출자에게 전달하고 정상 보고서 기록 전에 취소를 다시 검사한다.
- 진단은 순서가 있는 정상 경로에서 첫 불일치 하나만 반환한다. 네 경고 코드와 식별자만 남기고 `derived_from`·`supersedes`·`has_member` 변화는 영향 판정에만 반영한다. 진단은 응답이나 DB를 수정하지 않는다.
- 복구는 추가 관계 폐기→추가 컨텍스트의 참조 의존 순서별 폐기→정상 관계 재확정이다. 파일 배열의 역순에 의존하지 않는다. 각 복구 동작에 판단 표식을 남기고 해당 그래프의 적용 성공 기록을 재확인한다. 운영자 그래프 복구·가중치·자동 감점/제외/삭제를 추가하지 않았다.

## 집계와 실제 인수

질의·표본 쌍별 반복 평균을 먼저 구하고 `independent_unit`별로 묶어 대응 차이와 95% 구간을 계산한다. 통제 질의도 질의별 평균과 독립 단위를 사용한다. 같은 질의가 여러 표본에 등장해도 전체 대상·영향 질의 수를 중복 계산하지 않는다. 같은 회차의 영향 여부는 표본 간 합집합이며 질의·표본 쌍 수는 별도로 보고한다. 빈 표본·성공한 추적 대상 없음은 `-1`이고 독립 단위 하나의 구간을 0으로 만들지 않는다.

큰 기준 세트의 여섯 유형을 새 그래프에서 각각 공격 전후·복구 후 대조했다. 고의 기준선 불일치는 공격 전에 중단했고, 각 표본의 복구 완전성은 1이었다. 적용 기록에는 추가 관계 폐기 10건·추가 컨텍스트 폐기 12건·정상 관계 재확정 2건이 남았으며 추가·폐기 이외 연산은 없었다. 이 검사와 별도 실제 CLI는 정상 경로·그래프 격리·전체 감사·정리·원문 비노출을 함께 확인한다.

실제 CLI의 작은 세트도 허브 최대 차수, 브리지의 정상 경로, 공유 간선의 두 질의, 세 사건 연쇄와 연결된 상호 강화 조건을 유지한다. 고유 대상 질의는 2개, 질의·표본 쌍은 7개, 영향 질의 수는 2다. 전체 공격 성공률은 0.714286, 영향 비율은 1, 오염 근거 비율은 0.142011, 추적 완전성·복구 완전성은 1이다. 이 다섯 지표의 독립 단위는 하나여서 구간은 `-1`이다. 오탐률은 독립 단위 둘에서 1이며 구간 반폭은 0이다. 고정 벡터·충분한 후보/예산으로 대상 밖 질의도 오염 식별자를 반환하는 합성 입력의 결과이므로 운영 오탐률로 해석하지 않는다. 보고서에는 본문·질의·원천 locator를 포함하지 않는다. 이 표본의 관찰을 운영 기본값 변경이나 최종 채택으로 승격하지 않는다.

## 실행 결과·실패 이력

최종 고유 시험은 **509건**(최상위 **150건**, 하위 사례 포함)이며 평가 패키지 전체의 단일 명령이 실패·건너뜀 없이 **192.577초**에 통과했다. 기존 468건에 추가한 41건을 포함하며 중복 실행을 합산하지 않는다.

- Go 1.27.1, 직접 만든 `acs-eval08-db`의 새 `eval08_verified` DB, PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6, vector 768·정식 마이그레이션 6개를 사용했다. 임베딩은 로컬 HTTPS 대역만 호출했다.
- `TEST_DATABASE_URL`·`TEST_DATABASE_REQUIRED=1`과 `go test -race -count=1 -json -timeout=240s ./cmd/eval`을 사용했다. `-run`·`-skip`으로 최종 범위를 줄이지 않았다. 여섯 유형 상태 시험은 39.10초, 실제 CLI는 49.86초였다.
- `GO_BINARY=/Users/alphagone/sdk/go1.27.1/bin/go sh check-go.sh`의 의존성 검사·전체 build·vet·gofmt가 통과했다. 공개 데이터 다운로드·유료 호출·운영 DB나 기본값 변경은 포함하지 않는다.

앞선 508건의 전체 명령도 192.220초에 통과했다. 이후 같은 질의가 여러 표본에 등장할 때 영향 질의 수와 영향 비율·구간이 같은 회차별 합집합을 쓰도록 보완하고, 교차 회차 회귀를 추가해 최종 509건을 새 DB에서 다시 실행했다.

첫 모듈 명령의 `-timeout=120s`는 여섯 유형의 상태·복구 검사 109.71초와 작은 단일 유형 CLI 9.23초 뒤 기존 정리 실패 회귀를 준비하다 전체 제한에 도달했다. 그 전에 끝난 기능 시험은 통과했지만 이 명령을 전체 통과로 세지 않는다. 여섯 유형 시험의 질의를 각 표본의 대상과 통제로 좁혀 38.65초로 줄였다. CLI는 여덟 기준 컨텍스트에서 여섯 유형·각 10회·70개 그래프를 검증하도록 확대했고 49.67초에 통과했다. 중단 때의 시험 상태와 분리된 새 DB에서 최종 전체 회귀를 완료했다.

시험 뒤 세 합성 DB의 잔여 클라이언트 연결 0개를 확인하고 직접 만든 컨테이너·익명 볼륨을 정리했다. DOX pass에서 새 패키지·환경 변수·마이그레이션·소유 경계 변경이 없어 기존 DOX를 유지했다. 평가·시험 정본, 분야/전체 계획, SDD 진입점·서비스 색인, 공식 근거와 요청 기록을 정합화했다. 전체 계획은 111개 완료·1개 진행·12개 미착수이며 다음은 EVAL-09다. `feat/evaluation`에는 upstream이 없어 원격 대비 상태는 확인하지 못했다. 변경은 미커밋이며 개인 IDE 파일 두 개는 제외했다.

변경 Markdown 9개·로컬 링크/앵커 474개, 계획 ID 124개와 완료 111개를 대조했다. `git diff --check`가 통과했다. 시험 컨테이너와 해당 익명 볼륨의 삭제 및 기존 개발 컨테이너 두 개의 보존을 다시 확인했다.
