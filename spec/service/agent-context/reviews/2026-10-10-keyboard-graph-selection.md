# 시각화 키보드 선택 검토

## 대상과 상태

- 기준: 2026-10-10, `dev`의 `f9b8efd`, [#111](https://github.com/Alpha-gone/agent-context-sharing/issues/111).
- #101 처리로 목록의 기본 선택 버튼과 전체 보기·Esc·빈 영역 해제는 이미 존재했다. #111은 선택 상태·해제·상세 변경 안내·텍스트 근거와 명시적 상세 이동을 보완한다.
- 구현·자동 회귀 검증은 완료했으며 실제 브라우저 키보드와 스크린리더 수동 검증은 남아 있다. DOM 마크업과 headless Cytoscape 상태 검사를 음성 안내·브라우저 포커스 검증으로 승격하지 않는다.

## 구현과 계약

- 기본 HTML 버튼의 click을 사용해 Enter·Space의 브라우저 동작을 그대로 유지한다. 별도 keydown 활성화로 중복 실행하지 않는다.
- 포인터와 목록은 같은 선택 함수를 사용한다. 같은 노드를 다시 조작하면 해제하며 모든 버튼의 `aria-pressed`와 Cytoscape 선택을 동기화한다. 이름은 고정하고 `aria-controls`로 본문·근거 정보를 연결한다.
- 하나의 atomic status에 선택 식별자·국소 홉·상세 갱신만 알린다. 본문 전체는 자동 낭독하지 않고, 상세 링크로 제목에 이동해 계층·식별자·본문과 근거 정보를 읽는다.
- 강조한 나가는 `derived_from` 간선만 같은 방향의 텍스트로 표시한다. 후손이나 다른 관계를 근거로 혼동하지 않으며 부분 그래프에 연결이 없다는 안내를 실제 근거 부재로 단정하지 않는다.
- 국소 범위는 캔버스만 숨기고 목록·버튼은 유지한다. 선택·해제·홉 변경이 DOM 교체나 강제 포커스 이동을 일으키지 않으며 범위 밖 노드를 목록에서 선택할 수 있다. 전체 보기 복귀는 pressed·본문·근거도 초기화하고 홉 값과 절단 안내를 유지한다.
- 상세 이동 제목의 `tabindex=-1` 외에 양의 tabindex나 복잡한 ARIA 위젯을 추가하지 않았다. 보이는 선택·포커스 표시는 색뿐 아니라 border·outline으로 구분한다. 데이터는 `textContent`로 출력하고 사용자 본문을 HTML로 삽입하지 않는다.

## 검증 결과와 복구

- Go 1.27.1과 Node.js에서 렌더링·Cytoscape 회귀를 실행했다. 빈 그래프, 고립 노드, 범위 밖 목록 선택, 양쪽 선택 토글·pressed 동기화, 0·중간·최대 홉, 한 단계·다단계 근거 방향과 텍스트 일치·변경 안내·복귀 초기화를 검사한다.
- `go test -count=10 -race -run '^TestGraphDetailScopeControls$' ./internal/web` 통과.
- 임시 DB에 정식 `001_init`을 적용하고 `TEST_DATABASE_REQUIRED=1`, `go test -json -count=1 -race ./internal/web ./cmd/server`로 테스트·하위 테스트 208건이 실패·건너뜀 없이 통과했다. 실제 DB가 필요한 서버 시험도 포함하며 시험 DB만 정리했다.
- 양쪽 모듈의 `go build ./...`, `go vet ./...`, 루트 `gofmt -l .`과 `git diff --check`를 통과했다. 전체 서버·클라이언트 race는 실행하지 않았다.
- 첫 sandbox 실행은 `httptest` 포트 bind의 `operation not permitted`로 서버 시험이 실패했고 DB 미설정으로 통합 한 건을 건너뛰었다. 코드 결함으로 단정하지 않고 허용된 실행 환경·시험 DB로 재검증했다. 실패한 실행은 통과에 포함하지 않았다.
- 별도 loopback 브라우저 fixture는 실제 계정·DB 없이 같은 서버 템플릿과 자산을 제공했다. 준비 과정의 시험 helper 타입 불일치를 수정해 기동했다. Chrome 브라우저 연결은 제공되지 않았고 native Chrome 제어는 승인되지 않아 실제 UI 조작을 수행하지 못했다. 접근성 트리·스크린리더 음성도 확인하지 못했다.
- 검증 후 loopback fixture를 종료하고 이번 작업의 `issue111_test_20261010` DB 잔여 항목이 0건임을 확인했다. 삭제한 시험 데이터는 fixture로 다시 생성할 수 있다.

## 남은 수동 검증 절차

1. 빈 그래프와 원천·파생·근거·고립 노드가 있는 그래프를 Chrome 및 VoiceOver/Safari 같은 실제 보조 기술 조합으로 연다. 수행한 OS·브라우저·보조 기술 버전을 기록한다.
2. Tab·Shift+Tab만으로 목록 버튼·전체 보기·상세 링크·홉 슬라이더에 도달한다. Enter·Space로 선택하고 같은 노드를 다시 조작해 해제한다. 조작 버튼에 포커스가 남고 표시가 보이는지 확인한다.
3. 선택 버튼의 고정 이름과 pressed 상태, 짧은 선택·상세 변경 안내를 듣는다. 상세 이동 링크로 제목에 이동해 본문과 방향이 명시된 텍스트 근거를 읽는다. 본문 전체가 매번 자동 낭독되지는 않는지 확인한다.
4. 슬라이더 방향키로 0홉·중간·최댓값을 바꾸고, 캔버스에서 숨겨진 다른 노드를 목록으로 선택한다. 새 본문·근거·선택 상태가 같고 포커스가 숨겨진 요소로 이동하지 않는지 확인한다.
5. 전체 보기 버튼과 Esc로 해제해 pressed·본문·근거가 초기화되고 홉 값·절단 안내는 유지되는지 확인한다. 포인터 선택 뒤에도 같은 상태가 되는지 대조한다.
