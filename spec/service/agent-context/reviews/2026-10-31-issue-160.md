# #160 저장소 계층 낮음 등급 정합성 검토

- 대상: [이슈 #160](https://github.com/Alpha-gone/agent-context-sharing/issues/160).
- 기준: `dev`의 `ff64f3f`, 작업 브랜치 `fix/160-store-consistency`. 이슈의 행 번호는 비공개 `e163087` 기준이므로 현재 코드에서 항목별로 다시 확인했다.

## 항목별 처리

| 항목 | 처리 | 내용 |
|---|---|---|
| 호스트·DB 시계 혼용 | 처리 | 색인 등록은 이미 `statement_timestamp()`를 사용하여 변경하지 않았다. 유예 만료는 유예 시작과 같은 DB `clock_timestamp()`를 한 번 읽어 판정·삭제 시각을 정하고, 멱등성 정리는 예약·재생과 같은 DB 시계로 판정한다. 두 주기 작업은 기준 시각 인자를 받지 않는다. |
| 요청 ctx로 롤백 | 처리 | 웹·권한·서명 키·의미 관계 후보의 `defer tx.Rollback(ctx)` 13곳을 취소 독립 5초 예산의 `rollbackTransaction`으로 바꿨다. |
| DB 장애의 진단 분류 | 처리 | `writeFailure`의 드라이버 장애 판정을 `driverFailure`로 분리하여 관리 진단에도 적용한다. 감싼 PgError·연결·트랜잭션 종료·취소는 ERROR `store_unavailable`이며 도메인 거부는 기존 분류를 유지한다. |
| 자동 삭제 그래프의 유효 등급 재획득 | 처리 | 수정 전 코드에서 자동 삭제 뒤 팀 구성원 추가로 owner가 되살아나는 것을 재현했다. 유효 등급 질의가 `deleted_at`·`grace_started_at`이 함께 남은 그래프를 제외한다. 웹 직접 삭제 그래프는 기존대로 제외하지 않는다. |
| 운영 코드에서 쓰지 않는 export API | 부분 처리 | 저장소 패키지 시험에서만 쓰는 `CreateRelation`·`HasAppliedDiscard`·`RemoveTeamMember`·`DeleteTeam`·`ReplayIdempotent`·`TryIncrementRequestRate`·`OwnedGraphCount`를 `testing_entrypoints_test.go`로 옮겨 운영 빌드에서 뺐다. `CreateGraph`는 색인·마이그레이션·서버 시험이, `RevokeGraphGrant`는 서버 시험이 준비 도구로 쓰므로 유지하고 운영 대체 진입점과 시험 전용 용도를 주석에 명시했다. |
| 불변식 위반을 not_found로 가림 | 처리 | 그래프가 활성이고 한도도 넘지 않는데 저장량 갱신이 0행이면 `ErrInvariantViolation`을 감싼 내부 장애로 되돌린다. |
| 시스템 경로의 접근 기록 | 처리 | 시간·구성원 후보와 의미 유사도 후보 제안이 공개 `Context` 대신 내부 조회를 사용해 접근 시각·계층을 바꾸지 않는다. |
| 관계 후보 정리의 중단 범위 | 처리 | 그래프를 `graph_id` 순서로 훑고, 한 그래프의 해석·삭제 오류를 모아 보고하면서 다음 그래프 정리를 계속한다. 취소·마감은 회차를 멈춘다. |

자동 삭제 그래프는 이제 소유자 확인에서 먼저 거부되므로 웹 복구 시도의 오류가 `ErrInvalidState`에서 `ErrNotFound`로 바뀐다. 복구 SQL의 `grace_started_at IS NULL` 조건은 방어 조건으로 유지했다. 정본은 [인가](../sdd/authorization.md)·[소프트 삭제 수명주기](../sdd/context-lifecycle.md#소프트-삭제-수명주기)·[관계 후보 정리](../sdd/context-lifecycle.md#관계-후보-제안과-확정)·[데이터베이스 연결](../sdd/architecture.md#데이터베이스-연결)·[임베딩 접근 기록](../sdd/data.md)·[관측성](../sdd/observability.md)·[MCP 멱등성](../sdd/mcp.md)·[시험 설계](../sdd/testing.md#테스트-계층)에 반영했다. 스키마·설정·공개 API 동작은 위 항목 외에 변경하지 않았다. DOX pass에서 구조·소유권·색인 변경이 없어 기존 DOX를 유지했다.

## 회귀와 검토

Go 1.27.1, 고정 PostgreSQL/AGE 이미지 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`의 전용 합성 컨테이너에 정식 7개 마이그레이션을 적용하고 `TEST_DATABASE_REQUIRED=1`로 DB 건너뜀을 금지했다. 기존 개발·다른 시험 DB는 사용하지 않았다.

- 기준 `ff64f3f`의 별도 worktree에 새 시험을 옮겨 실행하여 실패를 재현했다. 감싼 PgError·`ErrTxClosed`의 WARN `constraint_violation` 분류, 자동 삭제 뒤 구성원 추가로 owner 재획득, 저장량 불일치의 `대상을 찾지 못했다`, 시스템 제안의 cold→hot 승격, 첫 그래프 `relation_decode` 뒤 정리 0건 중단이다. 멱등성 정리 시험은 같은 호스트에서 시계 차이를 만들 수 없어 기준 코드에서도 통과하며, DB 시계 판정의 회귀 확인으로만 사용한다. 롤백 ctx 변경은 별도 재현 시험 없이 기존 수명주기·연결 회복 시험으로 확인했다.
- 유예 만료 시험은 미래 시각 주입 대신 DB 시계 기준으로 유예·만료 시각을 옮긴다. 고정 만료 시각의 비소급, 무기한 유예 보존, 재연결 경합, 웹 자동 삭제 준비를 같은 의도로 유지했다. 웹 시험은 시험 전용 DB 연결을 저장소별로 보관하는 도우미로 만료 시각을 옮긴다.
- 새 단위·DB 시험은 감싼 장애 분류와 도메인 거부 유지, 자동 삭제 그래프의 유효 등급·등급 부여 거부와 삭제 상태 유지, 저장량 불일치의 불변식 위반과 롤백을 확인한다. 시스템 제안 두 종의 접근 기록 불변과 사용자 조회의 승격 양성 대조, 해석 실패 그래프 뒤 정상 그래프 정리·오류 보고·식별자 비노출, DB 시계 기준 멱등성 정리도 확인한다.
- `go test -race -p 1 -json ./internal/store ./internal/web ./internal/index ./internal/mcp ./cmd/server -count=1 -timeout=40m`에서 저장소 1,807건(433.005초)·웹 813건·색인 129건·MCP 480건이 실패·건너뜀 없이 통과했다. 서버는 693건 통과·1건 실패·21건 건너뜀(109.71초)이다. 건너뜀은 별도 CLI 19건·물리 복구 1건·이전 인수 1건의 환경 미설정이며 통과로 집계하지 않는다. 건수는 하위 사례를 포함한다.
- 서버의 유일한 실패 `TestOPS05DiagnosticFlushBudgetIntegration`은 진단 flush가 2.0023초에 끝나 최소 5초 기대에 실패한 것이다. [#201 검토](2026-10-31-issue-201.md)가 기준 코드에서 재현하고 #184 배치 이후의 기존 fixture 문제로 분리한 것과 같은 실패이며, 이번 변경의 저장소 경로를 호출하지 않는다. 서버 전체를 통과로 판정하지 않는다.
- `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check` 통과. 변경 문서의 상대 링크·앵커를 확인했다.
- 시험 뒤 임시 DB 잔류 0개·idle transaction 0개를 확인한 뒤 소유 컨테이너·익명 볼륨과 기준 비교용 worktree를 정리했고 잔류 없음을 확인했다. 기존 자원·개인 IDE 파일은 보존했다.
