- 대상: [ARCH-06](../development-plan/architecture.md#arch-06), [패키지·조립](../sdd/architecture.md#목표-추가-패키지와-조립), [기동과 종료](../sdd/operations.md#기동과-종료).

## 변경과 책임

기존 runConfigured는 파일·저장소·인가·웹·색인을 준비하면서 작업자도 시작했고 검색과 MCP 전체 업무를 기동 경로에 연결하지 않았다. `assembly.go`의 assembleApplication은 준비·주입·소유권을 담당하며 runConfigured는 조립 성공 뒤 작업자 시작·수신·신호·요청 drain을 담당한다. 조립 함수는 HTTP 수신기를 열거나 업무 소비 루프를 시작하지 않는다.

- 하나의 store와 계정 플랜을 웹·MCP 읽기/쓰기에 주입한다. 권한 검사는 기존 perm과 현재 유효 등급 어댑터를 그대로 사용한다.
- 하나의 index.Worker를 본문 색인·검색 질의 제공자로 공유한다. 검색 배포 구성 전체와 운영 ConsistencySnapshot을 search.New에 전달하며 검색·관리·색인·인가·요청·시스템 Reporter는 같은 Source/boot를 사용한다.
- 실제 읽기 5종·쓰기 8종에 agent_register를 더해 14종 처리기를 조립하고 기존 MCP SDK·Bearer·30초 요청 경계에 연결한다. `NewAgentHandler`는 기존 등록 API·스키마 검증·안전한 오류/구조화 결과를 연결하며 등록을 일반 쓰기 재생에 넣지 않는다. 미구현 도구의 합성 처리기를 사용하지 않는다.
- 조립 성공 뒤 embedded는 색인 소비와 주기 작업을, external은 주기 작업만 시작한다. external의 index 객체도 질의 transport를 소유하므로 종료 대상이다.
- 기록기·풀·각 작업자를 획득 직후 정리 대상으로 등록한다. 중간 조립 실패와 정상 종료가 작업자→조건부 풀 종료→시스템 종료 사건→진단 flush의 같은 경계를 사용한다. 요청/작업자/진단의 기존 예산과 풀 종료 생략 조건을 유지한다. 최초 종료의 원인·풀 안전 여부를 함께 처리하고 중복 종료가 자원을 다시 닫거나 사건을 중복 생성하지 않는다.
- provider HTTP client는 index.New의 기존 주입 경계로 전달한다. 기동은 nil 기본 TLS client를 사용하고 모듈 시험은 검증을 유지한 로컬 TLS client를 주입한다. 설정 키·DB 스키마·외부 의존성은 추가하지 않았다.

## 실행과 증거

Go 1.27.1·macOS arm64에서 `-race -json -count=1`로 실행했다. 서버 DB 시험은 TEST_DATABASE_URL·TEST_DATABASE_REQUIRED를 사용하되 시험별 빈 DB·정식 마이그레이션과 자기 자원 정리를 적용했다. 외부 Gemini 호출은 없다.

| 범위 | 명령 | 결과 |
|---|---|---|
| 조립·기동 실패·종료·구성·의존의 최초 모듈 인수 | `go test -race -json -p=1 -count=1 -timeout=180s -run '^(TestARCH06\|TestStartupFailureClosesWorkersIntegration\|TestPackageDependenciesMatchDesign\|TestConfiguration\|TestShutdown)' ./cmd/server` | **35건 통과** |
| 서버 패키지 전체 | `go test -race -json -p=1 -count=1 -timeout=180s ./cmd/server` | **369건 통과** |
| MCP 패키지 전체 | `go test -race -json -count=1 -timeout=180s ./internal/mcp` | **433건 통과** |
| 공통 정적 검사 | `GO_BINARY=/Users/alphagone/sdk/go1.27.1/bin/go GOCACHE=/private/tmp/acs-obs02-go-cache sh ./check-go.sh` | 의존성 검증/빌드·전체 build·vet·gofmt 통과 |

최종 합계는 **802건**이며 실패·건너뜀·race 오류는 0이다. 상위 시험·하위 사례의 pass 이벤트 합계이고 최초 35건은 서버 전체 369건에 포함되므로 중복 합산하지 않았다. 원시 실행 결과는 `/private/tmp/acs-arch06-server-full.json`·`/private/tmp/acs-arch06-mcp.json`에 남았다.

두 배치에서 조립 시 이미 점유된 HTTP 주소를 지정해도 조립은 성공하고 업무 작업자 수는 증가하지 않았다. 조립한 app.handler를 별도 TLS 시험 수신기에 연결하고 같은 DB의 실제 OAuth 자격을 사용해 tools/list의 14종, agent_register·graph_create·node_create·graph_get·context_flow_get을 실행했다. 본문과 질의가 같은 모델·차원·키·TLS 제공자에 도착했고 배치별 소비 루프와 내장 주기 작업 시작을 대조했다. 종료 뒤 DB Ping 거부와 중복 정리 불변, 실제 여섯 파일의 동일 boot·분류·허용 필드 및 토큰/본문/질의/API key 비노출을 확인했다.

진단 수준·임베딩 스키마·검색·인가·MCP 전송 단계의 오류에서 결과 객체 없이 단계별 원인을 반환하고 작업자를 시작하지 않았다. 실패 뒤 같은 슬롯 기록기를 다시 열어 잠금 반환을 확인했으며 모든 시험 DB 정리가 통과했다. 사전 취소는 context.Canceled를 보존했다. 서버 전체 회귀에는 실제 서버/별도 색인 프로세스의 embedded/external 배치와 기존 OAuth·MCP·웹·종료 시험도 포함된다.

초기 빌드의 Bearer 제공자를 authz.Service에서 실제 HTTP Handler로 수정했다. 첫 조립 시험의 작업자 관찰은 스택 문자열 중복을 고루틴 단위로 수정했고, index 진단은 직접 Embed 호출이 아니라 실제 노드 쓰기의 색인 등록으로 확인하도록 준비를 보완했다. 기존 기동 실패 시험에는 새 완전 조립의 필수 입력인 MCP 허용 Origin을 추가해 의도한 HTTP 수신 실패 단계까지 도달하게 했다. 수정 후 관련 시험과 두 패키지 전체가 위 결과로 통과했다.

## 제한과 정합성

- 이번 판정은 의존 조립과 해당 모듈의 실제 요청 표본이다. 전체 HTTP 경로·메서드·공통 보호는 ARCH-07, 모든 운영 실패 단계의 수명·강제 종료는 OPS-05, 전체 MCP 도구·호스트 지원은 MCP-09·TEST-08에서 인수한다. 실제 운영 배포·외부 호스트·Linux 실행·전체 저장소 시험을 수행하지 않았다.
- 패키지 의존의 허용표는 유지했다. 새 파일은 기존 cmd/server와 internal/mcp 경계 안에 있으며 DOX pass에서 새 지속 경계·소유권 이동·환경 키가 없음을 확인했다. 추가 하위 DOX나 부모 색인 갱신은 필요하지 않다.
- 아키텍처의 실제 열한 패키지·MCP 연결·준비/시작/정리 계약과 의존 도식을 정합화했다. Mermaid는 기존 문법·노드·방향의 정적 대조만 수행했으며 별도 렌더링은 수행하지 않았다. 현재 상태와 실행 근거는 계획·진입점·이 검토에 유지한다.
