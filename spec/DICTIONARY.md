# 용어 정리집

## 서비스 용어

| 단어              | 정의                                                                                   | 비고                                                       |
|-------------------|----------------------------------------------------------------------------------------|------------------------------------------------------------|
| 국소 그래프 보기  | 현재 선택한 컨텍스트를 중심으로 지정된 관계 깊이 안의 컨텍스트와 관계를 표시하는 시각화 방식이다. | 탐색 깊이와 표시 규칙은 후속 기획에서 정의한다.            |
| 근거 상태         | 컨텍스트가 원천 사실, 관찰, 경험 또는 의견 중 어떤 성격인지와 이를 뒷받침하는 근거를 나타내는 상태다. | 구분 체계와 신뢰도 정책은 후속 기획에서 정의한다.          |
| 사건 컨텍스트     | 하나의 상호작용이나 경험에서 함께 해석해야 하는 정보를 묶은 컨텍스트 단위다.           | 분할·병합 기준과 다른 컨텍스트와의 중첩 정책은 미정이다.   |
| 시간 유효성       | 컨텍스트나 관계가 사실로 간주되는 시점 또는 기간과 대체 여부를 나타내는 특성이다.      | 속성명, 시간 정밀도와 이력 정책은 후속 기획에서 정의한다.  |
| 에이전트 컨텍스트 | 에이전트가 작업을 해석하거나 이어가기 위해 사용하는 정보 단위와 그 관계를 통칭한다.    | 최소 단위와 필수 속성은 후속 기획에서 정의한다.            |
| 업무 연속성       | 에이전트가 이전 상호작용의 관련 컨텍스트를 활용해 사용자의 작업 상태와 흐름을 이어가는 특성이다. | 평가 시나리오, 지표와 합격 기준은 후속 기획에서 정의한다. |
| 연상 검색         | 시작 컨텍스트에서 그래프 관계를 따라 관련 정보를 찾는 검색 방식이다.                   | 그래프 확장과 순위화 알고리즘은 미정이다.                  |
| 원천 컨텍스트     | 에이전트 상호작용이나 외부 입력에서 수집해 출처와 함께 보존하는 원본 정보다.           | 파생 컨텍스트의 근거가 되며 구체적인 본문 형식은 미정이다. |
| 전역 요약         | 개별 항목이 아니라 관련 컨텍스트 집단이나 전체 그래프에서 도출한 상위 수준의 요약이다. | 제공 여부, 집단 구성과 갱신 정책은 검토가 필요하다.        |
| 전체 그래프 보기  | 사용자가 접근할 수 있는 전체 컨텍스트와 관계를 한 범위에서 표시하는 시각화 방식이다.  | 표시 규모, 필터와 집계 정책은 후속 기획에서 정의한다.      |
| 컨텍스트 관리     | 에이전트 컨텍스트의 저장, 조회, 관계와 수명주기를 다루는 기능 범주다.                  | 구체적인 관리 동작은 미정이다.                             |
| 컨텍스트 관리 연산 | 컨텍스트의 추가, 갱신, 대체, 폐기 또는 유지를 판단하고 적용하는 명시적 동작이다.      | 허용 조건, 실행 주체와 자동화 범위는 미정이다.             |
| 컨텍스트 관계     | 두 컨텍스트 또는 컨텍스트와 관련 주체 사이의 연결이다.                                 | Apache AGE 그래프로 표현하며 관계 유형과 방향은 미정이다.  |
| 컨텍스트 예산     | 한 번의 검색 결과나 모델 입력에 포함할 수 있는 컨텍스트의 허용량이다.                  | 단위, 기본값과 서비스 수준 목표는 후속 기획에서 정의한다.  |
| 컨텍스트 시각화   | 컨텍스트와 그 관계를 사용자가 시각적으로 이해하고 탐색할 수 있도록 표현하는 기능이다. | 표현 형식, 렌더링 주체와 상호작용 방식은 미정이다.         |
| 파생 컨텍스트     | 하나 이상의 원천 컨텍스트에서 생성한 요약, 성찰 또는 구조화된 정보다.                  | 근거 원천과 생성 이력을 추적하며 생성 정책은 미정이다.     |
| 하이브리드 검색   | 직접 후보 검색과 그래프 기반 연상 검색을 조합하는 검색 방식이다.                       | 각 단계의 알고리즘과 결합 방식은 후속 기획에서 정의한다.   |

## 기획 용어

| 단어              | 정의                                                                                               | 비고                                                                |
|-------------------|----------------------------------------------------------------------------------------------------|---------------------------------------------------------------------|
| `AGENTS.md`       | 특정 디렉터리와 그 하위 트리에서 작업자가 따라야 하는 작업 계약 문서다.                            | 루트와 지속 경계별 하위 경로에 둘 수 있다.                          |
| Apache AGE        | PostgreSQL에 그래프 데이터베이스 기능을 제공하는 확장이다.                                         | 이 프로젝트의 컨텍스트 데이터베이스로 사용한다.                     |
| `Child DOX Index` | 부모 `AGENTS.md`가 직접 소유하는 하위 작업 계약 문서의 목록이다.                                   | 하위 `AGENTS.md`를 생성·이동·삭제·이름 변경할 때 갱신한다.          |
| DOX               | 계층형 `AGENTS.md` 문서로 작업 맥락과 계약을 관리하는 프레임워크다.                                | 런타임이나 외부 의존성을 요구하지 않는다.                           |
| Effective Go      | 명확하고 관용적인 Go 코드 작성 방법을 설명하는 공식 Go 문서다.                                     | https://go.dev/doc/effective_go                                     |
| GitHub 이슈       | 명세에 근거한 구현, 조사 또는 결정 작업을 추적하는 GitHub 작업 단위다.                             | 생성·수정 전 사용자 승인이 필요하다.                                |
| GraphRAG          | 지식 그래프와 관련 집단의 요약을 이용해 국소 검색과 전역 질문을 다루는 그래프 기반 RAG 접근법이다. | 현재는 전역 요약의 연구 근거이며 채택 여부는 확정하지 않았다.       |
| MCP               | AI 애플리케이션과 외부 데이터·기능 사이의 컨텍스트 교환을 표준화하는 Model Context Protocol이다.   | 이 서비스의 외부 상호작용에 사용하며 참여자 역할은 미정이다.        |
| Mermaid           | Markdown 코드 블록에서 구조, 흐름과 관계를 표현하는 다이어그램 문법이다.                           | 명세에 확인된 요소와 관계만 표현한다.                               |
| openCypher        | property graph의 패턴과 관계를 질의하는 그래프 질의 언어다.                                        | Apache AGE의 그래프 질의에 사용 가능하며 구체 사용 범위는 미정이다. |
| Pull Request      | 검증된 브랜치 변경을 기본 브랜치에 병합하도록 제안하는 GitHub 협업 단위다.                         | 문서에서는 필요할 때 `PR`로 줄여 쓴다.                              |
| SDD               | 확정된 요구사항을 아키텍처, 인터페이스, 데이터와 처리 흐름으로 구체화한 상세 설계 문서다.          | `spec/service/{서비스 경로}/SDD.md`                                 |
| SRS               | 서비스의 기능·비기능 요구사항, 정책, 제약과 미정 사항을 정의하는 요구사항 명세 문서다.             | `spec/service/{서비스 경로}/SRS.md`                                 |
| 명세 문서         | 서비스 요구사항, 설계, 계약처럼 프로젝트의 지속적인 사실을 기록하는 문서다.                        | `spec/`에 보관한다.                                                 |
| 스킬              | 특정 작업의 입력, 절차, 승인 경계와 검증 기준을 정의하는 프로젝트 로컬 작업 지침이다.              | `.agents/skills/{스킬명}/SKILL.md`                                  |
| 용어 정리집       | 프로젝트에서 쓰는 서비스 용어와 기획 용어의 표준 표기와 정의를 모은 문서다.                        | `spec/DICTIONARY.md`                                                |
| 요구사항 ID       | 요구사항과 설계·이슈 간 추적성을 유지하기 위한 고유 식별자다.                                      | 기존 ID는 상태가 바뀌어도 재번호화하지 않는다.                      |
| 작업 로그         | 사용자 명령, 처리 결과와 변경 내역을 날짜별로 기록하는 비공개 운영 문서다.                         | `.personal/log/YYYY-MM-DD 작업 내용.md`                             |
| 프로젝트 이력     | 서비스 요청 기록과 제안을 날짜별로 요약한 공개 가능한 명세 작업 이력이다.                          | `spec/history/`에 보관하며 `.personal/` 내용은 포함하지 않는다.     |
