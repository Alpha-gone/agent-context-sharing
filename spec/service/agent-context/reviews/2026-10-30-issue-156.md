# #156 진단 로그 행의 판 호환성

- 대상: [이슈 #156](https://github.com/Alpha-gone/agent-context-sharing/issues/156).
- 기준: `dev`의 `f453c29`, 작업 브랜치 `fix/156-diagnostic-log-compatibility`.

## 변경과 계약

과거 로그의 보존 검사를 새 이벤트의 수락 검사에서 분리했다. 기존 행은 UTC time·파일과 일치하는 kind·디렉터리와 일치하는 instance_id·UUIDv7 boot_id를 가진 완전한 JSON 객체로 검사한다. 미지 단계·결과·원인·수준 코드와 확장 필드는 현재 판의 이벤트 목록으로 재해석하지 않는다. 혼합 파일의 유효 행은 공백까지 포함한 원래 바이트를 그대로 보존한다.

새 이벤트의 Event.Validate·인코딩·안전 필드·흐름 검증은 유지한다. 파일 권한·잠금·크기·보존·부분 행 격리 정책도 유지한다. JSON 구문 오류, 중복 키, 잘못된 UTF-8, 안정 외피의 누락/형식 오류·종류/인스턴스 불일치와 16 KiB 초과 행은 계속 log_invalid다. 손상된 완전 행을 만료로 보아 삭제하지 않는다.

[관측성 정본](../sdd/observability.md#회전보존과-총상한)에 경계를 명시했다. 안정 외피나 여섯 파일 종류 자체를 바꾸는 이행은 별도이며, 이 변경이 없는 과거 이미지의 엄격한 독자까지 소급 수정하지는 않는다. 시험은 다른 판 형식의 합성 행과 현재 시험 바이너리의 기동이며, 실제 과거 배포 이미지 두 개를 교체한 인수로 확대하지 않는다.

## 공급자 근거

Go 1.27.1 SDK `src/encoding/json/v2/doc.go`와 options 문서에서 구조체의 미지 멤버를 기본적으로 무시하고, 잘못된 UTF-8·중복 이름은 기본 거부함을 확인했다. 최소 외피 구조체로 역직렬화하되 JSON 구문/UTF-8/중복 이름 허용 옵션은 사용하지 않는다. 중첩 미지 객체의 중복 키와 미지 필드의 잘못된 UTF-8도 실제 회귀로 확인했다.

## 검증

- 원본 storage_unix.go를 Go overlay로 대조한 6개 사례는 모두 log_invalid로 실패했다. 자기/이전 슬롯의 활성·회전 파일 4개와 혼합 보존·부분 행 꼬리 복구 2개다.
- 수정 후 위 사례는 기동·정상 이벤트 추가·이전 행의 원래 바이트 보존을 통과했다. 만료된 다른 판 행은 제거하고 유효 행은 원문 그대로 유지하며, 새 이벤트의 미지 원인 코드는 계속 거부한다.
- 손상 회귀 14개는 JSON 구문·null/배열·필수 시각·UTC·boot 식별자·종류·인스턴스·루트/중첩 중복 키·UTF-8·크기 오류를 거부하고 원본 파일을 유지했다.
- macOS `go test -race -count=1 -json ./internal/diagnostic`: 195건 통과, 23.901초. DB 실행권 시험 1건은 TEST_DATABASE_URL 미설정으로 건너뛰었다.
- `GO_BINARY=.../go1.27.1/bin/go sh internal/diagnostic/test-linux.sh`: 기존 고정 arm64 이미지와 격리 볼륨에서 모듈 203건, 읽기 전용 마운트 1건·컨테이너 first/restart/replacement 각 1건 통과. DB 실행권 1건과 자식 helper 직접 실행 1건은 건너뜀이다. helper는 기존 ENOSPC·EMFILE 부모 사례에서 실행했다.
- Go 1.27.1 `go build ./...`, `go vet ./...`, `gofmt -l .`, `git diff --check` 통과. 건수는 하위 사례를 포함한다.

예비 race 실행에서 시험의 bytes.Buffer를 비동기 stderr 작업자 종료 전에 읽는 경합을 발견해, 기존 출력 종료 대기 도우미로 동기화한 뒤 전체 인수를 다시 실행했다. 최종 결과 JSON은 `/private/tmp/acs-156-diagnostic.json`, Linux 결과는 `acs-obs08-results-eQu6vm`, 원본 대조 결과는 `/private/tmp/acs-156-original.txt`에 보관했다. 격리 스크립트는 자신이 만든 컨테이너·볼륨을 정리했다.

공개 구성·스키마·소유권·DOX 구조와 색인은 바뀌지 않았다. 과거 리뷰의 당시 인수 상태는 보존했고, 개인 IDE 파일 두 개는 제외했다.
