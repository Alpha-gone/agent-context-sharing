# #150 기동 색인 보충과 명시적 재색인 분리

- 기준: 2026-10-30 KST, `dev`의 `0f2138b`에서 분기한 `fix/150-startup-index-registration`.
- 대상: [이슈 #150](https://github.com/Alpha-gone/agent-context-sharing/issues/150), [재색인 계약](../sdd/indexing.md#재색인), [시험 계층](../sdd/testing.md#테스트-계층).

## 재현과 원인

[신규 반복 기동 시험](../../../../internal/store/startup_index_registration_test.go)은 vector·halfvec 각각에서 현재 모델·옛 모델·벡터 누락·폐기 컨텍스트와 failed·백오프·실제 확보한 리스 작업을 같은 그래프에 준비한다.

수정 전 두 형식 모두 첫 `ReindexOutdatedEmbeddings` 호출이 failed의 시도 5회를 0으로 바꾸고, 백오프·리스·등록 세대도 초기화하여 실패했다. 옛 모델이 남은 그래프를 선택한 뒤 `ReindexGraph`로 활성 대상 전체를 다시 upsert하는 것이 원인이었다. 기존 벡터는 실패 뒤에도 남으므로 반복 기동에서도 같은 문제가 발생한다.

## 수정

- 기동 후보는 현재 대상인 활성 컨텍스트 중 현재 모델 임베딩과 작업 행이 모두 없는 대상으로 제한한다. 그래프 잠금 뒤 같은 조건을 다시 확인한다.
- 기동 등록은 삽입 충돌에서도 기존 작업을 변경하지 않는다. 새 행이 없으면 새 등록 진단도 만들지 않는다. 작업 ID·시도·상태·실패 사유·세대·백오프·리스·상관 ID를 보존한다.
- 명시적 `ReindexGraph`는 기존 전체 재등록·실패 초기화 계약을 유지한다. 같은 트랜잭션 조립과 그래프 선행 잠금을 공유하며, 원천 제외 시 작업→임베딩 정리와 내용 판 갱신도 유지한다.
- 기존 모델 격리 시험의 실패 초기화 표본은 명시적 재색인을 호출하도록 정합화했다. 기동 보존은 별도 신규 시험에서 직접 검증한다.
- PostgreSQL 삽입 충돌·반환 행 근거는 [reference.md](../reference.md#2026-10-30-150-기동-색인-보충)에 연결했다.

## 검증

Go 1.27.1, 고정 PostgreSQL/AGE/pgvector 전용 컨테이너와 `TEST_DATABASE_REQUIRED=1`·`TEST_DATABASE_URL`을 사용했다.

```sh
go test -race -count=1 -run '^TestStartupIndexRegistrationPreservesExistingWorkIntegration$' ./internal/store
go test -race -count=1 -json -run '^Test(StartupIndexRegistration|Reindex)' ./internal/store
go test -race -count=1 -json -timeout=15m ./internal/store ./internal/index
go build ./...
go vet ./...
gofmt -l .
```

수정 전 신규 두 형식 사례가 모두 상태 초기화로 실패했다. 시험 전용 DB에 정식 마이그레이션을 준비한 뒤 신규·기존 재색인 계약 32건이 9.357초에 통과했다.

신규 시험은 두 동시 기동을 세 차례 반복하고 기존 작업 행 전체와 보충 후 상태가 그대로인지 비교한다. 현재 모델·폐기 대상은 등록하지 않고 누락 두 대상만 보충하는지, 기동 전 확보분이 실제 결과를 공개하는지, 영구 실패가 남아도 완료 컨텍스트를 다시 등록하지 않는지 확인한다. 명시적 재색인은 실패·백오프를 초기화해야 한다.

필터 없는 전체 race 실행에서 `store` **1,682건(최상위 375건, 433.011초)**·`index` **119건(최상위 28건, 4.882초)**이 실패·건너뜀 없이 통과했다. build·vet·gofmt·문서 링크/앵커·diff 검사와 독립 읽기 전용 검토도 통과했다.

시험별 DB 잔류 없음과 생성 ID를 확인한 뒤 이번 작업의 컨테이너·익명 볼륨만 정리하고 기존 세 컨테이너·개인 IDE 파일은 보존했다. 기동 보충 실패의 로그 후 단발 시도 정책과 실제 외부 제공자 호출은 이번 완료 조건 밖으로 유지했다. 스키마·공개 구성·DOX 소유권과 구조는 바뀌지 않았다.
