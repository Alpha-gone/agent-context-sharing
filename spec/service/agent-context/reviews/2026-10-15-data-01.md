# DATA-01 논리 모델·물리 스키마 대응 검토

## 범위와 선행 조건

2026-10-15에 [DATA-01](../development-plan/data.md#data-01)의 DDL·property·제약·인덱스 대응을 완료했다. 시작 커밋은 PR #134가 병합된 `d7af8e4`, 브랜치는 `feat/data-schema-contract`다. 원격을 fetch하여 기존 feature upstream의 ahead/behind가 0/0이고 `origin/dev`에 해당 PR이 병합되었음을 확인한 뒤 새 브랜치를 만들었다. 선행 ARCH-02·PERM-01은 완료 상태다.

기준은 [SRS 모델](../SRS.md#컨텍스트-모델)·[그래프 속성](../SRS.md#컨텍스트-그래프-속성)·[관계 속성](../SRS.md#관계-속성), [데이터 SDD](../sdd/data.md), [OAuth 저장](../sdd/authentication.md#oauth-저장-모델과-원자적-전이), [행위자 등록](../sdd/mcp.md#공통-행위자도구쓰기-안전성)과 수명주기·플랜·색인 계약이다. 기존 SQL은 목표와의 차이를 찾는 입력으로만 사용했고 신규 구현·DB 완료 근거로 승계하지 않았다.

## 산출물과 계약 대응

- 데이터 SDD의 [DDL 대응](../sdd/data.md#신규-구현의-ddl-대응)에 기존 업무 13종과 목표 추가 4종의 SQL 타입·NULL·키·참조·행 제약·조회 조건을 연결했다. `context_embedding_hot/cold` 두 자식과 도구의 적용 이력은 업무 테이블 17종에 중복 합산하지 않는다.
- [논리 속성 대응](../sdd/data.md#논리-속성과-검증-위치)은 공통 9개와 계층별 15개, 관계 12개를 모두 포함한다. 그래프 10개·계정 4개는 관계형 열에 대응한다. `source_ref`의 두 하위 필드는 두 property에 보존하고 세 참조는 간선으로만 저장한다. 단일 Context·일곱 간선 label·RELATES_TO의 정규 방향·관계의 판/시간 유효성 부재를 유지했다.
- 판·저장량의 SQL bigint와 모델 int64를 맞추고 공개 `version`, 내부 `content_revision`, 유예 만료와 문자 누계를 분리했다. FK·CHECK로 보장할 수 없는 그래프 격리·참조 존재·소유자·관계 순환·동시 누계는 저장소의 조회·잠금·트랜잭션 책임으로 남겼다.
- [OAuth 열](../sdd/authentication.md#oauth-저장-열)과 [등록 열](../sdd/mcp.md#등록-저장-열)을 각 정본에서 구체화했다. 해시 길이·소비 쌍 NULL·계열 FK·자식 우선 정리와 폐기 행까지의 등록 유일성을 명시했다. 계정당 활성 등록 상한·인증 수명·회전·보존 종료 판정은 해당 저장 연산이 담당한다.
- 기존 인덱스 표와 OAuth/등록 목록·만료 인덱스를 연결했다. 실제 인덱스 생성은 DATA-02, 실행 계획·통계·규모 판정은 DATA-05에서 수행한다. 부모 파티션의 context_id 단독 전역 UNIQUE를 가정하지 않는다.

## 후속 DDL 검사 표본

아래는 DATA-02~07·MCP·인증 모듈 시험에서 구현할 관찰 표본이다. 이번에는 문서 대응과 표본의 책임 분류를 검증했으며 실제 DB에서 실행한 시험 결과가 아니다. 유효 표본과 위반 표본을 각각 독립 트랜잭션으로 준비하고, 거부 후 부분 적용 부재를 확인해야 한다.

| 다른 graph_id에 같은 그래프 이름 | 둘 다 저장 가능 | DB, DATA-02 |
| 그래프 version/content_revision 0·stored_chars 음수 | CHECK 위반 | DB, DATA-02 |
| 같은 팀 구성원·같은 graph/종류/대상 등급 행 | 복합 PK 위반 | DB, DATA-02 |
| 없는 계정·삭제 팀·소유자 부재가 되는 변경 | 해당 존재·활성·소유자 검증에서 거부·롤백 | 저장소, DATA-04·PERM-07 |

DDL 적용 뒤에는 다음 읽기 전용 카탈로그 조회로 실제 타입·NULL·제약·인덱스를 위 정본과 대조한다. 조회 성공만으로 제약 위반·경합·격리 시험을 대신하지 않는다. 아래 SQL은 검사 표본이며 이번에 DB 접속으로 실행하지 않았다.

```sql
SELECT table_name, column_name, data_type, is_nullable
FROM information_schema.columns
WHERE table_schema = 'public'
ORDER BY table_name, ordinal_position;

SELECT conrelid::regclass AS target, conname, contype,
       pg_get_constraintdef(oid) AS definition
FROM pg_constraint
WHERE connamespace = 'public'::regnamespace
ORDER BY conrelid::regclass::text, conname;

SELECT schemaname, tablename, indexname, indexdef
FROM pg_indexes
WHERE schemaname = 'public'
ORDER BY tablename, indexname;
```

AGE label의 실제 graph schema에서는 Context와 일곱 label 존재, property·간선 방향·내부 graphid의 UUID 매핑을 별도로 확인한다. public 카탈로그 조회만으로 AGE 속성·그래프 격리를 통과 처리하지 않는다.

## 기존 SQL과의 차이·검증 범위

기존 `001_init.sql`·`009_remove_legacy_connection.sql`은 수정하지 않았다. 후속 새 번호에는 OAuth/등록 4종·키·인덱스, 멱등성 키 uuid→text, 예약 결과 NULL 허용과 32바이트 지문/키 제약, 판·빈도 카운터 bigint 대응과 누락 양수 CHECK를 반영해야 한다. 기존 code/DPoP 저장은 009 제거 대상이며 목표 OAuth 저장으로 간주하지 않는다. `index_task.correlation_id`는 기존 001에 이미 있어 중복 추가하지 않고 최종 형상을 대조한다. 기존 키·감사·만료·적용 이력과 checksum을 보존하는 구체 변경은 DATA-02에서 검증한다.

문서 검증은 SRS 50개 모델 속성, 17개 테이블·Context/간선 사상, 184개 요구사항과 추적 행, 124개 작업·선행 링크·완료 상태, Markdown 링크/앵커·표/코드 블록·공백을 대조한다. Go·DDL·실행기 변경이 없어 Go build/vet/test·DB·Compose·외부 API·호스트 시험은 실행하지 않았다. 문서 검증을 DB 제약 시험이나 기능 구현 완료로 표현하지 않는다.

새 문서 검증 결과는 다음과 같다.

- 변경 Markdown 8개, 로컬 링크·앵커 243개, 표 44개와 코드 블록 구조를 확인했다.
- SRS 모델 속성 50개와 source_ref 하위 필드 2개, 목표 테이블 17종·정점 label 1종·간선 label 7종의 대응을 확인했다.
- 요구사항 184개와 두 추적표의 중복·누락 없음, 작업 124개·완료 7개·미착수 117개와 선행 링크의 존재·순환 없음을 확인했다.
- 기존 SRS·용어집·SDD 진입점·설계 추적표·001/009 SQL의 작업 트리 원문이 시작 커밋과 같고 diff 공백 검사도 통과했다.
- 위 23개 검사 표본과 카탈로그 SQL 3개는 후속 실행용이다. 이번 결과에 DB 실행 통과 수를 합산하지 않았다.

## 완료 판정과 DOX pass

DATA-01의 스키마 대응·검증 책임·검사 표본 산출물을 충족했다. 완료 작업은 기존 여섯 개와 DATA-01, 총 7개이고 나머지 117개는 미착수다. 다음은 DATA-02의 미완료 선행인 [OPS-01](../development-plan/operations.md#ops-01)이다. 이 단계에서도 운영 자원·기존 DB를 임의로 재생성하지 않는다.

데이터·인증·MCP의 정본 소유권은 그대로이며 열 정의를 상대 문서에 중복하지 않고 링크했다. 루트·internal·migrations·spec DOX와 Child DOX Index, SRS·용어집·SDD 진입점·설계 추적표는 책임·요구사항·진입 경로가 같아 유지했다. 공개 서비스 지원 상태도 승격하지 않았다. 기존 Compose·IDE 변경을 보존했으며 커밋은 별도 요청 시 수행한다.
