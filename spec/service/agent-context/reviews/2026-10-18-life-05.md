## 확인 사항과 구현

| ID | 영향도 | 확인한 차이 | 처리와 새 증거 |
|---|---|---|---|
| LIFE05-R1 | 중간 | 의미 후보는 기존 관계를 조회 상한 안에 포함해, 같은 상위 후보만 만날 경우 남은 유효 후보가 다음 방아쇠에서도 제안되지 않았다. | proposed/confirmed/discarded 정체성을 SQL의 LIMIT 전에 제외한다. vector·halfvec에서 상위 확정/폐기 관계를 보존하면서 다음 유효 후보를 상한 1개씩 제안하는지 확인했다. |

| LIFE05-R3 | 중간 | 사건 저장 후 제안 실패 로그에 임의 오류 객체가 들어갔다. | 기존 색인 경계와 같은 stage/result/reason_code의 고정 지표만 남긴다. 실제 후보 쓰기 직전에 pgx 질의 취소를 주입해 사건·색인 큐가 커밋된 상태로 남고 부분 간선·오류 원문 없이 실패 지표가 기록되는지 확인했다. |

위 차이는 코드와 계약을 대조해 보완한 뒤 새 모듈 시험으로 검증했다. 변경 전 별도 실행에서 제품 결함을 재현했다고 보고하지 않는다. 기존 저장 커밋 후 신호와 색인 성공 후 콜백을 유지했으며 새 주기 작업·전송 도구·설정은 추가하지 않았다. 이번 범위의 미해결 발견 사항은 없다.

## 인수 범위

- 시간 신호: 종료/시작 접점, 인접 임계값 경계·초과, 겹침과 진행 중 사건을 양쪽 입력 순서로 대조한다. 간격이 짧은 후보부터 신호 상한을 적용하고 이미 제안·확정·폐기된 정체성은 중복 생성하지 않는다.
- 구성원 신호: 진부분집합 중 포함되는 구성원이 많은 후보부터 제안한다. 구성원이 같고 순서만 다른 사건은 part_of 후보가 아니다. causes는 자동 제안하지 않는다.
- 의미 신호: vector·halfvec에서 같은 모델·같은 그래프·활성 사건만 비교한다. 본인·파생·삭제 사건·다른 그래프·이전 모델·임계값 미달 후보와 대상 벡터가 없는 모델을 제외한다. 기존 관계가 남은 후보의 상한을 차지하지 않는다.
- 판단과 보존: 기존 ID·상태·제안 시각을 보존한다. 만료된 proposed만 정리한 뒤 본문만 갱신하면 재제안하지 않으며, 다음 시간 범위 갱신은 새 ID로 유효 정체성을 다시 제안한다. confirmed/discarded는 유지되고 proposed는 관계 필터를 지정한 홉 탐색에 포함되지 않는다.
- 커밋과 실패: 바깥 멱등성 트랜잭션 전에는 후보가 없고 성공 커밋 뒤 생성된다. 롤백·지연 커밋 실패는 후보를 남기지 않으며 같은 키의 재생도 신호를 반복하지 않는다. 후보 실패는 사건·큐를 되돌리지 않고 다음 실행에서 복구된다.
- 색인 경계: 실제 작업 큐와 로컬 TLS 제공자 대역으로 성공 공개 뒤 별도 연결에서 작업 삭제·벡터 공개를 확인한다. 원천·제공자 실패·무효 세대는 의미 신호를 실행하지 않으며 제안 실패도 색인 성공을 바꾸지 않는다. 계정 준비 보완의 영향 범위인 재색인 진행률 시험도 통과했다.
- 경합과 자원: 그래프 행의 실제 차단을 확인한 뒤 신호 입력 변경·선행 확정·취소를 수행한다. 취소 원인과 4연결 풀·예약 반환을 확인한다. 전체 수명주기의 동시성 인수는 LIFE-09 범위다.

## 실행 결과

- Go 1.27.1 darwin/arm64. 고정 Dockerfile의 전용 이미지 `agent-context-life05:local`, 컨테이너 `acs-life05`, 볼륨 `acs-life05-data`, 소유 라벨 `agent-context.task=life05`, loopback 55666과 합성 계정만 사용했다. 기존 개발 DB에는 접속하지 않았다.
- 실제 PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6을 확인했다. 전용 DB는 vector/128·all_layers이며 정식 001/009/010/011/012/013 6개를 적용했다. 별도 vector/8·halfvec/8 DB도 정식 마이그레이션으로 생성하고 시험이 정리했다.
- 최종 고유 시험·하위 시험 **35건 통과**: store 27건(최상위 10·하위 17), index 8건(최상위 3·하위 5). `-race -count=1 -p 1`·`TEST_DATABASE_REQUIRED=1`로 실행했으며 최종 실패·건너뜀은 0이다. 반복 실행은 고유 수에 더하지 않았다.
- 최초 store 명령은 합성 벡터 준비에서 파티션 부모에 없는 전역 ON CONFLICT 키를 가정한 네 하위 시험과, AGE 간선 쓰기를 의도대로 차단하지 못한 SQL 트리거 시험 때문에 실패했다. 중복 삽입이 없는 단순 INSERT와 실제 pgx 후보 질의 취소 주입으로 고친 뒤 같은 모듈 범위 27건을 모두 재검증했다.
