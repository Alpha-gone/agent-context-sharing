# EVAL-11 임베딩 순위·관계/전역 임계값 비교 검토

## 범위와 설계

`FR-AGENT_CONTEXT-162`·EVAL-11의 독립 임베딩 비교 모드를 구현했다. `cmd/eval -embedding-comparison 입력.json -out 결과.json`으로 공통 원천/파생/사건·질의·정답·예산·조회 시각을 고정하고 구성별 모델 식별자·전체 재색인·임계값 조정·최종 검색을 연결한다. 실행 환경과 데이터는 비공개 입력으로 고정하고 결과에는 비식별 코드·점수·지표만 남긴다. manifest의 사전 검사 모드/역할은 `embeddings`/`embedding_comparison`이며 checksum 실물 연결과 최종 공개는 EVAL-13의 범위다.

- 모델·차원·표현 중 정확히 한 축만 바꾼다. 현재 Gemini 제공자가 허용하는 단일 모델·128~3072차원과 vector/halfvec만 받아들이며, HNSW 저장 타입 상한도 유지한다. 다른 모델·bit·다중 축·동일 구성은 접속 전에 거부한다. 같은 제공자 endpoint를 강제한다. 현재 지원 모델이 하나이므로 서로 다른 모델의 실제 비교는 제공자 지원 확장 뒤의 범위다.
- 구성별 사전 준비 DB의 실제 임베딩 스키마를 모두 확인한 뒤 첫 그래프를 적재한다. 실행기는 스키마·운영 모델을 변경하지 않는다. 조정/최종의 독립 단위와 원천 locator 중복을 거부하고 사건 anchor·모든 상대 사건의 관련성, 모든 질의의 전역 전환 필요 여부를 완전 주석한다.
- 두 단계에서 구성·표본·회차별 새 그래프를 만들고 색인 준비를 확인한다. 단계별 각 10회·회차 안의 구성 순환을 적용한다. 관계는 저장된 사건 벡터의 코사인 점수를 읽고 임계값/상한으로 선별하며 관계를 생성하지 않는다. 실제 제안 연산의 거리·UUID 동률 순서와 별도 DB 시험으로 대조한다.
- 구성마다 조정 표본의 관계 F1 최대·전역 균형 오판율 최소 하한을 선택한다. 동률은 큰 하한이며 최종 표본의 점수/정답은 선택에 사용하지 않는다. 최종 그래프에서 선택한 전역 하한을 실제 검색 서비스에 적용하고 순위·필수 근거·문자/지연을 측정한다. 전역 전환 필요 판정은 keyword 존재 또는 semantic 하한 통과의 현행 규칙과 같다. 전역 요약의 존재/반환 성공과 전환 필요 판정을 혼동하지 않는다.
- 반복→표본→독립 단위의 평균과 Student t 대응 구간을 사용한다. 관계 정밀도·재현율·후보 수와 전역 오통과/오탈락을 순위 지표와 분리한다. 분모 없음·표본 부족은 -1/보류이며 최종 품질 악화는 거부한다. 준비/검색 호출·저장량·지연은 실측하고 금액은 미측정 -1이다. 실제 자료에서 품질 비악화와 유의한 검색 지연 개선이 확인되어야 후보이며 운영 기본 활성화는 항상 false다.

## 모듈 검증

최종 코드의 평가 실행기 전체 **707건**(최상위 **169건**)이 race·필수 DB·240초 제한에서 **209.207초**에 실패·건너뜀 없이 통과했다. 실제 두 축 비교 CLI는 20.170초, 관계 선별/실제 제안 top-1 대조는 0.170초다. 예비 모듈 112건(최상위 7건)·16.123초와 중복 실행을 고유 수에 더하지 않았다. 최종 전체 회귀 뒤 코드 변경은 없다.

```sh
TEST_DATABASE_URL='<격리 vector(768) DB>' \
TEST_EMBEDDING_SMALL_URL='<격리 vector(128) DB>' \
TEST_EMBEDDING_HALF_URL='<격리 halfvec(768) DB>' \
TEST_DATABASE_REQUIRED=1 \
/Users/alphagone/sdk/go1.27.1/bin/go test -race -count=1 -json -timeout=240s ./cmd/eval
GO_BINARY=/Users/alphagone/sdk/go1.27.1/bin/go sh check-go.sh
```

전체 의존성·build·vet·gofmt 정적 검사도 통과했다. 기록은 `/private/tmp/acs-eval11-eval-final.json`·`/private/tmp/acs-eval11-static-final.log`에 남겼다. 초기 제한 환경의 기본 Go 캐시 쓰기 거부는 허용된 도구 실행으로 복구했으며 시험 실패나 코드 결함이 아니었다.

## 결과와 제한

합성 HTTPS 제공자·PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6에서 768→128차원과 vector(768)→halfvec(768)를 별도 비교한다. 두 성공 CLI는 각각 조정/최종 40개 그래프·320회 HTTP를 실제 실행하며 후보 저장량 감소를 대조한다. 기본 관계 하한 0.3과 128차원 후보 하한 0.2는 각각 조정되어 선택된다. 같은 모델 이름이더라도 차원/표현을 포함한 model_id와 DB 스키마를 구분한다. 입력·원문·locator·API 키·DB URL은 보고서에 노출하지 않는다.

이 검증은 비교 실행기와 분모·통계·격리의 모듈 인수다. 공개 코퍼스의 실효 품질, 실제 유료 제공자의 비용·지연 개선, 여러 실제 임베딩 모델과 운영 기본값의 최종 채택을 입증하지 않는다. 실제 금액/총비용 산정은 EVAL-12, manifest 자동 적용·최종 공개/채택은 EVAL-13에 남긴다. halfvec의 합성 비교는 운영 압축 채택을 뜻하지 않는다.


## 정리·문서·잔여 작업

합성 클러스터의 잔여 클라이언트 연결 **0개**를 확인한 뒤 직접 만든 `acs-eval11-db` 컨테이너와 익명 볼륨만 제거했다. 기존 개발 DB·WAL 정리 컨테이너는 유지했다. 해당 DB에서 관찰한 벡터 열의 행당 크기는 vector(768) 3,076바이트, vector(128) 520바이트, halfvec(768) 1,544바이트다. 이는 실제 `pg_column_size` 측정이며 논리적 벡터 크기 공식이나 인덱스/전체 DB 저장량이 아니다.
