# #131 MCP 입력 스키마의 필드 설명 보강

## 현황 확인

이슈 작성(2026-10-11) 이후 MCP 도구 정의가 `internal/mcp/tool_schemas.go`의 명시 JSON Schema로 바뀌었다. 현재 공개 도구 14종(이슈는 13종 기준)의 입력 필드에는 모두 `description`이 있었다. 이슈가 가리킨 `internal/mcp/schema.go`·`transport.go`와 `client/` 공유 계약은 호스트 직접 연결 전환으로 저장소에 없다. 클라이언트의 도구 필터링·`created_by_agent` 주입 경계는 등록 `agent_id` 입력으로 대체되었으므로, 서버 `tools/list`의 설명 전달만 검증 대상으로 남았다.

남은 부족은 설명의 정확성·완전성이었다.

- `layer`가 계층별 필수 필드를 나열하지 않았다.
- 계층 전용 필드들이 어느 계층에 속하는지 밝히지 않았다.
- `derived_from`·`supersedes_context_id`·`member_refs`의 역할 차이와 사건 관계와의 구분이 약했다.
- `relation_type`에 유형별 방향이 없었다.
- `node_get`의 `direction` 기준·`hops` 단위·`traversal_filter` 생략 시 기본값이 빠져 있었다.
- 사건 시간과 원천 구성원 발생 시각의 조건이 모호했다.

## 결정과 변경

- `layer`에 source·derived·event별 필수 필드와 다른 계층 필드 거부를 적었다. 각 계층 전용 필드는 "source/derived/event 전용 필수·선택 필드"로 시작한다. 이는 기존 조건부 스키마(`allOf`)의 필수·금지 규칙과 같다.
- `derived_from`은 근거 참조이며 사건 관계가 아님을, `supersedes_context_id`는 같은 계열 이전 파생의 대체이며 `derived_from`과 별개임을 적었다. `member_refs`에는 사건이 묶는 원천·파생 구성원이며 사건 사이 연결은 `relation_confirm`이라고 적었다([SRS 사건 관계](../SRS.md#사건-관계)).
- `relation_type`에 precedes(앞선→뒤따르는)·causes(원인→결과)·part_of(부분→전체)·relates_to(방향 없음·순서 정규화)를 적었다. 끝점 조건은 #130에서 보완했다.
- `node_get`에는 다음을 적었다([SRS 홉 범위 조회](../SRS.md#홉-범위-조회)·참조 간선 방향).
  - `hops`의 단위는 간선 수다.
  - `direction`은 저장된 간선 방향 기준이다. out은 파생→근거, 새 파생→이전 파생, 사건→구성원, 관계 시작→대상 방향이다.
  - `traversal_filter`를 생략하거나 빈 배열로 주면 7종 모두를 탐색한다.
- 사건 생성·갱신의 `event_start`에는 원천 구성원의 `occurred_at`이 사건 범위 안이어야 하고 파생 구성원은 검사하지 않는다고 적었다([SRS 사건 모델](../SRS.md)의 범위 검증).
- 호출 예시는 넣지 않았다. 이슈는 예시의 위치·형식을 호스트 지원 확인 뒤 정하도록 했고, 이번 작업에서 호스트의 스키마 `examples` 전달은 확인하지 않았다. 완료 조건의 구분은 필드 설명으로 충족한다.
- 입력 필드·필수값·열거값·검증·오류 계약은 바꾸지 않았다. 두 도구 스냅샷의 차이는 `description` 문자열뿐이다. [MCP 설계](../sdd/mcp.md)의 도구 설명 절을 갱신했으며 요구사항·추적표·DOX의 소유권과 구성은 바뀌지 않아 유지했다.

## 검증

- 두 스냅샷(`internal/mcp/testdata/tools.json`·`cmd/server/testdata/mcp09_contract.json`)을 생성 절차로 갱신했다. 갱신 변수 없이 다시 실행하여 일치를 확인했고, 변경 줄이 모두 `description`임을 diff로 확인했다. 조립 서버 계약 시험은 실제 `tools/list` 응답으로 설명 전달을 대조한다.
- Go 1.27.1, 작업 전용 합성 DB 컨테이너(정식 마이그레이션 적용), `TEST_DATABASE_REQUIRED=1`, `-p 1`의 필터 없는 `internal/mcp`·`cmd/server` 실행: 1250건 통과, 실패 0건. 건너뜀 21건은 서버의 물리 복구·전환·Codex CLI 실제 환경 인수이며 통과로 보고하지 않는다. 대표 원천·파생·사건 생성과 관계 확정 입력의 기존 스키마 검증 시험이 포함된다.
- `check-go.sh`의 의존성·`go build`·`go vet`·`gofmt` 검사, 변경 Markdown의 링크·앵커를 확인했다. 검증 후 소유 라벨의 합성 컨테이너와 익명 볼륨을 제거했다.
- #130의 결함 처리는 [#130 검토](2026-10-31-issue-130.md)에 따로 있다. 이 변경은 그 원인 판정이나 수정을 대신하지 않는다. 실제 호스트에서 설명이 모델에 전달되는 방식은 확인하지 않았다.
