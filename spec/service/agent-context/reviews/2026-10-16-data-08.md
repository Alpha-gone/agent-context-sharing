## 구현과 검토

- 접근 기록은 현재 문장에서 같은 그래프의 실제 활성 정점과 활성 그래프를 확인한다. 읽기 스냅숏 뒤 이미 커밋된 폐기 대상·다른 그래프·고아 정점을 승격하지 않는다. 기존 접근 시각 갱신·cold→hot 이동의 단일 문장과 정렬·SKIP LOCKED를 유지했다.
- 접근 차단 그래프·폐기 컨텍스트·미사용 활성 컨텍스트의 세 cold 이동 경로도 `context_id` 순서로 임베딩만 잠그고 잠긴 행은 건너뛴다. 다른 테이블을 잠금 대상으로 추가하지 않았다. 그래프 목록 이후 복구된 그래프는 현재 문장의 접근 차단 검사로 이동 대상에서 제외한다.
- 미사용 기간은 기준 시각보다 엄격하게 이전인 행만 이동한다. 기준과 같은 행·이후 행은 hot에 남는다. 기본 플랜 0은 기존대로 활성 임베딩을 이동하지 않는다.
- 기존 읽기 종료→연결 반환→접근 기록→자리 반환 순서를 유지했다. 접근 기록에만 `40001` 한 번 재시도를 적용하고 같은 ID·조회 시각을 새 자동 커밋 문장에 전달한다. 두 번째 실패·다른 오류·취소를 호출자에게 전파한다.
- 주기 cold 이동은 `40001`을 호출자에게 반환한다. 접근 기록의 재시도를 주기 이동까지 확대하거나 오류를 성공 이동 수로 감추지 않았다. 충돌한 행은 보존되어 다음 회차의 대상이 된다.
- AGE 정점·본문·간선, SQL 마이그레이션·적용 이력·의존성은 변경하지 않았다.

## 환경과 실행 결과

- Go 1.27.1 darwin/arm64, PostgreSQL 18.6 / Apache AGE 1.8.0 / pgvector 0.8.6 / Linux aarch64.
- 고정 Dockerfile로 DATA-08 전용 이미지·컨테이너·새 볼륨을 만들고 loopback 동적 포트만 공개했다. 기존 DB·볼륨·환경 파일과 외부 제공자를 사용하지 않았다.
- 최종 신규 시험은 기존 격리 도우미로 시험별 임시 DB 14개에 정식 001·009·010·011을 적용·재실행했다. 각 저장소 풀은 4연결로 제한했다. 기존 관련 회귀는 별도로 정식 적용한 전용 기본 DB에서 수행했다.
- **고유 모듈·하위 시험 37건 통과**: 신규 17건·관련 회귀 20건, 최상위 16개·하위 21개. `-race -count=1`, `TEST_DATABASE_REQUIRED=1`을 적용했으며 최종 실패·건너뜀은 0이다.
- 기간 경계의 앞·같음·뒤를 마이크로초로 구분하고 cold 직접 의미 검색→hot 되읽기를 확인했다. 이동 전후 AGE 원문·그래프 행 지문을 대조했다. 기본값 0·접근 차단 그래프·폐기 컨텍스트 이동도 관련 회귀에서 다시 검증했다.
- 스냅숏에서 활성 정점을 읽은 뒤 별도 연결의 컨텍스트 폐기 또는 그래프 차단을 커밋했다. 지연 접근 기록 뒤 임베딩 전체 행·내용 판 지문을 유지했고 폐기 컨텍스트 복구 조회도 cold를 유지했다.
- 실제 행 잠금을 유지한 상태에서 세 cold 이동과 접근 기록을 실행했다. 잠긴 행을 제외한 나머지 행은 제한 시간 안에 이동했고 잠금 해제 후 남은 행도 처리됐다.
- 서버의 BEFORE STATEMENT 장벽으로 접근 문장이 스냅숏을 얻은 뒤 다른 연결에서 실제 hot→cold 이동을 커밋했다. 첫 접근 문장은 PostgreSQL의 실제 `40001`을 냈고, 두 번째 문장은 같은 인자로 성공하여 현재 벡터 하나와 원래 조회 시각을 보존했다. 오류를 합성한 재시도 성공 시험이 아니다.
- 두 번째 `40001`, 첫 `40001` 뒤 `58030`, 첫 `40P01`·`58030`은 시험별 DB 트리거로 주입했다. 비트랜잭션 sequence로 실제 실행 횟수 2·2·1·1을 확인했고 호출은 빈 컨텍스트와 원인 오류를 반환했다. 실패 후 임베딩·내용 판 지문과 연결·예약을 대조했다.
- cold 읽기는 시험용 뷰에서 `58030`을 주입했다. 의미 검색은 빈 성공 후보로 감추지 않고 오류·nil 결과를 반환했으며 cold 원본 행을 보존했다. 이는 실제 tablespace 장치 장애나 디스크 복구 인수가 아니다.
- 4연결 풀에서 주기 이동 4개·접근 기록 4개가 각각 25회 경합했다. 최종 실행에서 주기 이동 `40001` 6건이 반환됐고 접근 기록 오류·교착은 0이었다. 임베딩 12개의 전체 수·고유 ID 수가 같고 실제 연결 상한과 풀·예약 회복을 확인했다.
- 최초 경합 시험은 주기 이동도 무조건 성공해야 한다고 판정하여 실패했다. 정본의 재시도 범위가 접근 기록임을 대조한 뒤 시험을 수정했고 신규 모듈 전체를 다시 실행했다. 최초 실패를 통과로 집계하지 않았다.
- 스냅숏 세 채널의 실제 점유 4, 접근 기록 동안 자리 유지, 취소 시 후보·홉·출처의 오류 전파, 단일 홉 최소 풀과 주기 작업 혼합 회복도 새 전용 DB에서 검증했다.
- `check-go.sh`의 의존성 검증·전체 build·vet·gofmt를 통과했다. 링크·앵커·계획 수·Markdown·용어·DOX 소유/색인과 `git diff --check`를 확인했다.
