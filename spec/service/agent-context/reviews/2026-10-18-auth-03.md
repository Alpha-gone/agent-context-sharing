# 계정 등록과 자격 대조 검토

- 기준: [AUTH-03](../development-plan/authentication.md#auth-03), [계정 생성과 비밀번호 처리](../sdd/authentication.md#계정-생성과-비밀번호-처리), [웹 화면 계약](../sdd/web.md#웹-화면-계약), `FR-AGENT_CONTEXT-130`·`131`·`133`.
- 범위: 계정 등록·중복 판별·자격 대조·더미 bcrypt·조건부 재해시·취소와 안전한 오류·웹 400/401/500 사상.
- 분리: 공개 시도 예산·주소·본문·상한의 전체 인수는 AUTH-04, 세션 수명·폐기·키 회전의 전체 인수는 AUTH-05, OAuth·Bearer는 후속 항목이다. 이번 웹 모듈 회귀는 실제 브라우저 접근성 인수나 전체 서버 통합 인수가 아니다.

## 발견 사항과 반영

기존 가입은 DB 유일 제약의 종류를 구분하지 않았고 대조 오류는 원인을 문자열로 감싼 채 반환했다. 웹은 조회·해시·저장 장애도 로그인 401·가입 400으로 처리했다. `public.account`의 `account_login_id_idx`와 SQLSTATE 23505를 함께 확인하여 아이디 중복만 분리하고 다른 제약·저장 장애를 내부 오류로 유지했다. 가입은 사전 존재 조회 없이 같은 비용의 해시를 만든 뒤 저장한다.

서비스는 가입 형식·아이디 중복·일반 자격 불일치·내부 장애를 구분한다. 없는 계정과 잘못된 비밀번호는 같은 고정 오류 문자열이며 내부 원인은 오류 체인으로 보존한다. 손상된 저장 해시와 더미·생성·조회·재해시 저장 장애는 `ErrUnavailable`다. 로그인 아이디가 형식에 맞지 않아도 같은 작업 자리의 더미 bcrypt를 거친다. 실제 저장소 오류의 문자열도 입력·드라이버 세부를 숨긴다.

해시·저장 호출 직후 취소를 확인하고 성공 ID·후속 저장·세션 처리를 계속하지 않는다. 웹은 자격 대조·세션 반환 뒤 취소된 요청에 본문·리디렉션·쿠키를 기록하지 않는다. 이미 커밋된 가입을 삭제하여 취소를 보상하지는 않는다. 레거시 재해시의 비교 후 갱신 경합에서는 먼저 저장된 현재 해시를 덮어쓰지 않는다.

## 새 검증 근거

- 자격 대조 5개 하위 시험: 정상·잘못된 비밀번호·없는 계정·빈 아이디/빈 비밀번호·잘못된 아이디를 실제 bcrypt로 대조했다. 정상 저장과 더미 모두 구성 비용이며 요청마다 한 번 대조하고 같은 작업 자리를 반환한다. 현재 형식의 불필요한 재해시는 없다.
- 중복 가입 시험: 정상·중복 모두 실제 해시를 생성하고 사전 존재 조회 없이 저장했다. 원래 계정·비밀번호를 보존하고 생성 2회·계정 1개·작업 자리 반환을 확인했다.
- 장애 8개 하위 시험: 계정 생성·조회·실제 대조 경계·더미·가입 생성·레거시 생성/갱신·손상 해시를 내부 장애로 구분했다. 오류 문자열에는 합성 민감 원문이 없고 원인 오류를 체인으로 확인할 수 있으며 성공 ID·저장 부작용·자리 누수가 없다.
- 취소 5개 하위 시험: 조회·대조·생성·계정 저장·레거시 갱신의 반환 시점에 취소하여 성공·후속 저장을 차단했다. 생성 오류와 취소가 함께 발생한 경우 취소를 우선한다. 기존 실행 중 해시의 자리 유지·취소·오류 회귀도 함께 실행했다.
- 실제 DB 동시 가입: 두 서비스가 각각 실제 해시를 생성한 뒤 저장을 함께 시작하여 1성공·1중복으로 수렴했다. 승자의 자격만 두 인스턴스에서 인증하고 UUID 기본 키 중복은 아이디 중복과 다른 안전한 저장 오류로 분류했다. 실제 저장소 종료도 불일치로 숨기지 않는다.
- 실제 DB 동시 레거시 재해시: 두 서비스가 같은 과거 해시를 읽고 현재 형식을 생성한 뒤 조건부 갱신을 함께 시작했다. 갱신은 한 번만 적용되고 두 인증은 같은 계정으로 성공하며 최종 현재 형식과 잘못된 비밀번호 거부를 확인했다.
- 웹 9개 하위 시험과 어댑터 6개 하위 시험: 로그인/가입의 정상·입력/불일치·내부 장애를 303·400/401·500으로 구분하고 내부 오류·비밀번호를 본문에 재출력하지 않는다. 자격 반환 뒤 취소하면 세션을 시작하지 않고 세션 반환 뒤 취소하면 쿠키·성공 이동을 하지 않는다. 실패 요청에도 세션·쿠키·성공 이동이 없다.
