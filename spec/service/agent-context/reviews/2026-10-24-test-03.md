## 산출물과 관찰 결과

`internal/store/testing_atomicity_acceptance_test.go`는 여덟 쓰기마다 커밋·취소 두 경우를 두 저장소 인스턴스로 실행한다. 첫 요청은 실제 업무 저장점을 해제한 뒤 커밋 전에 대기하고, 두 번째 요청은 같은 계정·키로 실제 PostgreSQL 자문 잠금 대기에 들어간다. 이때 외부 조회의 정점·간선·파생 판·큐·임베딩·그래프 누계/내용 판·감사·등급·쓰기 빈도·멱등성 지문은 준비 시점과 같다. 첫 요청이 커밋하면 두 번째 요청은 업무를 반복하지 않고 같은 저장 결과를 반환한다. 첫 요청이 취소되면 첫 쓰기가 롤백되고 대기자가 같은 식별자·판·한도로 새로 적용한다. 완료 뒤 두 인스턴스에서 다시 재생해도 전체 상태 지문이 같고 연결·예약은 반환된다. TEST-01의 커밋 동기화 도우미를 사용했다.

`internal/store/restore_channel_integration_test.go`의 감사 정리/미커밋 복구 롤백 검사를 원천·파생·사건으로 확장했다. 다른 실제 연결의 감사 정리는 아직 커밋되지 않은 복구를 근거로 현재 폐기 기록을 지우지 않으며, 복구가 롤백된 뒤에도 MCP 복구가 성공한다. 정리용 롤백에는 취소와 독립된 기존 제한 경계를 적용했다.

`internal/migrate/data_preservation_test.go`는 정식 012·013 이전 스키마에 후속 `context_revision`이 없음을 먼저 확인한다. 현재 저장 API에 후속 판 이력 저장이 추가되어 있으므로, 합성 이전 파생·참조·큐·저장량·폐기 감사 자료는 당시 스키마에 직접 넣는다. 스키마는 정식 마이그레이션으로 준비하며 새 DDL을 도우미에 복제하지 않았다. 012의 형상 전환과 013 적용 뒤에도 원본·업무·과거 이력이 같고 관찰하지 않은 과거 판이 생성되지 않는다. 전환/복귀의 합성 파일은 현재 정식 013과 충돌하지 않는 014로 옮겼다. `internal/store/reindex_contract_integration_test.go`의 합성 전환 파일도 같은 이유로 014를 사용한다.

## 실행 환경과 최종 결과

Go 1.27.1 darwin/arm64, PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6 Linux aarch64에서 실행했다. 고정 이미지 ID는 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`이다. 이번 작업이 만든 `acs-test03-atomic`·`acs-test03-channels` 컨테이너는 각각 tmpfs·임시 loopback 포트·합성 자격을 사용했다. 기준 DB와 각 전용 DB는 정식 마이그레이션으로 준비했다.

전체 저장소 시험이 아니라 TEST-03이 소유한 쓰기·경합·색인·불변식·마이그레이션과 서버 쓰기 어댑터를 선택했다. 정확한 시험 이름·정규식·원본 파일 목록은 실행별 `/tmp/acs-test03-{store,migrate,server}-manifest.json`에 기록했다. 저장소는 27개 파일의 최상위 시험과 `TestQueryUniqueIndexRacesIntegration`을 합친 141건, 마이그레이션은 `target_schema_test.go`·`data_preservation_test.go`·`checksum_configuration_test.go`·`configuration_test.go`·`rollback_test.go`의 18건, 서버는 `mcp_write_contract_test.go`의 7건을 선택했다. DB 실행은 모두 `TEST_DATABASE_URL`·`TEST_DATABASE_REQUIRED=1`·`AGE_GRAPH_NAME=agent_context`를 지정했다.

```sh
# 실행 목록을 JSON에 보존한 로컬 실행기는 다음 형태의 명령을 실행했다.
go_command=/Users/alphagone/sdk/go1.27.1/bin/go
"$go_command" test -race -json -count=1 -timeout=600s -run "$store_pattern" ./internal/store
"$go_command" test -race -json -count=1 -timeout=600s -run "$migration_pattern" ./internal/migrate
"$go_command" test -race -json -count=1 -timeout=600s -run "$server_pattern" ./cmd/server
# 수정 뒤에는 실패한 두 저장소 시험과 마이그레이션 범위만 재실행했다.
"$go_command" test -race -json -count=1 -timeout=600s \
  -run '^(TestReindexShapeTransitionIntegration|TestTEST03ConcurrentWriteCommitBoundaryIntegration)$' ./internal/store
```

- 최종 고유 시험 883건(하위 사례 포함): 저장소 787·마이그레이션 60·서버 36건. 최상위 시험은 166건이며 최종 실패·건너뜀은 없다. 같은 시험의 재실행은 마지막 결과만 사용했다. 신규 여덟 쓰기 경합 행렬은 최상위 1건·하위 16건이며 감사 정리 경합은 세 계층의 하위 사례를 추가했다.

## DOX pass와 남은 범위

변경은 기존 저장소·마이그레이션 시험 경계에 속한다. 제품 코드·공개 API·의존·실제 SQL 파일·SRS/SDD 계약을 바꾸지 않아 DOX·정본·용어집을 유지했다. 테스트 계획·전체 계획·요청 기록은 새 인수 결과로 갱신했다. 현재 변경은 미커밋이며 기존 `.idea` 미추적 파일은 변경하지 않았다.

도구·OAuth·웹 전수 격리는 TEST-04, 자원 상한과 종료 종합은 TEST-05, 브라우저·전송·실제 호스트와 전체 DB 반복은 해당 후속 인수에서 판정한다. 실제 외부 제공자 호출·운영 배포·공개는 실행하지 않았다.
