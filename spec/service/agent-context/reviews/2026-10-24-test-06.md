# TEST-06 브라우저·키보드·접근성 트리 인수 진행

- 기준: 2026-10-24, `feat/test-foundation`의 `66acc47` 이후 작업 트리.
- 대상: [TEST-06](../development-plan/testing.md#test-06), [시험 계층](../sdd/testing.md#테스트-계층), [웹 설계](../sdd/web.md), [화면 요구사항](../SRS.md#화면과-시각화-요구사항).
- 판정: 진행 중. Chrome·Node.js·DOM/접근성 트리는 통과했으며 Safari와 실제 VoiceOver 음성 관찰은 미실행이다. 전체 **98개 완료·1개 진행·25개 미착수**이며 TEST-06의 완료 체크박스는 유지한다.

## 변경과 실행 조합

기존 Go/TLS/격리 DB 브라우저 인수에 빈 그래프와 원천 하나의 그래프를 추가했다. Node.js 실행기는 실제 Chrome 입력으로 상세 조작 수단 전체의 Tab·Shift+Tab 순서, 빈/단일 그래프와 오류 화면을 검증한다. CDP 접근성 트리는 DOM backend 식별자로 검사 대상에 연결해 선택 상세·근거 패널의 하위 트리를 직접 대조한다. 목록의 같은 본문이나 근거 안내 문구만으로 패널의 접근성을 통과시키지 않는다.

- OS: macOS 26.6.2, 커널 Darwin 25.6.0 arm64.
- 실제 브라우저: Chrome 155.0.8059.86 headless, 시험별 임시 프로필·SPKI 지문 신뢰.
- Node.js: 26.11.1. 기존 렌더링 스크립트 상태 검사도 새로 실행했다.
- DB: 개발 이미지 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`, 별도 `acs-test06-browser` 컨테이너·`agent-context.task=test06` 라벨·tmpfs·임시 IPv4 loopback 포트·합성 자격. 기존 개발 DB에는 접속하지 않았다.
- Safari: 설치 판 26.6.2를 확인했으나 브라우저 시나리오는 미실행.
- 실제 스크린리더: VoiceOver 음성·읽기 조작 미실행. CDP 트리는 실제 음성이나 플랫폼 보조 기술의 읽기 순서를 대체하지 않는다.

## 관찰 결과

- **HTTP·실제 브라우저**: 로그인과 세션 쿠키 속성, 출처 거부, 이름/등급 필터·페이지·감사 필터, 팀 생성/구성원, 삭제/복구, 등록 폐기, 로그아웃을 새로 실행했다. 잘못된 커서는 실제 문서 400·한국어 안내·이름 필터 유지로 확인했다. 기존 화면 상태 행렬 39건도 통과했다. 브라우저 제출 결과는 기존 저장소 대조로 확인했다.
- **키보드**: 상세의 조작 수단 15개를 Tab으로 순회한 뒤 Shift+Tab으로 역순 이동했다. 매 이동의 포커스 대상과 `:focus-visible`을 대조했다. Enter 선택·Space 해제·Esc 전체 복귀에서 고른 버튼의 포커스가 유지됐다. 상세 이동 링크의 Enter는 2단계 제목으로 포커스를 옮겼다.
- **그래프 상태**: 고립 원천 선택은 자신만 보이고 Esc·빈 영역·전체 보기 버튼은 표시된 전체 범위로 복귀했다. 활성 시작점 다섯 개의 슬라이더 최댓값은 4였고, 방향키로 0/최대 홉을 대조했다. 국소 범위 밖 노드는 목록에서 다시 선택할 수 있었다. 빈 그래프와 단일 원천 그래프는 0홉이며, 빈 안내와 선택/복귀에 오류가 없었다.
- **DOM/접근성 트리**: 선택 전/후·해제의 고정 버튼 이름과 pressed, 짧은 상태의 `polite`·`atomic`, 슬라이더 수치/경계, 2단계 제목 포커스, 시각화 image 역할을 확인했다. 0홉으로 숨긴 두 단계의 `파생 후손 → 선택 파생 → 근거 원천`은 근거 패널 하위 트리에 방향과 종류를 포함해 남았다. 본문도 선택 상세 패널 안에서 읽기 대상으로 노출됐다. 해제 뒤에는 근거가 초기화됐다.
- **화면 크기**: 기존 일곱 화면의 390px 가로 넘침 없음·표 영역 방향키 스크롤·상세 한 열 배치도 새로 통과했다.
- **Node.js 상태 검사**: 기존 `TestGraphDetailScopeControls`의 disconnected/empty·javascript 하위 시험이 모두 통과했다. 이 결과는 브라우저 입력이나 실제 음성 결과와 별도다.

Chrome 시나리오는 기존 15개에 이번 5개를 더한 **20개**가 통과했다. 웹 패키지는 **고유 시험 811건, 최상위 96건**(하위 사례 포함)이 필수 DB·필수 브라우저·race에서 실패·건너뜀 없이 통과했다. 재실행을 중복 합산하지 않았다. Go 1.27.1의 의존성 확인·전체 build·vet·gofmt도 통과했다.

### CDP 값 표현 차이

첫 실행은 `aria-valuetext=0홉`을 CDP에서도 같은 문자열로 기대해 실패했다. 실제 DOM은 `0홉`이고 CDP의 슬라이더 `value`와 `valuetext`는 각각 숫자 `0`과 문자열 `0`이었다. Chromium의 [공식 직렬화 소스](https://raw.githubusercontent.com/chromium/chromium/main/third_party/blink/renderer/modules/accessibility/inspector_type_builder_helper.cc)의 `FillWidgetProperties`는 CDP `valuetext`를 native `kValue`에서 구성한다. 이 소스는 관찰한 표현 차이의 참고 근거이며 설치된 바이너리와 같은 revision이라고 주장하지 않는다.

검사는 DOM의 `0홉`·AX의 숫자 0과 경계를 각각 필수로 확인하고, CDP 텍스트가 DOM의 단위 안내 또는 같은 수치 문자열인지 대조한다. 두 원시 값은 `range-value-text.json`에 저장한다. 이 차이는 실제 VoiceOver가 단위를 읽거나 생략한다는 증거가 아니며 음성 인수에서 별도 확인한다. 제품 코드는 변경하지 않았다.

```sh

  WEB_BROWSER_REQUIRED=1 WEB_BROWSER_EVIDENCE='<존재하는 증거 디렉터리>' \
  /Users/alphagone/sdk/go1.27.1/bin/go test -race -json -count=1 -p 1 -timeout=600s ./internal/web
GO_BINARY=/Users/alphagone/sdk/go1.27.1/bin/go sh check-go.sh
```

세션 원시 근거는 `/tmp/acs-test06-web-final.json`, `/tmp/acs-test06-static.log`, `/tmp/acs-test06-evidence/`다. 증거 디렉터리에는 기존 화면 캡처, 상태별 `ax-*.json` 7개, `keyboard-order.json`, `range-value-text.json`, 판·미실행 조합을 포함한 `test06.json`을 남겼다. 임시 경로의 자료는 영구 보관을 보장하지 않는다.

종료 후 시험이 만든 자식 DB가 없고 다른 client backend 연결이 0임을 확인했다. 이 작업의 컨테이너를 제거했으며 기존 개발 DB·WAL 정리 컨테이너는 보존했다. Chrome은 시험 실행기의 임시 프로필 프로세스 종료와 함께 정리됐다.

## 남은 수동 인수

다음은 **예상 확인 항목이며 모두 미실행**이다. 별도의 합성 DB·동일 표본·TLS 서버를 준비한 상태에서 실제 사람이 수행하고 브라우저·OS·보조 기술 판, 키보드 탐색 설정, 사용 명령, 실제 음성 문구와 읽기 순서, 실패·미실행을 기록해야 한다.

1. Safari 26.6.2에서 출처·로그인/로그아웃·필터/페이지·팀·삭제/복구·감사·연결 관리, 빈/단일/고립/다중 시작점 그래프와 모든 키보드 시나리오를 실행한다. Chrome 결과를 Safari 통과로 옮기지 않는다.
2. Chrome·VoiceOver에서 목록 버튼의 이름·선택/해제 상태와 짧은 변경 안내를 듣는다. 본문 전체가 상태 안내로 반복되지 않는지, 선택만으로 포커스가 상세로 이동하지 않는지 확인한다.
3. VoiceOver에서 방향키로 0/최대 홉을 바꿀 때 숫자·단위가 이해되게 안내되는지 듣는다. DOM이나 CDP 값만으로 통과시키지 않는다.
4. 상세 이동 링크를 실행한 뒤 제목 탐색·본문 읽기·두 단계의 방향이 있는 근거 읽기를 실제 보조 기술 명령으로 수행한다. 국소 범위에서 숨긴 근거, 범위 밖 재선택, 선택 해제·전체 복귀의 읽기 결과도 확인한다.
5. Safari·VoiceOver 조합도 실행 여부와 관찰 결과를 별도로 남긴다. 실행하지 않은 조합은 미실행으로 유지하고 명시적인 검증 범위에 맞춰 완료 여부를 판정한다.

수동 결과가 없어 TEST-06과 단계 6의 전체 인수를 완료 처리하지 않는다. 독립적인 다음 자동 검증은 TEST-07이다. 서비스 요구사항·화면 동작·라이브러리·SQL·환경 기본값·DOX 소유 경계는 바뀌지 않아 해당 정본을 유지했고, 시험 설계·계획·요청 기록·근거만 정합화했다. 커밋·푸시는 수행하지 않았다.
