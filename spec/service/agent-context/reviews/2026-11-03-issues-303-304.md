# #303·#304 대화 흐름과 안내 진입점 구현

## 요청과 범위

2026-11-03 사용자가 두 이슈의 연계 검토 내용을 이슈에 반영하고 구현하도록 요청했다. 기존 세 계층과 원천 간 관계 금지를 유지한다. 새 의존성·시스템 자동 확정·운영 배포는 추가하지 않는다.

## 구현 결정

- 원천에 선택 `conversation_id`(1~128자, 공백만 금지)와 `turn_index`(0 이상의 정수)를 한 쌍으로 보존한다. conversation 출처에만 허용하며 생성 후 불변이다. 같은 그래프·대화·턴의 중복을 거부한다. 기존 데이터에는 순서를 추정해 채우지 않는다.
- 사건에 선택 `conversation_id`를 보존한다. 지정 시 모든 원천 구성원은 같은 대화여야 한다. 파생 구성원은 기존 계약을 유지한다. 사건의 대화 식별자는 생성 후 불변이다.
- 사건 생성에만 선택 `previous_event_id`를 받는다. 같은 그래프·활성·같은 명시적 대화의 앞 사건을 에이전트가 지정한다. 기존 precedes의 시작 시각·순환 제약을 유지하며 시간 범위 중첩은 자동 제안과 구분하여 허용한다. 사건과 confirmed precedes·감사는 같은 트랜잭션으로 저장하고 실패 시 전체 롤백한다. 이 입력 자체는 속성으로 중복 저장하지 않는다.
- 시간 인접 precedes 자동 제안은 같은 명시적 대화 안에서 앞뒤 각 1개로 제한한다. 대화 식별자가 없는 기존 사건은 기존 제안 규칙을 유지한다. 명시적 연결이 있는 방향에는 지름길을 추가 제안하지 않는다. 후보는 확정하지 않으며 기존 제안은 소급 삭제하지 않는다.
- 파생 요약에 선택 `navigation_refs`(0~100개의 중복 없는 같은 그래프 노드 ID)를 둔다. `NAVIGATES_TO` 간선으로 저장하며 근거와 분리한다. 사건·요약·원천으로 안내할 수 있지만 자기 참조는 금지한다. 생성 후 불변이며 변경은 새 요약과 대체로 수행한다. 기존 derived_from 필수·대상 제약을 유지한다.
- 그래프에 선택 `entry_context_id`를 둔다. 활성 요약 파생만 지정하며 편집자가 graph_update의 expected_version으로 설정·null 해제한다. 0~1개 대표와 여러 주제별 안내를 지원한다. 폐기·대체 시 이전 지정을 자동으로 새 대상으로 옮기지 않고 조회에서 무효 지정을 숨긴다. 새 지정은 별도 명시 갱신으로 수행한다.
- MCP graph_get에서 유효한 대표를 발견하고 node_get의 navigation_refs 탐색으로 사건과 원천에 도달한다. 탐색 참조를 요약 근거로 오인하거나 검색의 전역 근거 확장에 섞지 않는다. 웹 상세는 유효 대표를 시작점으로 우선 사용하고 지정이 없으면 기존 시작점 선택으로 돌아간다.
- 안내의 일반 갱신·새 주제 추가·다단계 근거 변경에 대한 최신성은 보장하지 않는다. 작성·재생성은 에이전트 책임이며 기존 evidence_invalidated를 탐색 대상 변경 신호로 확대하지 않는다.

## 검증 상태

2026-11-04 구현과 검증 완료. 실제 결과만 아래에 기록한다.

- Go 1.27.3으로 go build ./..., go vet ./..., gofmt -l . 통과. 도구 체인은 로컬 모듈 캐시의 공급자 배포본을 사용했고 빌드 캐시는 작업 전용 임시 경로로 분리했다.
- 모델·검색·MCP·웹 race 모듈 시험 통과. 실제 Chrome 부재에 따른 브라우저 인수와 별도 환경을 요구하는 호스트/운영 시험은 실행하지 않았다.
- 별도 합성 PostgreSQL 컨테이너에 001~017의 현재 migration 10개 적용. migration017의 016→017 전환·반복 무변경·기존 노드/그래프 필드·checksum/render_config/적용 시각 보존 시험 통과.
- 사건 명시 연결의 겹친 시간·다른 대화/그래프 거부·감사 실패 전체 롤백과 대화별 최근 후보 제한 검증 통과. 합성 MCP에서 동일 request_id 재생 시 사건 ID 재사용·확정 관계 1개·관계 적용 감사 1개를 확인했다.
- local 요약 대표→navigation_refs→앞 사건→precedes→뒤 사건→member_refs→원천과 턴 순서까지 실제 DB 조회 통과. 대표 지정·폐기 후 숨김·필드 생략 시 원래 지정 보존·null 해제·MCP09 실제 조립 계약 스냅샷 통과.
- 독립 코드 리뷰 P2 1건(기존 source_ref 재조회 시 새 대화 정보를 거부하는 계약 불일치)을 수정했다. 기존 원천을 변경하지 않고 반환하는 회귀가 통과했다. 리뷰 범위에서 P1 발견은 없었다.
- 새 NavigationRefs의 nil과 빈 목록이 JSON v2 이력 왕복에서 달라지던 회귀를 수정하고 nil/empty/실제 목록 왕복 시험 통과. 과거 migration 시험은 당시 형상을 raw fixture로 만들고 현행 색인/제공자/검색 시험을 전체 스키마의 별도 시험으로 분리했다.
- 기존 TestHopStaleStatisticsHubIntegration은 stale/both/2에서 40,067행 적재로 실패했다. 기준 HEAD 5abde86e의 임시 복사본에서도 같은 40,067행으로 재현했다. 기준 소스의 오래된 migration 개수 기대값만 8→9로 맞춰 실행 전제만 복구했으며 홉 구현은 변경하지 않았다. 이 기존 문제는 현재 구현 범위에 섞지 않고 재검증에서 별도 분리한다.
- 구조·소유권·지속 경계는 유지해 DOX를 추가하지 않았다. SRS FR176~179와 설계/개발 추적, LIFE-10 후속 작업, 용어집·README·이슈 본문을 동기화했다. 이전 124개 작업의 과거 인수 범위는 보존했다.


### 최종 검증과 범위

- 작업 전용 추가 DB에서 단일 프로세스로 저장소 race 전체 회차를 실행해 1,953개 사례가 실패·건너뜀 없이 통과했다. 위 기준 HEAD에서도 재현된 TestHopStaleStatisticsHubIntegration 한 건은 명시적으로 제외했다.
- 명령: `go test -json -race -timeout 12m ./internal/store -skip '^TestHopStaleStatisticsHubIntegration$'`. 별도 회차의 모델 204·검색 360·MCP 558·웹 872·서버 734·migration 88개 사례가 통과했다. 서버의 별도 호스트/운영 환경 23건과 웹 실제 브라우저 1건은 건너뜀으로 구분한다. 최종 go build ./..., go vet ./..., gofmt -l .과 git diff --check도 통과했다.
- 추가 집중 검증: 다른 그래프·폐기된 앞 사건의 생성/큐 전체 롤백, 대표부터 사건/원천까지의 실제 MCP 쓰기와 홉 조회, 대표 필드 생략/명시 null, 수정된 입력 조립 질의 상한(탐색 참조 포함 6회)이 race로 통과했다.
- 중간 넓은 검증에서 전체 DB fingerprint 시험과 다른 검증 프로세스의 쓰기가 간섭했다. 별도 DB의 취소 경합 3회와 위 단일 프로세스 저장소 전체 회차가 통과하여 간섭을 제거했다. 중간 실패 회차를 통과 근거로 사용하지 않는다.
- Markdown 파일/앵커·코드 블록과 활성 FR 175건(기존 171+추가 4)의 추적을 확인했다. 새 소유 경계가 없어 DOX는 유지했다.
- 이슈 #303·#304 본문과 완료 조건을 갱신했다. 코드는 로컬 작업 브랜치에 있으며 commit·push·PR·운영 DB 적용·배포는 수행하지 않았다. 현재 브랜치의 upstream은 미설정이다.

- 검증 종료 후 이번 작업에서 만든 컨테이너와 전용 익명 볼륨을 정리했다. 기존 개발 DB와 데이터에는 migration을 적용하지 않았다.
