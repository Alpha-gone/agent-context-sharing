- 기준: [AUTH-04](../development-plan/authentication.md#auth-04), [공개 로그인·가입 보호](../sdd/authentication.md#공개-로그인가입-자원-보호), [웹 처리 순서](../sdd/web.md#웹-요청-처리-순서), `FR-AGENT_CONTEXT-131`.
- 범위: 로그인·가입의 공유 시도 예산·출처 식별·본문 상한·비밀번호 작업 자리와 취소·응답 계약의 모듈 인수.
- 실제 브라우저·운영 부하·다중 인스턴스·외부 WAF·Tunnel과 OAuth·Bearer·웹 세션 전체 인수는 후속 범위다.

## 발견 사항과 반영

활성 출처 상태가 가득 차면 기존 구현은 항상 60초를 안내했다. 만료 항목만 회수하고 활성 항목을 보존하면서, 활성 출처 창과 초과한 전체 창의 실제 남은 시간 중 최댓값을 올려 안내하도록 보완했다. 제한 거부는 창을 연장하지 않고 성공도 카운터를 초기화하지 않는다.

기존 양식 오류에는 no-store가 없었고 ParseForm은 지원하지 않는 본문 형식을 읽지 않은 채 성공하여 빈 자격으로 인증을 호출할 수 있었다. 웹 처리기의 로그인·가입 POST 전체에 no-store를 적용하고 단일 URL-encoded 형식을 확인한다. 매개변수는 허용하며 누락·복수·잘못된 형식은 400이다. 알려진 본문 길이 초과는 읽기 전 413, 알 수 없는 길이는 MaxBytesReader로 제한된 해석 중 413이다. 예산은 형식 검사보다 먼저 소비한다.

주소 해석 뒤와 예산 판정 뒤, 양식 읽기 뒤에 취소를 다시 확인한다. 웹의 대체 실제 상대 해석도 IP와 숫자 포트를 함께 요구하고 zone을 거부하여 해석 실패를 공통 키로 합산한다. 신뢰 프록시 경계는 OPS-03의 조립 계층을 그대로 사용한다. 비밀번호 작업 상한의 구현은 유지하고, 실제 해시 생성이 반환하기 전 취소되어도 자리를 점유하며 반환 후 계정 생성 없이 해제하는지를 새로 검증했다.

기존 공개 인증 DB 시험은 공유 DB에 계정·서명 키를 만들 수 있었다. 시험별 임시 DB를 생성하고 실제 접속 DB를 확인한 후 정식 마이그레이션을 적용하도록 바꿨다. 저장소·마이그레이션 풀 종료 후 독립적인 10초 정리 문맥으로 자신이 만든 DB만 삭제한다.

## 새 검증 근거

- 웹 양식 24개 하위 시험: 두 경로의 8191·8192·8193바이트, 알려진/알 수 없는 길이, 형식 매개변수·누락·미지원·multipart·복수·잘못된 매개변수·잘못된 escape를 대조했다. 응답·본문 읽기·인증 호출·예산 소비를 관찰했다.
- 선행 거부·취소 8개 하위 시험: 출처 거부와 시도 초과는 본문을 읽지 않는다. 주소 해석 중 취소는 예산을 쓰지 않고, 본문 읽기 중 취소는 이미 쓴 예산을 되돌리지 않는다. 취소된 두 경로는 인증·쿠키·응답 생성을 막는다.
- 가득 찬 4096개 상태의 재시도 시간 감소·전체 창 최댓값·활성 항목 보존·만료 회복, 잘못된 실제 상대의 공통 키 합산을 검증했다.
- 같은 웹 인스턴스의 로그인·가입 120개 동시 HTTP 처리 중 60개만 인증 단계에 진입하고 나머지 60개는 429였다. 이 요청 수를 별도 시험 건수로 더하지 않았다.
- 비밀번호 생성 4개를 실제 bcrypt 후 반환 직전 대기시킨 상태에서 하나를 취소했다. 반환 전 추가 가입·로그인은 DB 조회·해시 실행 없이 Busy였고, 반환 후 1개 취소·3개 성공·자리 0개로 수렴하고 새 가입이 성공했다.
- 시험별 DB에서 실제 가입·로그인·서명 세션 검증과 공유 로그인/가입 예산·다른 출처의 같은 계정 접근을 확인했다. 추가 2개 하위 시험은 잘못된/복수/목록/누락 방문자 헤더의 실제 상대 합산과 IPv6 /64 합산·다른 대역의 독립 예산을 검증했다.
- 기존 더미/중복·레거시 재해시·오류 반환·전체 시도 경합 및 OPS-03 실제 HTTP/TLS 루프백 시험을 함께 통과했다.

## DOX pass와 저장소 상태

구현·조립·문서 소유권과 작업 흐름은 기존 경계를 유지한다. 루트·cmd·internal·web·spec 하위 DOX를 확인했고 새 패키지·환경 변수·스키마·지속 경계를 만들지 않아 DOX 본문·색인을 변경하지 않았다. 동작 상세는 인증 SDD에, 완료 근거는 계획·이 검토·요청 기록에 유지했다.

브랜치 feat/mcp-auth에는 upstream이 없어 원격 대비 ahead/behind를 확인할 수 없다. 기존 compose.prod.yaml과 IDE 설정 변경은 보존하고 이번 커밋에서 제외한다.
