# #276 일관성 평가 동시 요청 부하의 채널 실패 집계

## 결정과 변경

`-consistency`의 동시 요청 부하(`measureLoad`)가 응답을 버리고 요청 오류만 세던 동작을 바꿨다. 응답을 받은 요청은 동시 쓰기 측정과 같은 `countsAsFailure` 규칙으로 채널 실패를 세어 `concurrent_requests[].channel_failures`에 기록한다. 처리량은 보낸 요청 전체로 계산하고, 지연 분포는 요청 오류와 채널 실패가 없는 응답만으로 계산한다. 유효 응답이 없으면 지연 요약은 기존 미측정 값 `-1`이다.

manifest 요약은 해당 구성의 부하 결과에 요청 오류나 채널 실패가 있으면 `concurrent_load_failures`로 비채택한다. 동시 쓰기의 혼합 상태·채널 실패·요청 실패에 대한 기존 `inconsistent_or_failed_requests` 판정과 결과 묶음 검증은 유지했다. [평가 설계](../sdd/evaluation.md#라우팅일관-읽기홉-구현의-독립-통제)와 [시험 설계](../sdd/testing.md)에 집계·판정 기준과 회귀 시험을 명시했다. 요구사항·추적표·DOX의 소유권과 구성은 바뀌지 않아 유지했다.

요청 상한(`request_limit`) 초과 뒤에도 남은 부하 요청을 계속 보내는 동작은 이 이슈 범위 밖이며, 결과는 기존과 같이 시험 종료 단계에서 실패로 처리된다.

## 검증

- 수정 전 `trial_report.go`에서는 새 합성 판정 시험이 부하 실패 구성을 모두 `deferred`/`resource_and_quality_acceptance_pending`으로 남겨 실패했다.
- 수정 전 부하 집계를 덧씌우면 새 통합 시험이 질의 임베딩 장애 부하를 `errors=0`·`channel_failures=0`·정의된 지연으로 보고해 실패했다. 이슈의 증상과 같다.
- Go 1.27.3, 개발 DB 서버에 만든 작업 전용 DB(마이그레이션 001~014 적용), `TEST_DATABASE_REQUIRED=1`, `-p 1`의 필터 없는 `./cmd/eval` 실행: 907건 통과, 3건 실패. 실패는 `TestEmbeddingComparisonCommandIntegration`과 dimension·compression 하위 사례로, 별도 비교 DB(`acs_small`·`acs_half`)가 없는 실행 환경 조건이며 이번 변경과 무관하다. 통과로 보고하지 않는다.
- `check-go.sh`의 의존성 빌드·`go build`·`go vet`·`gofmt`·`govulncheck` 검사 통과.
- 검증 후 작업 전용 DB를 삭제하고 잔여 DB가 없음을 확인했다. 실제 외부 제공자·운영 배포는 미실행이다.
