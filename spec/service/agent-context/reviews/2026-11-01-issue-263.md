# #263 동일 사건 구성원의 간선 유지

## 원인과 변경

- UpdateContextWithOperation은 최종 구성원 집합이 이전과 같아도 HAS_MEMBER를 전부 삭제·생성했다. 순서와 무관한 집합 비교로 교체를 제한하여 본문·시간·순서만 바꾸는 갱신과 실질 변경 없는 갱신은 기존 간선을 유지한다.
- 같은 집합 비교를 관계 제안의 입력 변경 판정에도 재사용한다. 길이·같은 순서의 빠른 비교 뒤 필요한 경우만 사본을 정렬하며 호출자 slice를 바꾸거나 중복을 숨기지 않는다.
- 구성원 활성 검증·관계 시간·쓰기 불변식·참조/그래프 잠금·버전·감사·내용 판·색인 등록 경계는 유지한다. 구성원 추가·제거·교체는 기존 교체 경로를 그대로 사용한다. 공개 API·스키마·설정은 바꾸지 않았다.
- [수명주기 정본](../sdd/context-lifecycle.md#사건-재구성)·[시험 설계](../sdd/testing.md)와 [공식 근거](../reference.md#263-동일-사건-구성원의-간선-유지)를 보강했다. 기존 요구사항·개발 계획·DOX 소유권과 구조는 유지했다.

## 실제 DB 회귀

Go 1.27.3·`.env`의 TEST_DATABASE_URL·TEST_DATABASE_REQUIRED=1·race·count=1을 사용했다. 새 물리 ID 시험은 정식 마이그레이션을 적용한 시험별 격리 DB에서 실행하며 자신이 만든 자원만 정리한다.

- 구성원 1,000명 사건의 본문 갱신에서 변경 전 간선 ID 재생성을 재현했다. 변경 후 본문·시간·역순 입력·실질 변경 없음의 네 갱신에서 구성원별 HAS_MEMBER.id 1,000개가 모두 유지됐다. 응답의 정규 순서·새 버전·본문과 입력 slice 불변도 확인했다.
- 구성원 추가·제거·동일 개수 교체에서 대상 집합이 맞고 새 간선 ID로 교체됐다. 구성원 폐기 뒤 같은 구성원의 본문 갱신은 member_refs 필드 오류로 거부되고 사건·버전·간선은 유지됐다. 활성 구성원으로 고친 갱신은 성공했다.
- 기존 MCP 폐기 구성원 시험은 생성·구성원·본문·시간 변경의 invalid_argument/member_refs, 거부 감사·요청 키 재생·재시도와 복구를 확인했다. 기존 재구성·관계 제안 방아쇠·시간·색인 재등록·불변 필드 검증도 통과했다.
- 기존 AGE 롤백 시험은 본문 갱신에서도 DELETE edge를 기대해 한 사례가 실패했다. 본문 갱신의 SET node 장애와 실제 구성원 교체의 DELETE edge 장애를 분리하고 구성원 교체의 그래프·감사·커밋 실패를 추가했다. 20개 장애 사례와 상위 시험이 모두 통과했다.

## 검증 결과

대상 시험은 아래 정규식으로 store·server에서 실행했다.

```text
Test(EventUnchangedMembersKeepEdgesIntegration|EventChangedMembersReplaceEdgesIntegration|EventMemberOrderDoesNotTriggerProposalIntegration|EventProposalMemberSetComparison|LifeEventReconstructionIntegration|LifeEventMembersAndIndexIntegration|LifeEventRelationRollbackIntegration|EventUpdateChecksOnlyConfirmedRelationTimesIntegration|MCPDiscardedEventMemberRejectionIntegration)
```

최초 실행의 롤백 시험 지점 수정 후 해당 함수를 다시 실행했다. 최종 검증된 하위 사례는 중복 없이 store 60건·server 5건, 합계 65건이며 건너뜀은 없다. check-go.sh의 전체 build·vet·gofmt·govulncheck, 독립 코드 리뷰와 변경 문서 링크·내부 앵커·git diff --check도 통과했다. 리뷰의 발견 사항은 없었다.

전체 저장소 시험·실제 운영 부하·지연/dead tuple 감소량 측정·배포는 수행하지 않았다. 사용자 기존 `.env.example`·IDE 설정 변경은 포함하지 않는다.
