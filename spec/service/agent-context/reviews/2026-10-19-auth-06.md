# OAuth 발견과 공개 클라이언트 등록 검토

- 기준: [AUTH-06](../development-plan/authentication.md#auth-06), [OAuth 발견·최초 인가](../sdd/authentication.md#oauth-discovery와-최초-인가), [배포 구성](../sdd/operations.md#목표-추가-구성), `FR-AGENT_CONTEXT-166`.
- 범위: 고정 공개 메타데이터 두 경로·검증된 사전 등록의 주입·불변 사본·client/callback/resource 대조와 exact/same_ip 포트 정책.
- 인가 HTTP·코드 발급/교환·갱신·Bearer 보호 리소스·실제 호스트·운영 배포는 후속 작업이다. 메타데이터의 grant·PKCE·iss 광고를 프로토콜 전체 구현의 증거로 사용하지 않는다.

## 구현과 경계

구성 계층의 기존 JSON·issuer·resource·Origin·callback 형식 검증을 재사용한다. 인증 패키지가 config를 import하거나 환경 변수를 다시 읽지 않고 서버 조립이 검증된 값을 authz 주입 타입으로 옮긴다. 인증 서비스는 map과 각 URI 목록을 복사해 이후 호출자 변경과 분리하며 기존 웹 전용 생성은 OAuth nil로 유지한다.

인가 서버 메타데이터는 설정 issuer와 authorize·token·JWKS URI, 단일 scope, code, authorization_code/refresh_token, none, S256, iss 지원을 제공한다. 보호 메타데이터는 고정 resource·issuer 목록·scope와 header Bearer 전달을 광고한다. 두 경로는 TLS 판정 뒤 공개 GET·HEAD로 제공하고 JSON·no-store를 사용한다. POST·OPTIONS 등은 405·Allow: GET, HEAD이며 웹 catch-all로 빠지지 않는다. 요청 Host·전달 헤더·query로 공개 주소를 만들지 않고 DB·쿠키·토큰 발급·외부 HTTP 요청 없이 처리한다.

등록 대조는 client와 resource를 원문으로 확인한 뒤 callback을 비교한다. HTTPS와 exact는 완전 일치이고 same_ip HTTP literal loopback만 유효한 명시 포트를 바꿀 수 있다. IP 표기·scheme 표기·경로·query·escape를 정규화하여 허용하지 않는다. net/url의 scheme 소문자 변환을 피하려고 검증된 요청에서 포트가 포함된 authority만 등록 값으로 대체해 원문 전체를 비교한다. 대문자로 등록한 scheme도 그 원문을 유지한 포트 변경만 허용한다. 제품 이름에 따른 분기는 없다.

첫 시험 등록은 기존 예시의 codex-cli-first-test·127.0.0.1:49152/callback·exact를 조립하여 다른 포트를 거부했다. 일반 same_ip 등록과 분리되며 새로운 client ID·callback을 임의로 운영 등록하지 않았다. URL 형태의 미등록 client도 조회하지 않고 같은 고정 결합 오류로 거부한다. 대조 함수는 리디렉션을 수행하지 않으며 /authorize HTTP에서 성공·오류 리디렉션을 연결하는 일은 AUTH-07 범위다. CIMD·DCR·자동 등록·클라이언트 비밀을 추가하지 않았다.

## 새 검증 근거

- 등록 결합 42개 하위 시험: 첫 exact·일반 IPv4/IPv6 포트 경계와 1/65535·누락/0/범위 밖/이름 포트, 다른 IP·localhost·mapped·zone·userinfo·fragment, 경로/escape/query/scheme/대소문자 변경, HTTPS 완전 일치와 다른 client/resource를 대조했다.
- 등록 사본 시험: 호출자가 원본 map·callback 목록·resource 목록과 고정 resource를 바꾸어도 서비스의 최초 등록이 보존된다.
- 메타데이터 2개 하위 시험: JSON 전체를 대조하고 DB 접근 시 실패하는 저장소 대역으로 조회 없음·고정 주소·무리디렉션·무세션을 확인했다. OAuth 등록이 없는 웹 전용 서비스는 발견에서 503, 등록 대조에서 고정 오류를 반환한다.
- URI 구성 22개 하위 시험: issuer·resource·Origin의 HTTP·path/query/fragment·userinfo·잘못된 포트/zone·와일드카드·중복/빈 Origin을 자원 시작 전에 거부했다. 구성 모듈 303건의 기존 빈/중복 JSON·callback·배열·policy·환경 예시 검증도 통과했다.
- 서버 조립 3개 하위 시험: 구성 해석→주입 후 첫 시험 exact의 포트 변경 거부와 일반 same_ip의 포트 변경 허용을 확인했다.
- 실제 TLS HTTP 8개 하위 시험: 두 경로의 GET·HEAD·POST·OPTIONS, Host·전달 헤더·Origin·query 위조 비의존, JSON·no-store·405·본문 없는 HEAD·무쿠키·무리디렉션·임의 CORS 미허용을 대조했다. 시험 DB 풀을 닫아도 발견은 성공한다. 별도 2개 하위 시험은 위조 HTTPS 전달 헤더가 있는 미검증 평문 요청의 TLS gate 거부를 확인했다.
- 기존 웹 세션·공개 인증·전송 보안·구성 조립의 관련 서버 회귀를 함께 통과했다. 발견 응답이 client 목록·callback·등록 endpoint를 노출하지 않는다.
