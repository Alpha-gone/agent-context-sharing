## 구현과 계약

`NewReadHandlers`가 graph_list/get·node_get·relation_list·context_flow_get을 주입 인터페이스로 연결한다. 목록은 인증 계정의 유효 등급으로 저장 질의에서 필터하고 나머지는 현재 viewer 등급과 활성 그래프를 검사한다. 노드의 다른 그래프 소속·삭제 상태를 확인하며 관계 목록의 대상은 사건이어야 한다. 읽기에 등록 행위자는 요구하지 않는다.

현재 계정 플랜의 페이지 기본값·상한·최대 홉·결과 노드 수·문자 예산을 적용한다. 홉 생략은 0, 방향 생략은 both, 흐름 as_of 생략은 현재 UTC며 scope 생략은 검색기의 auto로 전달한다. 공개 스키마의 같은 검증을 사용하고 커서 인코딩과 내부 값 검증을 나누어 수행한다. 커서는 기존 저장소 구현의 최근 활동/ID 또는 관계 ID 정렬을 유지한다.

서버 조립의 `mcpReadStorage`는 저장 오류와 커서·부재 오류를 구분하고 공개 member_refs 필터를 내부 has_member로 바꾼다. `mcpReadFlow`는 검색 실패를 내부 의존 오류로 감싸 원인을 보존한다. 실제 구성원 간선도 응답 reference_type=member_refs로 사상한다. 내부 장애의 원인에 필드 오류가 있어도 입력 오류로 바꾸지 않는다.

정점의 그래프·삭제·중복 상태와 간선 양 끝의 반환 집합 포함 여부를 재검사한다. 노드 최단 거리, 평면 컨텍스트·참조·확정 관계, 흐름의 순위·진입 거리·출처·접기·채널·예산·절단과 선택 경로 메타데이터를 직렬화한다. 내부 연결 계측·후보 차수는 공개하지 않는다. 결과 배열·정렬·빈 커서를 명시하고 구조화 객체와 text content의 값은 같다. 표준 complete 외피는 SDK가 제공한다. 일부 채널 실패·빈 목록·예산/홉 절단은 정상 완료 결과다.

무제한 페이지의 요청값을 그대로 사전 할당량으로 쓰지 않도록 그래프·관계 목록 저장 코드를 보완했다. 그래프 목록의 추가 한 행 계산도 int 최댓값에서 넘치지 않는다. 새 상한이나 공개 입력·SQL 스키마를 추가하지 않았다.

## 검증

- Go 1.27.1, MCP Go SDK v1.8.0. 적용 판의 JSON v2와 SDK 결과 API를 [공식 근거](../reference.md)에서 확인했다.
- MCP 전체 **408건**, 선별 서버 **5건**, 선별 저장 **37건**, 부모 시험 포함·중복 제외 총 **450건 통과, 실패 0건·건너뜀 0건**, 각 범위 race 통과.
- MCP 시험은 다섯 처리기의 입력·기본값/명시값·현재 플랜·위반 필드·권한 검사 뒤 본문 차단·반환 범위·삭제/중복 정점·간선 완전성·거리·내부 원문 비노출·취소 전/중 경계를 확인했다. 고정 SDK의 실제 HTTP 교환에서 다섯 도구의 complete·no-store·구조화/텍스트 동등성을 확인했다. 이 HTTP 표본의 보호 인증은 대역이고 나머지 도구는 호출하면 실패하는 처리기다.
- 실제 DB에서 같은 활동 시각의 네 그래프를 크기 1로 넘겨 ID 내림차순·중복/누락 없음·마지막 빈 커서를 확인했다. 이름의 리터럴 부분 일치·등급 필터·다른 계정 목록/직접 조회 격리와 현재 viewer 부여/회수를 확인했다.
- 실제 0홉·in/out/both·derived_from/member_refs 필터·평면 간선·노드 상한 절단·다른 그래프 노드 거부·폐기 노드/삭제 그래프 거부를 확인했다. 세 확정 관계의 크기 1 페이지·ID 내림차순·유형/상태 필터·잘못된 내부 커서·사건 외 대상 거부도 확인했다.
- 실제 검색기는 동기화 스냅숏을 사용했다. 질의 임베딩 대역의 의도적인 실패에도 저장소의 나머지 채널과 흐름·출처 메타데이터를 반환했다. 1자 예산은 빈 배열과 예산 절단을, 빈 다른 그래프는 절단 없는 정상 빈 결과를 반환했다. 취소된 요청은 완료 결과를 반환하지 않고 종료 뒤 idle in transaction이 없음을 확인했다. 모든 풀 자리의 직접 회복 측정이나 실제 HTTP 단절 인수로 확대하지 않는다.
- 무제한 플랜에서 graph_list·relation_list의 page_size=9223372036854775807을 실제 실행해 추가 한 행 오버플로·요청량 사전 할당 없이 실제 행을 반환하는지 확인했다.
- 저장 코드 변경의 회귀 범위는 기존 유효 등급·현재 상태·취소·읽기 격리·Store 기본 연산이다. 서버의 import 경계도 SDD와 대조했다.
- `check-go.sh`: 의존성 확인·전체 go build·go vet·gofmt 통과. 변경 문서 10개·로컬 링크/앵커 344개와 Markdown fence를 검사해 발견 사항이 없었고, 작업 124개 중 완료 66개·미착수 58개를 대조했다. DOX pass도 수행했다.

초기 시험에서 허용하지 않는 필드명을 반환하는 정상 동작을 내부 원문 노출로 잘못 판정한 테스트를 수정했다. 실제 DB 시험은 감싸진 부재 오류와 내부 has_member를 처음에 내부 오류로 반환하는 발견 사항을 드러냈으며 두 사상을 보완한 뒤 해당 모듈을 재검증했다. 초기 실패를 통과 수에 포함하지 않았다.

각 DB 실행은 임의 이름의 suite DB를 만들고 정식 마이그레이션을 적용했다. 서버 표본은 그 suite에서 만든 시험별 자식 DB, 저장 표본은 suite의 합성 자료만 사용했다. 모든 실행에서 소유 DB 정리와 suite 부재를 확인했다. 기존 개발 DB·볼륨·적용 이력은 변경하지 않았다.

## 남은 범위와 DOX pass

기동 경로 전체 조립은 ARCH-07, 오류 계층·시간 예산·실제 HTTP 취소는 MCP-08, 전체 서버·스냅샷 계약은 MCP-09, 실제 호스트는 TEST-08이 소유한다. main의 `/mcp` 경로를 임시 처리기로 활성화하지 않았다.

소유 SDD·개발 계획·검토 근거·상태 진입점·README·요청/근거 기록을 갱신했다. 신규 패키지·디렉터리·소유권·요구사항·용어·물리 스키마가 없어 DOX 색인·SRS·용어집·마이그레이션은 유지했다. 사용자 Compose·IDE 변경은 보존했다. pull·commit·push·PR 갱신·배포는 하지 않았다.
