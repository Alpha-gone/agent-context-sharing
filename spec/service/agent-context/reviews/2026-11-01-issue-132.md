# #132 호스트 직접 연결 전환 완료 정리

## 결정

#132는 별도 MCP 클라이언트를 API 방식으로 바꿀 수 있는지 검토하는 이슈였다. 2026-10-11 사용자가 호스트 내장 MCP 클라이언트의 직접 연결(표준 원격 MCP·OAuth)을 목표로 채택했고, 같은 날 전용 연결 구현(`client/`)을 제거했다(`4217d92`). 이후 서버 구현과 첫 호스트 인수가 끝났으므로 2026-11-01 사용자 요청에 따라 이 이슈를 전환 완료로 정리한다. 권고안은 **대체**이며 별도 HTTP API·SDK·호스트별 어댑터는 만들지 않는다(`FR-AGENT_CONTEXT-172`).

## 완료 조건 대조

| 이슈 완료 조건 | 근거 |
|------|------|
| "API 방식" 후보·목표 호스트 정의와 기존 클라이언트 책임의 대응 | [SRS 개요](../SRS.md)와 `FR-AGENT_CONTEXT-164`~`172`가 목표를 MCP `2026-07-28` 표준 Streamable HTTP·OAuth PKCE·Bearer·회전형 갱신 토큰으로 정했다. 기존 클라이언트 책임은 다음과 같이 옮겼다. 브라우저 인가·토큰 보관은 호스트의 표준 OAuth·자격 저장으로, DPoP 서비스 전용 프로필은 Bearer·갱신 토큰 결합으로 바뀌었다. 행위자 주입은 서버 발급 `agent_id` 도구 입력이, 쓰기 멱등성은 선택 `request_id`가 맡는다. 도구 승인은 호스트, 권한·도메인 검증은 서버 소관이다([호스트 직접 연결 전환 설계](../sdd/architecture.md#호스트-직접-연결-전환-설계)) |
| 대표 호스트의 연결·발견·인증·연속 호출 최소 실증 | [TEST-08 인수](2026-10-27-test-08-completion.md)가 macOS Codex CLI 0.160.1 exec·`features.mcp_2026_07_28=true`·파일 자격 저장 구성에서 다음을 확인했다. 실제 브라우저 로그인과 코드 교환 1회, 새 CLI 프로세스의 저장 자격 재사용(추가 교환 없음), 실제 1시간 만료 뒤 단일 갱신과 다른 프로세스의 재사용, OAuth 결합 거부·403/500·쓰기 취소·현재 권한 재검사·중복 쓰기 방지 |
| 설치·인증 경험, 호환성, 보안, 유지 비용 근거의 권고안 | 대체를 채택했다. 프로젝트 클라이언트 설치·배포·호스트 revision 호환 코드가 사라지고, 인증은 표준 OAuth 계약으로 하향 없이 옮겼다. 공식 지원 범위는 인수한 호스트·판·표면으로 한정한다(`FR-AGENT_CONTEXT-171`) |
| Air Context의 CLI 제공과 직접 API 지원 구분 | 연결 방식 비교는 수행하지 않았다. 이슈 작성 시 확인한 범위를 그대로 남긴다. [JetBrains Context 시작 안내](https://www.jetbrains.com/help/jetbrains-console/getting-started-with-jetbrains-context.html)는 CLI·에이전트 설정을 안내하고, [Air의 MCP 서버 연결](https://www.jetbrains.com/help/air/mcp-servers.html)은 서버 URL 등록과 OAuth 연결을 안내한다. Air Context 자체의 공개 직접 API 지원은 확인하지 못했다. 이번 정리에서 다시 조회하지 않았으며 전환 결정의 근거로 쓰지 않았다. Air Context는 평가 요구사항 `160`~`163`의 연구 근거로만 추적된다 |
| 채택 시 SRS·SDD·DOX 변경과 후속 구현 범위 | SRS 직접 연결 요구사항, 분야별 SDD(MCP·인증·아키텍처·시험), DOX와 운영 안내가 재작성·인수되었다. 클라이언트 SRS·SDD(`spec/service/agent-context-client`)는 제거되었다. 추가 구현 후속은 없다 |

## 제한

- 공식 지원은 TEST-08이 인수한 macOS Codex CLI 0.160.1 exec 구성에 한정한다. Codex 데스크톱·다른 판·keyring·TUI·다른 호스트는 미인수다.
- #129(반복 브라우저 인가)는 별도 이슈다. 이 전환을 그 결함의 해결로 간주하지 않는다.

## 변경과 검증

- 이 검토 기록과 작업 로그만 추가했다. 정본은 이미 전환 상태를 반영하고 있어 바꾸지 않았다. 추적표·DOX의 소유권과 구성도 유지했다.
- 인용한 커밋(`4217d92`의 `client/` 제거), SRS 요구사항 `164`~`172`의 #132 근거, 아키텍처 절과 TEST-08 기록이 저장소에 있는지 확인했다. 변경 Markdown의 링크·앵커를 확인했다.
