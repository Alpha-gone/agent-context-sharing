# IDX-03 Gemini 제공자 요청·응답 계약 모듈 시험

- 정본: [SRS 색인 처리](../SRS.md#색인-처리), [제공자 계약](../sdd/indexing.md#임베딩-제공자-전환), [시험 계층](../sdd/testing.md#테스트-계층), [모듈 시험 시점](../DEVELOPMENT_PLAN.md#테스트-작성과-실행-시점).

## 구현과 검토

- 문서 `title: none | text: {body}`와 질의 `task: search result | query: {work_context}`를 분리하고 단일 content·단일 text part로 전송한다. `embedContentConfig.outputDimensionality`와 `autoTruncate=false`를 명시하며 키는 `x-goog-api-key` 헤더에만 둔다.
- 8MiB+1까지 제한해 응답을 읽은 뒤 JSON을 검증한다. 실제 읽기 실패는 안전한 전송 오류로, 정상적으로 전송된 잘못된 JSON은 재시도하지 않는 응답 계약 오류로 구분한다. 이전에는 완전히 수신된 닫는 괄호 없는 JSON도 UnexpectedEOF를 통해 일시 전송 실패로 오인할 수 있었다.
- 수치 포인터로 JSON null을 구분해 거부한다. null이 숫자 0으로 바뀐 벡터를 받아들이지 않으며 차원·유한 수치·비영 벡터 검증을 유지한다. 제공자 원문·URL·키·입력은 오류에 포함하지 않는다.
- 재시도 가능한 HTTP 상태를 408·429·500~599로 제한했다. 재시도 횟수·저장 상태·예산의 전체 검증은 IDX-04에 남긴다.
- 메타데이터 검증에서 빈 host·빈 포트·0·65535 초과 포트를 거부한다. 호출용 키는 Unicode 제어 문자를 거부하고 검증 뒤 공백을 정리한다. 평가 실행기는 키의 앞뒤 제어 문자를 정리하기 전에 검증하고 잘못된 차원 입력을 원문 없이 보고한다.
- 호출자가 주입한 표준 HTTP transport가 TLS 인증서 검증을 끄면 생성을 거부한다. 표준 transport와 TLS 설정·URL을 복제해 원본 변경이 제공자에 전파되지 않게 하며 timeout은 최대 30초로 제한하고 redirect를 차단한다. 종료 시 자신이 복제한 표준 transport의 유휴 연결만 닫는다. 기본 전역 transport와 다른 주입 RoundTripper는 소유하지 않는다.
- 서버 구성은 기존 공통 config 검증을 사용하고 평가·읽기 전용 감사는 같은 index.Config 계약을 사용한다. 감사의 메타데이터 검증은 계속 API 키를 요구하지 않으며 제공자를 호출하지 않는다. 실행기의 해당 검증은 DB 연결보다 먼저 수행된다.
- 모델 식별자는 `gemini:gemini-embedding-2:retrieval-v1:{type}:{dimension}`을 유지한다. 패키지 의존·환경 키·기본값·스키마·마이그레이션은 바꾸지 않았다.

## 검증 결과

- Go 1.27.1 darwin/arm64. DB·Docker 자원이나 외부 API 계정은 사용하지 않았다.
- **고유 시험·하위 시험 141건 통과**: index 85·config 27·eval 15·audit 13·server 1, 최상위 23개·하위 118개. `-race -count=1`을 적용했고 최종 실패·건너뜀은 0이다. HTTP 분류 재실행을 중복 합산하지 않았다.
- 본문·질의 각각 빈 값·공백·잘못된 UTF-8·ASCII/한글 8000자·8001자·이스케이프 문자를 확인했다. 잘못된 입력은 대역 호출 0회, 정상 입력은 정확한 접두사·원문·단일 part·출력 차원·명시적 false를 가진 1회 호출이었다. 기존 병행 시험에서도 문서·질의 각 16회가 섞이지 않았다.
- 정상 단일 벡터·추가 사용량 메타데이터·음수 성분을 허용했다. 누락/null·배열 응답·두 JSON 응답·중복 embedding·null/문자열/boolean/NaN/범위 초과 수치·다른 차원·영벡터·잘못된 UTF-8·완전 전송된 불완전 JSON은 영구 실패로 거부했다.
- 응답 크기 상한 바로 아래·정확한 상한은 허용하고 상한+1은 거부했다. 읽은 양은 상한+1 이하였고 본문은 닫혔다. 완성된 JSON 뒤의 실제 읽기 중단도 성공으로 공개하지 않았으며 고정된 재시도 가능 오류로 반환했다.
- TLS 대역이 헤더만 보낸 뒤 본문을 멈춘 상태에서 요청 취소와 HTTP client 시간 초과가 제한 시간 안에 끝나고 Canceled·DeadlineExceeded 식별을 유지했다. 입력 취소·제공자 지연·응답 상한·redirect의 기존 회귀도 새로 실행했다.
- 신뢰하지 않는 인증서는 요청 처리기에 도달하지 못했고 명시적 InsecureSkipVerify는 생성 전에 거부됐다. 주입 client의 timeout·redirect·transport를 바꾸지 않으면서 0/음수/30초 초과 timeout을 제한했다. 원본 URL·TLS 설정을 바꿔도 복제한 제공자는 유지됐고 Close 뒤 실제 유휴 연결의 닫힘을 관찰했다.
- 입력/인증/권한/모델 오류와 408·429·5xx 하한/상한·600·redirect의 분류, 제공자 원문·키·본문 비노출을 확인했다. vector 128~2000·halfvec 128~3072의 경계와 bit 거부, 서버 구성·평가·감사의 미지원/누락 제공자·URL·모델·키·host/포트와 키 없는 감사·식별자를 확인했다.
- 초기 실행의 실패 이벤트 3건은 시험 자료 두 문제였다. TLS 거부 시험이 httptest.Server의 공유 client를 바꾼 문제를 client 값 복사로 수정했다. OS가 허용하지 않는 NUL 환경 변수 준비는 제거하고 공통 제공자 구성에 직접 주입해 거부를 검증했다. 영향을 받은 시험을 재실행한 뒤 전체 대상 모듈도 다시 실행해 통과했다.
- 최종 `check-go.sh`의 의존성 검증·전체 build·vet·gofmt와 문서 링크·앵커·작업 수·용어·DOX 소유권·diff 검사를 확인했다.
