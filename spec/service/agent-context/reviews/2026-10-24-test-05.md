## 새 혼합 요청 시나리오

`internal/store/testing_resources_acceptance_test.go`는 정식 마이그레이션을 적용한 새 DB의 풀 상한을 4로 둔다. 실제 조정 스냅숏 하나와 읽기 트랜잭션 세 개로 네 연결과 세 자리를 모두 채운 뒤, 검색·같은 문자열 키 쓰기·같은 판 갱신·서로 다른 자문 잠금의 DB 주기 작업을 각 8개씩 보낸다. 검색은 실제 병렬 채널·스냅숏·색인된 원천의 벡터와 접근 기록을 사용한다. 멱등성 쓰기는 별도 파생 정점을 갱신하고 주기 작업은 실제 유예 만료 SQL을 실행한다.

| 단계 | 직접 관찰한 값과 결과 |
|---|---|
| 선행 점유 | `MaxConns=4`, `AcquiredConns=4`, 읽기 자리 3개다. |
| 각 종류 절반 취소 | 16개 요청 모두 `context.Canceled`와 주입 원인을 함께 보존한다. 연결 수는 4이며 성공 획득 누계·풀 획득 대기 취소 누계가 준비 시점과 같다. 업무 적용 횟수는 0이다. |
| 선행 읽기 해제 | 남은 종류별 4개 요청이 공통 20초 감시 마감 안에 종료한다. 검색 결과가 비지 않고 멱등성 적용은 1회다. 같은 판 갱신은 1회 성공·3회 판 충돌이며 네 주기 작업도 완료한다. |
| 최종 기준값 회복 | 선행 및 실제 검색 4개의 스냅숏 모두 활성 읽기 0·자리 0, 획득 연결 0이다. 예약 총량 4를 한 번에 다시 획득/반납할 수 있고 DB의 열린 트랜잭션·자문 잠금도 0이다. 두 파생 정점의 판은 각각 한 번만 증가했다. |

검색 저장소 대역은 기존 `WithReadSnapshot`에 위임하면서 실제 내부 읽기 범위만 수집한다. 제품 코드·정리 경계를 바꾸지 않으며 실패 시 대기 취소·선행 읽기 해제·작업 회수를 DB 제거보다 먼저 수행한다. 후속 조회 성공만으로 반환을 판정하지 않는다.

## 실행 환경과 결과

Go 1.27.1 darwin/arm64, PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6 Linux aarch64에서 실행했다. 고정 이미지 ID는 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`이다. 이번 `acs-test05-resources` 컨테이너는 tmpfs·동적 loopback 포트·합성 자격으로 기동했다. 기준 DB와 시험별 전용 DB는 정식 마이그레이션으로 준비했다. 기록기 파일·프로세스 시험의 실행 환경은 macOS다.

정확한 시험 이름·파일·정규식은 `/tmp/acs-test05-{store,server,authz,web,index,mcp,diagnostic,search}-manifest.json`에 남겼다. 선택 범위는 저장소의 새 혼합 요청·연결·홉·접근 기록·충돌/큐·진단 실패 15개 파일, 서버 조립/HTTP/주기/인증 보호/종료 13개 파일, 인증의 자격·해시 작업 4개 파일, 웹 공개 시도 1개 파일, 제공자/소비/재시도 5개 파일, MCP 전송 2개 파일, 진단 대기열/파일/실패/이벤트 4개 파일, 검색 채널/입력·스냅숏 2개 파일이다. 진단 자식 프로세스 전용 진입점은 독립 통과 건수에 넣지 않고 실제 상위 다중 프로세스 시험이 실행했다.
