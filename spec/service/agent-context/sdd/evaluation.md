# 품질·업무 효과 평가

평가 준비·집계·통제 조건·비교 실행과 산출물의 정본이다. 지표·합격 기준은 SRS 검증 절을 따르며 평가 실행기·합성/격리 비교·결과 저장의 [분야 인수](../reviews/2026-10-26-eval-13.md)는 완료했으며 실제 공개 품질·업무 효과·비용은 실증 대기다.

[설계 전체](../SDD.md) · [요구사항과 설계 대응](traceability.md)

## 검증을 가능하게 하는 설계

벡터 행 수·열 저장량과 주석 후보의 코사인 점수도 `store`의 그래프·모델 범위 조회로 얻는다. 실행기는 DB 드라이버나 연결을 보유하지 않는다. 후보 점수는 요청한 그래프·모델·기준 컨텍스트·후보 식별자로 제한하고 거리·UUID 순서를 유지하며 관계 상태를 변경하지 않는다. 이는 [단일 접근 계층](architecture.md#접근-계층)을 평가 계측에도 적용한 것이다.

[SRS 검증](../SRS.md#검증)이 판정 방법을 정했지만 그 판정에 필요한 값이 설계에서 나와야 한다. 어디에서 나오는지 정한다.

`FR-AGENT_CONTEXT-112`의 검증 원칙을 구현하는 평가 실행기의 집계·기록은 [GitHub #57](https://github.com/Alpha-gone/agent-context-sharing/issues/57)에 따라 같은 측정 표본과 구성에서 결정적이어야 한다. 부동소수를 누적하는 질의·사용 사례는 식별자 순으로 처리하고 결과 JSON의 맵 키도 정렬한다. 임계값 동점 처리 순서는 유지한다. 실행 시각·실제 지연·동시 쓰기 횟수는 매번 측정하는 값이므로 실행 간 바이트 동일성을 주장하지 않는다.

95% 신뢰구간은 유효 표본이 둘 이상일 때 자유도 `n-1`의 Student t 분포 0.975 분위수로 계산하며 자유도 30 뒤에 정규 임계값으로 대체하지 않는다. 표본이 없거나 하나뿐이면 표준편차·신뢰구간 반폭을 기존 미정의 표식 `-1`로 기록한다. 평균 차이는 표본이 있으면 보존하되 미정의 구간으로 유의성을 판정하거나 지속 평가를 합격 처리하지 않는다. 측정하지 않은 지표도 0과 구분하고 비교에서 제외한다.

일관성 평가의 동시 쓰기 구성은 이전 구성의 컨텍스트 폐기·임시 파생·확정 관계 상태를 모두 복구한 뒤 시작한다. 쓰기 성공 후에만 복구용 상태를 갱신하며 복구가 실패하면 다음 구성을 실행하지 않는다. 시나리오 적재 뒤에는 색인 처리 실패를 포함한 모든 실패 경로에서 전용 그래프를 소프트 삭제하고 정리 실패도 호출자에게 전달한다. 결과 통제 조건에는 색인 대상 계층을 남기고 일관성 보고서에는 중복 접기 임계값도 남긴다.

기본·적응형·지속·적대적·일관성 평가의 측정 전 색인 준비는 같은 그래프별 경계를 사용한다. 지금 확보할 작업이 없는 것만으로 완료를 판정하지 않고, 한 SQL 명령에서 해당 그래프의 전체 `pending`·`failed` 작업과 현재 색인 대상 계층의 활성 컨텍스트에 대한 현재 `model_id` 임베딩을 함께 확인한다. 원천 제외 구성에서는 원천 임베딩을 요구하지 않으며, 삭제된 컨텍스트는 임베딩 준비 대상에서 제외한다. 같은 모델의 이전 임베딩이 남아 있어도 새 작업이 남으면 준비 완료가 아니다.

색인 처리 회차는 호출자가 정한 유한 상한을 유지한다. 지금 처리할 작업이 없는데 재시도 대기나 다른 작업자의 리스·행 잠금으로 숨겨진 `pending` 작업이 남으면 자동 백오프 대기 없이 즉시 실패한다. 최종 실패 또는 현재 모델 임베딩 누락도 실패하며 남은 상태별 건수와 보관된 실패 사유를 알린다. 이 실패는 측정·합격 판정·정상 결과 파일 기록을 중단하고 기존 평가 그래프 정리 경계를 따른다. 큐 상태나 임베딩 누락을 평가기가 임의로 재등록하여 숨기지 않는다.

평가 실행기의 변환·업무 효과·확장 과업·지속·적응형·일관성·적대적·검색 단위·외부 원본·임베딩 비교 모드는 서로 배타적이며 둘 이상을 지정하면 입력 읽기·DB 접속·파일 생성 전에 거부한다. 각 모드가 쓰지 않는 데이터·검색 옵션도 같은 시점에 거부한다. 지속 평가는 내장 시나리오의 데이터·검색 단계·색인 대상과 고정 문자 예산을 쓰므로 `-repeat`·`-max-hops`·`-max-hop-nodes`·`-out`만, 기존 업무 효과 비교는 `-business`·`-out`만 받는다. 적응형·일관성·적대적 비교는 각자 고정한 그래프 단계를 쓰므로 `-stages`를 거부한다. 입력에 통제 조건을 고정한 검색 단위·외부 원본·임베딩 비교는 `-out`과 10회의 `-repeat`만 함께 받는다. manifest의 지속 평가는 고정 예산을 입력 연결에서 대조하고 실행 옵션으로 전달하지 않는다. `own-adversarial`은 여섯 공격 유형과 기준 질의를 함께 생성하므로 `-convert-use-case`를 허용하지 않고 출력 파일 생성 전에 거부한다. 공격 표본은 대상 질의마다 성공 조건을 정확히 하나만 가지며 같은 `query_id`의 중복 조건은 거부한다.

일관성 동시 쓰기 표본은 파생 20개·허브 원천 하나·사건 둘·임시 파생 하나로 최대 24개 활성 컨텍스트를 가지므로 `SEARCH_CHANNEL_CANDIDATE_LIMIT`는 24보다 커야 한다. 만족하지 않으면 DB 접속·평가 그래프 생성 전에 거부한다. `read_committed`의 스냅숏 보유 시간과 유효 응답이 없는 요청의 연결 수·최대 연결 수는 측정하지 않은 값으로 `-1`을 기록한다. 빈 지연 표본의 평균·분위수·최댓값도 `-1`이며 실제 측정된 0과 구분한다.

기본·적응형·일관성·지속·적대적 평가의 모든 그래프 정리는 취소된 평가 context와 독립적인 10초 제한 context에서 시도한다. 정리 실패는 원래 평가 오류와 함께 호출자에게 전달하여 실패 종료하며 로그만 남기고 성공으로 처리하지 않는다.

평가 그래프의 수명은 적재→색인 준비→측정→소프트 삭제를 하나의 경계로 묶는다. 기본·적응형 비교는 조건·회차마다 입력 표본을 새 그래프에 적재하며, 지속 시나리오와 공격 표본도 각각 회차별 그래프를 쓴다. 공개 데이터의 표본 경계는 준비 파일의 기억 그룹이며 같은 대화의 문항은 그 그룹을 공유한다. 일관 읽기 동등성은 동일 식별자·동일 상태를 비교하는 한 표본 안에서 수행하고, 부하 조건과 동시 쓰기 조건은 각각 새 그래프에서 실행한다. 준비·측정·정리 중 어느 단계라도 실패하면 다음 실행과 정상 보고서 기록을 중단한다. 실행기의 종료 신호도 평가 context를 취소하고 같은 정리 경계를 거친다.

[SEARCH-10](../development-plan/search.md#search-10)의 합성 홉 비교는 같은 결과를 만드는 조회 구현의 자원·지연을 확인한다. 일관 읽기의 후보별 연결 보유/재시도와 동시 쓰기 중 단일 커밋 설명은 [EVAL-06](../development-plan/evaluation.md#eval-06)의 별도 비교다. 라우팅도 같은 작업에서 그래프 범위·근거 선택을 고정한 독립 비교로 다루며, 근거 경로 선택의 효과와 색인 대상 계층의 효과는 [EVAL-05](../development-plan/evaluation.md#eval-05)에서 서로 분리한다. 홉의 동일 결과나 소수 warm-cache 반복을 이 비교들의 품질·효과·기본 활성화 근거로 확장하지 않는다.

지속 평가는 `cmd/eval -continual`이 온라인 갱신, 재생, 전이, 복구, 망각과 상충 해소를 서로 독립된 평가 그래프에서 실행한다. 기본 운영 구성을 검증하는 다섯 시나리오는 `baseline`을 쓰고, 근거 제공 여부 자체가 판정 대상인 전이는 `references`를 쓴다. 각 회차는 상태 변경 전 기준선과 변경 후 재현율·순위 역수·정답 1건당 문자 수를 같은 질의로 측정한다. 차이의 95% 신뢰구간이 나쁜 방향으로 0을 벗어난 지표가 있으면 품질 회귀로 판정한다.

검색 지표만으로는 상태 계약을 확인할 수 없으므로 시나리오별 불변조건을 함께 검사한다. 전이는 파생에서 근거로의 `derived_from` 경로, 복구는 폐기·복구 후 활성 상태, 망각은 만료 컨텍스트의 기본 검색 제외·홉 경로 존재, 상충 해소는 `disputed`에서 후속 판단으로의 응답 상태 변경을 본다. 온라인 갱신·재생·전이에서 수행한 추가·유지 판단과 나머지 상태 전이는 본문 대신 `continual:{scenario}:{action}` 형식의 판단 표식을 `operation_log.judgment_input`에 남긴다. 평가기는 `HasAppliedOperationJudgment`로 해당 그래프의 적용 성공 기록을 다시 확인하고 거부 기록을 성공 근거로 사용하지 않는다. 결과 파일에는 본문과 계정·에이전트 식별자를 남기지 않는다.

온라인 갱신은 추가된 세 컨텍스트의 활성 상태와 이전 답의 보존을, 재생은 유지 전후의 내용·판·속성 보존을 확인한다. 전이는 새 사건이 기존 지식을 구성원으로 참조하고 전후 검색 응답에도 근거 노드·간선이 남는지 대조한다. 복구는 폐기 직후 검색 제외까지 검사한다. 망각은 만료와 폐기를 함께 적용하고 기본 검색 제외, 지정한 과거 시점의 만료 파생 포함, 만료 파생의 직접/홉 조회와 폐기 컨텍스트의 제외를 구분한다. 상충 해소는 해소 전 두 의견의 동시 반환과 해소 후 신뢰 상태·유효 의견 보존을 검사한다. 응답에는 검사별 논리 결과와 판단 표식별 기록 확인 결과를 남긴다. 일부 검색 채널이 실패하면 품질 표본으로 사용하지 않고 실행을 실패 처리한다. 진입점이 없어 그래프 확장을 생략한 정상 빈 결과는 실패로 세지 않는다.

각 회차는 같은 조회 시각·질의·검색 단계에서 전후를 측정하고 단계·색인 대상·조회 시각을 보고한다. 같은 시나리오 입력의 열 번 반복은 하나의 독립 단위이며 품질 표본 열 개로 세지 않는다. 여섯 시나리오 각각에 세 지표의 비교와 `passed`·`failed`·`deferred` 상태를 남긴다. 누락/중복 회차, 미측정 지표와 독립 단위 부족은 품질 유지 합격으로 처리하지 않는다. 상태·기록 위반이나 유의한 악화는 실패이며, 합성 시나리오 하나씩의 반복 실행은 독립 단위 부족으로 품질 판정을 보류한다.

[SRS 그래프 효과 비교](../SRS.md#그래프-효과-비교)의 단계별 구성이 성립하는 근거는 채널이 서로 독립적으로 채점되고 결합이 채널 수에 의존하지 않는다는 것이다. 순위 역수 합은 한 채널이 빠져도 계산이 성립하므로, 기준선에서 그래프 경로를 빼고 단계마다 더하는 일이 코드 변경 없이 구성으로 된다.

4단계는 3단계와 같은 결합 후보를 두고 선택 활성화 값만 바꾼다. 평가 세트가 정답 컨텍스트와 함께 필요한 관계 경로를 갖고 있어야 근거 완전성과 경로 연속성을 계산할 수 있다. 평가는 반환된 컨텍스트·참조·관계를 그 정답 경로와 대조하고, 선택 전후 후보 수·연결 노드 수·예산 사용량·응답 지연을 함께 기록한다.

구조 지표는 평가 실행기가 원자료로 계산한다. 단절 근거 비율은 반환 부분 그래프에서 진입점·원천에 닿지 못한 비진입 컨텍스트 수를 분모가 0이면 0으로 두어 계산한다. 허브 편중은 반환 컨텍스트의 후보 부분 그래프 차수에 대한 지니 계수이며 반환 컨텍스트가 하나 이하면 0으로 둔다. 중복 컨텍스트 비율은 `context_id` 통합과 중복 파생 접기 전 후보 수를 분모로 두고 두 처리에서 순차적으로 제거된 수를 세며 분모가 0이면 0으로 둔다. 확장 단계의 한계 기여는 직전 단계 대비 정답·필수 근거 증가량과 문자 수·지연 증가량을 나란히 남겨 하나의 합성 점수로 축약하지 않는다.

질의 적응형 비교는 같은 질의·초기 후보·예산·모델·그래프 관계 범위·근거 경로 선택 값에서 직접, 국소 확장과 전역 진입을 모두 실행한다. 사실 검색은 재현율과 순위 품질, 연상 검색과 전역 요약은 근거 완전성과 경로 연속성을 차례로 우선하고, 동률이면 문자 수와 지연이 작은 경로를 오프라인 최적 경로로 정한다. 지연은 반복 측정의 95% 신뢰구간이 겹치지 않을 때만 차이로 보고, 겹치면 직접, 국소 확장, 전역 진입 순으로 고른다. 지연 잡음만으로 최적 경로가 바뀌면 두 정책의 오선택률이 함께 부풀기 때문이다. 선택 경로가 이 경로와 다르면 오선택 한 건으로 센다. 결과 파일에는 경로별 집계와 이유 코드만 남기고 질의문·본문·경로 원문은 남기지 않는다.

[SRS 색인 대상 비교](../SRS.md#색인-대상-비교)가 성립하는 근거는 색인 작업 등록이 저장 흐름의 한 단계라는 것이다. 등록 조건에 계층을 넣으면 원천을 색인에서 뺀 구성이 되고, 나머지 조건은 그대로다. `derived_from` 간선이 남아 있으므로 원천을 색인하지 않아도 근거 추적은 유지된다. 조건과 그 구성 값은 [색인 작업 큐](indexing.md#색인-작업-큐)가 갖는다.

[SRS 업무 효과 평가](../SRS.md#업무-효과-평가)가 컨텍스트 본문과 개인 식별 정보를 수집하지 않는 것은 [로그에서 제외하는 것](observability.md#로그에서-제외하는-것)이 이미 강제한다. 효과 측정이 쓰는 값은 요청 지표와 집계된 사용량뿐이며 본문에 닿는 경로가 없다.

`cmd/eval -business <집계 파일>`은 통제 과업에서 별도로 수집한 두 조건의 집계값을 짝지어 판정한다. 서버나 평가 실행기가 과업 본문과 참여자 식별자를 수집하지 않도록 입력 형식에는 다음 값만 둔다.

| 입력 영역 | 값 |
|-----------|----|
| 데이터셋 판 | 통제 과업 집합의 판 |
| 통제 조건 | 에이전트 버전, 모델, 컨텍스트 예산 |
| 조회 없는 조건 | 과업 완료 시간, 재작업 횟수, 세션 재개 상호작용 수, 협업 활용 비율 |
| 조회 있는 조건 | 같은 네 지표 |

배열 항목 하나에 같은 과업의 두 조건을 함께 두어 대응 표본으로 보고 최소 세 표본을 요구한다. 과업 완료 시간·재작업·세션 재개는 감소를, 협업 활용은 증가를 개선으로 본다. 질의별 단계 비교와 같은 방식으로 조건별 차이의 95% 신뢰구간이 0을 포함하지 않으면서 네 지표가 모두 개선될 때 통과한다. 결과 파일에는 데이터셋 판, 통제 조건, 표본 수와 지표별 집계·판정만 남기며 개별 표본 값은 싣지 않는다. 허용하지 않은 JSON 필드를 거부해 과업 본문이나 개인 식별 정보가 입력에 추가되어도 평가가 진행되지 않게 한다.

두 조건의 네 지표는 모두 명시적인 숫자여야 하며 누락·`null`은 입력 오류로 거부한다. 재작업·세션 재개 횟수와 협업 활용 비율의 명시적 0은 기존 범위 검증을 만족하는 측정값으로 허용한다.

## 비그래프 기준선

`NFR-AGENT_CONTEXT-005`가 요구하는 비교 대상이다. 별도 시스템을 만들지 않고 같은 코드에서 구성한다.

| 구성 요소 | 기준선에서의 상태                                   |
|-----------|-----------------------------------------------------|
| `model`   | 그대로 쓴다. 저장 방식에 의존하지 않는다            |
| `store`   | 그대로 쓴다. 정점과 간선은 여전히 저장한다          |
| `search`  | 그래프 경로 채널을 끄고 진입 채널 셋만 실행한다     |
| 응답 구성 | 그대로 쓴다. `references`와 `relations`가 비게 된다 |

`model`이 아무것에도 의존하지 않게 둔 [패키지 경계](architecture.md#패키지-경계)의 결정이 여기에서 쓰인다. 논리 모델이 그래프 구조를 모르므로 기준선과 그래프 구성이 같은 타입을 공유하고, [SRS 공통 원칙](../SRS.md#공통-원칙)이 통제 조건으로 요구한 동일한 입력과 표현이 코드 수준에서 보장된다.

간선을 저장한 채로 탐색만 끄는 이유는 표현을 바꾸지 않기 위해서다. 저장까지 빼면 입력이 달라져 통제 조건이 깨진다. 기준선은 같은 데이터에서 그래프 확장만 쓰지 않는 구성이다.

### 그래프 단계와 색인 대상의 실행 통제

`-prepared-input <준비 디렉터리>`는 EVAL-02의 `preparation.json`과 checksum이 일치하는 `memory.json`·`evaluation-private.json`을 통제 비교에 연결한다. 직접 `-contexts`/`-queries` 입력 및 다른 평가 모드와 함께 쓰지 않는다. 원본 매핑·정답 문자열은 검색 입력에 복사하지 않고 질의·비식별 독립 단위·근거 key만 연결한다. 문항의 기억 그룹마다 독립 그래프를 사용하고 질의가 없는 준비 그룹은 검색 측정 대상에서 제외하며 준비 그룹 수와 실행 그룹 수를 구분한다. 원본 유형은 표본에 남기고 multi-session/multi-hop/event는 연상 검색, 나머지 준비 유형은 사실 검색으로 집계한다. 근거 주석이 없는 문항은 회수 정답을 추측하지 않고 재현율·순위·정답당 문자와 근거 지표를 미측정으로 유지하며 실제 문자·지연·채널은 측정한다. 공개 준비 기억은 원천만 포함하므로 파생·사건·전역 요약의 효과 실증에는 별도로 고정한 에이전트 생성 입력이 필요하다.

기본 비교는 `-stages`의 인접 누적 단계만 허용한다. 한 단계만 측정할 수도 있으며, 모든 질의는 `scope=auto`를 사용한다. 기준선은 전역 fallback과 근거 선택을 끄고 의미·키워드·시간 진입 세 채널을 유지한다. `baseline,references,relations,global,evidence`에서 인접 단계 하나씩만 변경하며 마지막 단계는 global과 같은 그래프 범위에서 근거 선택만 켠다.

`-compare-index-targets`는 별도 색인 대상 비교 모드다. `-stages`에 고정 단계 하나를 명시하고 `-index-targets`와 다른 평가 모드를 함께 지정하지 않는다. `all_layers`와 `without_source`의 저장소·작업자를 각각 준비하며, 양쪽에 원천·간선·근거가 같은 입력 전체를 새 그래프로 적재하고 해당 대상 전체를 색인한다. 그래프 단계 효과와 한 실행에 섞지 않는다.

두 비교는 조건 순서를 회차 안에서 순환한다. 생략된 조회 시각은 실행 시작의 한 시각으로 고정한다. 각 조건·회차는 새 그래프를 적재·색인한 뒤 별도 warmup 없이 측정하며 공유 DB/OS 캐시를 비우지는 않는다. 이 준비 정책과 조건별 실제 준비 시간·문서 임베딩 HTTP 시도 수·현재 모델 벡터 행 수 및 `pg_column_size(embedding)` 합계를 남긴다. 벡터 바이트는 열 값의 저장량이며 테이블·색인·WAL·금액을 포함한 총비용이 아니다.

사용 사례별 대응 지표·문자·지연·채널 실패와 p95 500ms 상한을 보고한다. 그래프 단계에 유의한 개선이 없거나 유의한 품질/효율 악화·실패·지연 초과가 있으면 기본 활성화 후보로 승인하지 않는다. 비용 비례성과 공개 데이터 효과가 검증되기 전에는 개선이 관찰되어도 최종 판정을 보류한다. 색인 대상 비교는 재현율의 유의한 손실과 표본 부족을 구분하며 손실이 관찰되지 않았다는 사실을 동등성 증명으로 표현하지 않는다. 이 실행기의 관찰 결과가 운영 기본값을 직접 변경하지 않으며 최종 채택·총비용은 EVAL-12/13에서 판정한다.

### 라우팅·일관 읽기·홉 구현의 독립 통제

`-adaptive`는 그래프 범위·근거 선택·색인 대상·모델·예산을 고정하고 모든 질의를 `auto`로 실행한다. 생략된 조회 시각은 실행 시작 시각으로 고정한다. 강제 경로의 초기 라우팅 신호는 조건·회차 사이에 같아야 하며 채널 실패나 신호 변화가 있으면 임계값 재현을 중단한다. 조정 표본에서 고른 임계값과 같은 표본의 관찰 결과는 최종 채택 근거가 아니다.

`-consistency`는 Read Committed·동기화 스냅숏·내용 판 재시도를 병렬/순차로 각각 비교한다. 내용 판 후보는 평가 실행기 안에서만 조립하며 검색 시작·조립 완료의 `content_revision`이 다르면 전체 DB 읽기를 다시 실행한다. 질의 임베딩은 읽기 경계 전에 한 번만 실행한다. 요청은 30초와 최대 3회 재시도로 제한하며 호출자의 더 짧은 마감을 우선한다. 변경된 판의 부분 응답은 버리고 재시도 요청 수·재시도 합계·최대 연속 재시도·상한 소진을 기록한다. 이 후보와 Read Committed의 미계측 연결 수·보유 시간은 `-1`이다. snapshot의 연결 수·보유 시간은 실제 읽기 경계에서 측정한다.

쓰기 없는 결과 동등성을 먼저 검사하고 불일치하면 부하·동시 쓰기를 실행하지 않는다. 동일 표본의 각 응답은 본문·속성·참조·관계·순위·출처·예산·부분 상태까지 대조한다. 동시 쓰기 표본은 후보 상한·문자 예산·홉 상한 때문에 정상 컨텍스트가 빠지지 않는 전용 조건(문자·노드 무제한, 최소 1홉)을 사용하고, 요청 시작의 조회 시각은 재시도 중에도 유지한다. 관찰 가능한 혼합 상태·채널 실패·요청 실패를 구분하고 원상 복구 실패 시 다음 조건을 중단한다.

홉 비교는 공개 입력에 후보를 추가하지 않고 `store`의 시험 전용 실행기로 수행한다. 안전한 고정 표본에서 모든 구현의 결과 동등성을 통과한 뒤 회차 안에서 순서를 순환하여 10회 실행한다. 실제 SQL 명령·반환 행과 전용 풀 소켓의 수신 바이트·지연을 기록한다. 수신 바이트에는 PostgreSQL 프로토콜 제어 응답도 포함하며 본문 크기·네트워크 패킷 수와 구분한다. VLE 내부 본문·식별자·간선별 작업량은 미측정 `-1`을 유지한다. warm-cache 반복을 독립 품질 표본이나 운영 기본값 채택으로 해석하지 않는다.

### 적대적 평가의 실행·집계 경계

`FR-AGENT_CONTEXT-154`의 표본·진단·복구 계약은 [적대적 시험 설계](testing.md#관계경로-오염-적대적-평가와-홉별-진단)를 따른다. 실행은 10회로 제한하고 생략된 조회 시각은 실행 시작 시각으로 고정한다. 기준선·공격 전·공격 후·복구 후 모두 전체 불변식 감사를 통과해야 하며, 공격 전 응답의 key·순위·간선·진입점이 별도 기준선과 다르면 공격을 적용하지 않고 실패한다. 일부 검색 채널 실패도 실행을 중단한다. 비활성 채널과 진입점이 없는 정상 빈 결과는 장애로 세지 않는다.

대상 질의 ID 중복과 같은 식별자의 반환·제외 동시 요구를 거부한다. 관계 성공 조건은 기준·추가 관계만 참조하고 정상 기대 경로는 관계를 하나 이상 포함한다. 관계 삽입의 보조 컨텍스트는 관계 끝점인 추가 사건에서 선언된 구성원·근거를 따라 도달할 수 있어야 한다. 상호 강화는 컨텍스트와 관계를 포함한 서로 다른 오염 식별자 둘 이상을 성공 조건으로 요구한다.

복구는 추가 관계 폐기, 참조 의존 순서에 따른 추가 컨텍스트 폐기, 정상 관계 재확정 순서로 실행한다. 표본별 판단 표식으로 각 복구 연산의 적용 성공 기록을 확인하고 결과에는 확인 여부만 남긴다. 진단 전후 응답은 그대로 보존하며 자동 변경이나 운영자 그래프 복구를 호출하지 않는다.

질의·표본 쌍별 반복 평균을 먼저 구하고 같은 `independent_unit`에 속한 값을 합쳐 독립 단위별 대응 차이로 구간을 계산한다. 생략한 자체 질의는 질의 ID를 독립 단위로 쓴다. 오탐률은 통제 질의별 반복 평균을 같은 방식으로 묶는다. 영향 질의 수와 전체 대상 질의 수는 같은 질의가 여러 표본에 등장해도 고유 질의로 세고, 영향 여부는 같은 회차의 표본 간 합집합으로 계산한다. 질의·표본 쌍 수는 별도로 남긴다. 표본이나 성공한 추적 대상이 없으면 `-1`, 독립 단위 하나면 평균·차이만 보존하고 구간은 `-1`이다.

### 실행 명세와 데이터 준비

시험마다 별도 실행 명세를 고정하여 데이터 준비→파생 생성→그래프 적재→색인 준비→교차 실행→독립 단위 집계→판정→정리 순서로 수행한다. 기존 평가 실행기의 모드 배타성·유한 처리 상한·정리 실패 전파를 모든 추가 비교에도 적용한다. 새 입력 필드와 모드는 구현 때 계약 검증을 추가하며 현재 CLI에서 지원한다고 가정하지 않는다.

| 실행 명세 영역 | 필수 값 |
|---|---|
| 입력 판 | 공식 저장소 커밋, 데이터 파일 SHA-256, 전처리·분할·정답·근거 매핑 판 |
| 평가 단위 | dataset·비식별 conversation/task/query 코드, 유형, 독립 집계 단위 |
| 생성·검색 | 에이전트·프롬프트·임베딩 모델·차원·압축, 색인 대상·그래프 단계·선택 정책·임계값 |
| 자원 | 문자 예산, 실행·처리 상한, 10회 반복, 실행 순서·지원 seed, 준비·캐시 조건 |
| 정답 경계 | 정답·근거 주석의 별도 저장과 평가 전용 접근, 제외 표본·사유·개수 |
| 비용 | 단가 판·산정일·통화, 호출·저장량 배분 방법, 미측정 항목 |

주 평가는 `longmemeval_s.json` 500문항이고 사실·시간·갱신·여러 세션 종합·답변 유보를 분리한다. 보조 평가는 `data/locomo10.json`의 10개 대화·텍스트 질문·근거 주석이며 이미지 해석을 제외한 수와 이유를 보고한다. 사건 관계·근거 상태·격리·복구·오염·인계는 자체 보완 세트로 별도 판정한다.

원천은 발화·턴을 그대로 보존하고 발생 시각·origin·source_ref를 구성한다. 원본 데이터 판과 세션·턴 식별자는 시험 내부 매핑에 고정하고 공개 결과에는 비식별 코드만 남긴다. 질의·정답·평가용 주석을 기억 컨텍스트나 임베딩에 넣지 않는다. 근거 주석 없는 표본은 근거 검색의 정답 없음으로 만들지 않고 해당 지표의 미평가와 분모를 표시한다. 전처리 실패·제외는 사전에 고정한 규칙으로 처리한다.

### 공개 데이터 준비 입력·분리 계약

`cmd/eval -prepare-data longmemeval|locomo|own-supplement -prepare-source <로컬 원본> -prepare-out <새 디렉터리>`는 DB·외부 제공자 없이 데이터를 준비한다. 자체 보완 세트는 원본 경로를 받지 않는다. 준비 모드는 다른 실행 옵션과 배타적이며 고정 원본의 SHA-256·전체 문항/대화 수·필수 필드를 검증한 뒤에만 새 디렉터리를 만든다. 기존 디렉터리를 덮어쓰지 않는다. 고정 판·사용 조건·checksum은 [준비 구현](../../../../cmd/eval/prepare.go)과 공식 출처 기록으로 추적한다. 원본 판 LongMemEval_S와 cleaned 판을 혼용하지 않는다.

`memory.json`은 비식별 그래프 단위별 원천 발화/턴·시각·출처만 담는다. `evaluation-private.json`은 질의·정답·근거 키·주석 상태·시각과 보완 시나리오, `mapping-private.json`은 원본 문항/대화/세션/턴·발화자와 코드의 대응을 담으며 모두 평가 전용 로컬 입력이다. 디렉터리는 0700, 파일은 0600으로 생성하며 이 세 파일과 원본은 공개 산출물에 포함하지 않는다. 공개 가능한 `preparation.json`에는 판·checksum·사용 조건·단위/유형별 수·제외 코드/사유·근거 미평가 분모와 파일 checksum만 남긴다. 준비 파일의 집계·checksum·독립 단위·제외 항목은 `-prepared-input`의 통제 비교에 연결한다. 실행 manifest 자동 적용·입력/구성 대조와 최종 보고는 EVAL-13에서 완료한다.

LongMemEval은 모든 역사 세션의 발화를 보존하고 원본 역할을 비공개 매핑에 남긴다. 답변 유보는 별도 유형이며 근거 지표는 비해당이다. `_abs`와 원 문항은 같은 과업·독립 단위로 묶는다. 답변 가능한 문항의 근거는 정답 세션 안의 `has_answer` 주석이 있는 턴으로만 매핑하고 일부 정답 세션의 주석이 없으면 문항 전체의 근거 지표를 미평가한다. 빈 세션·반복 세션 식별자·빈 발화는 수를 보고하고 원래 위치를 매핑에 보존한다. 빈 발화는 본문 없는 컨텍스트를 만들지 않고 비공개 매핑에 그대로 둔다. 질문·정답·주석으로 파생을 생성하지 않는다.

LoCoMo는 대화별로 격리하고 턴의 `text`만 원천으로 보존한다. 이미지·검색어·자동 이미지 설명·요약·관찰은 기억에 넣지 않는다. 보수적인 텍스트 범위 정책으로 이미지가 연결된 턴을 근거로 지정한 문항은 `image_evidence`로 제외한다. 정규 `D세션:턴` 형식 밖의 근거 또는 존재하지 않는 참조는 원본을 추정 교정하지 않고 해당 문항의 근거 지표를 미평가하며, 빈 주석도 같은 원칙을 적용한다. 답변 유보 문항의 `adversarial_answer`는 정답으로 쓰지 않는다. 시각만 있는 세션도 매핑과 수를 보존하고 본문을 만들어내지 않는다. 시각의 시간대는 원본에 없으므로 UTC 표기를 정규화 기준으로만 사용하고 턴별 시각을 만들어내지 않는다. 공개 벤치마크 원천의 출처는 `external_content`로 둔다.

자체 보완 세트는 사건·근거 상태·다른 그래프 격리·폐기 후 복구·외부 오염 되짚기·행위자 인계를 여섯 독립 과업으로 고정하고 초기 컨텍스트와 연산/기대 상태를 별도 저장한다. 데이터 준비 검증과 실제 시나리오 실행·검색 품질 인수를 구분하며 과거 자체 결과로 공개 평가를 대체하지 않는다.

### 실행 manifest 입력 계약

`cmd/eval -check-manifest <파일>`은 실행 전 명세만 읽어 검증한다. 스키마 판은 `1`이며 허용 필드와 형식은 [manifest 입력 타입](../../../../cmd/eval/manifest.go)이 소유한다. 알 수 없는 필드·중복 JSON 키·누락/null인 필수 값·잘못된 모드·수치 범위를 거부한다. 파일은 최대 4 MiB이며 컨텍스트·질의·정답 파일, DB와 외부 제공자에는 접근하지 않고 출력 파일도 만들지 않는다. 성공은 명세 검증 완료일 뿐 데이터 checksum 대조·색인 준비·실제 측정 완료가 아니다. 이들은 EVAL-02 이후 작업에서 해당 명세를 입력으로 연결한다. 기존 직접 실행 CLI와 manifest 검사 모드는 함께 지정할 수 없다.

명세는 입력별 dataset 코드·판·저장소 commit·SHA-256, 전처리/분할/정답/근거 매핑 판과 비식별 질의별 대화 또는 과업·독립 단위를 고정한다. 같은 대화/과업의 문항은 같은 독립 단위에 속하고 서로 다른 대화/과업은 같은 독립 단위로 합치지 않는다. 정답·근거의 평가 전용 분리 정책, 전체 질의 수와 제외 코드·사유를 명시한다. 입력 경로나 원문·질의·자격은 명세 필드에 포함하지 않는다. 변환 모드는 원본, 업무 모드는 업무 입력, 나머지 모드는 컨텍스트·질의의 checksum 선언을 요구하고 적대적 모드는 공격 표본도 요구한다. 입력별 checksum은 선언 형식만 검증하며 실제 파일 대조는 데이터 준비가 담당한다.

모델·프롬프트 판·차원·벡터 표현, 검색 단계·색인 대상·임계값·문자/홉/후보 예산, 실행/색인 처리 상한과 timeout, 준비/캐시 정책, 조건별 10회·회차 안의 순환 순서와 지원 seed를 고정한다. seed 미지원은 값 없이 명시하고 지원 시 0을 포함한 실제 정수를 요구한다. 단가 판·산정일·통화·배분 판과 비용 항목의 `measured`/`unmeasured`/`not_applicable` 상태를 구분한다. 측정한 0은 값으로 보존하고 미측정·비해당에는 값을 넣지 않는다. 이 입력은 비용 산식·최종 산출물 공개를 대신하지 않는다.

모드는 `basic`, `convert`, `business`, `continual`, `adaptive`, `consistency`, `adversarial` 중 하나다. 변환 옵션은 변환 모드에만, 일관성 옵션은 일관성 모드에만 둔다. `own-adversarial`의 사용 사례 필터와 일관성 후보 상한 24 이하는 거부한다. 기존 CLI에서도 모드·변환·일관성 옵션과 수치 전제를 데이터 입력 읽기·DB·파일 생성 전에 검증한다. 직접 실행의 기본·허용 반복은 10회이며 집계 통계의 최소 유효 표본 수와 구분한다.

### 반복·통계와 실행 순서

조건마다 10회를 수행하고 A/B 조건을 같은 회차 안에서 교차 배치한다. 매 회차 모델·예산·데이터·준비·캐시를 같게 하고 생성 비용·색인 준비 시간은 측정 구간 밖의 별도 항목으로 남긴다. 조건마다 전용 평가 그래프를 사용하며 이전 회차의 상태를 다음 조건에 섞지 않는다.

질의·과업별 10회 값을 먼저 평균한다. 같은 대화의 문항은 대화 단위로 묶고 독립 대화·과업별 대응 차이로 95% Student t 구간을 계산한다. 반복 수와 문항 수를 독립 표본 수로 쓰지 않는다. 유효 독립 단위가 둘 미만이거나 구간이 채택 기준을 가르면 판정 보류다. 추가 시험은 목적·표본·회차를 사전에 기록한 별도 실행으로 만들고 최초 결과를 덮어쓰지 않는다.

직접 질의 입력의 `independent_unit`은 같은 대화·과업 문항에 동일한 비식별 코드를 지정한다. 생략한 기존 자체 입력은 질의 ID별 독립 과업으로 해석하며 공개 데이터는 준비 단계의 독립 단위를 명시적으로 연결한다. 기본·적응형 비교의 결과 집계 전에 단계별 1~10회·회차별 고유 질의·동일 질의 집합과 독립 단위 매핑을 검증한다. 누락·중복·변경은 정상 보고서 기록을 중단한다.

지표별로 열 회차가 모두 측정된 질의만 반복 평균을 계산하고, 비교 양쪽에서 같은 질의가 유효한 경우에만 독립 단위 안에서 평균한다. 이 독립 단위들을 같은 가중치로 집계하며 사용 사례별로 분리한다. 유효 독립 단위 수·자유도·미측정 또는 표본 부족 상태를 남긴다. 표본이 없으면 평균·차이도 `-1`, 하나면 평균·차이는 보존하고 표준편차·구간은 `-1`이다. 한계 기여는 같은 회차의 회수 집합 차이를 질의별로 평균하며 첫 회차만을 전체의 대표값으로 쓰지 않는다. 필수 컨텍스트와 필수 관계는 각각 고유 집합으로 세어 겹친 기대 경로가 근거 분모를 늘리지 않게 한다.

외부 유료 호출·원천 전송·공개 데이터 다운로드의 실제 실행은 별도 실행 권한 범위이며 이번 설계 작성에 포함하지 않는다. 단가·수치·다운로드 checksum은 실제 준비 시 확인하며 설계 문서에서 가짜 값을 채우지 않는다.

### 검색 단위 완전성 비교

`FR-AGENT_CONTEXT-160`은 원천을 유지한 채 현행 파생 경계와 의미 요소를 완결하는 파생 경계를 비교한다. 같은 모델·프롬프트 계열·원천·질의·예산·그래프 설정을 사용하고 경계 정책 하나만 바꾼다. 파생은 에이전트가 생성하며 서버에 자동 요약·AST 분할을 추가하지 않는다.

시험 내부 표본 명세에 주체·조건·예외·부정·선행 참조·다중 턴 결정의 필수 요소와 실제 근거를 고정한다. 평가자가 원천과 파생을 대조하여 모든 필수 요소와 `derived_from`이 보존됐는지 판단한다. 자동 판정기는 모델·프롬프트 판과 사람의 표본 검토 결과를 함께 기록한다. 코드·문서 표본은 대화 표본과 별도로 집계한다.

두 조건에서 완전성, 검색 품질, 파생 수·색인 호출 수·벡터 바이트와 과업 성공률·총비용을 수집한다. 완전성·품질·성공률 악화 없이 예산 효율 또는 비용 개선을 판정한 경우에만 기본 생성 지침의 후보가 된다. 특정 AST 파서·조각 크기를 이 설계에서 운영 방식으로 확정하지 않는다.

#### 검색 단위 비교의 실행 입력과 결과

`cmd/eval -unit-comparison 입력.json -out 결과.json`은 `current`·`semantic` 두 경계 조건을 10회 순환 실행한다. 다른 실행 모드·직접 contexts/queries·검색 설정 flag와 함께 지정하지 않는다. manifest 사전 검사의 모드는 `units`, 입력 역할은 `unit_comparison`이며 사전 검사만으로 실제 실행이나 checksum 실물 대조를 대신하지 않는다.

- 입력의 `agent`는 생성 에이전트 판·모델·공통 프롬프트 계열을, `judge`는 자동 판정기 판·모델·프롬프트 판을 고정한다. `policies`는 서로 다른 경계 정책 판만 지정한다. `search`는 그래프 단계·문자/홉/노드 예산·색인 대상·임베딩 모델 식별자·채널 실행·후보 상한·두 유사도 하한을 고정하며 실행 환경과 다르면 DB 접속 전에 거부한다.
- `samples[].code`는 독립 대화 또는 과업 코드다. 같은 대화·과업의 질의는 하나의 표본에 묶는다. `cohort`는 `conversation` 또는 `code_document`이며 대화 원천과 파일 등 비대화 원천을 섞지 않는다. 각 표본의 원천 본문·출처·시각·공유 질의와 명시적 조회 시각은 한 번만 선언하고 두 조건이 공유한다. 조건별 파생은 본문·근거 범위·수만 바꾸며 종류·신뢰·유효 기간 등 다른 속성은 고정한다. 이 비교의 파생 근거는 공유 원천을 직접 가리킨다.
- `required_elements`는 비식별 요소 코드·종류·검토할 의미·원천 근거를 고정한다. 종류는 주체·조건·예외·부정·선행 참조·다중 턴 결정이다. 조건별 `reviews`는 모든 파생의 필요한 요소·보존한 요소와 검토 입력 SHA-256을 연결한다. 해시는 판정기 판·모든 원천·요소 명세·파생·필수 요소를 포함한다. 주석은 그래프나 임베딩에 적재하지 않는다. 자동 판정기와 사람의 검토는 외부에서 수행한 결과를 입력하며, 실행기가 모델이나 사람을 대신해 의미 보존을 추정하지 않는다.
- 사람 표본 검토에는 검토자 코드·검토 판·보존 요소를 기록한다. 사람 판정이 있으면 완전성 계산에 우선하고 자동 판정과 불일치 수를 별도로 남긴다. 모든 필수 의미 요소와 그 원천 `derived_from`이 보존된 파생만 완전한 것으로 센다. 조건마다 요소 전체 범위를 검토해야 하며 누락된 요소를 분모에서 지워 완전성을 높이지 않는다.
- 조건별 `task_runs`는 회차 1~10의 외부 에이전트 과업 trace 판·입력 해시·성공 여부·총비용을 연결한다. 과업 해시는 생성 에이전트·원천·질의·파생·경계 판·검색 설정·정답 매핑·표본 코드를 포함한다. 총비용은 같은 `pricing_version`·통화에서 생성·임베딩·요약·검색·저장을 모두 포함한 금액이며 생략은 미측정이다. 검색 정답 반환을 과업 성공으로 바꾸지 않는다. 보고서의 `imported_task_trace`는 가져온 기록이며 이번 CLI에서 과업을 재실행했다는 뜻이 아니다. 입력의 `provenance`로 합성 기록과 실제 에이전트 trace를 구분한다.

조건·표본·회차마다 독립 그래프에 원천과 해당 파생을 적재하고 색인 전체 준비·문서 임베딩 HTTP 시도·현재 모델 벡터 행/열 바이트를 실측한다. 부분 채널 실패·취소·정리 실패는 정상 보고서 생성을 중단한다. 결과에는 본문·질의·원천 locator·요소 설명을 넣지 않고, 판·코드·입력 해시·자동/사람 검토 기록과 지표를 남긴다. 해시 구성과 입력 자료형은 [실행 입력](../../../../cmd/eval/unit_input.go), 합성 작성 예는 [모듈 표본](../../../../cmd/eval/unit_comparison_test.go)에서 확인한다.

두 표본군은 별도로 집계한다. 완전성 총계는 고유 파생 중 완전한 파생 비율이며, 대응 검정은 표본별 완전성·준비량·과업 반복 평균을 독립 단위 하나로 사용한다. 검색 지표도 질의 반복 평균→독립 대화/과업 평균 순서다. 10회 반복과 한 과업의 여러 질의를 독립 표본으로 늘리지 않는다. 한 회차라도 과업 지표가 미측정이면 해당 표본의 그 지표는 `-1`로 남긴다. 독립 단위 하나의 구간도 `-1`이다. 검색 단위 완전성은 반환 근거 완전성과 별도 필드다.

완전성·검색 품질의 유의한 악화 또는 과업 성공률 하락은 거부한다. 표본 부족·검색 근거 주석 누락·과업 미측정·사람 검토 부재/불일치·합성 기록은 후보 판정을 보류한다. 실제 trace에서 품질 악화 없이 예산 사용량 또는 완전한 총비용이 유의하게 줄면 통제 비교 후보로만 남긴다. 비용이 미측정이고 예산 개선도 확인하지 못하면 보류한다. `default_activation`은 항상 false이며 공개 실증·최종 채택은 후속 인수다.

### 외부 원본 재현성 비교

`FR-AGENT_CONTEXT-161`의 외부 재조회는 서버가 아닌 권한을 가진 격리된 평가 도구에서 수행한다. 입력은 고정 판·범위가 있는 URI와 원본 변경·이동·삭제·권한 상실·일시 장애의 통제 표본이다. 원천 생성 전에 수집 도구가 locator를 구성하며 서버는 URI scheme·길이만 검사한다.

평가 도구는 수집 당시 내용과 재조회 내용을 비교하고 고정 판·범위 식별 가능 비율과 실제 내용 일치율을 별도로 산출한다. 유효 URI·접속 성공·변경된 최신 내용만으로 재현 성공을 판정하지 않는다. 실패 사유와 미측정을 비식별 표본 코드로 기록하고 URI·원문·자격 증명을 결과에 싣지 않는다. 서버의 source_ref·MCP 스키마에 새 재조회 상태 필드를 넣지 않고 실패한 원천·근거를 수정·폐기하지 않는다.

#### 외부 원본 비교 실행 계약

`cmd/eval -original-reproduction 입력.json -out 결과.json`은 DB·임베딩 설정 없이 실행하는 격리 HTTPS 평가 모드다. 다른 실행 모드·직접 데이터·검색 옵션과 함께 지정하지 않는다. manifest 검사에서는 모드 `originals`·입력 역할 `original_reproduction`을 사용하며, manifest 검사 성공은 실제 원본 재조회 완료가 아니다.

수집 도구는 저장 원천을 생성하기 전에 출처가 제공한 판을 URI의 query 값 또는 경로 segment에 고정하고, 비교할 원본 바이트 범위를 `#bytes=시작-끝` fragment로 구성한다. 범위는 0부터 시작하며 끝은 포함하지 않는다. 이는 평가 도구의 최초 HTTPS 어댑터 계약이며 서버의 URI 해석 규칙이 아니다. Git 커밋 경로·문서 판·API 판 등 출처별 의미와 접근 권한은 수집 도구가 확인한다. URI에 판이 들어 있다는 사실을 출처의 불변 보증으로 승격하지 않는다.

비공개 입력은 수집/어댑터 판, 합성 또는 권한 있는 실제 출처 구분, 승인한 HTTPS origin과 선택적 Bearer 자격 환경 변수 이름, 표본·독립 단위·통제 유형·locator를 담는다. 수집 당시 전체 HTTP 본문 파일과 SHA-256을 입력 디렉터리 아래에 보관하고, 판 결합 위치/값과 선택적 응답 판 확인 헤더를 연결한다. 판 헤더는 `ETag` 또는 `X-Source-Revision`이며 강한 ETag만 확인 대상으로 쓴다. snapshot이 없으면 내용 비교를 미측정으로 유지한다. 파일을 지정했는데 없거나 checksum·범위가 다르면 접속 전에 실패한다. 원문·URI·자격 값은 보고서에 넣지 않는다.

모든 입력·snapshot·자격을 검사한 뒤 표본별 10회 GET을 순환한다. 시간 제한·응답 크기·총 요청 상한을 입력에서 고정한다. fragment를 요청에 보내지 않고 전체 본문을 받은 뒤 같은 바이트 범위를 추출해 수집 당시 바이트와 정확히 비교한다. 범위 없는 입력은 전체 본문을 비교할 수 있지만 판/범위 동시 식별 표본으로 세지 않는다. 인코딩 변환이나 최신 본문으로 snapshot을 갱신하지 않는다. HTTP 200만 내용 비교 대상으로 쓰고, redirect는 따라가지 않으며 이동으로 기록한다. 부분 응답·지원하지 않은 내용 인코딩·본문 절단·초과 응답도 일치 성공으로 표시하지 않는다.

연결 성공, 판 확인 결과와 내용 일치 결과를 서로 다른 필드로 남긴다. 판 헤더가 다르면 내용이 같아도 판 불일치 상태를 보존한다. 내용 변경·이동·삭제·권한 상실·일시 장애·시간 초과·전송/본문 실패·범위 누락·snapshot 미측정을 코드로 구분한다. 개별 조회 실패는 전체 재조회 시도의 분모에 남기고 다음 시도를 진행하며, 프로세스 취소는 정상 보고서 기록을 중단한다. 자동 재시도를 추가하지 않는다.

집계는 전체 표본 중 URI의 판과 범위를 모두 식별한 비율과 전체 GET 시도 중 원본 내용 일치 비율을 각각 보고한다. 고정 판이 없는 출처도 이번 시도의 내용 일치 여부를 별도로 남긴다. 비교하지 못한 시도는 일치 0건으로 분모에 포함하되 내용 불일치와 미측정 건수를 구분한다. 95% 구간은 질의/반복 수 대신 독립 단위별 반복 평균에서 계산하며 하나인 경우 `-1`이다. 원천·근거 그래프·MCP 스키마·서버 수집 동작은 이 도구의 산출물이 아니다.

### 임베딩 순위와 임계값 비교

`FR-AGENT_CONTEXT-162`는 모델·차원·압축 중 하나만 바꾸고 모든 다른 표현·질의·정답·예산·검색 설정을 고정한다. 각 구성은 별도 그래프에 전체 재색인하여 다른 모델의 벡터를 섞지 않는다.

검색과 임계값 품질이 모두 유의하게 나빠지지 않고 비용 또는 지연이 개선되어야 운영 후보로 채택한다. 별도 관계 벡터·이진 양자화·FP16·질의/문서별 전처리는 비교 대상을 확정한 것이 아니며 시험 명세에서 선정하고 검증한다.

#### 임베딩 비교 실행 계약

`cmd/eval -embedding-comparison 입력.json -out 결과.json`은 두 구성의 모델·차원·저장 표현 중 정확히 한 축을 비교한다. 입력은 구성별 제공자/모델·차원·vector 또는 halfvec와 비공개 접속 환경 변수 이름, 공통 검색 설정·명시적 조회 시각·조정/최종 표본을 고정한다. 현재 제공자의 지원 범위를 넘는 모델이나 표현은 사전에 거부한다. 표현 비교의 halfvec는 시험 후보이며 운영 채택이 아니다. 서로 다른 차원/표현은 미리 준비한 별도 DB를 사용하며 실행기가 스키마를 변경하지 않는다. 모든 구성·표본·환경을 검사한 뒤 접속하고, 모든 DB의 스키마 검사가 끝나야 적재를 시작한다.

표본은 독립 대화/과업 코드, 원천·파생·사건, 검색 정답/필수 근거와 질의별 전역 전환 필요 여부를 담는다. 사건 anchor 하나와 다른 모든 사건의 관련성 정답을 완전 주석한다. 독립 단위와 원천 locator가 조정/최종 집합 사이에 겹치면 거부한다. 조정과 최종 단계 모두 조건·표본·회차별 새 그래프에 전체 색인하고 10회 순환한다. 준비/채널/취소/정리 실패는 정상 보고서를 중단한다.

조정 단계는 저장된 사건 벡터의 실제 코사인 거리와 진입 검색 신호를 측정한다. 관계 후보는 anchor의 점수 하한 통과 후 유사도/식별자 순서로 고정 상한까지 선택하는 읽기 전용 판정이며 관계를 생성하지 않는다. 자동 전역 전환은 keyword 후보가 없고 의미 후보도 구성별 하한을 넘지 못할 때 필요하다는 현행 규칙을 재현한다. 각 구성에 명시한 후보 하한들을 독립 단위별 평균으로 비교해 관계는 F1 최대, 전역은 오통과율/오탈락률의 평균 최소로 고른다. 동률은 큰 하한을 선택한다. 최종 정답과 최종 측정은 조정에 사용하지 않으며, 선택 값이 우연히 같아도 구성별 조정 근거를 보존한다.

최종 단계는 고정한 하한으로 실제 검색을 실행하고 순위·근거·문자/지연 및 관계 정밀도/재현율/후보 수, 전역 오통과/오탈락을 별도로 보고한다. 오통과는 불필요한 전역 전환/불필요한 표본 수, 오탈락은 필요한 전환 누락/필요한 표본 수다. 해당 분모가 없으면 -1이다. 반복→질의/표본→독립 단위 평균과 대응 Student t 구간을 사용한다. 준비·검색의 HTTP 시도와 지연, 벡터 행/열 바이트를 실측하며 금액은 미계측이면 -1로 유지한다. 공개 본문·질의·locator·접속/자격 환경 값을 결과에 싣지 않는다. 실제 출처에서 사용 사례별 검색과 두 임계값 품질이 유의하게 악화되지 않고 비용/지연이 유의하게 개선될 때만 통제 비교 후보로 남긴다. 합성·표본/주석 부족은 보류하고 `default_activation`은 항상 false다.

### 에이전트 업무 비용과 축소 비교

`FR-AGENT_CONTEXT-163`은 기존 네 업무 지표의 집계 실행과 별도의 확장 입력·판정을 요구한다. 기존 `-business` 입력 계약이 새 토큰·성공률·총비용 필드를 이미 지원한다고 표시하지 않는다.

입력·출력·캐시 읽기·캐시 쓰기 토큰을 제공자의 과금 범주대로 분리한다. 비용 항목은 에이전트·임베딩·요약 호출, 검색·저장이고 준비·재색인 비용과 반복 실행 비용을 분리한다. 각 항목에는 측정값 또는 미측정 상태와 단가·통화·산정일·공유 색인 배분 기준을 둔다. 항목이 미측정이면 0으로 채우거나 완전한 총비용이라고 표시하지 않는다. 문자 예산을 토큰으로 바꾸지 않는다.

추가 비교는 조회 유무를 고정한 채 무관한 컨텍스트 추가 효과와 원문 유지/LLM 요약/관찰 마스킹 효과를 각각 분리한다. 마스킹은 활성 모델 입력에서 과거 도구 관찰을 제외하는 시험이며 저장 원천 삭제나 서버 응답 자동 절단이 아니다. 요약 비용·필수 근거 재조회도 함께 측정한다. 내부 추론·원문 실행 이력·개인 행동 식별자를 수집하지 않는다.

확장 실행은 `-business-tasks 입력.json`으로 외부 통제 과업의 비식별 집계 trace를 가져온다. 이번 CLI가 에이전트 과업을 다시 실행했다는 뜻은 아니며 `imported_task_trace`와 `synthetic`/`agent_trace` 출처를 명시한다. 판 1 입력의 `experiment`는 `lookup`(without_context/with_context), `irrelevant`(relevant/irrelevant), `reduction`(original/summary/masked) 중 하나다. 조회 비교는 원문·무관 컨텍스트 없음으로, 나머지는 조회 있음·같은 관찰 이력 해시로 고정한다. 공통 모델/에이전트·프롬프트·도구·성공 조건 판·준비/캐시 정책·실행 한도·문자 예산과 과업 입력 SHA-256을 선언한다. 과업 유형은 세션 재개·협업 인계·사실·다중 근거를 구분한다. 같은 독립 단위의 과업은 먼저 평균하고 10회 반복을 독립 표본으로 늘리지 않는다. 회차별 조건 순환 순서를 입력 기록과 대조하며 중복·누락 회차는 거부한다. 같은 과업 입력 해시를 서로 다른 독립 단위로 나누지 않는다. trace 결합 해시는 `businessTaskHash`의 결정적 JSON으로 공통 통제·과업·조건·단가 판을 함께 고정한다. 비용/사용량은 측정 0을 허용하고 누락·null과 구분한다.

각 과업·조건·회차는 성공/실패/timeout/취소, 전체 경과 시간·모델 턴·도구 호출·사용자 개입·필수 근거 재조회 수와 가능 여부를 기록한다. 비용은 preparation/reindex/execution의 세 구간과 agent/embedding/summary/search/storage의 다섯 항목을 모두 선언한다. 각 항목은 measured/unmeasured/not_applicable이며, 측정 항목은 사용량·단위당 단가·배분율을 가진다. 호출 항목은 겹치지 않는 input/output/cache_read/cache_write 토큰 네 범주, 검색/저장은 판으로 식별한 과금 단위의 사용량을 받는다. 제공자 원시 통계에 캐시가 포함되면 수입 전에 중복을 제거하며 문자 수에서 추정하지 않는다. 항목 금액은 Σ(사용량×단가/단가 기준 사용량 `unit_size`)×배분율이고 공유 준비/재색인 배분은 allocation_version으로 고정한다. 단가 판·통화·산정일·실제 단위와 계산 금액을 결과에 보존한다. 단가의 범주별 null은 가격 미측정이며 실제 사용량은 그대로 보존하되 금액은 -1이다. 사용량의 누락·null은 측정 0으로 받지 않는다. 미측정 항목이 하나라도 있으면 구간/총비용은 -1·unmeasured로 두고 알려진 소계만 별도로 남긴다. 준비/재색인/실행 토큰을 각각 보고하며 전체 토큰에는 요약 준비 사용량도 포함한다. 원시 사용 토큰과 배분된 금액은 별도 단위로 유지한다. 각 회차의 `index_state`는 initial/prepared이고 대응 조건 사이에 같아야 한다. `preparation_ms`·`reindex_ms`의 생략은 -1이며 실행 시간에 더하지 않는다. 시간 초과의 실제 종료 지연은 실행 한도로 잘라내지 않는다.

전체/성공만 지표·상태별 실제 실행 수, 반복→과업→독립 단위 평균의 대응 Student t 95% 구간과 지표별 개선/악화를 보고한다. 일부 단위만 측정된 추정량은 partially_measured와 실제 표본 수를 남긴다. 세 과업 미만, 독립 단위 부족, 합성 trace, 준비 시간·토큰·총비용 미측정 또는 축소 조건의 필수 근거 재조회 불가는 후보 판정을 보류한다. 성공률의 유의한 악화는 거부한다. 완전한 관측에서 시간·턴·토큰·총비용의 유의한 개선을 후보로만 남기며 다른 지표 악화도 함께 공개한다. `default_activation`은 항상 false다. 개인 식별자·본문·내부 추론·원문 이력을 받는 필드는 없고 알 수 없는 필드는 안전한 오류로 거부한다. manifest의 모드/입력 역할은 `business_tasks`이며 실물 checksum 연결과 원자적 최종 공개는 EVAL-13에서 인수한다.

### 산출물과 종료 조건

| 산출물 | 내용·검증 |
|---|---|
| `manifest.json` | 고정 입력 판·구성·비식별 시험 ID·독립 단위·반복·통제·제외 정책. 허용하지 않은 필드는 거부 |
| `preparation.json` | 원천·파생·색인 준비 수, 미완료·실패, 준비 시간·비용과 데이터 checksum 대조 결과 |
| `summary.json` | 유형별·독립 단위별 집계, 조건 차이·95% 구간, 미측정·판정 보류·채택 판정 |
| `cost.json` | 항목별 실제 사용·단가 판·완전성, 준비/실행 비용 구분. 자격·개인 정보 제외 |
| 실패 보고 | 안전한 단계·원인 코드·완료 회차·정리 결과. 정상 평가 결과와 구분 |

결과는 임시 파일에 완전한 JSON을 쓴 뒤 검증·원자적 rename으로 공개하고 기존 시험 ID의 파일을 덮어쓰지 않는다. 실패·준비 미완료는 정상 `summary`를 기록하지 않는다. 취소·내부 실패에도 독립 10초 정리 context로 평가 그래프를 소프트 삭제하며 정리 실패를 원래 원인과 함께 종료 오류로 전달한다. 시험 결과 파일에는 본문·질의·URI·대화 원문·자격 증명과 개인 식별자를 남기지 않는다.

#### manifest 실행과 결과 묶음

`cmd/eval -manifest 실행.json -results 결과루트 -trial-input 입력코드=로컬파일`은 manifest의 각 입력 코드를 실제 파일에 연결한다. 이 모드는 기존 개별 실행 옵션과 혼용하지 않으며 변환은 측정 묶음으로 실행하지 않는다. 준비 입력은 `-trial-prepared 준비디렉터리`로 연결하며 contexts/queries/preparation 역할을 각각 memory.json/evaluation-private.json/preparation.json에 대응한다. 직접 입력은 `direct-v1` 매핑·제외 정책과 제외 항목 없음으로 한정한다. 준비 입력은 준비 보고서의 매핑·고정 commit·문항·제외·대화/과업·독립 단위를 그대로 대조한다. 내장 지속 평가의 입력 역할은 continual_scenarios이며 `입력코드=builtin:continual-v1`로 고정 시나리오의 결정적 JSON checksum을 대조한다.

입력 역할을 복사 전에 검사하고 일반 파일을 최대 512 MiB씩 비공개 임시 디렉터리에 복사하며 복사한 바이트의 checksum을 검증한 뒤 해당 스냅숏으로 실행한다. 판·모델·문자/홉/후보 예산·실행 순서·준비/캐시·단가 판과 독립 단위를 대조하고 원본 비교의 로컬 수집 파일도 포함한다. 직접 검색의 단위 코드는 query의 independent_unit(없으면 id)을 과업 코드로 사용한다. 검색 단위/임베딩 비교는 표본코드.query코드를 문항 코드로 사용한다. 지원을 확인하지 못한 seed 선언은 거부한다. 실제 검색 구성은 환경에서 읽어 대조하며 자동으로 바꾸지 않는다. 그래프 모드의 준비/캐시 판은 `fresh_graph_no_explicit_warmup_shared_cache`/`shared_db_os_cache`다. 모델/생성 프롬프트 등 실행기가 호출하지 않은 외부 생성기의 판은 입력 출처 선언이며 실물 checksum 대조가 외부 생성 과정을 재실행·인증했다는 뜻은 아니다.

manifest의 request_limit는 실제 검색 요청(일관성 후보는 재시도 전 논리 요청) 또는 원본 GET의 전체 상한이며 수입한 과업 기록을 실제 호출로 세지 않는다. index_round_limit는 각 그래프의 색인 소비 상한을 좁히며 timeout_ms는 입력 준비부터 끝나는 전체 실행 시간 예산이다. 개별 검색·원본 요청의 기존 시간 상한도 함께 유지한다. 실제 완료 조건/표본/회차와 생성 그래프·정리 시도/실패·잔여 그래프 수를 남기고, 예산 초과·준비 실패·정리 누락은 정상 결과를 만들지 않는다. 실패 보고는 원문 오류 대신 안전한 단계·원인 코드·완료 회차·정리 상태만 포함한다.

같은 시험 ID는 배타적으로 예약한다. 성공 묶음의 manifest/preparation/summary/cost 네 JSON을 임시 파일에 쓰고 다시 해석·검사·동기화한 뒤 macOS/Linux의 덮어쓰기 없는 디렉터리 rename으로 한 번에 저장한다. 기존의 빈 디렉터리·파일·심볼릭 링크도 교체하지 않는다. 지원하지 않는 운영체제는 안전하게 거부한다. 실행/준비/검증 실패는 manifest/failure만 저장하며 부분 summary와 비공개 입력을 공개하지 않는다. 원자적 rename 뒤 디렉터리 동기화 오류는 이미 저장된 결과를 보존한 채 공개 동기화 오류로 전달한다. 강제 종료로 남은 예약은 자동 탈취하지 않는다.

summary는 기존 모드의 전체 지표·신뢰구간·개선/악화와 최종 accepted/not_accepted/deferred를 함께 싣는다. synthetic 또는 unverified 출처·독립 단위 부족·필수 지표/실제 비용 미측정은 보류하고 명백한 품질/성공률 악화·채널 실패·지연 초과·격리/복구 실패는 비채택한다. 지속 평가의 `failed`는 상태·기록 위반과 유의한 품질 회귀를 구분하지 않고 출처·독립 단위 검사보다 먼저 not_accepted로 요약한다. 완전한 실제 과업 trace와 항목별 사용량/단가에서 유의한 업무 효율 개선을 확인한 경우에만 해당 통제 비교를 채택할 수 있으며 default_activation은 항상 false다. cost는 manifest의 금액 선언을 실제 사용 증거로 쓰지 않는다. 현재 항목별 실제 금액 근거가 있는 확장 업무 입력만 산정하며 다른 모드의 금액은 미측정으로 남긴다. manifest의 측정 상태/금액과 실제 산정 결과가 다르면 묶음 검증 실패다. 원본 출처 정책·공개 공격 저항성·실제 운영 채택은 해당 실증을 대신하지 않는다.

완료 결과의 재검사 입력은 128 MiB로 제한한다. 임베딩 비교의 semantic_similarity_threshold는 null로 두고 고정 입력의 구성별 격자에서 조정한 하한을 결과에 기록한다.

보류 뒤 추가 시험은 새 trial_id와 선택적인 followup의 parent_trial·purpose_code·planned_samples·planned_repeats로 목적·문항 수·10회를 사전에 고정한다. planned_samples는 manifest 문항 수이며 독립 단위 수와 구분한다. 이전 시험 결과를 덮어쓰거나 반복 수를 독립 표본으로 더하지 않는다. 기능 구현·합성 실행과 실제 공개 데이터/에이전트/유료 제공자 효과 실증을 구분한다.
