# #274 임베딩 비교 최종 단계의 질의 임베딩 중복 제거

## 결정과 변경

임베딩 비교의 최종(evaluation) 표본은 전역 전환 신호를 위해 질의를 임베딩한 뒤, 검색 측정(`measure` → `service.Flow`)에서 같은 질의를 같은 제공자로 다시 임베딩했다. 이 중복이 측정 HTTP 시도·지연에 합산되어 측정 비용 지표가 실제 검색 1회의 두 배로 보고되었다.

한 회차의 질의 벡터를 기록하는 `queryVectors`를 두어 최종 표본은 검색이 먼저 임베딩하고 신호가 그 벡터를 재사용하게 했다. 검색이 없는 조정 표본은 지금처럼 신호 단계에서 한 번 임베딩한다. 실패한 임베딩은 기록하지 않아 검색 단계의 질의 임베딩 장애는 기존처럼 의미 채널 실패로 정상 보고서를 중단한다. 의미·키워드 후보 SQL은 신호와 검색이 각각 실행하며, 이는 #273에서 맞춘 현재 시각 기준 신호를 유지하기 위한 것이다.

[평가 설계](../sdd/evaluation.md#임베딩-비교-실행-계약)와 [시험 설계](../sdd/testing.md)에 질의당 측정 HTTP 시도 기준과 회귀 시험을 명시했다. 결과 JSON 형식·신호 필드·검색 설정은 바꾸지 않았다. 요구사항·추적표·DOX의 소유권과 구성은 바뀌지 않아 유지했다.

## 검증

- 명령 통합 시험의 기대값을 실제 검색 기준으로 고쳤다. 조정·최종 회차의 측정 HTTP 시도는 모두 질의 수(2)이며 전체 시도는 320회에서 280회가 된다. 신호값·선택 하한·벡터 저장량과 부분 채널 실패·질의 실패·취소 정리 하위 사례는 그대로 통과했다.
- 검색이 질의를 다시 임베딩하던 이전 동작을 덧씌우면 같은 시험이 `actual HTTP attempts 320 != 280`으로 실패했다.
- 새 단위 시험은 질의 벡터 기록기가 성공한 임베딩만 재사용하고 실패는 다시 제공자를 호출하는지 대조한다.
- Go 1.27.3, 개발 DB 서버의 작업 전용 기준 DB vector(768)와 `.env`의 비교 DB `acs_small` vector(128)·`acs_half` halfvec(768)(각각 마이그레이션 001~014 적용), `TEST_DATABASE_REQUIRED=1`, `-p 1`의 필터 없는 `./cmd/eval` 실행: 934건이 실패·건너뜀 없이 통과했다.
- `check-go.sh`의 의존성 빌드·`go build`·`go vet`·`gofmt`·`govulncheck` 검사 통과.
- 검증 후 작업 전용 기준 DB를 삭제했다. 실제 유료 제공자 호출·운영 배포는 미실행이다.
