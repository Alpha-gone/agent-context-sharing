## 구현과 발견 사항

| 항목 | 근거·처리 | 상태 |
|---|---|---|
| 작업 텍스트 검증 누락 | 기존 Flow는 빈 문자열만 거부했다. `model.FlowInput.Validate`를 추가하여 공백만인 값·8000자 초과·잘못된 UTF-8·U+0000, UUIDv7·UTC·scope·음수 예산/홉 상한을 `FieldError`로 거부한다. 원문은 자르거나 정규화하지 않으며 유니코드 문자 수로 센다. | 해결 |
| 취소를 부분 성공으로 처리할 가능성 | 제공자 대기 뒤 요청 취소를 확인하여 새 스냅숏을 열지 않는다. 조립 중 취소도 호출자 원인과 Canceled 분류를 보존하고 성공 본문을 비운다. | 해결 |
| 스냅숏 종료 오류와 조립된 본문 동반 반환 | 요청 읽기 경계가 실패하면 읽기 자원 집계만 남긴다. 모든 채널 실패의 기존 채널별 실패 메타데이터는 보존한다. | 해결 |

`Store`·`Embedder`·`ConsistentStore`는 모델 타입과 context만 전달하고 DB 핸들을 노출하지 않는다. 질의 임베딩은 스냅숏을 열기 전에 끝내고 제공자 오류는 의미 채널만 실패시켜 남은 진입 채널을 실행한다. 명시 global은 질의 임베딩을 호출하지 않는 기존 경계를 유지한다. 미지정 as_of는 현재 UTC, scope는 auto이고 예산 0은 내부 플랜의 한도 없음이다. 계정별 상한 적용은 권한 경계가 소유한다.

저장소의 조정 스냅숏·읽기 트랜잭션·4개 연결 예약·3개 읽기 자리·경계 밖 접근 기록은 ARCH-04/DATA-03에서 정한 접근 경계를 사용한다. SEARCH-01 시험으로 아래 동작을 새로 확인했으며 저장 SQL·스키마·배포 구성과 운영 읽기 방식은 바꾸지 않았다. 평가용 Read Committed는 운영 구성 키가 아니다.

## 새 모듈 검증

- `input_snapshot_contract_test.go`: 잘못된 입력 12종은 제공자/스냅숏에 도달하지 않고 위반 필드를 보존한다. 한글 8000자를 그대로 제공자에 전달하며 성공·제공자 실패·대기 중 취소·이미 취소된 요청을 구분한다. 스냅숏 종료 실패와 출처 조립 취소는 이미 조립된 본문/간선/진입점을 비우고 집계·원인을 보존한다.
- `search_snapshot_contract_test.go`: 작은 풀과 별도 쓰기 풀을 사용한다. 스냅숏 내보내기 뒤 파생·전역 요약·임베딩 공개를 커밋하고 의미/키워드/시간/전역 요약/홉/출처의 여섯 읽기를 대조한다. 경계 안에서는 이전 후보·본문·참조만 보이고 경계 밖에서는 새 노드·색인을 본다. 실제 읽기 모드가 read-only REPEATABLE READ임을 확인하고, 종료 뒤 연결과 예약이 회복되는지 검사한다. 실제 검색기의 제공자 대기 중에도 연결·예약이 0이며 취소 뒤 회복한다.
- 기존 모듈을 새로 실행하여 미지정/UTC 시각, 인터페이스 주입·오류, 모든 검색 패키지 회귀, 최대 3개 동시 읽기, 4개 연결의 실제 최대 점유, 접근 기록 중 자리 유지·실패·취소, 스냅숏 내보내기/가져오기/질의/종료 실패와 예약 대기·혼합 부하를 확인했다.

## DOX pass와 후속 범위

- 입력의 공통 논리 검증은 model, 검색 실행·실패 반환은 search, 실제 연결/스냅숏은 store가 소유하므로 기존 패키지/DOX 경계와 일치한다. 새 의존성·설정·스키마·용어·소유권 이동이 없어 SRS·SDD·DOX·마이그레이션·운영 안내·용어집은 유지한다. 공급자 공식 근거를 [reference.md](../reference.md)에 기록했다.
- SEARCH-01과 전체 계획·단계 상태·요청 기록을 갱신했다. 현재 41/124개 완료·83개 미착수이며 다음은 [SEARCH-02](../development-plan/search.md#search-02)다.
- 원문 JSON의 문자열/숫자 타입·잘못된 시각 문자열 해석과 MCP 오류 외피는 후속 MCP 작업이다. 이번 내부 검색 입력은 이미 해석한 time.Time·int를 받고 검증한다. 실제 제공자 품질·MCP/호스트·검색 성능/분야별 통합 인수·운영 배포·TEST-09 전체 시험은 후속 범위다. 기존 PERM-07 인덱스 계획 후속 사항도 재검증하거나 해결한 것으로 표시하지 않는다.
- 변경은 커밋 전이다.
