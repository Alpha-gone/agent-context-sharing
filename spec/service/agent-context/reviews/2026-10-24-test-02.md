## 변경과 확인한 계약

`internal/model/testing_acceptance_test.go`는 빈/최소/복수/역순/중복/잘못된 참조와 조회 결과의 누락·중복 치환·초과를 대조한다. 사건은 시작 직전 1ns·시작·종료·종료 직후 1ns·길이 0·진행 중 미래 시각을 검사한다. 파생의 사실 유효 구간은 사건 시간 범위로 제한하지 않는다. 기존 모델 시험도 함께 실행하여 계층별 필수·불변·UTC·관계·등록 키 계약을 새 실행에서 확인했다.

`internal/config/testing_acceptance_test.go`는 같은 계정의 대문자/하이픈 없는 별칭을 값 동일·상이·null과 두 입력 순서로 로더에 전달한다. 구성이 원자적으로 거부되고 계정 원문이 오류에 노출되지 않는지 검사한다. 보관/감사 기간의 무기한·같음·1일 미달/초과 조합도 로더에서 대조한다. 기존 플랜 전체 시험은 요청·누적 한도, 초과 상태의 읽기/축소, 정수 넘침·오류 메타데이터, 서로 다른 계정과 달력 기준 보존 기간을 확인했다. DB 접속 정보나 외부 제공자를 사용하지 않았다.

`internal/search/testing_acceptance_test.go`는 알려진 진입 점수 `3/2` 동점과 그래프 채널을 더한 `2` 점수, 사건 우선 라우팅, 유니코드 문자 예산과 절단 수를 여섯 채널 순서·양방향 간선 표본에서 대조한다. 이진수로 정확히 표현되는 충분성·분리 폭 하한과 인접 부동소수점도 검사한다. 기존 검색 시험은 채널 완료 순서 여섯 가지의 전체 응답 일치, 근접한 비동점 점수, 접기·연결 근거 집합의 예산과 최단 경로를 검증한다. 운영 선택기의 BFS·비용 함수를 재사용하지 않는 전수 단순 경로 기준기로 5정점 그래프·진입점·기선택 집합 61,440개를 대조했다. 이 반복 수는 시험 건수에 더하지 않았다.

`cmd/server/testing_acceptance_test.go`는 별도 임시 디렉터리에 일반·별칭·blank import, Linux 전용 제품 소스와 시험/텍스트 파일을 만든다. 실제 import 탐지기로 제품 의존을 모으고 금지 의존과 낡은 허용표의 누락 의존을 동시에 검출한다. 기존 설계 경계 시험은 SDD의 두 표를 읽어 열한 업무 패키지와 실제 import를 양방향 대조하며 `migrate`를 업무 패키지 밖 도구로 구분했다. DB 드라이버 직접 의존·공개 핸들·순환 의존 검사도 통과했다. 참조 수 상한은 소유 경계인 MCP의 입력 목록 검사로 0·1·최대·최대+1을 별도 확인했다.

## 실행 환경과 결과

Go 1.27.1 darwin/arm64에서 `TEST_DATABASE_URL`·`TEST_DATABASE_REQUIRED`를 빈 값으로 지정했다. 전체 저장소 시험이 아니라 TEST-02에 해당하는 네 패키지 전체와 서버 경계·MCP 목록 상한만 실행했다.

```sh
export TEST_DATABASE_URL= TEST_DATABASE_REQUIRED= GOTOOLCHAIN=local
go_command=/Users/alphagone/sdk/go1.27.1/bin/go
"$go_command" test -race -json -count=1 -timeout=180s \
  ./internal/model ./internal/plan ./internal/config ./internal/search
"$go_command" test -race -json -count=1 -timeout=120s \
  -run '^Test(PackageDependenciesMatchDesign|DatabaseHandleStaysInStore|BoundaryRulesRejectViolations|StoreExportsNoDatabaseHandle|HandleDetectorRejectsExports|TEST02DependencyScannerUsesProductionSources)$' ./cmd/server
"$go_command" test -race -json -count=1 -timeout=120s \
  -run '^TestCatalogArrayBounds$' ./internal/mcp
GO_BINARY="$go_command" sh ./check-go.sh
```

- 최종 고유 시험 1,063건(하위 사례 포함): 모델 179·플랜 210·구성 326·검색 331·서버 10·MCP 7건. 신규 7개 최상위 시험은 하위 사례를 포함해 52건이며 최종 실패·건너뜀이 없다. 재실행은 중복 합산하지 않았다.
- 첫 명령은 sandbox의 Go 빌드 캐시 접근 제한으로 준비에 실패했다. 캐시 접근 권한을 적용한 실행에서 새 검색 표본의 기대값 오류가 드러났다. 시간 채널 후보도 독립 진입점이라는 기존 계약에 맞춰 예산 1의 기대값을 고치고 검색 패키지 전체를 재실행하여 통과했다. 제품 동작 변경은 없다.
- 전체 의존성 검증·build·vet·gofmt와 문서 링크·Markdown·계획 상태 검사를 통과했다.
