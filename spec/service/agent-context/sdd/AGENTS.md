# 분야별 상세 설계 영역

## 목적

- 이 영역은 에이전트 컨텍스트 서비스의 확정 요구사항을 분야별 상세 설계로 구체화한다.

## 소유권

- 상위 `AGENTS.md`가 서비스 경계와 요구사항·설계의 관계를 소유한다.
- `../SDD.md`는 설계 진입점과 문서별 책임·상태를 소유한다.
- 각 분야 문서가 해당 분야 상세 계약의 정본이며 `traceability.md`가 요구사항 추적표와 설계 미정 사항을 소유한다.

## 로컬 계약

- 상세 설계는 분야별 Markdown 파일로 유지한다. 진입 문서에 상세 본문을 합치지 않는다.
- 각 계약은 한 문서만 소유하며 다른 분야에서는 상대 링크로 참조한다. 여러 분야가 관련된 요구사항도 추적표의 주 책임 문서는 하나로 정한다.
- 요구사항은 `../SRS.md`를 따르고 ID·확정된 결정을 보존한다. 요구사항 변경이 필요하면 SRS를 먼저 갱신한다.
- 현재 구현, 채택된 목표와 검증 대기를 구분한다. 문서 작성만으로 구현·호스트 지원·성능·로그 저장을 완료로 표시하지 않는다.
- 초기 MCP 목표는 `2026-07-28` 하나이며 `mcp.md`가 표준 발견·요청별 외피·헤더·캐시·취소를 소유한다. 이전 revision의 초기화 교환을 목표 계약에 혼합하지 않고 실제 적합성 검증 대기를 유지한다.
- 초기 임베딩 호출은 Gemini 단일 경로이며 `indexing.md`가 구성·응답·재색인 경계를 소유한다. 개발 Compose에는 별도 모델 서비스를 두지 않는다.
- 신규 문서나 책임 이동 시 진입점, 추적표, 문서 사이 링크와 상위 Child DOX Index를 함께 확인한다.

## 작업 지침

- 루트부터 이 문서까지 DOX 체인과 SRS·용어집의 관련 절을 읽고 편집한다.
- 구현 전에 해당 분야 설계를 갱신하며, 다른 분야에 영향을 주면 관련 계약과 추적 링크를 함께 정합화한다.
- 절의 단순 이동을 설계 결정 변경으로 기록하지 않는다. 과거 검토 결과는 원래 기록의 시점·범위를 유지한다.

## 검증

- FR 171건과 NFR 13건의 추적 행이 중복·누락 없이 존재하는지 확인한다. 폐기된 FR 156~159는 설계 대상에서 제외한다.
- 상대 경로·제목 앵커·표·코드 블록, 한국어 표현과 맞춤법을 확인한다.
- 설계 미정 063의 해소와 064의 실제 상호운용 검증 대기를 구분한다.
- 파일 간 데이터·시간·권한·오류·트랜잭션·자원 상한이 일치하는지 확인한다.
