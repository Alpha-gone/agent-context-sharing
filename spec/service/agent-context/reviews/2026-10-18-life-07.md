## 인수 범위

- 상태·속성: all_layers/without_source와 원천·파생·사건을 교차한다. 폐기 시 deleted_at, 복구 시 속성·참조 보존과 삭제 해제, 원천 판 1 고정·파생/사건 판 증가를 확인한다. 재폐기·재복구는 ErrInvalidState이며 부분 적용이 없다.
- 누계·색인·감사: 저장 문자 수를 한 번 차감/복원하고 내용 판·활동 시각을 같은 트랜잭션에서 갱신한다. 폐기는 기존 실패 큐를 그대로 보존하고 복구는 같은 작업 ID를 pending·시도 0·오류 없음으로 다시 등록한다. 원천 제외 구성은 원천을 등록하지 않는다. 두 전이의 실제 대상·계정·agent 적용 기록을 확인한다. 누락된 임베딩·큐를 재등록하는 기존 회귀도 통과했다.
- 원자성: 세 계층의 폐기/복구에 AGE 쓰기·그래프 누계·감사·지연 커밋 실패, 복구에는 큐 등록 실패·저장 한도 초과도 주입했다. 정점·간선·현재/이전 판·큐·임베딩·누계·감사 전체 지문을 비교하고, AGE 저장점 실패 뒤 바깥 커밋에도 변경이 없음을 확인한다. 실패를 제거한 같은 연산은 성공하고 풀·예약이 회복된다.
- 동시 전이: 계층별 폐기/복구 요청 6개를 겹쳐 정확히 하나만 성공하고 나머지는 상태 오류가 되는지 확인한다. 누계·내용 판·감사도 한 번만 적용된다.
- 잠금·취소: 원천·파생의 정점, 사건의 그래프→정점 잠금으로 실제 차단을 확인한 뒤 요청을 취소한다. context.Canceled와 사용자 지정 원인을 보존하고 업무 지문·4연결 풀·예약 반환을 대조한다.
- 현재 근거: applied_at이 현재 deleted_at과 같은 경계이면 허용하고 1마이크로초 앞서거나 rejected·다른 대상이면 허용하지 않는다. 복구 거부는 ErrRestoreChannel이며 상태·누계·감사·큐를 바꾸지 않는다.
- 채널·보존: 기존 원천·파생·사건의 MCP 폐기→복구→새 웹 삭제, 잠금 대기 중 웹 복구/재삭제와 새 MCP 폐기, 감사 보존 기간 이후 현재 근거 보호·복구 뒤 과거 근거 정리·웹 감사 정리 뒤 거부, 미커밋 복구 롤백과 병행 정리를 다시 검증했다.
- 교차 회귀: 사건 폐기와 확정/폐기/갱신의 양쪽 순서, 삭제 그래프의 거부와 그래프 삭제 경합을 검증했다. 더 넓은 수명주기 통합 인수는 LIFE-09 범위다.

## 완료 판정과 후속 범위

LIFE-07을 완료하여 전체 38/124개 완료·86개 미착수로 갱신했다. 다음 권장 항목은 선행이 준비된 [LIFE-08](../development-plan/context-lifecycle.md#life-08)이다.

DOX pass에서 상태 변경·복구 채널은 store와 기존 수명주기 SDD, 일반 보존 정리는 기존 운영·감사 경계 소유임을 확인했다. 새 지속 경계·스키마·공개 API·설정·용어가 없어 AGENTS·Child 색인·SRS·SDD·마이그레이션·운영 안내를 유지했다. 기존 PostgreSQL 18·pgx v5.10.0 공식 근거를 재사용하여 reference를 중복 추가하지 않았으며 개발 계획·요청·검토 기록을 갱신했다. 저장 경계는 현재 웹 삭제를 웹에서 복구하도록 안내하는 ErrRestoreChannel을 반환한다. MCP의 실제 not_supported 외피·웹 대체 채널 전달, 등록/권한 결합·브라우저·호스트·운영 배포와 수명주기 전체 통합 인수는 해당 후속 작업에서 수행한다. [PERM-07 조회 인덱스 후속 사항](2026-10-17-perm-07.md#별도-후속-사항)은 이번에 재검증하거나 해소하지 않았다. 변경은 커밋 전 상태다.
