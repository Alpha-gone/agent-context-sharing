# DATA-02 스키마·마이그레이션 실행기 모듈 검토

## 범위와 선행 조건

2026-10-15에 [DATA-02](../development-plan/data.md#data-02)를 완료했다. 시작 커밋은 `6428427`, 브랜치는 `feat/data-schema-contract`다. fetch 후 upstream `origin/dev` 대비 뒤처짐 0·앞섬 2를 확인했다. 선행 DATA-01·ARCH-01·ARCH-05·OPS-01은 완료 상태다.

기준은 [스키마 적용](../sdd/data.md#스키마-적용), [DATA-01의 목표 DDL](../sdd/data.md#신규-구현의-ddl-대응), [OAuth 열](../sdd/authentication.md#oauth-저장-열), [등록 열](../sdd/mcp.md#등록-저장-열)과 [SQL 계약](../../../../migrations/AGENTS.md)이다. 기존 구현·과거 시험을 완료 근거로 승계하지 않고 새 마이그레이션과 시험 증거를 확보했다.

## 구현

- `010_target_schema.sql`로 OAuth 3종·에이전트 등록 1종과 7개 조회 인덱스·통계를 추가했다. 업무 테이블은 목표 17종이며 임베딩 자식 파티션·마이그레이션 이력은 별도로 센다. 해시 길이·소비 쌍 NULL·계열 FK·폐기 행을 포함하는 등록 유일 키를 DB에서 강제한다.
- 그래프 version·관리 대상 판·요청 빈도 카운터를 bigint로 바꾸고 내부 content_revision·대상 판의 양수 제약을 추가했다. 멱등성 키는 기존 UUID를 텍스트로 보존하며 ASCII 길이/형식·도구 8종·32바이트 지문을 검사한다. 결과 NULL은 예약에만 쓰며 미완료 커밋 금지는 후속 MCP 저장 연산의 책임이다.
- 기존 001·009의 SQL·주석·checksum은 변경하지 않았다. 010은 기존 결과·최초 접수/만료·감사를 재작성하거나 벡터를 지우지 않는다. 새 제약 위반 행은 자동 복구하지 않고 해당 파일의 DDL·이력을 함께 롤백한다.
- `WithLock`은 획득 연결을 콜백에 전달한다. CLI와 관련 시험의 이력 조회·DDL이 같은 연결을 사용하여 잠금 대기자가 풀을 고갈시키지 않게 했다. 세션마다 AGE·search_path·UTC를 준비하며 store의 DB 핸들은 사용하지 않는다.
- 잘못된 구성·치환은 이력 생성 전 거부하고, 양수 세 자리 파일명·번호 중복·파일명/checksum 변조·과거 번호 재사용을 거부한다. 적용 파일은 당시 render_config로 검증하고 사라진 파일의 이력은 보존한다. 구형 NULL 구성의 checksum 일치 확인 후 보충 동작도 유지했다.
- 잠금 대기 취소·해제 실패의 불명확한 세션은 폐기한다. 취소와 별개의 최대 5초 정리 컨텍스트로 rollback/unlock을 수행하고 원래 오류를 보존한다. 콜백 오류·취소 후 연결과 잠금 반환을 검증했다.

## 새 검증 결과

별도 Docker Compose 프로젝트 `data02-db-0734-uku`의 합성 자격·새 볼륨·임시 IPv4 loopback 포트를 사용했다. 기존 `.env`·개발 DB·볼륨은 사용하지 않았다. DB 이미지는 OPS-01의 고정 AGE digest·pgvector 완전 패키지 판이며 이번 빌드는 캐시를 사용했다. 환경은 Go 1.27.1, Docker Engine 29.7.2, Compose v5.4.0, linux/arm64다.

시험 종료 후 해당 프로젝트의 컨테이너·이미지·볼륨·네트워크를 정리하고 프로젝트 label의 잔여 자원이 없음을 확인했다.

기존 차원 전환·복귀·구형 render_config 보충·checksum 보존 시험도 이번 모듈 실행에서 다시 통과했다. 이 사실은 DATA-09의 전체 보존 이행·현재 API 연동 완료를 뜻하지 않는다.

## 완료 판정과 후속 범위

DATA-02의 새 DB 전체 적용·반복·동시 실행·잘못된 치환·checksum 검사·부분 실패 조건을 충족했다. 다음은 [ARCH-04](../development-plan/architecture.md#arch-04)의 애플리케이션 AGE 연결·예약 구현이며, 이후 DATA-03의 단일 접근 계층으로 진행한다.

운영 DB 적용·기존 배포 전환·백업/복귀·전체 그래프 감사·권한/저장소 인수·OAuth/등록/멱등성 연산·실제 API/호스트·amd64 runtime은 미실행이다. 정식 DDL과 실행기 준비를 해당 기능의 완료로 승격하지 않았다. 두 파티션 간 전역 유일성·현재 권한·기여자 결합·등록 상한·인증 수명·미완료 예약 커밋 금지는 후속 저장 연산의 책임이다.

DOX pass에서 소유 경계·경로·Child DOX Index는 바뀌지 않아 유지했다. 적용 순서·잠금 연결·파일/치환 검증은 소유 데이터 SDD에 반영했고 SRS·요구사항 추적·용어집과 다른 분야 SDD는 유지했다. 기존 운영 Compose·IDE 변경을 보존했다.
