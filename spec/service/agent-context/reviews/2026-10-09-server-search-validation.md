# 서버 종료·전송 오류·검색·개발 검사 회귀 검증

## 대상과 확인 근거

[GitHub #83](https://github.com/Alpha-gone/agent-context-sharing/issues/83)의 다섯 항목을 최신 `dev`의 `81635f4`에서 만든 `fix/issue-83-server-search-validation` 브랜치에서 처리했다. upstream은 0/0이며 기존에 staging된 IDE 배포 설정 두 파일은 변경하지 않았다.

수정 전 회귀로 요청 대기 실패 뒤 연결·요청 컨텍스트가 남는 현상, 배치·숫자 메서드·문자열 params·중복 필드가 `-32700`으로 분류되는 현상, 명시적 전역 검색의 근거 누락과 수학적 동점의 식별자 정렬 불일치를 확인했다. 최초 종료 재현 테스트의 정리도 멈췄으므로 처리기의 취소 대기에 해제 경계를 추가하여, 제품 결함을 재현한 뒤에도 시험 자체가 종료되도록 보완했다.

## 해결한 항목

- 종료: `http.Server.Shutdown` 실패 뒤 `Close`로 진행 연결을 닫고 요청 취소를 전파한다. 작업자에는 기존의 독립적인 최대 10초 예산을 준다. 조립 지점은 요청 대기 실패 시 DB 풀의 무기한 반환 대기를 건너뛰어 `main`이 실패를 기록하고 프로세스를 종료할 수 있게 한다. 정상 종료와 기동 실패의 기존 정리 순서는 유지한다.
- JSON-RPC: 제한된 본문 스트림에서 JSON 문법을 먼저 검사하고 요청 객체의 형식을 별도로 검사한다. 문법 오류만 `-32700`, 배치·스칼라·중복 필드·필드 형식 오류는 `-32600`과 `id: null`이다. 기존의 상한 초과 `413`, 헤더 대조·메타데이터·인증 순서와 유효한 ID 원문 보존을 유지한다.
- 통합 순위: 표준 라이브러리 `math/big.Rat`로 순위 역수 합을 정확히 비교한다. 같은 5/3을 다른 순서로 누적해도 시각·식별자 정렬, 사건 진입점 라우팅 신호와 예산 절단이 같으며, 근사 오차 허용값은 쓰지 않는다.
- 전역 검색: SRS의 강제 범위와 근거 탐색, SDD의 검색 처리 흐름을 기준으로 모순된 기준선 설명을 수정했다. `scope=global`은 자동 전환 설정과 무관하게 `baseline`에서도 전역 요약을 시작점으로 `derived_from`만 탐색한다. 비그래프 기준선 평가는 기존 `auto`·전역 전환 비활성 구성을 유지한다.
- 개발 검사: 기존 pgvector 패키지·Ollama 고정 검사에 DB `FROM`의 정확한 태그·digest 대조를 추가했다. DB 이미지·Compose 구성 자체는 바꾸지 않았다.

## 검증

IntelliJ IDEA에 설치된 Go 1.27.1 SDK를 사용했다.

- 핵심 검색·MCP·종료 회귀 `-count=10`: 통과.
- 최초 서버 전체 `go test -race ./... -count=1`: 실행한 테스트 통과. 별도 JSON 실행에서는 테스트 항목 737개 통과, 165개 건너뛰기, 실패 0개였다. 이 실행에는 `.env`의 DB 연결 설정을 시험 프로세스에 주입하지 않았다. 이후 아래의 실제 DB 검증으로 건너뛴 계층을 확인했다.
- 클라이언트 전체 `go test -race ./... -count=1`: 통과.
- 서버·클라이언트 각각 `go build ./...`, `go vet ./...`: 통과.
- 개발·운영 Compose 정적 검사: 통과. 임시 복사본의 digest 제거·태그 변경·digest 변경 세 변조는 모두 종료 코드 1로 거부했다.
- Go 형식, 셸 구문, diff 공백, 한국어 표현과 상대 링크를 확인했다.

### 로컬 개발 PostgreSQL 추가 검증

사용자의 로컬 개발 DB 시험 요청에 따라 `.env`의 접속 설정을 사용했다. 해당 인스턴스는 PostgreSQL 18.6, Apache AGE 1.8.0, pgvector 0.8.6이며 DB 생성 권한을 확인했다. 기존 개발 DB 대신 같은 인스턴스 안에 이 작업 전용 임시 DB를 만들고 정식 `001_init` 마이그레이션을 적용했다. 임베딩 열과 기동 시험 구성은 `vector(768)`로 맞췄다. 접속 문자열·비밀번호·키는 출력하거나 문서에 기록하지 않았다.

- `TEST_DATABASE_REQUIRED=1`과 임시 DB URL을 주입하여 서버 전체 `go test -race -p 1 -count=1 -json -timeout=300s ./...` 실행: 테스트 항목 968개 통과, 실패 0개, 테스트 건너뛰기 0개. 테스트 파일 없는 패키지 이벤트는 개별 테스트와 구분했다. 이전에 건너뛴 DB 통합 계층도 실행했다.
- 수정 커밋 `3a5f7b2`의 실제 서버 바이너리를 임시 DB와 무작위 loopback 포트로 기동했다. 임시 DB의 `public.signing_key`에만 배타 잠금을 잡고 `/jwks.json` 요청이 실제 DB 잠금을 기다리는 상태를 관찰한 뒤 `SIGTERM`을 보냈다. 서버는 30.024초 뒤 종료 코드 1로 반환했고 `context deadline exceeded`를 기록했으며, 진행 중인 HTTP 요청은 `EOFError`로 연결 종료를 확인했다. 이 값은 이번 실행의 실측값이지 고정 기대값이 아니다.
- 프로세스 시험에서는 색인 소비 루프를 시작하지 않았고 임베딩 주소는 loopback의 미사용 포트로 제한했다. 외부 임베딩 API와 기존 Ollama 모델을 사용하지 않았다.
- 잠금 세션과 시험 서버가 종료된 뒤 시험 DB 연결이 0개임을 확인하고 이 작업이 생성한 임시 DB만 삭제했다. 시험 DB가 남지 않았으며 기존 개발 DB 컨테이너의 ID와 시작 시각은 검사 전후 같았다. 기존 개발 DB·볼륨·설정은 초기화하지 않았다.

## DOX pass와 제한

- 루트 DOX에 요청 종료 실패의 정리 예외, MCP DOX에 오류 분류, 서비스 DOX와 SDD에 정확한 동점 판정·명시적 전역 탐색을 반영했다. 개발 계획과 요청 기록도 갱신했다.
- 기존 부모 Child DOX Index는 같은 경계·소유권·경로를 유지하므로 변경하지 않았다. SRS·용어집·공개 도구 스냅샷·클라이언트 코드·마이그레이션은 요구사항·용어·API·스키마 변경이 없어 유지했다. 새 외부 의존성이나 배포 구성은 없다.
- 실제 DB 연결 점유 요청의 전체 프로세스 종료는 추가 검증했다. 개발 Compose `--runtime`, 외부 임베딩 API, 실제 Cloudflare 연결과 운영 배포는 여전히 검증하지 않았다. 기존 DB·볼륨·`.env`·비밀·IDE 설정은 변경하지 않았다.
- 수정 커밋 `3a5f7b2`는 [PR #98](https://github.com/Alpha-gone/agent-context-sharing/pull/98)로 게시되어 있다. 추가 DB 검증 기록은 동일 PR의 후속 검증 결과로 관리한다. PR 병합과 이슈 직접 종료는 수행하지 않는다. DOX의 경계와 계약은 바뀌지 않아 소유 문서와 Child DOX Index를 유지했다.
