# 서버 작업자 종료 오류 검증

## 범위와 처리 결과

2026-10-10에 [GitHub #106](https://github.com/Alpha-gone/agent-context-sharing/issues/106)의 작업자 종료 오류 누락을 수정했다. 기준 커밋은 원격 `dev`와 일치하는 `d1337bc`이며 작업 브랜치는 `fix/issue-106-worker-shutdown-errors`이다.

기존 `closeWorkers`는 오류를 로그에만 남겼고 `shutdownInOrder`는 HTTP 종료 결과만 반환했다. 기동 실패의 deferred 정리에서도 작업자 오류를 반환하지 않았으며, 풀 종료 조건은 진행 요청의 종료 여부만 반영했다. 종료되지 않은 작업자가 연결을 유지하면 실패를 보고하기 전에 풀 종료가 연결 반환을 기다릴 수 있었다.

- SDD의 「기동과 종료」에 오류 보존, 공유 작업자 종료 예산과 안전한 풀 종료 조건을 먼저 반영했다.
- `closeWorkers`는 작업자별 오류를 문맥과 함께 모아 반환하며, 하나가 실패하거나 공유 기한을 소진해도 후속 작업자의 종료를 시도한다. `shutdownInOrder`는 HTTP 종료 오류와 작업자 오류를 결합하여 `errors.Is`로 각각 확인할 수 있게 한다.
- `runConfigured`는 이름 있는 반환 오류에 deferred 정리 오류를 결합한다. 정상 종료와 기동 실패는 `closeServerResources`를 함께 사용하고, 요청이나 작업자 종료가 실패하면 연결 풀 종료를 건너뛴다. 이미 종료를 시도한 작업자는 실패 여부와 관계없이 목록에서 제거해 다시 기다리지 않는다.
- 기존 `main`의 오류 종료 경계를 유지하므로 호출자가 받은 종료 실패는 프로세스 종료 코드 1로 전파된다. HTTP 요청 대기 30초와 전체 작업자 정리 10초 예산, 작업자의 context 기반 종료 계약 및 분리 배치 동작은 유지한다.

## 검증

Go 1.27.1 SDK와 개발 PostgreSQL의 전용 시험 DB `issue106_test_20261010`을 사용했다. 매 실행에 정식 `001_init` 마이그레이션을 적용하고 `TEST_DATABASE_REQUIRED=1`을 설정했으며, 종료 뒤 자신이 만든 시험 DB만 삭제했다. 기존 개발 데이터·서명 키·컨테이너 구성은 변경하지 않았다.

- 작업자 단독 실패, HTTP·작업자 동시 실패, 여러 작업자의 오류 보존과 후속 종료 시도: 통과. 잘못된 성공 기대를 갖던 기존 시험을 수정했다.
- 공유 예산 소진 뒤 후속 작업자 호출, 정상 종료·기동 실패의 풀 종료 조건, 원래 기동 오류 보존과 작업자 중복 종료 방지: 통과.
- 실제 주기 작업이 세션 자문 잠금의 DB 연결을 취소 뒤에도 유지하도록 대기시켰다. 정상 종료·기동 실패 정리 모두 시험용 20ms 기한 초과를 반환하고 풀 종료를 호출하지 않았다. 시험은 작업을 해제하고 잠금·연결 풀을 정리했다.
- `go test -count=1 -race -p 1 -timeout=180s -json ./cmd/server ./internal/index ./internal/store`: 시험·하위 시험 342건 통과, 실패 0건, 건너뜀 0건, 종료 코드 0.
- 실제 서버 바이너리의 종료 코드 확인: 정상 종료 성공은 0, 작업자 종료 실패는 1, 수신 기동 실패와 작업자 종료 동시 실패는 1. 마지막 경우 로그에 두 원인이 모두 보존됐다. 오류 주입은 임시 Go overlay에서 주기 작업자의 종료 반환값만 바꾸었으며 저장소 코드에 시험용 분기를 추가하지 않았다. 격리 DB와 루프백 HTTP만 사용했고 임베딩 제공자 호출은 0회였다.
- 서버·클라이언트 각각 `go build ./...`, `go vet ./...`: 통과. `gofmt -l .`, `git diff --check`: 출력 없음.

다른 서버 패키지의 전체 race 시험, 클라이언트 race 시험과 외부 제공자 실연결은 이번 변경에서 재실행하지 않았다. 프로세스 검증의 임시 overlay·바이너리는 저장소 산출물에 포함하지 않는다.

## DOX pass
