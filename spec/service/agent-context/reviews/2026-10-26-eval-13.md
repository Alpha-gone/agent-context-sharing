# EVAL-13 manifest 실행·결과 저장·실패 보고·채택 판정 검토

## 범위와 실행 계약

EVAL-13의 [평가 산출물 계약](../sdd/evaluation.md#manifest-실행과-결과-묶음)을 구현했다. `cmd/eval -manifest 실행.json -results 결과루트 -trial-input 입력코드=파일`로 측정 입력을 연결하고, 준비 입력은 `-trial-prepared 디렉터리`로 연결한다. 기존 개별 모드와 `-check-manifest`는 유지한다. manifest 모드는 기존 개별 실행 옵션과 혼용하지 않으며 빈 manifest 옵션도 무시하지 않는다.

- manifest 판·역할·SHA-256을 검증한 실제 바이트를 비공개 스냅숏으로 만들고 해당 스냅숏으로 실행한다. 검증 후 원본 파일 변경의 영향을 받지 않는다. 직접·준비·복합 입력의 판, 문항/과업/독립 단위, 매핑·제외와 적용 모델·검색/준비/캐시/예산·단가 판을 대조한다. 내장 지속 시나리오의 판과 결정적 JSON도 고정한다. 원본 비교의 수집 파일은 같은 스냅숏에 포함한다.
- 실행기 호출 상태를 전역 변수로 공유하지 않도록 CLI 파싱을 지역 FlagSet으로 분리했다. 기존 업무 실행기를 재사용하며 manifest가 고정한 인자만 전달한다. 외부 생성기의 에이전트/프롬프트 판과 출처는 제공된 입력의 선언이며 외부 생성·에이전트 실행 자체를 재인증하지 않는다. 지원을 확인하지 못한 seed는 거부한다.
- 실제 검색 논리 요청/원본 GET·색인 소비·공통 시간 예산을 적용한다. 그래프 생성·준비·완료 회차·정리 시도/실패·잔여 수를 계측한다. 취소·실패에도 기존 독립 10초 정리를 유지하고, 정리 누락이나 요청 상한 초과가 정상 결과가 되지 않도록 한다.
- 성공 시 manifest/preparation/summary/cost 네 JSON을 완전히 쓰고 다시 해석·필수 필드/회차·사용 근거를 검사·동기화한다. macOS의 RENAME_EXCL과 Linux의 RENAME_NOREPLACE로 디렉터리를 한 번에 저장한다. 같은 시험 ID를 배타적으로 예약하며 기존 파일·빈 디렉터리·심볼릭 링크도 덮어쓰지 않는다. 비공개 입력은 저장 묶음으로 이동하지 않는다.
- 준비 보고서는 측정 대상의 원천/파생/사건 수, checksum 대조, 측정 시점의 색인 pending/failed, 실제 준비 시간·임베딩 HTTP 시도·벡터 행/열 바이트와 구간별 비용을 담는다. 준비 입력의 원래 전체 집계는 기존 결과의 input_preparation에도 유지한다. 계측하지 않은 값은 -1이고 과업 기록 수입을 실제 색인·호출로 세지 않는다.
- 실행/준비/검증 실패에는 manifest/failure만 저장한다. 정상 summary나 부분 결과를 남기지 않으며 안전한 단계·원인 코드·완료 회차·정리 상태만 공개한다. JSON 검증·기록 오류는 실패로 전파한다. 원자적 저장 뒤 디렉터리 동기화 오류는 이미 저장한 결과를 보존하며 공개 동기화 오류로 반환한다. 강제 종료로 남은 예약을 자동 탈취하지 않는다.
- 비용은 실제 사용량·단가·기준량·배분율에서 계산한다. manifest의 금액 선언을 사용 근거로 삼지 않고 상태/금액 불일치를 거부한다. 현재 항목별 실제 산정 근거가 있는 확장 과업 외 모드의 금액은 미측정으로 유지한다. 원래 지표·Student t 95% 구간과 개선/악화를 보존하면서 accepted/not_accepted/deferred를 별도로 기록한다. 합성/미검증·독립 단위 부족·미측정은 보류하고 명백한 악화·서비스 수준 목표 초과·격리/복구 실패는 비채택한다. default_activation은 항상 false다.
- 추가 시험은 새 trial_id와 선택적인 followup의 목적·문항 수·회차를 사전 고정한다. planned_samples는 manifest 문항 수이며 실제 독립 표본 수는 별도 집계한다. 이전 결과를 덮어쓰거나 반복 회차를 독립 표본으로 합치지 않는다.

## 최종 검증

최종 코드의 평가 실행기 전체 **865건**(최상위 **195건**, 하위 사례 포함)이 필수 DB·race·360초 제한에서 **231.717초**에 실패·건너뜀 없이 통과했다. 기존 EVAL-01~12와 새 EVAL-13을 같은 명령에서 실행한 분야 통합 인수이며 저장소 전체 TEST-09 인수를 뜻하지 않는다.

```sh
TEST_DATABASE_URL='<격리 vector(768) DB>' \
TEST_EMBEDDING_SMALL_URL='<격리 vector(128) DB>' \
TEST_EMBEDDING_HALF_URL='<격리 halfvec(768) DB>' \
TEST_DATABASE_REQUIRED=1 GOCACHE=/private/tmp/acs-eval12-go-cache \
/Users/alphagone/sdk/go1.27.1/bin/go test -race -count=1 -json \
  -timeout=360s ./cmd/eval
GOCACHE=/private/tmp/acs-eval12-go-cache \
GO_BINARY=/Users/alphagone/sdk/go1.27.1/bin/go sh check-go.sh
```

최종 전체 결과는 `/private/tmp/acs-eval13-full-final.json`, 전체 의존성 검증·build·vet·gofmt 결과는 `/private/tmp/acs-eval13-static-final.log`에 남겼으며 모두 통과했다. Linux/arm64의 최종 교차 빌드 시험 바이너리로 DB 없는 manifest 시험 **48건**(최상위 **11건**)도 실패·건너뜀 없이 통과했다. 이는 비 race 실행이며 Linux 전체 DB 시험을 대신하지 않는다. 결과는 `/private/tmp/acs-eval13-linux-final.log`에 있다.

새 DB 시험에서 직접 입력·준비 입력·색인 대상 비교의 정상 저장, 요청/색인 상한·모델 불일치·정리 실패와 검증 뒤 입력 변경을 대조했다. 실제 자식 CLI에 SIGINT를 보내 query 취소와 독립 그래프 정리, 실패 파일만 저장되는 것을 확인했다. 원본 비교는 같은 수집 파일을 공유하는 일곱 표본의 70회 GET과 비공개 URI/본문 제외를 확인했다. 업무 모드는 세 독립 비교의 과업 trace를 수입했고, 합성/비용 미측정의 보류·성공률 악화의 비채택·완전한 선언 trace의 채택 분기를 검사했다. 이 채택 분기 시험의 합성 기록을 실제 에이전트 효과로 해석하지 않는다.

예비 시험에서는 시험 manifest 후보 상한과 환경의 차이를 바로잡았다. JSON canonicalization이 원래 바이트 슬라이스를 바꾸어 과업 결과 재구성 대조를 방해한 부분은 복제본에서 정규화하도록 수정했다. 첫 전체 실행은 기존 시험에서 초기화한 표준 CA 캐시 때문에 같은 프로세스의 새 로컬 TLS 대역을 신뢰하지 못했다. 시험 transport에 대역 CA를 명시하고 서버의 TLS 검증을 유지한 채 새 DB 세 개에서 전체를 재실행했다. 수정 전·예비·중복 실행을 최종 통과 수에 더하지 않았다.

## 환경·제한과 다음 작업

실행 환경은 Go 1.27.1·macOS/arm64와 PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6 Linux/arm64다. 768/128차원 vector와 768차원 halfvec DB를 정식 마이그레이션으로 새로 준비했다. 합성 클러스터의 DB 이미지 식별자는 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`, Linux 파일 시험의 캐시된 Alpine 이미지는 `sha256:294b683cb724975bec92580e1e685676bd4b50bda910ddb8c51d4cabeaec77e6`다. 다른 OS·파일 시스템의 실행 인수는 하지 않았다.

실제 공개 데이터의 전체 검색 효과·외부 에이전트 업무·유료 제공자 단가/청구·실제 운영 채택은 미실행이다. manifest의 provenance와 가져온 trace는 입력 출처 선언이며 CLI가 외부 과업을 새로 수행했거나 진위를 독립 검증한 증거가 아니다. 비용·품질 미측정은 보류로 남으며 운영 기본값을 바꾸지 않았다. 실제 호스트·운영·최종 전체 인수는 후속 작업이다.

DOX pass에서 패키지·스키마·배포 환경과 소유권이 유지되어 DOX와 SRS는 변경하지 않았다. 평가/시험 상세 계약·분야/전체 계획·SDD 진입 상태·서비스 색인·공식 근거·요청 기록을 정합화했다. EVAL-13 구현·분야 인수 완료로 전체 **116개 완료·1개 진행·7개 미착수**이며 다음 권장은 TEST-08의 첫 Codex CLI 실제 연결 인수다. TEST-06의 Safari·실제 음성 관찰도 남아 있다. `feat/evaluation`에는 upstream이 없어 원격 대비 상태를 확인하지 못했고 변경은 미커밋이다. 개인 `.idea` 파일 두 개는 보존했다.

합성 클러스터의 잔여 클라이언트 연결 0개를 확인하고 직접 생성한 acs-eval13-db 컨테이너와 익명 볼륨만 정상 정지·제거했다. Linux 파일 시험 컨테이너는 --rm으로 정리했다. 기존 개발 DB와 WAL 정리 컨테이너는 유지했다. 의도적인 정리 거부 시험은 실패 보고의 잔여/실패 상태를 검사했으며 그 합성 데이터도 시험 컨테이너와 함께 제거했다.
