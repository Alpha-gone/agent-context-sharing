# #171 비업무 모드 비용 선언의 실행 전 거부

## 결정과 변경

manifest 검증(`validate`)에서 `business_tasks` 외 모드의 비용 항목이 모두 `unmeasured`인지 확인한다. 실제 비용 항목을 산정하는 모드는 확장 업무 과업뿐이고, 다른 모드의 결과(`resultCost`)는 항목을 모두 미측정으로 둔다. 그래서 `measured`·`not_applicable` 선언은 측정 뒤 대조에서 반드시 `cost_mismatch`가 된다. 이제 이 선언은 `-check-manifest`에서 거부되고, `-manifest` 실행은 예약·결과 경로 생성·입력 결합·DB 접속 전에 `manifest_invalid`로 멈춘다. 미측정 항목의 값 금지는 기존 항목 검증이 계속 맡는다.

이슈가 제시한 `arguments` 단계 대신 manifest 검증을 택했다. 같은 판정을 사전 검사(`-check-manifest`)에서도 얻을 수 있고, 다른 모드·수치 전제 거부와 같은 단계·코드로 구분되기 때문이다. 확장 업무 과업의 측정 뒤 상태·금액 대조(`checkCost`)는 바꾸지 않았다.

[manifest 입력 계약](../sdd/evaluation.md#실행-manifest-입력-계약)·[실행과 결과 묶음](../sdd/evaluation.md#manifest-실행과-결과-묶음)·[시험 설계](../sdd/testing.md#manifest-실행결과-저장실패-보고-시험)를 갱신했다. 요구사항·추적표·DOX의 소유권과 구성은 바뀌지 않아 유지했다.

## 검증

- 새 `TestManifestCostStatusByMode`는 `basic` 모드에서 `not_applicable`·`measured` 선언이 `validate`와 manifest 읽기에서 거부되는지 확인한다. `runManifestTrialContext`가 `manifest_invalid`를 반환하고 결과 경로에 파일을 만들지 않는지도 확인한다. 수정 전 `manifest.go`를 overlay로 쓰면 두 사례가 실패했다.
- 새 `TestManifestTrialBusinessCostMismatch`는 확장 업무 과업의 산정 금액과 다른 선언이 실제 CLI에서 측정 뒤 `cost_mismatch` failure로 공개되는지 확인한다.
- 공통 시험 manifest의 기본 비용 선언을 모든 모드에 유효한 미측정으로 바꿨다. 측정한 0·비해당 보존과 항목 형식 거부 사례는 확장 업무 과업 명세에서 확인한다.
- Go 1.27.1, 작업 전용 합성 DB 컨테이너(정식 마이그레이션 적용), `TEST_DATABASE_REQUIRED=1`, `-p 1`의 필터 없는 `./cmd/eval` 실행: 904건 통과, 건너뜀 0건. 이 실행 뒤 추가한 `TestManifestTrialBusinessCostMismatch`는 DB를 쓰지 않으며 DB 없는 필터 없는 실행에서 통과했다.
- 같은 DB 실행에서 `TestEmbeddingComparisonCommandIntegration`의 dimension·compression 두 하위 사례가 별도 비교 DB 환경 변수(`TEST_EMBEDDING_SMALL_URL`·`TEST_EMBEDDING_HALF_URL`) 미설정으로 실패했다. 이번 변경과 무관한 실행 환경 조건이며 통과로 보고하지 않는다.
- `check-go.sh`의 의존성·`go build`·`go vet`·`gofmt` 검사, 변경 Markdown의 링크·앵커를 확인했다. 검증 후 소유 라벨의 합성 컨테이너와 익명 볼륨을 제거했다.
