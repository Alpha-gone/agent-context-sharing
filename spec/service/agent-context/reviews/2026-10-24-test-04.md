## 새 산출물과 대응 행렬

`cmd/server/testing_isolation_acceptance_test.go`의 `TestTEST04CatalogIsolationIntegration`은 제품 HTTP 처리기의 실제 `tools/list`를 가져와 각 도구를 같은 목록·입력 검증 경계로 호출한다. 목록 개수와 도구별 대응 분기로 누락을 검출한다. 도구마다 새 DB에 서로 다른 계정의 그래프를 만들고 같은 그래프 이름·원천 자연 키, 원천/파생/사건 정점·참조·확정 관계를 준비한다. 검색 사례에는 양쪽 그래프의 실제 큐를 소비해 동일한 합성 벡터를 저장한다.

성공 응답의 모든 `graph_id`를 재귀 대조하고 상대 그래프 식별자·본문의 비노출을 확인한다. 그래프를 받는 모든 도구는 상대 그래프와 없는 그래프를 같은 `not_found` 내용으로 답한다. 호출 전후 상대 그래프의 정점·전체 간선·메타데이터/저장량·등급·감사·판·큐·임베딩 지문을 대조한다. 등록·목록·생성은 각각의 계정 범위로 판정한다. 이 신규 행렬의 인증 주체는 주입하며, 실제 OAuth/Bearer/TLS와 웹 경계는 아래 관련 시험에서 별도로 실행했다.

| 도구 | 해당 격리 책임과 새 관찰 |
|---|---|
| `graph_list` | 같은 이름의 상대 그래프를 제외하고 본인 그래프 한 건만 반환한다. |
| `graph_create` | 같은 이름을 본인 소유로 새로 만들며 상대 그래프는 그대로다. 같은 키의 두 인스턴스 결과가 같다. |
| `graph_get` | 요청 그래프의 속성만 반환하고 상대/부재 그래프의 오류가 같다. |
| `graph_update` | 본인 그래프의 판·설명을 갱신하며 상대 그래프 지문은 같다. |
| `node_create` | 본인 원천을 참조한 파생 정점·큐·감사를 같은 그래프에 저장한다. |
| `node_get` | 실제 양방향 2홉의 정점·참조를 반환하며 상대 그래프 식별자가 없다. |
| `node_update` | 본인 파생을 갱신하며 상대 정점·판·큐·감사를 바꾸지 않는다. |
| `node_discard` | 본인 노드를 폐기하며 상대 그래프를 바꾸지 않는다. |
| `node_restore` | 준비한 본인 MCP 폐기를 복구하며 상대 그래프를 바꾸지 않는다. |
| `context_flow_get` | 양쪽에 벡터가 있어도 본인 그래프의 의미 후보·평면 흐름만 반환한다. |
| `relation_list` | 본인 사건의 확정 관계 한 건을 반환하며 상대 간선을 포함하지 않는다. |
| `relation_confirm` | 본인 두 사건 사이에 관계를 확정하며 상대 그래프를 바꾸지 않는다. |
| `relation_discard` | 본인 확정 관계를 폐기하며 상대 그래프를 바꾸지 않는다. |
| `agent_register` | graph 인자 없이 같은 계정/client/key는 같은 등록, 다른 계정 또는 client는 별도 등록이다. |

`TestTEST04ManipulatedInputsIntegration`은 커서·등급·UUID·홉 방향/필터·관계 상태/유형의 조작 입력 9건을 제품 스키마/저장 경계에서 거부한다. 노드 읽기/수정/폐기/복구·관계 목록의 상대 대상과 부재 대상도 동일한 `not_found`로 반환하며 상대 그래프 지문은 같다.

| 교차 분야 | 이번 실행에서 대조한 책임 |
|---|---|
| 저장소 | 격리 읽기·참조/끝점 손상·벡터 행 재검사·잘못된 쓰기 참조와 커서/필터, 등록 결합/폐기, 멱등성 계정 범위·현재 재검사, 직접/팀 권한 회수와 유예 전이를 확인했다. |
| MCP·두 인스턴스 | 여덟 쓰기 재생·동시 적용과 현재 등급/등록 검사, 실제 자문 잠금 대기 뒤 회수·폐기, 읽기 목록/홉/관계/검색의 격리와 TLS 쓰기를 확인했다. |
| OAuth·connections | 두 저장소 인스턴스의 코드 client/callback/resource/PKCE 결합, Bearer 계정/client/grant 및 공유 폐기, 갱신 회전/재사용 계열 폐기, 본인 목록/폐기와 상대/부재 거부를 확인했다. |
| 웹 관리 | 실제 세션·TLS의 본인 연결 목록·상대 계열/등록 폐기 거부, 본인 폐기 뒤 다른 계열·등록·웹 세션 유지, 감사·그래프 페이지·팀 관리와 등급 재판정을 확인했다. |

## 실행 환경과 결과

Go 1.27.1 darwin/arm64, PostgreSQL 18.6·AGE 1.8.0·pgvector 0.8.6 Linux aarch64에서 실행했다. 고정 이미지 ID는 `sha256:2b6d51048c03dae147064683f5b078690f1525365d561fd80b78f74de8c3c697`이며 `acs-test04-isolation`은 tmpfs·동적 loopback 포트·합성 자격만 사용했다. 기준 DB와 각 시험 DB는 정식 마이그레이션으로 준비했다.

정확한 최상위 시험·원본 파일·정규식은 `/tmp/acs-test04-{server,store,authz,web}-manifest.json`에 기록했다. 서버는 새 시험과 `mcp_read_contract_test.go`·`mcp_write_contract_test.go`·`connections_contract_test.go`의 14건, 저장소는 격리/등록/재생/권한/팀 6개 파일의 42건, 인증은 OAuth 코드/Bearer/갱신/connections/등록 구성 5개 파일의 8건, 웹은 요청 경계/감사·연결/그래프 목록/권한·팀 7개 파일의 17건을 선택했다. 실행에는 `TEST_DATABASE_URL`·`TEST_DATABASE_REQUIRED=1`·`AGE_GRAPH_NAME=agent_context`를 지정했다.
