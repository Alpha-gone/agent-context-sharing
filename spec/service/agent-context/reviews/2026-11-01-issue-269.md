# #269 계정 등록 경유 OAuth 인가 복원

## 원인과 변경

인가 요청으로 로그인 화면에 도착해도 등록 링크가 고정 /register였고, 등록 양식·로그인 복귀 링크·가입 성공 이동도 next를 전달하지 않았다. 가입을 끝내고 로그인하면 원래 /authorize 대신 /graphs로 이동했다.

기존 localRedirect 규칙으로 GET과 정상 해석된 POST 본문의 next를 각각 검사한다. 로그인→등록 링크, 등록의 숨은 필드와 로그인 복귀 링크, 자격 검증 실패·인증 저장소 오류의 재렌더, 가입 성공 후 /login?registered=1 이동에 안전한 내부 값만 보존한다. POST는 query의 next를 대신 읽지 않는다. href query와 hidden value는 html/template의 문맥별 escaping을 쓰고 신뢰된 URL/HTML 타입으로 변환하지 않는다. 가입은 기존처럼 세션 생성·OAuth 동의를 대신하지 않으며 로그인 후 원래 동의 화면으로 돌아간다.

출처 검사→출처별 공유 시도 예산→8 KiB/형식 검사→자격 처리 순서는 유지한다. 본문 상한·잘못된 형식에서 거부된 데이터를 복귀 상태 보존을 위해 다시 읽지 않는다. 기존 일반 가입의 /login?registered=1과 로그인 기본 /graphs 이동도 유지한다.

[최초 인가](../sdd/authentication.md#oauth-discovery와-최초-인가)를 정본으로 가입 경유 복원을 명시하고 [웹 화면](../sdd/web.md#웹-화면-계약)은 참조한다. [시험 설계](../sdd/testing.md#가입-경유-최초-인가-복원-시험)와 [공식 근거](../reference.md#269-가입-경유-인가-복귀-상태)도 갱신했다. 요구사항·개발 계획·스키마·환경 키·용어·DOX 소유권은 변경할 이유가 없어 유지했다.

## 재현과 검증

- 수정 전 인가 요청·일반 내부 query·HTML 속성 경계의 next 표본에서 등록 링크가 /register로만 가는 실패를 재현했다. 빈 next·외부 주소의 기존 동작은 대조 표본으로 유지했다.
- 로그인 GET→렌더링된 등록 링크→등록 GET의 숨은 필드→등록 POST→가입 완료 로그인 GET→로그인 POST를 요청으로 연결했다. 인가 query·한글·인코딩된 구분자 값이 보존되며, 일반 URL의 동등한 퍼센트 인코딩은 해석한 query 값으로 대조했다.
- GET과 직접 POST의 외부·프로토콜 상대·스크립트·잘못된 URL을 버리고, POST가 query의 next를 대신 쓰지 않는지 확인했다. 자격 오류와 인증 저장소 오류 재렌더도 안전한 next만 유지하며 비밀번호를 다시 싣지 않았다. HTML 속성을 벗어나는 입력도 실제 렌더링에서 검사했다.
- 기존 OAuth TLS/DB 시험을 사전 가입 대신 실제 가입 경유로 강화했다. 신규 계정 등록→로그인→동의→인가 코드→토큰 교환·갱신·재사용 거부가 통과했다. 한글·공백·&·+·query 구분자가 포함된 state와 원래 인가 요청이 유지됐고, 명시적 동의와 로그의 자격 비노출도 확인했다.

Go 1.27.3, .env의 TEST_DATABASE_URL·TEST_DATABASE_REQUIRED=1로 실행했다. 실제 TLS/DB 인가는 시험별 전용 DB에 정식 마이그레이션을 적용하고 자신이 만든 DB만 정리했다. 외부 OAuth 서비스나 임베딩 제공자는 호출하지 않았다.

- `go test -race -json -count=1 ./internal/web`: 하위 사례 포함 실행 866건 통과, 실제 Chrome 인수 1건 건너뜀.
- `go test -race -json -count=1 ./cmd/server`: 실행한 하위 사례 포함 727건 통과, Codex CLI 인수 19건과 전용 물리 복구·이행 시험 2건 건너뜀. Go가 pass로 기록한 부모 중 모든 자식이 건너뛴 네 개는 실행 통과 건수에서 제외했다.
- 합계 실제 실행 통과 1,593건, 실패 없음. 별도 실행 조건이 없는 22건은 통과로 집계하지 않았다. 웹의 기존 본문 상한·출처·시도 예산과 서버의 인증·인가 회귀도 위 범위에 포함된다.
- check-go.sh의 의존성 검증·전체 build·vet·gofmt·govulncheck 통과. 독립 코드 리뷰에서 발견 사항 없음. 변경 문서의 링크·내부 앵커·용어·Markdown과 git diff --check도 확인했다.

## 미실행 범위

Chrome이 없어 실제 브라우저 인수는 실행하지 못했다. TEST_CODEX_BINARY가 없으므로 실제 Codex CLI 시험도 실행하지 않았고, test-pitr.sh·test-transition.sh가 제공하는 전용 실행 조건 없는 물리 복구·이행 인수는 건너뛰었다. HTTP/TLS 시험 결과를 실제 브라우저·데스크톱 앱의 수동 인수로 취급하지 않는다.

Modern Web Guidance CLI 검색은 자동 승인 검토가 미검증 외부 패키지 실행의 공급망·로컬 데이터 접근 위험을 이유로 거부했다. 우회 실행하지 않고 WHATWG HTML·Go 1.27.3 공식 문서를 읽어 구현·검증했다. 이 작업에서 새 외부 패키지나 의존성을 설치하지 않았다.

기존 .env.example·IDE 변경은 포함하지 않으며 운영 배포는 수행하지 않았다.
