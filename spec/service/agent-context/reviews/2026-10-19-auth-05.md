# 웹 세션 발급·검증·로그아웃 검토

- 기준: [AUTH-05](../development-plan/authentication.md#auth-05), [세션 쿠키 검증](../sdd/authentication.md#세션-쿠키-검증), [웹 처리 순서](../sdd/web.md#웹-요청-처리-순서), [SRS 웹 세션](../SRS.md#웹-세션).
- 범위: 웹 전용 JWT 발급·클레임·12시간 수명·쿠키·로그아웃·공유 폐기·키 회전·장애와 취소의 모듈 인수.
- OAuth·Bearer 보호 리소스 구현과 전체 인증 분야 통합 인수는 후속 작업이다. 실제 브라우저·호스트·운영 배포·Tunnel 시험으로 간주하지 않는다.

## 발견 사항과 반영

기존 WebSession은 임의 audience와 유효하지 않은 계정 식별자를 받아 발급할 수 있었다. 공개 발급은 web과 UUIDv7만 받고, 검증은 빈 기대 audience와 복수 audience를 거부한다. 필수 클레임·서명·issuer·미래 iat를 기존 공급자 검증과 함께 검사하며 iat < exp, now < exp와 웹 수명 최대 12시간을 확인한다.

적용 go-jose의 ValidateWithLeeway는 exp와 현재 시각이 같은 순간을 허용했다. RFC와 고정 수명에 맞게 만료 순간부터 거부하도록 보완하고 내부 시계 경계로 나노초 전·정각·나노초 후를 검증한다. JWT는 초 단위인데 발급 반환값은 소수 초를 보존하던 차이도 제거하여 쿠키·JWT·폐기 목록이 같은 만료를 쓴다. 공개 환경 변수나 갱신 경로를 추가하지 않았다.

기존 웹 세션 판정은 검증 저장소 장애도 로그인 화면으로 보냈고 로그아웃에서 검증에 실패하면 쿠키를 지웠다. 어댑터의 세션 발급·검증·폐기도 인증 장애를 사상하고 보호 화면은 자격 실패 303과 검증 장애 500을 구분한다. 로그아웃의 검증·폐기 장애에는 쿠키 삭제·성공 리디렉션이 없다. 세션 판정 응답과 로그아웃 POST는 no-store이며 내부 오류 원문을 표시하지 않는다.

취소된 발급·검증·폐기는 선행 저장소 호출이나 후속 성공 응답을 진행하지 않는다. 폐기 저장 뒤 취소되어도 이미 커밋한 폐기를 보상 취소하지 않고 로컬 캐시에 즉시 반영한다. 없는/무효 쿠키의 로그아웃은 폐기 쓰기 없이 쿠키만 삭제한다.

기존 서버 웹 세션 왕복 시험을 공유 DB에서 시험별 임시 DB로 옮겼다. AUTH-04의 정식 마이그레이션·실제 DB 확인·독립 정리 경계를 재사용하며 세션 본문은 저장하지 않는다. 기존 계정·공유 키·개별 폐기 테이블과 캐시 정책을 유지했다.

## 새 검증 근거

- 필수 클레임 15개 하위 시험: iss 누락/불일치·sub 누락/잘못된 UUID·aud 누락/다른 채널/복수·iat 누락/미래·exp 누락/정각/과거/비양수 수명/12시간 초과·jti 누락을 실제 서명 표본으로 거부했다. 빈 기대 audience와 웹 토큰의 다른 대상 검증도 거부한다.
- 수명 4개 하위 시험: 발급 직후·12시간 만료 나노초 전에는 같은 값·jti·만료를 반환하고 정각·직후에는 거부한다. 조회에 따른 갱신이 없다.
- 발급·폐기 장애 2개 하위 시험과 취소 시험: 고정 오류 문자열·ErrUnavailable·원인 보존, 이미 취소된 세 경로의 저장소 호출 차단, 키 조회 중 취소의 빈 결과, 폐기 저장 직후 취소의 폐기 유지와 로컬 차단을 확인했다.
- 보호 화면 16개·로그아웃 10개 하위 시험: 데이터 접근 전에 자격·저장 장애·취소를 분리하고 GET·출처 거부·무효/없는 쿠키·정상 로그아웃의 검증/폐기 호출 수와 쿠키·본문·리디렉션·no-store를 대조했다.
- 시험 전용 DB의 두 서비스 4개 하위 시험: 실제 로그인·독립 jti·로컬 즉시 폐기·원격 10초 경계 전후·서비스 재생성·키 회전 후 유효 세션 보존·개별 세션 격리·12시간 만료를 검증했다. 시간은 서비스 시계로 제어했으며 10초 실제 경과나 별도 프로세스 배포 실증은 아니다. 만료 시 폐기 목록 조회에서 제외됨을 확인했으며 주기 정리의 물리 삭제 인수는 이 범위가 아니다.
- 실제 TLS 루프백 8개 하위 시험: 로그인 쿠키의 Secure·HttpOnly·SameSite=Lax·Path=/·호스트 전용 속성과 JWT의 12시간 만료, 보호 화면에서 재발급 없음, Bearer/질의만으로 인증 불가·다른 audience 쿠키 거부·Authorization 대체 인증 없음, 확인 GET·교차 출처 로그아웃의 상태 보존과 성공 로그아웃 뒤 재사용 거부·같은 계정의 다른 세션 유지·반복 로그아웃을 확인했다.
- 실제 연결 풀을 닫은 추가 2개 하위 시험은 저장소→서비스→어댑터→웹의 검증 장애가 로그인 리디렉션이나 로그아웃 성공으로 바뀌지 않음을 확인했다. 발급·폐기 어댑터도 장애로 분류한다.
