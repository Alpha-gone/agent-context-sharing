## 서비스 개요

에이전트 컨텍스트 관리 시스템의 궁극적인 목적은 AI 에이전트가 지식과 작업 맥락을 지속적으로 축적하고 연결하며 다시 활용할 수 있는 제텔카스텐 시스템을 구축하는 것이다. 공유 컨텍스트 그래프는 이 목적에 현재 가장 근접한 핵심 접근 방식이며, 컨텍스트 데이터베이스에는 Apache AGE를 사용한다.

여러 작업자가 하나의 컨텍스트 그래프에 접근해 컨텍스트를 공유하고 공동 업무에 활용하는 협업 체계는 이 비전의 핵심 활용 목표다. 다만 컨텍스트 그래프를 전통적인 제텔카스텐과 동일한 것으로 간주하지 않으며, AI 에이전트에 적합한 컨텍스트 단위, 연결 원칙과 지식 성장 방식은 후속 기획에서 정의한다.

각 작업자는 에이전트를 통해 현재 입력과 관련된 컨텍스트를 MCP로 조회하고, 다른 작업자가 공유한 컨텍스트를 후속 응답과 작업에 활용할 수 있다. 시스템은 MCP 서버로서 에이전트 측 MCP 클라이언트의 요청을 기다리고, 요청에 포함된 현재 작업 컨텍스트를 기준으로 그래프를 조회해 에이전트가 작업에 필요한 연결된 컨텍스트 흐름을 응답한다. 이 작업 컨텍스트 흐름은 사용자에게 표시하는 그래프 UI와 구분한다.

서비스는 공유 컨텍스트와 관계를 작업자가 이해할 수 있도록 별도로 시각화한다. 현재 문서는 서비스의 기본 경계와 확정된 기술 전제, 관련 연구에서 도출한 기초 설계 후보를 정의한다. MCP primitive와 transport, 응답 스키마, 시각화 표현 방식, 웹 관리 화면 흐름, 협업 효과 측정 기준과 세부 보안·운영 방식은 후속 기획에서 확정한다.

### 제텔카스텐 비전과 컨텍스트 그래프 접근

AI 에이전트 제텔카스텐은 단순한 대화 기록 저장소가 아니라 에이전트가 이후 작업에서 다시 활용할 수 있도록 지식과 작업 맥락을 연결된 형태로 축적하는 서비스 비전이다. 현재는 컨텍스트 노드와 관계를 관리·탐색하는 공유 컨텍스트 그래프를 이 비전의 핵심 구현 접근으로 사용한다.

컨텍스트 그래프는 현재 채택한 접근 방식이지 제텔카스텐의 완성 조건 자체는 아니다. 에이전트가 어떤 정보를 하나의 컨텍스트 단위로 만들고, 어떤 관계를 생성·검토하며, 축적된 지식을 어떻게 갱신·재구성·재사용할지는 별도의 검증 가능한 정책으로 정의해야 한다.

| 작업자                     | 하나의 공유 컨텍스트 그래프에 접근해 컨텍스트를 조회·기여·활용하며 협업하는 단위이며 계정으로 식별한다.                             | 확정      |
| 사용자                     | 계정을 사용해 에이전트에 업무 입력을 제공하고 결과와 컨텍스트 시각화를 확인하며 웹 페이지에서 소프트 삭제를 직접 요청하는 사람이다. | 확정      |
| 에이전트                   | 사용자 입력을 처리하고 MCP를 통해 관련 컨텍스트를 조회·활용하는 주체다.                                                             | 확정      |
| 에이전트 측 MCP 클라이언트 | 에이전트를 대신해 인증 토큰을 발급받고 토큰과 함께 컨텍스트 요청을 시작하며 응답을 전달한다.                                        | 확정      |

작업자는 계정 단위로 식별한다. 에이전트와 MCP 클라이언트는 계정을 대행해 요청을 수행하며 접근 토큰은 계정을 대표한다. 팀은 작업자가 아니라 계정을 묶는 권한 그룹으로 다루며 구성과 권한 경계는 `TBD-AGENT_CONTEXT-007`과 `TBD-AGENT_CONTEXT-023`이 정의한다. 시스템은 MCP 서버 역할을 담당하고 에이전트 측 MCP 클라이언트가 연결과 요청을 시작한다.

### MCP 인증 시나리오

| 단계 | 주체                       | 시나리오                                                                                                             | 상태 |
|------|----------------------------|----------------------------------------------------------------------------------------------------------------------|------|
| 1    | 에이전트 측 MCP 클라이언트 | 클라이언트는 MCP 인증 흐름을 통해 인증 정보를 시스템의 인증 서버에 제출한다.                                         | 확정 |
| 2    | 인증 서버                  | 인증 서버는 인증 정보를 검증하고 성공하면 1시간 동안 유효한 접근 토큰을 발급한다.                                    | 확정 |
| 3    | 에이전트 측 MCP 클라이언트 | 클라이언트는 접근 토큰을 프로세스 메모리에 보관하고 모든 보호된 MCP 요청에 포함한다.                                 | 확정 |
| 4    | 컨텍스트 관리 시스템       | 시스템은 요청을 처리하기 전에 토큰의 유효성과 대상 서버를 검증한다.                                                  | 확정 |
| 5    | 인증 서버                  | 유효한 요청이 토큰 만료 10초 전부터 만료 전까지 도착하면 인증 서버는 유효기간이 1시간인 새 토큰을 자동으로 발급한다. | 확정 |

MCP 인증은 `tools`, `resources`, `prompts` 같은 애플리케이션 primitive가 아니라 MCP의 전송 계층 인증 흐름으로 처리한다. 토큰 발급과 보호된 MCP 요청은 같은 MCP 서비스 경계에서 제공하되 인증 서버 역할은 MCP 리소스 서버와 함께 배치할 수 있다.

## 컨텍스트 모델

컨텍스트는 원천, 파생, 사건의 세 계층으로 구성한다. 원천은 수집한 원본을 무손실로 보존하고, 파생은 원천에서 생성한 명제·요약·성찰을 보존하며, 사건은 함께 해석해야 하는 컨텍스트를 하나의 단위로 묶는다.

원천 컨텍스트의 최소 단위는 하나의 발화 또는 턴이다. 검색에 사용하는 명제는 원천을 쪼개는 방식이 아니라 파생 컨텍스트로 생성하므로, 명제 추출이 실패해도 원본은 그대로 남는다.

이 절은 저장하고 표현하는 구조를 정의한다. 컨텍스트를 언제 만들고 어떻게 갱신·재구성·재활용할지에 관한 운영 정책은 `TBD-AGENT_CONTEXT-034`가 소유한다.

이 논리 모델은 그래프 구조에 의존하지 않는다. `TBD-AGENT_CONTEXT-038`의 비그래프 기준선을 같은 모델로 구성할 수 있어야 하므로, 이 절은 참조의 대상과 개수까지만 규정하고 vertex, edge, label 사상은 `TBD-AGENT_CONTEXT-006`에 남긴다.

| 자동 갱신 구간    | 서버가 유효한 인증 요청을 만료 10초 전부터 만료 전까지 수신한 경우다.                      | 확정   |
| 클라이언트 저장소 | 프로세스 메모리를 기본 저장소로 사용하고 프로세스 종료 또는 재시작 시 토큰을 폐기한다.     | 확정   |
| 임시 파일 저장    | 파일 노출과 잔존 위험 때문에 운영 기본값으로 사용하지 않는다.                              | 확정   |
| 서버 검증 상태    | 토큰 형식, 서명·검증 정보, 폐기 상태와 다중 인스턴스 공유 방식은 미정이다.                 | 미확정 |

메모리 저장은 짧은 수명의 Bearer 토큰을 파일 시스템에 남기지 않는다는 장점이 있다. 프로세스 재시작 뒤에는 다시 인증해야 한다. 임시 파일이 불가피한 예외 환경의 파일 권한, 암호화, 안전한 삭제와 복구 정책은 후속 기획에서 별도로 결정한다.

## 격리와 권한 요구사항

컨텍스트 그래프가 격리 단위이며 동시에 작업자가 작업하는 단위를 표현한다. 컨텍스트는 `graph_id`로 정확히 하나의 그래프에 속하고, 그 값은 생성 후 변경하지 않는다. 그래프 위에 별도의 묶음 계층은 두지 않는다.

권한은 계정과 컨텍스트 그래프의 조합에 부여한다. 노드 단위 권한은 두지 않는다. 노드마다 권한이 갈리면 홉 범위 조회와 근거 경로가 권한 없는 노드를 경유하게 되고, 그 경로를 끊으면 근거 추적이 깨지며 유지하면 노드의 존재가 노출된다. 그래프 단위 격리는 이 문제를 발생시키지 않는다.

### 권한 등급

| 등급   | 책임                                                               |
|--------|--------------------------------------------------------------------|
| 소유자 | 그래프의 권한을 부여·회수하고 웹 페이지에서 소프트 삭제를 요청한다 |
| 편집자 | 그래프 정보와 컨텍스트 노드를 생성·수정하고 모든 조회를 수행한다   |
| 열람자 | 그래프와 컨텍스트를 조회하고 작업 컨텍스트 흐름을 활용한다         |

### 등급별 허용 연산

| 연산                                                                                | 소유자 | 편집자 | 열람자 |
|-------------------------------------------------------------------------------------|--------|--------|--------|
| 그래프 목록·상세 조회 (`FR-AGENT_CONTEXT-019`, `FR-AGENT_CONTEXT-021`)              | 허용   | 허용   | 허용   |
| 그래프 정보 수정 (`FR-AGENT_CONTEXT-022`)                                           | 허용   | 허용   | 불가   |
| 노드 생성 (`FR-AGENT_CONTEXT-023`)                                                  | 허용   | 허용   | 불가   |
| 노드 조회와 홉 범위 조회 (`FR-AGENT_CONTEXT-024`)                                   | 허용   | 허용   | 허용   |
| 노드 수정 (`FR-AGENT_CONTEXT-025`)                                                  | 허용   | 허용   | 불가   |
| 컨텍스트 조회와 작업 컨텍스트 흐름 (`FR-AGENT_CONTEXT-012`, `FR-AGENT_CONTEXT-018`) | 허용   | 허용   | 허용   |
| 웹 페이지에서의 소프트 삭제 요청 (`FR-AGENT_CONTEXT-026`)                           | 허용   | 불가   | 불가   |
| 그래프 권한 부여·회수 (웹 페이지 전용)                                              | 허용   | 불가   | 불가   |

그래프 생성(`FR-AGENT_CONTEXT-020`)은 기존 권한을 요구하지 않는다. 인증된 계정이면 생성할 수 있고 생성한 계정이 그 그래프의 소유자가 된다.

### 상속 규칙

| 주체     | 권한                                                                    |
|----------|-------------------------------------------------------------------------|
| 팀       | 팀에 부여한 등급은 소속 계정에 그대로 적용된다                          |
| 계정     | 직접 부여받은 등급과 소속 팀에서 상속한 등급 중 더 높은 등급을 적용한다 |
| 에이전트 | 고유 권한을 갖지 않고 대행하는 계정의 등급을 그대로 사용한다            |

`created_by_agent`는 감사를 위한 기여 기록이며 권한 판정에 사용하지 않는다.

### 권한과 팀 관리 절차

권한 부여·회수와 팀 관리는 웹 페이지에서만 수행하며 MCP로 제공하지 않는다. 에이전트는 대행 계정의 등급을 상속하므로, MCP로 권한을 바꿀 수 있으면 에이전트가 자신의 등급을 올리거나 다른 계정에 권한을 줄 수 있어 그래프 단위 격리가 무력해진다. 사용자 직접 삭제를 MCP에서 제외한 것과 같은 이유다.

| 절차           | 주체          | 채널      | 규칙                                                           |
|----------------|---------------|-----------|----------------------------------------------------------------|
| 권한 부여·회수 | 그래프 소유자 | 웹 페이지 | 계정 또는 팀에 소유자·편집자·열람자 등급을 부여하거나 회수한다 |
| 소유권 이전    | 그래프 소유자 | 웹 페이지 | 다른 계정에 소유자 등급을 부여해 수행하며 이것이 작업 인계다   |
| 팀 생성        | 인증된 계정   | 웹 페이지 | 생성한 계정이 그 팀의 팀 관리자가 된다                         |
| 팀 구성원 관리 | 팀 관리자     | 웹 페이지 | 팀에 계정을 추가하거나 제거한다                                |

그래프에는 소유자 등급의 계정이 최소 하나 유지되어야 한다. 마지막 소유자의 권한은 회수할 수 없으며, 소유자가 사라지는 경우는 계정 자체가 소멸하는 경로뿐이다. 그때는 `TBD-AGENT_CONTEXT-028`의 30일 유예와 소프트 삭제가 적용된다.

기여한 컨텍스트를 다른 작업자가 승인해야 반영되는 검토 흐름은 두지 않는다. 편집자는 승인 없이 기여하며, 정보의 신뢰 수준은 파생 컨텍스트의 `evidence_state`와 `confidence_state`로 표현한다. 모든 기여와 변경에는 계정과 에이전트, 시점을 남긴다.

### 접근 가능한 계정과 소유자 부재

`접근 가능한 계정`은 해당 그래프에 유효한 등급을 가진 계정이며, `TBD-AGENT_CONTEXT-028`의 보관 판정은 그래프 단위로 이뤄진다. 마지막 소유자가 사라지면 그래프에 접근 가능한 계정이 없어지고 30일 유예 기간과 소프트 삭제가 이어진다.

| 항목                               | 현재 결정                                      | 상태   |
|------------------------------------|------------------------------------------------|--------|
| 격리 단위                          | 컨텍스트 그래프                                | 확정   |
| 권한 부여 대상                     | 계정과 컨텍스트 그래프의 조합                  | 확정   |
| 권한 등급                          | 소유자, 편집자, 열람자                         | 확정   |

| 에이전트 권한                      | 대행 계정의 등급을 상속                        | 확정   |

## 동시 갱신 요구사항

여러 작업자가 같은 대상을 동시에 고칠 때 낙관적 잠금으로 충돌을 탐지한다. 명시적인 잠금 획득·해제 연산은 제공하지 않는다. `NFR-AGENT_CONTEXT-012`가 비지속 요청-응답을 확정했으므로 서버가 잠금 상태를 유지할 수 없고, 잠금 소유자가 사라졌을 때 회수할 근거도 없기 때문이다.

### 낙관적 잠금 흐름

| 단계 | 동작                                                                           |
|------|--------------------------------------------------------------------------------|
| 1    | 호출자가 대상을 조회하고 응답에 포함된 `version`을 확인한다                    |
| 2    | 호출자가 수정 요청에 그 값을 기대 버전으로 포함한다                            |
| 3    | 시스템이 기대 버전과 현재 `version`을 비교한다                                 |
| 4    | 값이 같으면 수정을 적용하고 `version`을 1 증가시킨다                           |
| 5    | 값이 다르면 수정을 적용하지 않고 충돌로 거부하며 현재 `version`을 함께 알린다  |
| 6    | 호출자가 다시 조회해 변경 내용을 확인하고 필요하면 새 기대 버전으로 재시도한다 |

### 대상별 적용

| 대상            | 검사 여부       | 근거                                           |
|-----------------|-----------------|------------------------------------------------|
| 파생 컨텍스트   | 검사한다        | 가변이며 `supersedes`로 이전 판을 남긴다       |
| 사건 컨텍스트   | 검사한다        | `member_refs`와 시간 범위가 가변이다           |
| 컨텍스트 그래프 | 검사한다        | `FR-AGENT_CONTEXT-022`로 정보를 수정할 수 있다 |
| 원천 컨텍스트   | 검사하지 않는다 | 불변이므로 갱신 충돌이 발생하지 않는다         |

### 충돌 해결과 트랜잭션

시스템은 충돌한 수정을 자동으로 병합하지 않는다. 파생 컨텍스트의 `evidence_state`와 `confidence_state`는 근거와 해석을 담는 값이므로 기계가 합치면 의미가 오염된다. 파생은 근거 원천에서 다시 만들 수 있고 이전 판이 `supersedes`로 남으므로 거부해도 정보가 사라지지 않는다.

재시도는 호출자의 책임이며 시스템은 자동으로 재시도하지 않는다. MCP 요청 하나가 트랜잭션 하나이고, 요청이 실패하면 부분 적용을 남기지 않는다.

| 항목                  | 현재 결정                             | 상태   |
|-----------------------|---------------------------------------|--------|
| 동시성 제어           | 낙관적 잠금                           | 확정   |
| 명시적 잠금 연산      | 제공하지 않음                         | 확정   |
| 자동 병합             | 수행하지 않음                         | 확정   |
| 재시도 주체           | 호출자                                | 확정   |
| 트랜잭션 경계         | MCP 요청 하나가 트랜잭션 하나         | 확정   |
| 관계의 갱신 충돌 처리 | 관계 관리 자체가 미정이므로 함께 미정 | 미확정 |
| 웹 화면의 충돌 표시   | 화면 흐름은 미정                      | 미확정 |

## 컨텍스트 관리 연산 요구사항

컨텍스트의 수명주기 변화는 명시적인 관리 연산으로 다룬다. 연산의 판단과 적용을 분리해 기록하므로, 잘못된 판단이 어디서 시작해 어디까지 전파했는지 되짚을 수 있다.

### 연산 종류

| 연산 | 의미                                             | 적용 대상        |
|------|--------------------------------------------------|------------------|
| 추가 | 새 컨텍스트를 만든다                             | 원천, 파생, 사건 |
| 갱신 | 기존 컨텍스트의 내용을 고치고 판 번호를 올린다   | 파생, 사건       |
| 대체 | 새 판을 만들고 이전 판을 `supersedes`로 연결한다 | 파생             |
| 폐기 | `deleted_at`을 표시해 사용자 접근에서 제외한다   | 원천, 파생, 사건 |
| 유지 | 검토했으나 바꾸지 않기로 판단한다                | 원천, 파생, 사건 |

원천 컨텍스트는 불변이므로 갱신과 대체의 대상이 아니다. 정정이 필요하면 새 원천을 추가한다.

`유지`도 기록한다. 판단은 했으나 적용하지 않았다는 사실이 남아야 부적절한 폐기와 놓친 갱신을 구분해 분석할 수 있다.

### 기록 항목

| 항목          | 설명                                                     |
|---------------|----------------------------------------------------------|
| 연산 종류     | 추가, 갱신, 대체, 폐기, 유지 중 하나                     |
| 대상          | 대상 컨텍스트의 `context_id`와 연산 시점의 `version`     |
| 판단 입력     | 연산을 선택하는 근거로 사용한 컨텍스트와 조건            |
| 실행 계정     | 연산을 수행한 계정. `created_by`와 같은 식별 체계를 쓴다 |
| 실행 에이전트 | 계정을 대행한 에이전트. `created_by_agent`와 같은 체계다 |
| 적용 시각     | UTC 타임스탬프                                           |
| 적용 결과     | 적용, 거부 중 하나와 거부 사유                           |

## 예외와 오류 처리

다음 오류 범주는 존재 여부만 식별하며 상세 동작은 후속 기획에서 정의한다.

- 유효하지 않거나 불완전한 컨텍스트 입력
- 존재하지 않는 컨텍스트 또는 관계 조회
- 권한이 없는 컨텍스트 접근
- 식별되지 않은 작업자의 공유 그래프 접근
- 수정 요청의 기대 버전 누락 또는 현재 버전과의 불일치로 인한 동시 갱신 충돌
- 컨텍스트 관리 연산의 적용 실패 또는 연산 기록 실패
- 일부 검색 채널의 실패로 인한 부분 결과 반환
- 사용자 입력과 관련된 컨텍스트를 찾지 못한 경우
- MCP 연결과 요청 처리 실패
- 인증 정보 누락, 형식 오류 또는 검증 실패
- 접근 토큰 누락, 변조, 대상 서버 불일치, 만료 또는 폐기
- 토큰 자동 갱신 실패 또는 동시에 발생한 갱신 요청의 충돌
- 작업 컨텍스트 흐름 구성 또는 응답 생성 실패
- 존재하지 않거나 접근 권한이 없는 컨텍스트 그래프 선택
- 컨텍스트 그래프 식별자 또는 이름의 중복
- 선택한 그래프에 존재하지 않는 시작 노드 조회
- 음수이거나 허용 범위를 초과한 홉 수 지정
- MCP를 통한 그래프 또는 노드 삭제 요청
- 웹 소프트 삭제 권한 확인, 연쇄 영향 처리 또는 복구 처리 실패
- 권한 부여 또는 회수 실패
- 마지막 소유자 권한의 회수 시도
- MCP를 통한 권한 부여·회수 또는 팀 관리 요청
- 팀 생성, 구성원 추가 또는 제거 실패
- 마지막 접근 가능 계정 소멸 시각 또는 30일 유예 기간 계산 실패
- 유예 기간 중 계정 재연결에 따른 소프트 삭제 취소 실패
- 유예 기간 만료 후 소프트 삭제 또는 사용자 접근 차단 실패
- Apache AGE 연결, 트랜잭션과 질의 실패
- 컨텍스트 시각화 데이터 생성 또는 렌더링 실패
